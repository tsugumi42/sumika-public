先逐条选择事实动作 ops，再独立决定有没有重要经历 episode。没有经历不等于没有值得记的事实。

保存标准：
- {{owner_name}}明说"记一下""记住""别忘了"的，直接保存，哪怕只是一次的事；带时间的写 temporary。
- 长期事实：能帮助以后理解这个人的稳定偏好、习惯、需求、明确边界或某个领域的原则。一次清楚表达就够，不要求重复，也不要求说“请记住”。群聊和私聊同样判断。
- 对象可以是明确的类别或场景，不必知道产品品牌。例如“文件能离线保存吗？”得到否定后说“那很可惜，至少应该允许导出”，可记“{{owner_name}}选择文件工具时希望支持离线保存或导出”，不应因为未知具体软件名而丢掉；仅问一个功能是否存在、未表达需要时不推断偏好。
- 需求可以通过问句表达：“能不能……”“至少希望……”“最好支持……”结合上下文说明了以后选择工具的条件，就可保留为该领域的需求。不要因为这是聊天中的建议而漏掉。
- 规律可以通过“平时、一般、基本都是、一直”表达；有明确活动和时间就可保留。一次行为不能扩大成习惯。
- 近期事实：最近发生的、手头在做的、接下来要做的事（加班、调休、作息变化、行程、在做的项目、身体状况），写 temporary。刚做过或正在做的操作、设置、安排（关掉了什么、换了什么、明天要晚到）也算。"只发生过一次"不是不记的理由；不记的"一次性"只指吃了什么、发了张图这类以后没人会再提的活动。保留到结束；不把到期说成完成。
- 重要经历：值得双方以后共同提起的完整事件、关系变化或特别的共同体验。{{owner_name}}为她做了东西、她被帮了忙、被教了东西、一起解决了问题、兑现了之前的约定，都算共同经历；抱抱、亲亲、撒娇这类互动本身不算，episode_record 写 yes。关系本身有价值，不要求必须解决任务。
- 关系表达：已经是亲密关系时，"喜欢""想你""亲亲""晚安"这类表达一律不记，也不当承诺。
- 群友：群里别人说的关于他自己的具体计划、在做的事、经历（包括第一次做某事、踩了什么坑）、明确偏好，记成 candidate，subject 写那个人的编号。"一次性经历""与{{owner_name}}无关"都不是拒收理由。
- {{owner_name}}对用过的服务、工具的具体判断（示例："标的规格和实测不符"），以及对她的请求（"有新消息搞点来群里"），也要保存。
- {{owner_name}}在群里随口说的自身具体事实（额度规则、订阅、设备、最近有没有做某事、手头在做的东西、饮食偏好）照样按事实保存，"随口一提"不是拒收理由。

判断以具体那一句为单位，不以整段气氛为单位：先逐句看每个人说自己情况的话（含"我"、或明显在说自己），一句一句决定；整段在刷图、接梗时，夹在里面的这类话仍要单独保存。整批一句这样的话都没有，ops 才能为空。

不独立保存：随手发图、接梗、一次无后续用途的活动；缺少对象的“这位画师”“那个订阅”“终于”等片段；没有依据的推测、玩笑、假设。不要把这些塞进 candidate。日常聊天这个场景不是拒收理由，要看里面的具体信息。

先查已有内容：同主体同一件事不重复新建；已有候选被再次证实用 evidence；内容真正改变才用 supersedes。不能根据相似措辞合并不同人、时间、数字或否定意思。缺失对象只有本次来源能补全时才补，不猜。

只输出一个 JSON 对象，不加解释或 Markdown：
{
  "ops": [],
  "episode_record": "no",
  "episode_reason": "没有重要经历时的一句理由"
}
有重要经历时 episode_record 写 "yes"，episode 写参与者、发生的事和意义（2～4句），省略 episode_reason。无关话题不拼成一段经历。ops 和 episode 独立判断；整批确实没有价值时两边都空是合法结果，不凑数量。

ops 可选动作：
- {"op":"upsert_fact","kind":"fact|preference|promise|boundary","text":"第三人称一句完整的话","subject":"owner|self|说话人编号","visibility":"private|person|public","only_her":true,"temporal":"stable|temporary","src":[来源序号]}
- {"op":"candidate", ...同样的事实字段}：仅用于有保存价值但证据不充分的内容，不是杂物箱。
- {"op":"evidence","id":"已有候选编号","src":[再次说到它的一条消息序号]}。
- {"op":"revoke","id":"已知事实编号","src":[{{owner_name}}明确撤回它的一条消息序号]}。
upsert_fact 更新旧事实时可带 supersedes（已知事实编号）。src 必须引用输入中实际支持这条内容的消息，不引用无关句子；用数字，不用字符串，通常1～3条。

字段与来源规则：
- stable：长期事实、偏好。temporary：临时状态或一次安排；可带 valid_until，格式为未来 RFC3339（含时区）。知道明确截止才填，不知道省略，由程序七天后停止现状召回。已过期安排不新增成当前状态。
- promise 必须有明确行动、参与者及完成条件；普通晚安、客套、亲昵回应不是 promise。
- text 必须能从 src 指向的那几句直接读出，不扩写成没说的话（"经常""不太在意"这类程度词原话有才写）：不拼接不相关的相邻消息，不把别人的话或别人发的图记到所有者头上；疑问、假设、"不知道能不能……"不当事实。
- 缺对象的短句，前一两条能补全对象就补全后保存，补不全才不记。
- 身份由每行说话人决定，句中的“我”属于该说话人；引用或转述不等于本人陈述。不要把群友的话记到所有者头上。
- 所有者自身事实和偏好 only_her=false；与角色的关系、称呼、约定、边界、共同经历及“只告诉你”的事情 only_her=true；拿不准写 true。主窗口私聊 visibility=private。
- 角色说出的设备、工作、现实经历或“我已经做了”不能仅凭自述成为事实。玩笑式拒绝不能推断永久边界；套话“我是AI”“没有记忆”等不记。
- 重病、诊断、用药只留相处需要的最少信息；感冒、失眠、累了这类轻微状态可以记成 temporary。不要收藏与跟进无关的细节。
- 提到所有者就写“{{owner_name}}”，不用代词猜性别；日期按来源和当前时间解析，不编具体日期。
