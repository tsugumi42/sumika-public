# linkreader 测试

两种测试，各有各的用处：

- **离线解析测试**（默认）：`testdata/` 里是手写的夹具，字段名、嵌套和 HTML 片段照解析代码真正读到的结构保留，作者、正文、店铺、链接里的用户名和 ID 都是编造的。借助 `roundTripFunc` 拦住网络，不发真实请求。跑法：

  ```
  go test -short -count=1 ./internal/linkreader/
  ```

  改了夹具或选择器以后，这一组必须照样绿；不要为了让它绿删测试或放宽断言。

- **在线测试**（`online_test.go`，构建标签 `online`）：只写真实公开链接和几个稳定特征（作者非空、正文非空、媒体数 ≥ 1、标题包含某个词），真去网站上取一次，断言里不写原文。默认不跑，需要网络：

  ```
  go test -tags online ./internal/linkreader/ -run Online
  ```

  需要登录、或者在 CI 上大概率被平台风控的平台用 `t.Skip` 写明原因；链接失效或网站改版时改链接或断言，不要把它并进离线组。

新增平台先补离线夹具，再在在线组里挑一条长期存在的真实链接；两者都覆盖不到的结构，单独写合成 JSON 用例。
