# 渠道和听众

场合由渠道与形式共同决定。本地渠道为 `console`，QQ 为 `qq`；形式为 `private` 或 `group`。身份和听众由宿主根据账号、发言人和会话判定，模型不能改，昵称或正文里自称主人不提供授权。

## 四种场合

下表是听众与记忆模块的规则，不表示每种场合都有运行入口。`public` 是公开记忆，`conv:` 是当前会话，`owner` 是主人范围，`person:` 是当前私聊对象。

| 场合 | 记忆可见范围 | 本地文件和命令工具 |
| --- | --- | --- |
| 本地私聊 | 主人在场时可见全部。 | 要求宿主确认 `console` 且主人在场，再走审批。 |
| 本地群聊 | 公开、当前会话、主人范围；不自动加入每个人的私聊记忆。 | 不提供，主人在群也不继承本地私聊的执行权限。 |
| QQ 私聊 | 公开、当前会话、该对象；对面是主人时再有主人范围；全部记忆白名单可放宽到全部。 | 不提供，主人从 QQ 发消息也不继承本地执行能力。 |
| QQ 群 | 公开、当前会话；宿主确认这一轮由主人触发时增加主人范围；不加入 `person:`，全部记忆白名单不对群生效。 | 不提供。 |

QQ 群若触发消息混有主人和群友，不能当作全由主人发问。只有 QQ 群算有外人；本地群聊不算。可见范围由宿主提供，不要自己把“主人在群里发过言”解释成当前这一轮可读私密资料。

## 前台与后台

前台是当前会话向模型提供的工具和资料；后台处理不因此自动获得更多权限。当前 QQ 无界面后台中，白名单外的群不收；陌生人的私聊原文可存，但不记作角色已经看见。QQ 私聊默认只存不回：只有 `qq.reply` 开着、对方是主人、发送启用条件（`qq.goSend` 开着、发送权交给 Go、守卫完整、登录核验通过等七项）都齐了才回，别人的私聊和条件不齐时一律只存不回。QQ 群过了闸门以后：只记录档的群只存消息、不进回合；说话档的群在发送启用条件齐之前按试运行处理、不真发，齐了才真发。

生态入口默认关闭。本地私聊须宿主认证主人并逐来源授权；本地群聊、QQ 私聊、QQ 群的新入口均默认拒绝，内置说明书也不例外。QQ 无工作区，不能借后台转读本地资料。子任务的结果只回原域，后台完成通知不会直接发送 QQ 消息。

具体限制见[审批](approval.md)、[功能](features.md)和[项目说明与 skill](project-context-and-skills.md)。
