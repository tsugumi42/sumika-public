## 三、文件、来源与版本

### 3.1 包格式

基本布局为 `<name>/SKILL.md`，可带 `references/`、`scripts/`、`assets/`。SKILL.md 是 UTF-8 Markdown + YAML frontmatter；沿用旧规格：name 1～64 Unicode 字符，NFKC 后是小写字母/数字/连字符、无首尾和连续连字符，与目录名规范化后相同；description 非空且最多 1024 字符；license、compatibility、metadata 字符串表和 allowed-tools 按原类型校验。compatibility 最多 500 字符。BOM、LF、CRLF 可读；重复键、多文档 YAML、错误类型、未闭合 frontmatter 拒绝该包。原始字节留存，渲染的 LF 规范化单独算 digest。

`disable-model-invocation=true` 不进自动目录/检索/候选，模型不能借精确 ID 绕过；`user-invocable=true` 才可由宿主确认的直接用户点名加载。引用、转发、网页、技能正文和模型生成的“用户点名”不算。当前 execute 未给 Request.DirectUser 赋值，实施时必须从可信输入绑定，不能新增模型可填的授权布尔值。

allowed-tools 只作兼容说明，不预批准、不凭技能扩大或收窄工具集。context/agent/model/hooks、命令插值（例如感叹号加反引号）、自动安装依赖、自动 import URL 均不执行；包含这些字段时给明确兼容性诊断。手册能陈述依赖，宿主只检查可用性；缺依赖报缺什么，不临时下载运行时。

短卡保存稳定 ID、名称、描述、适用/排除条件及可选中英别名/最多三条查询例子。默认从 description 建卡；主人在宿主管理的旁注补充 aliases、when、unless、examples，不修改上游文件。每项短卡检索文本最多 4 KiB；不自动用正文、历史私聊或模型生成试题填例子。旁注影响检索版本，不授予权限。

### 3.2 存放与寻址

| 位置（均相对所选数据根） | 内容 |
|---|---|
| `config/skills/<name>/` | 现有主人自编/手工导入来源，继续受来源和真实路径读取审批约束 |
| `config/skills-registry.json` | 拟新增管理投影：稳定来源/包 ID、选中版本、角色/场合授权引用、旁注；坏文件阻止管理写入，不按空表覆盖 |
| `shared/skills/objects/<package-sha256>/<name>/` | 拟新增已验证、不可变整包快照；SKILL.md 和资源保持包内相对布局 |
| `shared/skills/records/` | 拟新增只追加安装/更新/回退/停用记录，含前后版本和管理操作身份；registry 可从记录重建 |
| `cache/skills/` | 拟新增下载暂存、BM25/向量派生缓存；可删除重建，不作来源、权限或版本唯一证据 |
| 编译内 `native/internal/skills/builtin/sumika/` | 内置说明书，仍以 `builtin:sumika` 精确引用，不被市场同名技能替换 |

这些是数据根内的职责位置；统一自管根/下载服务冻结时只在 paths 层映射，不借技能安装决定工具环境根。用户兼容目录默认不扫，项目发现遵循 ADR-206 的 worktree 信任；不自动扫描用户其他客户端、整盘或所有角色目录。

沿用宿主分配稳定 root ID、相对 scope、包名形成的 source ID；托管包的 root ID 对应稳定仓库来源与所选子路径，不能以磁盘版本目录、数组下标或短名称当身份。重排来源/搬数据根/更新版本不改变包 ID。同名裸名仍按旧规格固定来源顺序取胜者；候选和续读始终使用精确 ID，不按相似名称退到另一个包。

版本分开记录：请求的 branch/tag、解析出的完整 commit、Git tree SHA（若取得）、整包 SHA-256、单资源 SHA-256、短卡/索引版本。metadata.version 仅展示。整包 SHA-256 按包内规范相对路径的 UTF-8 字节排序，对每个普通文件写入长度前缀路径、文件长度和原始内容 SHA-256，再哈希；不以 mtime、SKILL.md 单文件哈希或压缩包字节冒充整包身份。附件改了也必须改变包版本。

目录快照是不可变对象，物理解析可按内容共享，按 Access 过滤后的目录/分词统计/缓存键独立；一个角色的 Scan 不能替换另一个角色的可见 entries。每轮绑定角色、会话、完整 Scope/账号、工作区 revision、授权 generation、ContextID 和目录 revision。正文第一次加载固定包版本；同 ContextID 下续读和相对资源读同一快照，不把新版 SKILL.md 与旧版脚本混用。手工来源发生修改使旧游标失效，重新从头读取；托管不可变快照则可续读已绑定版本。

## 四、常驻目录、加载与缓存

### 4.1 三层信息

1. 短目录：首次有效 OnContext 追加一份稳定 user/KindContext 资料块，含 ID、名字、一句描述、版本、未展示数量和 `skill({query:"..."})` / `skill({name:"精确ID"})` 用法。在该上下文中保留，不每轮重拼进系统提示。
2. 候选：每个被准入的新输入批次/有效插话至多选一次；追加 0～5 张短卡，显式点名/复杂组合最多 10 张。写明“可能相关，可不用；可继续检索；不提供授权”。候选不会自动展开正文，也不改变工具表。
3. 正文：主模型调用既有 skill name 分支，返回来源 ID、包/资源版本、资源相对基准、范围/完整性/续读游标与正文；由 Controlled 工具结果持久追加。选中的主文须读到 complete 才能声称已加载完整技能；预算不足时报告未完整，不把截断尾部当无需遵守。

预算沿用：短目录含框架 8 KiB、每页最多 20 项、单条目录描述至多 512 字符、单次正文/附件含框架 32 KiB、单文件 1 MiB、同 ContextID 各版本正文/附件累计 128 KiB（已用 + 在途预留原子计入）。同版本已接纳且仍可见的资源范围复用；并发同资源读取合并，丢弃不记已加载。重复正文实际再次接纳仍照旧扣预算。

库超过 20 项或 8 KiB 时，初始目录先给主人固定项，再给 builtin，再按稳定 ID 填到上限；不随本轮查询或热度改变。必须写明“展示 N / 可用 M，另有 M−N 项可搜索”，不能声称这就是全部技能。固定项装不下时报超额，不截半条。完整获准目录由检索访问，不能只搜索初始二十项；几百项不要求一次全塞进窗口。候选块含框架最多 8 KiB，同 ContextID 初始目录、目录变化和候选累计最多 32 KiB；临近上限停止自动候选并追加一次原因，保留主动查询和现有正文。正常压缩后重置，不靠每轮强制压缩躲预算。

### 4.2 时间与顺序

采用现有 runTurn 接点，示意中的每个方括号都是独立且保留边界的消息：

```text
第一次请求：固定 system/tools → 已有历史 → [短目录、候选等本轮参考] → [本轮用户输入]
读技能后：  上述消息原样 → [assistant skill 调用] → [tool 正文] → [assistant 回复]
下一轮：    上述已发消息原样 → [新候选或目录通知] → [下一轮用户输入]
```

这是在旧历史之后追加一个本轮输入批次；不在已经发送过的 user 内容上拼字，不把候选插到旧历史或 system 中。不为自动候选伪造 assistant 工具调用/结果。普通工具循环不重跑挑选；新插话改变任务时用新批次挑选并追加，已发批次保持原位。若选择器超时，主请求按退路继续；迟到候选直接丢弃，不在流式生成中改上下文。

安装/正常更新只发布新目录 revision，下一个安全输入边界追加增删/新版本通知；旧目录不回写。消息框架明确哪个版本被当前目录替代。单次目录变化仍受 8 KiB 限制，变化太多给 revision、数量和分页查询入口，不丢失权威目录状态。用户要求换用新版时追加新正文并说明后续使用版本，旧工具结果不改。

停止使用一个技能只追加任务作用域结束说明，不删旧正文；历史保留不等于之后每轮强制执行其工作流。不把任务手册语气写进表达学习/长期人设。压缩、空闲重建和新会话换 ContextID，按现行压缩规则重建短目录、清空接纳账本，正在执行的任务需重新加载必要正文；摘要中的“已读技能”不等于正文仍在窗口。

撤权、移除受信来源或发现包被篡改是例外：取消受影响回合/审批/扫描，禁止旧代次继续派发请求和接纳工具结果，换实例再按新权限组装。不能用“请忽略旧技能”收回已经给模型的秘密；已经发给提供商的内容不可撤回。停用立即阻止新加载，旧包对象保留到没有快照引用后再按现有清理规则处理，不边读边覆盖/删除。

### 4.3 能证明到哪

[设计推断] 对两次实际请求，若提供商、模型、工具定义/顺序、system、采样相关模板和缓存键不变，且旧 messages 的角色、内容块、tool_call_id、边界逐一相同，新技能内容只出现在尾部，则技能选择不改写旧输入前缀。设前次已发送输入消息序列为 P，本次为 P 加新尾部 T；旧 P 的可缓存部分仍具备复用条件。此结论不承诺提供商一定命中：最短缓存长度、TTL、断点、路由、负载仍会影响命中。

必须在 `requestFor` 拼出中立消息、`openaichat` 编码后及提供商实际适配后的请求上比较，记录首个变化的消息/块索引与稳定前缀 token 估计；不能只比较 Live.msgs 或拼成一个大字符串。缓存控制标记变化、旧消息边界消失也算变化。

现有 slim 可改普通旧工具输出，渠道 settle/Commit 可将本轮候选改成实际发出的话，压缩可丢旧参考信息。因此本规格只保证技能资料在同代次的保留，不声称整个 Go 请求目前总满足 P 关系：验证时单列这些变化原因；首个变化若落在既有技能目录/候选/正文，就是技能路径失败。受控正文必须保持 Controlled，候选/目录也不得被普通输出裁剪重写。安全撤权和正常压缩允许重建，必须换代并标原因，不能归成技能命中提升。

## 五、几百项时怎么挑

### 5.1 公共输入、索引与门槛

仅在 skill 工具对当前可信调用确实可见、来源获准且有候选时运行。先过滤角色/场合/来源/调用开关，再做召回和模型调用；拒绝项的名字、描述、数量、分数也不能泄漏。显式点名先解精确 ID 或确定裸名；“不要用 X”、引用中出现 X 不算直接调用。主模型始终可通过现有 query 分支补搜，包括候选未展示的合法包。

查询由当前输入（最多 2 KiB）、本会话最近两条必要的任务相关用户输入及任务目标/对象（合计最多 2 KiB）组成，顺序固定，总计 4 KiB、最多 64 个去重词项，UTF-8 边界截断并记 truncated。只从该角色可见上下文取，不额外召回别的角色/会话记忆。“继续/换一个”保留当前任务对象；无可用任务状态则允许空候选，不凭空补意图。排队等候的后续批次不能提前用。

安装、更新或旁注变化时增量建立索引，不每轮扫正文、重算技能向量或加载模型。名称/别名、适用说明、完整 description 分字段；中文保留单字及相邻二字词，英文按 Unicode 词界、大小写折叠，NFKC 仅用于检索键，不改原始 ID。专有名词精确匹配独立保留；否定/已完成意图留给后续判断，不能因有关键词就强制加载。

所有门槛是自动展示门槛，不是授权门槛。允许零候选；必须报告无技能误注入与必要技能误拒两头。上下文不完整或对候选不确定时保留补搜入口，不能因超时就把全部技能给主模型。

### 5.2 三种路径与工程初值

| 路径 | 召回与精排参数 | 输出与时限 | 失败退路 |
|---|---|---|---|
| `algorithm`（模型明确关闭时） | 字段化 BM25 k1=1.2、b=0.75，名称/别名:适用说明:描述权重 8:4:1；召回前 40。第二阶段用完整名称/别名词界精确命中、查询词覆盖率及 BM25 排序，平分按精确 ID | 暖路径 p50≤10 ms、p95≤30 ms，总截止 50 ms；0～5，明确组合最多 10；不调用嵌入、精排或生成模型 | 无匹配为空；索引不可用则在获准短卡上有界名称/关键词匹配。仍失败只留常驻目录与主动查询，聊天继续 |
| `small-model`（大库可选小模型挑选） | 先跑纯算法前 20 项，显式点名置顶；小模型读短卡与上述查询，输入≤4K tokens，temperature=0、关闭思考、输出≤128 tokens，仅 JSON `{ids:[...],none:boolean}`。不要求每轮读数百份正文/描述 | 模型阶段≤450 ms，含召回完整截止 500 ms；暖路径目标 p50≤250 ms、p95≤500 ms；0～5，多技能最多 10 | 未配置/关闭直接 algorithm；超时、异常、未知 ID、重复/矛盾输出、截断均整次退到本次已算的 algorithm，禁止第二次补问或自动换模型 |
| `hybrid`（检索 + 小精排） | BM25 与已授权本地嵌入各取前 20，按 ID 合并最多 40；RRF k=60，同权融合；现有小型本地 reranker 排前 20，批大小最多 20、每卡≤256模型 tokens、查询≤256模型 tokens | 完整暖路径 p50≤100 ms、p95≤250 ms，硬截止 250 ms；0～5，组合最多 10。BM25/融合预算10 ms，嵌入40 ms，小精排150 ms，余量为排队/IPC | 向量缺/版本不配/40 ms 超时：algorithm；精排不可用/150 ms超时：已完成的混合召回；总期限到立即使用当次已完成的合法结果，晚到不接纳 |

纯算法第二阶段初值：除显式请求外，要求至少一个名称/别名/适用说明词项命中、加权查询覆盖率≥0.35，且 `BM25/(BM25+4)≥0.45`；覆盖率中名称/别名精确命中的查询词权重为 2，其余为 1。这是可复算起点，不是已校准概率。精确点名不被相关性门槛丢弃，仍须通过来源/调用权限；同名不明确时给有权看到的来源供选择，不猜安装来源。

混合路径的 cosine 和 reranker 原始分数没有跨模型通用阈值。先用 algorithm 资格保底；额外纯向量候选仅在“模型权重+分词器+短卡格式+阈值版本”有独立验证集校准记录时进入自动候选。阈值按第十节同时满足误注入/误拒目标选择，缺校准时不自动放行纯向量项，主动查询仍可显示为“检索相关，未判断必要”。RRF 只融合名次，不能当绝对相关性概率。更换模型/短卡表示使旧校准失效。

“算法精排”指确定性第二阶段，不暗中调用神经模型；专用决策模型可作为 small-model 路径的受限选项评分实现，同样需支持多选/none 和同题验收，不能把 RouteLLM 的强弱模型路由当成技能分类器。4B 精排只做质量对照，不设为每轮默认。

超过 20 项或目录放不下时启用所选路径；少量技能默认只用目录 + 显式点名，不多一次生成调用。大库有明确配置的小模型时可用 small-model，主人关闭“挑选模型”必须令三种神经调用均为零并切 algorithm；不是只关生成但继续跑嵌入。hybrid 为显式选项，是否设为默认见待定项。

小模型路由复用现有预算化 ModelCaller、取消与用量记录，不调用裸 llm.Client 绕过根预算。每输入批次至多一次；增强调用全局最多 2 个、每会话 1 个，排队包含在 500 ms 内，余额不足直接 algorithm。不固定某供应商或下载任何新权重；具体模型及本地/网关路由由主人选，未配置不偷偷借主模型。检索/向量/选择结果缓存最多 128 项 LRU、5 分钟，键含规范查询、任务 revision、可见目录 digest、授权代次、模型/分词器/阈值版本；取缓存仍重查授权，不跨角色/会话复用语义判断。

## 六、安装、更新与卸载

### 6.1 市场与 GitHub 输入协议

管理面提供市场搜索、仓库探测、选择包、安装、检查更新、预览更新、应用更新、回退、停用/移除，后台一套命令服务供本机管理入口调用。返回实际状态、来源与错误；不让聊天模型通过 skill 工具安装。

市场搜索由主人明确输入关键词后访问 `https://skills.sh/api/search?q=<编码查询>`；使用 skills 数组的 id/name/source/installs，所有字段按不可信数据校验/转义。market id 仅标明发现入口；将 source 规范化为 GitHub owner/repo 后，和直接安装进入同一流程。市场结果缺来源、格式变化、非支持 host 时报告“不支持/协议已变”，保留直接粘 GitHub 仓库入口；不从页面拼出并执行安装命令。不把聊天原文或私有技能目录传给市场搜索/遥测。

直接输入支持 `owner/repo`、`https://github.com/owner/repo` 及 `tree/<ref>/<path>` / `blob/<ref>/<path>/SKILL.md`。内部一律用结构化 `{host,owner,repo,ref,path}`；不把 `@skill` 猜成版本号。ref 包含斜杠、URL 编码或 branch/path 分界不明确时要求在探测表单显式填 ref/path；不猜 main/master。省略 ref 先查 API 的 default_branch，再解析一次完整 commit，后续归档与资源都取该 commit。固定 commit 不追更新；跟踪 branch/tag 的条目更新也先解析成新 commit。

探测已下载并验证的归档，优先列根 SKILL.md、skills/ 及兼容容器，必要时有界扫描仓库：深度≤6、目录≤2000、条目≤20,000，跳过 .git、node_modules、构建缓存。发现只为本次管理，不扩大运行时源扫描。多技能仓库逐包列 name/description/path/许可证/脚本数量，让主人勾选；不默认全装。包有相对引用越过包根时标不兼容，不通过复制整个仓库解除边界。

### 6.2 下载与验证

走宿主统一下载服务，代理/直连沿用 ADR-273；没有该服务时先完成其契约，技能插件不另起任意网络下载器。只取公开 GitHub HTTPS 数据归档，不执行 git/npm/bunx，不递归子模块、Git LFS 或包管理器依赖。私有仓库、企业 GitHub、任意 URL/well-known 提供方留待主人定；失败不切 SSH、其他镜像或获取用户凭据。

工程限额：市场/API 单请求 10 s、响应≤2 MiB；归档 60 s、压缩传输≤32 MiB、解压总量≤128 MiB、条目≤20,000；单包≤16 MiB/2000 文件、运行时可读文本单文件仍≤1 MiB；同时下载≤2。先按流累计实际字节，不能只信 Content-Length；超限拒绝本次发布，报告包太大，允许主人改选子路径后重新探测，不悄悄截包。

下载域名与每次重定向目标逐跳校验，DNS/连接地址均过内网检查；GitHub API 认证头不转交其他 host。归档逐条限制真实目标：拒绝绝对路径、点点段、反斜杠绕过、盘符/ADS、UNC/设备名、尾点/尾空格、大小写或 Unicode 规范化冲突、重复文件、symlink/hardlink/junction、特殊设备；先验证后写进自己的暂存根。类型不明拒绝，不把链接转成普通文件继续。

允许源码脚本和模板作为不可信文件保存；拒绝 PE/ELF/Mach-O 等二进制程序、安装器和加密/嵌套自动解包内容。scripts 可以通过受限资源接口按文本读，安装、索引、加载、更新都绝不执行它，不运行 hooks、postinstall 或下载其依赖。assets 的普通图片可存；运行时 skill 工具仍只读文本，不为二进制发明隐式加载路径。上游脚本今后要执行需独立授权的工具/可丢弃环境，受 ADR-277 限制，本规格不提供执行入口。

记录传输归档 SHA-256、逐文件清单与整包 SHA-256、解析 commit 和取得的 tree SHA。哈希只证明传输/存储一致与可复现，不证明作者可信；无上游签名不能标“已验官方签名”。若来源声明校验值则核对，不符拒绝；来源换仓库/路径/维护者不得借同名自动继承信任。许可证保留原文，缺失明确标未知。

### 6.3 发布与更新一致性

顺序固定：解析来源/commit → 下载至宿主暂存 → 路径/限额/格式/校验 → 构建短卡与索引 → 展示来源、diff、权限影响 → 主人管理动作确认 → 不可变对象入库 → 原子发布 registry revision 并记录管理事件 → 下一安全输入边界通知。预览令牌绑定来源、commit、包哈希、registry revision、操作者与所选授权；发布前变化则预览失效。未批准前内容不进角色模型/选择器。

对象、记录、registry 跨文件发布由宿主单写者串行处理：先落盘对象，再写含目标 registry revision 的提交记录，最后原子替换 registry 投影；启动时按已提交记录重放。提交记录成功后取消只能报告“已发布”，不能假报未安装；记录前失败/取消保留原 registry，孤儿对象可回收。磁盘满、占用、杀进程后只见完整旧版或完整新版，不见半个包。多个独立包的批量更新逐包提交，报告成功/失败，不把部分成功叫全批成功。

检查更新只查已登记来源的精确 ref/path；可用 ETag/条件请求，手动检查与拟议每日检查共用缓存。401/403/429、网络失败、404、上游路径删除分别标“无权限/限流/不可确认/来源已移除”，不当“当前最新”、不删除现有可用版本。检查不自动切版本；是否定时、自动应用见第十二节。

更新预览列新增/删除/修改文件，含 references/scripts/assets，旧/新 commit、哈希、兼容性与来源变化。手工来源绝不自动覆盖；托管对象与记录哈希不符视为篡改/本地改动，停止使用并通知，主人可导出为自编来源或重新取回已知版本，禁止批量强盖。新增技能不因同仓更新自动启用；权限旁注不由上游覆盖。回退也通过记录与原子切换，不改旧对象或历史工具结果。

停用/移除先撤新入口、取消受影响旧代次，再切投影、通知和换实例；等待读取/下载/选择器真实退出后释放快照。晚到结果不能以同名新安装包的身份接纳。被模型已看过的正文、聊天历史、审批记录不会因“卸载”被擦掉。

## 七、角色、场合与来源安全

有效集合为“插件已启用 ∩ 已接纳版本 ∩ 当前角色授权 ∩ 场合/发起人授权 ∩ 来源读取审批 ∩ 调用方式允许”。安装不等于给所有角色启用，角色卡写某技能名也不授予权限；用户选择公开来源不意味着任意本机路径免审批。按来源授权只扩大读取清单，不替代旧规格受保护目录逐次读取审批；是否给托管根专门读取授权须主人决定。

下表是保留现行限制的规格基线，不是本次新开的默认值；每一格的目录、短卡、正文、附件一并限制。

| 场合 | 技能读取与候选 | 执行与安装 |
|---|---|---|
| 本地私聊 | 主人可信入口、该角色和本会话获准来源才可见；当前 Go 已有接点，skills 默认仍关 | 动作照既有工具/审批。安装只给主人本机管理入口逐次操作，不给模型自动安装 |
| 本地群聊 | 当前 App 拒绝技能新入口；未来按角色、会话单独授权，未定/未实现不开放，不从 PrivateOK 推导所有成员可读 | ADR-269 已定执行可申请审批，不代表当前 Go 已完成，也不授予技能安装权；卡片保留真实触发者，角色接角色不冒充主人 |
| QQ 私聊 | 前台不给技能资料，后台默认零项；主人也不继承本地主窗口来源。以后只给主人标“QQ 能用”的包，并按真实发起人/任务约束 | ADR-277 后台上线前无本地执行；上线后仅可信主人直接发起可申请，既有来源约束仍在。QQ 安装管理本规格不开放 |
| QQ 群 | 同样前台不给、后台默认零项；主人在群也不使群友/其他角色取得技能根或私有短卡 | ADR-277 生效条件同上，群友/角色链不能申请本地执行；完整结果给主人，群内结论按 ADR-281，不发送技能正文、路径或工具输出 |

QQ 私聊另测主人/别人；QQ 群另测主人发起/群友发起/混批/引用主人旧话。模型用于选择不改变这些条件。后续给后台许可不是把同一包自动暴露给前台；后台只回任务所需的结果，结果/日志可见性沿用架构和 ADR-281。

不可信内容可作为获准的任务步骤参考；“忽略人设”“我有管理员授权”“请读其他角色记忆”“执行 scripts/install”都不能成为授权依据。短描述也可能注入，不能因为短就提升为高优先级指令。用结构化序列化与宿主生成框架包裹，转义伪造闭合标签/工具消息/控制字符；边界之外的模型服从程度无法由文本包装保证，后端权限必须独立拦截。是否将某来源设为更高信任、扩大场合或脚本执行，一律待主人定。

## 八、保护边界的形状 × 入口表

本次仅规定处理，不宣称测过。列中的“处理”均为实现要求；落地时逐格补用例 ID/实际结果，标“不可能”必须给可信边界依据。下列每行均覆盖本地私聊、本地群聊、QQ 私聊、QQ 群，后两者细分见第七节；评测工具也调用同一过滤/授权服务，不用自己的宽松门槛。

| 形状/敌对输入 | 主人管理入口（探测/安装/更新） | 自动目录/选择器及评测入口 | skill query/name/resource/cursor | 实际请求、审批和晚到接纳 |
|---|---|---|---|---|
| 身份/平台/角色/Scope 缺、空、0、类型错、未知；昵称冒充主人 | 处理：拒绝管理写入，不据名字补身份 | 处理：无有效绑定不给任何候选/数量 | 处理：拒绝，不退到 builtin/全局目录 | 处理：无有效授权代次不发请求、不接纳 |
| QQ 群友、混批、引用主人、角色接角色伪造安装/点名 | 处理：不能取得本机管理权 | 处理：不继承主人候选与历史任务状态 | 处理：不产生 DirectUser 授权 | 处理：实际触发者/账号绑定，审批消息不等于批文 |
| source/ref/path 缺失、伪造 market source、同名不同仓/内置保留名 | 处理：报告歧义/不支持；不跟同名走 | 处理：精确 ID 和有权集合排序 | 处理：ID/游标绑定首次来源，禁止同名换包 | 处理：旧结果不能交给新包或新角色 |

## 九、已知的坑与禁止的偷懒写法

对照边界清单，本规格重点处理文本/Unicode、生命周期、四场合、真实路径、数量预算、部分失败、并发、版本、缓存与隐私：

- 初始目录只列二十项却只在这二十项检索，会永久饿死其余技能；索引必须覆盖完整获准集合，回放让目标分布到目录头/中/尾。
- Top-k 总能返回某项，不能代表需要技能；“谢谢”“别截图”“刚才已经做完”需有真实负例，“继续”需带正确任务对象。
- 精排救不回召回漏项；相似技能和多技能组合分开标注，Hit@5 不能代替全部必要技能覆盖。
- 安装成功但权限未给、目录还旧、索引未切换是不同状态；显示已安装/未启用/待读取审批/不可用，不能假报已可用。
- 首次 Scan 的授权可不同，Catalog 全局可变 entries/全局 BM25 统计不能泄漏另一个角色；缓存键少账号、作用域或 generation 都会串权。
- 主文没变、附件变了仍需新包版本；目录版本不等于正文版本。反复命中解析缓存也不代表模型缓存命中。
- 旧正文仍占窗口；不能为省 token 每轮删旧技能、改旧 user 消息、只在当前请求临时插资料，或把模型已选名单累加回 system/tools。
- 来源不明不等于不存在；网络错误不删包、换来源或自动重新安装。强行覆盖用户本地改动、未知锁格式按空表重建均禁止。
- 禁止执行远程安装命令、技能 hooks/插值、自动补依赖；禁止把扫描通过、市场排名、Git commit 或本地 SHA-256 描述成安全审计结论。
- 禁止把身份/人设/权限拆成可选技能；禁止仅凭描述里的“必须”把技能变成长期全局规则；禁用技能不得借附件/精确 ID/缓存再次读入。
- 禁止用静态源码检查或假模型回声冒充端到端质量/缓存验收，禁止把本规格预算写成已经测到的延迟。

## 十、量测与验收

### 10.1 同题数据与口径

实施时先固定 500 个真实来源技能（含相似技能与不同来源同名），再用 50/200/500/2000 项库分别量。查询集至少 600 条：200 条无需技能、200 条单技能、100 条同义/跨语言/相似竞争、100 条多轮/否定/已完成/组合；组合至少 40 条。以人工编写和获准脱敏真实回放为主，训练/旁注示例、校准集、最终测试按会话与技能族分离，最终测试不拿来挑阈值。标签允许多个等效技能集合，区分必要与可选项。

同题、同短卡/正文版本、主模型、权限、上下文和工具结果，交替三遍比较：仅稳定目录、algorithm、small-model、hybrid；hybrid 再分别去掉精排作消融，不把所有阶段效果归给模型。角色聊天另做匿名版本盲评，人设一致性与打扰分开；干活按真实产物/操作证据判完成，不只看“模型说完成”。外部公开基准只作参考，不能代替中文技能数据。

| 指标 | 计算/报告要求 | 暂定验收目标 |
|---|---|---|
| 召回/候选命中 | Recall@20 为必要技能召回比例；Hit@5 为至少一个必要技能命中；Completeness@10 为某个等效必要集合全部覆盖；分单/多技能及库规模 | 召回≥95%、Hit≥90%、组合完整覆盖≥90%；各路径独立报，不拿大库平均掩盖尾部失败 |
| 拒选与误用 | 无需技能却给候选/加载正文；需要却给空/未加载；分“没召回、没展示、展示没读、读后做错” | 无技能误展示≤5%、必要技能误拒≤5%；主模型误加载另报。algorithm 与模型路径差值必须公开，不预言降幅 |
| 任务完成/人设 | 每题验收产物；失败含超时/拒绝/无结果；聊天盲评按固定量表 | 相比仅目录组不劣于2个百分点，配对置信区间须支持该结论；样本不足标“未证实达标”，不按点估计宣称通过 |
| 选择耗时 | 从输入已准入、准备挑选至最终合法候选/退路可用；含分词、IPC、排队、所有阶段 | 三路径按第五节预算；冷启动和超时退路单报，不能把空结果/失败当快速成功 |
| 首字与总时延 | 用户输入接纳→可见正文首字，另记主模型请求→首正文及思考首 token；全任务耗时 | algorithm 相对仅目录组 p95 增量≤50 ms，small-model≤500 ms，hybrid≤250 ms；同时报告完整 TTFT 分布 |
| 缓存与容量 | 原始 usage、cache read/write、首个变化位置、稳定前缀比例、短目录/候选/正文 tokens、压缩频次 | 稳定非压缩同代请求：技能旧块改写为0；满足服务商长度/TTL的暖请求读缓存比例目标≥90%，且比仅目录组下降不超过2个百分点 |
| 成本与资源 | 主模型+选择器+嵌入/精排完整费用/用量、未知费用、CPU/GPU/内存/显存、并发冲突 | 根预算不超派发上界；模型关闭时神经选择调用为0；选择器不能饿死主模型，延迟目标在同机并发下仍成立 |

当前 Go `llm.Usage.Input` 已扣除缓存读/写，总输入为 `Input+CacheRead+CacheWrite`，读命中比例为 `CacheRead/总输入`；来自 [llm.go](../native/internal/llm/llm.go) 的统一口径。OpenAI cached_tokens 是总输入内明细，Anthropic 原始 input/cache_creation/cache_read 要相加；缺 usage 标未知，不能记零或照搬历史 pi 的两项公式。聚合用 token 加权，不平均每轮百分比。

缓存对照固定模型/提供商/路由、工具表、缓存键、warmup、TTL 内间隔和消息边界；冷启动、TTL 到期、压缩、权限重建、渠道结算、普通结果 slim 各自标原因单列。读缓存达标而正文被删仍失败；前缀稳定但服务商没给命中也不能伪报通过。源码位置推断和真实 hit-rate 分开写。

## 十一、实施分步与交付边界

每步独立提交、可整步撤回；保持现有 `skills.enabled=false` 与场合限制，产品待定项未决时不以暂定工程值扩大可见范围。前置是干活任务入口、预算化模型调用、授权代次/受控结果契约，以及宿主统一下载/原子发布服务；尚缺的在相应所有者处完成，不在技能包内造旁路。

| 步骤 | 完整交付 | 过关证据与同时更新 |
|---|---|---|
| 1 格式/快照/目录 | 复用并补全 Catalog、不可变来源版本、授权过滤、全库 query、来源/版本结果框架、显式点名可信绑定 | S1/S2/S7；同步旧规格技能节、config/示例、runtime/tools 参考和内置说明书，清除重复描述 |
| 2 持久追加 | 目录/候选预算、接纳账本、正常更新通知、受控正文保留、压缩/撤权换代 | S3及S7/S8相关路径；实际请求证明边界，架构若改变契约同提交更新 |
| 3 纯算法 | 增量短卡/BM25、确定性第二阶段、none、多轮任务输入与完整补搜 | S4 algorithm组与首批真实脱敏任务；记录尾部技能覆盖和关闭模型零调用 |
| 4 模型挑选 | small-model 与 hybrid 显式模式、受限输出/校准、共享预算/期限/取消，关闭及异常退路 | S4全部、S8资源与S9对照；达不到质量或预算不宣称默认可用 |
| 5 安装与管理 | skills.sh搜索、GitHub探测勾选、验证发布、版本/校验、更新预览、应用/回退/停用、重启恢复 | S5/S6/S7；统一后台命令服务与实际管理入口一起交，不能只留下载函数。界面按当时设计规格/设计自查单独量 |
| 6 联合验收 | 固定数据/版本/权限的三遍对照，全部S项、保护表、实际任务与缓存同测，完成产品待定授权再开放 | S1～S9逐条结果；未达门槛写实际数字。更新状态头/待办/路线图；合并由主会话另行办理 |

每步完成后移除临时测量脚手架；量测证据按项目约定存主工作区 data/dev，文档只引用长期位置。实现时正常跑相关检查，合并前按既有 Go 验证流程；本次文档分支只跑文档/提交钩子，不合并。
