## 一、要做成什么样

| 层 | 写什么 | 用什么写 | 改了怎么生效 | 谁写 |
|---|---|---|---|---|
| Go 内置插件 | 回合、记忆、QQ、审批、链接解析这类要性能、要碰内部的 | Go，编进程序 | 重新编译、重启（实测改一个文件到看见效果 5～10 秒） | 我 |
| TS 热加载插件 | 新工具、链接规则、钩子、定期任务的脚本这类扩展 | TS，跑在进程内的 moejs | 存盘就重载，不重启 | 主人、她自己、我 |

两层都在同一张插件表里，设置页“插件”分类一行一个，能开能关；她能看到装了哪些（客户端自知，ADR-317）。npm 上要 Node 内置模块的大包（pi、OpenCode 插件）这一版不接（ADR-359 第 2 条）。

## 二、第一步：Go 内置插件有清单、能开能关

在现有 `turn.Plugin` + `Registry` 上补，不另起一套：

1. **清单**：插件可以另外实现 `Manifest() turn.Manifest`，字段：`ID`、`Name`（中文）、`Sub`（一行说明，照设计语言第十一节）、`Requires` / `Provides`（服务名）、`Essential`（关不掉的，比如审批）、`Settings`（一个结构体，字段带 `title`、`desc`、`min`、`max`、`enum` 标签）。没实现的当作“没有设置、能开关、无依赖”。
2. **服务**：`Registry.Provide(name, v)` 和 `Registry.Service(name)`；插件停掉时它提供的服务一起撤掉，依赖这个服务的插件先停（照 Magpie 的 `Reconcile`：先停该停的，从新往旧；再起该起的，反复直到起不动，起不动的记“等服务”）。
3. **开关**：配置 `plugins.<id>.enabled`（布尔，缺省开）。设置页改了走现有的受限写配置，写完立即 `Reconcile`，不重启；某插件 `Setup` 出错或 panic 记“启用失败”，它注册过的撤掉，别的插件照常。
4. **设置成表单**：`Settings` 结构体在启动时转成 `settingsreg` 的条目（路径 `plugins.<id>.<字段>`），设置页照现有画法画，不另写标题表。值改了：插件实现了 `Reconfigure(cfg)` 就当场调，没实现就停了再起（界面写“重载插件”）。
5. **先接三个**：链接解析（`linkplugin`）、生活工具（`lifetools`）、用户钩子（`userhooks`）补上清单，作为样板；其余插件以后碰到再补，不一次改完。

**第一步实现注记（2026-11-12，feat/plugin-step1）**：以下是和上面写法不一致或没写到的地方，以本注记为准。

- 清单、服务、依赖、启停（第 1～3 条）已做：`native/internal/turn/plugin_reconcile.go`。Reconcile 的停的顺序按启动序号、依赖方先于提供方；Setup 和 cleanup 在 `reconMu` 之内跑，所以 Setup 里不许调 Hub 的 Use、StopPlugin、Reconcile（会死锁）；`StopPlugin` 从别的协程调会等 Setup 跑完。
- 开关写成 `plugins.<id>.enabled`，和 `sumika.example.yml` 里写的 Bun 约定一致（`plugins.sessions` 保留，不能当插件 id）：`native/internal/config/plugins.go`。没写 enabled 的由装配处定默认；用户钩子默认跟 `hooks.enabled` 走，不另做迁移。
- `Reconfigure` 没有参数：插件自己读配置（样板插件本来就每次调用读），实现了就当场调，出错或没实现就停了再起。`Settings` 结构体的字段读成设置字段（标题、说明、范围、枚举来自标签）：`native/internal/turn/plugin_settings.go`。没接进 settingsreg 和设置页，也没有写回路径（下一步）。
- 生活工具停了再起会新建假日数据（旧的 Close 后取消了后台）；链接解析关着时不接收本地链接去取。
- 没做：设置页“插件”分类的一行一个和开关（现在还是旧的名字列表），`desktopread` 的投影，settingsreg 条目，其余插件的清单（只补了三个）。


## 二点五、插件日志（第一步和第二步之间做）

主人 2026-11-11：“每个插件是不是各自应该有各自的日志方便追踪问题才对？……平时也没法分析出哪里运行质量还不够好吧”；11-12 链接解析“很多没发成功”，Go 的桌面日志里只有两条取数失败，查不清（R-198）。Bun 线已照第 5 批规格 9.7（私有存档） 做完，Go 照同一个格式做，**文件、字段、清洗、上限、保留天数一字不改**，这样 `bun server/src/plugins/stats-cli.ts --data <数据目录>` 能直接读 Go 写的日志（它只读文件，不算动冻结的 Bun 后台）。

1. **包**：`native/internal/plugintrace`。路径 `<数据目录>/logs/plugins/<插件 id>/<本机日期>.jsonl`；字段白名单 `site`、`route`、`url`、`ms`、`result`（ok / fail / skip）、`kind`、`error`、`note`；`t`、`plugin`、`gen`、`event`、`tool` 宿主填。清洗、每天 20000 行加 `host.limit`、保留 30 天、写不进去只记一次宿主日志不抛错，全照 9.7。
2. **插件这一面**：`Registry.Trace(plugintrace.Event)`，所有插件都有；TS 热加载插件以后经 `sumika.trace` 交同一种（第三节）。
3. **宿主自动记**：`host.load`（启用成功、失败带原因）、`host.unload`（停用原因）、`host.tool`（每次工具调用：结果、耗时、失败分类）。在第一步的 `Reconcile` 和工具执行那里记，插件不用管。
4. **链接解析先接**，比 Bun 多记“发”这一段（主人说的是“没发成功”）：
   - 取数：每个链接一条，`site` 平台、`route` 线路或来源、`url` 清洗后的链接、`ms`、失败的 `kind` 和 `error`（带 HTTP 状态、底层原因），照 9.7；
   - 展开和发送：每条展开一条，`site` 平台、`route` 是 `send`；没发的 `result: skip`、`note` 写原因（开关关着、去重、频率限制、群档位、闸门拦了、超时），发了但失败的 `fail` 带发送错误。
5. **生活工具接上**：免费接口每次尝试一条，照 9.7。
6. **验收**：链接插件对一条消息走完取数、发送，各写一行、格式和 9.7 的例子逐字段对得上；`stats-cli` 读 Go 写的文件能出汇总；伪造的 `plugin`、`event` 字段没效果；超过每天上限写 `host.limit`；没给数据目录时不写；写失败不影响回合。测试用临时数据目录。

**第二点五节实现注记（2026-11-12，feat/plugin-trace）**：以下是和上面写法不一致或没写到的地方，以本注记为准。

- 包 `native/internal/plugintrace`。`Event` 是 Go 结构体（`Site`、`Route`、`URL`、`Took` + `Timed`、`Result`、`Kind`、`Error`、`Note`），没有 `plugin`、`event`、`t`、`gen`、`tool` 字段，伪造在类型上就不可能；字段里塞的 JSON 片段只是那个字段的字。
- 对拍：`trace_bun_test.go` 用同一批刁钻输入（转义序列、各种换行、超长、表情、网址的各种写法、令牌段、非整数毫秒、坏的 result）让 Go 和 `server/src/plugins/tracelog.ts` 各写一份，逐行一致；再起 `bun server/src/plugins/stats-cli.ts --data <临时目录> --json` 读 Go 写的文件出汇总。没装 bun 跳过，子进程环境清掉 `GIT_*`。
- 网址清洗照浏览器的 URL 解析写常见部分（主机小写和国际化域名转 ASCII、去默认端口、反斜杠当斜杠、解 `.` 和 `..`、路径按 Bun 实测的编码集编码，比 WHATWG 多编 `^`）；数字主机名的变体（`0x7f.1`）、IPv4 映射的 IPv6 不保证和 Bun 一字不差。
- 宿主：数据目录用 `turn.Config.Data.Root`（装配处本来就填了），没配不写。`host.load` 成功 note 写“代号 N”、失败 `kind: apply`；`host.unload` note 写“关掉了”或“依赖的服务 X 没了”，cleanup 慌了记 `fail`、`kind: cleanup`；`host.tool` 的失败分类是 `gone`（插件停了或换了）、`denied`（听众不能用）、`timeout`（这一轮到了总时限）、`error`（工具报错、慌了、回了出错结果），这一轮被停下记 `skip`、`kind: canceled`；准备时就拒掉、执行前绑定失效（没走到工具）的也各记一行 `gone` 或 `denied`。`host.context`、`host.seen` 这一步没接。
- 链接插件：取数每个链接一条（展开和“给她看”同时取同一个链接时只记展开那一次）。发送每个链接一条，`route: send`；没发的 note 是固定的几种：补录、去重（同一条重复送到 / 同一条消息里重复的链接）、开关关（自动展开没开 / 网站或页面类型）、白名单外、黑名单内、不能触发展开、取数失败、没取到内容、结果为空、发送条件不齐、源消息不再允许展开、闸门（QQ 发送已暂停）、超时、取消了、超出一条消息的展开上限、队列满、同一条消息里前面的链接记关联失败。读不到回执（库读失败）也按结果不明记。发了没成的 `fail`：`kind` 是 `rejected`（有段没送到，error 写哪一段、什么原因）、`aborted`（中途被中止）、`prepare`、`submit`、`store`（记关联失败）；有段结果不明的记 `fail`、`kind: unknown`（可能已经发出去了），退了文字版的记 `ok` 加 note。宿主的发送许可用 `linkplugin.Blocked` 带原因，插件据此记 skip 而不是 fail。补录、重复、白名单外这类只在消息里有能展开的链接时记，没链接的消息不写；自己号发的、陌生人、自检、角色、不能触发展开的补录和重复消息也不写。
- “频率限制”在链接展开的发送路径上没有（展开不走群闸门的频率，只看 QQ 发送有没有暂停和发送条件），所以没有这一种 note。
- 生活工具：`freeapi.Options.Trace` 每次真的调提供方后回调一次（探测不调），`url` 是包了一层传输记下的真请求地址；错误文字里的网址按同样的规则清洗（Go 的 http 错误会带查询串里的坐标）。用户自配假日地址取数也记一条（`site` 主机名、`route: holiday`）。
- 顺带修了链接插件四处（2026-11-12 读码发现）：提前 return 跳过收尾、开始表情一直挂着（收尾挪进 defer；关闭、许可撤了、源消息撤回时发送本来就过不了许可，收尾只记日志）；`linkexpand.Build` 返回空段时静默跳过；补录的链接没有任何记录（照规格-QQ收消息与补录 I-27 不展开，只补记录）；卡片载荷解析出错被吞（`linkreader.ParseCard` 带原因）。

## 三、第二步：TS 热加载插件（moejs 宿主）

1. **放哪**：数据目录 `plugins/<id>/plugin.ts`（以后可以多文件，入口固定 `plugin.ts`）。id 只认小写字母、数字、连字符；和 Go 内置插件同名的不加载，插件页写原因。
2. **长什么样**：
   ```ts
   export const manifest = { name: "查汇率小工具", sub: "按币种查今天的汇率" }
   export function setup(sumika: Sumika) {
     sumika.tool({ name: "fx", description: "…", parameters: { … }, async run(args) { return "…" } })
   }
   ```
   这一版宿主只给：`sumika.tool`（注册工具，走内核的审批和总时限，和 Go 工具一样）、`sumika.log`、`fetch`、插件自己目录下的文件读写（`node:fs`，根是 `plugins/<id>/files/`）、`setTimeout`。钩子（回合定了、看到新事件）第二版再开。
3. **热加载**：监视 `plugins/` 目录，文件变了等 300 毫秒（编辑器先写临时文件再改名会连发几次）再重编。编译失败旧版本照跑，插件页写错误和行号；编译成功先撤掉旧版本的所有注册，再跑新版本的 `setup`，在跑的那次工具调用结果照旧用旧版本的（和 Go 的“当轮绑定原注册”一致）。
4. **运行**：每个插件编译一次 `Module`，一个运行时池；一次调用取一个运行时，用完 `ReleaseCallData` 放回。兜底只用 moejs 自带的：
   - 内存上限 `MemoryLimit` 64 MiB；
   - 时限：工具 30 秒、`setup` 5 秒，到点 `Loop.Interrupt`，复用前 `ClearInterrupt`；
   - `fetch` 只放行 http / https，目标地址过 `netsafe`（不连本机和内网，免得调自己的接口，ADR-106 第 1 条）；
   - 文件只在自己目录里，路径过 `safepath.Inside`；
   - 不给环境变量、不给起进程、不给读别的插件和数据目录。
   其余交给审批、日志和反馈（ADR-359：引导加简单兜底）。
5. **工具怎么过审批**：`OnTool` 只认编译期的 `policy.Specs`，热加载的工具不在里面。宿主走一个只给它用的新入口 `Registry.OnScriptTool(t, spec)`，spec 由宿主写死、插件不能声明风险等级：
   - 名字一律加前缀 `plugin_<id>_`，不会和内置、Go 插件的工具撞名；
   - 效果 `net` + `write`（能联网、能写自己目录），放行档 `TierScoped`：手动档每次问，卡片上能记成“这个对话”“记住”；自动档只放只读的；YOLO 放行；
   - 给谁：缺省 `owner-console`（主人 × 主窗口，本地私聊、本地群聊里主人说话时）。要给 QQ 用得在插件页打开，打开时写明“群友也能让她调用这个工具”，这时按 `TierOpen` 放行（内网、大小、时限的边界在宿主那里）。
6. **`fetch` 的内网拦截在拨号层**：`webapi` 的 `http.Client` 用自己的 `Transport`，`DialContext` 先解析再用 `netsafe` 判每个 IP、按判过的 IP 连（照 `linkreader/fetch.go` 的 `safeDial`），不查 URL 字符串；重定向每一跳都重判。
7. **新插件**：她用写文件工具写进 `plugins/`（写文件本来就要主人批）就会自动加载并开着；插件页新出现一行“新装”，第一次调用在日志里记。主人随时能关、能删。

## 四、以后的步骤（先不做，挂在这里）

- **配置按插件家族分文件**：`config/<家族>.yml`，子插件通过主插件的服务读，只写改了的那个文件，写前备份、原子替换（原规格 2.2）。
- **三种生效方式**在设置页写清楚：立即 / 重载插件 / 重启（原规格第三节）；QQ 这类会断连接的，重载前等在发的回复最多 10 秒，断开期间的消息重连后补录（原规格 3.1）。
- **主窗口扩展点**：导航入口、设置分类页、右栏标签、消息右键菜单、命令面板、通知类型，插件声明数据、主窗口用组件画；1.0 插件不带自己的界面组件（原规格第四节）。TS 插件开放钩子、扩展点时另写一节。

## 五、参数

| 参数 | 值 | 理由 |
|---|---|---|
| 重编等待 | 300 毫秒 | Windows 编辑器存盘常连发 2～3 个事件 |
| 内存上限 | 64 MiB / 运行时 | moejs 文档示例值，工具脚本够用 |
| 工具时限 | 30 秒 | 和 Go 工具的默认总时限对齐，取更小的那个 |
| `setup` 时限 | 5 秒 | 注册不该慢；超时算启用失败 |
| 运行时池 | 每插件最多 4 个 | 工具调用并发低 |
| moejs 版本 | 锁 v0.1.0，升级照 ADR-213 | 刚发正式版 |

## 六、禁止的偷懒写法

- 不起 Bun / Node 子进程跑 TS；不用 `eval` 拼字符串执行。
- 不给 TS 插件直接摸数据库、配置、别的插件的服务；要的能力一律通过 `sumika.*` 宿主函数开，一个一个加。
- TS 插件注册的工具不绕开内核审批；不因为“是插件”就给始终允许。
- 测试里等重载不用固定 sleep：宿主发“重载完成 / 失败”事件，测试等事件（LESSONS：固定等待改事件同步）。
- 设置页不为插件另写一份标题表；清单是唯一出处。
- 开关不重启整个后台；`Reconcile` 只动该动的插件。

## 七、已知的坑

- moejs 去类型的做法和 Node 一样：带值的 `enum`、`namespace` 会被拒，插件页要把错误原样给出来，文档写明用 `const` 对象代替。
- 运行时一次只能一个协程用；别的协程只能 `Interrupt`。事件循环睡着时 `Runtime.Interrupt` 叫不醒，要用 `Loop.Interrupt`。
- 中断要是在没代码跑的时候到，会打断下一次调用：放回池子前必须 `ClearInterrupt`。
- 编辑器存盘可能先删再建：删除事件不立即卸载，等 300 毫秒看文件回没回来。
- 插件抛的错、`InterruptedError`、`MemoryLimitError` 都要变成工具的错误结果给模型，不能让后台崩；panic 也收住。
- 现有插件的 `Setup` 里有的会起后台协程（比如 `lifetools` 的探测）：停用时靠它返回的 cleanup 收，补清单时逐个核对 cleanup 真的收干净。

## 八、验收

第一步：
- 一个测试插件声明 `Settings`，设置页出现对应行（标题、说明来自标签），改值后 `Reconfigure` 被调到；没实现 `Reconfigure` 的被停了再起。
- 关掉一个提供服务的插件，依赖它的插件先停、状态写“等服务”；再打开，两个都回来。`Setup` panic 的插件状态是“启用失败”、注册撤干净（放回旧代码就红）。
- 链接解析、生活工具、用户钩子三个有清单，能在设置页关掉、再打开，关掉期间对应工具从清单里消失。

- 写一个 `plugins/hello/plugin.ts` 注册工具，不重启，本地私聊里她能调到；改文件里的返回文字，下一次调用就是新的；写一个语法错，旧版照跑、插件页显示错误行号；删掉文件，工具消失。
- 沙箱：死循环在 30 秒被打断、工具返回错误；分配超过 64 MiB 返回内存超限；`fetch("http://127.0.0.1:…")` 被拒；读 `../` 之外的文件被拒；每条都是“放回旧代码就红”。

- 测试全用临时数据目录；重载用事件同步，不用固定等待。

## 九、公共素材服务（图标、表情、字体）

> 状态：Go 内置插件的接口已做（2026-11-13，分支 feat/shared-assets）；TS 插件那层只有下面的接口草案，没实现。

主人 2026-11-12（R-216）：“以后这些插件如果需要icon、字体和emoji的话是不是可以直接从软件内带的mingcute、twemoji社区仓库版和文渊圆体使用”“文渊圆体和maple都放字体目录吧……默认应该从系统自带字体里选的”。
所以图标、表情、字体做成一个公共服务，界面、推特卡片、插件都从它取，不各抄一份、各找一遍。

**素材**（代码在 `native/internal/assets`，来源和许可证汇总在它的 `THIRD_PARTY.md`）：

| 素材 | 包 | 说明 |
|---|---|---|
| 图标 | `assets/icons` | MingCute 全套（`mingcute_icon` 2.9.72，Apache-2.0）1658 个，line、fill 两种，生成进 Go 源码（`scripts/gen-mingcute.ts`）；按名字取（`add`、`arrow_down`，MingCute 官网上的名字去掉 `_line`、`_fill`），不存在返回 `ErrUnknown`；含渐变和内嵌位图的 8 个没收（`loading*`、`apple_intelligence`） |
| 表情 | `assets/emoji` | 社区版 Twemoji（jdecked/twemoji v17.0.3，图形 CC-BY 4.0）4009 个 SVG；切序列（VS16、零宽连接、肤色、旗帜、键帽）和按序列取图一份，chatui 的回应表情和推特卡片共用；图在 `native/twemoji/`（`scripts/update-twemoji.ts` 下载），不进 git |
| 字体 | `assets/fonts` | 按用途给一串字体文件：文渊圆体 → Maple Mono NF CN（`fonts/` 里按字重取）→ Windows 自带固定名单（微软雅黑 `msyh.ttc`、Yu Gothic `YuGothR.ttc`、Malgun Gothic `malgun.ttf`、Segoe UI Symbol `seguisym.ttf`、Segoe UI `segoeui.ttf`，只到 `%WINDIR%\Fonts` 按文件名找，**不扫系统字体目录和用户另装的字体目录**）；用途有正文（文渊圆体排前）和等宽（Maple 排前） |

找素材目录只有一套（`assets.Twemoji`、`assets.FontDirs`）：明说的目录 → 环境变量 → **exe 旁的 `fonts/`、`twemoji/`（正式程序从这里读）** → 开发时 `native/fonts/`、`native/twemoji/`（worktree 里回主工作区）。打包时把 `fonts/`、`twemoji/` 拷到 exe 旁，步骤写在 `native/README.md`「打包：把素材放到 exe 旁边」。

**Go 内置插件怎么拿**（照第二节的 Provide / Service）：`internal/assetsvc` 是个只提供服务的插件（代号 `assets`，清单 `Provides: assets`，`Essential`，没有设置），装配时随后台起来。别的插件在清单里写 `Requires: []string{turn.ServiceAssets}`，`Setup` 里用 `turn.AssetsOf(r)` 取 `turn.Assets`：

```go
type Assets interface {
	Icon(name string, fill bool) (svg string, err error) // 完整 <svg>，24×24，currentColor
	IconNames() []string
	Emoji(seq string) (svg string, ok bool)                // Twemoji 的 SVG 文本，没目录或没这张图是 false
	SplitEmoji(text string) []EmojiPiece
	Fonts(purpose AssetFontPurpose) []AssetFont            // body / mono，先后就是回退的先后
}
```

接口只用字符串和数字，内核不依赖界面库。**插件不许直接 import `internal/assets`**：`archcheck` 的 `TestPluginsDoNotImportAssetsDirectly` 查——凡 import 了 `internal/turn` 的包都不许直接 import `internal/assets` 下的包（素材服务自己、入口、不接插件契约的界面库除外）。

**TS 插件那层的接口草案（第二步做完以后再实现，本轮不做）**：在 `sumika` 对象上加一组只读函数，和 Go 同一份数据：

```ts
sumika.assets.icon(name: string, opts?: { fill?: boolean }): string          // 完整 <svg>；名字不存在抛错，错误里带名字
sumika.assets.emoji(seq: string): string | null                              // Twemoji 的 SVG 文本；没有返回 null
sumika.assets.splitEmoji(text: string): { text: string; emoji: boolean }[]
sumika.assets.font(purpose: "body" | "mono"): { name: string; source: "wenyuan" | "maple" | "system"; weight: number; script: string }[]
```

- 只给文本和描述，**不给字体文件路径和内容**：脚本的文件读写限在自己目录（第三节第 4 条），路径给了也读不了，还会把本机目录结构带进插件日志和模型上下文。要用字体画东西的插件，将来由宿主提供“用某用途的字体画一段字”的函数，不是让脚本自己去读字体文件。
- 不需要审批：只读、不联网、不碰数据目录。
- 图标名单用 `sumika.assets.iconNames()`，几千个名字不进工具说明，让模型按需查。
