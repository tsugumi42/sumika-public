## 决定（已写成 ADR-337，下面是写 ADR 时的底稿）

**决定**：
1. 用户钩子是 `turn.Registry` 上的两种新挂点（工具结果后、回合结束前）+ 一个编译内插件 `userhooks`。内核只知道"有人想看工具结果、想拦结束"，不知道 PowerShell 和配置文件。依据 ADR-257。
2. 配置文件照 Claude Code 的形状，但**语义有一处有意不同**：PostToolUse 的 exit 0 普通输出和非零退出的输出**也给模型**。Claude Code 里 exit 0 的普通输出不进模型、exit 1 也不进。依据：任务要求"输出按尾注给模型"，`gofmt -l` 是 exit 0 + stdout，`go vet` 是 exit 1。不想要的用 handler 的 `"feedback": "failure"` 或 `"never"`。另一个选项是完全照 Claude Code，让用户把示例包成 `if (...) { exit 2 }`，用户不习惯命令行，所以没选。
3. `.sumika/` 目录写入一律每次审批，YOLO 和"始终允许"都不例外：这里的命令不经审批就会跑，写它等于拿到一次不审批的执行。这是 `policy.Decide` 唯一的改动。
4. 项目级钩子走项目说明的信任根；信任根没开就不跑。全局钩子不看信任根（文件在受保护的数据目录里）。
5. 只在本地私聊和本地群聊跑。门在内核（`in.local()`）和插件（`Audience.Channel`）各一道。子运行不跑（和 Crush 一样），Stop 不判子运行。
6. 钩子只能给反馈或要求继续，不能放行、不能改工具结果和参数。

**影响清单**（本分支已同提交改完）：`docs/架构.md`（挂点表）、`docs/subsystems/tools.md`、`docs/待办.md`、`sumika.example.yml`、`native/internal/config/hooks.go`、`native/internal/settingsreg/`、`docs/规格-运行页.md`（模块表多一行）。

## 一、我理解成

没有用户钩子时，改坏了要等人发现。这次让主人写一个 JSON 文件，就能做到"改完 Go 文件自动跑 gofmt，把结果告诉她""这一轮要结束时跑 go vet，没过就让她接着修"。默认没有任何钩子，所以默认行为不变。

做：PostToolUse、Stop 两个事件；全局和项目两级；匹配工具名和路径；超时、输出上限、并发、取消；运行页看记录；编辑未命中给提示。

不做：PreToolUse 和其他事件；http / prompt / agent 类型的 handler；改写工具结果；子运行里触发。见第十三节。

## 二、配置

### 文件位置

| 级别 | 位置 | 谁能改 | 什么时候跑 |
|---|---|---|---|
| 全局 | `<数据目录>/config/hooks.json` | 数据目录受保护，模型要改每次审批 | 所有本地回合 |
| 项目 | `<工作区根>/.sumika/hooks.json` | `.sumika/` 写入每次审批（第五节） | 工作区根在 `projectContext.trustedRoots` 之下才跑 |

两级都有时都跑，全局在前。文件改了下一次事件就生效（比较修改时间和大小，不用重启）。

### 格式

顶层只认 `hooks`，别的键忽略，所以可以把 `.claude/settings.json` 整个复制过来。

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "paths": ["**/*.go"],
        "hooks": [
          { "type": "command", "command": "gofmt -l \"$env:SUMIKA_FILE_PATH\"", "timeout": 30 }
        ]
      }
    ],
    "Stop": [
      {
        "paths": ["**/*.go"],
        "hooks": [
          { "type": "command", "command": "go vet ./...", "onFailure": "block", "timeout": 120 }
        ]
      }
    ]
  }
}
```

### 匹配

| 字段 | 在哪 | 意思 | 和 Claude Code |
|---|---|---|---|
| `matcher` | 组 | 工具名。空、`*`、不写：全部；只有字母数字下划线竖线：名单；否则正则（RE2） | 一样；Sumika 的工具名另外认 Claude Code 的叫法（下表） |
| `paths` | 组 | 路径 glob，字符串或数组。不带 `/` 的比文件名（`*.go`），带 `/` 的比工作区根下的相对路径（`native/**/*.go`），不分大小写 | **Sumika 扩展** |
| `if` | handler | `工具名(模式)`，文件工具比路径，`powershell` 比整条命令（比 Claude Code 粗，不拆子命令）；Stop 上写了就不跑 | 一样，只支持单条规则 |

Stop 的 `matcher`、`paths` 是 **Sumika 扩展**：`matcher` 看这一轮成功用过的工具，`paths` 看这一轮 `edit`、`write` 改过的文件；空的就和 Claude Code 一样每次都跑。不然每句闲聊都跑一遍 `go vet`。注意 `paths` 看不见 `powershell` 改的文件，要盖住就写 `"matcher": "edit|write|powershell"` 不写 `paths`。

工具别名：`Edit`、`MultiEdit` → `edit`；`Write` → `write`；`Read` → `read`；`Bash`、`PowerShell` → `powershell`；`Grep` → `grep`；`Glob` → `find`；`LS` → `ls`；`WebFetch` → `web_fetch`；`WebSearch` → `web_search`；`Task`、`Agent` → `task`；`TodoWrite` → `todo_write`。

### handler 字段

| 字段 | 默认 | 说明 |
|---|---|---|
| `type` | 必填 | 只认 `command`。别的类型跳过并记诊断 |
| `command` | 必填 | 一条命令，可以多行 |
| `shell` | `powershell` | `powershell` 或 `bash`（Git Bash，找不到记 `spawn_failed`）。**搬 Claude Code 的钩子**：它在 Windows 上默认 Git Bash，命令里有 `$CLAUDE_PROJECT_DIR`、`jq`、`&&` 这些就加 `"shell": "bash"` |
| `timeout` | `hooks.timeoutSeconds` | 秒。小于 1 按 1，大于 600 按 600，不是数字这一组跳过 |
| `onFailure` | 空 | `"block"`：Stop 钩子任何失败（非零、超时、起不来）都算要继续。PostToolUse 上没有效果，工具已经跑完了 |
| `feedback` | `always` | **Sumika 扩展**。PostToolUse 的普通输出给不给模型：`always` 有字就给；`failure` 只有失败才给；`never` 不给 |
| `statusMessage` | 空 | 显示在进度里，代替命令 |
| `async`、`args` | | 不支持。`async` 记诊断后同步跑；有 `args` 跳过这个 handler |

### 坏配置

- 文件读不了、不是 JSON、`hooks` 不是对象：这个文件的钩子一条都不跑（失败关闭），另一级不受影响；运行页记 `config_invalid`，弹一次提醒，同一份内容不重复。
- 单条坏（正则不合法、缺 `command`、未知 `shell`、不支持的事件）：跳过这一条，其余照跑，同样记一次诊断。
- 文件超过 256 KiB 当坏配置。开头有 BOM 能读（记事本）。

## 三、事件

### PostToolUse

**什么时候**：一批工具全部跑完、结果已经落库以后，按调用顺序一个个跑；只对成功的工具（失败的是 Claude Code 的 PostToolUseFailure，这版不做）。

放在 `runTools` 返回之后，不放在每个工具的执行协程里，因为：
1. 执行协程的上下文带停止宽限（[规格-停止三段](规格-停止三段.md)），钩子是新活，应该一按停止就杀；
2. 钩子不该占全局工具槽；
3. 同一批的第二个 `edit` 是对着钩子跑之前的内容生成的，`gofmt -w` 改到一半会让它白白未命中（Claude Code 的 CHANGELOG 修过同一件事）。

**标准输入**（JSON）：

```json
{
  "session_id": "会话", "transcript_path": "", "cwd": "工作目录", "permission_mode": "default",
  "hook_event_name": "PostToolUse",
  "tool_name": "edit", "tool_use_id": "c1",
  "tool_input": { "path": "a.go", "file_path": "D:\\x\\a.go", "edits": [] },
  "tool_response": { "text": "Successfully replaced 1 block(s) in a.go.", "success": true, "filePath": "D:\\x\\a.go" },
  "turn_id": "回合", "character_id": "角色"
}
```

`file_path` 是绝对路径（Claude Code 的脚本都读它）。`tool_input` 超过 256 KiB 时只留路径和 `"truncated": true`；`tool_response.text` 超过 64 KiB 截断。

**环境变量**：`SUMIKA_PROJECT_DIR` 和 `CLAUDE_PROJECT_DIR`（工作区根）、`SUMIKA_HOOK_EVENT`、`SUMIKA_TOOL_NAME`、`SUMIKA_FILE_PATH`（文件工具才有）。内容带 NUL 的不设。**工具参数只进环境变量和标准输入，绝不拼进命令文字**。

**工作目录**：回合冻结的工作目录。

**结局**：

| 情况 | 给模型的尾注 | 运行页 |
|---|---|---|
| exit 0，没输出 | 没有 | ok |
| exit 0，普通输出 | 输出（`feedback` 为 `always` 时） | ok |
| exit 0，JSON | `additionalContext` 和 `decision:"block"` 的 `reason`；`systemMessage` 只进进度 | ok（有 `block` 时 failed · `check_failed`） |
| exit 2 | stderr，空就 stdout | failed · `check_failed` |
| 其他非零 | 退出码 + stdout + stderr（`feedback` 不是 `never`） | failed · `exit_nonzero` |
| 超时 | 一行（已杀进程树） | timeout |
| 起不来 | 一行 | failed · `spawn_failed` |
| 被停下 | 没有 | cancelled |

尾注接在工具结果后面，和防复读那条提醒同一条路：只进模型看到的消息，不改库里的工具结果。

```
[用户钩子 PostToolUse：gofmt -l "$env:SUMIKA_FILE_PATH"，退出码 1]
a.go
```

### Stop

**什么时候**：模型这一步没有工具调用、也没有新插话，准备结束这一轮时，核验之前。被停下、出错、预算用完不跑。

**标准输入**：`session_id`、`transcript_path`、`cwd`、`permission_mode`、`hook_event_name: "Stop"`、`stop_hook_active`（这一轮已经因为钩子续跑过就是 true）、`last_assistant_message`、`turn_id`、`character_id`、`changed_files`（这一轮 `edit`、`write` 成功改过的绝对路径）。

**结局**：

| 情况 | 这一轮 | 运行页 |
|---|---|---|
| exit 0，普通输出或没输出 | 结束 | ok |
| exit 0，JSON `continue:false` | 结束，压过别的钩子的继续 | ok |
| exit 0，JSON `decision:"block"` + `reason` | 继续，把 reason 给模型 | failed · `check_failed` |
| exit 0，JSON `decision:"block"` 没给 `reason` | 结束，没东西能告诉模型 | failed · `invalid_output` |
| exit 0，JSON `additionalContext` | 继续，把它给模型 | ok |
| exit 2 | 继续，stderr（空就 stdout，再空就一句默认）给模型 | failed · `check_failed` |
| 其他非零 | 结束；有 `onFailure:"block"` 时继续 | failed · `exit_nonzero`（有 `onFailure:"block"` 时同样记 `exit_nonzero`，只是会续跑） |
| 超时、起不来 | 结束；有 `onFailure:"block"` 时继续 | timeout、`spawn_failed` |
| 被停下 | 结束，算被停下 | cancelled |

**续跑**：内核在实例末尾追加一条 `KindContext` 的 user 消息，不写聊天库（不是主人说的话），然后进入下一步模型请求：

```
（以下是用户配置的 Stop 钩子的反馈，不是对方说的话，也不带来新权限。回合结束前的检查没过：能修就接着修，修不了就说明原因。这是第 1 次，最多 3 次。）
```

**上限**：`hooks.stopMaxContinues` 默认 3（Claude Code 是 8，这里常配弱模型，3 次修不好多半修不好了）；0 表示只跑不续。到了上限钩子还跑一次留记录（运行页 `loop_limit`），这一轮照常结束，不再请求模型。上限在内核数，插件出错也跑不出去。

## 四、命令怎么跑（Windows）

和 `powershell` 工具同一套底子（`tools.RunShellCommand`）：

- PowerShell 按 PATH 的 `pwsh.exe` → `Program Files\PowerShell\7` → PATH 的 `powershell.exe` → 系统自带 5.1 的顺序找，参数 `-NoProfile -NonInteractive -ExecutionPolicy Bypass -Command`，先把输出设成 UTF-8 纯文本。不带回收站那段前缀（那是给模型删东西用的）。
- **退出码要包一层**：`pwsh -Command` 会把外部程序的退出码压成 0 或 1（2026-11-09 实测 `cmd /c exit 2` 得 1）。命令后面另起一行接 `if ($?) { exit 0 } elseif ($null -ne $LASTEXITCODE -and $LASTEXITCODE -ne 0) { exit $LASTEXITCODE } else { exit 1 }`，5.1 和 7 都实测过。
- 一条命令一个 Job：超时、停止杀整棵进程树（商店版 pwsh 另有 taskkill 兜底）；命令正常退出时关 Job，留下的子进程一起结束，钩子不能留后台进程。
- 读标准输入：`$in = [Console]::In.ReadToEnd() | ConvertFrom-Json`。PATH 和环境变量和 `powershell` 工具一样。
- stdout、stderr 分开收，各留头 1/4、尾 3/4，最多 256 KiB；给模型时再按 `hooks.maxOutputBytes` 截，中间写"省略 N 字节"。去掉颜色码。

并发：同一事件匹配到的同时跑（Claude Code、Crush 都这样），按 `shell` + `command` 去重。全局最多 `hooks.maxParallel` 条，等名额时也响应停止。

## 五、信任和场合

**项目级信任**：每次事件都问 `projectcontext.ConfigTrust`（和项目说明同一份实例）。没配置信任根、不在根里、根的身份变了、检查出错：都当不信任，不跑，运行页记一次 `untrusted`。`hooks.json` 的真实路径（解开联接）必须还在工作区根里，否则同样不跑。

**写保护**：工作区里的文件模型通常能写，不保护的话模型写一条命令进去，下一个事件就不经审批跑了。所以 `policy.Decide` 里，文件工具的路径或命令文字、拆出的目标碰到 `.sumika` 路径段时，非只读一律 `ask`（`Sticky`、只能允许一次），在 YOLO 和授权之前判。读不拦。

**残余风险**（不算漏洞，写清楚）：已经给过"这个对话允许这一类"或 YOLO 的命令，能经脚本间接写这个文件（拆不出目标的话）；但它本来就有不经审批的执行能力，没有多拿到什么。`git pull` 带来的项目钩子，和项目说明一样靠"这个目录我信任"。

**场合**：

| | 本地私聊 | 本地群聊 | QQ 私聊 | QQ 群 |
|---|---|---|---|---|
| PostToolUse | 跑 | 跑（工具本来就受听众限制） | 不跑 | 不跑 |
| Stop | 跑 | 跑，每个角色的回复各跑一次 | 不跑 | 不跑 |

门两道：内核 `Input.local()`（`Audience.Channel == "console"` 且不是子运行），插件再查 `Audience.Channel`。钩子输出只进本地回合的上下文，不外发。

## 六、运行记录

- 每跑一条记一行 `task_runs`：模块 `hooks`（运行页"用户钩子"），成功也记，否则算不出成功率。详情是 `事件 · 工具 · 命令头 · 退出码或第一行报错`，走 `taskrun.Detail` 脱敏。
- 回合时间线：`hook.post_tool`、`hook.stop`，名字是程序名，运行页"每一步的耗时"里显示"钩子（工具后）""钩子（结束前）"。
- 进度：跑的时候在过程气泡里显示"钩子"一步，目标是 `事件 · 命令头`，失败显示输出。只在内存，刷新后不留。
- `sumika-ctl stats quality` 同一份。
- 没钩子时什么都不记，时间线也不多一段。

## 七、编辑未命中提示（D4）

`edit` 找不到 `oldText` 或不唯一时，在原报错后面接提示。原报错的字不变，只追加。

找不到时依次：
1. `newText` 去空白后不短于 20 字且已经在文件里：说"可能已经改过了"。
2. 投票：`oldText` 的每一行（有字母或数字才算），和文件里去掉全部空白后相等的行投它的起点；至少一半的行同意才算。只显示首末命中行之间，最多 12 行、每行 200 字。显示的是原文，不加行号（`read` 也不加，加了模型会抄进 `oldText`），行号写在标题里。有只差开头空白的行，再用 `→`（Tab）、`·`（空格）把两边画出来。
3. 相似：投票没结果时，取 `oldText` 最长的 5 行，和文件每行算字二元组相似度，不低于 0.6 的取最高，显示那一段（前后各带一行）。这步能救"记错一个参数"这种最常见的情况，opencode 的投票救不了。文件超过 20000 行或 2 MiB 跳过。

不唯一时：写"分别在第 3、17、40 行"（最多 8 个）。

**只在读这个文件本来就允许时才给**（opencode 同款）：内核按受保护路径判断（含解开联接后的真实路径），受保护的文件不给提示，默认也不给（`tools.WithEditHints` 要内核显式打开）。审批卡的预览不带提示，只显示原报错。

## 八、参数

| 键 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `hooks.enabled` | `true` | | 总开关。开着但没写 `hooks.json` 时什么也不跑 |
| `hooks.timeoutSeconds` | 60 | 1～600 | 单条命令默认时限。Claude Code 是 600；这里回合在等它，默认短些，慢的自己写 `timeout` |
| `hooks.maxOutputBytes` | 8192 | 256～65536 | 单条命令给模型的字节上限（Claude Code 约 10000 字符） |
| `hooks.maxParallel` | 4 | 1～16 | 全局同时跑几条 |
| `hooks.stopMaxContinues` | 3 | 0～20 | 一轮最多因为 Stop 钩子续跑几次 |

## 九、禁止的偷懒写法

- 把工具参数或模型输出拼进命令文字。
- 钩子的错误让工具失败或让回合出错。
- 钩子通过 `Trusted` 以外的路子判断项目可信；信任出错当可信。
- 用 `AppendEvent` 存续跑那句话（那是主人说的话的路径）。
- 在 `pwsh -Command` 下直接取进程退出码。
- 按进程名杀；不等真实退出就返回。
- 上限放在插件里数。
- 没匹配到也记时间线或运行记录。

## 十、已知的坑

对照 [边界清单](notes/清单-常见边界情况-2026-10-26.md) 和 Claude Code 的 CHANGELOG：

- **PowerShell 压缩退出码**：见第四节。Claude Code 修过 "hooks that run in PowerShell not blocking when the hook's program exits with code 2"。
- **钩子改了文件，下一次编辑未命中**：Claude Code 修过 "File content has changed"。Sumika 的 `edit` 每次重新读文件，不查外部改动，只会在模型拿旧内容写 `oldText` 时未命中，此时第七节的提示正好指路。同一批不受影响（第三节）。
- **Stop 拦下后丢思考、断缓存**：Claude Code 修过。这里只往实例末尾追加，上一步的 assistant 消息连思考原样留着。
- **Stop 钩子的脚本路径写错导致死循环**：Claude Code 修过（带空格的路径）。exit 1 默认不续跑；有 `onFailure:"block"` 时靠上限兜住。
- **检查点**：`gofmt -w` 这类改动不进检查点；回退恢复的是工具改之前的内容，会连钩子的改动一起回掉，这是想要的。
- **工具结果被软门槛换占位**：尾注和结果是一条消息，一起被换，不会留一条孤零零的尾注。
- **重建实例后尾注没了**：和防复读提醒一样，只在实例里，不进库。
- **本地群聊的 Stop**：一条消息几个角色都回，就跑几次。按命令去重只在同一事件内。写 `paths` 能避开闲聊。
- **商店版 pwsh 的子进程脱离 Job**：靠 taskkill 兜底；后台被强杀时它们会留下，和 `powershell` 工具一样。

## 十二、验收

1. 默认没有 `hooks.json`：回合行为、时间线、运行记录都和以前一样（`TestNoHookNoSpan`，对拍照旧绿）。
2. 全局和项目两级都能跑；项目级不信任不跑。
3. 匹配工具名、别名、正则、路径、`if`。
4. PostToolUse 把输出按尾注给模型，下一次请求里看得到；工具失败时不跑；钩子失败工具结果不变。
5. Stop 没过时模型继续；到上限结束；第二次起 `stop_hook_active` 为真。
6. 超时、输出上限、并发上限、按停止杀进程树都有测试，用真 PowerShell。
7. QQ 私聊、QQ 群、子运行零调用；门改坏就红。
8. 运行页看得到"用户钩子"一行和失败原因。
9. 真实模型：改一个没格式化的 Go 文件，PostToolUse 的 gofmt 结果进下一次请求；Stop 的 `go vet` 对编译不过的文件，模型修好后结束。记录存 `data/dev/hooks-real/`（`TestRealModelUserHooks`，设 `SUMIKA_REAL_HOOKS_OUT` 才跑，走本机 Magpie 的 `auto/deepseek-flash`，临时数据目录和工作目录）。2026-11-09 实测：gofmt 场景 4 次请求，第二次请求里有"用户钩子 PostToolUse：gofmt -l ..."和 `main.go`，模型在回复里如实转述"钩子报它不在 gofmt 格式里"；go vet 场景 8 次请求，第一次 Stop 钩子 `go vet` 退出码 1（`x declared and not used`），反馈作为 Stop 钩子反馈送回，模型把 `x := 1` 改成 `x := 1; _ = x`，第二次 vet 通过后结束，运行记录是 failed · exit_nonzero 一行加 ok 一行。
10. 编辑未命中：四种提示各有测试；受保护文件不给；原报错的字不变。
