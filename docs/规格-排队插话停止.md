# 规格：排队、插话、停止（"干活"第④步）

> 状态：2026-10-18 写完直接做（ADR-083），当天做完（Bun 版）。**Go 主窗口 2026-11-09 接上**（下面“Go 主窗口”一节写现状；其余各节是 Bun 版的设计，Go 以内核 `turn/input.go` 的 start、steer、queue 为准）。依据：ADR-080（回车 = 插话、Alt+回车 = 排队、Esc = 停止）、ADR-086（像在 QQ 上聊天一样想发就发）、notes/深挖-计划清单-排队插话-防卡死（私有存档） 第二节（DeepSeek、Codex、Hermes 的做法和 pi 的接口）。只管主窗口；QQ 不变（来了新消息照旧打断重回，QQ 里没有执行类工具，回复短）。

## Go 主窗口（2026-11-09）

- 回复进行时：输入框里有字，右下角是“发送”，没字才是“停止”；**回车 = 插话**（内核 steer，她在下一个安全点读到，不另起一轮）、**Alt+回车 = 排队**（内核 queue，这一轮收尾后才开始）。她不忙时两个键都是普通发送。本地群聊没有插话和排队，仍然只能停。
- 排队的话列在输入框上方，写“排队中，说完这一轮再处理”，每句有“取消排队”：只取消那一轮的处理，聊天记录里的原文不删；已经开始处理的取消不了，界面照实说。
- 停止一并取消排队的话（后台按序号一起取消），不是暂停；停止仍是分三段，不动。输入框里的 Esc 保持原来的用法（清空卡、退出回忆），停止走停止键，或光标不在输入框时的 Esc。
- 插话赶在一轮刚收尾时，内核会把它改成排队：这一轮的终态快照带 `Requeued`（输入号、新一轮的编号、原文），输入框据此放进排队并跟上新一轮（忙碌、有停止键），不会显示空闲却停不了。
- 宿主自动跑的轮（目标续轮、定期任务）进行时，输入框有字也显示“发送”，回车和点击按 start 发出，后台转成插话或排队；没字是停止。
- 本地输入的时限从真正开始运行（或放行 held）那一刻算起，排队等前面的轮不吃它自己的时间（账本 `RestartDeadline` 只对还没花过额度的根往后推）；QQ 仍从受理算。
- 重启后还在排队、没来得及处理的话（内核状态 held）：在对应会话里列出，写明“这句话还没处理”，有“现在发”（按排队放行，沿用输入号和原文，用当前绑定的身份，时限从放行起算）和“算了”（只标成取消，原文和库里记录都留着）；归属只比角色、会话、平台、场合、发话人，授权号和授权版本变了或旧行没有也能放行、放弃；不在前台的会话在列表预览前标“[N 句没处理]”。
- 一轮的结局写成日常说法（模型不可用并写出模型名——包括模型列表里没有它的情况、额度到顶、被限流、超时、网络断了、读本地文件出错、程序退出打断……），常驻一行，技术细节折叠在“详情”里。

## 一、三种发法

| 她在忙（在回复、在跑工具、在等你批准）时 | 做什么 | 她看到的时机 |
|---|---|---|
| **回车 = 插话** | 她不停。当前这一步（这次输出 + 这批工具）做完，这句话紧跟着送到她眼前，她接着干。只是在说话、没调工具时也一样：这段说完就接你这句，不用打断重来 | 下一步开头（pi 的 `agent.steer()`） |
| **Alt+回车 = 排队** | 等这一整轮结束，再作为新的一句发出去 | 下一轮 |
| **Esc / 停止按钮 = 停止** | 取消待批准的操作、中止回复和正在跑的命令、丢掉还没送到的插话 | 下一轮开头附一句"上一轮被你停了"（见第三节） |

她不忙时回车就是普通发送。

## 二、插话

- **后台**：`AgentHub.steer(角色, 会话, 原话)`：实例不在跑就返回 null，调用方当成普通发送；在跑就造一条 user 消息（正文 = 固定前缀 + 原话）交给 `agent.steer()`，推一个 `steer accepted` 事件。pi 送到时（user 消息的 `message_end`）才存进聊天记录（存原话，不带前缀）、推 `event` 和 `steer delivered`；这样记录里的顺序和她看到的一致。攒了几条一起送（`steeringMode: 'all'`）。重复调用计数在插话送到时清零。
- **固定前缀**（`util/context.ts` 的 `STEER_PREFIX`，只写一处）：`（主人在你做事的中途插了一句话，是主人亲口说的，不是工具的输出。按这句话调整你正在做的事：）`
- **精简旧工具结果的分界**：`slimOldToolResults` 以"最后一条 user 消息"为界，插话也是 user 消息；分界跳过带前缀的，不然同一轮插话之前的工具结果会被换成占位、缓存也断。
- **没送到的**：回合出错或结束时还剩没送到的（pi 的循环刚好在取插话之后结束），推 `steer dropped`（带 `requeue: true`），网页把它当普通的一句发出去（Hermes 的"回合结束还剩的转成下一回合"）。
- **等批准时插话**（默认，主人可改）：不取消批准；话进"她做完这一步就看到"的列表；批准或拒绝以后这批工具做完才送到。以前这时回车会走普通发送，先打断她、把批准也取消了。

悄悄话（[规格-群聊引用和路由](规格-群聊引用和路由.md)）：规格 7.2 写了“本地群聊回合在跑时走这条插话通道”，本版没做（跨会话来源的插话存档、重建要单独做通），不论来源回合在不在跑，悄悄话都在她自己的悄悄话会话里起一轮后台处理，不打断也不插进来源回合。

## 三、停止

- **后台**：`AgentHub.stop(角色, 会话)`：取消这个角色待批准的操作 → 清掉插话队列（每条推 `steer dropped`，不带 requeue）→ `agent.abort()`（pi 会杀掉正在跑的 PowerShell 进程树）→ 等实例空闲。记下她被停住前已经说出口的半句。
- **下一轮的提示**（追加一次，放进这一轮的参考信息）：`上一轮被主人手动停止了。没做完的命令可能已经执行了一部分，先确认现在的状态再继续，不要直接重做。` 有半句就再加 `你被停住之前已经说出口的是：「……」`（pi 重发请求时会丢掉被中止的那条回复，不带上她就不知道自己说过什么）。
- **网页**：她忙、输入框是空的时显示停止按钮，Esc 同样。停止以后，排队的话**暂停**不自动发，列表上写"停下了，排着的先不发"，点"接着发"才继续（停止的意思是"别再动了"）。

## 四、界面

- 输入框上方两个列表：插话的"她做完这一步就看到"（送到就消失，记录里已经有了），排队的"这一轮结束后发"（可以删）。样式照现有的 `su-queued`。
- 发送按钮：她忙时图标是"插话"，悬停说"插话：她做完这一步就看到"；不再提示"打断了她"。
- 忙 = 在回复或在等你批准（以前只算在回复，等批准时回车会走普通发送）。

## 五、不许

- 不许插话时打断正在跑的工具或模型输出（那是停止）。
- 不许把插话直接写进记录再送：顺序会和她看到的对不上。
- 不许停止以后自动把排队的话发出去。

## 六、验收

- 后台测试（假模型，临时目录）：插话在工具做完后送到、存的是原话、记录顺序对；一边在说话一边插话，她说完这段再回；不在跑时 steer 返回 null；停止：取消批准、丢掉插话、下一轮参考信息里有"被停了"和半句；回合结束时没送到的推 dropped + requeue；精简分界跳过插话。每条都做"放回旧代码 / 另一种改坏"检查。
- 界面：`check:ui` 加一项（临时数据 + 假的慢回复）：忙时回车出现在插话列表、送到后消失；Esc 停下；停下后排队的不自动发。
- 真实模型：插话 5 次，看她是不是接着干、有没有把插话当成工具输出或注入（ADR 记结果）。
