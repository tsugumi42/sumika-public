## 一、为什么换（量得到的东西）

| 现在 | 量到的 / 数得出的 | Go 一个程序以后 |
|---|---|---|
| 界面和后台是两个程序，中间隔一层接口 | 124 个 HTTP 接口 + 一条 WebSocket 推送（`grep ctx.server.*` 计数，2026-10-25）；前端约 1.3 万行在读写这些接口 | 界面直接调后台的方法、订阅事件，没有这一层 |
| 两种语言 | 后台 TS 约 1.9 万行；界面要换成 Go（mygo），类型和事件得两边各写一遍 | 一套类型 |
| 要带 Bun 运行时 | 后台 Bun 进程工作集 181 MB（2026-10-23 量） | 和界面同一个进程；省多少要量（嵌入用的 Python 747 MB 不受影响，不是主要理由） |

不是因为现在的后台慢或常出事——这一点如实写：**主要理由是界面要换成 Go，后台跟着换以后整个程序只有一种语言、一个进程**（主人 2026-10-25："我想让后台也直接改成 Go，跟 mygo 一起"）。

## 四、怎么搬（逐块对拍，能撤回）

**数据不动**：Go 版读写同一个数据目录、同一个 SQLite 库，表结构不改。哪一块搬坏了，切回 Bun 那一版就行。（已被渠道线的"Go 写自己的库、不写 Bun 正在用的库"和 ADR-199 改为：Go 的库放 `<数据目录>/go/`，原始聊天记录按平台分库，Bun 的库只读打开做对拍、第 7 步一次性导入，见[规格-聊天记录按平台分库](规格-聊天记录按平台分库.md)；"表结构不改"只对只读打开 Bun 的库成立）

| 步 | 做什么 | 怎么证明对 |
|---|---|---|
| 0 | 骨架：`internal/app` + `store` + `llm`，读现有库、能调一次模型 | 读出来的会话和消息条数和 Bun 版一致 |
| 1 | **本地私聊一轮**：你说一句 → 拼提示词 → 流式回 → 存库 | 同样的输入，Go 版发出去的请求和 Bun 版**逐字节对比**（提示词、缓存键、思考档位）；存进库的行一样；缓存命中率不低于 Bun 版 |
| 2 | 工具和审批、排队插话停止 | 照 Crush 的做法写假模型测试：批准 / 拒绝 / 取消 / 插话时机 |
| 3 | 记忆（总结、检索、嵌入） | 已被 ADR-159 第 2 条改为：检索直接按规格-记忆-v2 在 Go 里做，验收是"记忆考题的分数不低于 TS 版"（考题和跑分脚本在 `scripts/memory-eval/`）；不再要求检索出来的条目和顺序和 Bun 一致 |
| 4 | QQ + 闸门 + 路由 | 拿真实聊天记录回放（现在的 `replay-gate` 那套），说话次数在同样的范围 |
| 5 | 识图、表达学习、备份、设置 | 各自的测试搬过来 |
| 6 | 界面切到 mygo 版、Bun 后台和网页版退役 | 你日常用一段时间没问题 |

每一步：先写这一步的小规格，搬完对拍出数写进提交说明；**换一个模型（Codex）独立复核**对拍结果（三道关第②关），过了才下一步；照搬下来的取舍和临时补丁补进第七节（ADR-167）。（第 1 步做完以后定这份规格：2026-10-25 已定稿。）

## 四点五、第 0 步细则（2026-10-25）

**做什么**：Go 代码放在 `native/`（和 mygo 界面同一个模块，最后就是同一个程序），包在 `native/internal/` 下：
- `paths`：照 `daemon/util/paths.ts` 的新布局（v1）给出各个路径；**只认 v1**，碰到旧布局（没有 `sumika-data.json`）直接报错、提示先跑 `scripts/migrate-data.ts`，不偷偷兼容；`format` 不是正好 1（比程序新、缺字段、0 或负数）都报错（比 TS 版严，TS 只拦比程序新）。
- `config`：照 `daemon/config.ts` 找配置文件（`SUMIKA_CONFIG` → 数据目录 `config/sumika.yml` → 项目根 `sumika.yml`）、定数据目录（`SUMIKA_DATA_DIR` 优先，否则项目根 + `dataDir`）；第 0 步只读用得到的几项（`console`、`magpie.baseUrl`、`dataDir`、`characters` 的模型、`defaults`、`agent.thinking`），默认值和 zod 里的一样，**不认识的键原样忽略、不写回**。YAML 用 `goccy/go-yaml`。
- `store`：`modernc.org/sqlite`，打开 `events.db`、`trace.db`，PRAGMA 照 `daemon/util/db.ts`（WAL、busy_timeout 5000、foreign_keys）。两种打开方式：**只读**（`mode=ro` 加 `query_only`，路径里的 `% # ?` 要转义，不然 SQLite 把 `#` 后面当片段截掉、`mode=ro` 跟着丢——modernc 打开时总带着"可写、不存在就建"；对拍真实库用；只检查表和列是不是它认识的，**绝不补表补列**）和**读写**（临时库用：用基线迁移建表）。基线迁移 `0001_baseline.sql` 是从真实库 `sqlite_master` 原样导出的 31 张表和索引，用 goose 执行、嵌进程序。第 0 步的几条查询手写；sqlc 等第 1 步查询多了再引入。
- `llm`：标准库 `net/http` 发请求、自己读 SSE（2026-11-08 起不再依赖 openai-go）。列 `/models`（读 Magpie 多给的上下文长度、能开的思考档位）；一次流式调用：带 `prompt_cache_key`、`reasoning_effort`，读响应头，收文本增量、思考增量（`reasoning_content` → `reasoning` → `reasoning_text` 取第一个不为空的，从原始 JSON 取）；用量口径照 pi 的 `parseChunkUsage`：输入 = `prompt_tokens` 减缓存读、缓存写，缓存命中依次看 `prompt_tokens_details.cached_tokens`、`prompt_cache_hit_tokens`、顶层 `cached_tokens`，也认 `choice.usage`；结束原因照 pi 的 `mapStopReason`：`length` 算截断不算错，没给、`content_filter`、不认识的都报错，已收到的字留着。
- `cmd/core-check`：命令行小工具，打印配置摘要、只读打开真实库做表结构检查和条数统计；加 `-call` 时调一次模型。

**怎么证明对**：
1. 条数对拍：同一个真实库，Go（只读）和 Bun（`bun:sqlite` 只读）各数一遍——总消息数、每个会话的消息数、模型调用条数、步骤条数——**全部一样**。
2. 表结构：Go 用基线在临时目录建库，和 Bun 版 `Store` 在另一个临时目录建的库比 `sqlite_master`；差异逐条列出、说明原因（Bun 的表是各模块用到时才建，临时库里可能缺一些，这是预期的，基线以真实库为准）。
3. 模型调用：真调一次（花一次很便宜的请求），打印收到的字、思考、用量、缓存命中、响应头里的实际渠道；用假服务器（`httptest`）的测试断言请求里确实带了 `prompt_cache_key`、`reasoning_effort`、`stream: true` 和 base_url。
4. 测试只用临时目录，不碰真实 `data/`（真实库只在第 1 条对拍时只读打开）。

**结果（2026-10-25）**：对拍 Bun → Go → Bun 三次一样（events 23555、消息 20979、会话 7、model_runs 5462、steps 402，每个会话消息数的汇总哈希 1575a56566ccbea5；两边都打印库的绝对路径，`go-core-count.ts` 和后台一样用配置里的 `dataDir` 找数据目录）；Go 的条数放在每个库一个读事务里。真调 `auto/deepseek-v4.1-flash` 一次正常。Codex 独立复核挑出 5 处必须改的（地址没转义、用量口径、没查结束原因、对拍脚本数据目录、格式号只拦一头），都改了：四处各有改回去会红的测试，对拍脚本那处靠三次对拍打印同一个库路径验证。复核原文：主工作区 `data/dev/process-study/result-review-step0.md`。

**第 1 步要注意的**（Codex 复核时对着 `daemon/plugins/agent.ts`、`llm.ts` 和 pi 的 `openai-completions.js` 列的，动手前逐条核对）：
- 请求体字段顺序照 pi：`model, messages, stream, prompt_cache_key, prompt_cache_retention, stream_options, store, max_completion_tokens, temperature, tools / tool_choice, reasoning_effort`；`prompt_cache_retention: "24h"`、`store: false`、`max_completion_tokens` 怎么定看 pi 的 `simple-options.js`。逐字节比要抓原始 HTTP 请求体，不比解析后的对象。
- 系统提示词用 `system` 还是 `developer` 角色按模型定（pi 905 行附近）。
- 缓存键 = `sumika-` + sha256(`角色id:会话`) 十六进制前 24 位（`llm.ts` 224 行，`agent.ts` 661、700 行）。
- 思考档位按模型能开的档换：先往上找、找不到再往下（`llm.ts` 279 行，pi `models.js` 692 行）。
- 上下文窗口、最长输出的取法照 `llm.ts` 143 行。
- 对比时把时钟和状态固定住（`agent.ts` 942 行）；响应没带渠道头时不要把上次记的渠道覆盖成空（`agent.ts` 699 行）。
- 复核顺带的建议没做、留到用得到时：配置校验和 zod 完全对齐（`maxLive ≥ 1`、`idleMinutes > 0`、空模型名、环境变量为空字符串时 TS 的 `??` 当作已设）；`Init` 碰到旧布局也拦、身份证用独占创建。

## 四点六、第 1 步细则（2026-10-25）

参考：Sol（omp 调 codex/gpt-6.1-sol，只读）列的清单，原文在主工作区 `data/dev/process-study/result-step1-inventory.md`；其中系统提示的角色（`openai-completions.js:905`）、输出上限（`simple-options.js` 的 `clampMaxTokensToContext`、`utils/estimate.js`）、缓存键哈希的字符串（`agent.ts:661`、`700`）我对着源码核过。

**"逐字节"改一个说法（我改的，原来草案写"请求逐字节对比"，主人看过草案）**：JS 和 Go 写 JSON 时字段先后、`<` `&` 这类字符的转义天生不一样，这些不影响模型看到的内容，也不影响服务商的提示词缓存（缓存按 token 算）。现在的判法：两边的请求体解析成 JSON 后**每一层的字段一个不多、一个不少，值相同，数组顺序相同**；其中每个字符串（系统提示、每条消息、缓存键）**逐字节相同**。

以上逐字节验收已被 ADR-225 改为按 Go 自己的规格验收，Bun 录像仅保留为历史回归材料。2026-11-04 记忆跨场合改动同步清理 turn 录像中的固定措辞及其衍生值断言：提示词、工具说明/JSON 属性先后、说明改变导致的 token 估算和 hash 不再逐字固定；继续比较用户/助手/工具消息、工具名称集合、请求选项、实例历史、events/observations、工具步骤及审批授权。输出预算检查实际模型的上限与上下文余量，不把某段旧文案算出的偶然数值重录成金标准。各模块的来源、角色隔离、工具执行与守卫行为验收不变，见[本轮规格](规格-记忆召回不分场合.md)。

**场景**：本地主窗口私聊、实例冷启动后的第一轮（不是话题；历史可以有，也可以有压缩快照和"新话题"分隔）。

**Go 版要做的**（包都在 `native/internal/` 下，一个包一个提交）：
- `prompts`：`{{变量}}` 替换后整段 trim；用户改过的 `config/prompts/<名>.md` 优先、没有读出厂 `prompts/<名>.md`；读的时候不改换行，填变量之前统一成 LF（2026-10-25 起，Bun 版一起改）；场合预设和风格预设照 `selection.json`（会话自己选的优先，没选的那项跟着"本地 · 私聊"的默认）；段之间两个换行，空段不出现。

## 五、禁止的偷懒和要避开的坑（来自拆解笔记）

- 事件不能静默丢：文本增量是不可恢复的，缓冲满要么阻塞要么合并成快照，不能像 Crush 的 `Publish` 那样丢。
- 不要两份历史：kubectl-ai 是 SDK 里一份、程序里一份，恢复时对不上；我们只有库里那一份，每次构造请求副本。
- 审批按请求 ID 批，取消以后迟到的批准不能执行；不要一把全局锁。
- QQ 消息按"账号 / 群 / 私聊 + 角色"找会话，不能像 Crush 那样"优先当前正在看的会话"。
- 有副作用的工具（写文件、PowerShell）默认串行；只读的才并行。
- K3 分支将整批串行/无界并行替换为顺序 prepare、有界滚动池和局部独占屏障；同根模型/工具尝试、token、输出和期限统一记账，真实执行退出才释放槽。接口与尚待 K1/K2 的接线见内核补强规格 7.3（私有存档）；本页上文第 2 步的旧整批策略是历史记录。
- 不引入 agent 框架（Fantasy、adk-go、eino）：循环自己写，口子都在自己手里（调研-Go 第八节的结论）。
- 不为了 Go 改表结构；要改表另走迁移、单独提交。
