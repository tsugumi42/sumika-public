# 模型与服务商开发指导

来源：`data/dev/fable-review/块-C.md` 第七节（质检读 main），2026-11-14 对 main 核对。路径相对 `native/internal/`；〔目标〕的含义见 [README](README.md)。

1. 线上格式只出现在编解码器里；回合、记忆、顾问、插件一律用中立对话。反例：`turn/loop.go:182` 在 `turn` 里拼 `{"role":"tool","content":`。〔目标〕编解码器和中立对话类型，现在没有。
2. 服务商差异是数据，不是代码分支：先试“预设 + 兼容开关”〔目标，现在没有〕，表达不了再问是不是新协议。反例：`llm/failover.go:185` 在通用判定里认 `api_error` 这类某家的错误字样；`if strings.Contains(baseURL, "deepseek")` 一类也不许。
3. 调模型只有一个入口，经带调用身份的 `modelcall.Client.Stream`（`modelcall/client.go:192`），不自己写“计划、发、换下一个”的循环，不自己按 ID 在列表里找模型。检查：`grep -rn "selector.Plan(" native/internal` 现在命中 `advisor/runtime.go:245`、`app/guarddeps.go:144`，目标是只剩路由自己。〔目标〕`Router`，现在没有。
4. 未知就说未知：能力、限额、价格取不到时标来源为“默认”并显眼显示；危险的未知（看图）报错，不悄悄降级。
5. 一家坏了不拖别家，也不拖启动；〔目标，现在只有 Magpie 一个来源〕目录、凭据、健康状态按服务商分开存、分开报。反例：`app/app.go:450` 列模型失败就 `return failed(...)`，整个后台开不了（待办 P2-2）。
6. 凭据只经凭据库的一个写入口；日志、错误、trace、录像、导出里都不出现原文；加新入口时用带“毒值”的假 key 全局搜一遍。
7. 改请求体先看缓存：任何改变发出字节的改动（字段顺序、空白、新增字段）用 `llm.PromptHashes`（`llm/prompthash.go:17`）对比前后前缀，并重录录像。
8. 新协议必须带录像（`llm/llmtest`）：普通回复、带工具、带思考、流中断、4xx、限流、上下文超长；请求体另配逐字节 golden，录像回放只比 JSON 语义。

开新接口前先写三句：输入输出是什么、谁会实现第二个、坏了怎么被发现；答不出第二句就做成内部函数。

## 和现行规矩冲突、待定

无。规则 6 的凭据库写入口照 ADR-373（主密码为主）落地。
