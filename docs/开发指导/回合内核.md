# 回合内核开发指导

来源：`data/dev/fable-review/块-A.md` 第六节（质检读 main），2026-11-14 对 main 核对。路径相对 `native/internal/`；〔目标〕的含义见 [README](README.md)。

1. 开始一轮只走 `Hub.Submit`，不再加 `SendXxx`；要带的东西做成 `Submission` 字段。反例：`SendLocalStored`（`turn/local_auto.go:28`）。
2. 状态只在一处改，不在 SQL 里写状态字面量。反例：`store/kernel_lifecycle.go:207` 的 `'interrupted'`。〔目标〕`kernel` 里一张迁移表，现在没有。
3. 内核不认识具体工具、平台、shell、线格式；`turn`、`kernel` 里出现 `"powershell"`、`"qq"`、`"console:"`、`"tool_calls"` 就是放错地方。反例：`turn/stop.go:102`、`turn/input.go:180`、`turn/input.go:672`、`turn/turn.go:275`。改法：工具特例加 `policy.Spec` 声明字段〔目标〕，场合判断用 `kernel.Scope` 的方法（`kernel/types.go:17` `LocalWork()`），平台校验由平台插件登记。
4. 会进库的结构体不是内部结构体：带 `v`、显式 json 标签、有一条字节快照测试，内部结构体要存先转它。反例：`turn/input.go:325` 直接 `json.Marshal(in)`（`in` 是 `turn.Input`）。
5. 工具调用只走 `turn/prepare.go` 的 `Gate.Clear`、再经 `turn/scheduler.go` `runTools` 的预算 `Reserve→Dispatch→Settle` 这一条路；不管来自模型、脚本、外接 Agent 还是后台任务，都不直调 `tools.Execute`（`tools/exec.go:63`）或插件 `Exec`，否则绕过审批、预算、并发槽和步骤记录；审批门只留一个入口，来源不同用参数区分。反例：`turn/prepare.go:116` 按工具名 `mcp_call` 走 `approvalGate.CheckMCP`（`app/kernel_wiring.go:145`）另一个入口。〔目标〕抽成单一 `toolgate.Dispatch`，现在没有。
6. 锁里不写库、不调回调；要“写库和登记一起成立”用每会话串行队列。
7. 每个等待要有上限和去处：写 `<-ch`、`WaitRun`、`Wait()` 之前先答“对方永远不来怎么办”。反例：`turn/input.go:424` `WaitRun(context.Background(), …)`。
8. 错误要么处理、要么让人看见，不积攒：不往共享字段里 `errors.Join`，出错时定影响范围、恢复方式、显示位置。反例（已改，2026-11-15）：`lc.err`。现在每处出错先分类，写不进的状态记成会话故障（`turn/fault.go`），只挡这个会话，进自检 S10，解除只有 `RetryFault`。
9. 新的循环变体不往 `runTurn` 加分支，不往 `Input` 或 context 塞标记。反例：`turn/completion.go:67` 把 `*workReview` 放进 context，`reviewFor` 被读 5 处。〔目标〕实现 `driver` 接口，现在没有。
10. 开新接口前先答：现有入口加事件流能不能表达；是稳定契约还是内部接口；谁能调、四种场合各是什么行为；失败时调用方看到什么；配契约测试和敌对输入测试（缺、空、0、自己的号、类型错）。
