# 开发流程、测试与便携开发指导

来源：`data/dev/fable-review/块-I.md` 第六节（质检读 main），2026-11-14 对 main 核对。路径相对仓库根；〔目标〕的含义见 [README](README.md)。

1. 新测试先选层：判断逻辑用纯函数表驱动；跨模块行为用包级带假外部；“换语言重写也必须成立”的行为用一致性场景（`testdata/shared/`）。反例：为测一个判定条件每个用例 `app.Open` 一次。
2. 等事件，不等时间；计时器逻辑用虚拟时钟。正例：`native/internal/turn/plugin_test.go:412` 用 `synctest.Test`。反例：`time.Sleep(100 * time.Millisecond)` 后断言，或把绝对毫秒数放进合并关卡。
3. 红了先分类再动手：真红、墙钟、抢资源、main 当时坏着；把分类写进队列结果或待办，再决定重排。不分类的重排等于重试。
4. 脚本里不按分号拆 PATH、不写盘符路径；要低优先级或排队走名额接口（`scripts/slot.ts`）。
5. 默认值不写本机路径：输出目录从仓库根（认 `sumika.example.yml`）算，或要求显式给。反例：`native/cmd/stress/main.go:64` 默认写到 `仓库根/data/dev/stress/`。
6. 〔目标〕用到仓库外的东西先登记进环境清单，写明必需还是可选、缺了怎么表现，缺了必须明说，现在没有这份清单。正例：`scripts/scan-private.ts:216-224` 读不到名单退出码 2 并说明。反例：`scripts/fetch-tools.ts:86` 下载失败只警告，之后对拍才红。
7. 临时补丁必须挂得住：写“临时”就要有一条现在还在、专门说这件事的待办；瘦身待办时被点名的条目不能直接挪进历史。反例：`native/go.mod:68` 点名“桌面主题验收”，现行 `docs/待办.md` 里已经没有这条。
8. 新模块、新领域先填开工卡（AGENTS 动手前第 4 条、ADR-378）；第二栏写这门学问公认的做法，不是别的 Harness 怎么做。
9. 改检查本身，清单只改一处：新增检查如果要同时改两处以上文件名单，说明清单又分叉了，先合并再加。
10. 冻结的代码不为过关卡去改：关卡碰到冻结代码红了，把它从关卡里隔离出去并登记（ADR-378 第 4 条）。反例：`48c321bb7` 在冻结的 Bun 测试里登记跳过。
11. 取号（ADR、R 号、迁移号）用命令查，不凭眼睛：现行做法是 AGENTS“新号先占后写”，〔目标〕命令化是后续路线 P5-21（`data/dev/fable-review/后续路线.md`）。
12. 写“主人定的”必须能指到原话，指不到就写“我定的，待确认”，ADR 和需求登记两处写法一致。

要开新接口还是沿用旧的（沿用一个现有步骤并加参数，除非新东西“读哪些路径、什么时候失效”和它不同）：

| 要加的东西 | 接在哪 | 照哪个例子 |
|---|---|---|
| 一组一致性场景 | `testdata/shared/<组>/` + README + `scripts/go-affected.ts:37` 的 `SHARED_READERS` | `qq-send/`、`qq-frames/` |
| 一个外部工具 | 钉版本和摘要的取数脚本 | `scripts/fetch-tools.ts` |
| 一种验证记录 | 统一记录里加 `step`，不新开文件 | `scripts/go-verify.ts:137` `verifyMygo` |
| 一条流程规矩 | 先进 LESSONS，三个日子再升 AGENTS；能机查的同时加进 `check:docs` | `scripts/check-docs.ts` 的 D14 |
