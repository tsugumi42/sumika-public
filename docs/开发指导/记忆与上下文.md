# 记忆与上下文开发指导

来源：`块-E.md` 第六节（读 main），2026-11-14 核对（main）。路径相对 `native/internal/`。

动手前先答三问，答不出先别写：

1. 这段内容每轮都会变吗？会变只能放请求最后（尾部临时行），不进历史；不变或只追加才可进历史，并想好重建时怎么原样拿回。
2. 它从模型视野消失时去哪了？必须是进了摘要、进了记忆、原话还能搜到之一。
3. 它引用别处的数据（记忆、文件、设置）吗？引用就带条目 id 和指纹，原件变了它跟着失效。

规则：

- 往上下文加东西走 `turn.Contribution`，不自己往 `l.msgs` 塞。正例：`memplugin/plugin.go:431` 的记忆召回只出候选，内核接纳后 `OnAccepted` 才记账。
- 给模型看的固定文字当接口：改前搜它有没有进指纹或被 `HasPrefix` 判断（`turn.ContextHeader`、`history.SummaryHeader`、`turn/workhistory.go:560` 的 `foldHandoffPrefix`）。反例：顺手改报时那行字，`turn/refblock.go:181` 的 `restoredState` 就认不出报时块。
- 新增持久的上下文内容不再开新表：〔目标〕上下文日志现在没有；现行做法照 `store/ref_blocks.go` 的三道门（同档、同卡、引用核对），本地和渠道一起做。
- `memory` 包不引用 `turn`、`store`、`llm`、`app`；要外面的东西在 `memory/ports.go` 加端口方法，如 `EventSource.Find`。
- 记忆写入只有两个入口：`Memory.Remember`（`memory/tools.go:103`）和 `Memory.SummarizeBatch`（`memory/summary.go:166`），不开第三条直接写表的路。
- 配置键要么有读取点，要么不存在；加键的提交带读取代码和改了行为会变的测试。反例：`memory.idleMinutes`、`memory.batchEvents`、`memory.topK` 只在设置页列出（`desktopread/settings.go:49`），后台没读它们。
- “退一步继续”的地方写原因码进结果结构（如 `memory.BatchResult.Skipped`），不只 `return nil`。
- 改压缩或重建必须跑：`turn.TestPrefixRebuildEqualsReuse`（`turn/prefix_contract_test.go:154`）、`TestRebuildPrefixAnchored`、`TestPrefixReport`（`turn/prefix_report_test.go:254`）、`memplugin` 的 `TestRaceCompact*`。
- 不拿摘要当数据库：“以后一定找得到”的写进记忆或留引用。反例：往 `prompts/compact-chat.md` 继续加“某某一条都不能丢”。
