# 渠道与平台开发指导

来源：`块-B.md` 第六节（读 main），2026-11-14 核对。路径相对 `native/internal/`；〔目标〕见 [README](README.md)。

先问：这是某个平台才有的事，还是有这种特性的平台都有的事？前者进平台包，后者写成特性或中间件规则。

1. 平台名只出现在平台包、登记表、配置里。反例：`turn/input.go:180` 的 `s.Channel == "qq"`。正例：按渠道名查策略表、查不到就丢（`app/channel.go:476`）。〔目标〕按 `Traits` 判断，`Traits` 现在没有。
2. 按名字、按表判断一律 fail-closed，不认识就拒绝或只记录。正例：`app/channel.go:156-161` 别的渠道一律 `ModeRecord`。反例：规则只写给某个平台，别的平台整条跳过。
3. 适配器只做翻译、执行动作、报告事实，不写库、不认主人、不判闸门、不重试、不拆条、不读配置。检查：适配器非测试代码只依赖 `alert`、`channel/types`、`selfcheck`（`snowluma` 现在如此）。
4. 往外发只走 `types.Outbox`。新动作 = 新 `Part.Kind` + `Caps` 字段 + `channel/outlet.go:343` `checkParts` 一个分支 + 契约测试 + `channel/fake` 支持；只有一个平台有、又不经模型的动作做成适配器可选小接口（照 `types.Recaller`，`channel/types/adapter.go:224`）。
5. 不往 `Adapter` 接口加方法；新读取能力照 `MessageReader`（`adapter.go:217`）、`HistoryReader`（`:236`）加可选接口，调用处类型断言，没有就报不支持。
6. 回执只有 `confirmed`、`failed`、`unknown`，不许第四种或零值；超时、断线、没回包一律 `unknown`，不重发。机器判断的原因不比 `Err` 里的中文，〔目标〕`Receipt.Code`，现在没有。
7. 新的入站东西归三类：一句话 → `Inbound` + `Seg`，发生了一件事 → `Notice`，连接或账号状态 → `Status`；认不出的留 `SegOther`、`NoticeOther`，不丢不猜。
8. `channel/types` 不写任何协议字段名；平台专有数据进扩展位，翻译在适配器里做完。反例：`channel/types/card.go:35` 的 `qqdocurl`。
9. 会话只用 `types.Conversation`，会话串只经 `String`、`ParseConversation`，不 `strings.Split(conv, ":")`，不 `HasPrefix(conv, "qq:")`。
10. 新平台默认只记录、不发；写完它自己的发送规矩（谁能触发、频率、失败怎么办）并过“形状 × 入口”表，才放开说话档。
11. 一个平台坏了不拖别的平台和本地。〔目标〕致命错 = 该平台 `Login` 进 `needs-action` 带原因码，现在没有，先照 `types.Status` 报告。
12. 状态只有一个事实来源：加“QQ 怎么了”的提醒前，先看它是不是平台状态，是就改状态，提醒从状态派生。
13. 时间从 `types.Clock` 取，测试用假钟。
14. 凭据代码里只出现名字；日志、错误、提醒不带地址里的查询串和令牌（照 `snowluma.CheckURL`、`dialWithin`，`channel/snowluma/connect.go:145`、`:173`）。
15. 〔目标〕每个平台包自带设置项声明、凭据声明、自检函数、契约测试（现在没有统一声明），外加“形状 × 入口”表（行：号空、0、自己的号、错类型；列：该平台私聊和群）。

速查：平台 A 的准入、发送规矩和别人不同，放平台自己的策略（现在是 `app/channel.go:448` 的 `channelPolicy`），不进中间件；功能插件看每条消息用 `channel.Observer`（`channel/pipeline.go:74`），要拦截用 `types.Interceptor`；中间件里要按平台分岔，先看能不能表达成特性布尔；落库 JSON 加字段只加、带 `omitempty`。
