# 界面与交互开发指导

来源：`data/dev/fable-review/块-H.md` 第七节（质检读 main），2026-11-14 对 main 核对（`internal/winshell` 此后没有提交，控件行号不变）。路径相对 `native/`；〔目标〕的含义见 [README](README.md)。写 mygo 界面另读技能 `.claude/skills/mygo-ui/SKILL.md`。

## 八条规则

1. 先填页面蓝图（下面模板）再写代码，贴进规格或提交说明。
2. 控件查下面的表选，不凭感觉；表里没有的形状先加一行并写理由。
3. 页面只通过受控接口面（现在是 `internal/winshell` 的 `Kit`）用组件，不直接 import 组件库实现，不写死颜色、尺寸、圆角、字号、时长（ADR-374、ADR-347）。
4. 〔目标〕设置只在设置目录里加一条，界面自动出，不为一个设置手写状态机；目录记录要带生效时机和后台读取处。现在 `internal/settingsreg` 每个键一条记录（`records.go`），带生效方式、读取处（`readers`，测试核对）和设置页文案（`ui`）；设置页的投影还没改成直接读它（P3-2）。反例：`settings_notify.go:27` 为五个开关写 `notifyToggleUI`；`settings.go:338` 在页面里直接用组件库下拉加“试听”按钮。
5. 一行一件事：一个标题、至多一行说明、一个控件；说明写“这个会怎样”，不写字段名和原理。
6. 每个状态都画出来：加载、空、读不到（带原因）、只读（带原因）、写入中、没存上（带原因）、要重启。
7. 数量乘十再看：十个角色、几百个群、最长的名字、最窄的窗口。
8. 后台没人读的设置不上架，界面不出现可编辑控件。

“提醒”这类对象做成管理页，不塞进设置分类；开发参数的说明可以空着，真写就写人话（“她找顾问最多等多久”）。

## 组件选用表（数据形状 → 控件；文件名都在 `internal/winshell/` 下）

| 形状 | 用 | 不要 |
|---|---|---|
| 布尔，立即生效 | `settings.go:356` `SwitchValue` | 勾选框 |
| 布尔，属于一次提交的表单 | `dialog.go:121` `CheckValue` | 开关（暗示立刻生效） |
| 2～4 个短选项 | `kit.go:216` `Segment` | 下拉 |
| 5 个以上或名字长 | `settings.go:487` `Dropdown` | 一排单选 |
| 很多项或要搜（模型、字体、群） | `settings.go:200` `Picker` | 长下拉 |
| 小范围整数 | `stepper.go:35` `Stepper` | 滑块 |
| 连续量要边拖边看 | `settings.go:427` `SliderRow` | 不需预览的数用滑块 |
| 大范围数（字节、毫秒） | `controls.go:91` `NumberField`，按人习惯的单位显示（单位换算缺） | 让人填毫秒和字节 |
| 短文字 / 长文字 | `kit.go:144` `TextField` / `controls.go:108` `TextArea` | 单行框塞长文 |
| 只读事实 | `controls.go:174` `KeyValues` | 混在可编辑行中间 |
| 进入下一层 / 可展开细项 | `settings.go:269` `ValueRow` / `settings.go:300` `DisclosureRow` | 整页跳转不带返回 |
| 危险动作 | `dialog.go:42` `ActionDialog`，写清后果，按钮写动作名 | “确定 / 取消” |
| 空态、错态、状态标记 | `controls.go:115`、`:130`、`:154` `Badge` | 空白、只靠颜色 |
| 缺（先在接口面补一个受控控件）：选项卡片、本机路径、密钥（只显示已存 / 没存，永不回显）、时间段、字符串列表、多选片、表格、带“测试”的外部地址 | | |
| 对象集合（账号、提醒、定期任务、MCP） | 管理页：列表 + 详情，建、看、改、完成或取消、删五件齐 | 塞进设置行 |

选型顺序：数据形状，其次生效时机，再次选项数量，最后才是好不好看。

## 页面蓝图（动手前填）

页面一句话目标；对象和数量级；层级（页、至多 7 节、行，哪些默认收起）；每个数据项的形状、控件、生效时机、档；七种状态各显示什么；主操作和危险操作的确认话术；窄窗口怎么变；每个标题和说明的文案（一行内、主人的词）；照的是哪个现成页面、不同处及原因。

## 要加东西时往哪接

- 加设置：〔目标〕设置目录加一条，后台读它的地方就是读取处；现在照 `notifications.*`（值、可写、热生效都齐，`internal/settingsreg`）。
- 加控件：先查上表；没有就在接口面加一个受控接口、表里加一行，照 `SwitchValue` 的写法：值进、回调出、禁用态、读屏名；配状态矩阵、几何、键盘操作测试。
- 加页：填蓝图，在新包里写状态结构和画法；还没有现成样板，做完设置页后以它为样板；用 Tester 走完状态矩阵和十倍数据。
- 加一类对象的管理页：列表加详情，建、看、改、完成或取消、删五件齐；结构参考 `workbench_reminders.go`，状态要搬出 `app`。
- 改文案：〔目标〕改文案目录，现在文字直接写在代码里。
- 沿用旧接口还是开新的：能用目录加字段解决就不开；要新的读写形状先写下来再做，配“旧配置能读、旧客户端不崩”的兼容测试。

## 审查

机检（〔目标〕多数还没有检查）：页面包不 import 组件库实现；设置都来自目录；一页不超过 7 节、一节不超过 8 行；可点元素有读屏名、命中区不小于 24×24（常用 32）；状态矩阵逐个构建得出来；十倍数据下的元素数和帧耗时有数（ADR-056）。人看：第一眼是不是这页最重要的事；遮住说明能不能猜对每项；有没有两处说同一件事、内部词漏到界面；常用的三件事各点几下；和相邻页的行高、间距、标题档次是不是同一套。

## 和现行规矩冲突、待定

- 规则 3 的检查（2026-11-14 P0-6 已对齐，`native/internal/archcheck/newui_test.go`）：全模块除 `internal/winshell` 外，任何 .go 文件（含测试、`cmd/`、`_spike/`、带构建标签的）都不许直接 import MewTypeUI、CrychicUI、mygo-m3e；`winshell` 只放开 CrychicUI，其依赖树里不许有另两个；`chatui` 依赖树里一个都不许有。已经在直接 import 的存量登记在 `newui_baseline_test.go` 的 `uiKitBaseline`（文件 × 库），只许变少、不许新增，登记项不成立也红。接口面所在的包是不是只有 `winshell`、mygo 自带控件算不算“组件库”，ADR-374 没写清，现按“只有 `winshell`”“不算”处理，等主人定。
- **过渡期页面该引用什么**：新页面和新改的页面只从 `winshell.Kit` 取控件，选用表里没有的先在 `winshell` 补受控接口；不要为了省事直接 import CrychicUI 或 MewTypeUI，检查会红。老页面里已有的直接 import 先不动，等换到接口面时一起清。
- 规则 4 和档位：设置页分类和“常用 / 进阶 / 开发”三档，主人只说“你先出一版，我看一眼”，没拍板。
- 质检原文还有“新界面包里没有中文字面量（文案目录）”：现在界面文字直接写在代码里，也没有文案目录，没收进规则。
- 质检原文说其余界面文档只算背景：AGENTS 验收仍要求按[设计自查](../设计自查.md)验收，[设计语言](../设计语言.md)的四边等距、圆角同心是硬规矩，没收进规则。
