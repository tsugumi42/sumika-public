# 技术栈开发指导

来源：`块-J.md` 第八节（读 main），2026-11-14 核对。路径相对仓库根；〔目标〕见 [README](README.md)。技术栈已由 ADR-380 定：后台和界面都不换，Rust 只用在隔离执行器和本地模型两个独立小程序上；以后换任何一层，先照 ADR-380 的比较表填。

1. 换技术先填表，不填不讨论：栏目、按层的触发条件、换层前提和测法见 [ADR-380](../决策记录.md#adr-380选型怎么改技术栈不换换之前先填比较表一次只换一层)（要点：换哪一层、不许写“整个后台”；触发的数字和出处；那条缝的共用场景；并存期怎么切、怎么撤；退出条件；一次只换一层；比较表里的数照各家官方写法测）。反例：ADR-345 凭“Go 合并动辄几分钟”决定重写整个后台，ADR-359 又回到 Go。
2. 新代码不让运行期功能依赖冻结的目录或别的软件（`server/`、`desktop/`、`~/.pi`、MaiBot 的环境）；外部程序先登记进工具清单〔目标，现在没有〕。反例（已改，2026-11-15）：开发脚本 `scripts/secret-set.ts` 曾引 `../server/src/web/secrets.ts` 写密钥，现已删掉，改用 `sumika-ctl secrets set <名字>`（P1-2）。
3. 默认不开 cgo（ADR-229、ADR-238 已这样做）；不往 `native/go.mod` 写绝对路径的 `replace`；要用 C 或 Rust 的库，依次考虑纯 Go 的、编成 wasm 用 wazero 跑、做成子进程。正例：`native/internal/pdftext/engine.go` 用 wazero 跑 pdfium。反例：`native/go.mod:69` 指向 `<本机项目>/MewTypeUI`（待办 P0-2）。
4. 界面要后台的东西，先在 `protocol/sumika-rpc.json` 加方法并用 `scripts/gen-rpc.ts` 生成，不在根包直调后台。反例：`native/inproc_rpc.go:14` 一带，界面靠内嵌 `*DesktopReader` 直调。
5. 跨语言的缝（RPC、插件契约、持久格式）加东西只许加：加方法、加可选字段随时可以。〔目标〕破坏性变更检查，现在 `scripts/gen-rpc.ts --check` 只比对生成文件。
6. 返回的错误要么处理、要么带原因往上传、要么写明为什么可以丢（LESSONS 已有）。〔目标〕“没有注释的 `_ =` 过不了检查”，现在没有。
7. 并发约定写成断言，不写成注释：“这里不许回调 X”用运行时检查兜住，测试里故意违反看它红。
8. 脚本插件只用 `sumika.*` 和标准 JS，参数和返回值只许是 JSON 能表示的值，不把 Go 结构体指针给脚本。
9. 选新依赖写三行：创建时间和最近提交、主要维护者几人、许可证；不满三个月或只一人维护的写清退路。正例：`native/internal/localmodels/ort/backend.go:11`“换绑定只换这一个文件”。
10. 说“更快”“更稳”要带数：引用量过的或现量一个，没有就写“不确定”。

## 和现行规矩冲突、待定

- 质检原文是“不许 cgo”，比 ADR-229 严：ADR-229 只说不开 cgo、留 cgo 绑定作退路，`localmodels/ort/backend.go:11` 也留着口子，所以规则 3 写成“默认不开”，待定。
- 质检原文规则 5 还有“删和改类型留两个次版本过渡”：上级 AGENTS 不做没有需求支撑的兼容层，迁移一节要求旧格式兼容集中并标寿命，未收进，待定。
