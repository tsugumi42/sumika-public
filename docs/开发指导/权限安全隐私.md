# 权限、安全与隐私开发指导

来源：`块-F.md` 第六节（读 main），2026-11-14 核对。路径相对 `native/internal/`。整页权限类，主人没看过。

1. 新工具声明跟着工具写，效果照实填：查天气写“联网读”、听众“任何”、走默认放行；不为“不想弹卡”写成 `self`。反例：`policy/policy.go:125` 的 calendar、weather、exchange_rate。
2. 不许按工具名写判断，要特殊对待就给声明加字段。反例：`policy/policy.go:590` 的 `tool == "open"`。
3. 谁能用、谁能看只调立场函数，不拆会话字符串。反例：`approval/approval.go:360` 的 `":group:"`。
4. 要问主人只走 `Approvals.Ask`（`approval/decide.go:633`），不自己建等待、不自己画卡；结局落库以后才算数。
5. 门里算位置和执行时算位置用同一个函数（LESSONS 已有）；新加一种路径写法，先加到归一化函数，再加一条“门和执行结果一致”的测试。
6. 失败往严的方向退，并且说出来：读不了规则当没有放行规则，写不进记录按拒绝，同时发提醒。反例：`policy/risk.go:151` 防线的输入为空就返回“没碰到”，而没有人负责填这个输入。
7. 放宽任何默认值之前：写 ADR、过“形状 × 入口”表、主人拍板；有审批度量就附上，没有不拦（主人 2026-11-14：度量不当硬前提）。
8. 新的协议入口（MCP、ACP、新平台）：先定来源种类和默认立场（默认不是主人），再把请求映射成动作描述，不许另开一条判定路径。
9. 密钥只存名字引用；值只在发请求那一行取；错误和日志里不出现值；新增用途先确认脱敏名单覆盖到。
10. 开新接口：有副作用的东西映射成动作描述；新的问主人场合给 `Request` 加可选字段；新的隔离、审查方式实现对应端口；三者都不是才考虑新接口，并先写进规格。
11. 判定改动加整表用例；门的改动加“改坏会红”的用例；涉及场合的列全四种。
