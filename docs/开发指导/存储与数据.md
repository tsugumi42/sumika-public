# 存储与数据开发指导

来源：`data/dev/fable-review/块-G.md` 第七节（读 main），2026-11-14 核对（main）。路径相对 `native/internal/`；〔目标〕见 [README](README.md)。

1. 新增落盘的东西先登记再写代码：路径从 `paths` 取，类别进 `storagestat/category.go` 的 `categories()`。共用记忆库路径已收进 `paths.OwnerMemoryDB()`（P0-7），`archcheck` 的 `TestOwnerMemoryPathOnlyInPaths` 守着生产代码不再手拼。〔目标〕写明保留期和备份方式的数据清单，现在没有。
2. 开库只走一个入口，声明读写还是只读。反例：`memory/backup.go:37`、`memory/db.go:66`、`memory/index.go:59`、`memory/migrate.go:147` 各抄一份 `sql.Open`，PRAGMA 不同；底座入口是 `store/store.go:97`。
3. 包外不写 SQL、不传库句柄，在所属领域的仓库加窄方法。反例：`turn/approvalsteps.go:32`、`:43` 直接 `st.Trace.Exec`。
4. 写迁移前判断类别：加法（只加表、可空列、索引）、重建派生、改写原始数据。迁移号先在 main 占号（AGENTS 已有），低号晚合并会让已升级的库启动失败。〔目标〕同提交涨每库最低兼容版本（待办 P1-4）。
5. 迁移是唯一批量改真实数据的自动动作：先快照，后迁移，失败只停这一块。反例：`store/store.go:221` 打开即迁移。〔目标〕待办 P1-4。
6. 派生数据和原始记录分开放，备份不带。反例：`store/migrations/events/0005_raw_search.sql` 把检索索引挂在事件表触发器上。
7. 跨库、跨文件、进导出包的引用用事件 `id`，不用 `seq`。
8. 写文件先写同目录临时文件、刷盘，再 `fileatomic.Replace`（`fileatomic/rename.go:13`），JSON 带 `version`。现在没有统一的写函数（`approval/decide.go:441`、`desksettings/desksettings.go:188` 各一份），新代码先收成一个。反例：`goal/store.go:64` 用固定 `.tmp` 名、不刷盘。
9. 每种数据要回答“留多久”。反例：`store/task_runs.go:21` 注释写“由存储页的清理规则管”，规则不存在。〔目标〕维护调度器执行并写 `maintenance_runs`，现在该表只存占用统计。
10. 配置里的开关要么生效，要么标明没生效。曾经的反例：`backup.daily` 没人读（已修，`3d0a461d4`，现 `app/backup.go:72`）；仍在的见[记忆与上下文](记忆与上下文.md) 的 `memory.topK`。
11. 测试专用行为不放进生产路径，用构建标签或测试包注入。反例：`store/write.go:34` `NewID` 判断 `testFastSync`。
12. 存进库的路径只能相对数据目录或内容哈希；用户选的外部目录可存绝对路径，读时检查还在不在。

别人要长期读的东西（导出、备份、插件）是契约，先写下来再动手。
