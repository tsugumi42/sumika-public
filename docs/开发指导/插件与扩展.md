# 插件与扩展开发指导

来源：`data/dev/fable-review/块-D.md` 第六节（质检读 main），2026-11-14 对 main 核对。路径相对 `native/internal/`；〔目标〕的含义见 [README](README.md)。插件分内置、脚本、进程外三档，见 ADR-376。

1. 先分清加的是哪一种：内核订阅事件走内部订阅口、不进插件表；用户看得见、关了有明确后果的功能才是插件，必须有清单；能被主人、命令行、模型触发的动作是操作登记表里的一条〔目标，登记表现在没有〕。反例：`app/goalwire.go:128` 的 `goalPlugin` 是内核接线借了插件的壳。
2. 工具的风险声明写在工具旁边，不去别的包按名字加分支。反例：`app/kernel_wiring.go:113` 的 `switch name` 里再加 `case "新工具名"`；写到第三个文件时停下，说明接错地方。〔目标〕`Tool{Decl, Spec}` 自带声明加声明快照测试，现在 `turn.Tool` 只有 `Decl`，`Spec` 在 `policy.Specs` 全局表（后续路线 P4-2）。
3. 运行时会增减的来源（MCP、脚本、技能）只走“目录 + 调用”元工具，不进固定前缀。正例：`mcpplugin/plugin.go:24` 起的 `mcp_search`、`mcp_call`。反例：让热加载脚本直接往工具清单注册。
4. 插件之间只通过服务表说话：提供方登记，用方清单写 `Requires`，用 `turn.AssetsOf` 取（`turn/assets.go:9`、`:50`）。反例：`skills/resources.go:12` 起为拿工具声明 import 了 `mcpplugin`、`subagent`、`web`。
5. 每种失败要有三样：插件日志一行、状态可见、能恢复。正例：`turn/plugin_reconcile.go:242` 起 `start()` 失败写日志、状态 `failed`、改开关可重试。加任何“停用、隔离、暂停”状态之前先写出怎么解除；正例：MCP 的隔离有解除入口（`sumika-ctl mcp release`，必须写原因）、状态可见（`mcp status`、提醒、自检 `mcp.quarantined`）、本机服务能自动重连（`mcpclient/recovery.go`、`app/mcp_quarantine.go`）。
6. 依赖外部的东西（PATH 里的程序、模型、别的服务）用清单 `Requires` 声明，缺了是 `pending` 加原因；不要在 `Setup` 里返回错误或悄悄跳过功能。
7. 要不要开新接口：现有钩子、服务表里能不能表达；会不会在数据目录或别的进程里留下依赖它的东西（会就是稳定契约，先带版本和跨实现测试）；是不是只为一个插件开的（是就做成可选接口，照 `Manifested`、`Reconfigurer`，`turn/plugin_reconcile.go:46`、`:437`）。反例：`turn/plugin.go:64` 把记忆专用的 `Contribution.Refs []MemoryRef` 放进通用契约。
8. 〔目标〕给模型的能力先问“能不能做成登记表里的一个操作”：一个操作同时得到命令行、设置页入口、脚本函数、审批分类、撤回方式，一个工具只得到工具。
9. 沿用外部格式时做超集，不做方言：`mcp.json` 兼容 Claude Desktop 片段、自己的开关放 `sumika` 段（`mcpclient/config.go:37`）；技能 frontmatter 照规范、自己要的放 `metadata`。不改上游字段含义。
10. 〔目标〕写脚本宿主函数（`sumika.*`）：参数和返回值只用 JSON 能表达的类型；不给路径、密钥、别的插件的数据，要用密钥由宿主在出口加；每个函数对应登记表里一个操作，效果如实填。

## 和现行规矩冲突、待定

- 规则 8 的“操作登记表”在 ADR-376 里只在第 7 条被提到（Code Mode 要等它），没有哪条 ADR 定过，待主人定。
- 规则 10 的 `sumika.*` 脚本宿主还没写，范围随后续路线 P6-2 的规格定。
