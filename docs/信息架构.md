## 定位

Sumika 就是一个 IM，主人自己也在里面。会话分两种：

- **本地**：普通的 agent harness。主人直接找角色说话、让她干活，有工具、审批、本轮注入，相当于现在的主窗口私聊。以后也会有本地的群聊（几个角色和主人一起聊）。
- **QQ**：角色在 QQ 等外部社交平台上和别人聊天。这里像 MaiBot 的面板，**只展示角色实际能拿到的聊天记录**；主人想正常聊天就直接回 QQ（或在 QQ 上私聊这个小号）。在 Sumika 里，主人只能用"耳语"提醒她（见下文）。以后给她做的内部浏览器（自己去逛社交网站）也归在这里。

导航栏显示图标和名字；会话列表顶部放搜索框和收起按钮。

同一个角色在两种会话里共用一份记忆，但上下文分开（ADR-012～014）。

**没有系统标题栏**：窗口隐藏系统标题栏，系统三键浮在右上角；MewTypeUI Title 槽统一保留原生控件高度和左右避让，拖动带只留一条。聊天顶栏使用 chat.Header，基准最小高 54 DIP，文字放大后按度量增长。记忆、运行和设置整页也留同一高度的原生标题带，内容从下方开始。

**主动收为头像、窄窗切为单栏**：用户把列表收起时仍保留头像入口；窗口不足双栏宽时切列表/聊天页面，打开第三栏则占主槽，不再盖住聊天。

### ② 会话列表

- **选中本地**：分两组，先列出所有角色，再列出这些角色组成的群聊（本地的群聊）。角色每项是头像、名字、职业标签、最后一句话；正在想或正在等审批时显示状态小点。右上角"+"新建角色或群聊。
- **本地群实现**（2026-11-03）：会话列表提供“新建群聊”，弹窗起名并选 2–10 个角色；空群用创建时间列出。群消息按实际角色 ID 显示名字和头像。输入框暂不接，建群、发消息、停止的可选接口见[本地群聊规格](规格-本地群聊.md)。
- **选中某个平台账号**：列出这个账号上已接入的私聊和群聊。
  - 每个会话头像的右下角叠一个小的角色头像，表示"这是谁在聊"；两个角色都在同一个群时叠两个。
  - 顶部一排筛选：全部、有新消息。"只看某个角色"以后群多了再加，现在角落的小头像已经能看出是谁在聊。
  - 排序：最近活动在上，置顶的会话固定在最上面。
- 列表最上方是搜索框和收起按钮，整行空白处仍能拖窗口；按显示名和最后一句文字过滤当前已取到的列表，不分大小写、去首尾空白、空词不过滤。本地和 QQ 各留自己的搜索词，搜不到显示“没有匹配的会话”；收成头像的窄列表不放搜索框。

### ③ 聊天窗口

- **顶栏**：现有 mygo 界面为 `Theme.Space(13)` 高的紧凑一行，左边是半粗会话名（1.1rem，Windows 默认 15.4 DIP，过长省略、悬停全文）和下面的条数 / 取数据中 / 本地翻到头小字；右边只有加载更早消息、右侧栏开关的图标按钮，演示模式另有万条压测图标。搜索行、聊天顶栏、右侧栏标签行等高、底边对齐；隐藏标题栏且右侧栏并排时，三行一起排在三键空带下面。兜底加载图标常驻、加载中和翻到头禁用（我定的，2026-11-02）。设计中的在线状态和模型（本地）或群人数（QQ）、搜索本会话、多角色切换仍未接入。
- **消息流**：气泡、工具卡片、审批卡片、Markdown、表情回应。
  - 群聊（QQ 群、本地群）：每条消息带发言人的头像和名字，连续发言合并成一组只显示一次。
  - 私聊：不显示头像和名字（像 Telegram 的私聊）。
- **输入框**：
  - 本地：打字就是对她说话。
  - QQ：**只有耳语，没有插话**。输入的内容只给角色看、绝不发到平台上，实现上和 steer 一样。（ADR-302：交给这个会话的前台；要干活时前台开工单交给后台。）两种用法：
    1. 框选或点选一条（或几条）聊天记录，"回复"给她，相当于"关于这条，我想说……"；
    2. 直接打字提醒她。
  - 耳语就在聊天窗口里完成，不跳到右侧栏。耳语记录以小字显示在时间线里（只有主人看得到），标明是给哪个角色的。群里有多个角色时，耳语前先选给谁。

### ④ 右侧栏

用顶部标签切换，内容随会话类型变化：

| 标签 | 本地 | QQ |
|---|---|---|
| 本轮注入 | 提示词各段落、注入的记忆、用时和用量（现有面板） | 同左 |
| 她在想什么 | — | 她看到了哪些消息、打不打算接话、准备怎么回、为什么不回；正在生成的草稿。同群有多个角色时，用顶栏的角色切换来切换显示谁的 |

## 竖栏下方的全局界面

点开后占据 ②③④ 的位置；按 Esc 或点竖栏其他图标回到会话。

### 通知中心

按"需要我做什么"分组，每条都能直接处理，不用跳走：

- **待审批**：工具调用（写文件、跑命令）。可以批准、拒绝、查看详情。
- **待解答**：角色看不懂、想问主人的（梗、表情含义、群里的事）。回答后写进公共知识层。
- **待确认的记忆**：后台总结出的"待定"条目。可以确认、修改、丢弃。
- **连接问题**：掉线、风控、重连失败，附带上次正常的时间和处理建议。
- **系统**：更新、挂机异常、磁盘或模型额度提醒。

### 全局搜索 / 命令面板

搜消息、角色、记忆、公共知识；也能执行命令，比如"切到 A""打开设置""换模型"。

### 运行（原叫"运行状态"，中间叫过"数据中心"）

- **用量**：按模型、角色、天统计调用次数、token、缓存命中、首字时间、费用（参考 Magpie）。
- **性能**：Sumika 和嵌入进程的内存、运行时长、挂机记录；还有数据健康度（每类数据多大、每天涨多少、预写日志、上次维护清了什么、离提醒线多远，见 [规格-数据与日志.md](规格-数据与日志.md) 第九节）。
- **模型岗位**：回复、构思、要不要接话、总结、识图分别用哪个模型。

### 设置

- **外观**：挑选页的正式版，所有选项都保留。
- **模型**：Magpie 连接、模型列表。
- **工具与审批**：审批模式（手动 / 自动 / YOLO）、工作目录、允许自动放行的目录。
- **平台账号**：添加或移除账号、SnowLuma 连接地址、收发自检。
- **通知**：系统气泡、提示音、免打扰时段。
- **数据**：数据目录、备份、导出。
- **快捷键**

## 从会话里打开的界面

### 角色详情

> ADR-304（2026-11-07）：聊天里点头像打开资料（角色进右侧栏资料，群友弹资料卡），资料里点头像才看头像大图；资料卡等浮层从触发位置长出来。资料里关于这个人的内容按 ADR-297、298（条目；客观事实共用、关系和印象分角色）。

放在右侧栏的"资料"标签里（参考 Telegram 频道和群的右侧资料栏）：顶部大头像、名字、一排快捷按钮，下面分组列出信息。点会话顶栏的头像，或会话列表右键菜单进入。

规律（照搬 Telegram）：内容多、要常看的放右侧栏（角色、群）；只看一眼的用浮层卡片（群友：点头像弹出小卡片，显示昵称、QQ 号、她对这个人记住了什么）。

角色详情的内容：

- **人设**：核心人设（主人写，角色改不了）、标签、编辑文件。
- **成长记录**：成长层的改动，每条都有理由和证据，可以撤回。
- **记忆**：事实、片段、待定、已撤销；可以搜索、编辑、删除，能看到每条是从哪次对话来的。
- **模型**：她自己的回复模型和后台模型。
- **她在哪些地方**：本地，以及她接入的私聊和群聊。

### 公共知识层

主人确认过的梗、表情含义、群常识，所有角色共享。从通知中心的"待解答"进来，或者从设置里进。

## 多个 QQ 账号（2026-10-13 补充）

最麻烦的情况：两个角色分别登录两个 QQ 号，各自加了不同的群，也可能加了同一个群。

- **数据上**：会话的身份是"平台 + 群号或对方号"，与"哪个号看到的"分开存。同一个群被两个号同时看到时，消息只存一份，每个号各记一条"我看到了"（与 Notion 研究 34「事件溯源」一致）。
- **界面上**：
  - 竖栏按平台放一个 QQ 图标；点开后，侧栏顶部有"全部 / 按账号"切换，默认"全部"。
  - 同一个群只出现一次，头像角上叠两个角色的小头像；进群后，两个角色的发言都在同一条时间线里，各用自己的角色色。
  - 只有一个号在的群，就只叠那一个角色。
  - 按账号筛选时，每个群下面注明"通过哪个号"。
- **耳语**：同群有两个角色时，耳语前先选给谁；主人不会以任何一个号的身份在群里发言。

## 聊天记录要支持的 QQ 消息形式（2026-10-13 补充）

- 内容：文字、图片、表情包（自定义表情）、QQ 小黄脸（face）、超级表情（mface）、语音、文件、视频、合并转发、引用回复、@ 人、链接和小程序卡片。
- 通知（单独一种小字样式，不当成气泡）：撤回、戳一戳、禁言、进群退群、改群名片、贴表情回应。
- **图片和表情包的描述**：给 bot 看的那段文字描述也要能看到。平时正常显示图片；鼠标悬停时图片变模糊，描述浮在模糊层上面。表情包另外注明含义来自哪里（主人确认的 / 本群学到的 / 通用含义，对应设计文档里表情含义的三个来源）。
- 补录的消息（断线期间补回来的）有一个小标记。

## 两种消息样式（2026-10-13 补充）

风格挑选页的对话更像 IM，却没有群聊里每条消息的头像和名字；作为本地的会话，又缺少了模型、用时、用量这些信息。线框图要分开设计：

- **群聊**（QQ 群、本地群统一）：每条消息带发言人的头像和名字（群友用自己的 QQ 头像和昵称，角色用角色色），连续发言合并成一组只显示一次头像；引用、表情回应、撤回、戳一戳都要有样式。
- **私聊**（QQ 私聊、本地私聊统一）：不显示头像和名字，像 Telegram 的私聊。
- **本地额外要有**：每条回复能看到用的模型、首字时间、token、注入了什么（悬停或展开显示）。

## 线框图评审后的决定（2026-10-13）

线框图：（私有链接）

- **导航栏**：
  - "运行状态"当时改叫**数据中心**（用量、性能、运行状态；后来 ADR-061 拆成"记忆"和"运行"两个入口）；
  - 最底下的"主人"是**我的资料**：主人自己的设定，以及每个角色怎么认识主人（可以查看、纠正）；
  - 搜索是**全局搜索**：消息、角色、记忆、公共知识，也能当命令面板用。
- **会话列表**：可以拖动改变宽度（像 Telegram），最窄只显示头像；按住拖动时边上出现一条小竖条。同一个会话里角色多时，最多叠两个小头像，后面接"+N"。
- **本地的输入框**：下面一行放模型选择、思考强度、快速模式，以及上一轮的首字时间、输出速度、缓存命中、本会话花费（参考 DeepSeek Harness）。**本地和 QQ 的模型分开设置。**
- **右侧栏**：顶部改成图标标签条，能放更多面板。（已被 ADR-263 改为"资料／活动／请求详情"三个有字的主项，工作面板按任务出现；又被 ADR-293 改为按场合分：本地私聊默认表情、文件、终端（命令行）、上下文、资料、活动，平台上是活动（运行日志）和资料。）
  - 本地：注入、子代理、终端（后台任务）、文件（文件树）、预览（文件预览）、资料；
  - QQ：这一轮（按步骤：收到的消息 → 要不要接话 → 思考 → 动作 → 发送前检查）、注入、群资料；
  - "看谁的右侧栏"的角色切换放在右侧栏自己的顶部，不放聊天窗口顶栏。
- **QQ 的聊天窗口**：
  - 顶栏去掉"只读，回复请到 QQ"这类说明；在群里的角色用小头像表示，不用文字；
  - 耳语记录用耳朵图标加角色头像（普通头像，不用 Orb），不再写"只有你看得到"；耳语放在聊天窗口里，方便针对某条消息补充解释；
  - 表情包和图片一样：含义或描述在悬停时模糊背景显示，或点开大图后在图片下方显示（像图片查看器），不注明来源。
- **角色详情**：人设显示完整提示词的开头几行，不显示标签；标签只用于"新建角色"时的引导。职业是可选功能（"AI 同事"风格），默认不开。
- **新增"通知中心"**：占满导航栏右边的三栏；按类型筛选；连接问题排最前；每张卡片都能就地处理（批准/拒绝、直接回答、记住/修改/丢掉、立即重连）。
## 第二轮评审（2026-10-13）

## 第三轮评审（2026-10-13）

- **措辞**：界面上不用"耳语给 A"（像机翻），改成"对 A 说"。
- **对她说 = steer**：她正在想的时候，你的话插进下一步，不打断；她没在想，就和群里的新消息一起叫醒她。
- **引用样式**：统一用圆角竖条 + 被引用人颜色的浅色圆角底（Telegram 手机版），不用左侧彩色粗边。
- **时间戳**：气泡右下角放发送时间（Telegram）；会话列表每项右上角放最后一条的时间，隔天只显示日期。
- **头像**：群聊里头像放在一组消息的底部，滚动时贴着这一组滑动（Telegram），本地和 QQ 都一样。
- **会话列表的 +**：拆成"角色 +"和"群聊 +"，各管各的。
- **正在回复的状态**：分阶段显示（读上下文 → 等首字 → 思考中 → 输出）；群聊里思考默认折叠，回复旁边留一个思考图标，点开再看。
- **工具卡片**：用图标说明是什么工具（搜索网页用地球），完成用勾，不写"完成"两个字。
- **本地群聊的输入框**：去掉思考强度和花费；思考强度在群资料里按角色设，花费在群资料和运行页看。"谁来回答"默认"她们自己决定"：各自的闸门判断要不要接，同一件事只让最合适的一个先说，另一个有新内容才补充。"角色之间连着说"只算你没说话时角色之间连着发的消息，干活时的工具调用和多步思考不算。
  - 2026-11-03 的本地群实现范围与起步参数以[本地群聊规格](规格-本地群聊.md)为准：确定性轮转、@ 优先、整轮最多两个角色、自动续接一层；这里的各自闸门和群资料调参属于后续设计。
- **右侧栏**：
  - QQ 的"这一轮"改成流式记录（像 harness 里看她输出）：收到的消息、要不要接、你插进来的话、思考（可展开）、工具、发出的消息、发送前检查；没有输入框。
  - 本地群聊不要"这一轮"，思考和工具已经在聊天里了。
- **通知中心**：
  - 跳转按钮和其他按钮同一种形状，用中性灰，不用超链接蓝；
  - 待解答卡片去掉说明文字，高频卡片只放必要信息；
  - 记忆确认只放一条汇总，点进记忆页 › 记忆处理；
  - 排列方式可切换：按紧急程度排（宽窗口自动换行）/ 按类型分列（像 Trello 看板）；
  - 连接卡片以后换成对应平台的图标。
- **公共知识分四档可信度**：你确认过 / 你随口答的 / 群里学到的 / 网上查到的。待解答里的回答进"你随口答的"，不直接当事实；可以再点"确认"升档。
- **记忆页和运行页**（当时合在"数据中心"里，ADR-061 拆开）：用量、性能（运行页），记忆、公共知识（记忆页）四页；记忆的确认队列放记忆页。
- **角色详情**：去掉"聊天"和"编辑人设"（和下面的人设卡片重复），快捷按钮改成记忆、人设版本、暂停、更多。
- **新建角色**：
  - 三步：人设 → 名字和外观 → 可选（职业、去哪些地方）；标签、完整提示词、试聊在同一步；来回切换不丢内容；导入已有设定、复制现有角色放在左下角。
  - 标签可改，写几个词让 AI 联想（分类和联想方式待定）。标签改了不自动重写提示词，只提示"不一致"，点开先看改动再决定。
  - 提示词有版本号和版本历史（像 git）；字数给经验范围（600～2,000 字，不是硬标准）。
  - 试聊有"重新开始"；提示词改了会提示"这段是旧版说的"；可以存测试题，用同一组题对比两个版本。
- **QQ 的表情回应**：QQ 自己的表情（小黄脸、超级表情、表情回应）不映射成 emoji，按 QQ 的表情编号显示 QQ 自己的图（动态的也照样播）；只有本地的表情回应用 Twemoji。

## 记忆和公共知识的区别（2026-10-13）

| | 记忆 | 公共知识 |
|---|---|---|
| 属于谁 | 每个角色自己的，A 看不到 B 的 | 所有角色共用 |
| 讲什么 | 具体的人和事：你、群友、发生过什么、约好了什么 | 跟具体某个人无关的常识：梗、表情含义、某个群的规矩 |
| 怎么来的 | 她自己的经历，后台从聊天里整理 | 你教的、你确认的，或从群里多次学到、网上查到 |
| 可信度 | 事实 / 待定，按版本更新 | 四档：你确认过 / 你随口答的 / 群里学到的 / 网上查到的 |
| 在 QQ 上 | 按可见性检查，私聊的内容不会在群里说出来 | 按范围用：全局的哪里都能用，标了某个群的只在那个群用（ADR-034） |

判断方法：**和某个人有关，进记忆；和某个词、某样东西、某个群的惯例有关，进公共知识。**

## 框架：继续用 pi（2026-10-13 调研）

- 主人问 opencode v2（也是 TypeScript）和 pi 哪个合适。结论：**继续用 pi**。
- 理由：
  - pi 是纯库，直接调模型，不用起服务；上下文怎么拼完全由我们控制（transformContext 等钩子），和"只追加"的缓存策略合得来。
  - opencode 的 SDK 目前要连它自己的服务端，每一步从持久化历史重建上下文。v2 还在快速变动，公开的嵌入接口没查到。
- 可以借鉴 opencode v2 的三点：
  1. 输入先落库再唤醒；
  2. 按会话 ID 隔离并发；
  3. steer 在安全的步骤边界投递。
- 我们已经用的是新包名 `@earendil-works/pi-*`（旧的 `@mariozechner/*` 已标弃用）。
- 待办：pi 没有多 key 轮换，要在我们自己的模型层做；多个角色同时跑各自的 Agent 实例，文档里没写，需要自测。
- 出处：https://github.com/anomalyco/opencode/tree/dev/specs/v2 、https://github.com/earendil-works/pi/blob/main/packages/agent/README.md
- **2026-10-14 补充**：上面"SDK 要连服务端"的说法过时了。v2 的 `@opencode/sdk`（2.0.28）可以进程内嵌入（`OpenCode.create()`），插件能换供应商地址、改每一步的上下文、管审批。做了一次探针（临时目录，约 30 次请求）：
  - 通过：Bun 上进程内运行、经 Magpie 流式、两个会话人设隔离、只追加时缓存命中 97.8%～98.6%、steer / queue 在步骤边界送达。
  - 没过或没验证：审批端到端（自定义工具没暴露给模型）、会话历史存在它自己的库里且位置改不了、几轮后内存约 300 MB、默认注入约 1.7 万 token 的编码系统提示和 12 个工具要全部替换、Windows 上 3 个依赖的安装脚本被拦。
  - 结论：继续用 pi；opencode 留作以后"写代码"的子工具。

## 本地私聊分话题、斜杠命令（2026-10-13 主人确认）

- **话题**：和普通 harness 一样，一个角色的私聊可以开多个话题。点进角色后，会话列表换成她的话题列表（像 Telegram 的话题群），分"置顶""最近""已归档"。
  - 操作：置顶、重命名、分叉、归档、删除（删话题不删记忆）。
  - 分叉：从某一轮复制出一个新话题，两边各走各的。原话题里留一行"从这里分出了……"，新话题标明出处。
  - 上下文和缓存按话题分开，记忆是同一份。上下文快满时自动压成摘要，也可以用 /压缩。
- **斜杠命令**（只在本地）：输入 / 弹出，按"话题 / 记忆 / 其他"分组，例如 /新话题、/分叉、/压缩、/记住、/忘掉、/模型、/任务。↑↓ 选，Tab 补全，Esc 收起。
- **新建角色第 2 步**：名字和小名；头像三选一（图片裁剪 / Orb / 只用首字）；角色色在同一色系里自动避开已用的，也可以从头像取色；右边实时预览列表、群聊、深色模式里的样子。
- **新建角色第 3 步**：职业从已有的里选或不要；QQ 要选账号和群、设群昵称。一个号同一时间只给一个角色用；完成后 QQ 默认不开，要在资料里打开。
- **设置 · 职业**：职业单独管理，可以给几个角色套用。每个职业有：工作说明（接在人设后面，带版本）、能用的工具（哪些要批准）、工作目录、工作记忆的三个开关（QQ 不带、成长层不学、职业习惯流露默认关）。
- **QQ 私聊**：对方的话在左、她的在右，不显示头像；只能"对她说"；右侧栏里有"对方资料"（她对这个人的了解、关系、约定）。被问到你的事时，只说"我的资料"里允许说的。
- **设置 · 平台账号**：按平台分组；每个账号显示连接地址、在线状态、分给哪个角色；收发自检逐项列出（升级 SnowLuma 或 QQ 后再测）；添加账号四步：选平台 → 填连接地址 → 自检 → 分给谁。Sumika 只连接 SnowLuma，不负责安装和登录 QQ。

## 第八轮评审（2026-10-13～14）

- **通用**：所有菜单项都是"图标 + 文字"；不用 emoji 和 ✓✕ 字符当图标；确认框按严重程度用不同图标（能恢复的用提示图标，找不回来的用警告图标和红色按钮）；"取消"改叫"算了"，免得和"撤销"看混。
- **改名**："公共知识"改叫**共享常识**，按种类分：梗和黑话、表情的意思、群里的规矩、圈子常识、其他；再按四档可信度筛。和某个人有关的东西不在这里，在记忆和人物画像里。
- **记忆页新增"人物画像"**（已被 ADR-297 扩成"条目"：人、虚构角色、作品、产品、群、事件统一一套，真实的人挂平台账号、机器人号单独标，角色卡另放）：她们认识的人。身份认 QQ 号（极少数会换号），名字只当线索：常用称呼、QQ 昵称（含曾用名）、各群的群名片、别人对他的叫法。QQ 昵称可以重名，也可能和其他平台上的人撞名，所以听到这些叫法只当"可能在说他"。下面分角色显示"A 眼里的他""B 眼里的他"，两边互相看不到，只有主人能同时看。（已被 ADR-298 改为：客观事实共用、记谁在场听到；关系记录和主观印象按角色分栏；角色之间共享，不在场的知道是听来的。）
- **表情包**：瀑布流，按原比例显示，往下滚自动加载；透明底用棋盘格，动图标"动"。意思用关键词标签，打完按回车就加一个。每一项点着就能改。来源只记第一次收到的群。可信度旁边有"没错"，点了升到"你确认过"。谁能用：点一下变灰，就是不让她用。删除叫"忘了吧"。同一个文件只存一份；长得像但不是同一个文件的放进"长得像的"等主人挑，推荐清晰的那张（参考 Eagle）。
- **右侧栏的工作面板**：
  - 子代理用鸟的名字（山雀、翠鸟、戴胜……），**没有角色的人设**，只照她给的任务做。展开后像一个普通 agent 的对话：她给的任务、跑了什么、进度；她可以对子代理插话；收起时一行结果预览，太长就省略。
  - 终端数量不固定，改成列表（状态点、命令、时长），点一个看输出；审批只写方式：自动放行 / 手动批准 / 免审批。
  - "文件"改叫**工作区**：她的工作目录树 + 预览（行号、Markdown 渲染、图片视频音频预览），兼容长文件名、横竖滚动条。
- **回复的四个阶段**各是一种样子：读上下文（三个点）→ 等第一个字（灰色占位）→ 思考（和工具调用同样的小卡片：图标、用时、转圈或勾，点开看思考流式出来）→ 输出（直接在气泡里出字）。
- **她说话时你又打了字**：两种发法。插话（Enter，她做完手上这一步马上看到，不打断）和排队（Alt+Enter，这一轮结束后自动接着发）。
- **本地私聊**：气泡宽度按内容，不强行对齐；一轮结束后最后一条消息下面显示这一轮的输入输出 token、用时、平均输出速度（只算出字阶段，不含等首字）。输出速度在生成时实时更新。
- **所有聊天窗口**右下角有"跳到最新"按钮，带新消息数。
- **QQ 会话列表**：默认最新的在上，右上角按钮换排序方式和正倒序；分组可以折叠；在场角色的小头像挪到第二行末尾，不压文字。
- **通知中心**："待审批"改叫"待审批请求"。
- **记忆**："原话"点开是一个小弹窗：那句话前后的聊天，原话高亮，可以跳到会话里。
- **定期任务**：内部用 cron；界面上用好懂的写法，详情里附 cron 表达式。分"她们的"（以她的身份做事、会说话）和"维护"（反思、整理记忆、备份，不说话）。结果可以发到私聊、新话题、系统通知、QQ 私聊，以后加手机。角色想加的任务大多在聊天里当场问；没处理会留在这里，到点还没同意就作废，显示"改个时间 / 算了"。
- **新建角色**：
  - 点头像换图，悬停时右下角出现笔。
  - 小名可以几个，第一个是常用的；听到后面几个只当"大概在叫我"。
  - "不设职业"叫"通用"：什么都能做，只是没有专门的工作说明和工具清单。
  - 群名片从 QQ 读，要改得在 QQ 里改（或等 SnowLuma 支持）。
  - 谁能找她、在哪说话的黑白名单，之后参考 AstrBot、MaiBot。
- **职业**：工作说明是所见即所得的 Markdown；工具的"直接用 / 要你批准"做成可以点开切换的样子；用的角色直接写名字，超过三个省略。三个开关：在 QQ 上想不起工作的事 / 性格不跟着工作变 / 闲聊时带一点职业病。职业和"通用"的区别只在工作说明、能用的工具（含 MCP、skill）、工作目录、审批默认值、工作记忆标签；人设、主体记忆、外观都不变。
- **记下待做**：QQ 聊天要兼容 OneBot 能收到的所有消息和提示（小程序、禁言、合并转发、视频等）；"学到的"页信息太少，之后参考 MaiBot 重做；平台账号的收发自检怎么展示，实现时再定。

## 第九轮评审（2026-10-14）

- **关于主人的记忆**：事实（学业、身体、习惯、在做的事）**所有角色共用一份**；每个角色另有自己和主人之间的部分：怎么叫你、关系、约好的事、一起经历的片段、你"只告诉她"的事。主人对某个角色说的事默认大家都知道，说"只告诉你"就只进她自己那份。
- **QQ 群聊**：我们自己的角色（不管几个）发的消息都在右边；多选勾选框规则和别人一样，在左边固定一列。
- **角色详情**：名字下面显示她正在哪活跃（在本地干活 / QQ 某群 / Telegram 私聊），最多两个，多了显示"+N"，下一行是心情。最下面的模型和记忆数那块去掉（记忆数在"记忆"按钮里，模型在设置里）。
- **我的资料**："出门时的我"改叫"社交账号"。
- **表情**：
  - 表情包面板挪到右侧栏的"表情"标签，里面分"表情包"和"emoji"两个。
  - 表情回应是双向的：你可以给她的回复贴，她也会给你的消息贴。
  - 表情包页的"意思"改叫"标签"；输入框写"添加标签"，右边有加号；详情只留格式、尺寸、文件大小；"没错"改叫"采用"（共享常识也一样）。
  - 她挑表情包时，综合看标签、"适合用在"和"别用在"。
- **跳到最新按钮**：数字和按钮做成水滴融在一起的样子（gooey），不再贴得很挤。
- **工作区**：文件树有缩进线；预览上方是打开的文件标签（像编辑器），图片和视频就在它自己的标签里显示或播放。
- **新建角色**："角色色"改叫"角色主题色"；点头像打开"调整头像"弹窗（缩放、旋转、挪位置），去掉说明文字。
- **新增**：设置的工具与审批、通知、数据、快捷键四页；运行 · 性能；通知中心 · 已处理；新建群聊；第一次启动；图片查看器；新建定期任务；调整头像。
- **设置 · 通知**是一张"什么事 × 走哪条路"的表（窗口里、系统通知、QQ 私聊、桌宠气泡），加上免打扰时段、提示音、连着来的合并。
- **设置 · 工具与审批**：手动批准 / 自动放行 / 免审批三选一（免审批用红字提醒）；工作目录、不用问就能改的目录、超时时间；"无论如何都要问的"清单，免审批也照样拦（比如删除文件、git push、改 MaiBot 和 NapCat 的配置）。
- 私聊也要有黑白名单，和群一起之后参考 AstrBot、MaiBot 设计。
