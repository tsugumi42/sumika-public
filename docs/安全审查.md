# 安全审查

首轮审查初稿，基于 [`68334fe`](https://github.com/tsugumi42/sumika-public/commit/68334fef08c17467755a0fc20f33812b101a3935) 的源码和现行参考。下面记录本轮核对的行为与待确认项。开发约定见[权限、安全与隐私](开发指导/权限安全隐私.md)。

| 边界 | 已核对的行为 | 待确认 |
|---|---|---|
| 身份和执行 | 本地工具调用由策略按场合、身份和规则决定是否放行或询问。主人 QQ 私聊的设置提议在本地私聊确认。默认关闭的 QQ 远程审批是另一条流程，用于结算本地发起的审批。[工具策略](../native/internal/policy/policy.go#L542) · [设置工具](../native/internal/app/settingtool.go#L202) · [QQ 审批](subsystems/qq.md#主人-qq-私聊审批go默认关) | 对照后台任务和子代理的现有证据，确认发起者、执行权限和结果回到哪处会话。 |
| 数据流向 | 记忆可以跨场合召回，模型上下文与回复披露使用各自的范围。QQ 回复由发送前守卫检查披露范围。模型请求默认走本机 Magpie，实际转发取决于网关和模型配置。[记忆参考](subsystems/memory.md?plain=1#L46) · [模型网关](../README.md#how-it-fits-together) | 顺着代码核对聊天、附件和工具结果各自会送到哪些服务、留在哪些日志里。 |
| 文件恢复 | 默认开启检查点，文件写入与编辑会保存检查点，恢复前核对内容并请求单次确认。PowerShell 检查点覆盖工作目录内符合条件的普通文件。网络、数据库、工作目录外改动和后台进程超出恢复范围。[工具与审批](subsystems/tools.md?plain=1#L24) · [检查点规格](规格-检查点与回退.md) | 核对主窗口和命令行现在能看到哪些恢复状态。 |

更新时记下核对的提交和证据。已有代码或测试能回答的直接引用。仍有疑问时，沿正常入口用临时数据验证该行为；发现缺陷后，把修复和验收记入对应条目。
