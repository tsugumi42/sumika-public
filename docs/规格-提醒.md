# 规格：提醒（她自己建，到点找主人）

> 状态：2026-11-09 已实现并合 main；QQ 发送路径的假协议端测试 2026-11-10 已补（见第十五节末）。依据 [ADR-330](决策记录.md) 第 1 条。每条验收对应的测试见第十二节。
>
> 参考及采用（都读过源码，路径在 `_external/_audit/`）：
> - Hermes `tools/cronjob_tools.py`（`cronjob_manage`）、`cron/jobs.py` 的 `parse_schedule`、`cron/missed_runs.py`。采用：模型直接管增删改查；相对时间给一个单独写法（`in 30m`，“别手算绝对时间戳”）；错过的合成一条 `missed ×N` 记录；投递目标是任务上的字段。不采用：一个工具加 action 参数（我们的工具族是一件事一个名字，照 `task_*`）；一次性提醒错过就跳过（主人要的是补发，见第六节）；每次在全新会话里跑、最后回答直接投递（我们只要一句话，不是任务）；cron 表达式和自然语言解析（第四节）。
> - OpenClaw `packages/gateway-protocol/src/schema/cron.types.ts`（`at`、`every`、`cron` 三种）、`src/cron/active-hours.ts`、`src/agents/tools/cron-tool-creator-cap.ts`。采用：建的人和能力分开记（我们的“来源”）；到点时不沿用建它那一轮的权限。不采用：活跃时段（主人说几点就是几点；只有她在线里自己建的才受“别烦”约束，第七节）。
> - Claude Code `CronCreate`：一次性和周期共用一个入口，结果里写实际下次时间，用户本地时区。采用后两条。不采用：周期任务 7 天自动到期（那是为了限定会话寿命；提醒是主人要的东西，到期悄悄没了反而坑人）。
> - Codex：克隆里只有“当前时间”这类上下文提醒（`core/src/context/current_time_reminder.rs`），没有定时或提醒功能，没得对照。
> - 本项目：`internal/loop`（Options 注入、不 import 回合内核、`FileStore`、遇忙不叠）；`app/lifewire.go`（听众是主人的判法）；`turn.ThreadInput`（宿主预先绑定身份的受限回合）；`proactiveHost.deliverLocal`（往本地私聊写一句她的话）。
> - 审查：`data/dev/harness-audit/06-日常任务和主动性.md` A1、A2、C1。

## 一、我理解成

主人说“明天九点叫我”，她调一个工具记下来；到点她用自己的话说一句，出现在主人的本地私聊里，窗口不在前台弹系统通知。程序关着错过了，下次开的时候补上，并说明晚了多久。主人在设置里能看到全部提醒，能改、能取消、能删，也能自己建。

不做的：到点让她去干活（跑命令、改文件）。那是 `/loop`，主人亲手建，这条线不碰。ADR-330 第 1 条原话带“定时任务”，她自己建 `/loop` 没有做，理由见第十节第 1 条；要不要做交主人定。

## 二、技术路线

新包 `native/internal/remind`（不 import 回合内核，照 `loop` 用 Options 注入）。接线在 `native/internal/app/remindwire.go`。数据存 `data/go/reminders.json`（一个文件、整份换名写，几十行的量，不占数据库迁移号）。

**到点那一轮不用主人身份。** 这是和 `/loop` 最大的不同，也是这条线最要紧的决定：

- `/loop` 把任务原文存成 `actor_kind=owner` 的输入。它的原文是主人亲手打的，所以没问题。
- 提醒的文字是**模型写的**，可能建在 QQ 私聊或主动联系的线里，那两处都没有执行工具。如果到点存成主人身份的输入，`bindKernelInput` 会给这一轮签本地授权，她就在主窗口拿到了命令行和写文件的工具；开着 yolo 时不用审批。QQ 里的一段内容（比如链接正文里夹的话）就能借提醒绕到本地执行。这撞了 AGENTS 安全边界（QQ 不提供本地执行）、第 7 条（兜底后可触发的人不能更多），也算冒充主人说话。
- 所以到点用 `turn.ThreadInput` 那一套：听众 `PrivateOK` 和 `OwnerAsked` 都为假，发言人是宿主预先绑定的 `system`，内核不签授权，工具清单里没有执行工具。这条路已经过主动联系的身份审查，**不用改 `turn/input.go`**。
- 这一轮跑在每个角色一条的专用会话 `console:<角色>:topic:thread-reminder`（`audience.ReminderConversation`）里，不开线、不看 `proactive.enabled`，主动联系关着也能响。线的工具对它不可见（`inThread` 把它排除），提醒工具也不可见，所以到点那一轮建不了新提醒，不会连环。她这一轮的回答不直接给主人看，宿主拿到文字后写进 `console:<角色>`。
- 这条会话不进会话列表（不登记 `local_topics`），事件带 `selftest` 标记，记忆不收（主人看到的那句在主会话里，只记一次）。

## 三、数据

一条提醒：

| 字段 | 说明 |
|---|---|
| `id` | 全局递增的小数字，工具和界面都用它 |
| `character` | 属于哪个角色。从调用身份取，工具参数改不了 |
| `text` | 提醒内容，最多 500 字 |
| `at` | 第一次响的时间；周期提醒的墙钟时刻、星期、几号都从它取 |
| `repeat` | 空是一次性；否则 `unit`（minute、hour、day、week、month）、`every`（默认 1）、`weekdays`（只给 week，1 是周一，7 是周日） |
| `nextAt` | 下次响的时间 |
| `source` | `owner` 主人在界面建的；`chat` 她在和主人说话时建的；`thread` 她在主动联系的线里自己建的 |
| `targets` | 发到哪：`local`、`qq`。空表示跟配置 `reminders.defaultTargets` |
| `status` | `active`、`paused`、`done`（响完或被标完成）、`cancelled` |
| `pending` | 正在响的这一次（第六节），持久化 |
| `history` | 最近 20 笔：响了（她说的 / 原文 / 晚了多久 / 错过几次 / 各目标结果）、建、改、完成、取消，以及谁做的 |

结束的提醒留 30 天再清（`endedKeep`），期间界面能看、能删。

## 四、工具

五个，一件事一个名字（照 `task_*`）。声明在 `remind.Decls`，`policy.Specs` 登记 `self`、`any`，不弹审批：只碰主人自己的提醒。

| 工具 | 参数 | 说明 |
|---|---|---|
| `reminder_create` | `text`，`at` 或 `in_minutes` 二选一，可选 `repeat`、`targets` | 建。结果写回实际下次时间、还有多久、发到哪 |
| `reminder_list` | 可选 `include_ended` | 看。每行：编号、内容、下次时间、重复、来源、发到哪、状态 |
| `reminder_update` | `id`，可选 `text`、`at`、`in_minutes`、`repeat`、`targets`、`paused` | 改。`repeat` 传 `{"unit":"none"}` 变回一次性 |
| `reminder_finish` | `id`，`outcome`（`done` 完成，`cancelled` 取消）| 不再响，记录留着 |
| `reminder_delete` | `id` | 从表里拿掉 |

时间：`at` 写成 `2026-11-10 09:00`（本机时区，也收 `T` 分隔、带秒、带时区偏移的 RFC3339），不做自然语言解析：她自己算好，算日子可以先调 `calendar`。`in_minutes` 给“半小时后”这种：她知道的时间可能是 15 分钟前报时的，相对时间手算容易偏（Hermes 同样的教训）。过去的时间、超过 10 年、算不出的格式都拒，错误文字里写现在几点。

周期的算法（`remind.Next`）：按墙钟算，不是加固定秒数。每月 31 号在小月落到月底；`week` 的 `every` 从 `at` 所在那一周数起；`weekdays` 为空取 `at` 那天的星期。工作日写 `{"unit":"week","weekdays":[1,2,3,4,5]}`，不看调休，这一点写进工具说明，她可以用 `calendar` 查了提醒主人。

重复建：同一个角色、一样的内容和下次时间，已有没结束的，直接回那一条，不新建（模型重试不会多出一条）。

## 五、到点怎么响

调度器每 10 秒看一次（`Poll`），同一个角色同一时间只响一条，别的下一次检查再看。

1. 认领：把这一次写进 `pending` 并落盘，**落盘成功才往下走**。
2. 看目标：提醒自己的 `targets`，空就用配置；`qq` 没开就去掉（记一笔）。
3. 组织那句话：往专用会话存一行 `system`（origin `proactive:wake`，`toMessage` 已认），内容是提醒文字（框成数据，转义）、是谁建的、现在几点、晚了多久、主会话最近几句（最多 4 条、每条 100 字、6 小时内）。起一轮（`hub.RespondContext`，总时限 45 秒）。场合提示词 `prompts/scene-reminder.md`：只说这一句，不提“系统”“工具”，可以按需调 `calendar`、`weather`。
4. 退回原文：出错、超时、被停、回答是空的、回答超过 1000 字，一律用 `提醒：<原文>`，不丢。刚失败过的 2 分钟内不再试模型，直接原文（模型挂了又错过一堆时不排长队）。**程序在退出时不算失败**：这一次留在 `pending`，下次启动接着响。
5. 晚了的说明由宿主补在句尾：`（本该 11-09 09:00 提醒，晚了 3 小时 12 分；这段时间一共错过 2 次）`。不靠模型记得说，发到 QQ 也有。门槛 2 分钟（`LateAfter`）。提示词告诉她句尾会自动补，不用她说时间差。
6. 投递：
   - `local`：写进 `console:<角色>`（自检话题里建的写回自检话题），`actor_kind=character`、`origin=character`，`segments.reminder` 带编号和这一次的键；`MarkStale`（不打断在跑的回合）、`statusChanged`、`attend`。
   - `qq`：第八节。
7. 收尾：记一笔 `history`，一次性改成 `done`，周期算下一次（从现在往后，不补跑）。

系统通知：`AttentionReminder` 新种类，窗口不在前台才弹（`native/attention.go` 现成逻辑）。种类里带编号，两条提醒紧挨着响各弹各的，不互相顶替；自检话题不弹。

响铃不算主动联系：不改导演的系数，不算今天找了几次。主人回这一句走普通路径；开着的线不会认领（它要求线的话仍是最近一条角色发言）。

## 六、错过、重启、不重发

- **错过**：到点时程序没开或电脑睡着，下一次检查发现过点，照常响一次，算出晚了多久。周期提醒错过多次也只响一次，写明错过几次（数到 1000 为止）。
- **一次性也补**：不学 Hermes 的“过期跳过”。主人让叫他，晚了说一声比悄悄没了强。
- **重启不丢**：提醒表整份落盘，临时文件换名，写到一半断电不坏旧文件。文件读不懂时不覆盖，提醒功能不开，报一条后台提醒；不拖累整个程序。
- **不重发**，靠三样：
  - 认领写盘（`pending`）。同一条同一次只有一个 goroutine 在响；并发 `Tick` 靠锁和 `inflight`。
  - 幂等键：本地事件带 `segments.reminder.key`（`<编号>:<这一次的毫秒>`）。重启后接着响前先查 `console:<角色>` 有没有这个键，有就当已送达，不再调模型、不再写。
  - QQ 先写后发：发之前把 `qq: sending` 落盘；重启时看到 `sending` 记成 `unknown`，不重发（Alma 的教训，主动联系同一条），写明“不知道有没有发出去”。

中途被改：响的过程中主人取消或删除，投递前再查一次（`StillWanted`），不再发；模型已经在跑的那一轮让它跑完，结果丢掉。响的过程中改了时间，收尾时不覆盖新的 `nextAt`。

## 七、防跑飞，不让提醒绕过主动联系的节奏

主动联系有导演管时机（间隔、每天次数、`quiet_until`）。提醒是“主人要我到点说”，不过这些闸。所以要防她拿提醒当自由开口的通道：

| 规则 | 默认 | 超限的文字 |
|---|---|---|
| 同时存在的条数（每个角色，她建新的时数这个角色所有没结束的）`reminders.maxActive` | 20 | “已经有 20 条没结束的提醒了（上限 reminders.maxActive）。先用 reminder_list 看看，结束或删掉不用的再建。” |
| 周期下限 `reminders.minIntervalMinutes`（她建或改周期时）| 60 | “周期提醒最短每 60 分钟一次（reminders.minIntervalMinutes）。这不是用来隔一会儿找他说话的；想找他聊走主动联系。” |
| 线里建的条数 `reminders.threadMaxActive` | 3 | “线里最多留 3 条提醒……” |
| 线里只能建一次性 | 固定 | “线里只能建一次性的提醒。周期提醒要主人开口。” |
| 线里建的至少 `minIntervalMinutes` 以后才响 | 同上 | 写明最早能定到什么时候 |
| 线里只能改、结束、删线里建的 | 固定 | “这条是主人那边建的，线里不能动，等他开口再说。” |
| 线里建的到点遵守“别烦”：`proactive.quiet_until` 没到就顺延到那之后 | 固定 | 记一笔，界面上看得到 |
| 到点那一轮没有提醒工具 | 固定 | 工具不可见，调了也拒 |

工具说明写明：只用于主人要你提醒的事，或者和他约好的事；想主动找他聊天不要用这个。

线里建的提醒，宿主在本地私聊存一行系统行（“她建了一条提醒 #3：……”），主人不用翻设置就知道。主人在界面建的不受这些上限管（底线是周期不短于 1 分钟，和 `/loop` 一样）：防的是模型，不是主人。

`maxActive` 的数法不分来源：主人自己建了 20 条时她就建不了了，会收到明确文字。这个简单，代价可接受。

## 八、QQ 私聊投递（可选，默认关）

- 配置 `reminders.qq`（默认 `false`）开了才能发。提醒的 `targets` 写 `qq`、或 `reminders.defaultTargets` 含 `qq` 才发。关着时她传 `targets:["qq"]` 会被拒并说明，不悄悄改成本地。
- 只发给配置里的主人号：每次发都重读配置（`qq.owner` 改了旧主人立刻收不到，写法同 `lifeQQBindingCurrent`）；主人号为空、等于机器人号、账号没绑这个角色都不发。
- 走 `Outlet.SendHeld(来源 character)`，过档位和发送钳制（`qqSendMode`）、`qqPrivateReplyOK`（`qq.reply` 开着）。不走 `BindAutomation`：那会在历史里渲染成“系统替你自动发的”，这句就是她说的。主人私聊听众就是主人，不过群里那套文字守卫（ADR-311 第 1 条同理）。
- 结果：发完等计划到终态（最多 60 秒）读状态，`sent`、`failed`、`unknown`；试运行档（钳制中）记 `dry-run`，算没发出去。
- **不丢**：QQ 明确没发出去、又没有本地目标时，退回本地写一条，句尾带“QQ 没发出去”。结果不明不退回，也不重发，系统行说明一声。

默认值和要不要开交主人定（交回的 needsOwner）：真实发送由主人决定，测试只用假协议端。

## 九、界面

设置左栏“通知”后面新增“提醒”，排在“定期任务”前（提醒是到点说一句，定期任务是到点干活，两种东西）。

- 顶上一个“新建提醒”按钮；有多个角色时编辑框里选角色。
- 一行一条：内容开头，下面一句 `角色 · 下次 11-10 09:00 · 每天 · 她建的 · 发到本地 QQ`。来源用 `Kit.Badge`，一眼分得出。她建的和主人建的按钮一样。
- 按钮：`详情`（展开全文和最近的记录）、`改`、`暂停`/`继续`、`取消`、`删除`（先确认，默认按钮是取消）。结束的提醒只留 `详情`、`删除`，收在“已结束”下面（数量写在标题里，默认折叠）。
- 编辑框：内容（`TextArea`），时间（`TextField`，预填下一个整点），重复（`Chips`：不重复、每天、工作日、每周、每月；已有的其他周期多一个选项显示原样），发到（`Check`，QQ 没开时灰着并写一句原因）。错的时间在框里写原因，不关框。
- 空态用 `Kit.EmptyState`。

数据走 `api.LocalStatus.Reminders`（和定期任务同一个订阅，只挂在 `console:<角色>` 上），动作走 `api.ReminderControl`。

## 十、不做和后做

1. 她自己建 `/loop`（到点干活）：不做。那一轮要执行工具，就是第二节要防的事；要做得先想清楚身份怎么来，单独拍板。
2. `/remind` 斜杠命令、`sumika-ctl remind`：先不做，设置页够用；挂待办。
3. 消息上的“提醒”角标：先不做，话已经说清楚了；挂待办。
4. cron 表达式、自然语言时间：不做。五种常见周期覆盖了主人说得出来的绝大多数，模型写 cron 容易错。
5. 手机推送：等多端线。
6. 开机自启：不在这条线。程序不开就响不了，靠错过补发兜底；这一点写进设置页不合适，写在这里。

## 十一、禁止的偷懒写法

1. 不把提醒文字存成 `actor_kind=owner` 的输入（第二节）。
2. 不按名字、不按 `PrivateOK` 判主人（本地群聊、子代理的 `PrivateOK` 也为真）。可见和执行两层都判，复用 `ownerListener`。
3. `character` 不从参数取；一个角色看不到、改不了别的角色的提醒，也不告诉她有没有。
4. 不在工具参数里接受身份、来源、投递的会话串。
5. 不让模型决定发给谁：`targets` 只有 `local`、`qq`，都指向主人。
6. 不用墙钟 sleep 写测试：假时钟加 `Tick`。
7. 不吞失败：写库、落盘、QQ 失败都留记录（`history`、日志），工具失败回 `IsError`。
8. 不在 QQ 结果不明时重发。

## 十二、已知的坑

- 专用会话的历史会慢慢变长（每次响一行），靠现有压缩；每次是冷缓存，量小不在意。`scene-reminder` 的成本没量。
- 专用会话的行会进原话搜索索引（和线一样），主人搜得到自己的提醒；不算泄露，没处理。
- 改电脑时区：`nextAt` 是绝对时间，已排好的不变，下一次起按新时区算墙钟。
- 在途的那一轮模型调用不能被“取消提醒”打断（让它跑完，结果丢掉），最多多花一次调用。
- 文件读不懂时提醒功能关着，主人要手动处理那个文件。

## 十三、“形状 × 入口”表（AGENTS 第 7 条）

列是所有读这道门槛的入口：四种场合、主动联系的线、到点那一轮、子代理。行列形状。每格“处理了 / 不可能 / 测了”，测试名见下。

“别人的私聊里伪造主人身份”这一格：可见按听众判，身份由宿主绑定、模型伪造不了，所以工具清单里有；挡在执行端（`TestReminderExecRejectsForgedCallers` 走完整路径硬调，什么都没建）。直接调执行函数、不在宿主正在跑的调用里也一律拒（`TestReminderExecRejectsCallsOutsideARun`）。
