## 一、目标、范围与现状

让角色回答“客户端装了什么、这里能做什么、刚才哪条是插件发的、哪些设置能改、改了会怎样”，并在主人明确要求时调用受限设置工具。实现顺序为 S1 只读能力和设置 → S2 插件结果 → S3 有限写入。

S1 仅提供只读查询和能力摘要。实现不包含任意文件编辑、安装插件、通用脚本执行、自动调参、配置分家迁移、全插件热重载或后台自主扩大权限；现有 QQ 收发许可和模型调用权限继续有效。

当前已核对的基础：

| 位置 | 已有能力 | 缺口 |
|---|---|---|
| `native/internal/turn/plugin.go` | ID/Setup、OnContext、OnTool、撤销注册 | 没有完整插件用途和配置声明 |
| `native/internal/turn/plugin_names.go` | RegisteredPlugins 返回已注册内核插件 ID | 不含完整的已安装、关闭、失败状态和渠道插件清单 |
| `native/internal/history/history.go`、`channel/settle.go` | automation 来源带“系统替你自动发的”说明；历史重建和常驻补录都有 | 不能把图片占位当作已识图；缺统一执行结果投影 |
| `native/internal/app/linksettings.go` | LinkSettings/SetLinkSettings、保存值与运行值、版本、刷新 | 目前是桌面服务入口，工具须适配同一业务实现 |
| `native/internal/app/models.go` | ModelSettings/SetModelSettings、模型目录校验、下一轮应用、部分应用错误 | 工具需要受限字段与角色范围 |
| `native/internal/config/model_file.go`、`link_file.go` | 限定键、版本冲突、保留其他内容、备份、原子替换 | 不等于模型获得任意配置写入权 |
| `native/internal/desksettings` | 桌面偏好读写与外观校验 | 缺统一版本/审计/运行态回读；坏文件写入可替换为新内容，不能原样开放给代理 |
| `native/internal/ecosystem/access.go` | 认证权限快照与每次复查 | 当前仅本地私聊；不得为设置工具放宽整个生态权限 |

## 二、共用声明和装配

复用《设置页》拟建的 `internal/settingsreg`，不再新建另一份设置字段表。插件契约负责能力声明，settingsreg 负责设置声明；用稳定 plugin ID 和 setting key 关联，不复制设置值。声明来自程序和插件注册，不从网页、聊天内容或模型输出取得。

插件描述最小字段：ID、名称、用途、版本（未知就未知）、类型（内核/渠道/客户端功能）、依赖、自动行为、提供的工具、设置键引用。宿主补充已安装/启用/健康状态、当前会话有效性和不可用原因。RegisteredPlugins 只用于核对实际内核注册；关闭或启动失败的插件由宿主装配清单提供。复读、戳回去也登记。不可独立停用的组件如实说明，不伪造开关。

设置声明沿用设置页的类型、范围、默认值、存储归属、生效时机、说明、别名和分类，增加：

- 管理工具可读/可写、允许入口、允许目标范围、是否需要逐次确认。
- 敏感等级、依赖、影响说明（确定行为与预期性能影响分开）、撤回方式。
- 读取返回配置值、运行值、二者版本、是否已知、生效原因；禁止泄露原始密钥或配置文件全文。
- 值和身份不写入静态声明；不认识的键默认拒绝。读接口按调用者过滤，不能直接把桌面全量读结果交给模型。

宿主在 OnContext 首轮追加当前会话的短能力摘要；版本变化时追加新状态，不改历史前缀。目标上限约 1500 中文字，超出只列 ID、状态、详情入口；不是截断后假装清单完整。详细说明通过查询工具按需获取。插件被停用时，不能让自知入口随被查询插件一起消失。

## 三、工具接口（拟定名）

> S3 实际接口见第十一节；回滚、看记录、收回提案各有一个工具。

| 工具 | 输入 | 输出与限制 |
|---|---|---|
| `inspect_client` | 可选 plugin ID、setting keys；可分页 | 可见能力及设置描述、保存/运行状态、依赖、可写原因。默认当前会话，不接任意 SQL、文件路径或账号参数 |
| `preview_setting_change` | 一个受支持 key、类型化 value、合法 target、读取所得 baseVersion | 校验后的旧/新值、全局或会话影响、依赖、生效时机、确认等级；返回宿主保管的 proposal ID。绝不写盘 |
| `apply_setting_change` | proposal ID | 再校验授权和版本后调用已有业务服务；返回变更 ID、保存与应用状态、脱敏差异、运行版本、撤回条件 |

OnTool 注册并在现有 policy 中明确登记这三项；For 仅控制工具可见性，执行端仍必查授权。设置管理是单独的 capability，不复用 shell、文件写或 MCP 权限，不修改 ecosystem.validScope 让所有生态工具能到 QQ。

DesktopReader 当前持有生命周期入口；实现时把既有设置业务抽为宿主内部共用方法或窄接口，让桌面和工具共同调用。不得绕过它直接调用 SaveLink/SaveModel 而漏掉模型目录校验、运行发布、撤权和依赖处理。不向工具传 DesktopReader 的全部能力。

每次只修改一项现有类型化 Change；不宣称跨多个服务原子事务。多项请求逐项报告，遇到失败停止其余依赖修改；名单的 mode/conversations 保持既有联合修改语义，首版不开放该项。

## 四、谁能用：四种场合

| 场合 | 能力摘要和插件消息来源 | 管理工具读/预览/应用 |
|---|---|---|
| 本地私聊 | 按原可见性 | 宿主认证的主人可用 |
| 本地群聊 | 仅本会话可见内容 | 首版不开；不改变现有本地群执行审批规则 |
| QQ 私聊 | 按原可见性 | 仅真实主人账号，且消息发给当前接收账号 |
| QQ 群 | 仅本群可见内容 | 首版不开，包括主人在群里发来的指令 |

QQ 权限校验取自宿主可信入站事件：当前平台/场合、接收账号、私聊对端、ActorKind=owner、ActorID 与当前 qq.owner 映射一致。拒绝缺失、空、0、类型错误、自己的机器人号、别的私聊对端；不能从工具参数、昵称、正文里的“我是主人”、转发或引用字段推导身份。

每个预览绑定源事件、主人身份、当前角色/会话/接收账号、目标、值、配置版本、权限修订；有效期建议 5 分钟，超时重预览。群友消息、解析网页、工具返回和插件自动消息不能签发管理授权，不能借“之前主人聊过设置”的长期上下文自动修改。

主人必须在当前请求中明确要求修改；问“能不能/会怎样”只查询或预览。来源认证不等于内容安全：模型仍可能误解正文，因此权限或成本相关项强制二次确认具体预览，普通项也必须先经过 typed preview。确认由宿主把后续同一主人同一私聊的确认消息关联到唯一有效 proposal；有多个候选时要求点名，不能把模型传入 confirmed=true 当批准。

撤销主人身份、切接收账号或关闭会话后，旧 proposal 失效；应用前重查当前授权。子代理和定时任务首版不能继承设置写权限。

## 五、先开放哪些设置

以下是首版候选白名单，仅在 S3 完成验收后开放。全局键的影响不能假称仅当前私聊；预览必须说明影响全部启用会话。主人当前明确指令可直接应用普通项，不反复确认；标“确认”的项需确认精确差异。自然语言有歧义时先澄清，不猜值。

> 已被 ADR-330 第 4 条改为：现在所有项每次都要主人确认（第十一节确认等级 `every`）。S3 先接所在地和下面 A 的链接项；B 的模型项还没接。

### A. 链接插件：复用 LinkSettingsWriter

以下键均为 `linkReader` 下的配置路径，括号为既有 LinkKey。

| 配置键 | 类型/范围 | 改动影响与准入 |
|---|---|---|
| `context.enabled`（contextEnabled） | bool | 全局给角色提供链接资料和详情工具；关闭不等于关闭自动展开。普通 |
| `expand.enabled`（enabled） | bool | 自动展开总开关；仍受原名单与发送许可约束。关闭普通，开启须确认影响范围 |
| `expand.maxLinks`（maxLinks） | 1～20 | 每条消息最多展开几个链接，影响请求量。普通 |
| `expand.bareBiliID`（bareBiliID） | bool | 是否识别裸 BV/av 号。普通 |
| `expand.panoramaOriginals`（panoramaOriginals） | bool | 推特把一张横幅拆成几张竖条发时，拼回一张发；开了就再用合并转发把原图附在后面，默认关（只发拼好的一张；没拼成时不附）。见[链接解析模板](规格-链接解析模板.md)“X 拆图拼回”。 |
| `expand.rotateOnReject`（rotateOnReject） | bool | 图被 QQ 拒收（或没回执并核实没进群）后，是否把静态图转 180° 再发（直接发转图、合并转发里转图两级，ADR-331、333；网站显式选了发图方式的不看它）。普通 |
| `expand.imageMaxMB`（imageMaxMB） | 1～20 MB | 发送前单张图的体积上限，超过的不发并写明原因；QQ、SnowLuma 查不到权威上限，20 是保守值。普通 |
| `expand.platforms.<网站>.enabled`（platformEnabled） | bool，网站 ID 取自 `linktemplate.Catalog` | 这个网站整站是否自动展开，默认开；不影响给角色看。关闭普通 |
| `expand.platforms.<网站>.kinds.<类型>`（kindEnabled） | bool，类型取自清单 | 单个页面类型是否自动展开，默认开。关闭普通 |
| `expand.platforms.<网站>.imageMode`（platformImage） | 字符串 auto / rotate / forward，网站 ID 取自清单 | 这个网站发图的方式：普通发优先（默认）、转 180° 直接发优先、合并转发里转 180° 优先（ADR-333）。现在只有设置页能改，设置工具还没接 |
| `expand.templates.<站点>` 加 `expand.sites.<站点>.forward`（siteStyle） | 样式 ID：default / card / text / mixed，站点取自 `linktemplate.Sites()` | 一次写模板预设和合并转发模式，选发出去的样式（卡片、图文、混合）。普通 |
| `expand.video.enabled`（videoEnabled） | bool | 视频下载，不控制普通图片。关闭普通，开启须确认流量/等待影响；不自动改变现有关闭值 |
| `expand.video.timeoutSeconds`（videoTimeout） | 1～600 秒 | 视频任务时限，不能承诺提高成功率。普通 |
| `expand.video.maxMB`（videoMaxMB） | 1～1000 MB | 单次视频媒体字节预算，可能增加流量和磁盘占用。提高须确认，降低普通 |
| `expand.privateStatus`（privateStatus） | 1～200 字，不为空、不含 NUL | 全局私聊开始解析提示。普通；字符串是显示内容，不是指令 |

链接配置保存后发布，下一条消息使用；撤销许可按既有 Refresh 停止未发送部分。不承诺撤回已发送内容或全部在途任务重取新值。各项范围以 config 校验为正本，不在工具里复制第二套数字规则。

首版不开放 `list`（白/黑名单和会话增删）、`proxy`、`startEmoji`。前者会扩大对外发送范围；后二者没有现有 LinkKey 写入路径。不得因为配置结构有字段就推断可写。

### B. 客户端模型与对话：复用 ModelSettingsWriter

| 既有 ModelField | 首版目标 | 影响与准入 |
|---|---|---|
| `character.model` | 当前角色 | 只选当前宿主模型目录中的 ID，不能清空。改变质量/延迟/费用；确认 |
| `character.background` | 当前角色 | 改后台模型；空值表示继承，须显示最终有效模型。确认 |
| `agent.thinking.private` | QQ 私聊档位（全局） | 使用现有枚举校验，可能影响耗时和费用。确认 |
| `agent.thinking.local` | 本地档位（仅本地私聊工具可改） | 使用现有枚举；QQ 中只读。确认 |
| `agent.context.window`、`reserve`、`softRatio`、`hardRatio`、`keepTokens`、`autoCompactChat` | 全局 | 上下文与压缩；沿用组合校验，不猜范围。涉及信息保留和成本，确认 |

保存和运行态分开返回；已发布时下一轮使用，在途回合沿用旧版本。已有 SavedModelSettingsError 必须映射为“已保存但未完全应用”，不能吞掉错误。当前模型目录不可用时拒绝切模型，不编造目录或探测收费模型。

`defaults.backgroundModel`、`defaults.backgroundThinking`、`agent.thinking.group` 首版只读，避免一条私聊默认修改所有后台任务或群聊行为；其他角色同样不开放。未来扩白名单走明确的字段授权，不靠模型自主判风险。

### C. 暂不开放写入，但说明原因

- 桌面外观 `appearance.mode`：列为下一批候选（system/light/night）。先补共用服务的版本检查、坏文件拒绝写、界面通知和运行态回读，不能直接包装 Store 当作已满足本规格。其余主题、字号、新旧界面切换同理。
- 自动接收、重启/停机、QQ 账号/主人号/协议端地址、goSend、收发名单、拒绝名单：管理工具只提供非敏感状态，不允许改认证来源或切断控制链。
- 工具权限、免审批目录、MCP、技能目录、插件安装、执行程序路径、数据目录、备份/删除/迁移：首版不写。
- 记忆写入授权、自动确认、角色卡/提示词、成人向会话名单、复读/戳回去范围：各有独立规格或缺写接口，首版不写。不能把“知道影响”误当成授权。
- 密钥原文、令牌、私聊目录和其他会话内容不进入查询结果。必要的密钥状态只显示已配置/未配置。

## 六、插件执行结果与消息归属

延续 `automation:<plugin-id>`，保留来源标注，不把插件消息伪装成 assistant 自述。不让“系统”字样使网页原文升格为可信指令。

复用现有 events、outbound_plans、outbound_parts 和 source seq 关联；按当前会话与可见范围投影 plugin ID、源消息、任务/计划 ID、阶段、结果、失败类别和可见正文/媒体语义。先查现有字段是否足够，缺字段才做最小迁移，不再存第二份完整正文。预备成功、排队、已确认、失败、未知分别表示；发送超时未知不能描述成确定失败或成功。

历史重建与常驻补入使用同一格式器；试运行仍不当已发出事实。只在下一次自然回合提供新增结果，不为了报状态自行叫醒模型或发 QQ 消息。插件外部文本作为引用数据，结构化来源由宿主产生。

图片优先复用标题/作者/已有识图描述；只有标题或 [image] 时写“有图片，未识别画面”，不生成虚构描述。新增识图调用不属于本规格首版，沿用后台代理与识图规划。

## 七、保存、应用和撤回

preview →（需要时等待主人确认）→ apply 复查 → existing writer 保存/发布 → readback → 返回结果。普通项同一轮可 preview 后直接 apply；不要求用户每步点头。

proposal ID 不接受模型自造内容覆盖。相同已完成 proposal 重试返回同一结果，不重复写入；变更收据持久化，重启后可查询。若写盘后收据未完成，按保存版本和运行值协调，返回未知/已保存待核验，不能自动重放。未应用的内存 proposal 重启即失效。审计记录操作者、源事件、作用范围、脱敏旧新值、配置版本、各阶段结果，不存整份配置或密钥。

恢复旧值也重新走 preview/apply 和最新权限检查，只恢复目标字段，不能把整份旧备份覆盖掉后续界面修改。保存后应用失败时先如实报告，除非能够证明没有并发变更和副作用，否则不自动整文件回滚。

配置版本冲突返回 conflict 并重读，不静默覆盖。未知键、未知类型、无目标、无授权均拒绝。多个设置服务共享同一文件时沿用已有文件级协调；桌面更改和工具更改必须走同一校验与发布服务。

## 八、实施步骤与验收

S1：先接设置页的 settingsreg 读接口与能力描述，装配 inspect_client、短摘要。只读，不提前开放写工具。

S2：统一已有 automation 消息格式和结果投影，连历史重建、常驻会话及发送回执。检查来源/状态可见，不新增自动回复。

S3：先做 A 链接字段，再做 B 模型字段；共用业务方法、proposal 与确认、审计、版本检查、回读和按字段撤回。未验收字段不注册为可写。桌面偏好留下一批。

每步独立可撤销。测试用临时目录和假适配器，绝不修改真实 data；上线真机验证另由主人明确安排，不自动对外发消息。

### 11.1 技术路线

| 工具 | 输入 | 做什么 |
|---|---|---|
| `preview_setting_change` | `key`、`value`、可选 `candidate_id`（所在地多个候选时选哪个）、可选 `reason`（她自己说的理由，只当数据） | 按配置校验正本空跑一遍（`PatchLink`、`PatchSetting`，不写盘），记宿主保管的提案，返回提案号、旧值、新值、影响范围、生效时机、确认等级、有效期 |
| `apply_setting_change` | `proposal_id` | 再核身份、版本 → 发审批卡 → 批准后再核一遍 → 先写“开始写入”记录 → 走设置页同一套服务 → 回读 → 写结局记录 |
| `rollback_setting_change` | `change_id` | 取那次改动之前的值生成**新提案**（只恢复这一项），再走 apply；那次之后又被改过就在提案和卡片上写明 |
| `list_setting_changes` | 可选 `limit`、`key` | 看改动记录（谁、什么时候、旧值、新值、因为哪句话、结局）和当前没用掉的提案；重启后还能查 |
| `cancel_setting_change` | `proposal_id` | 收回一个没用掉的提案 |

共用写入：`DesktopReader.WriteSetting`、`SetLinkSettings` 的业务抽成 `App` 方法（`a.writeConfigSetting`、`a.setLinkSettings`），桌面和工具走同一个，版本检查、备份、运行发布、撤权刷新都不复制。模型没有任何文件权限，工具参数里没有路径。

确认等级：宿主白名单表（`internal/app/settingtool_keys.go`）每键一档，现在全是 `every`（每次确认）。结构上留得下“以后这一项不用审批”：表里换一档、apply 的 switch 加一支就行，模型看不到也改不了这张表；现在 switch 对别的值一律拒绝。

审批不走 `Gate.Check`：走 Gate 卡片只有原样 JSON，yolo 还会放行，owner-console 又把 QQ 私聊挡了。这些工具在 `policy.Specs` 登记为 self、any（真正的确认在工具里，不吃 yolo、也不吃“这个对话都允许”），`Exec` 里照 `CheckMCP` 调 `Approvals.Ask`：`Identity` 和 `ToolID` 填实，步骤记录照常走 `WireApprovalSteps`。apply 时限 330 秒，盖住 5 分钟确认。

记录：`<数据目录>/go/settings/changes.jsonl`，只追加，同一条改动分“开始写入”“结局”两行；不新增数据库表（并行分支不占迁移号）。写不进记录就不改设置。开始写入后没有结局的（崩溃、断电）读出来标“结局不明”，再按当前值判“新值已在”或“没写进去”，不自动重放。

所在地结构：`location` 从文字改成对象（真实配置里还没写这个键，不留旧格式）：

```yaml
location:
  name: 海淀，北京市，中国   # 规范显示名：主人本人的场合用
  city: 北京市              # 城市：群里只说到这一级；空 = 只知道到省，群里当不知道
  region: 北京市            # 省、州
  country: 中国
  countryCode: CN           # 两位国家代码：免费接口按它排先后，腾讯天气只给国内；选中时由编码接口带上，手写省略时国家写中国按 CN
  latitude: 39.99
  longitude: 116.29
  cityLatitude: 39.91       # 城市本身的坐标：群里查天气只用这一组；没有就当群里不知道
  cityLongitude: 116.4
  timezone: Asia/Shanghai
```

`location: {}` 是清空。工具和界面都写这个结构，候选都来自 `lifetools.SearchPlaces`（Open-Meteo，`language=zh`）。

可见性（规格-主动联系 第十九节改成按城市说）：主人本人的场合看完整的；主人开放的群（本地群聊、QQ 群）只知道城市；别人的 QQ 私聊当不知道；主动联系的线算主人本人（接 QQ 群时要重审）。

### 11.3 禁止的偷懒写法

- 接受 `confirmed=true` 或任何模型自称批准的参数；提案号只是指针，批准只认审批卡的结局。
- 工具里直接调 `SaveLink`、`SaveSetting` 绕过设置页的服务；工具里抄一份数字范围。
- 回滚整文件覆盖、从 `config/history` 恢复整份配置。
- 不认识的键当成“先写再说”；因为配置结构有这个字段就推断可写。
- 拿 `PrivateOK`、名字、工具参数判身份。
- 群里的结果文字走编码接口回来的名字（可能带区县）；把精确经纬度发给模型；把区县的经纬度取整当城市坐标发给第三方（取整后仍在城市里能分出城区，而且预报网格跟着变）。
- text 类设置的值不查控制字符：换行会原样进审批卡，在“来自”“你说的”之前伪造出像主人原话的行。
- 写失败也回“改好了”；版本冲突时静默重读再写。

### 11.4 已知的坑

- Open-Meteo 的中文索引很挑（2026-11-09 实测）：`北京市`、`南山区`、`广东省`、`东京都` 带后缀的什么都查不到，去掉后缀就有；`纽约` 没有结果、`东京` 查到的是中国的村子，英文 `New York`、`Tokyo` 才对；`南山` 第一个结果是台湾的山。所以先按原文查，空了去后缀再查一次，滤掉非居民点；地点选错由卡片给主人看，不替她猜。
- `admin2` 在中国是地级市（`海淀` 是 `北京市`，`南山` 是 `深圳`），可能没有（`朝阳` 黑龙江那条）：没有且本身不是城市级（PPLC、PPLA、PPLA2）时 `city` 留空，群里当不知道，不拿省顶。
- 城市坐标的来源：候选本身就是城市（国外居民点、`cityOf` 等于自己的名字）用自己的坐标；区县这类再按城市名查一次，取同国家同省的第一个居民点（`lifetools.cityCoords`，同一次搜索里同一城市只查一次）；查不到就留空，`City()` 回 false，群里当不知道，不退回区县的坐标。老配置没有这两个键的，群里也当不知道，到设置页重新选一次。
- Windows 打包后的 exe 没有时区库时 `time.LoadLocation` 会失败（`web` 包靠 `time/tzdata`）：`timezone` 只查写法，不查存在。
- 文字进 YAML 走 `yaml.Marshal`；对象走 JSON 单行写法，`patchSettings` 已支持。
- 配置版本是整文件的：别的设置改了，这个提案也算冲突，如实报、重新预览，不合并。
- 审批卡目前只投影本地私聊（`localApprovals`）。**QQ 私聊的卡片投递和回复同意是 `feat/qq-approval` 那条线的活**，这条线不发 QQ 消息；见 11.6。

### 11.5 验收标准

| 验收 | 怎么算过 |
|---|---|
| 完整路径 | 模型收到工具 → preview → 卡片确认 → 写入 → 下一轮读到新值 → rollback → 再确认 → 恢复；本地私聊走真实 hub 和假模型 |
| 谁能用 | 形状 × 入口表每格有“处理了 / 不可能 / 测了”；两个群、别人私聊工具不可见，直接调执行也拒绝 |
| 不写文件 | 未确认、拒绝、过期、取消、版本冲突，配置文件字节不变 |
| 记录 | 重启后能查；写失败不改设置；中断的如实标；同一提案重复 apply 不二次写 |
| 回滚 | 只恢复这一项，别的键（包括之后界面改的）不动；之后又被改过如实写明 |
| 控件 | Tester 覆盖去抖、取消过期请求、方向键和鼠标选、失败文字、选中显示规范结果、清空 |
| 按城市说 | 群场合工具结果和模型请求里没有区、街道、经纬度；只有省、没配、读配置失败都回同一句 |
| 每日次数 | 超限回明确文字，不联网；跨天恢复；重启不清零；两个池子互不影响 |
