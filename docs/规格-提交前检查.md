## 一、为什么挂在钩子上

几种做法比过（npm 上的版本和日期是 2026-10-26 查的）：

| | lefthook 2.2.2（2026-10-13，MIT） | husky 9.1.7（2024-11，MIT）+ lint-staged | simple-git-hooks 2.14.0（2026-08，MIT） | 一个脚本，手动跑 |
|---|---|---|---|---|
| 按改了哪些文件挑检查 | 自带（`glob`） | 要加 lint-staged | 没有，自己写 | 自己写 |
| 提交 / 推送时自动跑 | 是 | 是 | 是 | **否，还是靠记得**（F01 的根因） |
| 配置进仓库、几个 worktree 和会话共用 | 是（钩子装在共用的 `.git/hooks`） | 是 | 是 | — |
| 维护 | 活跃 | 快两年没发版 | 活跃 | — |

选 lefthook。GitHub Actions 和分支保护先不做：私有仓库的分支保护受套餐限制（审计 F01 查过），本地钩子已经能挡住"红着提交、红着推送"；要不要再加云端那一层等主人定。

## 二、跑什么（2026-10-26 在本机量的耗时）

**提交前（pre-commit），按暂存区里改了的文件挑，并行跑**（2026-11-19 起 lefthook 只有一项，调 `sumika-dev hook pre-commit`：挑选表写在 `native/internal/devtools/hook/table.go`，glob 逐字照搬原 `lefthook.yml` 各项；一个进程里并行，每项自己的输出、跑完按表里顺序打印，末行汇总“几项过、几项红、几项没挑上”，任何一项红退出码就是 1；已迁进 Go 的检查直接调函数，没迁的 bun 项起子进程、表里注明“迁完删”）：

**推送前（pre-push），先按远端 ref 分档（2026-11-19，ADR-398），再按这次要推的提交范围挑：**

钩子对输入的每一行（本地 ref、本地提交、远端 ref、远端提交）各判一次，判断只有 `scripts/pre-push.ts` 的 `pushMode` 一处，不认环境变量或参数：

| 这一行 | 查什么 |
|---|---|
| 本地提交全零（删远端分支，含删 main） | 什么都不查 |
| 远端 ref 恰好是 `refs/heads/main`（含 `git push origin feat:main`） | 下表整套：隐私扫描、Bun 步骤、Go |
| 其余：功能分支、试验分支 `try/x`、新建分支、`refs/heads/mainline`、`refs/heads/main2`、tag | 只扫隐私（范围见下“扫哪些提交”），Go 和脚本测试交给公开仓库 CI |
| 输入不是 git 给的格式（缺远端 ref） | 按整套，认不出就多查 |

同一次推送里混着 main 和别的分支，各行各判，一行红整体退出码 1。测试 `scripts/pre-push.test.ts`（编造的临时仓库起真的钩子脚本，每种形状一条，含 `feat:main` 仍整套、`main2` 不当成 main、功能分支里有认识的号码照拦）。

**扫哪些提交**（2026-11-19，复核改过）：扫“这次会新发到远端的全部提交”，即 `<本地提交> --not <远端已有的提交>`（`sumika-dev check private --range` 把后面的参数整个交给 `rev-list`，每个提交扫新增行、提交说明、作者和提交者，文件名随 diff 头一起扫）。远端已有的提交这样取：该分支远端已有、且那个提交在本地，就用它；否则（新分支、远端提交不在本地）问远端本身——`git ls-remote --heads --tags <推送地址>`（钩子第二个参数，没有就用第一个参数的远端名，lefthook 的 `{1} {2}`），再用本地对象过滤（本地没有的当不存在，标签剥成提交；超过 150 个当取不到，命令行装不下）。**不看本地的 `refs/remotes/<远端>/main`**：换了远端或久没 fetch，它指向的提交远端不一定有，旧历史里加过又删掉的号码、提交说明、作者邮箱会漏。ls-remote 失败（网络、权限、地址不对、超时 60 秒）、没给地址和远端名、排除列表太长：一律失败关闭，扫 `<本地提交>` 的全部可达历史（慢，但只在少见情况下触发），不退成少扫；git 数不出提交数或 rev-list 报错按红处理。远端空仓库（ls-remote 成功但什么都没有）= 全部历史都是新的。本地提交远端已经有时 0 个提交，什么都不扫、通过。main 那一档没有可比的远端提交（新远端、远端提交不在本地）时，挑检查用的文件清单按整棵树（宁可多查）。`--range` 和 `--staged` 的 `git show` / `git diff` 带 `--text`：含 NUL 或标了 `-diff` 属性的文本文件照样按文本扫（2026-11-19；`--tree` 的“前 8192 字节有 NUL 当二进制”没改：导出树里有字体、图片等二进制，全当文本扫会误报也慢，UTF-16 文本文件不在导出范围里）。带标注 tag 的标签对象文本（tagger、标签说明）、分支名和 tag 名（本地 ref、远端 ref）也一起扫。

**第二轮复核补的**（2026-11-19）：
- 推送地址：先按钩子第一个参数问 `git remote get-url --push <远端名>`；不是已配置的远端（按地址推）才用第二个参数；参数多于两个（lefthook 的 `{2}` 遇到带空格的地址会被劈开）按取不到处理，失败关闭。
- 输入行格式不对（缺段、提交号不是十六进制）红，不再当成没事跳过；本地提交剥不出提交（指向 tree、blob，或本地没有这个对象）红；检查过程里抛异常（git 起不来、临时目录写不了）打印原因按红。
- `sumika-dev check private --range` 不再逐个提交起 git：`rev-list --parents` 列出提交，说明和作者一次取完，diff 每 200 个提交一批用 `git log --no-walk --stdin -p` 取，扫完一批丢一批（全历史 diff 三百多 MB，不整段留在内存）。按父提交数分三类：0～1 个普通 diff；2 个 `--remerge-diff`；3 个以上（章鱼合并）用 `-m`（`--remerge-diff` 对它只在 stderr 打 `Skipping remerge-diff for octopus merges.`、stdout 为空、退出码 0，等于什么都没扫），输出里出现 `Skipping` 一律按失败。每个提交的 diff 前一行 `@@COMMIT@@ <哈希>` 标记，diff 正文的行都以空格、`+`、`-`、`\` 或 diff 头里的词开头，内容伪造不出来。实测本仓库 main 全部历史 6084 个提交 80 秒（原来每个提交 4 个 git 进程，约 1.6 秒一个，要两三个小时）。
- 文件名：`diff --git` 行就扫（新建空文件没有 `+++` 行），带引号的路径（git 对特殊字符加双引号、C 风格转义）解开再扫，同一个块里同一个名字只扫一次。
- **第三轮复核补的**（2026-11-19）：提交对象用 `git cat-file --batch` 按字节数整个取（不再用 `%B`：说明里的 NUL 之后和 `x-note`、`mergetag`、`gpgsig` 这类头字段原来不扫），头字段和说明整段当文本扫，`tree`、`parent` 的哈希值不扫，`author`、`committer` 去掉时间戳；缺对象、类型不对、数量对不上、`git log` 给出的提交和请求的对不上都报错。所有出 diff 的调用带 `--src-prefix=a/ --dst-prefix=b/ --no-textconv --no-ext-diff`，`git log` 还带 `--root --no-show-signature`，用户配置 `diff.noprefix`、`diff.mnemonicPrefix`、textconv、外部 diff、`log.showRoot=false`、`log.showSignature` 改不了扫到的内容；`Collect` 遇到认不出 `a/ b/` 前缀的 `diff --git` 行返回错误（红），不静默跳过。扫描和 `pre-push.ts` 的 git 子进程都设 `GIT_NO_REPLACE_OBJECTS=1`，`refs/replace/` 换不掉提交。标签嵌套读到 10 层还有下一层按失败。输出里不打印推送地址和 ref 名。测试里起 git 一律用固定的干净配置（空的 `GIT_CONFIG_GLOBAL`、`GIT_CONFIG_NOSYSTEM=1`），敌对配置在专门的用例里写进测试仓库。
- **第四轮复核补的：扫描规则本身**（2026-11-19；`native/internal/devtools/private/`）：
  - 每行扫原文和归一后的副本（`variants`）：含 NUL 的行（UTF-16 文件按行切开）去 NUL、按 UTF-16 小端大端各两种对齐解码；每个再做全角转半角、去零宽字符、各类空白（不间断空格、全角空格）换成普通空格。`--tree` 只有“前 8192 字节有 NUL、又不像 UTF-16”的才当二进制跳过。
  - 8 位以上的认识的号码嵌在更长的数字里（前后加位、补零、12 位以上）也拦；夹分隔符的不做。
  - 名字两边都按 ASCII 小写比，空白归一、零宽字符去掉、全角字母转半角，名字里的空格数量不同也对得上；英文名仍要整词。
  - 密钥：`api_key`、`password` 这类键名后允许引号（JSON 写法）；新增 `AKIA…`、JWT、`Authorization: Basic|Bearer` 后面跟 12 位以上令牌字符（`<令牌>`、`${变量}`、`%s` 这些占位写法不算）。
  - `data/` 下新增或修改的路径（`--staged`、`--range`）红，删除不拦；名单、误报登记文件被 git 跟踪就拒绝读、红。
  - 推送前（`--range`）私人字符串名单、群名表缺失或为空红，`--allow-missing` 绕不过；提交时（`--staged`）照旧只提示。没配置 MaiBot 库（生产环境永远如此）不算缺失，不再写“缺 MaiBot 库”。
  - `SUMIKA_SCAN_DATA`、`SUMIKA_SCAN_MAIBOT` 只在测试构建（`go test`、`go build -tags scantest`）里认，生产构建见到就拒绝扫描（红）；`scripts/lib/sumika-dev.ts` 的 `devEnv` 按大写比较所有键去掉它们，已没有 `testDataDir` 选项，脚本测试要编造的名单用 `scripts/lib/sumika-dev-fake.ts` 的 `makeFakeScanRoot`（假仓库根）。lefthook 里的 `env -u` 只列大写名，小写名的变量到了程序里同样被拒绝，不会悄悄生效。
  - author、committer 行末的时间戳删掉之前先对认识的号码比一次；提交头有 `encoding gbk` 这类非 UTF-8 编码的，说明另用 `git log --encoding=UTF-8` 转一份再扫；`git log` 带 `--encoding=UTF-8`。
  - 没改的：未知长数字、未知邮箱“只提醒”（退出码 0）是规则取舍，等主人定；`--tree` 不看提交说明和作者。
- `--line 文字`、`--tag 标签对象` 是给 `--range` 的补充：把 ref 名当一行文字扫；把带标注 tag 的标签对象文本（一层层往下读）扫一遍。输出里不打印 ref 名（可能带号码）。
