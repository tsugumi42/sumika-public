## 一、先说人话

设置窗口的"模型"页现在是原型：下拉里是写死的五个假名字，选了不保存，后台也不认。要做成：

1. 打开页面就从 Magpie 读一遍模型列表（有刷新按钮），按服务商分组，每个模型写清楚能不能看图、上下文多长、有哪几档思考。
2. 每个角色一行：说话用的模型、后台用的模型（空 = 跟全局）；话题模型那一列灰着，写"话题还没做"。
3. 全局：后台模型、后台思考档位；三个场合的思考档位（本地、QQ 私聊、QQ 群聊）；上下文几个数。
4. 点一行弹出选择框（照 Telegram 选语言那个框：上面搜索、下面分组的单选列表），选了就保存，**不用重启接收**，下一轮她就用新的。
5. 每一项旁边看得到"配置里写的"和"现在实际在用的"，两个不一样时说为什么（比如"这一轮还没结束，下一轮换上"）。

## 二、现状（调研结论，2026-11-03）

以下记录实现前的读码结论；当前后台已按第三节切到运行快照，实际接口见[运行时参考页](subsystems/runtime.md#go-模型页后台adr-2492026-11-03)。

- 正式窗口的设置走 `realSettingsView`，显示 `ReadSettings` 返回的只读配置；`pageModels`（`native/settings.go:197`）只是演示原型。
- 配置启动时读一次存在 `App.cfg`，没有发布新配置的入口。`Hub.Cfg` 是另一份，多个会话并行读，不能直接赋值。
- 后台模型、后台思考：`App.backgroundModel`（`internal/app/guarddeps.go:103`）和 `memoryGenerator.Call` 每次现读 `App.cfg`，换掉来源下一次就生效。
- 角色说话模型：启动时 `modelMap(cfg)` 复制进 `turn.Config.Models`；每轮 `cardAndModel` 用它；模型 ID 变了 `acquire` 会重建这个角色的实例（`internal/turn/hub.go:1024`）。
- 思考：启动时复制 group → `Thinking`、local → `LocalThinking`；**private 没接，QQ 私聊用的是 group 那一档**。
- 上下文：启动时复制进 `turn.Config.Context`，每轮 `Built.refresh` 用；`topicCompactAt` 没有消费者。
- `characters.<id>.topic`、`vision.model`：Go 里没有消费者（Go 现在没有识图）。
- 总结开没开是启动时定的（`memwrite.decide`，没后台模型就关）；后台模型同时决定发送前守卫的能力。
- `NewHub` 会 `SweepInterrupted`，重建整个内核会把正在跑的回合当成崩溃残留——不能靠重建内核换设置。
- `llm.Model` 没解 `display_name`、`magpie_label`；`Models()` 没缓存，只在开始接收时调一次。
- 写文件已有 `internal/fileatomic.Replace`（Windows 上短时重试）。

## 三、做法

### 3.1 页面能写的键（ADR-249 第 3 条）

| 键 | 控件 | 能不能空 | 校验 |
|---|---|---|---|
| `characters.<id>.model` | 选择框 | 不能 | 必须在模型列表里 |
| `characters.<id>.background` | 选择框 + "跟全局" | 能（空 = 删掉这个键） | 在列表里 |
| `defaults.backgroundModel` | 选择框 + "不设" | 能 | 在列表里 |
| `defaults.backgroundThinking` | 档位单选 | — | 现有枚举 |
| `agent.thinking.local` / `.private` / `.group` | 档位单选 | — | 现有枚举 |
| `agent.context.window` | 数 | 0 = 跟模型 | 0 或 ≥1000 |
| `agent.context.reserve` / `.keepTokens` | 数 | — | 现有校验 |
| `agent.context.softRatio` / `.hardRatio` | 数 | — | 0.1～1，另加 soft ≤ hard |
| `agent.context.autoCompactChat` | 开关 | — | — |

只读、灰着：`characters.<id>.topic`（"话题还没做"）、`agent.context.topicCompactAt`、`vision.model`（"Go 还没做识图"）、`magpie.baseUrl`（显示地址和连接状态）。

### 3.2 后台接口

`api.ModelSettingsWriter` 是可选能力（照 `LocalGroupWriter` 的样子，不扩大 `Reader`），由 `*app.DesktopReader` 提供：

- `ModelSettings(ctx) (ModelSettingsView, error)`：配置值、运行值、模型列表（带读取时间、出错原因）、文件版本（内容哈希）。
- `RefreshModels(ctx) (ModelSettingsView, error)`：重新拉列表；失败保留上次列表，视图带错误与上次读取时间。
- `SetModelSettings(ctx, change, baseVersion) (ModelSettingsView, error)`：`change` 是上表里的键的类型化修改，不收任意路径。

`ModelSettingsChange` 是 `config.ModelChange` 的别名：Field 取白名单枚举，角色 ID 独立传，String / Int / Float / Bool 四种值指针恰好一个。错误分别为未保存的校验 / I/O 错误、`ErrModelSettingsVersion`（同次返回重读视图）、`*SavedModelSettingsError`（已保存，视图带 ApplyErrors）。ModelsEditable 和 ModelsDisabledReason 供界面禁用选择；Configured / Running / Active 分别为磁盘、已发布版本和在途实际参数。

### 3.3 写回（照设置角色页 3.4）

1. 进程内一把写锁；`baseVersion` 和磁盘上的哈希对不上（外面改过文件）就拒绝，页面提示"配置文件在外面改过，已重新读取"。
2. goccy `ast` 找目标键的位置，原文上只换那一小段；缺的键在同级末尾加一行，缩进跟同级；`characters: {}` 这种写法换成块写法。换行风格（CRLF/LF）、注释、对齐空格原样。
3. 把 `config.LoadIn` 的"字节解析 + 默认值 + 校验"抽成共用函数，用它解析候选文本；和改之前逐键比，除了这次要改的键别的都一样；模型 ID 在列表里。不过就不写，返回原因。
4. 旧文件原样存进 `config/history/<YYYYMMDD-HHMMSS>-sumika.yml`（同一秒重名加序号）；候选文本写同目录临时文件 → Sync → Close → `fileatomic.Replace`。
5. 替换成功后才发布新快照（3.4）。发布失败（比如总结前提没过）返回"已保存，部分没生效"和原因。

### 3.4 不重启生效

- 新增不可变的 `ModelRuntime`（只含 3.1 的字段 + 那一版模型列表），`atomic.Pointer` 发布。
- 每轮回合开头取一次，组成这一轮的 `turn.Config`，沿 `cardAndModel`、`acquire`、`runTurn`、硬门槛恢复、提前压缩一路传下去，**一轮里不混用两版**。正在跑的回合、提前压缩用各自的旧快照跑完。
- 后台调用（总结、守卫确认）开头取一次，模型和思考出自同一份。
- QQ 私聊用 `private` 档位：按回合的场合选档，不是只换个值。
- 后台模型没有 → 有：照 `memwrite` 原来的前提（首次备份、catchUp、元数据）走一遍才开总结；不顺带开 `memory.write`。有 → 没有：总结跳过、守卫降级、发送门照 `guardFull` 收紧。
- 换说话模型：下一轮 `acquire` 重建她的实例，聊天记录从库里来，提示词缓存重新热。

### 3.5 模型列表

- `llm.Model` 补 `display_name`、`magpie_label`、`reasoning_levels`（平面数组）、`modalities.output`。
- 打开模型页拉一次，刷新按钮再拉；不轮询，不在每次推理前拉。拉到的列表和快照同一版本发布。
- 显示：按 `owned_by` 分组；名字用 `display_name`，没有就用 ID；副标题"能看图 · 512K 上下文 · 思考：低/中/高"。没报告的写"未报告"，不按名字猜。上下文没报告时写"未报告（按 128K 算）"。
- 当前选的模型不在新列表里：那一行标红"列表里没有了"，不自动换别的。
- archive（没在接收）：不联网，没有列表；模型那几行灰着写"开始接收以后才能选模型"，思考和上下文照样能改。

### 3.6 界面（MewTypeUI 的 settings 包）

照 MewTypeUI 画廊里的"模型设置示例"页接：分段小标题、设置行（标题 + 右侧当前值 + 箭头）、开关行、档位单选、数值行、选择框。保存是即时的（选完就存），失败在那一行下面红字写原因并回到旧值。

实现入口是 `native/modelsettings.go` 的 `pageModelSettings`；正式窗口和演示窗口共用，演示仅注入 `demoModelSettings`。参考本机 MewTypeUI `gallery/settings.go:169` 的模型设置示例、`settings/choose.go` 的宿主 ID 和过滤状态、`overlay/box.go` 的弹框；借了分段设置行、宿主持值、搜索后按 ID 保存、数字弹框直接消费提交文字四条，不复制组件绘制。

打开页面调用一次 `ModelSettings`，离开后再进入重新读取；刷新只走 `RefreshModels`。读和写都在 worker，结果由既有 `app.post` 交给 `Window.Update`；换数据源按 `srcGen`、请求按序号丢弃旧结果。一个请求在途时暂停编辑，保存使用上次返回的 `Version`，这一行显示正在保存。普通错误保留旧值并显示原因；版本冲突和已保存但部分未生效采用同次返回视图。模型选择框按 `Groups` 分组，直接使用后台提供的名称和能力副标题；后台模型另有“跟全局”或“不设置”。

整数用 MewTypeUI `NumberInput`；比例用原生小数输入，因为 `NumberInput` 会去掉小数点。保存前按 config 的范围检查，不增加人工上限：window 为 0 或至少 1000，reserve 至少 0，keepTokens 至少 1000；比例 0.1～1，soft 不大于 hard。话题、话题压缩门槛和识图始终禁用。archive 只禁用模型选择，思考、上下文和自动压缩仍能保存。

## 四、禁止的偷懒写法

- 整份 YAML 读出来再整份写回去（会改掉主人的注释和对齐）。
- 直接给 `App.cfg`、`Hub.Cfg` 的字段赋值，或者为换设置重建整个 `Hub`。
- 一轮里多处各自 `Load` 快照。
- 模型名允许自由输入；或者选的模型不在列表里时悄悄换成别的。
- 后台模型配上了就直接把 `SummarizeEnabled` 置 true。
- 话题、识图这些没有消费者的项做成能改、还说"已生效"。
- 保存失败吞掉错误、界面照样显示新值。

## 五、已知的坑

一轮混用两版设置；旧的异步保存盖掉新选择；刷新后当前模型不在列表里；后台模型清空影响发送守卫；首次配后台模型总结没开；0 和缺省语义不同（`window` 0 = 跟模型，`reserve` 0 在内核里当默认 16384）；卡里旧 `model` 的回退；`SUMIKA_CONFIG` 指到别处；同一秒备份重名；YAML 的 alias、flow 写法（`{}`）、多文档、CRLF、行尾注释对齐；保存成功但生效失败。

| 形状 | 桌面 SetModelSettings | 共用 PatchModel / SaveModel | 回合 / 后台消费者 |
|---|---|---|---|

## 六、验收

1. 写回：拿 `sumika.example.yml`（CRLF、LF 各一份）改每个可写键各一次，`diff` 只有目标行变（新增键只多那几行）；输出重新解析，别的键全等；`config/history/` 里有逐字节相同的旧文件。外面改过文件 → 拒绝。
2. 校验：模型不在列表、说话模型清空、soft > hard、枚举外的档位，各一个测试，都拒绝且文件不变。
3. 生效：假 Magpie + 临时数据目录，接收中改角色模型 / 思考 / 上下文，下一轮请求里的 `model`、思考参数、裁剪门槛是新的；改的同时有一轮在跑，那一轮请求全是旧值；并发改 + 并发回合跑 `-race` 不报。
4. 私聊思考：QQ 私聊回合用 `private`，群聊用 `group`，本地用 `local`。
5. 后台模型没有 → 有：总结按前提打开（有备份记录）；有 → 没有：守卫降级、发送门拦。
6. 列表：带 `display_name` 的假列表显示名字、分组、能力；没报告的写未报告；当前模型不在列表里标红。
7. archive：不发请求，模型行灰着，思考能改能存。
8. 界面：MewTypeUI 组件，`ui.NewTester` 点开选择框、搜索、选中、看到保存；失败回到旧值、红字。

6415 帧的 P95 7.1 ms、P99 10.7 ms、最大 31.4 ms，超过 100 ms 为 0；响应分位数与 60 Hz 应用帧 P95 在[性能标准](notes/标准-性能与效率-2026-11-03.md)预算内。P99 仅为探索值，未满 10000 个观测。首次量测保留了一个 101.2 ms 帧（软件 present 100.2 ms）；排查发现 Caption 的内容过渡使静止 Tester 时钟反复构建并保留旧加载文字，改成无过渡的 MewTypeUI 正文字阶，增加 `status-settled` 回归和恢复旧过渡会红的检查。
