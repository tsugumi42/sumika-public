## 二、候选

调研时间 2026-10-16；"未核实"的都要真机试（第四节）。

| | Electron | Tauri v2 | Wails v3 | 其他 |
|---|---|---|---|---|
| 内核 | **自带 Chromium，版本由我们定**，三个平台一样 | 系统 WebView2（跟 Edge 走），macOS 用 Safari 内核（没有 `corner-shape`） | 同 Tauri | Electrobun：默认系统 webview，穿透要额外打包 Chromium；Neutralinojs：功能清单对不上 |
| 通知带按钮 | 有（actions、reply、自定义 toast XML） | **桌面端没有**，要自己写原生代码 | 有 | — |
| 透明穿透（桌宠） | 整窗穿透 + 把鼠标移动转发过来，能做"鼠标在角色上才接收点击" | 有已知 bug 没修（#11461） | 有接口，还在修 | — |
| 管 Bun 后台 | 主进程是 Node，开子进程最直接 | 有 sidecar 机制，关闭和重启要自己补 | 要自己写 Go 代码管 | — |
| 成熟度 | 稳定 | 稳定 | **还是 beta**（beta.30，2026-10-15） | Electrobun 很新 |
| 体积 | 大，约 85 MB 量级（第三方说法） | 壳几 MB | 壳几 MB | — |

Bun 后台打成单文件（`bun build --compile`）本身就有几十 MB，所以三者装好以后的总体积差距没有壳本体那么悬殊（具体数字未核实）。

只做 PWA（Edge 里"安装此站点为应用"）当不了壳：没有托盘、开不了机自启、拉不起后台、做不了桌宠。

## 三、推荐：Electron

理由按重要程度：

1. **内核由我们定**：主窗口大量用了新的 Chrome 特性。用系统 WebView2 时，主人电脑上 Edge 的版本决定能不能显示对；换到 macOS 就直接没有。Electron 自带固定版本的 Chromium，哪台电脑都一样。
2. **通知按钮和桌宠穿透都有现成的**：这两样是本地功能里最难的，Tauri 一个要自己写原生代码、一个有没修的 bug。
3. **管后台最省事**：Node 的子进程管理成熟，退出、重启、日志转发都好写。
4. **代价是体积**：多出几十 MB。Sumika 是装在自己电脑上常驻的程序，不是到处分发的小工具，可以接受。

Wails v3 技术上很合适（小、有通知按钮和穿透），但还是 beta；等它出稳定版再评估，换壳不影响主窗口和后台。

## 四、动手前先做三个小验证（各半天以内）

1. **样子**：Electron 窗口里打开 7720，跑一遍 `check:ui`（换成连 Electron 的 Chromium），截图和 Chrome 里对比；同时在 Edge（WebView2 的内核）里也跑一遍，记下差别，作为以后换壳的参考。
2. **桌宠窗口**：一个透明、置顶、可穿透的小窗口，里面放一个 Spine 的 WebGL 示例动画；鼠标移到角色身上能点、移开能点到后面的桌面；在主人 125% 缩放的屏幕上不糊。
3. **通知按钮**：发一条带"批准 / 拒绝"的系统通知，开发模式和安装以后各试一次（Windows 要给程序登记一个身份才显示得对），点按钮能把结果送回后台。

三项都过就定 Electron；第 2 项不过就先不做桌宠窗口，其余照做。

## 五、结构

```
Sumika.exe（Electron 主进程）
  ├─ 看管后台：启动 bun 后台（打包后是单文件 sumika-daemon.exe），崩了 3 秒后重启，
  │           一分钟内崩 3 次就停下、弹通知让主人看日志；退出时先让后台收尾再关
  ├─ 主窗口：加载 http://127.0.0.1:7720（和浏览器里看到的是同一个主窗口）
  ├─ 托盘：打开、暂停她们（不回消息）、退出；有待审批时图标加小红点
  ├─ 系统通知：后台通过本机接口告诉壳"弹一条"，按钮结果回传给后台
  └─ 以后：桌宠窗口、全局快捷键、自动更新
```

- **后台仍然独立**：不开壳、直接 `bun start` 照样能用，浏览器里打开 7720 也照样能用（开发时、手机访问时）。壳只是多一层"看管 + 本地能力"。
- **壳和后台怎么说话**：壳启动后台时传一个一次性的令牌，两边只在本机端口上用这个令牌通信，别的程序冒充不了。
- **数据目录**：壳按[数据目录规格](规格-数据目录与备份.md)第四节找数据目录（便携 / 安装），再把路径告诉后台。
- **主窗口不依赖壳**：页面里用到壳的能力（选文件夹、弹通知）时先问"有没有壳"，没有就退回现在的做法。

## 六、不许偷懒

- 不许把后台的逻辑挪进壳里：壳只管进程、窗口、托盘、通知、本地对话框。
- 不许壳和后台之间不验证就通信。
- 不许关窗口就退出整个程序（关窗口 = 收到托盘；退出要从托盘菜单点）。
- 不许后台崩了没人知道。

## 七、要主人定的

已定（ADR-061）：关窗口收到托盘；托盘里能暂停。

还没定：
1. ~~选 Electron 吗~~：主人 2026-10-17 定了用 Electron（ADR-065）。
2. **"睡眠模式"和"频率 0""不学习"怎么分**（主人 2026-10-16：原来的"暂停"改叫睡眠模式，照手机的"睡眠 / 就寝模式"理解；原来暂停时不学也不写记忆，看不出存在的理由，重新定义）：

| | 回消息 | 主人 @ | 学说话方式、写记忆 | 为什么要有它 |
|---|---|---|---|---|
| **频率 0**（某个群，一直有效） | 不主动说 | 回 | 照常 | 这个群让她潜水：在看、在学，就是不插话 |
| **不学习**（某个群） | 照常 | 回 | 这个群的不学 | 这个群的说话方式不想让她学（比如太糙的群） |
| **睡眠模式**（全部，有时段） | 都不回 | 默认能叫醒她（可以关） | 睡着时照收；醒来后像人翻聊天记录一样补看：照常学、照常整理记忆 | 让她有作息（晚上睡觉，更像活人）；主人开会、直播时让她整个安静；可以每天定时（比如 1:00～8:00），也可以倒计时（"睡 2 小时"） |

- 睡着时主窗口和托盘显示"她睡着了"和几点醒；醒来后她不去补回复过时的消息。
- 睡眠和频率 0 不冲突：睡眠是全部、临时；频率 0 是某个群、一直有效。睡醒后各群照各自的频率。
- 没有"连学习都停掉"的开关：真要她什么都不做，直接从托盘退出程序。

## 八、验收

- 第四节三项小验证的结果写进这份规格。
- 后台被强制结束后 3 秒内自动拉起；一分钟内崩 3 次停下并弹通知。
- 托盘退出后没有残留的 bun 进程。
- 开机自启后，主人登录 30 秒内她就在线（QQ 号 online）。
- 不开壳时 `bun start` + 浏览器的用法一切照旧。
