# 规格：她问主人一个问题、给几个选项（`ask_owner` 工具）

> 状态：后台已实现并合 main（24f779e8，ADR-341；工具形状以[规格-向主人提问](规格-向主人提问.md)为准）。界面那一半（[规格-组件库需求清单](规格-组件库需求清单.md) C5，消息里的选择题）还没接。ADR-153 第 2 条定了：答完不能改，只在本地私聊和话题里有，QQ 渠道不出现。
>
> 参考了：现有审批的做法（`daemon/plugins/tools.ts`：挂起的调用存在 `pending`、到 `tools.approvalMinutes` 自动取消、`tools/approval` 事件推给主窗口、主人点了 `decide`）；计划清单（`daemon/tools/todo-tool.ts`：参数先校验、不对就返回一句话让她改了重发，界面从 steps 表里那次调用的参数读）；[规格-排队插话停止](规格-排队插话停止.md)（插话、停止的语义）；CrychicUI `overlay/ask`（只看界面思路）。

## 一、要解决什么

她干活时常遇到"往哪边走都行、但得主人拍板"的岔路（改 A 还是改 B、要不要顺带清理），现在只能写一段话问，主人再打字回答，回答的格式也不固定。给她一个工具：问一个问题、给几个选项，主人点一下就回来，结果是结构化的。

## 二、工具的形状

```
ask_owner({
  question: string          // 一句话，≤ 200 字
  options: { label: string; detail?: string }[]   // 2～6 项；label ≤ 40 字，detail ≤ 80 字，label 不能重复
  multiple?: boolean        // 默认 false：单选
  other?: boolean           // 默认 true：允许"其他"自己写
})
```

- **声明**（`daemon/tools/spec.ts`）：`effects: ['self']`、`audience: 'owner-console'`（只给主人 × 主窗口）、不并行（同一时间最多一个问题挂着；第二个直接返回"上一个问题还没答完"）、`timeoutMs` 跟着 `tools.approvalMinutes`（默认 10 分钟，和审批共用一个设置，不新加键）。
- **四种场合**：本地私聊 ✓、本地话题 ✓、本地群聊 ✗（几个角色同时问会乱，先不开）、QQ 私聊 ✗、QQ 群 ✗。不在名单的场合根本不把这个工具给她（照 `audience` 的做法），不是给了再拦。
- **校验**：照 `validateTodos`，不对就返回一句给她看的话（"选项最多 6 个，合并一下再问"），不挂起、不推给界面。
- **工具说明里写清什么时候用**（写在工具的 `description` 里，不改 `prompts/`）：会改变接下来怎么做的岔路才问；能自己判断的、闲聊里的"你觉得呢"不用；问之前先把已经知道的写在问题里，不让主人再去查。

## 三、返回给她的结果（一行文字）

| 情况 | 返回 |
|---|---|
| 主人选了 | `主人选了：A`（多选：`主人选了：A、C`；带"其他"：`主人选了：其他——原话`） |
| 主人没点选项、直接在输入框说了话（插话或新发一句） | `主人没选，直接说了：原话`；问题卡片收成"没选，你直接说了" |
| 到时间没人答 | `主人这次没回答（等了 10 分钟）。按你判断最稳妥的做，做完说明你选了哪个` |
| 主人按了停止 | 跟审批一样：这一轮中止，下一轮开头附"上一轮被你停了" |
| 实例被释放、后台重启 | 挂着的问题作废；卡片显示"没等到回答"；她下一轮看到的是"上次问的问题没得到回答" |

"直接说了"那一条要和插话配合：问题挂着时主人回车发的话**不走插话**，直接当成这次的回答交回去（不然同一句话她会看到两次）。Alt+回车（排队）照旧排到下一轮。

## 四、事件和存储

- 推给主窗口：`tools/ask`（问题、选项、id、角色、会话、过期时间），答了推 `tools/asked`（选了什么）；主窗口发 `answer { id, picks: number[], other?: string }`，id 不在了回 `ask-gone`（照 `approval-gone`）。
- 不加表：问题就是 steps 表里这次工具调用的参数，答案就是这次的工具结果。界面重建时从这两样画卡片（照计划清单）。
- 日志只记"问了几个选项、选了第几个"，不记问题和"其他"的原文（照 CrychicUI 的"不记打的字"，也省得日志里出现私事）。

## 五、禁止的偷懒

- 用审批卡片凑合（审批只有同意 / 拒绝两种，语义不同，读屏和统计都会混）。
- 问题挂着时把主人的插话同时当插话又当回答。
- 在 QQ 场合"给了工具再在执行时拒绝"——工具不能出现在她的工具列表里。
- 答完以后允许改答案（ADR-153 第 2 条）。

## 六、验收

1. 单选、多选、带"其他"各一次，返回文字和上表一致（测试）。
2. 选项 1 个、7 个、重复、问题 201 字：都返回让她改的话，不推给界面（测试）。
3. 挂着时主人回车发一句：她收到的是"主人没选，直接说了：…"，这句话没有再作为插话出现一次（测试，看她实例里的消息）。
4. 到时间：返回"没回答"那句；卡片变"没等到回答"（测试用很短的超时）。
5. 停止：和审批一样中止（测试）。
6. QQ 私聊、QQ 群、本地群聊的实例里工具列表没有 `ask_owner`（测试断言）。
7. 后台重启后历史里那张卡片画成"没等到回答"，不是还能点的样子（测试 + check:ui 一项）。
8. 两个问题：第二个直接返回"上一个还没答完"（测试）。
9. 真实模型试 5～10 次（LESSONS"核心靠真实模型的功能合并前过一遍"）：数出她该问的时候问了几次、不该问的时候（闲聊、自己能判断的）乱问了几次，写进提交说明。
