## 一、要解决什么

- 现在哪些工具要审批是写死的三个名字（`tools.ts` 的 `NEEDS_APPROVAL`）：以后接 MCP、子代理，新工具不在名单里就**直接执行**。
- 读文件、列目录、搜索不审批、不限路径：她读得到 `data/` 里的配置（ADR-080 第 5 条要修）。
- 命令没有默认超时，卡住了就一直卡着。
- 她写错的命令在"自动""YOLO"下没人看就跑了（ADR-082）。

## 二、分三步做

### ①a 声明和判定（这一步）

**每个工具登记一份声明**（`daemon/tools/spec.ts`）：

| 字段 | 意思 |
|---|---|
| `effects` | 会做什么：`self`（只读写她自己的记忆）、`read`、`write`、`exec`（跑命令）、`net`（联网）。必填，不能空 |
| `audience` | `owner-console`（只给主人 × 主窗口）或 `any`。`any` 只允许 effects 全是 `self`，否则开机就报错 |
| `parallel` | 能不能和别的工具一起跑；默认否（pi 的 `executionMode: 'sequential'`） |
| `timeoutMs` | 默认超时 |
| `paths(args)` | 这次会碰哪些路径（给受保护路径、自动模式判断用） |
| `classify(args)` | 只给 PowerShell：命令每一段都只读时收窄成 `read` |

登记表（起步值，偏收紧）：

| 工具 | effects | audience | parallel | 超时 |
|---|---|---|---|---|
| `memory_search`、`recall_raw` | self | any | 是 | 30 秒 |
| `remember` | self | any（已被 ADR-088 改为：只在主人在场的私聊给，群里、朋友私聊不给） | 否 | 30 秒 |
| `read`、`ls`、`grep`、`find` | read | owner-console | 是 | 30 秒 |
| `write`、`edit` | write | owner-console | 否 | 60 秒 |
| `powershell` | exec（只读时 read） | owner-console | 否 | 命令没写超时就补 120 秒，最多 600 秒 |
| **没登记的** | exec、write、net | owner-console | 否 | 60 秒 |

**判定顺序**（`daemon/tools/policy.ts` 的 `decide()`，纯函数）：

1. **渠道**：`owner-console` 的工具出现在别的听众那里 → 拒绝（`forAudience` 本来就不给，这里是第二道）。
2. **只碰她自己的记忆**（effects 全是 self）→ 放行。
3. **受保护路径** → 问，任何模式都问（YOLO 也问），以后也不给"始终允许"（第⑤步）：
   - Sumika 的数据目录（`data/`，里面有配置、密钥、记忆、角色卡）；
   - 用户目录下的 `.ssh`、`.aws`、`.gnupg`；
   - 名字是 `.env` 或 `.env.*` 的文件。
   - 读、列目录、搜索、写、改都算；搜索 / 找文件的起点**包含**受保护目录时也算（会搜进去）。
   - PowerShell 命令里写到了这些路径，或者写到 `secrets.bin`、`sumika.yml`、`tool-grants.yml` 这几个文件名 → 算。
4. **灾难性命令**（格式化、分区、改启动配置、删还原点、删盘符根……现有的 `isCatastrophic`）→ 问，任何模式都问（ADR-021、ADR-081）。
   - 2026-10-19 ADR-106 加：删用户目录、它的直接下一级、凭据目录（`.ssh`、`.aws`、`.gnupg` 等），各种写法都算（`%USERPROFILE%`、`$HOME`、`$env:USERPROFILE`、`~`、绝对路径），绕开回收站的删除（`cmd /c rd /s /q` 这类）也算；YOLO 下"拆开看不清、又带删除动词"的命令也问（"看不清"按 ADR-112 的 `opaque` 判，不看 `unclear`：`unclear` 里还有"bun 会运行别的程序"这种说明，2026-10-19 第二轮复核发现"删 node_modules 再装"因此每次都问、只能一次）。
   - ADR-115 第 3 条（2026-10-19 复核）：点过"这个对话里都允许"的灾难性命令也要看目录——要改的东西看得清、碰到的外面都落在当时批准的目录里才放行（和普通命令的授权同一个判断，`policy.ts` 的 `covered()`）；批准了删 `C:\Users\me`，删 `Z:\` 照样问。不带路径的格式化类（`Format-Volume -DriveLetter Z`）没有"外面的目录"可比，拆得开就和以前一样：同一类不再问；拆不开的（没装 pwsh、超时）看不出碰到哪，照样问。
   - 已被 ADR-115 第 5 条改为：只有拆不开（没装 pwsh、超时）、语法不完整、动态执行或编码过的（`iex`、`powershell -EncodedCommand`/`-Command`、`node -e`、算出来的命令名、直接调 .NET……）又带删除动词的，才"只能允许一次"；目标从管道来、没写死（变量）、参数绑不上、换到看不清的目录的删除照样问，但能给"这个对话里都允许"。按分析器给的类别判（`shell.ts` 的 `opaqueKinds`：parse / dynamic / loose / unbound / cwd / piped / download），不靠原因文字；老的、手写的结果没有类别的当最严的算。灾难性的（`Get-ChildItem ~ | Remove-Item`）不被这一步截走，照旧走灾难性那一步。
   - 2026-10-19 ADR-106 加：命令里出现后台自己的地址和端口（`127.0.0.1`、`localhost`、`[::1]` 加主窗口端口和 7721）→ 任何模式都问，只能允许一次（免得她调自己的接口改设置、切档、批自己的审批）。
5. **按模式**（按 effects，不按名字）：
   - 手动：`read` 放行（不碰受保护路径的）；其余都问。
   - 自动：`read` 放行；`write` 且所有路径都在工作目录或允许的目录里 → 放行；`exec` 且命令只读 → 放行；其余问。
   - YOLO（**ADR-112 做了**，取代原来"登记过的一律放行"；2026-10-19 复核后改成"只有写死的才算看得清"）：读照旧放行；写、改文件（`write`/`edit` 工具）和会改东西的命令只在看得清目标、目标都在工作目录或允许的目录（`tools.autoApproveDirs`）里时放行，碰到外面的或看不清的一律问。和自动档的差别只在执行类命令：自动只放只读的执行，YOLO 下看得清、只碰工作目录里的执行（`npm`/`bun`/`node build.js`、`tsc`、`git clean` 等）也放。没登记的照样问。判不了的一律往"问"那边靠（jcode 的做法）。具体怎么算（`shell.ts` 的 `judge`、`policy.ts` 的 `decide`）：
     - **看得清**：会改东西的命令，参数只有字符串常量和数字算看得清（数组里的常量元素、`-Param:常量` 照常取出来）；变量、括号表达式、子表达式、拼出来的字符串、脚本块都算看不清。
     - **按结构认参数**（2026-10-19 第二轮复核）：分析器用 PowerShell 自带的 `StaticParameterBinder` 按 cmdlet 的参数元数据绑参数，位置参数、缩写、别名都换成正式参数名，只看语法树、不执行；只绑已加载的命令（先加载 Management、Utility、Archive、Security 四个自带模块，再关掉模块自动加载，免得查命令时顺手加载别的模块、跑模块里的代码）。参数元数据里没有"这是文件路径"的标记，所以"哪些参数是路径"仍按正式参数名列（名单很短，因为写法已经被 binder 归一了）。
     - **被改的那一侧要写死**：改文件的 cmdlet（只读动词白名单以外的 Verb-Noun，名词是 Item、Content、ChildItem、ItemProperty、Archive、File……）要写死 `-Path`/`-LiteralPath`/`-FilePath`（`New-Item` 不写 `-Path` 时还认 `-Name`）；复制、压缩、解压的源只是读，写死 `-Destination`/`-DestinationPath` 就行。目标从管道来（管道送来的对象会填进 Path / LiteralPath，所以 `… | Remove-Item -ErrorAction SilentlyContinue`、只写了目的地的 `… | Move-Item -Destination ./here` 都算）、根本没写、参数绑不上（绑定出错、不是自带模块里的命令）都算看不清。写死的值照旧全按路径查（内容串也在里面）。
     - **只是写进去的内容用了变量**（ADR-115 第 6 条）：改文件的 cmdlet 里 `-Value`、`-InputObject`、`-Encoding`、`-Stream`、`-Width`、`-Delimiter` 和通用参数（`CONTENT_FREE`，按绑好的参数名认，位置参数绑到 `-Value` 的也算）用变量、表达式、拼出来的字符串不算看不清；被改的那一侧照上一条写死、在里面才放（`Set-Content ./tmp/x.txt -Value $result` 放行，`Set-Content $p -Value hi` 问）。`New-Item` 建链接（`-ItemType` 是 SymbolicLink / Junction / HardLink，或者变量、带通配符、认不出的；pwsh 按前缀认类型，只有写死的 directory / container / file 开头一截算不是链接）时 `-Value`（别名 `-Target`）是链接指向的位置，不算内容，照样要写死、照路径查。
      - **已知工具链里"值是内容"的参数**（ADR-117 第 2 条）：同一个思路从 cmdlet 延伸到程序，做成一张小表（`shell.ts` 的 `CONTENT_ARGS`，键是"工具 子命令"，只列明确是内容的开关）。现在只有 `git commit`：`-m` / `--message`（含 `-am` 这类合写的、`--message=$msg` 连着写的）的值用变量、表达式不算看不清（`git commit -m $msg` 放行；点过"这个对话里都允许"以后手动档也不再问）。`-F` / `--file` 的值是文件路径，不在表里：写死的照旧按路径查在不在里面（指到外面的收进 `fileTargets`），用变量就不知道读哪个文件，照旧算看不清。说明里嵌的子命令（`"$(Remove-Item $p)"`）分析器当单独的命令各判各的，整条仍看不清。别的工具按同一思路逐个加，先量真实命令、再加测试；不认识的工具、不在表里的开关，用了变量照旧算看不清。
     - **网络取数的参数**：`Invoke-WebRequest`/`Invoke-RestMethod` 只要求地址（`-Uri`、位置参数）、`-Proxy`、`-WebSession`、落地文件（`-OutFile`、`-InFile`）写死；`-Body`、`-Headers`、`-Method`、`-ContentType` 这类只管"发什么"的（白名单 `NET_FREE`）可以用变量，带 `$body` 去 POST 本机 3425 照常放行。地址仍必须写死：后台端口检查按命令文字查。
     - **换目录**：`cd`/`sl`/`chdir`/`pushd`/`Set-Location` 之后的相对路径接在新目录后面算；pwsh 自带的 `cd..`、`cd\`、`cd~` 也算；换到外面的，后面的写和程序都算碰外面；换到看不清的目录（变量、`cd -`、`C:` 这类换盘函数——切到那个盘上次的位置），后面的相对路径都算看不清。
     - **在外面的写法**：命令里 `~` 开头、两个字母以上的盘符（`HKCU:`、`Env:`）、provider 写法（含 `::`）一律当在外面；工作目录里指向外面的联接 / 符号链接按外面算（gate 先用 realpath 解析好再交给 `decide`，policy 保持纯函数）。
     - **命令名**：先去掉目录和 `.exe` 再查表；别名按分析器所在 pwsh 自己的别名表（`Get-Alias`，启动时读一次；pi 跑命令也是 `pwsh -NoProfile`，两边一样）解析，不再手写别名表；是不是 PowerShell 命令看已加载的 cmdlet / 函数，或者 Verb-Noun 且动词在 `Get-Verb` 里（模块没加载的也认得出）。pwsh 自带的 `mkdir`（`md` 是它的别名）照 `New-Item` 查；别的名字不是 Verb-Noun 的函数算看不清。按路径调用的程序、脚本本身要在工作目录里。
     - **一律问**（`mustAsk`）：改系统状态的程序（`reg`、`net`、`sc`、`schtasks`、`setx`、`taskkill`、`winget` 这一类）和改的不是文件的 cmdlet（服务、进程、模块、计划任务……）；`git config --global / --system`；`npm`/`pnpm`/`yarn`/`bun` 的全局安装；直接写 `pip` / `python -m pip` 的 `install`/`uninstall`（ADR-115 第 2 条：看不出装进哪个 Python；按路径用工作目录里虚拟环境的 `pip`、`python -m pip`——`.venv\Scripts\pip install -r requirements.txt` 这类——不问，程序本身在不在工作目录里照 `runs` 查；带 `--user` 的问）；认得的包管理器和工具链不在子命令白名单里的（下一条）。`mustAsk` 的命令没有"始终允许"，最多"这个对话里都允许"（ADR-115 第 4 条，照 ADR-081"危险命令没有始终允许"，fd711f8）。
     - **工具链按子命令白名单**（`shell.ts` 的 `TOOLCHAINS`）：npm、pnpm、yarn、bun、pip、cargo、go、dotnet、gem、uv、pipx、poetry、conda 只有明确只作用于当前项目的子命令（装依赖、跑脚本、构建、测试、格式化、加减依赖这类）放行；其余（改用户级配置、装到用户目录、登录、发布、清全局缓存……：`npm config`/`cache`/`login`/`link`/`publish`、`cargo install`、`go install`、`go env -w`、`go clean -cache`、`dotnet tool`/`workload`、`dotnet new install`、`gem install`、`uv tool`、`uv python install`、`uv pip --system`、`pipx install`、不带 `-p` 的 `conda install`……）一律问。pnpm / yarn / bun 允许省略 run（`bun build:web`、`pnpm dev`）：这三个把自己的子命令列全，不在里面的当跑项目里的脚本。完全不认识的程序照旧只按参数里的路径判（见"已知的坑"）。
     - **下载一个包来跑**（ADR-115 第 1 条，`shell.ts` 的 `fetches`）：`npx`/`bunx`/`npm exec`/`npm x`/`bun x` 要跑的包写在项目的 `package.json`（`dependencies`/`devDependencies`）里、或者 `node_modules/.bin` 下有同名程序，就当跑项目里装好的工具，YOLO 下放行（参数照常查：变量算看不清、指到外面的路径收进目标）；没声明的问（卡片上的原因照实写：没声明 / 写了版本号这类不按声明认 / `--prefix` 指到了工作目录外面的项目，三种不混）。从跑的那个目录往上找到工作目录为止，每一级都读；读 `package.json` 在 gate 那一侧做（`projectToolsOf`），policy 保持纯函数；读不到、解析失败的当没声明。下面几种不按声明认、照样问：写了版本号（`npx eslint@8`：可能下载另一个版本来跑）、网址、git、本地路径；`uvx`（从 PyPI 拉，不看 `package.json`）；`pnpm dlx`/`yarn dlx`/`pnpx`（总是现下载、不用项目里装好的那份，2026-10-19 复核）；`npm create x`/`npm init x`。包名前面的开关才算这些工具自己的（`npx tsc -p ./tsconfig.json` 的 `-p` 是 tsc 的）；`npx -c`、`npm exec --call`、`pnpm dlx --shell-mode` 把一段字符串当命令跑，算看不清。"同一类"带上包名（`npx cowsay`），点过"这个对话里都允许"的不让 npx 别的包跟着放行。
     - **看不清**（`opaque`）还包括：解释器自己位置上（第一个脚本 / 子命令之前）的内联代码开关（`node -e/-p/--eval/--print`、`python -c`、`bun -e`、`ruby -e`、`perl -e`、`php -r`、`deno eval`；perl、ruby 合写的短开关里有 e 也算——perl 的 e / E，ruby 的 e，`-MFile::Temp`、`-rjson` 这类值贴在后面的不算；`node build.js -e prod`、`pip install -e .` 里的是脚本、子工具自己的开关）；解释器的代码从标准输入来（接了管道又没写脚本、或者写了单独的 `-`；`Get-Content data.json | node ./x.js` 写了脚本，送来的是数据，不算）；`iex`、`cmd`/`powershell`/`bash` 这类 shell；算出来的命令名；直接调 .NET（实例方法只放字符串、集合那些；静态方法只放白名单里的纯计算 / 只读：String、Math、IO.Path（不含会建文件的 GetTempFileName）、DateTime、TimeSpan、Guid、Convert、Regex、数字类型、Uri、Version、Linq.Enumerable……，解析不出类型的、IO.File、Environment、Console 这类都算）；语法拆不完整。
     - **程序的参数**：不认识的程序和具名工具，参数里的绝对路径、`~` 开头、带 `..` 的收进目标；git 的 `-C`、`clone`/`worktree add`/`init` 的目标、`--prefix`/`--dir`/`--cwd`、pip 的 `--target`/`--prefix`/`-d`/`-w` 也收进目标。git 的只读子命令（`diff`、`log`、`show`……）也查：`--output` 收进目标，子命令参数里指到外面的也收；`-C`、`--git-dir` 这些全局开关的值不算（只是在那里读，`git -C <外面> status` 照旧放行）。
     - **网络取数**：碰后台自己的端口照 ADR-106 一律问；地址、代理、落地文件是变量的看不清、也问；访问别的本机服务（3425 Magpie）和外网照旧放行，写文件的参数照文件目标查。
6. 兜底：问。

**超时**：包一层 `execute`，到时间返回一条"超时了（N 秒），没做完"的工具结果；PowerShell 用它自己的 `timeout` 参数（单位秒），没写就补 120，超过 600 压到 600。

**审批卡**：受保护路径、灾难性命令、没登记的工具，卡片上写原因（"要读 Sumika 自己的数据目录：里面有配置和密钥"）。

### ①b 她写一句"要做什么"（ADR-082 第 2 层）

`powershell`、`write`、`edit` 多一个必填参数 `purpose`（一句话，30 字以内）：显示在审批卡和工具卡片上；执行时去掉、不传给 pi。说的和做的对不上，主人一眼看得出来。

### ①c 先看懂命令、删除进回收站（ADR-082 第 1、4 层）

- 用 PowerShell 自带的语法解析器（常驻一个 pwsh 进程，免得每次起进程）拆开命令：用了哪些命令、哪些是改动类的、目标路径、有没有看不清目标的写法（变量拼路径、`iex`）。结果显示在审批卡上；看不清的一律问。
- 删除进回收站：PowerShell 工具的每条命令前面加一段定义（pi 的 `commandPrefix`），把 `Remove-Item`（及别名 `rm`、`del`、`rd`……）换成"挪进回收站"。只是兜底：`cmd /c del`、`[IO.File]::Delete` 这类绕得过去，所以第 1 层看到删除照样要问。

## 三、禁止的偷懒写法

- 不许再按工具名字写死判断（`if (tool === 'xxx')`）：一律查声明。
- 没登记的工具不许默认放行，YOLO 下也不行。
- 受保护路径不许只查 `read` 一个工具：读、列、搜、找、写、改、命令全要查。
- 路径比较不许区分大小写、不许不归一化（Windows：`D:\X` 和 `d:/x/` 是同一个）。
- 读、写、改、列、搜、找工具的路径不许自己另写一套解析：判定前先用和工具一样的办法归一化（`policy.ts` 的 `toolPath`，照 pi 的 `resolveToCwd`：去开头的 `@`、展开 `~`、转 `file://`、Git Bash 的 `/c/x`），再查受保护路径和在不在工作目录里（2026-10-19 复核：旧代码把 `~\.ssh\config` 当成工作目录下的相对路径，受保护目录任何档都没拦住）。

## 四、已知的坑

- 搜索的起点是受保护目录的上级时，ripgrep 尊重 `.gitignore`、通常不会搜进 `data/`，但不能靠这个：起点包含受保护目录就问。默认工作目录是用户目录，不包含项目目录，平时碰不到。
- PowerShell 命令能用变量、环境变量、相对路径绕开文字检查：①a 只是文字检查，①c 的语法解析会把"看不清目标"的标出来；兜底仍是手动模式每次问。
- YOLO 的拆命令判不了的（2026-10-19 第二轮复核后还剩的）：
  - **不认识的程序的副作用看不见**：只按参数里的绝对路径、`~`、带 `..` 的判，它自己往哪写（配置、缓存、用户目录）看不出来；子命令白名单以外的工具链（`deno`、`bundle`、`composer`、`mvn`、`gradle`……）也是这样。
  - **"同一类"仍按命令名认**（`git` 带子命令、`npx` 这类带包名，别的工具链只看工具名）：`cargo build` 的授权也会放过 `cargo install`、`winget install` 的授权也会放过 `winget uninstall`。ADR-115 第 3 条以后，命令的授权只管看得清、碰到的外面都落在当时批准的外部目录里的（"始终"只管工作目录里的；碰到外面的卡片不给"始终"，以前点过的也只管里面，ADR-117 第 1 条），所以写到哪不再跟着放开；但同名命令做的事不一样（子命令、开关）还是认成同一类。
  - "这个对话"记的外部目录：碰到的是已有的目录就记它自己，否则记它所在的目录（`Set-Content D:\out\x.txt` 批准的是 `D:\out` 和下面）；建目录、删除这类命令记要建、要删的东西本身（`New-Item -ItemType Directory D:\newproj` 只批 `D:\newproj`，不批整个 D 盘；`Remove-Item D:\out\x.txt` 只批这一个文件），写文件的上级是盘根、用户目录根或它们的直接子目录时（`Set-Content D:\a.txt`、`C:\Users\me\x\a.txt`）也只记文件本身（2026-10-19 复核）；`HKCU:`、`Env:` 这类 provider 写法落不到目录上，授权管不到，每次都问。目录只在内存里，重启后台就没了。
  - 管道删除的源头只认第一段是 `Get-ChildItem`/`Get-Item` 写死路径、中间只有 `Where-Object`/`Sort-Object`/不展开属性的 `Select-Object` 的；`Get-Content list.txt | Remove-Item`、`$items | Remove-Item`、中间有 `ForEach-Object` 的认不出，点过"这个对话"下一次也照样问。参数绑不上的删除（`rm ./a ./b`）分不出删的是哪几个，授权也管不到。
  - 只读命令的路径用变量 / 表达式写时，受保护路径检查看不到（读照旧放行）。
  - 改文件 cmdlet 写死的值全按路径查（内容串、`-Encoding` 的值也在里面），内容长得像外面的路径（`~`、`HKCU:`、`D:\…`）会多问一次。内容参数用变量的放行了（ADR-115 第 6 条），但只认 `CONTENT_FREE` 里那几个参数名；`-Filter`、`-Include`、`-Exclude` 这类决定改哪几个文件的用了变量照旧算看不清。
  - 程序参数里的绝对路径分不出是读还是写，读外面的文件也会问；git 只读子命令的参数指到外面（`git log -- ../x`）也问。
  - 模块没加载的 Verb-Noun（`Set-NetFirewallRule`、`Resize-Partition`）只靠动词的样子认、不绑参数：名词是文件的算看不清，别的一律问。
  - 参数绑不上的改文件命令算看不清：bash 习惯的 `rm -rf ./dist`（Remove-Item 没有 `-rf`）、多写了位置参数的 `rm ./a ./b`，带删除的照样问，ADR-115 第 5 条以后能给"这个对话里都允许"（原来走 3.6、只能允许一次）。这类命令在 PowerShell 里本来就会报参数错，问一次不漏，但会多打断；写成 `rm -r -fo ./dist`、`Remove-Item ./a, ./b` 照常放行。
  - 下载来跑按 `package.json` 认（ADR-115 第 1 条）：她先在工作目录里改 `package.json` 加一个依赖、再 `npx` 它，也会放行——和 YOLO 下 `npm install` 装 `package.json` 里写的依赖是同一个口子；`pnpm dlx`/`yarn dlx`/`pnpx` 总是现下载、不用装好的那份，所以不按声明认，照样问（2026-10-19 复核）。
  - pnpm / yarn / bun 允许省略 run，它们的子命令表漏列的会被当成跑脚本放过去；npm 和别的工具链不在白名单里的子命令都问，第三方插件子命令（`cargo watch`、`cargo nextest`）也问。
  - perl / ruby 合写的开关只要有 e 就算内联代码：值贴在后面的起头字母（`-M`、`-I`、`-r`……）排除了，`perl -wMFile::Temp` 这种还会多问一次。
  - 用相对路径调用的脚本不进受保护路径检查用的目标列表，只靠命令文字检查。
  - 别名表、函数表是分析器那个 `pwsh -NoProfile` 的，pi 跑命令也是 `-NoProfile`，两边一样；以后要是让 pi 加载用户的配置文件，配置文件里定义的别名、函数分析器看不到（会当成不认识的程序）。
  - 分析器冷启动约 0.78 秒（原来约 0.65 秒，多加载了四个自带模块）；超过 4 秒当看不清，机器忙时偶发（测试偶发失败挂了待办）。
- 改工具的参数（①b 加 `purpose`）会改变工具定义：对话实例下次重建才生效（工具定义在固定前缀里，ADR-022）。
