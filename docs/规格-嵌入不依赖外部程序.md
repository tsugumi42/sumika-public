# 规格：嵌入不依赖外部程序（P2-4）

> 状态：已做完（2026-11-16）。第 1 步后台（删 legacy、默认模型目录、相对路径、旧配置处理、自检）已合 main；第 2 步设置页缺模型时的两个入口 2026-11-16 做完。决定：后续路线决 10（主人 2026-11-15 拍板：嵌入默认后端改成自带的）。参考：规格-本地模型服务（私有存档）（Python 版，现为对拍参照）、归档的规格-Go本地模型（私有存档）（GM8 已于 2026-11-02 切生产）、质检 X-15。

## 开工卡

- **我理解成**：Sumika 的嵌入只走自带的 `sumika-models`（Go 版，ADR-229），借 MaiBot-Embeddings 的 Python 那条 legacy 退路整个删掉；全新安装不配任何路径也能找到模型目录（数据目录下的 `models/`）；三个路径可以写相对路径；缺模型文件时设置页给出“打开下载页”和“指定模型目录”两个入口。正例：一台没装 MaiBot 的电脑，把模型放进 `<数据目录>/models/gte-multilingual-base/`，开接收后向量检索可用。反例：继续保留 legacy 当“以防万一”（那就还是挂在别的软件上，X-15 没解决）；缺模型时悄悄只用全文检索、不告诉人。
- **领域正统做法**：自带推理运行时、模型文件放在应用数据目录下、缺模型时提示下载位置（例：Ollama 把模型放 `~/.ollama/models`，LM Studio 有模型目录设置和下载入口）。
- **最省事的字面做法够不够**：只把默认值从 `legacy` 改成 `go-models` 不够：legacy 代码还在、`embed.python` 等键还在、全新安装没有模型目录默认值，仍然起不来。
- **不做什么**：不做程序自动下载模型（几百 MB 的下载、校验、断点续传是另一件事，入口先给下载页链接）；不换嵌入模型（换模型要整表重算向量）；不改 `sumika-models` 本身和它的协议。
- **用户能看能试的验收**：见“验收”第 1、4 条。

## 设计

1. **默认后端**：`embed.backend` 默认 `go-models`；`legacy` 不再是合法取值。
2. **旧配置**：`embed.backend: legacy` 时不让启动失败：嵌入不启动、记忆检索退回全文检索（和现在嵌入起不来时一样），日志一次、自检报一条“`embed.backend: legacy` 已移除，改成 `go-models` 并确认模型目录”。配置里残留的 `embed.python`、`embed.serverDir`：读到时日志警告一次、忽略（配置结构里删掉这两个键，读配置不因多余键失败——照现有对未知键的处理，若现有处理是报错，就为这两个旧键单独放行并警告）。
3. **删掉的东西**：`internal/embed` 里起 Python 桥的整段（`server.py`、`bridge.py`、venv 检查）、仓库根的 `embed/bridge.py`、`config.Embed.Python`/`ServerDir`、设置注册表里这两个键、`sumika.example.yml` 里它们的注释和示例、参考页里的说明。`internal/localmodels/engine/spec.go` 等注释里提到 `server.py` 作为参照的保留（那是对拍参照，不是运行依赖）。
4. **模型目录默认值**：`embed.modelsRoot` 空 = `<数据目录>/models`（加进 `internal/paths` 的路径表，名字 `ModelsDir()`）。`embed.modelsRoot`、`embed.modelsExe`、`embed.ortLibrary` 写相对路径时相对于数据目录解析；绝对路径照旧。`modelsExe` 空照旧是 `<资源根>/sumika-models.exe`，`ortLibrary` 空照旧是 exe 旁边的 `onnxruntime.dll`。
5. **缺模型时**：开接收时 `sumika-models` 找不到 `embed.model` 对应的模型文件：嵌入不启动、退回全文检索、自检报一条（写出它在找的完整路径）；设置页“记忆”分组里嵌入那一节显示“找不到模型文件：<路径>”，下面两个按钮：“打开下载页”（打开这个模型在官方模型站的页面，地址写在模型登记表里，没有就不显示按钮）、“指定模型目录”（选文件夹，写进 `embed.modelsRoot`，提示重启接收生效）。
6. **配置键变化**照 AGENTS“改了什么”表：`native/internal/config` → `sumika.example.yml` → 参考页 → 本规格；设置注册表删两键、`embed.modelsRoot` 的说明改成写明默认值。

## 禁止的偷懒写法

- 留着 legacy 代码只是“默认不走”；把 `legacy` 悄悄映射成 `go-models`（换后端就是换模型，向量对不上）。
- 缺模型时不报、只静默退回全文检索。
- 相对路径按当前工作目录解析（Sumika 的工作目录不固定，必须相对数据目录）。

## 验收

1. 全新数据目录（`t.TempDir()`）、不配 `embed.*` 的路径：嵌入去 `<数据目录>/models` 找模型；把测试模型放进去后能启动（用现有测试里假的 `sumika-models` 或模型夹具）。
2. `embed.modelsRoot: models`（相对）解析成 `<数据目录>/models`；绝对路径照旧。
3. `embed.backend: legacy`：启动不失败、嵌入不起、自检一条；残留 `embed.python`、`embed.serverDir` 只警告不失败。
4. 缺模型：自检一条带完整路径；设置页那一节和两个按钮出现，“指定模型目录”写回 `embed.modelsRoot`。
5. 全仓 `git grep -n "bridge.py\|MaiBot-Embeddings"` 只剩历史文档、ADR 和对拍参照的注释。
