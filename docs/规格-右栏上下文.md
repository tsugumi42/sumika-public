# 规格：右栏的上下文标签（第一刀）

> （2026-11-12 ADR-359 后从历史挪回；mygo 界面按组件族重做时照这份做，和需求登记 R-185～R-196 冲突的以登记为准）
>
> 状态：第一刀已合 main；2026-11-09 第二刀（检查器、本轮用量钮）在 `feat/side-inspector` 上做完，已合 main；之后右栏加上下文标签见 abdd0327。挂待办“右侧栏按 ADR-293 做进新界面”“每一步的耗时时间线”。
> 依据：ADR-293 第 5 条（上下文照 DeepSeek harness 的轨迹和检查器）；主人 2026-11-09 定的顶行小胶囊（ADR-325）。
> 参考了：DeepSeek harness 拆解（私有存档） 第 18 节：按轮分组的记录、进行中不虚构耗时、首字从步骤开始计。采用这些；不采用它的时间概览和整张表，右栏放不下，行点开看细节。

## 做什么

右栏顶行的小胶囊放选项卡，下面的内容跟着换：

| 场合 | 标签 |
|---|---|
| 本地私聊、本地群聊 | 资料、上下文 |
| QQ 私聊、QQ 群 | 资料、活动 |

ADR-293 说的表情、文件、命令行等做了再加，不放占位。“活动”和“上下文”这一刀是同一个视图，都读这个会话的模型请求，只有数字和模型名，不显示正文。

列表一轮一行，新的在上：时间、用时、结局；第二行模型、输入（含缓存命中）、输出。点开一行：这一轮每次请求一行，下面是每一步耗时的横条（从 `turn_spans` 读，横条按这一轮的总时长算位置）。

## 数据

`api.StatsReader.ConvTurns(ctx, 会话, 条数)`：用 `ix_runs_conv` 倒着读 `model_runs` 这个会话最近的请求，按 `turn_id` 分组，不查提示词那几列大文本。没有 `turn_id` 的行（后台任务）不算。展开时用已有的 `Spans(ctx, _, {Turn: id})`。

只读连接、读失败不影响聊天；右栏这个标签看得见时才读，每 5 秒看一次要不要刷新（靠帧里的定时，不起常驻协程），切走就不读。

## 参数

- 最多读 400 次请求，够列 50 轮左右；超过就写“只列最近的”。
- 自动刷新 5 秒。这一轮在跑时看得到请求一条条多出来；没有变化不重排。

## 禁止的偷懒写法

- 不从消息反推用量。
- 不显示 `request_json`、`sections_json` 这些正文（检查器是下一刀，只在主窗口）。
- 不给没做的标签放占位。

## 已知的坑

- `turn_id` 同一轮可能有好几个角色（本地群聊每位成员一轮），各算一轮，行上写角色。
- 进行中的轮没有结束时间：用时写“进行中”，不编。
- 失败的请求没有用量：只写原因类别。

## 验收

- 四种场合标签都对，QQ 场合不出现“上下文”。
- 读服务返回的分组、顺序、命中率、截断有测试（假 trace 库）。
- 展开后横条位置按开始时间；没有耗时记录时写“这一轮没有耗时记录”。
- 右栏关着或切到“资料”时不读库（用计数的假读服务测）。
- 第二刀的验收见最后一节。

## 第二刀：检查器和本轮用量

> 参考：ADR-293 第 5 条；DeepSeek harness 拆解（私有存档） 第 18.4 节的检查器标签（系统提示词、工具、用量）。采用：点开一条请求分页看；不采用：它的差异页、原始输出页（我们没存回复正文）。

### 做什么

- 点开一轮以后，每次请求是一行可点的摘要；再点一下，下面（同级，不嵌在可点的行里）出现检查器，用 `Kit.Segment` 分四页：系统提示词、注入、工具表、用量。长内容在右栏的滚动区里滚，文字可选中复制；长文按空行分段排版，不把几万字放进一个文本框。
- “活动”（QQ 私聊、QQ 群）和“上下文”（本地）是同一个视图，检查器一样能看。这个界面只在主窗口，不往 QQ 发任何东西。
- 聊天里每轮用量：本地私聊、本地群聊的角色消息，悬停操作条多一个“本轮用量”钮，悬停提示是这一轮的输入（命中）和输出，点一下切到右栏上下文并展开这一轮。QQ 两种场合不摆。

### 数据（先读了库里实际存的格式）

`api.StatsReader.RequestDetail(ctx, id)`，按 `model_runs.id` 取一行，只在点开时读（列表查询 `ConvTurns` 仍不碰大文本，只多取一个 `id` 列）；查询有 2 秒时限，读不到界面写原因，记录被清理了写“这次请求的记录已经不在了”。

| 页 | 来源 | 实际格式 |
|---|---|---|
| 系统提示词 | `sections_json` + `prompt_sections` | `[{id, source, chars, hash}]`，正文按哈希在 `prompt_sections`；`memory` 以外的段 |
| 注入 | `sections_json` 里 id 为 `memory` 的段 + `injected_json` | `injected_json` 是任意数组（目前后台写 `[]`）；元素是字符串就当文字，其余按 JSON 原样转成文字 |
| 工具表 | `context_json` 的 `breakdown.parts.tools.items` | `[{name, tokens}]`，按 token 从多到少 |
| 用量 | 窄列 + `context_json` 的窗口 | 输入合计 = 未命中 + 命中 + 写缓存 |

解析不了的列不崩：原文放进 `SectionsRaw`、`InjectedRaw`、`ContextRaw`，写明是哪一列，界面写“这一列的格式解析不了，原文如下”并原样显示；单段正文超过 256 KB 截断并写明。

### 已知的坑

- **`request_json` 永远是 NULL**：`store.AddRun` 不写它（“完整的请求和回复默认不存”）。所以工具表页给的是工具名和估算 token，不是工具的完整 schema；`request_json` 以后真存了，会原样出现在工具表页底部的“完整请求”。没有就写“这次请求没记工具表”这类原因，不留空页。
- **`injected_json` 目前总是 `[]`**：注入页实际只有 `memory` 段。
- **消息表没有轮号**：`MessageView` 没有 `turn_id`，聊天里的消息和轮只能靠时间和角色对。规则：只给已结束的轮、只给它时间窗（开始 ～ 结束后 2 秒）里这个角色的最后一句；一句话落在两轮窗口里就都不给；进行中的轮不给。宁可没有钮，不乱挂。后台以后给消息挂轮号，就改成精确对应，这段推断删掉。
- **用量钮的数据来自右栏已读到的报告**，不为它另读库（“右栏关着不读库”不能破）：右栏没打开过上下文、或换了会话，钮就不摆；右栏开着时每 5 秒刷新，新一轮结束后钮才出现。
- 小标签没做成常驻的字：消息气泡的时间旁和过程气泡头都要改排版宽度，会让列表行高和气泡宽度跟着变；悬停操作条本来就占位，不改行高。要常驻再做，先等后台给消息挂轮号。

### 验收

- 详情查询：假 trace 库的正常、id 不存在、各列坏格式三种（`internal/runstats/reqdetail_test.go`）。
- 只有点开才读：计数的假读服务，展开一轮 0 次，点开请求 1 次，翻页不再读（`workbench_side_inspector_test.go`）。
- 四种场合：四种场合的检查器都能分页看；本地两种有“本轮用量”钮，QQ 两种没有。
- 读不到写原因、格式坏了原样显示、对不准的消息不挂用量，各有测试。
