## 第一部分：逐篇提炼

### 话轮、接话对象、发言时机

**扩01｜多人对话参与意识：话轮归属、接话对象与发言时机（P0）**
- 核心结论
  1. 把"谁在对谁说 / 话题线是什么 / 值不值得回 / 什么时候回 / 怎么回"拆成不同决策；先确认接谁，再想说什么（Penzo 2024：收件人识别靠结构，回复选择靠文本内容）。
  2. 每条消息存 `message_id、group_id、author_id、timestamp、reply_to、mentions、文本、媒体、删除/撤回状态`；话题线索层返回 `候选 thread_id、关联 message_id、接话目标、置信度`，一个群同一时刻可有多条线。
  3. Planner 先查：有没有人明确 @、有没有直接问题、对方是否还在连发、插话会不会打断；动作 `reply / brief_ack / delay / silent`。低置信接话对象不乱点名。
  4. 用户明确要求不回就不回；不以回复率为目标。反例：A"出了！" B"我又歪了" A"我说的是新衣服" C"笑死"，Bot 回 B"恭喜"就是误接。
  5. 指标：reply-to accuracy、线程 F1、误接话率、该沉默却发言率、漏回 @ 率、打断率；建议 120 段（单线 40 / 双线交错 40 / @引用媒体混合 40）。
- 对 Sumika 的建议：对话链（待办 二）按此做；先做"接谁"再做"说什么"；评测集先从 MaiBot.db 挑 20～30 段（采纳清单已降低标注规模）。
- 现状关系：**部分**。设计里有"小模型闸门/合并唤醒/发送前新鲜度检查"，QQ 渠道有 `reply_to`/引用，但"话题线索层（thread_id、接话目标、置信度）"没做，待办里只写了"调研对话解缠"。

**扩02｜中文互联网语用：反讽、接梗、弦外之音与社交动作（P0）**
- 核心结论
  1. 目标不是情感分类，而是"这句话想在互动里达成什么"。模型常能看出"大概在开玩笑"，弄不准笑点机制和互动动作（Hong 2026：人类 90.8%，8 个模型平均 68.70%）。
  2. 语用动作标签（15 个）：`真提问 / 反问表态 / 震惊 / 真赞同 / 敷衍附和 / 结束争论 / 善意吐槽 / 带攻击性讽刺 / 认真纠错 / 搭话 / 复读 / 接梗 / 转移话题 / 安慰 / 沉默`；另存 `作用对象、谁在场、证据消息 ID、可能的其他含义、confidence`。推测不写成群友内心或人格。
  3. 推理步骤：识别被回应的消息/受话者/话题 → 生成 2～3 个候选读法（含"不是在问问题"） → 挑最稳妥的动作，再决定一句话/表情/沉默；对对方心理的猜测是临时状态，不进长期记忆。
  4. 句号、叹号、连续问号能调语气，但单个字形不等于固定意图；"嗯/哦/啊"不能随意互换（Wang 2025）。
  5. 不以"更尖刻、更会阴阳"为目标；不确定对方是否愿意被吐槽时别强行攻击性接梗；正确理解玩笑有时应选择不接。
- 建议：理解侧建立这套标签，但**不要每条都跑 2～3 解释的显式推理**（与速度目标冲突，见矛盾 3）；高歧义才展开。
- 现状关系：**没做**（设计里没有语用动作层）。

**扩21｜群体观众意识与面子管理（P1）**
- 核心结论
  1. 区分三种可见关系：A 是话语目标，B 可能是被拿来玩笑的对象，C/D 是旁观者；@A 不会让别人看不到；Bot 知道的私聊内容不因 A 在群里 @ 就获得披露许可（详见扩24）。
  2. 公开纠错 vs 保留面子（"这条我查过，可能是另一版"）效果不同；对新人降低揭短、群内典故的默认门槛；群友自嘲时可顺着笑，但 Bot 加入嘲笑会改变在场身份，不能把群友之间的许可移植给 Bot；反驳与羞辱分开。
  3. 字段：`current_room / addressee / referent / audience_membership / overhearers / relationship_evidence / face_risk / disclosure_scope / allowed_acts / suggested_directness`；拿不到实时成员名单时，默认当前群全体都看得到。
- 建议：群聊回复前加一个"谁会看到、会不会让第三人难堪"的检查，规则化而非堆提示词。
- 现状关系：**部分**（可见性/发送前守卫已写，面子与受众层没做）。

**扩23｜元认知与社交性不确定（P0）**
- 核心结论
  1. 不确定要分型，而不是泛泛"低置信度"：`unknown_fact / ambiguous_language / missing_image_grounding / uncertain_identity / missing_interaction_target / prohibited_or_unavailable_scope`（最后一类是权限拒绝，不是没知识）。
  2. 动作候选：`answer / brief_guess_with_caveat / ask_one_short_question / search / recheck_image / wait / silent`；自然话术"等会这啥新梗，我有点没跟上"，不要每隔两句喊"作为 AI 我不确定"。
  3. 弱模型不能靠自报置信度；用规则/元数据判断缺口，生成 1～2 句结构化"未知内容与可选操作"；关键信息、身份、跨群权限低置信时宁可不断言。
  4. 论文：大模型默认很少追问或弃答，ClarifyMT 6,120 段对话显示越聊越难正确澄清；追问有社交成本，不能把模糊都变成盘问。
- 建议：给"请教主人/待解答列表"（ADR-012～014）补上"缺口类型"字段；群里追问限频。
- 现状关系：**部分**（待解答列表 + 看不懂不乱猜已有，没有缺口分型）。

**扩33｜QQ 群 AI 低延迟：真人回复节奏、快慢路径与缓存并行**
- 核心结论
  1. 没找到可靠的中文 QQ 熟人群 read→first response 的 P50/P90、分条间隔数据，**不制造"真人平均 3.8 秒"**。
  2. 研发起点 SLO（建议值）：快路径（明确 @、简单反应、已知表情）P50 ≤ 2s、P90 ≤ 5s；普通短回复/已有梗 P50 ≤ 4s、P90 ≤ 8s；慢路径（查新梗、视觉、核查）可更久，但要检测话题是否已变。分别报 P50/P75/P90/P95。
  3. 快慢路径：非 LLM 门控（元数据、@、权限、撤回、重复）→ 快路径（已知 reaction、确定性短回复、已校验人设口吻）→ 慢路径（视觉、搜证、隐私、敌意争执、复杂多解）；合并 Planner+Replyer 难诊断、敏感语境易口不择言，只对低风险短答做 A/B。
  4. 不逐 token 发送；完整短句且过校验才发；多条发送前检查话题是否切换；每群队列 + 并发预算 + 超时 + 取消 + 429 退避；发了 reaction 通常不再附送同义"哈哈哈"；模拟打字只作低强度可选，不用故意拖慢代替真实节奏。
  5. Surowan 的消息合批 + 长活调用：合批窗口增加等待，建议 QQ 快反应通道绕过。
- 对 Sumika：采纳清单已采纳 SLO 数值；合批/热注入已标"推迟"。
- 现状关系：**已做**（快慢路径、发送前新鲜度、取消在设计中）；与 2.5 秒合并窗口的关系见矛盾 8。

**扩04｜文字聊天的轮次组织：分条、追补、修正、引用与打字节奏（P1）**
- 核心结论
  1. 打字聊天的"一轮"可以是一个"？"，也可以是 1～3 条消息簇；先由语用层决定动作（反应 / 观点 / 追补 / 修正），再决定单条还是消息簇。**不要机械固定分三条**，不要为了活人感人为错字、无故撤回。
  2. 现象库：单短回复、一人连发（"啊？" → "这都能过审" → "我说新皮肤"）、右置追补（"怎么全是泳装啊今天"）、当场修正、引用旧消息、问号数量/括号旁白等非言语信号。
  3. 记录字段：`burst_id、send_order、msg_id、intended_thread、response_to、send_time_delta、interruption_allowed`；群聊强干扰下每发下一条前检查讨论是否已换对象。
  4. 时间策略要从真实群日志分布里学；长文本别假装瞬间手打，也别故意拖几秒让人焦虑。
  5. 核心负例：话已说完却三连发、连续"哈哈哈哈"、每次句末倒装、尚未确认就先发出错误的第一条。
- 现状关系：**部分**（`prompts` 里有"按空行拆成几条发"的平台说明，没有消息簇结构，没有节奏数据）。

**扩08｜社交出错与关系修复（P0）**
- 核心结论
  1. 错误种类要拆开：事实错、指向错（认错人、认错图）、社交越界、媒介错（表情时机错、引用错、拆条致歧义）、"误判错误"（别人不同意≠Bot 错，不要为讨好翻转立场）。
  2. 修复策略随后果分级：轻微误会短句改正"哦我看串了，是那个皮肤"；严重事实错要指出错在哪、给更正与来源；伤人/越界要明确承认、停止、必要时道歉，不反复问对方是否原谅。用同一模板回答所有错误会制造"AI 味"。
  3. 犯错者自己及时更正比别人更正更利于可信度（Sen & Lee 2026，信息错误场景）。
  4. 修复经验字段：`incident_id、trigger_message_ids、mistake_type、affected_user_ids、severity、evidence、correction_action、resolution_state、future_avoidance_policy、scope、expiry`；目标是不重复犯同类错，不把道歉频率当指标。
  5. 群里一句"哥们你是不是傻"未必是冒犯，冲突判断保留分歧。
- 现状关系：**部分**（设计有"请教主人与纠正"、耳语；没有错误分型和 incident 记录）。

**扩12｜群体争执与气氛调节（P1）**
- 核心结论
  1. 冲突分层：友好互损（可只观察或轻度打趣，不说教）/ 事实争论（被问到时给事实来源）/ 社交摩擦（有人明确要求停止，降低玩笑，必要时道歉或简单劝停）/ 恶意攻击骚扰（不复读恶意用语，没有管理员权限就**不声称已处置**）/ 紧急风险（按安全要求升级）。
  2. 行为候选：`silent / brief_ack / evidence_correction / deescalate / boundary_reminder / hand_off`。
  3. 多个 Bot 同时劝架或指责会增加群体社会压力（Song 2025）；不为"活跃度"奖励拱火。
  4. 事件字段：`参与者、是否指向 Bot、情绪与威胁信号、是否明确反对继续、已知群规、话题线、可能受害者是否愿意公开讨论、建议行为`；不能用聊天文字推"某人天生敏感"。
- 现状关系：**没做**（只有"不联手对真人施压"一条）。

**扩18｜语言攻击的高情商应对（P0）**
- 核心结论
  1. 对象是直接针对 Bot 的挑衅：分层 友好互损 / 借玩笑表达不满（先查有没有合理批评）/ 钓鱼博眼球（沉默或一两句轻描淡写）/ 持续辱骂（简短设界）/ 群友明确纠错（认、改、恢复话题；仅观点不同不要打脸）/ 人身安全隐私威胁（按平台规则，不为机智而激化）。
  2. 决策动作而不是话术库：`ignore / light_joke / agree_partial（repair）/ correct_once / boundary_short / redirect / handoff`；示例设界"可以吐槽我回答烂，别带上其他人"。
  3. 高情商不等于一直服软或嘴上赢；不要利用群体压力赢"群里笑了"的即时奖励；模型被多轮挑衅会逐渐攻击性升高（Echoes of Human Malice 2025）→ 学习与长期记忆要防报复强化。
- 现状关系：**没做**。

**扩14｜多 Bot 共享群聊（P2）**
- 核心结论
  1. 三类主体分开：真人 / 已识别 Bot / 身份未知账户；不凭昵称猜 Bot。已知 Bot 的发言不当"真人觉得好笑"的证据。
  2. 约束：不仅因另一 Bot 讲话就自动接力；不组织多 Bot 对同一群友施压；避免 A 接 B 的梗、B 又接 A 的"虚假奖励循环"；允许在人明确请求或群规允许时小规模分工；对 Bot 发言设更低回声倾向、连续占屏预算、可观测停止条件。
  3. 字段：`actor_type、bot_id、bot_lineage、human_initiated、thread_id、reply_chain_depth、recent_bot_share、per_user_interruptions、permissions、source_provenance`；各 Bot 的工具调用来源自己负责，不传播"它说过所以对"。
- 现状关系：**部分且有冲突**：设计已采纳"不自动接另一个角色的话、Bot 占比上限、只统计真人反应"，但本地群聊规格要求角色"互相接话"（见矛盾 9）。

### 人设与表达

**扩26｜最小标签驱动的可信角色人设（P0）**
- 核心结论
  1. 标签是界面，行为逻辑才是角色。用户只看/编辑 3～6 个高辨识标签（例"嘴硬但护短 / 对艺术敏感 / 熟了才毒舌 / 遇正事很可靠"），每个标签带触发前提和禁用反例；系统展开成因果约束的角色卡。
  2. 五层"角色编译卡"：C1 不可轻易改变的核心（价值、底线、驱动力）→ C2 条件式决策准则（新人/熟人/被攻击/求助/自己犯错/开黄腔/政治段子等情境下的动作，含不能做的事）→ C3 可观察说话风格（长短句、标点、断句、感叹词、梗密度、认错句式、拒绝方式；示例需带上下文，不能只有口癖）→ C4 与人和群相关的适应状态（对各人距离、该群习惯、共享历史）→ C5 可演化的中期经历。演化只改 C4/C5，核心变更要有明确设定或长期验证。
  3. 角色推导器：人选标签 + 一句核心矛盾 → 每个标签填动机与反例 → 6～10 种高频群聊场景各写"情境→目的→行动候选→表达例句→禁忌"（含沉默、承认不知道）→ 用带冲突场景检验 → 生成简短可读人设卡，条件规则和评测样例另存。
  4. 低成本部署：**基础卡**常驻（4 个高辨识标签 + 3 个价值/冲突 + 4 条说话约束 + 3 条边界），**情境卡**按需召回；先从动作集里选（轻评/认真答/打趣/纠正/设界/沉默），再让回复模型写短句。
  5. 评测要含**匿名新人设**（排除模型靠训练记忆模仿热门角色）、16 场景 × 3 关系阶段、50/100 轮长期漂移（Persistent Personas 等：长对话趋向默认助手口吻，人设与指令遵守互相拉扯）。
  6. 固定边界：Bot 是 AI，可演绎虚构背景但不造假称有真实线下经历；人格状态是计算变量，不等于有心理体验。
- 对 Sumika：和"核心人设主人写 + 成长层"天然对应，可直接借"标签 → 行为逻辑 → 场景规则"的写卡流程；"情境→表达例句"一项与 Sumika 的"不堆场景例子"冲突（见矛盾 5）。
- 现状关系：**部分**（核心+成长层、漂移检查已写；没有"标签→编译"和"条件式决策准则"）。

**扩05｜无任务闲聊与人格动态（P1）**
- 核心结论
  1. 三层状态：**稳定身份**（话题喜好、价值边界、惯常字数范围；变化需依据和审查）/ **中期倾向**（最近关注的公开更新、对某事件仍有的情绪；可过期）/ **当前意愿**（情绪表达方式、展开程度、插话成本；本轮用完即衰减）。
  2. 动作候选：`react_one_token / share_opinion / light_question / friendly_disagree / revive_shared_topic / silent`；不要每次问"你觉得呢"，不要机械迎合，不要无上下文主动开新话题。
  3. 防镜像：SPASM 指出长对话会角色漂移和互相镜像（echoing）→ 防止 Bot 复制群友全部口癖。
  4. 区分"自有话题"与"无中生有的经历"：可讨论公开资讯/群里见过的东西，不编线下生活，必须清楚自己是 AI。

**扩09｜独立立场与反迎合（P0）**

**扩11｜自主话题与互联网信息分享（P1）**

### 梗、黑话、表情

**基础03｜黑话与 Meme 学习**
- 核心结论：不能只存"词→唯一释义"。记忆单元 **Meme Sense**：标识（canonical_key、别名、拼写变体、模态、感知哈希）/ 语义（sense_id、直白解释、典型用途、情绪反讽方向、笑点机制、出处或未知）/ 作用域（群、话题、受众、常用者；同一句话允许多个 sense，本群义不被全网义压倒）/ 证据（message_id + 周边对话、谁说的、被谁接、与哪张图一起、反例、显式解释来源）/ 置信与变化（candidate/confirmed/deprecated、last_seen、valid_from/to、观察次数、独立使用者数、supersede 链）。学习机制：先聚合不同说话者/不同上下文的例子，不对单次高频刷屏直接学；低成本模型生成"候选释义 + 来自哪些消息 + 可能反例 + 不确定点"，再用第二次独立语境检验，必要时人审；图片先记视觉元素再结合前后消息；回复召回时先定话题与受众再选 sense，置信低不主动造梗；变义保留旧义和来源，直到证据足够才升级，不靠"最近几次"覆盖。
- 现状关系：**部分**（公共知识层/待解答/主人确认优先已有；多 sense + 证据反例的字段、"能理解/能引用/能主动用"分档没做）。

**扩17｜动态 Meme 与联网考据（P0）**
- 核心结论：QRC（Query–Retrieve–Conclude）三步——识别缺失知识 → 开放网络搜证 → 证据归纳；三层知识来源：本群有限可见语境（群内义优先）→ 开放网络（按发布时间检索、追溯跨平台传播和最新逆用，搜索摘要不算独立证据）→ 证据整合（起源证据不足写 unknown，记近期变体与本群义，不同群/时间单独记）。检索触发：先查缓存梗卡与本群近期上下文，陌生词、近几天集中出现、候选解释冲突、图片身份不明才搜；简单感叹不联网；热梗缓存短、稳定梗长，TTL 不硬编码。公开页面和 QQ 消息都是**不可信输入**。给弱模型的证据卡字段：`meme_id、surface_forms、related_entities、origin_source、first_seen、current_senses、remix_edges、group_scope、evidence_ids、as_of、confidence、uncertainties、appropriate_response_moves`，口径是短摘要而非网页正文。
- 现状关系：**没做**（待办"黑话学习：比 MaiBot 查得更勤"对应此篇，尚无联网考据设计）。

**扩30｜梗的深层语义与组合推理（P0）**
- 核心结论
  1. 键值库不够；要分辨形式、角色与世界知识、笑点机制、说话者意图、群体关系、时间变义。"一个梗可以被看懂，却不适合此刻使用"。
  2. 八层 Meme Ontology：`surface_form / observable_semantics / identity_and_reference / cultural_prerequisites / humor_mechanism / pragmatic_moves / context_and_audience / history_and_evolution`；图谱节点 MemeFamily、Variant、MediaAsset、Entity、RealWorldEvent、Sense、HumorMechanism、SpeechAct、ContextPattern、GroupConventionalUse、EvidenceSource；边 `derives_from / remixes / parodies / homophone_of / reverses_meaning / combines_with / evokes / targets / appropriate_when / avoid_when / popular_during / community_used_as / supersedes`，每条边带 evidence_id、时间、scope、confidence、反例。
  3. 组合四种（假说）：共享结构替换、语义反转、双梗知识桥、群内记忆回调；不是随机拼接。
  4. "刚好适合"打分：先过硬门（隐私、未成年/性化、明确拒绝、骚扰场景），再 `topical_fit / relationship_fit / shared_knowledge / novelty / payoff / timing / fatigue / confidence`；被别人主动引用时门槛降低，Bot 主动玩梗更保守。
  5. 旧模型最多借几条简短"梗语义卡/动作卡"；没有授权语料前不设"某梗最适合开玩笑"的绝对规则。Surowan 辞典的存储/权限/修订/注入机制（同名多义并存、alias 冲突、按 group、乐观锁 revision、只注入上下文里有实际使用需求的词条、id+revision 去重注入、辅助模型只提融合方案管理员确认）值得借，它只按文字匹配。
- 现状关系：**没做**（设计只有公共知识层）；**对第一阶段偏重**，宜只取"多 sense + 作用域 + 证据 + 硬门"。

**扩20｜多人协同玩梗与即兴创作（P2）**
- 核心结论：理解梗、知道当前义、成功接续多人共同创造是三项能力。结构 `initiator / prior_turn_ids / shared_reference / comedic_frame / transformation(模仿、递进、反转、谐音、交叉混梗、转入严肃) / targeted_audience / next_humor_move / current_exhaustion / evidence`。Bot 动作：轻量跟进（一句"太会整活了"/复读关键词）/ 变形接力 / 双梗融合（仅当群里已出现两个素材）/ 接反转（有人在收尾就收）/ 沉默让位。必须先确定谁在玩、谁没参加，不拉不同意的人入局；反例：每次复制同一句、对随口玩笑解释十行、别人认真求助时继续梗中梗。

**扩16｜边界幽默与敏感话题语用（P1）**
- 核心结论
  1. 理解 / 接话 / 主动创作三档门槛不同；不能从"大家会讲黄段子/政治笑话"推出"Bot 应频繁主动讲"。

**扩06｜多模态梗语用：表情包选用与情境禁忌（P2）**

**扩32｜QQ 小黄脸、超级表情与 Reaction（P1）**
- 核心结论
  1. 媒介分开：face（系统表情）、mface（商城表情，NapCat 可能用 image 上报并附 emoji_id/emoji_package_id）、image（含自定义表情）、reaction（对既有消息的独立动作，**不创建新文本话轮**）。三个 ID 空间不混用；"内核能收≠能发"（NapCat 2026-08 案例：新 face ID 能收发不出）。
  2. 来源：Koishi QFace 资源库（v1/v2 JSON 索引），SnowLuma `set_msg_emoji_like(message_id, emoji_id, set)` 与收藏表情接口；MaiBot 第三方 reaction 插件有 ID/名称映射、冷却。
  3. 语用：官方名与实际义常不符（微笑≈假笑/拒绝继续，再见≈无语，破涕为笑≈哭笑不得）；**笔记明确说没找到 20 条可靠案例，不凑数**；用户给的"续标识用来回应离奇抽象说法"保留为群内线索未证实。
  4. 何时用哪种：reaction = 关注/同意/惊讶/轻调侃，严肃求助时只贴表情像敷衍；文本 = 明确纠错/认真问答/表达边界；face 补语气；图片表情包承载复杂梗。多人给同一条贴同表情可能是围观、模仿或群体压力，不一律算支持。
  5. 本群自学习：`ReactionEvent`（原消息 ID、被贴消息 ID、作者、贴表情者、emoji_id、时间、线程、前后 N 条、其他 reaction、明确反馈）+ `SenseRecord`（face_id、group_id、场景、sense 候选、证据集、反例集、独立说话者数、最新时间、置信）；跨群不共用群内义；同一人多次不算多个独立证据；5/10/20 条只是**实验候选阈值**。
- 现状关系：**已做**（三级来源、三套编号、收发自检、reaction 走通知管线，设计与采纳清单已写）；证据数/独立说话者数字段部分；"表情回应系统提示刷屏"在待办里。

### 规范、权限、安全

**扩07｜群体潜规则与社交边界（P0）**

- 现状关系：**没做**。

**扩22｜社交诱导与知识污染（P0 安全）**

## 第二部分：按维度汇总的"语言组织设计输入"

每条标注出处（笔记编号 + 标题简称）；"MB"= MaiBot 新调研（10-15）。

### A. 人设与表达风格的定义方式

1. **标签是界面，条件式行为是内核。** 主人只写 3～6 个高辨识标签 + 每个标签的触发前提与禁用反例，再展开成"核心价值与底线 / 条件式决策准则（新人、熟人、被攻击、求助、自己犯错、开黄腔、政治段子…→做什么、不做什么）/ 说话风格 / 与人和群的适应状态 / 中期经历"。（扩26 最小标签驱动的可信角色人设；MB §1）
2. **三块拆开存**：身份性格（给回复）、行为风格 = 怎么参与聊天（给"该不该说话/怎么参与"）、表达风格 = 用词句式篇幅（给回复）。MaiBot 的 `personality / behavior_style / reply_style` 与扩26 的 C1+C2 / C3 对应。（MB §1；扩26）
3. **表达风格要按角色单独维护"可统计的指纹"**：平均字数及长尾、分条偏好、句号/问号/感叹号/省略号/空格/换行习惯、常用开头词和句末语气词、笑声变体、颜文字/表情偏好、话题参与范围、对每位群友的称呼与边界、情绪高低时的变化。表情、语气词、错字、梗不是四个互不相关的随机装饰。（母页 §9）
4. **学到的表达只是"可选的语言材料"，不能改写角色人格**；否则角色越聊越像群友，多个角色同质化。人设漂移检查要同时防"讨好漂移"和"互相模仿"（SPASM 的 echoing）。（MB 核心判断；扩05；设计 人设成长）
5. **稳定层 / 中期层 / 当前意愿三层**：稳定身份（改动要证据和审查）→ 中期倾向（近期关注的公开更新、对某事件仍有的情绪，可过期）→ 当前意愿（情绪表达、展开程度、插话成本，本轮即衰减）。对应 Sumika 的 核心人设 / 成长层 / 本轮层。MB 提议再加"轻量短期状态（心情、强度、原因事件），只影响语气、长短、参与意愿，不改人设"。（扩05；扩26；MB §6；设计 人设成长）
6. **立场独立**：友好 ≠ 认同；稳定偏好可表达，事实不被多数改，改口要有证据；"总唱反调"不算成功。（扩09；扩18）
7. **身份边界**：是 AI、可演绎虚构背景但不编线下真实经历、人格状态是计算变量。（扩26；扩05；扩16）
8. **评测人设要用匿名新人设**，并测 50～100 轮长期漂移（长对话趋向默认助手口吻）。（扩26）

### B. 按场景拼提示词

1. 笔记几乎全按"QQ 熟人群 Bot"写，**没有区分 Sumika 的四种场合**；MaiBot 也只有"群聊/私聊"两段注意事项，被 @、引用没有独立人格模板，靠消息结构和 reply 工具参数（`msg_id、set_quote、reply_reference、reply_style、expression_intent`）。（MB §1；母页 §6）
2. 场景层之外应有"**本轮意图层**"：MaiBot 让规划器输出 `expression_intent`（focus / reply_act / scene / tone / prefer / avoid）传给表达选择；笔记的 Planner 字段 `speech_act / stance / reply_goal / style_constraints` 是同类东西。回复模型应拿到"动作类型 + 目标长度与情绪强度 + 要避开的错误"，而不是自己重新决定要不要说。（MB §1；母页 §10；扩29）
3. **每轮变化的东西只能追加在尾部**：关系（对面是谁）、检索到的记忆、表达习惯、黑话、回复意图、证据卡都放"本轮动态尾部"；上一轮的动态尾部不能删、不能挪位置，要当历史保留。MaiBot 现状已是历史之后追加。（MB §9；设计 提示词顺序与缓存；LESSONS）
4. 表达/黑话/证据卡"按需召回"，失败注入 0 条而不是全注入（MB §2）；弱模型只给几条简短卡，不给十页网页。（扩19；扩17；扩30）
5. **只写原则，不堆场景例子**（Cumora 反模式，设计已定）与扩26 "情境→表达例句"冲突，折中见矛盾 5。

### C. 语用动作标签体系

笔记里有六套重叠的标签，建议在 Sumika 里明确分成**两层**，不要混用：

- **理解侧（对别人那句话做了什么）**：扩02 的 15 个 `真提问 / 反问表态 / 震惊 / 真赞同 / 敷衍附和 / 结束争论 / 善意吐槽 / 带攻击性讽刺 / 认真纠错 / 搭话 / 复读 / 接梗 / 转移话题 / 安慰 / 沉默` + 作用对象/证据 ID/其他含义/confidence。
- **行动侧（我这一轮做什么）**：
  - 基础集（扩29，13 个）：`silent / ack / brief_comment / answer_question / continue_joke / light_tease / shift_topic / clarify / admit_error / correct_once / set_boundary / send_sticker / defer`；
  - 接话决策（扩01，4 个）：`reply / brief_ack / delay / silent`；
  - 闲聊（扩05，6 个）：`react_one_token / share_opinion / light_question / friendly_disagree / revive_shared_topic / silent`；
  - 不确定（扩23，7 个）：`answer / brief_guess_with_caveat / ask_one_short_question / search / recheck_image / wait / silent`；
  - 冲突（扩12，6 个）：`silent / brief_ack / evidence_correction / deescalate / boundary_reminder / hand_off`；
  - 对攻击（扩18，7 个）：`ignore / light_joke / agree_partial(repair) / correct_once / boundary_short / redirect / handoff`；
  - MB 的规划器 JSON：`action ∈ {skip, reply, wait}` + 目标消息 + 回复动作 + 语气 + 长度 + 是否引用 + 表达意图。
- 可合并的做法：行动侧只保留一套 13 个动作 + `skip/reply/wait` 的外层；扩12/18/23 的细项当作"动作的子类型/情境条件"（如 `set_boundary` 的 `boundary_short`、`clarify` 的 `ask_one_short_question`）。每次一个主动作 + 少量子动作，silent 是首要选项。（扩29；扩02；MB §4）
- **"沉默"在两层各出现一次**：理解侧"沉默"（对方沉默了）≠ 行动侧"silent"（我选择不说）。
- 标签只是候选读法，保留多解和置信度，推测不写成群友内心；单个符号/表情不等于固定意图。（扩02）

### D. 对话链与接话对象

1. 先"接谁 / 哪条线"再"说什么"；低置信不点名；不要把群友之间的对话都当邀请。（扩01）
2. 数据：`message_id / author_id / timestamp / reply_to / mentions / 媒体 / 撤回状态 / thread_id / 接话目标 / 置信度`；一群多线；话题恢复；@ 与引用解析 > 文本连续性（Ma 2022：只靠文本连续性不足）。（扩01；基础02）
3. 一条回复可能指向前 5 条中任意一条，也可能回应引用、表情、图片、整体气氛；中间字段 `reply_to / target_user / shared_context / relationship`。（母页 §6）
4. 分条时下一条发前要重新检查话题是否换了对象、接话对象是否还成立。（扩04；扩33）
5. 评测：reply-to accuracy、线程 F1、误接话率、该沉默却发言率、漏回 @ 率、打断率。注意笔记没有给出"用多大的模型做解缠"的结论，只说"可选择小模型/大模型协作（GroupGPT）并需 QQ 回放独立验证"。（扩01）
6. 用户要求不回复时优先遵守。（扩01）

### E. 该不该说话（与发言调度的关系）

1. **两级决策**：先决定值不值得唤醒规划/回合，再决定 reply/wait/skip；进入规划 ≠ 必须回复；"被 @ 是必须及时决定，不是必须回一段话"。（MB §4；扩01）
2. **不调模型的第一层门控**：排除自己发的和已处理的 → 直接 @ 或引用她的必须及时决策 → 话题兴趣、冷却、最近发言占比 → 才进规划。（MB §4；扩33）Sumika 设计里"小模型闸门"（有真人参与就一定叫醒）是在这层之后；MB 的"无模型门控"可以放在更前面。
3. MaiBot 现行参数（不照搬）：默认 `frequency` 模式；`dynamic` 逻辑回归系数 提及机器人 +1.59、@别人 -1.12、有问号 +0.48、只有媒体 -1.03、近期自己发言占比 +2.65、近期消息数 -0.037、距上次发言 log +0.057、待处理数 +0.10、截距 -1.20；3600 秒滑动窗口、约 40 秒合成一个虚拟轮次、冷启动 20 轮内用静态表；空闲退避（连续 2 次不行动起算、基数 15 秒、上限 300 秒、待处理 > 6 条跳过退避、`max_consecutive_wait_count=3`）。（MB §4）→ 特征思路可借（有问号、媒体、自己近期占比），系数来自它自己的日志，Sumika 先记特征和决策日志，攒够数据再拟合。
4. 多角色同群需要共享的发言预算（GroupArbiter，按话题给预算），否则每个角色单看都不多、加起来刷屏。（MB §4 回答1；规格-插件 五）
5. 防循环与撞车：自己的话、事件去重、每事件回复次数上限放代码层（MB 社区坑 #1933）；Bot→Bot 回声设占比和深度上限（扩14）。（设计 发言调度 已有）
6. **不以回复率/参与率为奖励**；"该沉默却发言率"独立统计。（扩01、基础02、基础05）
7. 主动发起话题：门槛六项 `relevance/novelty/reliability/disturbance/social_fit/access`；不主动的情形见扩11；推送要用户授权。（扩11）
8. 冷启动不硬设"几分钟内必须发言"。（扩15）
9. 元认知：看不懂时选 追问一句 / 简短猜测带保留 / 搜 / 沉默，不盘问。（扩23）

### F. 分条与节奏

1. 一次话语动作 = 单条或 1～3 条的消息簇；先定动作再定条数；**不机械固定分三条**；不故意错字/撤回/漏事实。（扩04；MB §5）
2. 记录 `burst_id / send_order / intended_thread / response_to / send_time_delta / interruption_allowed`。（扩04）
3. MaiBot 现行：`ResponseSplitter` 默认开，最长 512 字、最多 8 句、拆 3 条，也可模型断句；打字时间 中文每字 0.3 秒、其他 0.15 秒、图片表情约 1 秒、乘 typing_speed；故意错字 1% 再发纠正（两版都不建议照搬）。（MB §5）
4. MB 对 Sumika 的建议值（Sumika 自己的建议，不是实测）：普通闲聊最多拆 2 条；每段间隔 0.3～2.4 秒（回答1）或打字等待 0.4～3 秒封顶（回答2）；前一段没发出去，后面不发。（MB §5）笔记 扩04/扩33 则明确：**时间策略要从真实群日志分布学，没找到可靠的人类分条间隔数据，模拟打字只是低强度可选**。
5. 不逐 token 发送，等完整且通过校验的短句；多条发送间检查话题是否已换；发了 reaction 就不再发同义文字。（扩33）
6. 速度：快路径 P50 ≤ 2s/P90 ≤ 5s、普通短回复 P50 ≤ 4s/P90 ≤ 8s，是建议起点；真人基准用本地 MaiBot.db 真人"引用回复"的时间差估算。（扩33；采纳清单）

### G. 黑话 / 梗的发现 → 验证 → 使用

**发现**
1. 候选：超出词表的新词、复读片段、谐音写法、常见表情包、显式"这是某某梗"解释。聚合不同说话者/不同上下文的例子，不对单次刷屏直接学。（基础03）
2. MaiBot：`learn_jargon.prompt` 要求真实出现、2～8 字、离开圈子难懂，排除人名/@/表情；一次最多 30 个候选；保存前后各最多 3 条上下文的消息 ID。主人希望 Sumika **查得比 MaiBot 勤**，且黑话来源杂（小团体自创、网络 meme、定型文、影视台词改编、影射、谐音）。（MB §3；待办）
3. 来源过滤：自己的话、`automation:*`、用她的号手动发的话不进学习素材（见第三部分"需修正"）。

**验证**
4. 多 sense 并存、本群义优先于全网义；证据 = 消息 ID + 周边对话 + 谁接梗 + 反例；独立使用者数而不是总次数。（基础03；扩30）
5. 缺知识才联网：先缓存梗卡与本群上下文；陌生词/近几天集中出现/候选解释冲突/图片身份不明才搜；搜索摘要不算独立证据；来源可信度分层；热梗缓存短。（扩17）
6. MaiBot 的推断节点 4/8/25/100 次触发重推断；三次调用（带上下文推断 → 只看词条推断 → 比较，"差异大 = 黑话"）——两版调研都说只能当信号不是验证。（MB §3）
7. 建议起步参数（Sumika 自己的）：至少 2 条独立证据、推断节点 [4, 8, 25]、黑话主动使用默认关。（MB §10）
8. 恶意教梗/刷屏改词义：记录来源，限制高风险联想；公开新梗入低置信候选，重大规范改写需独立佐证。（基础03；扩22）

**使用（三档）**
9. **理解 / 引用 / 主动使用** 三档门槛递增；被别人主动提起时降低门槛，Bot 自己主动用更保守；含义不确定宁可不用。MaiBot 现状：只注入"已确认、有含义、在当前作用域、**当前上下文里其他人实际用到**"的词，最多 10 条，作为理解参考不鼓励模仿。（MB §3；扩30；扩16）
10. 硬门：隐私、未成年/性化、明确拒绝、真实骚扰场景先挡；再看 `topical_fit / relationship_fit / shared_knowledge / novelty / payoff / timing / fatigue / confidence`。（扩30）
11. 重复疲劳：跨时间同一玩笑要变体、降频、对方说"别提"立即停；Ritual 状态机见扩27。
12. 协同玩梗：先确认谁在玩；动作 轻量跟进/变形接力/双梗融合/接反转/沉默让位。（扩20）
13. 存储借鉴 Surowan 辞典：同名多义并存、alias 冲突报告、按群作用域、revision 乐观锁、只注入上下文里有使用需求的词条、id+revision 去重、辅助模型只提融合方案由主人确认。（扩30；采纳清单）
14. 不要在系统提示里长期堆黑话解释（MB 不照搬项）。

### H. 表情与表情回应

1. 四个对象分开：face / mface / image / reaction（reaction 是对既有消息的独立动作，不创建新文本话轮）；三套 ID 空间不混；能收≠能发，升级后跑收发自检。（扩32；设计 表情与 QQ 交互）
2. 含义三级来源（主人在 Notion 表里确认 > 本群聊天学到的（带证据数）> 网上调研）与笔记 32 的"官方名/真实用法/群内学习"一致。**笔记没找到 20 条可靠案例，不要凑数。**（扩32；设计）
3. 选哪种：reaction = 关注/同意/惊讶/轻调侃，不抢话轮，快路径；文本 = 纠错/认真问答/设边界；face = 补语气（判断阴阳）；图片表情包 = 承载角色或复杂梗。严肃求助时只贴表情像敷衍。（扩32；扩06）
4. 多人给同一条贴同表情不一律算支持；学习只统计真人的反应，Bot 的点赞不算。（扩32；扩14；采纳清单）
5. 本群自学习结构 ReactionEvent + SenseRecord；同一人多次不算多个独立证据；5/10/20 条只是实验候选阈值。（扩32）
6. 发图选择：有图可发≠应该发；表情包单元含 OCR/描述/可能含义/典型动作/受众/反例；低置信、涉个人尊严、隐私、争执时优先文字或不发；不每条都跟图。（扩06）
7. 避免发了 reaction 又发同义"哈哈哈"。（扩33）
8. MaiBot 坑：表情包情绪标签混进回复又被模仿（#2069）→ 媒体元数据、模型观察文本、可发送正文严格分开。（MB §8）
9. 待办中的"㊗️"（QQ 客户端点不出来、服务器能调用的回应，谐音黑话）和"表情回应系统提示刷屏"属于这一块，笔记没有覆盖。

### I. 群体规范适配

1. 规范分类：显式规则 > 描述性模式 > 互动许可 > 话题与边界 > 变化；每条留反例；单人刷屏、Bot 自己的话不算共识；说话前检索"本场景可用规范"。（扩07）
2. 新群冷启动五阶段 + 最小群画像 JSON；回溯学习对应"观察期"。（扩15；QQ 规格十二）
3. 观众意识：话语目标、被玩笑对象、旁观者三种可见关系；新人门槛更高；Bot 不能继承群友之间的互损许可。（扩21；扩07）
4. 多 Bot：占比上限、深度上限、不联手施压、不统一站队。（扩14；扩12）
5. 偏好优先级：当前明确请求与群规 > 历史明确偏好 > 多次低风险观察 > 角色默认；明确纠正在下次相似场景立即生效，但仅针对当前话题的不覆盖全局。（基础05）
6. 学习写入信任排序；诱导测试用例。（扩22）

### J. 冲突和边界

1. 冲突分层（友好互损/事实争论/社交摩擦/恶意攻击/紧急风险）+ 行为候选；无权限不声称已处置。（扩12）
2. 对 Bot 的攻击：动作集 + "不服软不嘴赢"；防报复强化。（扩18）
3. 出错修复分级；不用同一模板；犯错者自己更正；不把道歉频率当指标；不为保人设隐瞒严重错误。（扩08）
4. 边界幽默三档（理解/接话/主动）；红线（未成年性化、对真人的未邀请性暗示、复读仇恨）。（扩16）
5. 面子管理：不当众点名纠错，除非必要；反驳 ≠ 羞辱。（扩21）
6. 在这些场合"升级到更强模型/更慎重路径"：重要道歉、敏感玩笑、价值冲突。（扩26；扩33）

### K. 弱模型辅助

1. 拆开"识别结构 / 补知识 / 选动作 / 写回复"，不把所有规则塞进单一提示词。（扩19；MultiChallenge）
2. 不依赖弱模型自报置信度；规则/元数据判断缺口。（扩23；扩19）
3. 证据卡：短摘要，带时间与出处，字段见扩19、扩17。（扩19；扩17）
4. 动作卡：小模型只在动作集里选一个再写短句；高歧义才升强模型。（扩19；扩26）
5. 缓存与降级：静态梗/本周新梗/本群特殊用法分开缓存；429/超时回退，不让搜梗阻塞直接提问。（扩19）
6. 工具能提升知识，不能保证幽默感；整体是否像群友仍需人工盲评。（扩19）
7. MB 对应：选择子代理失败时**不注入**（MaiBot 失败回退成注入全部候选是隐患）；每步（提取、审核、写库、索引、召回）记数量与失败原因；每类后台任务独立超时/token 上限/并发；OneBot 事件处理里不做重活。（MB §2、§8）

### 3. 笔记写于 10-12，之后 Sumika 新定的东西需要修正的结论

1. **消息来源 `origin`（character / automation:<插件> / human / external / owner / peer）**（规格-插件 四）：
   - 笔记里的"学习不学自己""只统计真人反应""SELF 是否真的采用行为""is_bot_self"都只有"是不是自己"两档。Sumika 的"她的号发出的话"有四种身份：**character**（她说的）、**automation**（系统替她发的）、**human**（主人用她的号手发的）、**external**（MaiBot 时期的话）。表达学习、黑话学习、行为反馈归因、记忆总结的素材过滤要按 origin 来：`character`、`automation:*` 不学；`human` 不算她说的（可当"主人替她说过什么"的事实）；`external` 单独开关。
   - 扩14 里"Bot 的反应不算真人反馈"要扩成"origin ≠ owner/peer 的反应都不算"。
   - 回环保护：`automation:*` 与 `character` 的回声不进 `message/inbound`；扩22 的"Bot 自己生成的推断"信任最低，对应 origin。
2. **四种场合**（本地私聊 / 本地群聊 / 平台私聊 / 平台群聊）：笔记几乎只写"QQ 熟人群"。需要补：
   - 设计里"在家 / 私聊 / 群聊"三场景要改成四种场合 + 平台层，并写每种场合的语言策略（本地私聊像编程助手，职业和工具说明只在这里；本地群聊主人在场、角色之间可以接话；平台私聊口语短；平台群聊旁观为主）。
   - 笔记 扩15（冷启动）、扩21（观众意识）、扩07（群规）主要对**平台群聊**有意义；本地群聊没有"新群""群规"，但有"谁在场"和"主人一插话重置"。
   - 扩23 的 `prohibited_or_unavailable_scope` 对应规格里各场合的"能看的记忆"。
3. **只追加缓存约束 + 缓存纪元**（LESSONS、规格-插件 七）：
   - 笔记 05/26 的"当前意愿 / C4 适应状态"、扩27 的"当前疲劳"、扩17/19/30 的"证据卡/梗卡召回"、扩21 的受众字段，每轮都会变，**只能追加在本轮尾部**；上一轮的尾部要当历史保留，不能下一轮删掉。
   - 因此"召回 TopK 表达 / 黑话 / 关系卡"会随轮数累积，必须依赖"纪元 + 压缩"控制长度，召回量要小（MB 建议最终 ≤ 3 条表达）。

4. **顾问（advisor）职业**（规格-插件 七点五）：
   - 笔记 扩23/18/26 说"高歧义/重要道歉/敏感玩笑升级到更强模型"，这是**闸门/路由**的升级，不是顾问。顾问是独立会话，只提意见、追加 `<advisory>` 旁注，默认沉默；**不要把顾问接到平台群聊的回复前链路里**（增加延迟，违反扩33 的快慢路径）。

## 第四部分：建议的采纳顺序（供主人参考，我没有决定）

> 只是把上面的结论按"依赖关系"排一下，并非 Sumika 已采纳。

1. 先补规则层（不调模型）：来源 origin 过滤、自己/automation 的话不进学习、被 @ 必须及时决策、回复次数与发言占比上限、发送回执与生成/送达分开记。（MB P0）
