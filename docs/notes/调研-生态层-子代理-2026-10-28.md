## 1. OpenCode v2

### 怎么派、怎么定义

这份 v2 源码的实际工具叫 **`subagent`**。迁移提示明确把旧 `task` 的 `subagent_type` 改为 `agent`，`task_id` 改为 `sessionID`。不能拿旧版 `task` 的实现当当前行为。【读码确认：O/core/src/database/v1-migration.bun.ts:1030】

参数是：

| 参数 | 含义 |
|---|---|
| `agent` | 专用代理类型 |
| `description` | 界面任务短标题 |
| `prompt` | 交给孩子的任务 |
| `model?` | 显式模型覆盖，支持 `provider/model#variant` |
| `sessionID?` | 继续以前的子会话 |
| `background?` | 后台启动后立即返回，默认前台等待 |

返回结构是 `{sessionID, status: "completed" | "running", output}`；新会话从新上下文开始，调用方要把必要材料写进 `prompt`。【读码确认：O/core/src/tool/plugin/subagent.ts:29、:50、:55】

代理可以来自配置中的 `agents`，也可以来自 `agent/`、`agents/` 下的 Markdown。Markdown 用 YAML frontmatter，正文变成 `system`；v2 字段包括 `model`、`request`、`system`、`description`、`mode`、`hidden`、`steps`、`permissions`。旧格式另走迁移解码。【读码确认：O/core/src/config/plugin/agent.ts:21、:103、:185；O/schema/src/config/agent.ts:11】

模型选择顺序是：调用覆盖 → 代理定义模型 → 父会话模型。继续已有孩子时允许切换代理，但要求该会话确实是当前父会话的直接孩子。【读码确认：O/core/src/tool/plugin/subagent.ts:164、:180、:193】

### 上下文与结果

新孩子只收到子代理说明和本次任务；这里没有复制父对话。继续调用则沿用孩子自己的会话。【读码确认：O/core/src/tool/plugin/subagent.ts:193、:215】

完成结果取最终 assistant 消息的所有文本块，空结果给固定说明；不会把全部工具过程和思考交给父代理。后台完成通过 `sessions.synthetic` 追加通知，附带孩子 ID、代理和结局元数据。【读码确认：O/core/src/session/subagent-completion.ts:8、:10、:37】

前台工具结果经过统一截断：默认 **2,000 行、50 KiB**，完整文本保存到文件，返回截断标记和文件路径。后台完成通知走 `synthetic`，不能仅凭这条工具截断路径断言它也受同一限制。【读码确认：O/core/src/tool-output.ts:13、:69；O/core/src/session/runner/step.ts:126；O/core/src/session/subagent-completion.ts:37】

### 权限与审批

父代理调用 `subagent` 本身先审批，资源是被调用的代理 ID。孩子执行工具时，权限按**孩子代理定义 + 孩子会话规则 + 项目保存授权**计算；这段实现没有把父工具清单与孩子清单做交集。因此，不能笼统说“孩子权限必定是父的子集”。【读码确认：O/core/src/tool/plugin/subagent.ts:138；O/core/src/permission.ts:154、:170】

需要询问的权限通过统一事件总线发布 `Permission.Event.Asked`，不是把审批问题变成父模型的一段文字。【读码确认：O/core/src/permission.ts:195】

默认深度 **1**：根能派孩子，孩子不能再派。检查会沿 `parentID` 向上数，`experimental.subagent_depth` 可覆盖。【读码确认：O/core/src/tool/plugin/subagent.ts:114】

### 并行、取消、错误、显示

前台等待 `jobs.block`；等待被中断时同时中断孩子会话、取消孩子 job。后台任务已交给 job 管理，完成后另发通知。**正常父回合结束与取消前台等待不是一回事。**【读码确认：O/core/src/tool/plugin/subagent.ts:230；O/core/src/session/subagent-job.ts:31】

出错、取消都作为工具失败返回，并保留 `sessionID`，便于继续同一个孩子。在该工具及 `job.ts` 的本次检查中，未找到子代理专用的并发数量默认值或整项任务超时参数。【读码确认／查找范围：O/core/src/tool/plugin/subagent.ts:244；O/core/src/job.ts；O/core/src/tool/plugin/subagent.ts:29】

孩子步骤照常发布 token、费用事件；统计层读取每条消息的模型、输入输出、缓存 token 和费用。TUI 显示代理、任务标题、运行状态、显式指定的模型和后台标记，点击进入子会话。【读码确认：O/core/src/session/stats.ts:27；O/core/test/tool-subagent.test.ts:100；O/tui/src/routes/session/index.tsx:3281】

## 2. Crush

### 怎么派、怎么定义

`agent` 工具只收一个参数：`prompt`。它不是让模型任意挑命名代理，而是调用配置里的固定 `AgentTask`；构造时生成任务提示词、建立子代理对象，执行时建立子会话。【读码确认：R/internal/agent/agent_tool.go:18、:26、:57】

默认 `task` 使用 Large 模型，工具来自父级允许工具的只读交集：`glob`、`grep`、`ls`、只读 LSP 查询、`sourcegraph`、`view`。默认 `AllowedMCP` 是空 map，即不给 MCP 工具。`AllowedMCP == nil` 与空 map 的含义不同：前者不限，后者全禁。【读码确认：R/internal/config/config.go:1084、:1129；R/internal/agent/coordinator.go:950】

在检查过的 `agent_tool.go`、`Config.SetupAgents` 和 `buildTools` 中，没有找到供这个工具使用的 Markdown 命名代理定义加载流程。【读码确认／查找范围：R/internal/agent/agent_tool.go:26；R/internal/config/config.go:1117；R/internal/agent/coordinator.go:861】

### 上下文与结果

每次调用创建任务子会话，传入独立 `Prompt`。历史读取以这个子会话 ID 为准，派遣代码没有复制父消息。父代理只拿 `result.Response.Content.Text()`。【读码确认：R/internal/agent/coordinator.go:1648、:1673、:1715；R/internal/agent/agent.go:1723】

生成出错转成 `NewTextErrorResponse`；没有文本也明确报错。`MaxOutputTokens` 取模型默认值，配置值非零时覆盖。在这个回传函数里没有看到额外的长文本截断或完整结果句柄。【读码确认：R/internal/agent/coordinator.go:1659、:1692、:1709】

### 权限、并行与取消

默认 task 不带 `agent` 工具，所以不能递归派遣；它靠默认工具集合限制递归，并非这里有数值深度检查。`buildTools` 只在允许列表包含 `agent` 时才添加该工具。【读码确认：R/internal/config/config.go:1084、:1129；R/internal/agent/coordinator.go:863】

工具构造使用共享 `c.permissions`，没有在普通 task 派遣处复制父会话的一次性授权。权限服务按 `SessionID + ToolName + Action + Path` 记会话授权；需要审批时统一发请求。子代理不执行用户的内部工具 hooks，顶层 `agent` 调用仍可经过 hook。【读码确认：R/internal/agent/coordinator.go:950、:977；R/internal/permission/permission.go:95、:161、:180】

`agent` 用 `NewParallelAgentTool` 声明可并行；孩子 `Run` 直接使用工具传下来的 `ctx`，因此取消信号会传入孩子。但在这些派遣与运行函数中未找到专用并发上限、任务总时限。【读码确认：R/internal/agent/agent_tool.go:40；R/internal/agent/coordinator.go:1675】

### 记账与显示

孩子有独立会话；完成后读取孩子费用，加到父会话再保存。费用更新失败只记警告，不丢掉已经生成的回答。这里是读父费用后加回的写法，**本次没有证明并发累加是原子的**。【读码确认：R/internal/agent/coordinator.go:1697、:1723】

UI 能根据父消息 ID 和工具调用 ID 找到任务子会话，读取内部消息；聊天工具卡也单独识别 `agent`。【读码确认：R/internal/ui/model/ui.go:1781；R/internal/ui/chat/tools.go:261】

## 3. Codex CLI

### 先区分 V1 与 V2

本机源码同时有两套多代理行为。**V1 默认不复制父历史、默认深度 1；V2 默认全历史 fork，并忽略 V1 的 `agent_max_depth`。** 两套不能混成一个结论。【读码确认：C/core/src/tools/handlers/multi_agents/spawn.rs:231；C/core/src/tools/handlers/multi_agents_v2/spawn.rs:213；C/core/src/config/mod.rs:986；C/core/src/tools/handlers/multi_agents_tests.rs:2487】

### 怎么派、怎么定义

| 项目 | V1 | V2 |
|---|---|---|
| 创建参数 | `message` 或 `items`、`agent_type?`、`model?`、`reasoning_effort?`、`fork_context?` | `message`、`task_name`、`agent_type?`、`model?`、`reasoning_effort?`、`fork_turns?` |
| 上下文默认 | `fork_context=false` | `fork_turns` 省略按 `all` |
| 创建返回 | `agent_id`、可选 nickname | `task_name`，可选 nickname |
| 后续控制 | 等待、发输入、恢复、关闭 | 发消息、列代理、中断、等邮箱活动 |

【读码确认：C/core/src/tools/handlers/multi_agents/spawn.rs:225；C/core/src/tools/handlers/multi_agents_v2/spawn.rs:201；C/core/src/tools/handlers/multi_agents_v2.rs:1；C/core/src/tools/handlers/multi_agents.rs:1】

V2 的 `fork_turns` 接受 `none`、`all`；兼容正整数，但整数也映射到全历史，并不是只取最近 N 轮。V2 明确拒绝旧 `fork_context` 参数。【读码确认：C/core/src/tools/handlers/multi_agents_v2/spawn.rs:213】

角色定义用 TOML。角色声明含 `description`、`config_file`、`nickname_candidates`；角色文件可有 `name`、`description`，以及模型、推理档、`developer_instructions` 等配置。加载后只应用受限字段，不能把任意 ConfigToml 选项原样当成孩子的权力。【读码确认：C/agent-roles/src/agent_role_config.rs:9、:22、:37；C/core/src/agent/role.rs:36、:77】

### 权限与审批

子配置从父**调用这一步的有效设置**构造，不单纯克隆建会话时的旧配置；运行时审批策略、权限配置和 cwd 最后再覆盖回去，防止角色配置改大权限。【读码确认：C/core/src/agent/child_config.rs:104、:178】

角色只允许关闭一组能力，如 Shell、Apps、Plugins、Memory、RequestPermissions；skills 配置也只保留禁用项。没有在这里看到可随意扩大工具清单的规则。【读码确认：C/core/src/agent/role.rs:91、:105】

子代理审批可以到用户 UI。TUI 对未认识的子线程读取其来源，检查父线程归属，避免把别的根会话的审批混进当前窗口。【读码确认：C/tui/src/app/app_server_events.rs:802；C/tui/src/app/tests/startup.rs:1598】

### 并行、深度与取消

V1 默认最多 **6** 个子线程、深度 **1**。V2 默认总并发配置 **4**，有效非根子代理容量由它减 1，默认相当于 **3 个孩子名额**；V2 另有活动执行许可，不能只引用旧的 `max_threads=6`。【读码确认：C/core/src/config/mod.rs:260、:1702；C/core/src/agent/control/execution.rs:39；C/core/src/agent/control/execution_tests.rs:18】

V2 的执行许可从根初始化，孩子不能重设上限。名额释放靠 guard 的生命周期。【读码确认：C/core/src/agent/control/execution_tests.rs:18】

等待超时是**本次等待**的超时，不是孩子任务的总时限。V2 默认等 30 秒，默认最短 10 秒、最长 1 小时；收到邮箱或插话也能唤醒。【读码确认：C/core/src/config/mod.rs:262；C/core/src/tools/handlers/multi_agents_v2/wait.rs:53、:96】

单代理中断与整树关闭分开。中断当前任务不等于关闭所有后代；`shutdown_agent_tree` 才遍历活后代关闭，runtime 关闭另有统一取消 token 和收尾追踪。【读码确认：C/core/src/agent/control/interrupt.rs:14；C/core/src/agent/control/legacy.rs:110；C/core/src/agent/control/runtime.rs:301】

### 结果、错误和记账

V1 等待返回 `{status, timed_out}`，状态可携带最后回答。V2 的 `wait_agent` 只返回等到活动还是超时，结果通过代理间消息另送；终局回传不要求复制孩子过程。【读码确认：C/core/src/tools/handlers/multi_agents/wait.rs:294；C/core/src/tools/handlers/multi_agents_v2/wait.rs:144；C/core/src/agent/control/completion.rs:26】

每个线程有自己的 token 记录；另把实际消耗记进共享 rollout budget。创建和完成还发 `SubAgentActivityItem`，记录孩子路径、模型和状态。【读码确认：C/core/src/session/mod.rs:1587；C/core/src/session/rollout_budget.rs:34；C/core/src/agent/control/budget.rs:12；C/core/src/tools/handlers/multi_agents_v2/spawn.rs:158；C/core/src/agent/control/completion.rs:74】

## 4. omp

### 怎么派、怎么定义

当前默认是批量 `task`：

```text
{ context, tasks: [{ name?, agent, task, solutionSpace, ... }] }
```

可选字段随设置变化，包括 `isolated`、`outputSchema`、`schemaMode`、`tools`、`effort`。关闭 batch 后使用单任务形状。默认 batch 开、结构化结果关。【读码确认：M/src/task/types.ts:48、:70、:103；M/src/task/settings.ts:242、:255】

代理定义是 Markdown + YAML frontmatter。字段包括 `name`、`description`、`tools`、`spawns`、`model`、`thinkingLevel`、`output`、`blocking`、`structured`、自动加载 skills 等。【读码确认：M/src/task/agents.ts:22、:108；M/src/task/types.ts:270】

发现顺序覆盖 bundled：项目 `.omp/agents`、用户目录、扩展和插件代理等。跨工具格式不一概视为同一种：Claude 插件方言的 model 选择器可能被丢弃，避免误当 omp 模型模式。【读码确认：M/src/task/discovery.ts:76、:99、:139、:164】

### 上下文、权限与结果

尽管函数名是 `runSubprocess`，当前普通任务实际通过 `createAgentSession` 创建**进程内会话**。它传入独立任务上下文、代理提示词和所需资源，没有直接把父消息列表传进新会话。还显式 `excludeAgentsMd: true`，不能假设孩子自己重读父项目的 AGENTS.md。【读码确认：M/src/task/executor.ts:4664、:4700、:4770】

孩子工具由代理定义和受限运行模式决定；普通模式不是自动与父工具清单做严格交集。受限模式会关闭 MCP、扩展路径等；未受限运行可继承 MCP manager 和扩展资源。【读码确认：M/src/task/executor.ts:4289、:4664；M/src/task/structured-subagent.ts:589、:639】

`task` 本身声明为执行类审批；孩子无 UI，设置 `tools.approvalMode="yolo"`，注释明确说父 task 审批是授权边界，同时用户工具审批策略仍适用。**这不能直接拿来满足 Sumika 的 QQ 执行规则。**【读码确认／推断：M/src/task/index.ts:587；M/src/task/executor.ts:1181；S/docs/决策记录.md:744】

默认结果取最终消息；打开结构化结果后使用 `yield`，按调用、代理或会话 schema 校验。父模型收到状态、正文或预览和 `agent://<id>` 句柄，不需要接收全部过程。【读码确认：M/src/task/settings.ts:255；M/src/task/structured-subagent.ts:242；M/src/task/result-summary.ts:56】

结果有两层限制：执行层默认 **500,000 字节、5,000 行**尾部截断；交给父模型的摘要层，对过长结果改给约 5,000 字符的头部预览和可读句柄。两层不能混称为一个输出限制。【读码确认：M/src/task/types.ts:28；M/src/task/executor.ts:2866；M/src/task/result-summary.ts:24、:42、:102】

### 并行、取消与超时

默认 `task.maxConcurrency=32`、递归深度 **2**、任务硬时限 **0，即关闭**。默认软请求预算 200，执行代码还给 scout、sonic 等内置代理较低上限。【读码确认：M/src/task/settings.ts:294、:330、:349、:396；M/src/task/executor.ts:169】

并发由 task 工具的**会话级 semaphore**控制，同一会话的多次 task 调用共享；不能据此断言整棵嵌套树最多只有 32 个孩子。【读码确认／边界：M/src/task/index.ts:662、:895、:1582】

是否后台运行按每项代理的 `blocking` 决定：非 blocking 项在 async manager 可用时成为独立 job；blocking 项留在父工具里等待。同步项绑定父信号，异步项绑定 job 信号，因此父工具结束不等于后台 job 取消。【读码确认：M/src/task/index.ts:1019、:1409、:1460、:1607；M/src/task/spawn-run.ts:105】

运行时限到达会走正常子代理 abort；取消后的清理有独立宽限期。`SpawnRun` 在最终收尾中释放并发许可。【读码确认：M/src/task/executor.ts:166、:1553；M/src/task/spawn-run.ts:74】

### 记账与显示

每个孩子记录输入、输出、缓存、费用、请求数和工具进度；同步聚合结果汇总用量，异步进度也更新费用和当前工具。观察总线沿根任务传递，避免混入别的根会话。【读码确认：M/src/task/index.ts:92、:418、:1435；M/src/task/executor.ts:4712】

## 5. pi

### 范围：这里查到的是官方随包示例

可读实现位于 `examples/extensions/subagent`，它是扩展示例，不能把它的默认值写成 pi 内核所有部署的保证。【读码确认：P/examples/extensions/subagent/index.ts:1；P/package.json:23】

支持三种互斥模式：

- 单任务：`agent + task`。
- 并行：`tasks[]`。
- 顺序链：`chain[]`，用 `{previous}` 代入上一步结果。

另有 `cwd`、`agentScope`、`confirmProjectAgents`。默认只找用户代理，项目代理需要显式纳入；非信任项目在有 UI 时可弹确认。【读码确认：P/examples/extensions/subagent/index.ts:438、:454、:510】

代理文件是 Markdown + YAML：`name`、`description` 必需，`tools` 可写逗号串或数组，`model` 可选，正文为系统提示词。`both` 模式项目同名覆盖用户定义。【读码确认：P/examples/extensions/subagent/agents.ts:25、:43、:92、:123】

### 进程、上下文、权限

每次启动独立 pi 进程，使用 `--mode json -p --no-session`，传模型、工具名和追加提示词文件；任务以 `Task: ...` 传入，没有传父对话。【读码确认：P/examples/extensions/subagent/index.ts:307、:340、:350】

这是进程隔离，不是权限继承证明。代码把代理定义的 `tools` 交给 CLI，没有与父工具清单做交集；普通执行路径中也没找到父审批服务转发、数值深度限制。项目代理确认只是信任提示，不能代替运行时工具授权。【读码确认／查找范围：P/examples/extensions/subagent/index.ts:307、:438、:510】

### 并行、结果、取消和用量

单批最多 **8** 个并行任务，实际并发 **4**；不同批次是否共享总上限，这个局部执行器没有提供保证。顺序链失败会停在当前项。【读码确认：P/examples/extensions/subagent/index.ts:34、:213、:586、:608】

父结果取最后一个 assistant 消息里的第一个文本块。并行返回每项成功或失败摘要，每项最多 **50 KiB**，完整消息保留在 tool details；单项和链最终结果在这些返回分支没有同样的截断。【读码确认：P/examples/extensions/subagent/index.ts:163、:184、:599、:676、:714】

取消时调用 `SIGTERM`，5 秒后按 `proc.killed` 判断是否发 `SIGKILL`。这段代码没有给出 Windows 子孙进程全部结束的保证，也没有任务总超时。【读码确认／推断：P/examples/extensions/subagent/index.ts:415】

JSON 事件累加每个 assistant 步骤的 token、缓存、费用和轮数；TUI 从这些 details 渲染用量和工具活动。【读码确认：P/examples/extensions/subagent/index.ts:47、:369、:734】

## 6. DeepSeek harness

### 怎么派、怎么定义

它把委派拆成工具、管理服务和后端 provider：

- `tool-subagent`：模型可见参数、模型与 preset 选择。
- `subagent`：孩子身份、容量、消息、生命周期。
- `subagent-spawn-in-process`：新上下文。
- `subagent-fork-in-process`：继承完成轮次。
- 另有 SDK、ACP 等外部后端。

这些能力由编排配置挂载，不是所有 provider 自动具有同样能力。【读码确认：D/tool-subagent/src/index.ts:49、:157；D/subagent/src/index.ts:193；D/subagent-spawn-in-process/src/index.ts:38；D/subagent-fork-in-process/src/index.ts:61】

模型参数必需 `description`、`prompt`，可选 `cwd`、受允许的 `agent_preset`；模型路由参数只有启用相应能力时才出现。工具立即返回 `{kind:"activation", subagentId}`。【读码确认：D/tool-subagent/src/index.ts:213、:221、:265、:340】

代理配置使用 preset 和 `agentOptions`：provider、model、reasoningEffort、maxTokens；可限制 `allowedAgentPresets`。这与 omp/pi 的代理 Markdown 文件不是同一个格式。【读码确认：D/tool-subagent/src/index.ts:51、:80】

### 上下文与回传

spawn 明确从零父历史开始。fork 复制父日志到最后一个 `turn/end`，**排除正在调用委派工具的当前轮**；前缀创建时只取一次，冷恢复不重新 fork 父亲的新历史。【读码确认：D/subagent-spawn-in-process/src/index.ts:45；D/subagent-fork-in-process/src/index.ts:46、:78】

可继续的孩子通过 `send_message` 向直接父亲报告；完成时运行时还会补终局通知。当前实现的终局通知也包含 closing text、可选 structured 结果和诊断，因此不能说“父只收到一个完成标志”。【读码确认：D/subagent/src/continuation-messages.ts:80、:143】

最终输出取最后一条非空 assistant 消息；空的 usage-only 消息不会覆盖前文，没有完整消息时才退回累计文本流。【读码确认：D/subagent/src/assistant-output.ts:32、:55】

在检查过的 `continuation-messages.ts`、`assistant-output.ts`、工具和 manager 中未找到成功结果的统一字节截断。外部 provider 诊断单独限制 **4,096 字节**，按 UTF-8 边界截。【读码确认／查找范围：D/subagent/src/continuation-messages.ts:143；D/subagent/src/assistant-output.ts:55；D/subagent/src/out-of-process.ts:19】

### 权限与审批

进程内派遣在第一次异步操作前捕获父权限状态；孩子固定 `approvalPolicy="never"`。继承父显式 sandbox override 和特定权限 preset，**不继承一次性授权**。需要再审批的操作直接拒绝，不挂起等待用户。【读码确认：D/subagent/src/child-agent.ts:232、:251】

孩子可用不同 preset 和历史 toolFilter；这段共享实现不是简单的父工具名交集。它强制的是委派权限快照和审批不可升级，工具组成还受 preset 约束。【读码确认：D/subagent/src/child-agent.ts:157、:188、:217】

provider 声明是否支持深度、模型选项、preset、输出 schema；要求它不支持的能力会在派遣前报错。数值深度限制不是偷偷忽略后继续跑。【读码确认：D/tool-subagent/src/index.ts:165；D/subagent/src/out-of-process.ts:50】

### 并行、取消与生命周期

默认深度 **1**，每棵 activation 树默认 **8** 个活孩子。创建中的、等待中的、停止收尾中的孩子都占位；同根的兄弟、后代和不同 provider 共享名额，根本身不占。【读码确认：D/subagent/src/index.ts:186；D/subagent/src/manager.ts:740；D/subagent/src/activation.ts:15】

容量满时立即拒绝，不排队。文档给出的理由是：父代理本身等待后代时，不能再因自己占着的槽形成死锁。【读码确认：D/subagent/src/activation.ts:24；读文档：D/subagent/README.md:51】

启动调用的取消信号负责接收前回滚；已受理后由 manager 管理。中断孩子当前执行会保留尚未领取的 inbox、activation 和后代；`drainDescendants` 才关闭树并按孩子先于父亲的顺序释放。【读码确认：D/subagent/src/manager.ts:418、:650、:1100；D/subagent/src/index.ts:345、:367】

生命周期区分完成、被停、token 用尽、拒绝和错误，不能以“资源释放成功”当成任务完成。子结果归属直接父亲，发送和恢复要求确切的活父身份；结局通知根据父当前状态排队或插话。【读码确认：D/subagent/src/lifecycle.ts:125；D/subagent/src/manager.ts:543、:1187】

### 记账与显示

孩子日志记录自身执行，另有身份、catalog、活动时长投影；生命周期携带独立 `runId` 和孩子最终内容。这里不能据此宣称已经把孩子 token、费用可靠合并到父账单。【读码确认／边界：D/subagent/src/lifecycle.ts:96；D/subagent/src/projection-types.ts:10、:21、:76】

UI 有子会话导航和活动分类；父工具活动计数只算父实际发生的委派，不自动把孩子内部全部工具算进父工具组。【读码确认：`_external/deepseek-harness/packages/client/ui-conversation/src/client/skeleton/ConversationSession.tsx:81`；同仓 `packages/client/ui-chat/src/client/conversation-nodes/README.md:279`】

### Sumika 的验收建议

以下是建议用例，不是本次新增或执行的测试。

1. **检查完整模型请求与工具表，不只看回复。** 在后台造只有主人能看的独特事实；主人任务完成后切群友、夹压缩、实例回收、恢复，群友请求中都不得出现该事实或高权限结果。【推断／建议；依据：S/docs/规格-Go后台.md:350、:377】

4. **结果隔离检查句柄。** 公开孩子不能读私有孩子的结果 ID；猜中 ID、旧 ID、同父不同 Scope、其他群和其他角色都要拒绝。错误文字、来源标题、路径也算泄漏面。【推断／建议；依据：O/core/test/tool-subagent.test.ts:576；D/subagent/src/manager.ts:543；S/docs/规格-Go后台.md:377】

## 9. 给 Sumika Go 的具体建议

### 9.1 复用同一个 Hub，但增加真正的子任务运行入口

**同一 `Hub`，独立子会话和实例；不要每个孩子 `NewHub`。** 当前 `NewHub` 会执行 `SweepInterrupted`，源码要求进程只建一个。对子任务再构造 Hub，可能把当前进程的在跑记录误判成遗留任务。【读码确认／推断：S/native/internal/turn/hub.go:161】

也不能直接把新的 `Scope` 塞进父会话当孩子：回合队列按 `角色 + Conversation` 串行，孩子沿用父 Conversation 会排在等它的父回合后面。应给孩子独立内部会话 ID，并登记内部存储归属。【读码确认／推断：S/native/internal/turn/hub.go:213、:259、:185】

建议增加内核入口，示意为：

```go
StartChild(ctx context.Context, spec ChildSpec) (ChildHandle, error)
CancelTree(taskID string)
DeliverTaskResult(resultID string) error
```

`ChildSpec` 由可信的任务管理器构造，包含：

| 字段 | 用途 |
|---|---|
| `TaskID / ParentTaskID / RootTaskID` | 任务树和去重 |
| `ParentTurnID / ParentInstanceID / ToolCallID` | 精确回到哪次调用 |
| `CharacterID / DefinitionSnapshot` | 角色、模型、提示词、工具定义快照 |
| `Authority` | 原始派活人、来源和后台授权上限 |
| `ReturnAudience / ReturnScope` | 结果允许回给谁 |
| `Prompt / ContextRefs` | 明确交给孩子的材料 |
| `Depth / Deadline / Budget` | 递归、时限、用量 |

【推断／建议；依据：D/subagent/src/manager.ts:379、:740；C/core/src/agent/child_config.rs:104；S/native/internal/turn/hub.go:125】

当前 `Respond(Input)` 没有父任务、每孩子模型和定义覆盖，也没有传入 ctx；内部从 `h.base` 建回合 ctx。实现时应扩展内部运行描述，复用模型循环、工具门、压缩、trace，而不是临时改全局 `Hub.Cfg` 或假装一个普通 QQ 发言。【读码确认／推断：S/native/internal/turn/hub.go:125、:505、:582、:927】

后台输出应保存在内部任务记录；不要当成角色在 QQ 说过的话发 `OnSeen`、写公开聊天或直接交渠道发送。现有 `local()` 仅按 `Channel=="console"` 判断，因此需要明确的内部运行种类，不能靠伪造渠道绕过。【读码确认／推断：S/native/internal/turn/hub.go:153、:1459；S/native/internal/turn/plugin.go:79】

### 9.2 用“委派授权”推权限，不能只看父工具表

QQ 前台可能只有 `task`，后台却要能搜索。因此孩子工具不一定是**父模型可见工具名**的子集；它必须是**原派活人拥有的后台授权集合**的子集：

```text
孩子可执行能力
= 原派活人的后台授权上限
∩ 代理定义所需能力
∩ 当前渠道允许能力
∩ 任务自己的收窄限制
```

模型可要求收窄，不能提供身份、渠道、`PrivateOK`、批准状态或提高上限。【推断／建议；依据：S/docs/决策记录.md:744；C/core/src/agent/role.rs:91；D/subagent/src/child-agent.ts:251】

具体默认：

| 原始来源 | 后台默认能力 | 结果上限 |
|---|---|---|
| 群友在群里 | 搜索、公开网页 | 原群可见 |
| 主人在群里 | 搜索、公开网页；私有能力仍按独立授权 | 不能把“主人问了”扩大成全群可见私有结果 |
| 主人在 QQ 私聊 | 搜索、公开网页；MCP/skill 仅 QQ 白名单 | 主人私聊 |
| 主人在本地主窗口 | 按本地授权与代理定义取交集 | 本地私有 |
| QQ 的本地执行特例 | 默认关闭；主人专门打开后，每次电脑审批 | 指定私有目的地 |

前四行是建议的具体落法；QQ 禁本地执行、MCP/skill 默认无 QQ 授权、特例每次电脑审批来自既定 ADR。【读文档／推断：S/docs/决策记录.md:744】

**MCP 和 skill 都不能因“后台能用”而获得额外权力。** MCP 工具逐项过 capability gate；skill 是指令材料，执行效果仍由工具门限制。【推断／建议；依据：S/docs/决策记录.md:748；S/native/internal/turn/plugin.go:87；S/native/internal/policy/policy.go:374】

现有 `Audience` 有 `PersonIDs`、`PrivateOK`、`OwnerAsked`，但执行门只投影 Channel 和 PrivateOK。子任务需要另有可信 `Authority`，不能把 `OwnerAsked=true` 当成“主人本地主窗口”。【读码确认／建议：S/native/internal/audience/audience.go:8；S/native/internal/turn/hub.go:156】

### 9.3 任务工具保持简单，权限参数不交给模型

建议模型可见创建参数：

```text
task({
  agent,
  description,
  prompt
})
```

同一消息的多次调用即可并行，不先加入 chain、任意模型覆盖、任意 cwd、自由 tools、fork 全历史等参数。需要继续孩子时用受控 `task_message(task_id, message)`；取消用 `task_cancel(task_id)`。【推断／建议；依据：R/internal/agent/agent_tool.go:18；O/core/src/tool/plugin/subagent.ts:29；D/tool-subagent/src/index.ts:213】

创建立即返回 `{task_id, status:"running"}`；完成后可靠追加一个结果。前台无需反复轮询。同步内部调用可以等待同一个 handle，不另建第二套执行路径。【推断／建议；依据：D/tool-subagent/src/index.ts:265；O/core/src/session/subagent-completion.ts:37】

`task` 必须在 `policy.Specs` 正式登记。不能把它仅标成无害 `self` 就放任后台任意执行；它的执行函数应先建立委派授权，孩子每次工具调用再过内核门。创建工具时限与孩子任务时限分开。【推断／建议；依据：S/native/internal/policy/policy.go:17、:64；S/native/internal/turn/loop.go:701】

### 9.4 上下文按结果听众准备，默认不 fork

QQ 公开任务只给公开任务文本和公开引用，不给主人私有记忆、角色私下段落、父工具结果或审批内容。即使任务由主人发起，只要结果预定回群，默认仍按群可见集合准备孩子上下文。【推断／建议；依据：S/docs/规格-Go后台.md:350；D/subagent-fork-in-process/src/index.ts:46】

本地主窗口需要额外材料时，前台明确整理 `ContextRefs`；后续真有需求再开放“同权限档、完成轮次”的 fork，不能直接复制正在执行的父轮工具调用。【推断／建议；依据：D/subagent-fork-in-process/src/index.ts:46；C/core/src/tools/handlers/multi_agents_v2/spawn.rs:213】

每个孩子的模型、工具 schema、定义提示词在创建时固定。参考信息、插话、结果只在末尾追加。授权变化要建立新权限档或取消重建，不回头洗写已有请求前缀。【推断／建议；依据：S/docs/规格-Go后台.md:342、:350；S/native/internal/turn/hub.go:950】

### 9.5 审批卡显示原始派活人和任务链

现有 `approval.Request` 有角色、工具、目的、预览，但没有任务来源链。建议增加可信结构字段：

```text
root_task_id, task_id, parent_turn_id
requested_by
origin_channel, origin_conversation
agent_name, task_description
return_audience
```

卡片示例：

> 主人 · QQ 私聊 → 后台 worker  
> 任务：更新项目配置  
> 请求：修改 `D:\...\config.json`  
> 结果回：主人 QQ 私聊

【读码确认／推断：S/native/internal/approval/approval.go:28；C/tui/src/app/app_server_events.rs:802】

本地主窗口孩子继续走现有审批门。QQ 默认不提供执行类工具；将来启用 ADR 的特例时，必须在 policy 层增加明确授权通道，逐次审批，不能把孩子 `Audience.Channel` 改成 `console`。审批只能批准当前操作，不能把整棵任务树改成 yolo。【推断／建议；依据：S/docs/决策记录.md:747；S/native/internal/policy/policy.go:374；M/src/task/executor.ts:1181】

“这个对话允许”的授权应绑定原授权域、派活人、渠道、权限档和操作类别，不能直接用每次随机孩子 Conversation，也不能把整个 QQ 群当共享授权域。【推断／建议；依据：S/native/internal/approval/approval.go:47、:125；R/internal/permission/permission.go:95】

### 9.6 并发、深度、时限与预算默认值

建议初始配置如下，均需通过实际任务测量再调整：

| 参数 | 建议默认 | 理由 |
|---|---:|---|
| `maxDepth` | **1**，根深度 0 | OpenCode、DeepSeek 默认一致；QQ 前后台不需要孙代理 |
| `maxActivePerRoot` | **4 个孩子** | 足够并行检索，低于 omp 的会话 32 |
| `maxActiveGlobal` | **8 个孩子** | 多角色、多群共用进程，控制本机与 API 压力 |
| `maxActivePerRequester` | **2** | 避免单个群友占满全局容量 |
| 容量满 | **立即 `busy`** | 不让等待后代的任务占槽排队形成死锁 |
| 公开检索总时限 | **120 秒** | QQ 前台需要有界等待 |
| 本地工作总时限 | **15 分钟** | 与交互检索分开 |
| 公开检索模型步骤 | **32** | 控制循环与费用 |
| 本地模型步骤 | **64** | 给多步工作余量 |
| 初次内联结果 | **16 KiB，且不超过 4,000 个估算 token** | 两个上限先到者截；保留完整受控结果 |

【推断／建议；依据：O/core/src/tool/plugin/subagent.ts:129；D/subagent/src/index.ts:186；D/subagent/src/activation.ts:24；M/src/task/settings.ts:294、:349；P/examples/extensions/subagent/index.ts:34】

并发与预算按**整棵根树**共享，创建中先预留，失败释放，停止清理完才归还。满额失败不能让模型无间隔反复重派；回包给明确状态即可。【推断／建议；依据：D/subagent/src/manager.ts:740；D/subagent/src/activation.ts:41】

token/费用上限要预留并发请求可能产生的支出，已取消但实际发生的用量也算。金额默认不在本次定死：不同模型价格不同，现有 ADR 也只确定“要有上限”。【推断／建议；依据：C/core/src/agent/control/budget.rs:12；S/docs/决策记录.md:749】

### 9.7 明确“父回合结束”与“取消任务树”

孩子从父工具成功受理后，可以活过父回合正常结束；否则 QQ 前台说完“我去查”就会取消后台。用户停止该任务、会话重启、角色关闭或插件停用时，则显式取消相应任务树。【推断／建议；依据：O/core/src/tool/plugin/subagent.ts:230；D/subagent/src/index.ts:367；S/native/internal/turn/plugin.go:466】

不要直接长期持有 `Tool.Exec` 的 ctx：它受当次工具时限与插件生命周期控制；需要完成受理后转交任务管理器，同时保留取消树和插件关闭的关联。受理前取消必须回滚。【推断／建议；依据：S/native/internal/turn/plugin.go:91；S/native/internal/turn/loop.go:708；D/subagent/tests/continuation.spec.ts:650】

现有 `Hub.StopIn` 只停当前会话，后台是另一个会话，必须补任务树联动。取消后允许保留已发生的副作用和部分结果，但终局标成 cancelled/partial，不能假装回滚。【读码确认／建议：S/native/internal/turn/hub.go:369；S/native/internal/turn/loop.go:701】

Windows 继续复用现有命令工具的进程收拾能力；若未来真接外部子代理进程，另外验证 Job Object 或整树结束，不能复制 pi 示例的两个 signal 就算做完。【推断／建议；依据：P/examples/extensions/subagent/index.ts:415】

### 9.8 结果必须绑定原权限档，句柄本身也要鉴权

建议结果封套：

```text
task_id, result_id, parent_task_id
status: completed | partial | failed | cancelled | timed_out
text, sources[], truncated
usage, steps, duration
return_scope, return_audience, authority_version
```

状态、身份和用量由运行时填；正文和来源由孩子产生。部分正文与故障原因分字段，不能让“有字”变成“完成”。【推断／建议；依据：M/src/task/result-summary.ts:56；D/subagent/src/lifecycle.ts:125；O/core/src/session/subagent-completion.ts:37】

**不能把结果仅按 Conversation 调 `SteerIn`。** 目前 `SteerIn` 找的是这个会话正在跑的实例，没有传原 Scope。若主人后台结果返回时，正在说话的是群友档，就会送错。【读码确认／推断：S/native/internal/turn/hub.go:351、:239；S/docs/规格-Go后台.md:350】

任务管理器应将结果追加到绑定的父实例／权限档邮箱；原实例已回收时，仅用相同权限重建；找不到安全目的地就留本地待处理。禁止降级塞入另一个档，也禁止结果回来时自动把听众改成“现在群里的人”。【推断／建议；依据：D/subagent/src/manager.ts:1187；S/native/internal/turn/hub.go:215】

防漏应从**孩子输入**开始：公开任务没有机会读私有材料；高权限孩子产生的整个结果按高权限处理。不能让孩子自行写一句 `public: true`，就把私有结果降级发群。截断、概括和来源标题也不改变权限级别。【推断／建议；依据：S/docs/规格-Go后台.md:350、:377；S/docs/决策记录.md:745】

前台拿到结果后生成对外话语，仍走既定渠道裁决、改写、守卫、入库和 `Commit` 流程。后台结果、错误、日志、思考不能直接绕到 QQ 发送端。【推断／建议；依据：S/docs/规格-Go后台.md:344、:354；S/native/internal/turn/hub.go:763】

大结果保存后，`task_result` 读取必须同时校验角色、根任务、权限档和听众。公开孩子不得获得通用本地 `read` 作为读取结果的补救工具；可给只认受控结果 ID 的专用读取接口。【推断／建议；依据：M/src/task/result-summary.ts:102；O/core/src/tool-output.ts:89；S/native/internal/turn/plugin.go:294】

### 9.9 记账、界面和恢复

孩子继续复用 model_runs、工具步骤和审批记录，增加 `root_task_id / parent_task_id / requester` 归属。父汇总按孩子实际用量去重聚合，避免“读取父总数、加孩子、写回”在并发时丢账。【推断／建议；依据：R/internal/agent/coordinator.go:1723；C/core/src/agent/control/budget.rs:12】

本地主窗口显示任务树：谁派的、从哪来、代理、状态、当前工具、步骤、用量、耗时、审批等待和取消。QQ 只见适合该听众的进度和最终回答，不见本地路径、审批预览、原始错误或思考。【推断／建议；依据：O/tui/src/routes/session/index.tsx:3281；M/src/task/index.ts:1435；S/docs/规格-Go后台.md:344】

任务受理、终局和结果交付都应有持久化 ID；交付重放按结果 ID 去重。进程重启后未收尾任务标 interrupted/unknown，不自动重跑有副作用的工具；恢复时重新校验权限，不能恢复旧的一次性批准。【推断／建议；依据：O/core/test/tool-subagent.test.ts:211；S/native/internal/turn/hub.go:161；D/subagent/src/child-agent.ts:242】
