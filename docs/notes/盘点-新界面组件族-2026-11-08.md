## 一、先说结论

1. **统一的组件包其实已经在 proto-port 上长出来了**，不用从零起名：`P: internal/winshell/kit.go`（`Kit.Button` 69、`IconButton` 89、`TextField` 103、`Avatar` 111、`Segment` 137）、`settings.go`（`Row` 146、`Switch` 161、`Slider` 186、`SliderRow` 208、`Dropdown` 262）、`dialog.go`（`Dialog` 14、`Check` 31），全部从同一份 `Geometry`、`Palette` 取值，并带 `Surface` 测试挂钩（登记每块表面的圆角和内距，几何测试用）。`P*: legacy_choice.go` 已经是“新界面走 kit、旧界面走旧库”的桥。所以建议不是“新建一个包重写”，而是**把 `winshell.Kit` 的控件层拆出来、补齐缺的族、堵死绕过它的路**（第四节）。要动 proto-port 的文件，必须和那条线协调。
2. 新界面范围里一共数出 **32 族**，**31 族不止一种实现**，只有滚动条（F25）是一种；另有三处是整族或族内变体根本没有，都是缺口：toast（0 个）、危险按钮变体、延迟显示的加载占位。汇总表见 1.1。
3. 乱的根不是“没有组件”，而是**三层叠着**：新界面自己的两套令牌词汇（`chatui.Tokens` 的 `S1/RCtl/HSm/FS[]` 和 `winshell.Geometry` 的 `SpaceTight/RadiusControl/HitSmall/LabelSize`，各自推导一遍）、旧主题（MewTypeUI 的 `c.Theme().Space(n)/Rem(x)`）、CrychicUI 的页面级组件（记忆、运行、设置、状态四页几乎全是它）。页面在新外壳里只是“重新应用了旧主题”。
4. 主人看到的几条现象，能在代码里找到的原因：
   - **状态码原样露出**：`internal/chatui/blocks.go:380-410` 的 `forwardBlock` 直接 `meta += " · " + f.State`，`f.State` 是 `fetching`、`too_large`、`not_receiving` 这样的内部码；旧界面 `forward.go:218` 的 `forwardStateText` 有一张映射表，新界面没接。另外 `internal/segview/blocks.go:122` 的 `ImageNote` 又是一张图片状态映射表。两张表互不知道对方。`[读码]`
   - **弹窗一闪**：`chatviewer.go:42-47` 图还没准备好时先开 `ui.Modal` 写一行“正在准备图片”，图好了再换成真的看大图。`[读码]`（`fix/image-bubble` 工作区正在改这个文件，别在这里动。）
   - **骨架屏一闪**：记忆页 `memoryview.go:323、426、517` 和运行页 `runpage_view.go:95` 一进 `loading` 阶段就立刻画 `feedback.SkeletonList`，没有延迟显示，也没有最短显示时间。后端回得快就一闪而过。`[读码]`
   - **选中块飞出去**：proto-port 工作区有个未跟踪的 `zz_seg_scroll_test.go`，专门量 **CrychicUI 的 `choice.Segments`** 放在滚动区里时选中块相对轨道的位置，说明那条线已经把问题定位在旧库的分段上。字号选择 `textsize.go:102` 和“带哪些媒体”`settings.go:373` 都是它，都在会滚动的设置页里。`winshell.Kit.Segment` 用的是 mygo `SegmentedBase` + 轨道里自画选中块（`P: kit.go:137-185`），选中块位置取自上一帧量到的格子位置，不会跟着旧库的毛病走。`[读码]`；是不是这就是主人看到的那个，`[推断]`。
   - **图片、视频、转发各一种样子**：`blocks.go` 里四块（图片组 317、链接卡 358、转发卡 380、下载/文件/视频块 412）是各写各的，背景和圆角靠复制粘贴凑得一样（都是 `Background(h.T.C.Hover).Radius(h.T.RInnerMin)`，内距 `S2`），但文字字号、元信息写法、状态处理、按钮写法各不同；审批卡 `approval.go:198`、命令和改文件卡 `cards.go:81、283` 又是另外两种容器。尺寸写死：`mediaSize` 里 `240`、`320`、`48`（`blocks.go:305-313`）。`[读码]`
   - **悬停框超出列表**：悬停底色在每个控件里各算各的（见 F12），`conversationRow` 整行铺满（`P: sidebar.go:84`）和别处的圆角悬停块不是一套；具体哪一处超出，没有复现，`[推断]`。
   - **分隔条突兀**：分栏线用 mygo 的 `ui.Split`（`P: frame.go:117、121`（`Kit.columns` 里）），样子取自 `Kit.Theme`，没有自己的令牌；设置页里的分隔用旧库的 `settings.Divider`（`linksettings.go` 2、`modelsettings.go` 5）。两处取的颜色来源不同。`[推断]`
5. 设计规矩在**文档里有、在代码里没有**：`设计语言.md` §八 “悬停叠一层、按下再深一层只有一种写法”（Bun 的 `.su-press`，`B: ui.css`），Go 版里这句话被写成了 11 处 winshell 里的 `if b.Pressed() {…} else if b.Hovered() {…}` 复制粘贴，加 chatui 里 7 处自己的版本（`approval.go:123` 附近甚至直接 `bg.Mix(t.C.Text, 0.11)` 写死了令牌里本来就有的按下浓度）。Bun 版能做到统一，是因为有 `lint-ui.ts`（静态拦写死颜色、圆角、间距、焦点环）加 `check-census.ts`（真页面里量每类元素有几种高度圆角字号，只拦变多）两道检查；Go 版目前只有 `archcheck/newui_test.go` 拦“依赖旧库”这一条。`[读码]`

## 二、逐族盘点

约定：每族先写“现有实现”（包·函数·位置），再写取值来源和违反的规矩，最后是对照。规矩简称：**等距**（四边等距，设计语言 §一.3 / R001）、**同心**（内圆角 = 外圆角 − 内距，R002）、**填满**（内层缩进并填满可用宽度，LESSONS 界面节）、**不闪**（加载不闪、退场保留内容，LESSONS 界面节）、**一族**（改一个就改一族，`feedback-ui-change-whole-family`）、**不露码**（状态码不原样露出，规格里的“用日常完整说法”，设计语言 §十一）。

## 三、对照小结

### 3.1 原型（`cmd/sumika-proto`）里这一族长什么样

原型是“应该长成的样子”，整窗只有一套：`a.button`、`a.iconButton`、`a.textField`、`a.choice`（下拉）、`a.switchControl`、`a.segment`、`a.avatar`、`a.sideRow`、`a.surface`（登记表面，几何测试用）、`slider`（`view.go:824-845`）。**原型有、Kit 还没有的**：`plugins.go` 的拖动调整、选项切换、折叠卡（`:336-:792`）。**原型没有的族**（Kit 要补，缺口按“原型 > Bun > 设计语言推导”，ADR-322 第 3 条）：对话框、确认框、toast、加载占位、空/错误状态、页头、表格、卡片/分组、富卡片、菜单（+菜单是 P 分支照 `choice` 推的）。

### 3.2 Bun 版 `web/src/ui/` 怎么做到“每族一种”

[读码] Bun 的做法是**三层**：
1. **令牌**：`B: tokens.css`（352 行）按用途起名（`--h-ctl/--h-pill/--h-badge`、`--r-xs/--r-ctl/--r-1/--r-2/--r-pill`、`--s1…--s5/--inset`、`--dur-*`、`--z-*`、`--sh-*`）。
2. **组件包**：`B: controls.tsx`（`Button/IconButton/Segmented/IconTabs/Switch/Checkbox/RadioCards/TextField/SearchField/Select/ComboBox/Slider/NumberField/TimeField/CheckboxGroup/Toolbar/TagInput`，全部包 React Aria 的行为）、`overlays.tsx`（`Tooltip/Menu/ContextMenu/PopoverCard/HoverCard/ConfirmDialog/DecisionDialog/PromptDialog/Sheet/toast/Toaster/ApprovalCards`）、`display.tsx`（`Avatar/AvatarStack/Badge/Chip/Kbd/Skeleton/Card/Meter/ProgressBar/EmptyState/Banner/Disclosure/Spinner/ThinkingDots`）、`lists.tsx`、`table.tsx`、`page.tsx`（`CategoryPage/SettingGroup/SettingRow`）、`media.tsx`（`ImageViewer/Images/ImageMessage/VideoMessage/ForwardCard/LinkCard/FileCard/VoiceMessage`）、`deferred.tsx`（`Deferred/LoadBoundary/AppBoundary`，按需加载的块先占固定高度，取不到只坏这一块）。规则写在文档里：`设计语言.md` §十点五“写界面只用这些库，页面里只用 `ui` 导出的组件”。
3. **检查**：`lint-ui.ts`（静态，扫 `web/src/ui/*.css`：写死颜色、自己混色、写死字号、写死圆角、焦点环自己写、不可用自己写透明度、写死控件尺寸、写死层级、写死时长、间距只许用档位、能点的块 hover 里自己写 background 要用 `.su-press`；放过的写法要在行尾标 `/* 材质 */`、`/* 自有尺寸 */`、`/* 微调 */`，所以每个例外都留在代码里能搜到）和 `check-census.ts`（动态，用 Playwright 在真页面里按语义（role、组件类名）把菜单项、列表行、分段和标签、输入框……每类的高、圆角、字号量出来，**和 `census-baseline.json` 比，只拦“变多”**；有意统一后 `--update` 重写基线；状态矩阵里的样本、大小跟着内容走的东西（图片、视频、转发卡、引用）不算）。

Go 版目前对应的只有：`Kit.Surface` 挂钩（登记表面，几何测试用）和 `archcheck/newui_test.go`（拦依赖旧库）。**没有等价于 `lint-ui` 的“拦写死数字”，也没有等价于 `check-census` 的“量种类”**。第五节的规则草案补的就是这两道。

### 3.3 设计语言、设计自查、界面模式规范里已经规定的

- `设计语言.md` §八：状态一套（平时、悬停叠一层、按下叠一层不缩放、键盘焦点 2px 环、选中、不可用 45%、进行中、危险）；§八.1 `.su-press` 唯一写法；§十点五“写界面只用这些库”（Bun 版，原生版对应的是界面模式规范 §3 的 mygo 控件表）。

## 四、建议：统一后的唯一实现

### 4.1 放在哪个包

**建议：`native/internal/uikit`**（备选：`native/uikit` 放 internal 外，不选，因为只有本模块用）。理由：

1. 名字说“控件层”，和 `winshell`（窗口外壳：导航、列表、标题栏、窄窗三层）分开。记忆、运行、设置页要用控件，但不该依赖外壳；外壳也不该再是“控件的家”。
2. 避免和 MewTypeUI（旧“组件库”）、CrychicUI（旧式用法）混叫。本包不叫 `kit` 是因为 CrychicUI 里已经有个 `kit` 包，grep 时分不清。
3. 已有 `winshell.Kit` 的方法签名基本可以原样搬进来，改动小，迁移是机械的。

**分层（避免循环依赖，这是关键）**：现在 `winshell` 依赖 `chatui` 取令牌（`chatui.Tokens`、`chatui.Derive`、`chatui.Icon`）；但 `chatui` 的消息列自己也要按钮、头像、卡片容器。如果 `uikit` 再依赖 `chatui`，`chatui` 想用 `uikit` 就成了环。两种做法：

- **阶段一（低冲突）**：`uikit` 依赖 `chatui` 取令牌，只给 `winshell` 和各页面用；`chatui` 自己的按钮、头像等先不动，只用检查规则把它们锁成“只许缩短的白名单”。
- **阶段二**：把令牌、颜色（OKLCH）、图标、`Settings/Derive` 从 `chatui` 下沉进 `uikit`（或更底的 `internal/uitoken`），`chatui` 反过来依赖 `uikit`，这时 `chatui` 才能删自己的按钮、头像，改用 `uikit`。文件搬动大（`chatui` 几乎每个文件都引 `Tokens`），**必须等 proto-port、image-bubble 合进 main 之后**再做，否则冲突范围覆盖这两条线的全部文件。

最终依赖方向：`uikit`（令牌 + 控件，只依赖 mygo）← `chatui`（消息列）、`winshell`（外壳）← 根包页面文件。

### 4.3 内置哪些规矩（写进组件本身，页面没有选择）

1. **等距、同心**：外轮廓圆角 = 内层圆角 + 内距，由组件内部按 `T` 算，页面不传圆角、内距、高度；`Surface` 挂钩登记，几何测试量。
2. **悬停、按下、选中、不可用**：一个内部函数 `pressable(b, base, mode)` 决定底色（浓度只取 `P.Hover/P.Press/P.Selected`），所有控件和行都经它，页面不写 `if b.Hovered()`。
3. **加载不闪**：`Loading` 内置延迟（默认 200ms 内不画骨架）和最短显示（骨架一旦画了至少留 400ms），内容区尺寸预占（有宽高按比例，没有按档位默认），加载完淡入不换元素。
4. **对话框不闪**：`Dialog` 的内容没准备好时不开（由调用方在数据到位后设 `open`），或内容区自己用 `Loading`；退场动画结束前保留最后内容（LESSONS 界面节）。
5. **状态码不外露**：`MediaState`、`LoadState`、错误全部走 `StatusText` 枚举；组件不接受自由字符串当“状态”；未知码有兜底话和一次日志。
6. **填满**：行、卡片、输入框默认 `FillWidth`，内层缩进后填满可用宽度；分段、筛选片的格子按内容撑开但轨道等距。
7. **一族一个入口**：消息内五种卡（图片、视频、链接、文件、转发）共用 `MediaCard` 的容器：底、内距、圆角、文字层级（标题、说明、元信息）、操作按钮位置、加载占位、失败占位，只有内容不同。
8. **危险**：`Danger` 变体的按钮、`Confirm{Danger:true}`：文字和图标用 `P.Danger`，底用危险浅底，放在菜单最下面（设计语言 §八）。
9. **读屏、键盘**：每个控件都必须有 `Label`；键盘焦点环用统一的环（`Kit.Theme.Focus`）；方向键切换分段。组件内部保证，页面不用管。

## 五、收拢顺序

依据：用户日常看到的程度 × 出问题的频率 × 依赖关系 × 和别的分支的冲突。

0. **先建尺子，不改界面**（新增文件，零冲突）：`archcheck` 的几条规则（第六节）和 census 基线测试。先看到“现在有多乱”的数，之后每一步都只能让它变少。
1. **等 proto-port 合进 main**（它占着 `winshell`、`kit.go`、`memoryview.go` 等文件）。合进来后：把 `Kit` 的控件层拆进 `internal/uikit`，`winshell` 只留外壳布局并 import `uikit`。**不是现在做**，现在做会和那条线撞满文件。这一步只搬家，不改行为。
2. **控件七族**（F01–F09）：补齐缺的（危险按钮、`Select` 带搜索、`NumberField`），把记忆、运行、设置、状态页上的 CrychicUI、MewTypeUI 控件换掉（用 `legacy_choice.go` 那种桥一族一族过）。每族单独提交，每族同提交扫同族全部用法（`k-ui-change-whole-family`）。顺序：分段（主人点名）→ 按钮 → 开关、复选 → 下拉 → 输入。悬停、选中（F11）在这一步里一起收成 `pressable`。
3. **加载、空、错误、状态文案**（F19、F20、F28）：这一块**没人在改**，且对主人感知最强（一闪而过、码外露）。先做 `StatusText` 单表 + `Loading` 的延迟与最短显示，再换记忆页、运行页。可以在第 2 步之前就开做，因为只依赖令牌，不依赖控件。
4. **对话框、菜单、提示**（F16–F18）：`Confirm`、`Menu` 统一，加 `Toast`，把 `a.status` 28 处引用换成 toast。`chatviewer.go:42` 的 `ui.Modal` 要等 `fix/image-bubble` 合进 main 后再动。
5. **消息内富卡片**（F23）：先和 `fix/image-bubble` 约定 `MediaCard` 的容器 API，等它合进 main，再把 `blocks.go` 四块收进去（图片组占位尺寸、视频封面、转发、链接、文件）。最后收审批卡和命令卡的容器。
6. **页面结构**（F10、F13–F15、F24）：记忆、运行、设置、状态四页按原型令牌重做，删 `legacyPage`、`legacy_choice.go` 的旧分支，列表行、页头、标签、表格换掉。这是把“新界面”从“新外壳装旧页”变成真新页的一步，也是 ADR-322 第 4 条九个区域验收的最后几个。
7. **头像、徽标、图标尺寸**（F21、F22、F26）：低风险收尾；等第 1 阶段二（令牌下沉）做完才能把 chatui 里三份头像并掉。
8. **删旧库**：MewTypeUI、CrychicUI 的 import 全部消失后，从 `go.mod` 去掉依赖，`archcheck` 里 `oldKits` 对整个新界面范围全开，白名单删空。

不排的：旧界面（`mainView=legacy`）的消息行、转发层、看大图旧版——它们等旧界面退役时一起删，不在这轮收。

### 6.5 加载、对话框、状态码（行为测试）

- **加载**：uikit 包里 `Loading` 的单元测试，用测试时钟：`Loading=true` 维持 150ms → 元素树里没有骨架节点；维持 250ms → 有；再变 `false` → 骨架至少还在到总计 400ms。页面层：每个会读后台的页面（记忆、运行、状态）在“加载中 100ms 就返回”的假后端下，断言没有任何一帧出现骨架。同时用 AST 禁 `feedback.SkeletonList`、`ui.Spinner`、`ui.Skeleton*` 出现在 uikit 之外。

- **状态码不外露**：`StatusText` 的表驱动测试，输入是 `api.ForwardView` 的全部 `State` 常量、`segview.ImageNote` 的全部 case、`MediaState` 全枚举，断言每个都有非空中文、不含 ASCII 下划线词（正则 `[a-z]+_[a-z_]+`）；再做一个渲染测试：用 `ui.NewTester` 画每种状态的 `MediaCard`，收集元素树里所有文字，断言匹配不到那个正则。页面层同样对 `Failure` 传入 `errors.New("dial tcp 127.0.0.1: connection refused")`，断言界面文字里没有这串英文。AST 补一条：`Failure`/`Empty` 的 `Err`、`Hint` 字段不许直接传 `err.Error()`。
