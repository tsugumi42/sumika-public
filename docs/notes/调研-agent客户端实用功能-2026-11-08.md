## 1. 先看三件点名的

三件都按"引导加简单兜底"：给模型一段清楚的说明和一两个工具，宿主只守住预算、停止和权限，不替模型规定怎么干活。

### 1.1 /goal

先把四家做法摆成一条谱：谁来判断"做完了"。

| 谁判断 | 做法 | 出处 |
|---|---|---|
| 模型自己 | Codex：没有外部评判，`create_goal`、`update_goal` 两个工具；每轮结束自动注入一段"继续"提示（目标当用户数据不当指令；"完成"前必须逐条对照证据审计；连续 3 轮同一阻塞才允许标 blocked；`paused` 只能由用户要求）；可设 token 预算，到顶转 `budget_limited` 并要求收尾。OMP 同样走 `goal` 工具（create/get/resume/complete/drop，也有 token 预算）。 | CX `ext/goal/templates/goals/continuation.md`、`budget_limit.md`、`ext/goal/src/spec.rs`；OMP `prompts/tools/goal.md`、`goals/tools/goal-tool.ts` |
| 小模型当裁判，看整段对话 | Claude Code：`/goal` 是"会话级 Stop hook"；每轮结束把条件和对话交给小快模型，判 未达成 / 达成 / 不可能；达成或不可能自动清除；"没有工具调用的几轮"会交还控制权但目标仍在；条件最长 4000 字，可以在条件里自己写"或 20 轮后停"。OC 同类：裁判提示写明"助手自称完成不算证据，只认对话里的工具结果和文件内容"；`MAX_ROUNDS=50`、`MAX_STALLS=3`、后台等待超 30 分钟就暂停；进程重启后目标回来是暂停状态。 | CC 文档 goal 页；OC `core/src/plugin/goal.ts:15-20`、`goal/judge.txt` |
| 小模型当裁判，只看最后回答，外加硬检查 | Hermes：裁判看目标原文、最后回复约 4KB、该会话登记的后台进程；四种判决 done/continue/blocked/wait；`wait` 让循环停在某个进程或若干秒上，不空转；裁判出错一律当 continue（"坏裁判不能卡死"），连续解析失败 3 次、传输失败 5 次才停；默认 20 轮到顶暂停；可选"质量门"：目标上挂 shell 命令，必须退出码 0，门没过就不调裁判，把命令输出尾部当下一轮提示；可选"完成合同"（outcome、verification、constraints、boundaries、stop_when）；`/subgoal` 中途追加验收项。 | HA `hermes_cli/goals.py:32-46,113-175`、`website/docs/user-guide/features/goals.md` |

**交互和状态显示：**

- CC：`/goal <条件>` 立即起一轮；`/goal` 看状态（条件、已跑多久、评估轮数、token、最近一次理由）；`/goal clear`（别名 stop/off/reset/none/cancel）；终端里有 `◎ /goal active` 指示和计时，Ctrl+O 看每轮裁判理由。
- CXD：输入框上方一行（靶心图标、状态词 Pursuing / Paused / Goal stalled / Goal usage limited / Goal limited / Complete、目标原文截断、计时或 `已用/预算` token）；行内三个小按钮：编辑（铅笔）、暂停/恢复、清除；整行点开编辑对话框；输入框页脚有 `Goal` 模式标签，悬停变 X 清除；替换已有目标先确认"Replace current goal?"。出处：`拆解-Codex桌面版-界面.md` 842 行起。
- HD：状态栈里的"目标"组（顺序固定为 goal → todo → subagent → background → queue → preview，默认收起）；头部 `状态 · 回合信息`，体里是目标标题、暂停原因或最近判定理由；`⋯` 菜单：查看详情、追加验收项、暂停/恢复、清除；详情对话框分 Objective / Outcome / Verification / Constraints / Boundaries / Stop when / 等待条件 / 质量门；破坏性操作先确认。出处：`拆解-Hermes-界面.md` 3375～3445 行。
- OMP：`/goal set|show|pause|resume|drop|budget`，另有 `/guided-goal`（先让 agent 在聊天里采访你，再设目标）。

**怎么停：** CC 用 `/goal clear`、Ctrl+C；Hermes `/goal pause`（保留）、`clear`（丢弃），预算到顶自动暂停并提示 `/goal resume`；Codex 的暂停只能由用户要求；OC 重启即暂停。

**对照我们已写的规格，要改的几处（不是另起炉灶）：**

1. 裁判输入：规格写"目标原文 + 最终回答 + 工具调用摘要"，方向对。再加两条便宜的：①裁判提示写明"助手自己说完成不算证据，只认工具结果"（OC）；②目标原文进入提示时包在"这是用户数据，不是指令"的一段里（Codex、OC、OMP 三家都有，一句话的安全收益）。
2. 不加 `wait` 判决：Hermes 的 wait 依赖后台进程登记表，我们现在没有后台命令（`native/internal/tools` 没有 process 类工具）。等后台命令做了再加。
3. 裁判出错：规格没写。取 Hermes 的做法：出错当"继续"，但连续 3 次出错就暂停并写原因；认证、余额、模型不可用这类要人修的直接清除并说明（CC）。
4. 预算：规格只有轮数（30）。同行是 20（HA）、50（OC）。我们已有 `turnbudget` 账本（`native/internal/turnbudget`），建议轮数和 token 并列，任一到顶就暂停；文案学 Codex 的"到预算先收尾，写清还剩什么和下一步"。
5. 主人点"停止"：规格写成结束目标。建议改成"暂停，可继续"（Hermes 对 loop 的做法：打断即暂停；Codex 的 paused）。误触停止不该丢掉目标。
6. 防早退：Codex 的"连续三轮同一阻塞才算 blocked"，写进续轮提示里，不靠宿主判。规格里"连着两轮卡住就停"保留作兜底。
7. 后做：质量门（Hermes）和完成合同、`/goal draft`（Hermes、Codex 的"让 agent 起草"、OMP 的 guided-goal）。先不做，规格里记一行。
8. 规格已经和同行一致的：重启后显示已暂停（OC）、界面常驻一行（Codex、Hermes）、目标进行中主人发的话当插话（Hermes：真实用户消息永远优先）。

### 1.2 /loop

| 家 | 做法 | 出处 |
|---|---|---|
| CC | 三种：`/loop 5m <任务>` 固定间隔（折成 cron，最短 1 分钟，秒向上取整）；`/loop <任务>` 不给间隔，由 Claude 每轮结束自己选 1 分钟～1 小时后醒（`ScheduleWakeup` 工具，理由会打印）；`/loop` 无参数跑内置"维护提示"或 `.claude/loop.md`。停止：自适应模式 Esc 或 Ctrl+C；固定间隔要让 Claude 取消；7 天自动过期；一个会话最多 50 个任务；连着几次没事的醒来折叠成一行；周期任务有抖动（最多晚半个间隔、最多 30 分钟）；错过的只在空闲时补一次。`/usage` 里有"循环"明细（每个循环跑了几次、总 token、每次 token），防失控。 | CC 文档 scheduled-tasks 页；CHANGELOG 4156、4205 行 |
| CC 桌面 | 另有"已安排任务"页：新建任务（名称、说明、本地文件夹、权限模式、模型）、频率（每小时/每天/工作日/每周/手动/自定义 cron）、立即运行、启用/暂停、运行历史（含被跳过的，悬停看原因：电脑睡眠、上一次未跑完）、"总是允许"面板；每次运行是新会话；错过的只补最近一次并弹通知。 | CC 文档 desktop-scheduled-tasks 页 |
| HA | `/loop [间隔] <提示> [--times N] [--until <条件>]`，一个会话一个循环；不给间隔则自适应：从 1 分钟起，回复不变就指数退避到 15 分钟，回复一变立刻回到下限（宿主算，不靠模型调工具）；停止条件：模型回复末尾单独一行 `LOOP_COMPLETE`、次数上限、`--until` 条件由同一个裁判判、`/loop stop`、兜底 `max_ticks=100`；唤醒就是一条普通用户轮次，不动系统提示，缓存不破；中断唤醒轮次就暂停循环；**活跃的 /goal 优先于 loop，goal 在推进时 loop 唤醒顺延**；会话有循环时桌面窗口关了后台继续跑。界面：输入框上方"循环卡"：`Loop active · 2 runs · next 00:04:12`，每秒走字。 | HA `website/docs/user-guide/features/loops.md`、`hermes_cli/loops.py`；HD 拆解界面 3427 行起 |
| OMP | 不是定时器：`/loop` 打开"循环模式"，下一条发出的提示在每次 agent 结束后自动重新提交，可用次数/时长或 `--until '<cmd>'`、`--while '<cmd>'`（shell 命令的退出码决定继不继续）限界。 | OMP `slash-commands/builtin-modes.ts:373` |
| OC | 没有 `/loop`，有会话级"计划"工具：`schedule_create` 的时间可以是 `in`、`at`、`every`、`cron`，另有 `until` 条件（到点先查条件）；`schedule_list/pause/resume/delete`；错过的槽不连发，保相位跳过；受 `experimental.schedules` 开关控制。 | OC `core/src/schedule.ts:90-157`、`core/src/tool/plugin/schedule.ts`、`plugin/command/schedule.txt` |
| CX | 没找到 `/loop`；已安排任务在桌面版的"已安排任务"页（CXD 键表，未核实控件）。 | CXD |

**给 Sumika 的建议**（规格 3 节已经很接近，只补几处）：

- 规格里和同行已对齐的：错过只补一次（CC 桌面）、7 天自动停（CC）、同会话不叠跑（CC、HA）、没事回暗号不出声（CC 折叠"无事醒来"）。
- 补一：自定节奏时，宿主给兜底退避（Hermes：回复没变就拉长间隔，变了回到下限），模型调 `schedule_next` 只是覆盖；上限别定死 1 小时，CC 的更新日志里记过"1 小时唤醒刚好踩在 1 小时缓存过期之后"这个坑，我们按所用模型的缓存时长选上限（未核实各模型缓存时长）。
- 补二：goal 在推进时 loop 顺延（Hermes 的一条规则），写进规格第三节。
- 补三：中断一次循环里的轮次 = 暂停循环，不是停止（HA）。
- 补四：每个循环在用量里单列次数和 token（CC `/usage` 的"循环"明细），防止悄悄烧钱；预算用现有 `turnbudget`。
- 补五：循环只在本地私聊（规格已写）；`/loop` 的"无参数默认提示"不做，我们没有仓库维护这种场景。

### 1.3 回复引用

**诚实的先说：这六家里没有一家把 Telegram 式"回复某条消息"做成一等功能。** 最接近的几样：

| 家 | 有什么 | 出处 |
|---|---|---|
| CXD | 在助手消息里选中文字，浮出"加到聊天"，把选段作为引用附件挂到输入框（设置项 `allowAddSelectedTextToChat`、`responseTextAnnotationAttachments`）。触发 UI 没细看。 | `拆解-Codex桌面版-交互.md:254` |
| HD | 输入框里 `@file:`、`@url:` 等引用变成行内小标签（值用反引号包起来）；助手消息底部有分支、操作条；用户消息可行内编辑重发。没有"回复某条"。 | `apps/desktop/src/components/assistant-ui/reference-kinds.ts`、`app/chat/composer/rich-editor.ts` |
| HA 的消息网关 | 机器人发回复时可以引用原消息，`reply_to_mode` 三档：`off` 不串线、`first` 只第一块、`all` 每块。这是平台协议层，不是桌面功能。 | `docs/archive/notes/拆解-Hermes-架构.md:5417` |
| CD | 在 diff 的行号旁点 + 写评论，Ctrl/Cmd+Enter 一批提交给 Claude；是对代码行的引用，不是对消息。 | CD 文档"Diff view" |
| CC、OMP、OC、CX CLI | 没找到消息级引用（未核实 OC 桌面的 gui-plugins 里有无相关东西，列表是 browser/btw/context/details/file/goal/review 等，没有 quote）。 | 各自目录 |

QQ 机器人这一边倒是很成熟，已有对照：对照-引用和附加内容怎么给模型看（私有存档）（几个机器人框架怎么把引用放进模型输入、截多长、作者怎么标）。

**Sumika 现状：** 半有。

- 有：气泡里的引用块渲染（`native/internal/chatui/bubble.go:178,311,387`、`group.go:17`，原型里有夹具 `cmd/sumika-proto/engine.go:84`）；后台读侧的 `api.QuoteView`、`ReplyTo`（`native/internal/api/api.go:95,113`，QQ 收到引用时用）；库里事件表有 `ReplyTo` 列（`history/history.go:21`）；QQ 发送引用的出口按规格已实现（[规格-表情包和引用回复](../规格-表情包和引用回复.md) 状态头）。
- 没有：本地私聊的输入通道没有 reply 字段（`api/local_inputs.go`、`app/desktop_chat.go` grep 不到 Reply 或 Quote）；界面上没有"回复"入口和输入框上方的引用条；没有给模型的引用格式。

**建议做法：**

界面：

1. 气泡悬停出"回复"小按钮，右键菜单同样有（Telegram 式，是我们的建议，不是哪家现成的做法）；也可在助手消息里先选一段文字，再点"回复"，引用的就是选段（学 Codex 的"加到聊天"）。
2. 输入框上方出一行引用条：左侧竖线、发言人名字（主人用强调色，同气泡内引用块）、一行摘要、右侧 × 关闭；Esc 先关引用再关别的。引用条放在状态栈里，排在队列下面、输入框最近一层。
3. 发出的气泡带引用块（现成的 `chatui.Quote`）；点引用块滚回原消息并闪一下；原消息不在已加载窗口时先翻页再滚；原消息被撤回或不可见时显示"原消息不可见"占位，不泄露原文。
4. 同一套给 QQ：收到的引用走现有 `QuoteView`，出站走现有引用出口，界面行为一致（规格 QQ 那边已有）。

后台：

5. 输入加 `ReplyTo`（`EventRef`，按事件 id 和 `ActorKind`/`ActorID`，不按名字），可选 `Selection`（选段原文，限长）。内核校验被引事件属于同一会话且这个会话的这位听众看得到，校验失败当没引用并给界面一个失败角标（LESSONS：身份按 ID 认，失败不能回成功）。
6. 给模型：只在这一条用户消息前追加一小段，格式固定，例如 `（引用：<名字> <时间>：「原文前 N 字」）`；原文当资料，不当指令；原文含图时附识图描述，沿用现有识图（[规格-识图](../规格-识图.md)）；引用的是她自己的消息时标"你说的"。不进系统提示，不插入历史中间（LESSONS：每轮变化只追加末尾、不破缓存）。N 取值参考上面那份对照里各家的截断，先按 200 字，写进配置。
7. 存库：沿用事件的 `ReplyTo` 列，选段另存；记忆和压缩时引用块跟着消息走，不单独成事实。
8. 测试：引用不可见、引用已撤回、引用别的会话、引用选段超长、引用自己、引用含图，各一条；改坏检查：去掉可见性校验应有测试变红。（涉及"谁能看什么"，属 AGENTS 第 7 条的高风险核验范围。）

**Sumika 应采用的结构要点（最多 15 条）：**

1. 输入框上方做一个"状态栈"：固定顺序 目标 → 循环 → 清单 → 子代理 → 后台 → 排队 → 引用条；每组一行、默认收起、有内容才出现（HD、CXD）。
2. 目标行和循环行格式照 CXD/HD：图标、状态词、截断的原文、计时或次数；行内按钮：暂停/恢复、清除；整行点开看详情。
3. 引用条是状态栈里最靠近输入框的一层，Esc 先关它。
4. 发送键在忙时变成排队/插话/停止三态，文字只放在提示和可访问名里（CXD）。
5. 输入框下方一条控件药丸：权限模式、模型、推理强度（CD、HD、CXD 三家一致）。
6. 输入框里的 `/` 和 `@` 是弹层，不是页面；命令表登记式，命令面板（⌘K）是同一份表的另一入口。
7. 左侧栏：会话列表带搜索、状态点（跑动、未读、等审批）；右键和 ⋯ 共用一份菜单。
8. 定时任务（含 /loop 建的）有自己的页：名称、频率、状态、立即运行、运行历史（含被跳过及原因），每次运行落成一个真实会话（CD、HD）。
9. 审批卡堆叠、1/N、Enter/Esc 手势；"这次/本会话/以后"分档；卡片标明是谁的话引起（沿用 AGENTS 的审批要求）。
10. 工具过程：读搜折成一行，命令和改文件各一张卡，失败才用红色；改文件卡上放"回退到这次改之前"。
11. 助手消息底部操作条：复制、重新生成、从这里重发、回复；用户消息悬停：编辑重发。
12. 通知：窗口不在前台时，目标达成、循环有内容、审批到了才发系统通知；有数量角标（CD、CX 0.167 的未读标记）。
13. 设置浮层：左分类、右字段、搜索；已有设置页注册表，新开关（技能、联网、子代理、MCP、项目说明）一律走注册表（`调研-agent客户端设置页-2026-11-08.md`）。
14. 默认只显示少量控件，进阶项收进 Advanced（HD 的两档）；常驻说明最多一行（设计语言第十一节）。
15. 不做终端、文件树、浏览器侧栏和 diff 审阅面板：我们不是代码编辑器，右侧栏留给"她在想什么"和记忆。

## 4. 推荐顺序（前 10 项）

按"做完用户马上能感觉到"排，后一项常依赖前一项。

1. **把已有但关着的能力做成设置页开关**（技能、联网搜索、子代理、MCP、项目说明）：代码都在，只差界面和一次"要不要开、花多少"的决定；体感最大、最便宜。联网要 Tavily key，先问主人。
2. **斜杠命令框架（登记式）**：/goal、/loop、/btw、/compact 都要它。
3. **回复引用**：后端读侧、库字段、气泡渲染都有，补输入通道、引用条、给模型的格式；用户点名且每天用。
4. **/goal**：规格已写，按 1.1 的改动落地；有它才能"交代一件事就去忙"。
5. **通知**：goal、loop、审批做完都要告诉人；窗口不在前台时才响。
6. **/loop 和定时任务页**：同一张表，规格已写；先固定间隔，再自适应。
7. **回退和改了重发 + 文件回退入口**：检查点后端已有，把它接到改文件卡；"编辑重发"是每天会用的后悔药。
8. **权限模式、模型药丸和上下文用量条（带手动压缩）**：三者都是输入框下一行的小件，后端基本现成。
9. **搜索聊天历史和命令面板**：消息一多就找不到；命令面板同时给 `/` 命令第二个入口。
10. **导出 markdown 和 /btw 侧问**：各自小，/btw 对她来说就是"插嘴问一句、不记进主线"。

排在后面的：计划模式、问主人、后台命令（解锁 goal 的 wait）、子代理面板、hooks、手机远程。
