## 1. OpenCode v2

### 库、协议和传输

使用官方 TypeScript SDK 拆分包，`@modelcontextprotocol/client`、`core` 为 **2.3.1**。本地 stdio 没直接使用 SDK 的进程启动器，而是自己实现 Transport，经 Location 的 `Environment` 启动，因此 MCP 进程与该工作区的执行位置一致。出处：`O/core/package.json:108`、`O/core/src/mcp/stdio.ts:38`、`O/core/src/mcp/client.ts:263`。**读码确认**。

协议配置有 `legacy`、`auto`、`2026-07-28`：

- 默认 `legacy`，使用 initialize 握手；配置说明写明覆盖到 2025-11-25。
- `auto` 探测 2026-07-28，不支持时回退。
- 指定 `2026-07-28` 则要求该版本。

出处：`O/schema/src/mcp.ts:20`、`O/core/src/mcp/client.ts:441`。协商选择为**读码确认**；legacy 支持范围为**读文档〔源码内配置说明〕**。

传输工厂实际创建本地 stdio 或 `StreamableHTTPClientTransport`。在 `core/src/mcp/client.ts`、`stdio.ts` 和 `schema/src/mcp.ts` 中没有找到老式独立 HTTP+SSE 客户端分支。**读码确认／限定查找范围**。不要把 Streamable HTTP 响应中的 SSE 当成旧 SSE 传输。

### 配置和密钥

v2 原生结构是 `mcp.servers`，本地 command 是数组，远端用 URL；超时拆成三种，单位均为毫秒。例如：

```json
{
  "mcp": {
    "servers": {
      "docs": {
        "type": "local",
        "command": ["npx", "-y", "some-mcp-server"],
        "environment": {},
        "timeout": {
          "startup": 30000,
          "catalog": 30000,
          "execution": 60000
        }
      }
    }
  }
}
```

这是按当前类型声明写的示例。配置发现识别 `opencode.json`、`opencode.jsonc`；归一化器也识别旧版 MCP 条目并迁移。出处：`O/schema/src/config/mcp.ts:19`、`O/schema/src/mcp.ts:7`、`:26`、`:53`、`O/core/src/config/discovery.ts:12`、`O/core/src/config/normalize.ts:276`。**读码确认**。

远端 OAuth 凭据进入全局 Credential 存储，身份包含本地服务名与 URL，避免同 URL 不同账号共用凭据。普通连接不主动打开登录流程；需要交互时进入 `needs_auth`。出处：`O/core/src/mcp/index.ts:195`、`:201`、`O/core/src/mcp/oauth.ts:133`、`O/core/src/mcp/client.ts:411`。**读码确认**。

在本次查过的 `core/src/config`、`core/src/mcp` 中，没有找到直接读取 Claude `.mcp.json` 或 Codex `[mcp_servers]` 的实现；确认的是 OpenCode 自己的新旧格式兼容。**限定查找范围**。

### 生命周期

启用的服务异步连接，不让慢服务器阻塞 Location 启动；连接成功前会先列工具，列举失败也算连接失败。默认：

| 项目 | 默认值 |
|---|---:|
| 建连、初始化 | 30 秒 |
| 工具、提示词等目录请求 | 30 秒 |
| 配置服务器的执行 | **12 小时** |
| 外部 attach 进来的服务器执行 | 10 分钟 |
| HTTP 会话 DELETE | 1 秒 |

出处：`O/core/src/mcp/index.ts:448`、`:658`、`O/core/src/mcp/client.ts:34`、`:309`。**读码确认**。12 小时不能当作适合 Sumika 的默认值。

HTTP 建连对暂时错误最多追加两次尝试，间隔 250 毫秒、1 秒；普通工具执行没有套这层通用重试。已建立的 legacy HTTP 会话过期会重连，并重做当前请求一次。普通进程退出则清理连接、标失败；本次读到的 watch 路径没有通用的 stdio 崩溃循环重启。出处：`O/core/src/mcp/client.ts:177`、`:284`、`:332`、`O/core/src/mcp/index.ts:361`、`:369`、`:423`。**读码确认**。

### 生命周期与 Windows

初始化遍历启用配置并发连接；交互入口有总等待预算，`InitWaitBudget` 为 10 秒。初始化时限默认 10 秒，OAuth 服务 30 秒，配置可覆盖。出处：`C/internal/agent/tools/mcp/init.go:338`、`:738`、`:399`、`:1410`。**读码确认**。

调用前会 ping，失败时按服务名加锁，重建 session 并补回工具、prompts、resources。它是**使用时恢复**，不是已确认的持续后台崩溃重启。ping 返回 MethodNotFound 也算服务器活着。出处：`C/internal/agent/tools/mcp/init.go:791`、`:906`、`C/internal/agent/tools/mcp/lifecycle_test.go:284`、`:426`。**读码确认**。

`RunTool` 使用传入 ctx 执行 CallTool；这里没有额外施加“配置 timeout 秒”的调用截止时间。不能把初始化 timeout 当成工具调用 timeout。出处：`C/internal/agent/tools/mcp/tools.go:43`。**读码确认**。

监听三类 list_changed 并发布事件。`sessionless` 服务刻意不装这些 handler，规避 SDK 打开订阅流后被服务器 404 断连的问题，代价是失去实时目录变化。出处：`C/internal/agent/tools/mcp/init.go:1060`、`:1072`。**读码确认**。

Windows 是明确不能照搬的地方：stdio 使用 `exec.CommandContext`，本层没有 npx.cmd 适配；Windows 的 `configureStdioProcess` 是空函数，ctx 取消只杀直接子进程。出处：`C/internal/agent/tools/mcp/init.go:1211`、`process_other.go:1`。**读码确认**。

另外，启动 EOF 的诊断路径会**再次执行原命令**收集输出。Sumika 应在第一次执行时捕获 stderr，避免为了诊断再启动可能有副作用的命令。出处：`C/internal/agent/tools/mcp/init.go:1160`、`:1474`。前者为**读码确认**，后者为**设计建议**。

### 名字、schema 和结果

原始 server/tool 与模型 callable namespace/name 分开。清洗后碰撞会加身份 hash；排序后再保证唯一。当前实现的模型名称预算为 **128 字节**，不是常见的 64 字符。出处：`X/codex-mcp/src/tools.rs:25`、`:111`、`:155`、`:198`、`:226`。**读码确认**。Sumika 要兼容多个 Chat API，不应照搬 128。

schema 统一整理：

- 保存 anyOf、oneOf、allOf、局部 `$ref` 和可达 definitions。
- `const` 变单值 enum。
- 补 object properties、array items。
- 删不可达 definitions。
- 大 schema 可按预算压缩；配置说明的普通工具默认阈值为 5,000 字节。
- 布尔 schema 在当前受限表示中会被改成 string，这一项会改变语义，不宜照抄。

### 生命周期

### 建议的 Sumika 验收

以下为**设计建议**，依据上表测试边界及 Sumika 的听众隔离要求。

1. **协议与传输**：真实只读测试服务器，覆盖 stdio、Streamable HTTP、旧 SSE；旧版初始化、协商拒绝、JSON 与 SSE 响应、无 GET 流、会话失效、取消、进度、分页重复 cursor、缺少可选方法。
2. **调用不重复**：服务器先记录副作用再断连接，客户端返回“结果未知”，计数必须为 1；超时、取消后迟到结果不能被记录成成功，也不能自动重放。
3. **生命周期**：8 个并发调用只建立一个连接；发现时停插件、退避时停插件、关闭后 spawn 才返回、旧代通知晚到、配置更新撞重连，都不能留下旧注册或新旧两份进程。
4. **Windows**：npx、npx.cmd、node.exe、带空格和中文的路径；空参数、引号、尾反斜杠、`% ! & | ^`；PATH/Path、PATHEXT；终端启动与无控制台启动；服务器和包装进程先后退出；孙进程持有 stdout/stderr；强杀宿主后后代必须退出。
5. **身份和审批**：同名 raw tool 跨服务共存；有损清洗、超长、碰撞；换 URL 或 command 后旧批准不覆盖；同一服务批准 read 不自动批准 delete；readOnlyHint 不能越过 ask 或 deny。
6. **内容**：text、image、resource_link、embedded resource、仅 structuredContent、`isError=true`、空 content、不支持媒体、非法 base64、大 UTF-8 输出；错误标志与正文一起留存。
7. **权限与缓存**：主人本地有入口，QQ 私聊、QQ 群、主人在 QQ 发言都没有入口；伪造工具名、资源 URI、旧工具调用同样拒绝。逐次比较完整模型请求，已有前缀不变，目录变化只在末尾追加。
8. **性能**：同一组假服务器测 0／10／100 个服务、10／100／1,000 个工具；冷启动、热连接、搜索、调用、通知风暴、长时间运行后内存与句柄。至少记 p50/p95、分配、目录 schema 字节、模型输入 token、进程数。与相同配置的 omp、OpenCode、pi 对比后，才能谈“性能以上”。

## 9. 给 Sumika Go 的具体建议

### 9.1 库和协议边界

采用官方 `github.com/modelcontextprotocol/go-sdk`，固定已验收的 release/tag 或 revision；不自写 JSON-RPC、SSE、OAuth。库负责协议，Sumika 负责听众、审批、目录、进程归属、输出投影。依据：Crush 已有直接 Go 接入；omp、pi 自写客户端需要维护大量传输和平台兼容代码。出处：`C/go.mod:50`、`M/pi-coding-agent/src/mcp/transports/`、`P/pi-mcp/dist/transports/`。**设计建议**。

**不建议只因为 Crush 用了某个伪版本就照抄版本号。** 它已经遇到 sessionless／订阅兼容问题。实施时先核对所选 SDK 的协议版本、旧 SSE、订阅和 OAuth 支持，再用上节服务器矩阵验收。默认保留 legacy 握手兼容，2026 协商作为明确选项；不要无条件先起一个探测进程再起正式进程。依据：Crush 的 sessionless 处理、Codex 的协议模式、DeepSeek 的 probe 清理测试。**设计建议**。

### 9.2 `OnTool`：先固定入口，运行时目录放 MCP 插件内

当前接口确实不能直接注册任意远端工具名：

- `OnTool` 必须在 `policy.Specs` 查到名字。
- `Gate.Check` 又按名字查一次。
- `within` 再按名字取超时。
- `toolsFor` 用注册时保存的 spec 限听众；并行调度也读这个 spec。

出处：`S/native/internal/turn/plugin.go:249`、`:300`、`S/native/internal/approval/approval.go:98`、`S/native/internal/turn/loop.go:532`、`:703`。**读码确认**。

**默认方案：通过 `OnTool` 注册固定的 `mcp_search`、`mcp_call`，需要资源时再注册固定资源入口；不把每个远端名字添加进全局 `policy.Specs`。** 远端工具放插件自己的不可变目录快照：

```text
(serverID, rawToolName)
  → publicID、原始 schema、annotations、目录版本、连接绑定
```

建议参数：

```text
mcp_search { query, server?, limit? }       limit 默认 8，上限 20
mcp_call   { tool, arguments }
```

搜索返回 publicID、来源、说明和完整参数 schema；调用按保存的映射找到原始路由，绝不反解析 publicID。这样既能接运行时工具，又不需要每次发现新工具就改变模型 tools 前缀。依据：pi 默认按需发现、omp xd 按需读取、DeepSeek 原始身份与公开名分离。**设计建议**。

这并不等于只注册两个壳就完了。现有授权按工具名归类：`mcp_call` 若不改，批准“这个对话”或“始终”可能覆盖全部远端工具。必须增加**宿主解析的调用目标身份**。出处：`S/native/internal/policy/policy.go:531`、`:548`、`:562`。**读码确认／设计建议**。

建议在进入 Gate 前解析一次，形成内部值：

```go
type ResolvedMCPCall struct {
    ServerID        string
    RawToolName     string
    BindingDigest   string
    SchemaDigest    string
    CatalogRevision uint64
    // 内部固定的执行目标、有效时限；不接受模型自填。
}
```

审批、记录和执行共用这次解析结果；批准后再确认该绑定仍有效，变了就重新审批。授权键至少包含“服务器绑定摘要＋rawToolName”，不能只用 publicID，更不能只用 `mcp_call`。`Gate.Check` 和 `within` 接收同一份宿主算出的有效策略，避免各自回查得到不同结果。**设计建议**。依据：Codex 区分原始身份、连接绑定；Sumika 当前三处独立查表。

如果以后确实要把远端工具直接放进模型 tools，才扩展 `OnTool` 为受限的 `MCP` 策略类别，由宿主统一赋予 owner-console、默认 ask、时限和并行限制；不能允许远端 annotations 自带任意 `policy.Spec`。那时必须一并迁移 Gate、within 和调度，单放宽注册检查不成立。**设计建议**。

### 9.3 审批默认值与听众

固定入口在 `policy.Specs` 集中登记：

| 入口 | 建议默认 |
|---|---|
| `mcp_search` | owner-console；只查已获准发现的目录，不执行远端工具 |
| `mcp_call` | owner-console；外部未知副作用；默认 ask；默认串行 |
| 资源读取 | owner-console；默认 ask，允许主人按服务器／资源范围授权 |
| sampling | 默认关闭、不声明 |
| elicitation | 仅已有本地主人交互桥时声明；取消即拒绝 |

**设计建议**。依据：现有 owner-console 闸门、Crush execute 权限、omp 不按 hints 降级，以及 Codex hints 放行带来的信任取舍。

readOnlyHint、destructiveHint、idempotentHint、openWorldHint 保留给审批界面和诊断；**不让它们自行扩大权限、开启并行或批准重放**。denylist 先卡；allowlist 只决定可见／可调用范围，不等于免审批。用户明确设置的逐工具 allow 才能免问。**设计建议**。

听众同时控制入口、搜索结果、服务器 instructions、resources、prompts 和历史存储。QQ 渠道连“主人本人发消息”也不应得到这些本地执行入口。已有分档实例和压缩规则继续遵守，不能只隐藏 tools 却把主窗口的 MCP 结果带进 QQ 上下文。依据：`S/docs/规格-Go后台.md:336` 的听众与缓存约束、`S/native/internal/turn/plugin.go:300`。**读码确认／设计建议**。

### 9.4 配置格式

主格式采用 `mcpServers` JSON，便于复制 Claude、pi 风格条目；Sumika 专有策略单独放 `sumika` 字段，避免把别家的字段误当权限。示意：

```json
{
  "mcpServers": {
    "docs": {
      "command": "npx",
      "args": ["-y", "some-mcp-server"],
      "env": {
        "DOCS_TOKEN": "${DOCS_TOKEN}"
      },
      "sumika": {
        "startupTimeoutMs": 30000,
        "callTimeoutMs": 60000,
        "enabledTools": ["search", "read"],
        "approval": "ask"
      }
    }
  }
}
```

这是**建议格式，不是现有 Sumika 配置**。

兼容策略：

- Claude `.mcp.json`：直接识别 `mcpServers` 的常见字段。
- Codex TOML、OpenCode JSON/JSONC：显式导入并转换，保留来源和转换诊断。
- 不自动扫描所有编辑器目录再启动其中的 command。
- 同名条目整条替换，不拼接 args、env、headers；禁用项保留遮蔽作用。
- 协议类型与超时单位逐项转换，不能把 Codex 秒、OpenCode 毫秒混用。
- 项目配置不能把全局凭据引用挪到另一个 URL；新 command、URL、cwd、env 绑定应重新授权。

依据：omp 的广泛导入与禁用遮蔽、pi 的全局／项目信任边界、OpenCode 与 Codex 不同字段单位。**设计建议**。

环境变量支持 `${NAME}` 和显式 env/header 引用即可；缺失就报服务配置错误。不要隐式执行 `$(cmd)`。凭据与普通配置分开保存，日志脱敏；HTTP 跨源重定向不携带原授权头。依据：Crush 支持 shell 展开但增加执行面，omp 有跨源 header 策略，Codex 支持环境变量 token。**设计建议**。

### 9.5 生命周期默认值

| 参数 | 建议默认 |
|---|---:|
| 握手＋首次 tools/list 总预算 | 30 秒 |
| 后续一次目录刷新总预算 | 30 秒，含全部分页 |
| 工具执行 | 60 秒 |
| 资源读取 | 30 秒 |
| 重连间隔 | 0.5、1、2、4、8 秒 |
| 一次连续故障自动尝试 | 最多 5 次 |
| 稳定后重置故障预算 | 连续运行 30 秒 |
| 正常关闭输入后宽限 | 2 秒 |
| 强制结束及回收总预算 | 再给 3 秒 |
| 单帧接收上限 | 16 MiB |
| stderr 尾部缓冲 | 64 KiB |
| 模型文字结果预算 | 20 KiB，UTF-8 安全截断 |

以上均为**设计建议**。依据分别为 OpenCode／Codex 的 30 秒初始化、pi／DeepSeek 的 60 秒调用、omp 的有界退避与熔断、DeepSeek 的关闭屏障、OpenCode／pi 的帧限制和 pi 的输出预算；不是已经测出的最优参数。

在首次授权的本地主窗口会话建立时，后台启动启用的服务、发现工具；并发启动数建议先限 4。QQ 会话不触发本地 MCP 服务启动。已断开的连接按服务 single-flight 恢复；旧进程未确认退出时禁止再启动。认证失败进入 needs_auth，不反复弹浏览器。**设计建议**。

**工具调用默认不自动重放。** 连接建立、只读目录列举可以重试；工具调用超时、EOF、响应流中断都可能已经有副作用。即使重新连接成功，也返回“执行结果未知”，让模型先查状态。HTTP 事件恢复优先使用协议提供的 Last-Event-ID，而不是重新 POST tools/call。依据：omp 的 post-acceptance 标记、pi 对普通工具不做 transient retry。**设计建议**。

### 9.6 Windows 进程托管

Go SDK Transport 外增加自己的进程托管层，至少做到：

- 按最终 env 的 PATH/PATHEXT 找 executable，环境键大小写不敏感。
- `.exe` 直接 argv 启动；常见 npm shim 能可靠解析到 node＋脚本时优先直接启动。
- `.cmd/.bat` 用专门的 cmd 转义路径；不能 `strings.Join(args, " ")`，不能把 PowerShell 包一层当通用解决方案。
- 宿主无控制台和有控制台分别测试，不照搬一个 windowsHide 开关。
- Job Object 管理整树，尽量挂起创建、先分配 Job 再恢复；宿主结束时清理后代。
- stdout 只解析 UTF-8 协议帧，stderr 独立持续排空；不把整个协议输出过一遍控制台代码页转换。

依据：Codex 的 resolver、Job Object；omp 的 batch 注入、控制台继承处理；pi 的树清理与 UTF-8 framing。**设计建议**。

### 9.7 schema、结果与上下文

保存远端原始 inputSchema/outputSchema；给模型的 schema 是独立投影，不原地改。最小修补 object 根和 properties；供应商特殊限制放 `internal/llm` 的统一出口，避免 MCP 自己复制另一套适配。局部 `$ref` 要保留或正确重定位；不要无条件展开递归引用，也不要把“所有字段 required”当成修补。依据：OpenCode 统一出口、Codex 局部引用、pi 输出引用重定位、omp strict=false。**设计建议**。

公开 ID 采用 DeepSeek 的有损即 hash 规则：`mcp__server__tool`、64 字符、固定 SHA-256 后缀；目录中另存原始 route，排序稳定，最终碰撞明确拒绝。**设计建议**。

Sumika 还有一个前置缺口：目前 `tools.Result` 只有 Text、IsError，模型工具结果编码也只发字符串；图片读取仍明确报未迁移。不能声称 MCP 一接 SDK 就支持图片。出处：`S/native/internal/tools/exec.go:25`、`:247`、`S/native/internal/turn/loop.go:166`、`:227`。**读码确认**。

MCP 接入验收应包含结果链升级：

- 原始 content、structuredContent、isError 保留在运行记录。
- 模型投影按顺序保留文字、图片；不支持的媒体返回明确说明。
- resource_link 保留 URI 和服务器身份，按需读取，不自动抓任意 URL。
- structuredContent 若没有等价文本，追加一次 JSON，不能静默丢掉。
- isError=true 必须进入失败状态，不能只把正文当成功结果。
- 大输出截断只影响模型投影，完整内容放受同一听众权限保护的结果存储；不给 QQ 暴露本机路径或高权限内容。
- `_meta` 默认不进模型上下文。

依据：pi、DeepSeek 的原始结果／模型投影分离，以及 Crush 适配丢字段的反例。**设计建议**。

服务器 instructions、目录摘要经 `OnContext` 在回合开头追加，按“服务绑定＋内容 hash”去重；更新时追加新版本，不改旧 system 段。list_changed 只原子换内部目录，不直接改固定工具声明。MCP prompts 由主人主动选取，按其角色内容追加；不升格成不可覆盖的系统指令。依据：Sumika 8.1 的尾部追加约束、pi 的摘要追加、DeepSeek 的代次同步。**设计建议**。

## 10. 没查到、拿不准的地方

- **官方 Go SDK 完整协议日期**：确认了 Crush 固定依赖、Transport 和新订阅兼容代码；未取得该 SDK 修订的完整版本常量。本机尝试读取 `%USERPROFILE%/go/pkg/mod/github.com/modelcontextprotocol`，目录不存在。不能把 Crush 使用的库版本与已确认的协议日期画等号。
