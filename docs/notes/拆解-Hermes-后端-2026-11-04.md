## 三、一次用户输入怎么跑；循环、恢复和长会话

### 3.1 路径与写入顺序

- [读码] 外层 owner 接收输入并维护会话状态；`AIAgent` 负责该轮推理。典型路径：创建/恢复 turn context → 固定系统提示和工具 pin → 请求组装 → preflight token 压力检查 → provider 请求/重试 → 正规化输出 → 工具批或最终回答 → finalize。`_run_phase` 从 `_LoopState` 取阶段所需字段，并回收阶段 verdict 的 action/state。出处：`agent/conversation_loop.py:1480-1598,1750-1813`。阶段拆分是基线已有设计，不是本次新发明。
- [读码] 每次模型请求内有独立 retry loop：rate guard → build request → perform → check；中断走 interrupt，其他错误走 classifier/recovery。退款重启另有跨迭代 restart_count，避免 redirect/fallback 不断退预算形成无限循环。出处：`agent/conversation_loop.py:1490-1500,1557-1590`、`agent/turn_iteration_prep.py:355-380`。
- [读码] 关键 durable 边界：执行工具前，先把 assistant/tool-call 行写入 SessionDB；写失败→`session_persistence_failed`，本批工具不执行。工具结果写失败也不继续把仅内存结果送模型。UI 的 interim assistant 事件在写入成功后才发布。出处：`agent/turn_tool_round.py:132-192`。这证明“执行前有记录”；不代表 shell、网络、副作用能与 SQLite 同事务提交。
- [读码] 当前最终封装给所有退出路径盖 turn_id/current_turn_user_idx，避免历史压缩后边界仍指向旧位置；失败会补 Hermes 自己的 assistant 边界，错误及 error_surface 在落库前强制脱敏。出处：`agent/conversation_loop.py:1815-1897`。其价值是后续恢复知道哪一轮已经结束，而非把失败当新用户请求再执行。
- [读码] Codex app-server 是例外：整轮由外部 app-server 驱动，Hermes 做投影与工具桥接；`_codex_app_server_turn` 在 fallback 激活后保留已投影行和调用计数，改走通用循环。出处：`agent/conversation_loop.py:1607-1638`；`agent/transports/base.py:1-4` 说明普通 transport 只管格式，不拥有重试/凭据/缓存。两种执行权不能混写。

### 3.2 子代理：新的是路由策略接口

- [读码] 当前 `DelegationProvider` 只回答“这个 task 走哪个 model/provider/profile”，核心继续管深度、角色、并发、工作树、停止、结果、进度。跨接口都是 JSON，因而可以经 plugin host 执行。任务字段不能占用核心保留字段；路由失败只拒这一项，不让它悄悄用父模型。出处：`agent/delegation_provider.py:1-46`、`tools/delegate_tool_routes.py:1-7,29-52`。
- [读码] 路由可以指定 model/provider/base_url/api_mode/reasoning/fallback，也可以指定 profile。profile 路由忽略其它路由字段，采用目标 profile 的完整运行配置和凭据。settings 独立在 `delegation.backends.<name>`；默认 backend 在 `plugins/delegation/default`。出处：`agent/delegation_provider.py:15-32`。
- [读码] 每 task 的 service_tier 为 normal/fast/ultrafast；创建 child 前按该 route/account 核对是否支持，建好 child 后再钉一次，防止 provider 的 extra_body 把选择覆盖。不存在的 tier 拒绝，不悄悄降级。出处：`tools/delegate_tool_tuning.py:1-5,44-81`。
- [读码/API] `/delegation` 默认保存给下一会话，`--now` 才重建当前工具 pin；后续 task 必须沿当初构建 schema 的 backend 路由，防止模型看到旧 enum、执行却用新策略。证据：提交、、；`agent/delegation_provider.py:5-8`。默认并发10、child 独立迭代250、worktree isolation 可选的基本结构沿旧稿，不重抄。出处：`hermes_cli/config_defaults.py:1347-1365`；旧稿 `:6088-6107`。

### 3.3 压缩：提前准备，不提前改历史

- [读码] 原有 0.50 ratio、小于512K窗口抬到0.75、lean tail、最多3轮无效压缩等仍在。micro_compact/proactive prune 默认关闭；每次真正重写历史都会影响 prefix cache，因此不能把频繁后台摘要当免费优化。出处：`hermes_cli/config_defaults.py:573-621`。
- [读码] 真正新增 `compression.prepare_ahead`，默认关。provider 报告的 prompt 接近压缩阈值前12%带宽时，在工具批执行期间或回合结束启动一份后台 summary；每 compressor 只留一份，整个进程最多两个。工作对象是 compressor/message 副本，不改 live transcript，不提前破坏缓存。失败至少退避60秒。出处：`agent/prepared_compaction.py:1-11,52-64`；调用点 `agent/turn_tool_round.py:173-177`；提交。

## 四、运行环境：PM、打包、沙箱、worktree 各管一层

### 4.1 PM 确实是包管理，但不是通用系统包管理器

- [读码] `pm` 管 Hermes 自己依赖的 tool binaries、Python 环境、Node 依赖/sidecar 等。`ensure(name)` 让安装状态符合 pin 并返回带环境的 Runner；`env_for` 只组合已安装项；模块用 PEP562 懒导出，启动选择 Python 前不能先拉入 downloader 或第三方依赖。出处：`pm/__init__.py:1-49`。
- [读码/文档] 三套状态不能混：lock＝应该是什么；tool facts＝实际已装字节、导出环境；install facts＝这份 checkout/payload 选择了哪一代 Python。install key 是规范化源码路径 SHA256 前16位，不同 checkout/worktree 分开选环境；共享同一安装的 profiles 可贡献依赖联合。出处：`pm/environments.py:1-42`；`website/docs/reference/package-management.md:9-28,109-131`。
- [读码/API] 锁中的标准桌面/服务器 Python 从 `3.14.7+20260901`→`3.14.9+20261021`，uv `0.12.3`→`0.13.5`，Node `26.7.0`→`26.12.1`；Chromium `1208+145.0.7632.6`、git `2.53.0+3` 在两端不变。bionic 的 Python/Node/uv 有自己的 artifact，不能拿通用版本覆盖 Termux。证据：两端 `pm/lock.json` 中 packages 的 version/artifacts；当前 `pm/lock.json:1`（JSON 路径 `packages.python` 等）。
- [读码] 核心依赖直接使用 OpenAI/httpx/requests、Pydantic、Rich、prompt_toolkit、croniter、FastAPI/Uvicorn 等；浏览器执行新增默认 `browser-harness==0.1.13`。`requires-python >=3.11,<3.15` 是老安装升级桥，注释明确正式运行只支持3.14，不能据字段声称生产支持3.11～3.14。依赖表有 exact pins，也仍有明确范围项，不能概括成所有依赖全是 exact。出处：`pyproject.toml:10-17,19-39,72-85,131-151`。

### 4.2 安装/更新是一套有所有者的事务

- [文档＋读码] 源码安装由 launcher 在 import 第三方包前选 PM interpreter；输入戳变化触发 sync，然后以新 interpreter 重启。新环境完成验证才发布选择；进程保留旧 imports，必须 restart 才真正切代。packaged payload 直接从不可变包内运行，不是首开复制整份源码再 pip install。证据：`website/docs/reference/package-management.md:25-56,62-108,121-131`、`pm/environments.py:111-133`、`pm/publication.py:1-5`。
- [读码] `steward.py` 是“谁拥有安装树”，不是自动编程管家。`.git` 存在为可自管理源码；无 `.git` 看 install stamp 的 distribution，缺失→unknown 也拒绝自行删代码。desktop-app/docker/nix/apt-termux 分别交其发行机制升级/卸载；删用户数据另有操作。此文件窗口内完全不变。出处：`hermes_cli/steward.py:1-29,39-76,198-220`。
- [读码] `gateway_runtime_service` 只启动已登记且身份匹配的 systemd/launchd/Windows/s6 服务，不顺便重写 unit/plist，不因服务坏了就偷偷绕成无托管进程。不同 home 的 service suffix 绑定请求 home，自定义根用 hash，防止临时 profile 命中真实 bare unit。出处：`hermes_cli/gateway_runtime_service.py:1-5,37-57,89-146,149-176`。
- [文档＋读码] 窗口内 PM 补了中断下载进度、5xx mirror、损坏 uv cache、native sdist 编译器/CMake、继承 extras 与插件 dev groups。下载复用要校验长度/ETag/hash，没有强 validator 就重来；partial 不直接成为已发布工具。现有被继承 extra 编译不再可用时可报告并省略，临时下载错误则整次失败；用户显式请求的 extra 不能按此省略。证据：`website/docs/reference/package-management.md:131-139,199-215`；提交、、、、、。

### 4.3 工具打包与权限不是 PM 的职责

- [读码] 核心模型工具在 `toolsets._HERMES_CORE_TOOLS`，registry 按 toolset、可达性 check_fn、profile scope 筛选；MCP 不在 `model_tools` import 时做网络发现，避免最多120秒阻塞导入。工具定义缓存含 registry generation、check_fn epoch/有效期、config signature、profile 等。出处：`toolsets.py:11-25`、`model_tools.py:150-158,193-202,278-297`。

### 4.4 worktree 是现场隔离，不是权限隔离

- [读码] CLI/child 可以建 Git worktree、保留/归档/回收；删除前先检查 live lock、未推送提交、tracked dirt、skip-worktree/assume-unchanged 的隐藏编辑、嵌套 repo；不可归档内容保留。忽略文件通常被当可重建材料，不都保留。出处：`hermes_cli/worktree_gc.py:101-159`、`hermes_cli/worktree_retention.py:1-19,99-118`。
- [读码] 删除前 release 这棵 workspace 的 LSP clients，多根 server 则 detach folder，避免长驻 gateway 留下指向已删树的 tsserver。它是 best effort，不以 LSP 失败阻止删除。出处：`hermes_cli/worktree_ops.py:88-99`、`agent/lsp/manager.py:700-735`。
- [推断] 从这些约束可借“现场有 owner、可回收条件明确”；不能据 worktree 目录隔开就宣称文件读取、进程、网络、密钥都隔开。依据是 Git worktree 共享主仓对象且 terminal 另有完全独立的 backend/provider 策略，出处同上与 `agent/terminal_env_provider.py:23-56`。

## 八、插件与记忆：目录、依赖、进程隔离不是同一件事

### 8.1 如何安装与更新

- [文档＋读码] catalog 名称安装使用 YAML 中 HTTPS repo＋完整40位 SHA，可加 subdir；更新通过 catalog SHA-bump PR 与 `hermes plugins update`，不是插件自己换代码。Nous 也有 official-plugins/labs 等集合仓库，不能从 `hermes-plugin-*` 命名穷举能力。条目分 official/verified/community，runtime工具、hook、middleware、env必须披露。出处：`plugin-catalog/README.md:1-32,41-103,190-203`、`plugin-catalog/hermes-memory-wiki.yaml:1-17`。

### 8.2 进程 host 到底隔离多少

- [读码] 默认 `plugins.isolation=in_process`；host为每 profile 一个第三方插件进程，bundled仍在核心。通过 ctx proxy/JSON wire注册工具、hook、provider，回调携 origin上下文；自发后台工作绑定本profile，不继承碰巧第一个caller的session权限。host死亡工具返回错误、核心继续，重启预算600秒内3次，加载时致死的插件不回装。出处：`hermes_cli/plugin_isolation.py:1-18`、`hermes_cli/plugin_host.py:1-18,43-51,117-153,173-196`。

## 九、网关怎样给远程/手机用：后端证据交给手机端一路

### 9.1 新 Webapp 路径是本轮最明显的接入变化

- [读码] gateway自身同一HTTP listener服务Webapp，`webapp.enabled`开；默认host127.0.0.1、port9120，关闭时仍用临时loopback端口给native client。允许loopback或wildcard，wildcard/配置public_url触发登录gate。native clients由bind派生loopback地址，不拿0.0.0.0去拨。出处：`gateway/webapp_listener.py:1-48,112-149,184-204`。
- [读码] `webapp_access` 提供LAN 0.0.0.0和用户已有HTTPS反代/隧道两种配置形状。它配置地址和登录callback，不负责提供一个自带全球中继。Web Access的Nous OAuth client与独立dashboard分开，注册信息写home内user-only文件，不改dashboard client。出处：`hermes_cli/webapp_access.py:1-17,51-64,93-100`。
- [读码] 浏览器每次WS dial先POST `/api/webapp/socket-ticket`，一次性票据绑定socket种类与profile；gateway/host-terminal/voice各有能力门。浏览器签入绑定HMAC token generation，sign-out换browser credential，旧tickets不能开、新旧sockets会关闭。native login token与browser cookie token另记，不能混当同一注销范围。出处：`hermes_cli/web_routers/webapp.py:1-4,186-246`、`hermes_cli/webapp_sign_in.py:1-27,60-80`。
- [推断] 手机浏览器可以远程用持续在电脑/服务器运行的agent，不要求手机执行Python。这个结论来自HTTP/WS后台可访问形状；不能据此断言原生Android app已开源、APK已公开或手机本地能跑完整agent。UI/APK来源交另一路核对。

### 9.2 保持一份 owner，恢复一份状态

- [读码] `GatewayEndpoint` 描述profile/instance/authority_epoch/protocol/api_origin/code_sha等，不带凭据；ensure默认最多60秒，服务发现不应每客户端另起一个owner。ready可接，restart_wait的draining也可接以答审批/clarify，其余draining不能当新鲜空闲owner。出处：`hermes_cli/gateway_runtime.py:15-62,104-155`。

- [读码] `tui_gateway.ws` 是共用传输；先AuthorityConnection.dispatch，只有unknown method、旧表存在且legacy允许才退侧车；session writer不能靠fallback跨过规范owner。它也将读消息与慢handler分离，用256项dispatch queue维持ping响应，队满才背压。出处：`tui_gateway/ws.py:94-103,370-396`。
- [读码] 事件是epoch＋sequence，ring每session最多512帧/4MiB、全进程64MiB/最多64session，按冻结UTF8 payload计费；超大帧/淘汰都有truncation watermark，不会把有洞的列表当完整。epoch不同、cursor超前或缺口→snapshot_required。出处：`tui_gateway/event_replay.py:1-38,84-121`、`gateway/session_events.py:133-138`。

- [读码] ACP同样使用fresh session.resume投影、watermark跳过snapshot之前的帧；owner重启中断的pending会显示unknown，不自动重新提交。下一次连接失败可重建transport，不永远持有旧失败。出处：`acp_adapter/gateway_server.py:157-184,205-209,862-878`。
- [推断] 手机断线恢复需要“事件缺口→状态快照→明确unknown处理”，不是重新WebSocket连上后把最后一条用户消息再发一次；涉及发QQ、shell、支付等副作用时尤其不能把transport retry当业务retry。依据为上述admission/receipt/unknown设计；本次没有实际网络重连验收。
