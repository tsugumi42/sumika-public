## 1. OpenCode v2

### 项目说明文件

- **自动文件名是 `AGENTS.md`。** 用户全局来自 `global.config/AGENTS.md`；项目从当前 Location 向上找。位于 home 下时，发现边界可以到 home；在 home 外时止于项目根。不能概括成“一律止于 Git 根”。出处：`OC/packages/core/src/config/plugin/instruction.ts:35`、`:50`、`:84`。**读码确认**。
- **顺序是全局 → 最近的项目目录 → 更远祖先 → 显式配置。** 这份 v2 实现的项目说明顺序不是 root-to-cwd。发现容器明确说明按插入顺序渲染；测试也断言 global、package、project、shared 的顺序。出处：`OC/packages/core/src/instruction-discovery.ts:29`；`OC/packages/core/test/instruction-discovery.test.ts:241`。**读码确认**。
- `instructions` 配置还支持本地文件、glob、`~/`、HTTP(S) URL。远程请求时限 5 秒，并发 4；只在配置加载时抓取，普通文件重扫不重抓；失败保留上一次成功结果。出处：`OC/packages/core/src/config/plugin/instruction.ts:98`、`:119`、`:148`。**读码确认**。
- 文件监听后以 100ms 合并事件。说明源变化通过 hash 和语义差异表达；新增、删除、修改分别渲染，修改时比较 diff 与全文替换的长度，选较短者。临时不可用保留已经接纳的值。出处：`OC/packages/core/src/config/plugin/instruction.ts:211`；`OC/packages/core/src/instructions/index.ts:140`；`OC/packages/core/src/instruction-discovery.ts:127`。**读码确认**。
- **子目录说明在成功 `read` 后发现。** 文件从父目录起找，目录列表从目录本身起找；排除已由初始说明覆盖的 Location 及祖先，跳过外部目录，发现失败不让 read 失败。发现内容写成持久 synthetic 消息；转换后模型看到 user 角色。出处：`OC/packages/core/src/tool/plugin/read.ts:83`；`OC/packages/core/src/session/instructions.ts:47`、`:80`；`OC/packages/core/test/session-instructions.test.ts:324`。**读码确认**。
- 去重账本依据**当前模型可见历史**，并发读取另有 in-flight claim。压缩或回退移除 synthetic 后，能够重新注入。这里按路径去重，不能据此声称已加载的子目录文件发生变化会自动再次注入。出处：`OC/packages/core/src/session/instructions.ts:39`、`:59`、`:113`。**读码确认**。
- 在上述加载器中没有找到项目说明的专用总字节上限、递归 `@文件` 展开，也没有找到首次打开项目必须确认的逻辑；加载会经过文件系统访问限制，sandbox 拒绝的文件可被跳过。出处：`OC/packages/core/src/config/plugin/instruction.ts:64`；`OC/packages/core/test/instruction-discovery.test.ts:645`。**读码确认；未找到范围限于这些位置**。

## 5. omp（oh-my-pi）

### 项目说明文件

- 通过 capability provider 聚合，而非一个固定文件名数组。普通 `AGENTS.md`、`CLAUDE.md` provider 优先级都是 10；native `.omp` 为 100、Claude 80、共享 `.agent/.agents` 与 Codex 70、Gemini 60、OpenCode 55、GitHub 30 等。每个 user scope 一份、每个项目深度一份，高优先级 provider 遮蔽低优先级；显式 extra 文件是 additive。出处：`OMP/src/capability/context-file.ts:34`；`OMP/src/discovery/agents-md.ts:24`；`OMP/src/discovery/claude-md.ts:24`；各 provider 的 `PRIORITY` 声明，如 `discovery/builtin.ts:45`、`claude.ts:44`。**读码确认**。
- standalone walker 通常止于 repo root；但 repo 在 home 下时，会继续找 workspace 祖先直到 home 之前。非仓库且在 home 下，可到 home；其他情况可到盘根。它有 Windows 大小写比较。出处：`OMP/src/discovery/helpers.ts:686`、`:711`。**读码确认**。
- 聚合后先展开 `@`，再按深度排序；较深目录更靠后。还做规范化段落序列包含去重：较具体文件完整包含祖先段落时，可以省略祖先全文。出处：`OMP/src/system-prompt.ts:323`、`:354`。**读码确认**。
- **实现递归 `@文件`，默认最多 5 跳。** 相对路径基于引用文件所在目录，支持 `~/`、转义空格，跳过 fenced code 和 inline code；读不到或遇到已访问路径保留原 token。visited 为整棵展开树共享，因此重复引用同一个文件也会被抑制，不只是阻止递归栈循环。出处：`OMP/src/discovery/at-imports.ts:33`、`:67`、`:126`、`:168`。**读码确认**。
- 说明参与 system prompt 构建；另从 workspace tree 收集子目录 `AGENTS.md` 路径，排序、限制条数，提示模型进入目录修改前读取。**这条路径是目录索引 + 模型读取，不是 OpenCode 那种 read 后自动注入正文。** 出处：`OMP/src/system-prompt.ts:774`、`:864`；`OMP/src/prompts/system/project-prompt.md:18`。**读码确认**。
- 通用发现文件缓存包含内容和不存在的结果，支持 clear/invalidate；只读普通文件，避免 FIFO 等挂住。不能据此认定所有外部编辑会即时生效。出处：`OMP/src/capability/fs.ts:4`、`:11`、`:110`。**读码确认**。
- 在这些 context provider、system prompt、文件缓存中没有找到统一的说明字节总预算或首次项目确认；`@` 路径展开本身也没有 realpath 后的 root containment 检查。出处：`OMP/src/discovery/at-imports.ts:168`、`:184`。**读码确认；确认范围限于这条路径**。

### Skill

- 用户可开关不同生态来源。`loadSkills` 默认开启 Claude project、Pi user/project、Agents user/project；默认关闭 Codex user、Claude user，另有 native、插件、安装包和 customDirectories。发现必须结合来源开关，不能简单写成“扫到的都加载”。出处：`OMP/src/extensibility/skills.ts:287`、`:360`。**读码确认**。
- 普通本地 scanner 扫直接 `<child>/SKILL.md`，部分来源可 includeSelf；name 回退目录名，拒绝 `/`、`\`，description 可按来源要求，`enabled:false` 跳过。普通扫描不是严格规范校验。出处：`OMP/src/discovery/helpers.ts:424`、`:463`、`:488`。**读码确认**。
- **Agent Plugin 来源有另一套严格规则。** 只接受标准六字段；name NFKC 后最多 64 字符、lowercase、合法连字符、目录名匹配；description 1024、compatibility 500、metadata string map、allowed-tools 必须 string。它支持 Unicode 字母/数字，与其他家的 ASCII 校验不完全一致。出处：`OMP/src/discovery/agent-plugin-format.ts:91`、`:101`、`:127`。**读码确认**。
- 同名处理最完整：普通先接纳者保留裸名；作者本地 skill 胜过安装 registry 包，custom directory 胜过 provider；正文和 frontmatter 都相同则合并，不同则保留为 `<namespace>/<name>`，冲突再加 `~N`。出处：`OMP/src/extensibility/skills.ts:117`、`:145`。**读码确认**。
- 最终目录按大小写无关名字 → 原名字 → 路径排序；只有存在声明能读取 `skill://` 的工具时才展示目录；hide、disableModelInvocation 隐藏目录条目。模型用 `read skill://name` 读全文，用户也可 `/skill:name`。出处：`OMP/src/extensibility/skills.ts:601`、`:613`；`OMP/src/system-prompt.ts:935`。**读码确认**。
- `skill://name/path` 解析资源路径，拒绝 `..` 越界；Agent Plugin 再 realpath 校验，资源必须在**插件包根**内，允许同包其他目录。普通非插件 skill 没有同样的 canonical containment。资源只在需要时读取；脚本不因加载而自动运行。出处：`OMP/src/internal-urls/skill-protocol.ts:89`、`:102`、`:183`。**读码确认**。
- `allowed-tools` 在严格格式里被验证，但在普通 skill 结构、加载与 URI 执行链中没有找到它改变执行授权。`skill://` 资源标为 unbounded，也不适合直接照搬为无限读取。出处：`OMP/src/extensibility/skills.ts:30`；`OMP/src/internal-urls/skill-protocol.ts:126`。**读码确认；权限结论限于查过的调用链**。

## 8. Agent Skills 开放规范与各家偏差

规范要求 `SKILL.md` 加 YAML frontmatter；name 必填、1–64、lowercase 字母数字连字符、不得首尾/连续连字符、须匹配父目录；description 必填、最多 1024；可选 license、compatibility（最多 500）、metadata string map、实验性 allowed-tools。先展示元数据，激活再读主文，附件按需读取；主文少于 500 行、约 5000 tokens 是建议，不是强制解析上限。出处：[Agent Skills specification](https://agentskills.io/specification)，Frontmatter、Progressive disclosure、File references。**读文档**。

网页对 Unicode 的表述不够统一：一处写 “unicode lowercase alphanumeric”，同时举 `a-z`、`0-9`；omp 的 Agent Plugin 校验显式对齐 skills-ref 的 Unicode/NFKC 行为，pi 和 DeepSeek 采用 ASCII。Sumika 需要明确自己选择，不能声称 ASCII 正则就是覆盖所有生态实现。出处：同上；`OMP/src/discovery/agent-plugin-format.ts:101`；`PI/dist/core/skills.js:65`；`DS/packages/skill/skill/src/index.ts:21`。**读文档 / 读码确认**。

| 实现 | 对规范的实际关系 |
|---|---|
| OpenCode v2 | 兼容目录布局与渐进披露；name、description 可选，ID 与展示名分离，不做严格规范校验。 |
| Crush | 明确声称实现规范；字段、长度、目录一致性较完整，但允许大写，用字节计长度，未解析 allowed-tools。 |
| Codex | 兼容 SKILL.md 生态；解析宽松，并扩展 `agents/openai.yaml`；不是严格格式验证器。 |
| DeepSeek harness | 相同核心布局与按需加载；支持平铺文件、自定义字段；缺标准长度与目录名一致校验。 |
| omp | 必须分来源看：普通本地兼容宽松，Agent Plugin 六字段严格校验。 |
| pi | 明确按规范生成警告，但多数格式违规仍继续加载；支持平铺文件与调用扩展字段。 |

以上对应各家 parser 出处见前六节，均为**读码确认**。`allowed-tools` 在规范中是“预批准工具”的实验字段，**不能自动理解为隔离沙箱，也不能因 skill 写了它就提高 Sumika 权限**。前半为**读文档**，后半为基于 Sumika 审批约束的**推断**。

## 10. 给 Sumika Go 的具体建议

本节全部是**推断：设计建议**，不是已实现状态。

### 10.1 插件分工与现有接口缺口

建议两个编译内插件：

- `project-instructions`：说明发现、引用展开、版本差异、作用域、尾部渲染。
- `skills`：目录、名称解析、正文与资源读取、可见性过滤。

共用小型文件缓存和路径边界函数，不引入运行时第三方插件框架。依据：Crush workspace Manager、DeepSeek 分包方式，以及 Sumika 已选编译内插件。出处：`CR/internal/skills/manager.go:13`；`DS/packages/skill/tool-skill/src/index.ts:78`；`SUM/docs/规格-Go后台.md:336`。

**现有 `ContextIn` 没有 cwd、workspace ID、请求中已成功接纳的说明记录；`ToolCall` 也没有插件的 `State`。** 不能让 skill 工具直接偷用 `OnContext` 的 map，更不能以进程 cwd 代替会话 cwd。出处：`SUM/native/internal/turn/plugin.go:38`、`:102`。**读码确认**。

建议由本地主窗口持有会话级：

```go
type Workspace struct {
    ID          string
    CWD         string // 绝对路径，显式选定
    Root        string // worktree 根；无仓库时等于 CWD
    Trusted     bool
    Revision    uint64
}
```

插件通过宿主注入的只读 `WorkspaceResolver` 按会话、权限档解析；QQ 返回“无工作区”。不用向所有渠道暴露一个可伪造的 cwd 参数。依据：Sumika 现有 audience 隔离约束；DeepSeek 按 agent scope 查目录。出处：`SUM/docs/规格-Go后台.md:351`；`DS/packages/skill/tool-skill/src/index.ts:134`。

`OnContext` 做初始快照和回合间更新，插话机会同样核对。**不追加模型每步前的通用 context 重写钩子。** 依据：`SUM/native/internal/turn/plugin.go:3`、`:38`；`SUM/docs/规格-Go后台.md:342`。

### 10.2 子目录规则：不能靠 OnContext 单独完成

当前 `OnContext` 只在回合起点和插话时调用。一次工具读完子目录后，同轮模型可能马上编辑；等到下一回合才给规则会晚。`OnSeen` 是聊天事件，`OnSettled` 是整轮结束，均不能替代文件读取事件。出处：`SUM/native/internal/turn/plugin.go:3`、`:73`、`:218`。**读码确认**。

建议在**文件工具的组合层**注入一个窄接口，不开放通用“任意插件改工具结果”：

```go
type InstructionResolver interface {
    ForPath(
        ctx context.Context,
        workspaceID string,
        target string,
    ) (InstructionSnapshot, error)
}
```

- `read/ls` 成功结果带目标目录作用域说明，作为这次工具结果的一部分尾部追加；不改旧消息。
- `write/edit` 也走同一个 resolver。若这批作用域规则尚未给模型，先返回规则和“尚未执行，请按规则重新调用”，避免同批 read+edit 并发时先写后知道规则。
- `powershell` 可以任意改文件，不能谎称能从命令字符串完整推导路径。提示模型进入新目录前用文件工具读取该目录规则；执行权限仍由现有 policy 管。

这是为本题补的文件工具组合接口，**不是现有 `Registry.OnTool` 就能覆盖内置工具**：注册器明确拒绝内置重名。依据：OpenCode read 后加载、DeepSeek touch 生命周期；`SUM/native/internal/turn/plugin.go:260`。

若不补这个组合入口，可用单独 `project_context(path)` 工具实现显式读取，但只能保证“模型调用时可用”，不能宣称自动加载与编辑前生效已完成。

### 10.3 工作目录与说明发现顺序

**工作目录是本地主窗口会话明确选定的绝对路径。** shell 执行 `cd` 只影响那次 shell，不暗中改变会话工作目录；改变工作目录由本地界面操作，产生新 workspace revision。QQ 不继承最近使用的本地目录。

建议默认发现：

1. Sumika 用户配置根的一份全局说明：`AGENTS.override.md` → `AGENTS.md`。
2. 项目 worktree 根到 cwd，每目录取一个基础文件：  
   `AGENTS.override.md` → `AGENTS.md` → `CLAUDE.md` → `CONTEXT.md`。
3. 每目录再追加一份 local：`AGENTS.local.md` → `CLAUDE.local.md`。
4. 子目录沿相同候选规则按需加载。
5. 自定义 fallback 文件名可配置，必须是单个文件名，拒绝路径分隔符、NUL、盘符/ADS 语法。

`CONTEXT.md` 作为低优先级兼容 fallback，避免把普通文档误作必加载规则。`CLAUDE.md` 默认只作 fallback，不与 AGENTS 重复全收；这是有意选择 Codex/pi 的单基础文件策略，而非 DeepSeek 的全收策略。local 的追加语义需要在自带说明书明确写出。

依据：Codex 单目录候选与路径校验、DeepSeek local overlay、pi worktree 去重。出处：`CX/core/src/agents_md.rs:272`；`DS/packages/context/agent-instructions/src/config.ts:11`；`PI/dist/core/resource-loader.js:128`。

默认止于最近 `.git` 标记，支持标记文件；无标记只用 cwd。不要默认扫到用户 home 或盘根。需要 workspace 祖先规则时由主人显式加 root，避免临时目录意外继承外层规则。依据：Codex、DeepSeek 的有界发现，以及 omp/pi 的越界继承成本。

### 10.4 说明预算、引用与更新

建议参数：

| 参数 | 默认值 | 处理 |
|---|---:|---|
| `maxSourceBytes` | 1 MiB | 先限量读取；超限跳过并报告，不先整文件读入 |
| `maxRenderedBytes` | 32 KiB | 包含路径、框架、截断标记 |
| `maxImportDepth` | 5 | 包含根为第 0 层的定义写清楚 |
| `maxImportFiles` | 64 | 防宽度爆炸 |
| `readConcurrency` | 8 | 有界并发，不照搬 unbounded |
| 普通文件变更核对 | 每回合起点 | 热路径 stat；内容变化才重新解析/hash |
| 同轮触及核对 | 文件工具边界 | 不重扫整个项目 |

32 KiB 参考 Codex，source 1 MiB 与 UTF-8 边界参考 DeepSeek；并发 8、引用文件数 64 是待基准验证的初始选择，**不是六家共同标准**。

`@文件` 参考 omp 的语法：相对引用文件、支持空格、跳过代码块/inline code；但需要额外做：

- 只读普通文件。
- realpath 后检查允许根；项目默认只允许当前受信工作区，用户全局引用只允许显式用户配置/资源根。
- Windows junction、symlink、UNC、ADS、大小写统一纳入边界判断。
- 用 canonical identity 防循环；拒绝越界时保留引用并给可见诊断。
- 所有展开字节计入同一预算，不因 include 重置额度。

依据：omp `at-imports` 有深度但无 canonical root 边界；Codex 与 omp Agent Plugin 都校验资源包边界。出处：`OMP/src/discovery/at-imports.ts:168`；`CX/ext/skills/src/loader/host.rs:216`；`OMP/src/internal-urls/skill-protocol.ts:102`。

变更消息用**完整的新正文替代同路径旧版本**，删除用 tombstone，默认不生成 patch。理由：Go 端实现更简单，模型不必还原多次 diff；32 KiB 已有上限。借 OpenCode 的差异状态和 DeepSeek 的 replace/remove 语义，不照搬 patch 优化。

账本至少记：

```text
workspace revision
权限档 / 可见性指纹
模型上下文 epoch
规范化来源 ID
完整内容 digest
实际渲染内容 digest
截断状态
```

只有真正进入模型上下文的内容才能记为已给。压缩切换 epoch 后，重新给当前有效快照；不能让 `State` 永久记住“以前给过”。若当前内核没有成功接纳或 epoch 信号，需补一个只读上下文代次/接纳结果接口；不能假定 `ContextFn` 返回即已经被模型看见。依据：DeepSeek 的预算提交测试和 OpenCode 当前历史账本。

### 10.5 Skill 发现、格式与加载接口

建议发现优先级明确为：

1. 主人在设置里显式配置的覆盖目录，数组顺序。
2. 当前可信项目中 cwd → worktree 根的技能目录；越近优先。每层顺序 `.sumika/skills` → `.agents/skills` → `.claude/skills`。
3. Sumika 用户配置根 `skills/`。
4. `~/.agents/skills`。
5. `~/.claude/skills`，兼容开关默认关闭。
6. 编译内 `embed.FS` 自带 skills，最低覆盖优先级。

**优先级与最终展示排序分开。** 同名胜者按上述规则确定；同一实际文件去重；其他冲突记入本地诊断，不让文件遍历完成顺序决定胜者。插件自带来源保留 `builtin:<name>` 稳定 ID，避免覆盖后失去诊断能力。依据：Crush 编译资源、omp 来源开关/冲突诊断、pi realpath 去重。

默认只扫直接 `<name>/SKILL.md`，不递归扫 `scripts/references/assets`。平铺 `.md` 仅兼容开关开启；若显式允许分类嵌套，深度最多 6。每 root 最多 2000 个目录、20,000 entries，超限有诊断，不能静默“看起来成功”。目录规模限制参考 Codex；默认直接子项参考 omp、DeepSeek。

格式建议：

- 必填 name、description。
- name 1–64 Unicode 字符，NFKC 后 lowercase 字母/数字/连字符，无首尾/连续连字符；与父目录规范化后匹配。
- description 1–1024 字符；compatibility 存在时 1–500。
- license string、metadata string map、allowed-tools string 原样保存。
- 支持 `disable-model-invocation`、`user-invocable`，默认 false/true。
- BOM、CRLF 正常解析；拒绝重复关键字段和多文档 YAML；未知字段保留并报告，不能转换为宿主配置。
- 不自动修补任意坏 YAML；错误应明确到文件和字段，坏一份不影响其他目录。

依据：Agent Skills 规范、omp Agent Plugin 验证、Crush 换行兼容、DeepSeek 坏条目隔离。Unicode 选择需要以官方 skills-ref 样本补验，见不确定项。

建议只注册一个只读 `skill` 工具：

```text
skill({name})                       读取当前可见 skill 主文
skill({name, resource, offset, limit}) 读取该 skill 包内资源
skill({query, cursor, limit})        搜索/分页目录
```

三个互斥参数分支由 schema 表达，避免再建立第二套任意文件读取工具。正文带来源、版本、资源基 URI；附件不预展开；脚本仍由现有 powershell 等工具执行并过审批。

建议预算：

| 项目 | 默认值 |
|---|---:|
| 初始 skill 目录 | 8 KiB 渲染文本 |
| 单条展示描述 | 最多 512 字符 |
| 目录分页 | 20 条 |
| 单次主文或资源返回 | 32 KiB，支持续读 |
| 单个资源可读大小 | 1 MiB |
| 自动调用开关 | 默认允许 |
| 用户调用开关 | 默认允许 |

超目录预算时给出实际显示数量和查询入口，不静默裁掉尾部；显式名字仍可解析全部**可见**目录。主文分页返回必须明确还有后文，不能像完整 skill 一样宣称已读完。依据：Codex 的独立目录/资源预算和分页、DeepSeek 的描述截短；32 KiB 返回是本设计初值。

### 10.6 权限、渠道与信任边界

**加载 skill 不授予任何新工具权限，不免审批。** 标准 `allowed-tools` 暂作兼容元数据与说明展示，不实现 Bash(...) 一类字符串到 PowerShell 权限规则的猜测转换。若以后要执行“仅允许这些工具”的限制，需另立宿主可验证的策略契约；不能把实验字段直接当能力授权。

建议分清：

- `disable-model-invocation`：模型不能自主加载。
- `user-invocable`：直接用户能否点名加载。
- 宿主 audience/policy：这一轮到底能看哪些目录、读哪些资源、执行什么工具。

QQ：

- 没有 workspace，不发现项目说明和项目 skills。
- 不给本机绝对路径，不复用本地主窗口目录缓存。
- 只可看显式标记适用于该听众/渠道的自带或用户 skills。
- 若允许 QQ 加载纯说明类 skill，资源读取只能访问该 skill 已授权的只读包；不能因此拿到通用本地 read 或 powershell。
- 目录和执行都重新按当轮 audience 检查，不能只在实例创建时判断一次。

依据：DeepSeek 精确工具可见性与 scope、Sumika 按权限档分实例和 policy 的前置限制。出处：`DS/packages/skill/tool-skill/src/index.ts:210`；`SUM/docs/规格-Go后台.md:351`；`SUM/native/internal/turn/plugin.go:91`。

项目说明属于**仓库提供的任务指导**，不能覆盖宿主角色、直接用户指令和工具策略。首次本地主窗口打开未信任工作区，建议沿用一次工作区信任选择；拒绝时不自动载入项目说明和项目 skills，仍可普通聊天。无需每次文件更新再次确认。理由：Codex 明确跳过不可信项目说明，pi 把项目 skills 纳入信任资源；仓库内 Markdown 本身不是可信授权来源。

### 10.7 性能实施原则

- 不在热轮次递归扫描项目，不遍历 node_modules。
- workspace 层缓存解析结果；实例层只记可见上下文状态。缓存 key 含 workspace revision、权限可见性，不能按进程 cwd 单例。
- watcher 只标 dirty，不能直接改模型历史；回合边界消费 dirty，并保留 stat 核对作为 watcher 丢事件的补偿。
- 文件版本不变不重读正文；目录没变不重新格式化整份 skill 目录；只有 digest 改变才追加。
- `Setup/cleanup` 管 watcher 和任务取消；已卸载插件的晚到结果交由内核丢弃。
- 默认并发有界，按测试记录实际 bytes read、entries scanned、allocs、耗时；达到同机比较目标后再调整并发，而非照搬 JS 的 unbounded 或 Rust 远程探测并发。

依据：DeepSeek version 快路径、watcher LRU，OpenCode 100ms debounce 与 unavailable 状态，Sumika 插件超时/撤销契约。出处：`DS/packages/context/agent-instructions/tests/agent-instructions.spec.ts:3986`；`DS/packages/skill/skill-filesystem/src/index.ts:619`；`OC/packages/core/src/config/plugin/instruction.ts:211`；`SUM/native/internal/turn/plugin.go:119`、`:204`。
