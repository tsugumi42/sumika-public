### 1.2 一轮的公开数据流

`[文档]` 可以从 ACP、hook 和 headless 契约还原出的外部流程如下；它不是源码级调用栈：

1. 客户端 `initialize`，之后 `session/new` 或 `session/load`，传 `cwd`、`mcpServers`、可选 `_meta` 规则和权限参数。
2. `session/prompt` 提交内容；`UserPromptSubmit` hook 可以拒收用户输入。
3. 服务发 `session/update`，分别携带 `agent_message_chunk`、`agent_thought_chunk`、`tool_call`、`tool_call_update`、`plan`。
4. 模型提出调用后，宿主执行 hook、权限规则、授权和工具，结果进入继续推理的消息；流式 Messages 格式用 `tool_use.id` / `tool_result.tool_use_id` 关联。
5. 工具后的下一次模型响应可能继续调用工具；结束时记录用量、会话更新并触发 Stop 类事件。后台任务完成也可唤醒新的回合。

出处：U15:95–146、209–215；U10:90–116；U14:315–335；U20:193–207。`[本机帮助]` H0 的 `--max-turns` 和四种 output format 证明有多步 Agent 执行与机器输出入口；精确循环退出分支、锁和线程调度未知。

### 7.2 子代理消息

`[文档]` `send_subagent_message` 默认关闭，需 `active_agent_messages`。`delivery` 有三种：

- `steer`：下一安全点进入当前 turn。
- `queue`：保护成后续独立 turn，不被并入当前回合。
- `interject`：排在 steers 前，能提前结束正在等后台的 wait；后台工作仍运行。

inactive child 收到消息会以同一个身份苏醒；active 但 between-turns 时 steer/interject 变成 protected queued turn。每 sender-target 最多 **4 in-flight**，每 sender attempt 最多 **32 outbound**，超额 `QuotaExceeded`。child 可以向符合条件的 parent/peer 发消息，但 root 直接子代理不能反向给 root 发消息。出处：U16:165–201。没有本次运行证明这些高级接口在 1.0.70 已启用。

### 7.3 后台任务和定时队列

`[文档]` shell 用 `block_until_ms:0` 立即返回 task ID；`get_command_or_subagent_output` 的 `task_ids` 最多 **20** 个，正超时等所有 ID 完成，最多 **3,600,000 ms**。完成后自动通知/唤醒父会话。`kill_command_or_subagent` 对 shell 发终止信号，对 child 发 Cancel/Shutdown；跨平台具体信号实现没有实测。出处：U20:7–33。

`[文档]` `/loop` 最短 **60 s**，创建后立即执行，周期任务 **7 天** 到期，最多 **50** 个；每次 firing 是 detached background subagent，**不继承当前对话**，stored prompt 必须自包含。底层 scheduler 有 `fire_immediately/recurring/durable` 字段，durable 默认 false；`monitor` 将合并 stdout/stderr 的每行转通知，过量自动停，但数量阈值未给。出处：U20:56–175；WBG。

### 8.4 hooks 与执行后的模型视图

`[文档]` hook 可 shell command 或 HTTP endpoint，按 session / turn / tool cadence 运行。事件包括 SessionStart/SessionEnd、UserPromptSubmit、PreToolUse/PostToolUse/PostToolUseFailure、PermissionDenied、Stop/StopFailure/StopCancelled、Notification、SubagentStart/SubagentStop、PreCompact/PostCompact。Stop 可拒绝结束并把缺口反馈给模型。出处：U10:7–15、90–116；WH。

`[文档]` handler 输入为一行 JSON，含 sessionId/cwd/workspaceRoot/permissionMode/toolName/toolInput 等；PreToolUse 可 allow/deny/ask/defer、重写参数、追加带来源 reminder、停止 turn。多 hook 参数重写最后一个获胜，deny 丢弃重写；重写不得把 use_tool 改投另一个 tool。普通 hook 超时/崩溃可能 fail open，不能把任意 hook 当不可绕过边界。出处：U10:118–122、377–433。

`[文档]` PostToolUse 的 `updatedToolOutput` 只换模型读取的副本，真实工具输出仍留记录；post 的 block 是告诉模型有问题，不是回滚已发生动作。UserPromptSubmit 拒收则不写模型对话和 session record，队列等待用户处理；local prompt history 仍可能保留。出处：U10:14、118–122、435–458。

### 8.5 无界面、多模型与失败回退

- `[本机帮助]` H0 支持 `-p/--single`、prompt-file/prompt-json、max-turns、json-schema，输出 `plain/json/streaming-json/streaming-messages-json`。HA/HS/HW 另给双向 ACP 与 WebSocket；流式 JSON 输出本身是只读，不承载审批回包。`[文档]` U14:328–383；U15:95–105。
- `[文档]` 自定义模型支持 chat_completions / responses / messages 三种 API，model 与 catalog name 分开，provider 块可共享 endpoint/header/limit。可按子代理 type、role、persona 选模型。主会话可 `/model` 或 ACP `session/set_config_option` 换 model/effort。出处：U11:72–104、131–147；U16:133–143、269–287；U15:190–204。
- `[文档]` 失败处理有 max_retries、429 threshold、inference idle timeout；subagent 在未设置 sampler threshold 时有独立限流等待路径，文档给累计 **150 s** 等待预算，配置 threshold 后关闭这条路径。出处：U11:153–177；U26:467–470、512–516。这证明重试策略可配，不证明失败会自动换别的模型。
- `[文档]` 没有找到“推理失败后按固定候选模型序列降级”的公开契约。模型目录缓存失败回退与推理模型 fallback 是两件事；U26:506 只讲 daemon route 目录缓存（同版最多 7 天）与 Auto，不据此写成推理容灾路由。

### 8.6 用量、费用与可观测性

`[本机帮助]` HU 支持按 session 和可选 turn 读持久 token/cost；HT 可以 trace 导出/上传，`--local` 跳过远端上传，output 要求目标不存在。本次只读帮助，没有导出或上传。

`[文档]` headless JSON ledger 包括主模型回合与 turn 结束前已完成子代理；compaction/其他 side-model calls 排除。`num_turns` 是有 usage 的主 Agent model rounds，不是用户消息数，也不包含 child sampler calls。费用不完整时 `cost_is_partial`、usage 不完整时 `usage_is_incomplete`；完整费用才有 dollars 和整数 ticks（**1 USD = 10^10 ticks**）。OAuth/pool 未报价格不能当免费。出处：U14:218–245。

`[文档]` `streaming-messages-json` 为兼容 schema，未知费用/用量可数值回填 0，而普通 json 可省略字段；因此同一个 0 在不同格式的可解释性不同。每行 uuid 也不是 provider/message correlation key，关联应看 message id / tool-use id。出处：U14:328–335、353–357、377–381。

`[文档]` 日志有 `GROK_LOG_FILE/RUST_LOG`、本机 unified log 路径；OTel 导出 metrics/events，指标包括 token、turn outcome、TTFT/TTFM、API/tool duration、permission decisions；content/details/prompt 可分开门控，`grok_code.compaction` 带 before/after/duration。没有独立 cost.usage metric，组织可把 tokens join 价格表。出处：R:2638–2657；U24:235–275、293–307。未实际打开日志、收 trace 或测延迟。

## 10. 本家值得单列的设计（不声称业界唯一）

1. **完成声明交给独立核验。** `[文档]` `/goal` 把可测条件、候选完成、reviewer 核对、继续/暂停组织成宿主行为；比单靠主模型“觉得完成”更有可追责的结束条件。核验者是否更强未知。出处：WCMD；U04:320–338。
2. **研究报告以 claim 为核验单位。** `[文档]` `/deep-research` 不是把多份摘要直接拼接，而是 researcher → independent verifier → 保留通过的 claims/source locators；覆盖不足标 Partial，适合把可证实程度传给读者。出处：U04:340–350。
3. **MCP catalog 与模型工具前缀解耦。** `[文档]` 固定 search/use 元工具，远端 `server__tool` 在 catalog 内；结果溢出保全文、大参数走有界文件快照。值得比较的收益是减少一次性披露全部 schema、减少大 JSON 重复传输，同时保留审批真实目标。实际 cache 提升未量。出处：U07:45–61、184–217、236–277；U17:27–42。
4. **插话语义与任务取消分开。** `[文档]` steer/queue/interject、send-now、background 是不同动作；尤其 urgent interject 只结束 wait、后台继续，可降低“为了说一句话误杀长任务”的风险。具体 cancellation races 未实测。出处：U16:165–201；U03:350–356；U20:43–52、199–207。
5. **模型输入、界面事件、真实输出分别留记录。** `[文档]` `updates.jsonl/chat_history.jsonl/system_prompt.txt/tool_definitions.json` 让恢复与请求追查有各自依据；PostToolUse 可只改模型副本，保留真实输出，便于查“模型到底看到什么”。出处：U17:27–42；U10:14、435–458。
6. **记忆捕获与整理分离，并有完成屏障。** `[文档]` turn 后 capture → observations inbox → Dream topics → bounded index；`/flush` 明确等待停止或完成的 turn 捕获结束。普通 Markdown 可读可改，索引预算可控；没有效果评测不能声称召回更好。出处：U13:19–38、125–145、259–295。
7. **用量缺失是显式状态。** `[文档]` json 把 partial/incomplete 与真实 0 分开，token buckets 互斥、费用提供整数 ticks，避免将 child 未计入和 OAuth 未报价写成完整低费用。流式兼容格式的 0 回填又明确披露限制。出处：U14:218–245、353–357、377–381。

## 11. 给 Sumika 的启发

以下是建议，不是本次实现，也不据此改变工具权限或记忆可见性。Grok 的事实仍只用上文 `[文档]` / `[本机帮助]`；Sumika 定位来自本工作树对应代码的具体符号。

1. **把 queue、steer、打断当前回合、取消后台任务做成明确的交付契约。** `[文档]` 可借 Grok 的动作拆分与“只打断 wait、任务继续”语义（U03:350–356；U16:177–189；U20:199–207）。Sumika 已有 `Steering` 的 accepted/delivered/dropped/Requeue（`native/internal/turn/steer.go:13–68`）和 `Hub.SteerIn`（`native/internal/turn/hub.go:390–417`）；应在这些状态上补明确的交付方式，而不是以“新输入”隐式决定是否杀工具。现有工具批次是否可中断等待，需要另行设计，本文不假定已经支持。
2. **为将来的大规模外部工具保留按需 schema 目录，执行仍走现有授权门。** `[文档]` 借 MCP 的 search/use catalog 和完整目标审批（U07:236–277）。Sumika 对应 `plugins.toolsFor`（`native/internal/turn/plugin.go:306–328`）、`runTools`（`native/internal/turn/loop.go:538–575`）、`policy.Spec`（`native/internal/policy/policy.go:16–25`）。已有 `linkplugin` 的短摘要→详情工具是内容按需读取的例子（`native/internal/linkplugin/plugin.go:4–8、327–328`），可复用这个产品思路；它不等于已有 MCP schema 延迟加载。目录可见性和每次执行仍须按当轮 audience、注册身份和 Gate 核对。
3. **项目知识优先借“有预算索引→按需打开原文”，不要复制跨范围共享默认。** `[文档]` Grok 的每 scope 8 KiB topic index、capture/flush/dream 分工可借（U13:125–145、259–295）。Sumika 对应 `memory.Query/Recalled`、按场合预算和门控（`native/internal/memory/recall.go:31–81、102–132`），已有本地私聊/本地群聊/平台私聊/平台群的不同预算。可以把编码工作区长期知识作为一种受范围控制的来源；不能把 Grok 的 global/workspace 文件共享规则直接套到角色记忆或 QQ，尤其不能让本地私聊知识默认进入本地群、QQ 私聊或 QQ 群。
4. **第二意见先做“可复现的证据审查”，模型强弱是可选路由。** `[文档]` 借 `/goal` 的 objective + verification gaps，而不是加一个只有“请再想想”的 advisor 提示词（WCMD；U04:320–350）。Sumika 对应执行入口 `runTools`（`native/internal/turn/loop.go:538`）、模型记录 `runRow`（同文件:512–514）、审批 `Approvals.Decide`（`native/internal/approval/decide.go:327`）和权限分类（`native/internal/policy/policy.go:60–84`）。审查先看限定的任务、变更、输出证据；要重跑命令仍走 owner-console 和审批，不因“审阅”身份获得额外执行权限。是否另用更强模型属于后续路由选择，不能从 Grok 文档推成必要条件。
5. **窗口、缓存、主回合、子任务、压缩费用分开核算并标完整性。** `[文档]` 借 Grok 的 buckets、partial/incomplete 与 exact ticks，而不借某个输出格式的 0 占位（U14:218–245、353–357）。Sumika 已在 `loop.go:265–278、505–514` 记录 usage，在 `compact.go:247–252` 独立记 compact stage，并在 `turn.go:232–234` 提供会话缓存键。可以沿这些记录点补统计口径和缺失状态；压缩是否保前缀应对比 Sumika 实际请求（`compact.go:182–188`），不能拿 Grok 未公开的 cache 策略当性能证据。
