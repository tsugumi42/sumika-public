## 范围与口径

查过 `prompts/` 全部文件的输出要求，并在 `native/` 的生产代码、命令入口和测试中搜索提示词名、字段名及解析函数；内嵌提示词另查 `OutboundConfirmPrompt`。下表的“无 Go 解析器”指这些位置未找到消费入口，不推断历史 Bun 端的行为。`prompts.Store.Read` 支持用户版优先（[prompts.go](../../native/internal/prompts/prompts.go)，`Read`），表中只登记仓库的出厂版。

ADR-168 要求模型做二选一的 JSON 判定使用字符串 `"yes"` / `"no"`；其他线在下次改到对应提示词时同步改解析，不为本次盘点改协议。`category` 也只有两个选项，单列为分类字段，避免漏掉识图这条线。

## episode_record：字段异常与整批失败

以下均为 [读码]，来源为 `summary_parse.go` 的 `parseEpisode`、`parseSummary`、`extractObject`。这不是本轮测试结果。

| 输入形状 | 现行处理 |
|---|---|
| 精确字符串 `"no"` | 计 `episode_no`，丢弃 `episode`；合法 `ops` 照常解析、执行 |
| 精确字符串 `"yes"` | 有非空字符串 `episode` 才生成经历；空文本计 `episode_yes_empty`，不生成经历 |
| 缺字段 / `null` | 计 `episode_record_missing`；若整份输出格式有效，有经历文本就保留，没有就不存 |
| 布尔 `false` / `true` | 都计 `episode_record_bool`；false 按 no；true 按缺省路径，有经历文本才保留 |
| 空串、`"YES"`、`"maybe"`、数字、对象、数组等 | 计 `episode_record_unknown`；有经历文本就保留，没有就不存；不把这些值直接规范化成 yes/no |
| `episode` 不是字符串 | 计 `episode_bad_type`，无经历文本；其他合法动作仍可继续 |
| `episode_reason` 缺失、空或类型不对 | 不拒整批；非空字符串只计 `episode_reason`，该解析器不保存原因原文 |
| 既无非 null 的 `episode_record`，又无非 null 的 `ops` | `ErrBadOutput`，原因 `no_fields`；即使有 `episode` 文本也失败 |
| `ops` 非 null 且不是数组 | `ErrBadOutput`，原因 `ops_not_array` |
| 围栏、前后说明、尾逗号、字符串内裸换行或截断 | `extractObject` 先取对象，必要时有限修复；修过计 `repaired`。截断修复必须得到 `ops` 数组，否则 `truncated_no_ops`；仍解不开报 `json_invalid`，没有对象起点报 `no_json` |

整批解析失败时，`SummarizeBatch` 计 `bad_output`、返回错误，游标不动、不执行本批写入（[summary.go](../../native/internal/memory/summary.go)，解析在 `apply` 之前）。生产排程的 `runBatch` → `failed` 调 `NoteFailure` 记录失败和重试时间，达到 `MaxFailures` 停下等新通知；取消或库关闭不记失败（[schedule.go](../../native/internal/memplugin/schedule.go)）。

## prompts/ 外的现行二选一：发送守卫

[guard-confirm.txt](../../native/internal/memory/guard-confirm.txt) 内嵌为 `memory.OutboundConfirmPrompt`，要求整份回复为 `{"leaked":"yes"}` 或 `{"leaked":"no"}`。线上与离线评测共用提示词，各自解析，不共用失败结果。

| 入口 | 解析函数与位置 | 合法值 | 缺失、null、空串、布尔、未知值、坏 JSON、围栏或调用失败 |
|---|---|---|---|
| 线上发送守卫 | [outbound.go](../../native/internal/memory/outbound.go)，`CheckOutbound` → `checkOutbound`；`json.Unmarshal` 到字符串 `Leaked`，再精确比值 | yes 保留可疑集合的拦截结果；no 放行本次模型确认 | `model_error`、路线 `model-down`；返回此前达到相似度门槛的 `blocked`，不因解析失败清空拦截。父 context 已取消时先返回 context 错误 |
| 离线 `guard-eval` | [main.go](../../native/cmd/guard-eval/main.go)，`confirm`；同样用 `json.Unmarshal` 与精确字符串比较 | yes 返回 true，no 返回 false | JSON 错误、非 yes/no 或调用错误直接返回 error；`run` 中的取证与 `decide` 向上传错，不把失败统计成 no |

这里没有摘要解析器那种取对象或 JSON 修复：围栏、前后解释、多份 JSON 都会解码失败。JSON 对象内的额外字段会被 `json.Unmarshal` 忽略。

## 后续改动的落点

已符合出厂输出要求的是 `summarize-v2.episode_record`、旧 `summarize.episode_record` 和内嵌守卫 `leaked`。尚待对应线下次修改时处理的是审核的 `ok`、内层 `fit`，以及识图二元分类 `category`：提示词、字段语义、真正的 Go 消费入口与失败处理须同一步确定，不能只替换提示词示例。当前没有 Go 解析器的条目保留该事实，不虚构迁移函数。

本次交付只完成字段盘点；统一现有格式仍挂在待办。未跑 Go 测试 / vet、改坏检查或真实模型；没有业务行为改动。
