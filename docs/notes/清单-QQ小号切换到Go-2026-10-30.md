- 记下 Bun 最后一次写库的时间（主人在资源管理器里点开看，或主会话在主人面前跑命令；别的会话不用去读 `data/`）：打开资源管理器进 `仓库根\data\shared`，看 `events.db` 和 `trace.db` 的「修改日期」；`events.db-wal`、`trace.db-wal` 如果还在，也一起看。取这几个里最晚的一个。命令行的看法：
  ```
  Get-Item 仓库根\data\shared\events.db*, 仓库根\data\shared\trace.db* | Select-Object Name, LastWriteTime
  ```
  Bun 正常退出时 SQLite 会把 `-wal` 合回主文件并删掉它，所以主文件的修改时间多半就是它退出的时刻；`-wal` 还留着，多半是 Bun 被直接结束、没来得及收尾，那就取它们里最晚的时间。把这个时间和是哪个文件抄到最下面的「切换记录」；第 2 步导入的「最新数据」就到这个时间为止。

## 桌面入口怎么配合（2026-10-31 加，规格-界面接Go后台第 5 步）

桌面入口 `native/sumika.exe` 和诊断入口 `cmd/sumika-go` 用同一套装配、同一把数据锁（`go/backend.lock`），**两个不能同时开**：哪个先拿到锁，另一个就停在"数据锁被占用"。所以上面每一步只用其中一个入口。

| 切换前后 | 用哪个 | 注意 |
|---|---|---|
| 第 1 步关 Bun 之前 | 都不开 | 桌面入口这时会停在"后台没在运行"（7720 还开着），这是对的，不是坏了 |
| 第 2 步导入、核对媒体 | 都不开 | 导入和 `media-check` 要独占数据锁；桌面开着会拦住它们 |
| 第 2 步启用以后，第 3 步之前 | 可以开桌面（只看历史） | 双击默认只看历史，不连 QQ、不查模型，用来对一眼导入的历史、图、小黄脸；看完从托盘"退出"，再往下走 |
| 第 4 步只收不发 | 二选一：命令行 `sumika-go -mode receive`，或桌面托盘"开始接收 QQ" | 托盘接收用的是配置里唯一的那个小号（多个时要 `-account`）；开不了会回到只看历史，"运行"页写原因 |
| 第 5 步以后 | 同上 | 发送开关只看 `qq.goSend`，桌面入口不改它；界面这一阶段没有发送和审批入口 |

停写清单（桌面这边多出来的几条）：

- [ ] Bun 和它的看门、自动重启入口都已停，7720 及配置的旧端口无监听，再开桌面；不要为“看看”关掉端口探测。启动后旧端复活不会自动发现、不会自动停收，必须保持旧端停用（issue #14）。
- [ ] 桌面的"开机自动启动"先别勾（ADR-209 默认关），等切换稳定了主人再决定。
- [ ] 切换当天第一次开桌面：在"运行"页看到"只看历史"、角色都列出来（读不到的卡单独写原因），QQ 群点开能看到导入的图。
- [ ] 要退回 Bun：先从托盘退出桌面（等它收完，任务管理器里没有 `sumika.exe`），再照上面各步的"退"做。桌面在接收期间收到的新消息只在 Go 的库里，不会自动并回 Bun。
