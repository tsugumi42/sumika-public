### 1.2 一轮的完整路径

1. `AgentSession.prompt()` 先处理扩展 slash command；普通输入过 `input` handler，再展开 `/skill:` 和 prompt template。正在运行时按 `streamingBehavior` 入队；空闲时检查模型和认证，再 `_startRun()`。[读码] 出处：`pi@642e30b packages/coding-agent/src/core/agent-session.ts:2112-2199`。
2. `_prepareRun` 先检查是否需要压缩，执行 `before_agent_start`，合并本轮 prompt options 和 active tools；启动前就标记会话 busy，避免 handler 尚未结束时又开第二轮。[读码] 出处：`pi@ packages/coding-agent/src/core/agent-session.ts:1886-1996`。
3. 循环在每次请求前补 system/tool 增量，调用 `prepareRequest`，再 `transformContext → convertToLlm → normalizeContext → streamFunction`。流里的 text/thinking/toolcall 增量统一转成生命周期事件。[读码] 出处：`pi@642e30b packages/agent/src/agent-loop.ts:174-254,334-380,392-493`。
4. 完整 assistant 到达后才执行这一批工具；回填全部结果，再执行 `finishTurn`，检查 steering；若无工具和 steering，才检查 follow-up，最后发 `agent_end`。[读码] 出处：`pi@642e30b packages/agent/src/agent-loop.ts:253-323`。
5. Session 在 `message_end` 落盘；`agent_end` 后仍可能重试、压缩恢复或被 `agent_before_settle` 续接。`agent_settled` 才标明整个宿主回合收尾。核心 `Agent.waitForIdle` 还会等 `agent_end` 的异步订阅者完成。[读码] 出处：`pi@ packages/coding-agent/src/core/agent-session.ts:1094-1104,1162-1203,1894-1938,2039-2063`；`packages/agent/src/agent.ts:266-277,339-347,565-620`。

仓库另提供 `Harness`、`GenerationTask`、`ToolTask`、`CompactionTask`、`InboxDoc`、`LiveDoc`、持久化 submission/task 和 JSONL/SQLite/IndexedDB storage。`SubmissionDraft` 区分 input/write/continue，忙时可 steer/followUp/reject，`Submission` 能查状态、等待、取消；这是一套可嵌入的持久任务接口。CLI 的 `sdk.ts` 则实际实例化 `pi-agent-core.Agent` 与 `AgentSession`，依赖表没有 pi-durable。不能把 durable 的持久队列、任务重启语义写成普通 CLI 已有的默认行为。[读码] 出处：`pi@642e30b packages/durable/src/index.ts:1-148`；`packages/durable/src/harness/types.ts:71-175`；`packages/coding-agent/src/core/sdk.ts:397-480`；`packages/coding-agent/package.json:50-79`。durable 的具体崩溃恢复是否覆盖全部外部副作用，本文未核验。

### 2.2 一次返回多个工具调用时怎样并行

- 核心默认 `toolExecution = "parallel"`。若全局设 sequential，或这一批任一工具声明 `executionMode:"sequential"`，则整批串行；没有自动依赖 DAG。[读码] 出处：`pi@642e30b packages/agent/src/agent.ts:246-263`；`packages/agent/src/agent-loop.ts:536-551`。
- 并行路径分两段：先按模型调用顺序逐个发 start、找工具、准备和校验参数、等待 `beforeToolCall`；通过的调用先保存为闭包，所有准备结束后一次 `Promise.all` 开跑。它没有普通工具批的固定并发上限；“并行”也不意味着审批同时弹出。[读码] 出处：`pi@642e30b packages/agent/src/agent-loop.ts:605-680,728-791`。
- 每个调用完成即可发 `tool_execution_end`，完成事件可乱序；真正的 `toolResult` 消息等整批收齐后按 assistant 原调用顺序生成、落盘和回填。序号由 `Promise.all` 输入顺序保持。[读码] 出处：`pi@642e30b packages/agent/src/agent-loop.ts:635-688`；`packages/agent/src/types.ts:39-47`。
- 相互依赖需由模型分多次请求，或在 codemode 中 `await A` 后把结果传给 B。把 A、B 放同一普通工具批并不会推导“B 等 A”。同文件 edit/write 另有 `withFileMutationQueue`，realpath 作 key，同路径串行、不同路径并行；这不是 bash、read 和所有外部副作用的通用事务锁。[读码／推断] 出处：`pi@642e30b packages/coding-agent/src/extensions/codemode/tool.ts:109-120`；`packages/coding-agent/src/core/tools/file-mutation-queue.ts:4-60`；`packages/coding-agent/src/core/tools/edit.ts:160-209`；`packages/coding-agent/src/core/tools/write.ts:65-81`。
- 若 assistant 的 stopReason 是 length，整批工具都不执行，即使修补后的 JSON 看似通过 schema。每个调用回错误，让模型重发完整参数；避免截断参数造成真实副作用。[读码] 出处：`pi@642e30b packages/agent/src/agent-loop.ts:262-275,495-530`。

## 3. 上下文：可重放投影、压缩、缓存与计数

### 3.1 压缩触发和切分

- 默认开启，`reserveTokens=16384`、`keepRecentTokens=20000`；条件为 `contextTokens > contextWindow - reserveTokens`，不是固定百分比。请求前、工具回合之间与完成后都有检查，虚拟模型按路由后的物理模型限额检查。[读码] 出处：`pi@ packages/coding-agent/src/core/compaction/compaction.ts:120-130,264-270`；`packages/coding-agent/src/core/agent-session.ts:782-858,914-945,3032-3168`。
- 从 canonical projection 倒数约 20000 token，切点可以是 user-like 或 assistant，不能从 toolResult 开始，保留 assistant 调用与随后结果。若在一个长 turn 中间切开，分成较早 history 和当前 turn prefix，各自总结，再合成同一个 summary；原始 JSONL 不删除。[读码] 出处：`pi@ packages/coding-agent/src/core/compaction/compaction.ts:351-500,789-921,952-1055`；`packages/coding-agent/src/core/session-manager.ts:476-514`。
- 已有 summary 作为 previous-summary 送入更新请求；新 summary 包含目标、约束、进展、决定、下一步和关键上下文，末尾追加从工具调用提取的 readFiles/modifiedFiles。system prompt 不作为普通对话去总结，压缩 entry 单独保存完整 systemMessage 状态。[读码] 出处：`pi@642e30b packages/coding-agent/src/core/compaction/compaction.ts:98-102,507-579,719-729,903-920,1042-1055`；`packages/coding-agent/src/core/session-manager.ts:91-104,1280-1294`。
- 默认压缩模型是当前选中模型；选中虚拟模型时以 `reason:"direct"` 路由到物理模型，思考档位随该路由。没有另一个默认“便宜摘要模型”字段。扩展 `session_before_compact` 可取消或提供整个 CompactionResult，因而可以另做摘要策略。[读码] 出处：`pi@642e30b packages/coding-agent/src/core/agent-session.ts:585-624,2804-2829,2878-2927`。
- 摘要是独立请求：把对话序列化为文本包进 conversation 标签，使用专用总结 system prompt，不向其提供原工具执行能力；`cacheRetention:"none"`，无 session id 时新建路由 id，使用模型自身输出上限。error、length 或返回 toolCall 均不能当成完成摘要写入。[读码] 出处：`pi@642e30b packages/coding-agent/src/core/compaction/compaction.ts:585-637,681-750`。

### 3.3 token 计数

- 优先取最后一个有效 assistant usage：totalTokens 非零时用它，否则 `input+output+cacheRead+cacheWrite`，再加其后消息的估算。error/aborted/全零 usage 不作锚点。[读码] 出处：`pi@642e30b packages/coding-agent/src/core/compaction/compaction.ts:140-223`。
- 纯估算按文本字符数除 4 向上取整；assistant 包含 thinking、工具名与参数 JSON；system 计入 sections 和 toolsAdded；每张图片按 4800 字符即 1200 token。它不是对每个供应商都精确的 tokenizer，中文与图片的真实 token 仍以供应商 usage 为准。[读码／推断] 出处：`pi@642e30b packages/coding-agent/src/core/compaction/compaction.ts:276-348`。

### 3.6 主动保温

`CacheWarmer` 保留上次请求，默认模式 streaming；TTL 到期前重放，`maxTokens:1,maxRetries:0`。仅当原 transcript 仍是当前历史前缀且模型一致才继续。刷新安排在 TTL 的 90% 或距到期至少 10 秒的位置；预计节省须至少 $0.05。运行中续接概率按 1，idle 模式按 0.15，运行保温总窗口上限 1 小时、idle 30 分钟。预算式 Anthropic thinking 会随 max_tokens 改 budget，无法安全重放时不保温；adaptive thinking 才允许。每次成功保温单独写 usage(cache_warm)，不伪装为助手回答。[读码] 出处：`pi@642e30b packages/coding-agent/src/core/settings-defaults.ts:59`；`packages/coding-agent/src/core/cache-warmer.ts:15-59,211-256,285-414`；`packages/coding-agent/src/core/sdk.ts:361-374,414-421`。
