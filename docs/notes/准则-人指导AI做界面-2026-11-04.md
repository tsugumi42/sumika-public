# Sumika 人指导 AI 做界面的设计准则

- 先确定用户任务、设置归属和作用域，再画控件；视觉修饰解决不了分类错误。【我的建议；[A1] [F1]】
- 同一“配置项＋作用域”有一个权威编辑面，其他位置可提供捷径；继承、覆盖和实际生效值要说清。【我的建议】
- 优先用分组、对齐、留白和字重表达关系，文字和图标只补充结构不能表达的信息。【来源：[B1] [B2]】
- 不存在通用的“每层最多七项”或“三次点击定律”；两层页面导航可作为 Sumika 的起点。【来源：[A6] [A7]；层数为我的建议】
- 数值优先沿用 MewTypeUI 的既有组件和固定 Telegram 基线，不能把多个设计系统的参数拼在一起。【我的建议】
- 动效要覆盖进入、退出、打断和减少动态效果；瞬时完成也可以是明确的设计选择。【来源：[D1]；项目化建议】
- 给 AI 的任务须包含真实内容、信息架构、组件规则、尺寸和状态，不能只写“精致、现代、别有 AI 味”。【来源：[E1] [F1]】
- 验收采用任务走查、布局测量、同条件截图和必要的录屏，只检查本次改动涉及的规则。【我的建议】

版本：1.0。资料核查日期：2026-11-04。适用对象：Sumika 的 Windows 原生聊天区、右侧栏、状态页和设置窗口；Go／mygo／MewTypeUI，中文界面，主要输入为鼠标与键盘，主验收环境为 2560×1440、125% 缩放。

**标记说明**：“来源规则”表示链接中的原则或平台建议；“项目约定”来自本次需求；“我的建议”表示为 Sumika 制定的操作规则、数字或验收方法，不能冒充行业标准；“社区实践”表示署名经验、工具实践或有限范围的评估。

**使用顺序**：本次明确需求 → 项目已批准的设计语言与组件基线 → 本文适用规则 → 其他平台的参考做法；发生冲突时说明具体冲突，不默默换一套参数。

本次没有审计 Sumika 私有仓库或实际界面；下文路径、尺寸起始值和作用域例子都是可落地的建议，不声称项目已经采用。

## a 信息架构与设置逻辑

### 规则

- **A01【来源规则＋我的建议】** 按用户要完成的任务或要管理的对象分类，同一层保持分类维度一致，不把后台模块、配置文件或代理分工直接变成菜单。[A1]
- **A02【来源规则】** 分类名应能预告里面有什么，入口标签与落地页标题保持一致，避免用“其他”“更多能力”等含混名称兜底。[A2] [A3]
- **A03【项目约定＋我的建议】** 为每个“配置项＋作用域”指定一个权威编辑面，搜索、右侧栏和快捷入口可以打开同一个编辑面，不建立各自保存的重复副本。[A4] [A15]
- **A04【我的建议】** 存在覆盖关系时，编辑处明确当前作用域与本级值，查看具体对象时显示其有效值和来源并为本级覆盖提供“恢复继承”，全局默认不得显示成所有下级均已采用，优先顺序以项目配置规则为准。
- **A05【来源规则】** 经常改变的任务内选项放在任务附近，低频全局偏好集中到设置，并保留一个可找到全部应用设置的入口。[A4] [A5]
- **A06【来源规则】** 常用项及有助于判断的当前值优先可见，低频或专业选项通过命名清楚的入口逐步展开，核心任务必需项不能藏进高级区。[A3] [A8]
- **A07【来源规则＋我的建议】** 内容仍属于同一任务且需要一起扫读时使用同页分组，不为每一条设置单独创建一个标题或卡片。[A3] [A9]
- **A08【我的建议】** 只有独立子任务、对象详情或足够大的相关类别才使用二级页面，不能为了减少本页条目数增加只放一两条内容的空壳页面。[A9]
- **A09【来源规则】** 折叠用于多数人可以跳过的次要细节，需要同时阅读、比较或完成主要任务的内容默认可见。[A10]
- **A10【来源规则＋我的建议】** 折叠最多嵌套一层，折叠标题能概括隐藏内容和必要状态，展开箭头与设置开关不得承担含混的双重动作。[A4]
- **A11【来源规则＋我的建议】** 依赖主开关的选项紧接在主开关下方，不可用时就近说明依赖原因，并明确关闭主开关后子项值是保留还是重置。[A3]
- **A12【来源规则＋我的建议】** 少用且不可恢复的清空、重置或移除放在所属对象的低优先位置并交代后果，可撤销的常用动作不反复弹确认。[A11]
- **A13【来源规则＋我的建议】** 设置多或层级复杂时提供搜索，结果展示所属路径并跳到原设置，用户常用叫法可以作为别名而不是新增另一份设置。[A3] [A12]
- **A14【来源规则】** 页面深入后保留当前位置和返回路径，相关内容之间避免必须先退回上级再进入，超过两级导航时提供面包屑或等效路径提示。[A13]
- **A15【来源规则】** 不把“七项上限”“三次点击”当验收门槛，优先检查分类是否可预测、目标是否找得到以及是否反复误入和回退。[A6] [A7]
- **A16【我的建议】** 默认从“分类页 → 必要的详情页”两层页面导航开始，超过两层或一页出现约 12–15 条设置时触发一次结构复核，而不是自动拆页。

### 分组标题 二级页面 折叠怎么选

以下选择表是对 A07–A10 的项目化归纳，不是按条目数机械判定的算法。

| 结构 | 适合的关系 | 不适合的情况 | Sumika 示例方案 |
| --- | --- | --- | --- |
| 同页分组标题 | 同一任务里有几个可命名的小组，用户需要扫读或对照 | 每个控件都分一组，标题和设置名重复 | “模型”页内的“默认使用”“连接”“生成参数” |
| 二级页面 | 管理独立对象、完整子任务或大量相关字段 | 一个简单开关被迫多点一次，返回路径不清楚 | 进入某个模型服务连接的凭据与连接详情 |
| 折叠 | 当前任务的可选细节，跳过不妨碍主要任务 | 必填项、需要横向比较的内容、折叠套折叠 | 某连接的低频重试参数 |

**层级的计算口径**：设置窗口入口不计内容层级，分类页为第一级、详情页为第二级；同页分组标题不增加导航层级，折叠另算一次披露层级；视觉上套了几层卡片又是另一个问题。

**每层多少项**：没有适用于所有产品的统一上限；九个清楚的类别可能比五个含混的大类更好找；A16 的 12–15 条只是提醒复核的项目建议，不能用它把一组有自然关系的设置强行切开。[A6] [A9]

### 先写清设置归属和作用域

**我的建议**：每次新增或迁移设置，补一行内部归属表，至少包含“用户目标、显示名、配置标识、作用域、默认／继承关系、权威编辑位置、依赖项、生效时机、失败处理”；这些是给设计和实现者看的信息，不需要都显示在界面上。

| 用户目标 | 建议的权威编辑位置 | 必须表达的区别 |
| --- | --- | --- |
| 改以后默认使用的对话模型 | 设置 → 模型 → 默认使用 | 改全局默认；是否影响已有会话由项目规则决定 |
| 只改当前会话的模型 | 当前会话的模型选择器或同一份详情编辑面 | 改当前会话覆盖；其他入口打开同一编辑面 |
| 让当前会话重新跟随上级设置 | 上述编辑面的“跟随……”选项 | 删除本级覆盖，不能只复制上级此刻的值 |
| 调整一个 QQ 账号的连接 | 设置 → 平台账号 → 该账号 | 影响这个账号，与某个群的临时静音分开 |

以上是示例方案，具体名称和继承顺序应与实际配置语义核对；“同名”不等于“同一个作用域”。

### 分歧与采用方式

| 常见说法 | 来源实际支持什么 | Sumika 采用方式 |
| --- | --- | --- |
| 每层最多 7±2 项 | NN/g 明确指出菜单靠识别而不是背诵，不能由短期记忆容量推出菜单项上限。[A6] | 不设统一硬上限；用分组、名称和任务测试决定 |
| 必须三次点击内到达 | NN/g 指出三次点击阈值没有普适数据支持。[A7] | 记录找对、误入、回退和耗时，不只数点击 |
| 官方有一个固定条目数 | Windows 设置指南建议尽量少、约 4–5 个设置；Android 指南在 15 条及以上时建议子页，语境与对象不同。[A3] [A4] | 不把某平台的建议当作完整桌面应用的容量上限 |
| 危险功能全部藏深 | Apple 按是否常用、是否可撤销决定确认，并未要求全部藏深。[A11] | 清空全部数据可放页末或明确子页；停止、取消、撤销要及时可达 |
| 所有设置只能有一个入口 | Windows 支持统一设置入口，Apple 支持就地配置，Telegram 文件夹同时有集中管理和上下文入口。[A4] [A5] [A15] | 统一权威编辑面，允许多个通往它的入口 |

## b 视觉层级 图标和说明文字

### 规则

- **B01【来源规则＋我的建议】** 为页面标题、分组标题、设置标签、当前值和辅助说明分配稳定的视觉角色，同一种角色跨页面使用同一套字重、字号与颜色。[B1]
- **B02【来源规则】** 标签靠近所属控件、分组标题靠近下方内容，组内间距小于组间间距，使相关关系在读文字前就能看出来。[B2]
- **B03【来源规则＋我的建议】** 用留白和对齐足以表达分组时不加新容器，每一层背景或边框都要对应实际对象、分组或交互边界。[B1] [B3]
- **B04【我的建议】** 同一任务区域若有主要动作就赋予相应强调，其余动作采用次级样式，没有主要提交动作的设置页不为凑层级添加按钮或宣传区。[B1]
- **B05【来源规则＋我的建议】** 设置分类和陌生动作保留可见文字标签，不能靠一个需要猜含义的图标或仅悬停出现的说明承担导航。[B4]
- **B06【我的建议】** 图标只在帮助识别对象、执行动作或表达状态时使用，同一语义用同一个图标，不能为每条设置补一个任意图标来填空。[B4] [E2]
- **B07【来源规则】** 必要字段标签、输入要求和会改变选择的重要信息持续可见，不只放进占位符或 Tooltip。[B5] [B6]
- **B08【项目约定】** 默认窗口与默认文字大小下，常驻说明最多一行且只补充一个必要信息点，说明用自然完整的中文，标签则用清楚的短语。
- **B09【我的建议】** 窄窗或文字放大导致说明放不下时优先调整布局、改写或自然换行，不用缩小字体、裁掉关键条件或隐藏错误来满足“一行”。[B5]
- **B10【来源规则＋我的建议】** 辅助说明紧邻对应设置，字段错误就地显示并说明如何修正，长原理和罕见细节进入明确的帮助入口。[B5] [B6]
- **B11【来源规则＋我的建议】** 减少说明的重复表达，但不删除设置标签、单位、适用范围或决定操作结果的条件，状态数据可在不歧义时合并成自然短语。[B7]
- **B12【来源规则＋我的建议】** 颜色只承担已定义的层级和状态语义，文字可读性采用 WCAG 对比度作为项目检查目标，并用文字或形状补足不能只靠颜色传达的状态。[B1] [B8]

### 说明文字怎么减

**我的建议**：先问“这个信息是否影响此刻的选择”，再决定是否常驻，而不是把所有说明都藏起来。

| 内容 | 放置方式 | 示例 |
| --- | --- | --- |
| 设置名称 | 稳定可见标签 | “自动保存记忆” |
| 会改变用户决定的后果 | 控件旁的一句短说明 | “关闭后不再自动记录，新旧记忆仍可查看。” |
| 当前状态或范围 | 当前值或就近状态 | “仅当前会话”“跟随角色设置” |
| 输入要求与错误 | 对应字段附近持续可见 | “地址须以 https:// 开头。”，仅在产品确有该要求时使用 |
| 算法原理或很少需要的细节 | 帮助或详情 | 记忆提取过程、重试策略的详细解释 |
| 重述标题的废话 | 删除 | “在这里，你可以对记忆设置进行配置。” |

“常驻一行”是 Sumika 的默认呈现约定，不是通用可用性标准；Fluent 的字段指南允许必要时使用多句或列表，本文保留重要内容在窄窗和大字模式下换行的空间。[B5]

**对比度的具体口径**：WCAG 2.2 的普通文字基线是 4.5∶1，大字号文字是 3∶1，规范有适用条件与例外；Sumika 可将普通说明文字也按 4.5∶1 检查，这是对原生界面的项目采用，不等同于完成整套无障碍认证。[B8]

### 出处

- **B1 · NN/g — Visual Hierarchy in UX**，2021：用大小、对比、字重和分组传达重要性；模糊查看可辅助检查层级，但不能替代可读性与操作测试。[原文][B1]
- **B2 · NN/g — Proximity Principle in Visual Design**，2020；**Laws of UX — Law of Proximity**：近的元素更容易被理解为一组；后者是设计原则汇编，不是尺寸规范。[NN/g][B2] · [Laws of UX][B9]
- **B3 · Refactoring UI**，Adam Wathan、Steve Schoger：公开内容建议减少不必要边框，并建立间距、尺寸与字阶系统。[原文][B3]
- **B4 · NN/g — Icon Usability**，2014：多数图标有歧义，导航尤其需要可见标签；它不是要求把每个熟悉的窗口关闭按钮都改成大段文字。[原文][B4]
- **B5 · Fluent 2 — Field**：稳定标签、辅助说明、禁用与验证状态，必要信息不能只放在占位符中。[原文][B5]
- **B6 · NN/g — Tooltip Guidelines**，2019：完成任务必需的信息不可只藏在 Tooltip，提示也须可由键盘触发。[原文][B6]

## c 间距 形状 对齐和点击区域

### 规则

- **C01【来源规则＋我的建议】** 布局记录统一用项目逻辑单位，截图另记物理像素和缩放比例，禁止把逻辑尺寸与截图像素混算。[C1]
- **C02【项目约定＋我的建议】** 同类组件复用 MewTypeUI 已批准的字号、行高、间距、圆角和图标 token，需要例外时说明组件语义与具体数值。
- **C03【来源规则＋我的建议】** 每个空隙明确归属为容器内边距、同级间距或外部间距，避免父子或相邻控件重复叠加同一份空白。[C2]
- **C04【项目约定＋我的建议】** 有意等距包裹的嵌套块四边轮廓间距相等，普通列表和表单按声明的横向、纵向内边距执行，不要求所有容器四边都同值。[C2]
- **C05【来源规则＋几何推导】** 等距嵌套且需要同心的圆角采用 `R内 = max(0, R外 − d)`，其中 `d` 是对应轮廓的实际内缩距离，且计算后半径不能超过内层尺寸允许的范围。[C3]
- **C06【我的建议】** 同心半径的测量须写清采用外轮廓、填充边界还是描边中心线，边框已计入内缩距离时不得再次扣除。
- **C07【来源规则＋我的建议】** 同一设置列表共用文字左边线和尾部控件对齐线，同一行不同字号文本按实际字体基线对齐，不能只把控件矩形居中。[C2] [B3]
- **C08【来源规则＋我的建议】** 图标按统一资产盒布局，必要的光学修正固化在图标资产或共用组件里，不能由每个页面分别添加临时偏移。[C4]
- **C09【项目约定＋我的建议】** 需要占满容器宽度的按钮或设置行显式声明并测量其布局宽度，不能假定放进块布局后会自动撑满。
- **C10【来源规则＋我的建议】** 图形大小与真实命中区分别验收，相邻命中区不互相抢占，大小按输入方式与组件基线选择。[C5] [C6] [C7]
- **C11【我的建议】** 用最长的真实中文标签、模型名、账号名和混排数字检查布局，主操作与关键条件不得被截掉，必要省略须有可操作的完整查看方式。
- **C12【项目约定＋我的建议】** 展开、收起、窄窗和深色状态遵守同一套组件关系，修改公共布局后复核受影响状态，禁止只为一张截图补另一层边距或底板。

### 可以直接测量的口径

以下为**我的建议**；已有组件 token 优先，表中的起始值只用于项目尚无定义的情况。

本文的“逻辑像素”按 Windows 96 DPI 的 DIP／epx 口径使用；若 mygo 另有应用内缩放或采用其他坐标单位，先确认单位映射并记录总缩放，再换算物理像素，不直接把任意项目单位当作 DIP。

| 项目 | 量什么 | 建议的判定方式 |
| --- | --- | --- |
| 尺寸单位 | 逻辑宽高、实际客户区、屏幕缩放 | 每份测量记录写明单位；125% 时 4 逻辑像素对应 5 物理像素 |
| 间距阶梯 | 同角色实际 gap／padding | 缺少规范时可从 4、8、12、16、24、32 逻辑单位开始；不把所有尺寸强制限定为 4 的倍数 |
| 层级距离 | 标签至控件、组内、组间 | 明确不同角色，例如 4、8、24；数值是起点，必须满足关系清楚 |
| 等距嵌套 | 左、右、上、下的对应轮廓距离 | 设计为等距的四个逻辑值相等；截图栅格化差异另行解释 |
| 同心圆角 | 外半径、内缩、内半径 | 同一曲线族下检查公式与实际轮廓；不能用负半径或超尺寸半径 |
| 全宽控件 | 容器内容区和控件左右边界 | 若无额外声明的外边距，两者左右边界相同 |
| 对齐线 | 标题、标签、尾部控件的布局坐标 | 同角色布局坐标一致；截图测量可暂以不超过 1 物理像素为栅格误差参考，超出须解释 |
| 光学修正 | 图标统一资产盒及偏移 | 记录偏移数值和原因，同图标跨页面一致；不拿非对称轮廓的重心替代资产盒布局 |
| 鼠标图标按钮 | 真实可点宽高与周边空间 | 无既有基线时可从 32×32 逻辑单位命中区试起，再做实际点击检查；这不是平台规定的通用最小值 |
| 文字 | 字体、字号、行高和基线 | 使用项目字体和中文样本测量；保留数字、拉丁字母混排检查，不能以缩小字体修补溢出 |

Fluent 的基础间距是 4，但它也明确提供 2、6、10 来补偿图标内留白；“统一体系”不等于“每个数都必须整除 4”。[C2]

屏幕 2560×1440 在 125% 下理论上对应 2048×1152 的逻辑范围，这是算术换算；窗口边框、任务栏和非最大化尺寸会改变实际客户区，因此布局验收仍以客户区为准。[C1]

### 同心圆角的具体例子

**几何推导／我的建议**：两个等距的圆角矩形轮廓，外半径为 16、内缩为 4，内半径为 12；如果“4”仅是从父边框内缘开始量的 padding，父边框另向内占 1，则总内缩为 5，内半径为 11。

公式适用于对应的等距轮廓和一致的圆角曲线；非等距布局、不同圆角曲线、独立悬浮按钮或相接边不应被强套为同心关系；半径归零后采用组件规定的直角或退化处理。[C3；条件与例子为推导]

### 点击目标为什么不能统一写 44 或 48

| 来源与用途 | 原始口径 | 对 Sumika 的意义 |
| --- | --- | --- |
| Windows 可触摸体验 | 至少 40×40 epx，或宽至少 120 时高可为 32 epx | 需要支持触摸时参考，不能说所有鼠标控件必须高 40。[C5] |
| Windows 触摸优化体验 | 44×44 epx，至少 4 epx 可见间距 | 是另一种输入密度目标。[C5] |
| Material 2 触摸目标 | 48×48 dp，至少 8 dp 间距 | 明确是 Material 2 的规则，不替换 Windows 桌面组件基线。[C6] |
| WCAG 2.2 AA 的 SC 2.5.8 | 24×24 CSS px，存在间距、等效目标、行内等例外 | 是 Web 最低可达性标准，不是原生图标按钮的理想尺寸。[C7] |
| WCAG 2.2 AAA 的 SC 2.5.5 | 44×44 CSS px，存在相应例外 | 与上一行等级不同，不能混称一套强制数值。[C8] |

## d 动效与状态切换

### 规则

- **D01【来源规则＋我的建议】** 每个动效必须解释它帮助理解的变化、反馈或空间关系，高频操作不添加会让用户等待的额外装饰动画。[D1] [D2]
- **D02【我的建议】** 采用动效的浮层、侧栏和展开项同时定义进入、退出、被打断和瞬时完成路径，不把“只有进场”视为完整实现。
- **D03【来源规则＋我的建议】** 动画记录目标属性、起终状态、触发条件、时长和曲线，并优先复用所选组件的既有 token 与行为。[D2] [D3]
- **D04【我的建议】** 同类交互遵守同一套动效语言，Fluent 的缓动建议不得默默覆盖已经采用的 Telegram 组件行为。[D3] [D4]
- **D05【来源规则＋我的建议】** 动画期间接受下一次有效操作，快速打开、关闭、再打开时从当前可见状态转向新目标，不跳回旧起点或排长队。[D1]
- **D06【项目约定】** 退场播放完成前保留当前绘制内容或等效快照，不能先清空内容再让空壳退出。
- **D07【我的建议】** 浮层分别定义逻辑关闭、焦点恢复、命中测试和绘制资源释放的时机，退场后不得有透明残层拦截点击或键盘。
- **D08【来源规则＋我的建议】** 展开与收起的空间关系前后一致，容器和其中内容同步变化，不能用相互矛盾的移动方向制造错误层级感。[D1] [D2]
- **D09【我的建议】** 加载完成或失败时立即转为真实结果，不为播满动画延迟反馈，并让尺寸变化、当前选择和焦点保持可追踪。
- **D10【来源规则＋我的建议】** 默认跟随 Windows 系统动画偏好，减少动态效果时取消非必要位移、缩放和弹跳，同时保留可读状态与操作反馈。[D1] [D5] [D6]
- **D11【我的建议】** 使用录屏或时间戳与状态记录验证进入、退出、反转和完成，不以静态截图证明动效正确。

### 时长和曲线怎么定

| 依据 | 已核实的数值或行为 | 采用方式 |
| --- | --- | --- |
| WinUI 3 官方时长资源 | Normal 250 ms、Fast 167 ms、Faster 83 ms | 是 Windows 组件体系中的资源，不是所有应用的统一标准。[D3] |
| Fluent 官方曲线 | 入场减速 `cubic-bezier(0,0,0,1)`，退场加速 `cubic-bezier(1,0,1,1)` | 可用于没有既定基线的新设计讨论，不能与既有组件随意混搭。[D3] |
| Telegram 固定 lib_ui 源码样本 | `SlideWrap` 的默认展开／收起时长 150 ms，调用时使用 `linear` | 说明具体组件确有不同选择，不能把“linear 一律错误”写成硬规则。[D4] [D7] [D8] [D9] |
| 本项目尚无对应 token | 先选同类组件作基线，再记录差异 | 我的建议：先解决用途和状态，不先发明一套全局 200 ms |

Telegram 样本固定到 `lib_ui` 提交；时长已沿 `basic.style → slide_wrap.cpp → animations.h` 及 `lib_crl` 时间实现核对；这不是对 Sumika 当前采用版本的认定。[D4] [D7] [D8] [D9]

**我的建议**：动效规格最少记录“触发 → 属性／起终值 → 时长／曲线 → 反向操作 → 减少动效 → 何时释放”；例如面板关闭时，逻辑可先进入关闭状态，画面保留至退场结束，但是否阻断背景输入应有明确策略，最终不能残留拦截层。

减少动态效果在 Go／mygo 中需要读取或等效响应 Windows 的系统偏好；仅写一个 Web 的 `prefers-reduced-motion` 条款不能说明原生程序已经支持该功能；`UISettings.AnimationsEnabled` 是微软提供的系统属性之一，本文不指定具体桥接实现。[D6]

## e AI slop 的可见症状与约束写法

### 规则

下表的“给 AI 的约束”均为**我的建议**，把用户已有教训、可用性原则和近两年的实践观察转成可执行要求；这些症状是检查线索，不是鉴定某界面是否由 AI 生成的方法。

| 编号与可见症状 | 给 AI 的一句话约束 | 对应依据 |
| --- | --- | --- |
| E01 设置散在多个近义页面，靠说明互相指路 | 先提交配置项与作用域的归属表，再选择控件，每项只指向一个权威编辑面。 | A03–A04；[F1]；项目需求 |
| E02 每条设置都有同样醒目的大卡片 | 先标出页面、分组和设置行三个层次，只为独立对象或任务使用卡片。 | [B1]；[E1]；[E2] |
| E03 大卡套小卡，边框和留白层层相加 | 每增加一层可见容器都说明新增的语义边界，没有新增关系就删掉这一层。 | [B3]；C03；[E2] |
| E04 每个标题前都塞图标、彩色底板和徽章 | 逐个说明图标承担的对象、动作或状态，没有必要含义的装饰图标删除。 | [B4]；[E2] |
| E05 标题、占位符、帮助文字重复解释同一字段 | 保留稳定标签，只为影响选择或输入的信息补一处说明，重复文字删除。 | [B5]–[B7]；[E2] |
| E06 “智能中心”“赋能配置”等大词多，入口含义不明 | 用用户寻找的对象或任务命名，按钮写实际动作，不加宣传口号。 | [A2]；[E3] |
| E07 状态页出现营销首页式大标题和无依据指标卡 | 按真实状态与排障任务排列内容，不擅自加入 hero、宣传语或虚构统计。 | [E1]；我的场景迁移建议 |
| E08 普通设置到处有渐变、发光和彩条，状态失去重点 | 使用项目语义色，没有明确的状态、层级或品牌用途就不新增强调效果。 | [B1]；[E2]；[E3] |
| E09 不同代理做出的页面像不同软件 | 所有代理使用同一版组件和 token 约定，已有组件能表达的内容不再自创局部变体。 | [F2]；[F3] |
| E10 正常数据时整齐，空、加载、断线或长中文时坏掉 | 同时交付本任务适用的状态与真实内容样本，不用短英文或演示数据掩盖布局问题。 | [E1]；[E3]；项目需求 |
| E11 只有进场动画，关闭时闪空或留下透明遮罩 | 进入、退出、快速反转和关闭后输入都纳入验收，退场结束前保留绘制内容。 | D05–D07；项目教训 |
| E12 每个元素依次淡入，静态状态点一直呼吸 | 动效只服务操作反馈和状态关系，稳定信息保持静止，不按组件数量添加动画。 | [D1]；[E2]；[E3] |
| E13 宽窗正常，窄窗出现裁切和消失的按钮 | 声明最小客户区与布局变化规则，在该尺寸用真实中文完成主任务。 | [C1]；[E2]；我的验收建议 |
| E14 修好一张截图，深色或展开态又多出一套间距 | 按共用组件和状态规则修复，并列出受影响状态的复核结果。 | C12；[F2]；项目教训 |

### 近两年的讨论能支持到哪里

NN/g 在 2025 年发表、2026 年复核的原型评估比较了宽泛提示、详细提示和附带视觉参考的提示；明确的情境、组件与状态能改善输出，但实际结果仍出现层级、分组和间距问题，因此提示词与实物验收需要配套；这是一组实际设计任务的评估，不是对所有模型的通用量化结论。[E1]

设计师和开源实践对多层卡片、重复文案、装饰动效、缺失状态有相近观察；Impeccable 还把“风格模式”“一般质量缺陷”“违反项目设计系统”分开，命中后要求结合任务判断，这比给字体或配色列永久黑名单更适合 Sumika。[E2] [E3]

**有争议的地方**：Anthropic 2025 年的前端示例倾向用独特字体、背景与动效摆脱通用网页外观；这种方法可以服务品牌展示，但不能直接变成中文桌面设置页的验收目标；Sumika 采用熟悉的系统字体、稳定列表、统一组件和克制动效，完全可以是有意且合适的选择。【我的建议；E4】

## f 人怎样指导 AI 设计与验收

### 规则

- **F01【社区实践＋我的建议】** 任务说明先给用户目标、使用情境、主要动作和成功结果，再提供真实字段与内容，不让 AI 用通用页面模板猜产品。[F1] [F4]
- **F02【我的建议】** 涉及设置归属时先给信息架构树和配置归属表，并写清页面、分组、折叠和作用域，随后再实现控件。
- **F03【社区实践＋我的建议】** 参考实物标明平台、版本、窗口尺寸与状态，并明确要精确匹配哪些结构、只借鉴哪些风格，不用一句“像 Telegram”代替规格。[F5]
- **F04【社区实践＋我的建议】** 同时给 AI 数值 token、组件使用规则、正常与异常示例，让主代理和子代理共享同一版依据。[F2] [F3]
- **F05【我的建议】** 已确定方案的实现任务必须给可判定条件，“现代、精致、高级、简洁、别有 AI 味”只能作方向补充，不能单独作为验收标准。[E1] [F4]
- **F06【我的建议】** 先走查用户任务、配置作用域和保存语义，再核对布局、文字与动效，避免用圆角和配色修饰掩盖分类错误。
- **F07【来源规则＋我的建议】** 分类或标签有实质变化时，用不泄露菜单名称的真实任务做树测试，记录首次选择、成功与回退，AI 自测不冒充用户测试。[F6]
- **F08【我的建议】** 精确复现或同页回归对比时使用相同客户区、缩放、主题、内容和状态做测量及叠图，跨产品参考只比较事先指定的组件、结构或 token，不要求整页内容相同。[F5]
- **F09【社区实践＋我的建议】** 评审给出“规则编号、操作步骤或实际值、预期、结果、证据”，复杂改动可让独立评审者复核，小修不必新增多代理审批。[F7]
- **F10【我的建议】** 验收按改动风险选取最小充分集合，通过相关规则和主要任务后停止，重复缺陷优先修共用根因，超出本次范围的共用问题单独记录而不自动扩大成全库重构。[F1] [F7]

### 任务说明至少给什么

| 输入 | 足够具体的内容 | 不足的说法 |
| --- | --- | --- |
| 用户任务 | “在当前会话中更换模型，其他会话不受影响，并能恢复继承” | “优化模型设置” |
| 信息架构 | 入口、所属分类、分组、必要详情页、作用域和返回路径 | “功能合理分类” |
| 实物参考 | 某版 Telegram 的具体页面、截图状态、组件来源与复制边界 | “照着 Telegram 做” |
| 数据与状态 | 真正的中文文案、长模型名、空列表、保存失败和禁用原因 | “放点示例数据” |
| 组件与尺寸 | 具体组件及 token、逻辑客户区、最小宽度、缩放 | “间距舒服、圆角统一” |
| 行为 | 即时生效或提交保存、失败恢复、返回、焦点、进入与退出 | “交互完整、动效丝滑” |
| 验收 | 真实任务步骤、尺寸表、同条件截图及相关录屏 | “自查没问题就提交” |

### 验收顺序和证据

1. **查任务与语义**：按真实目标找到设置，确认改动作用域、有效值、保存结果和恢复行为；即时保存失败时不能仍显示成功状态。
2. **查结构与状态**：确认分类、分组、折叠的关系，并检查本次涉及的空、加载、成功、失败、禁用及长文本状态。
3. **量布局**：记录客户区、DPI、逻辑单位、内边距、同级间距、实际宽度、对齐线和命中区，与同一组件基线比较。
4. **比实物**：精确复现或同页回归时匹配条件再叠图，跨产品参考则只对约定的组件区域、结构和 token 比较；中文字体回退、抗锯齿或栅格化差异需要单独解释，不能把全页像素差直接当失败率。
5. **走动效与键盘**：涉及变化时检查进入、退出、快速反转、减少动态效果、Tab／Shift+Tab、确认与取消以及关闭后的焦点。

这五步和下面的证据格式均为**我的建议**；树测试和截图参考的方法依据分别见 F6、F5，实操评审的工程实践见 F7。

**一条合格的测量记录示例**：`C09｜设置客户区 960×720 逻辑单位，125%｜内容区宽 912，按钮布局宽 880｜预期 912｜不通过｜缺少 32 的伸展宽度`；这里的尺寸是演示数据，不是 Sumika 的指定窗口大小。

### 按改动选择检查范围

| 改动 | 必查 | 只在相关时增加 |
| --- | --- | --- |
| 单处文案或图标 | 真实中文、标签含义、截断、资产对齐 | 涉及导航名称时测可发现性 |
| 一个设置页的布局 | 默认与最窄客户区、125%、长内容、命中区和保存流程 | 更改主题 token 时加浅深色；更改分类时加树测试 |
| 公共容器或设置行组件 | 受影响使用处、不同状态、宽度和主题、几何一致性 | 有动画的容器加进入／退出／打断；有文字布局加系统文字放大 |
| 动效或浮层生命周期 | 进入、退出、连续反转、减少动态效果、关闭后输入和焦点 | 性能异常时再检查帧时间，不预先扩大成全应用性能项目 |

**我的建议**：结构改动可选 3–5 个真实任务做一次人工走查；这是一组省力的检查样本，不是统计样本量承诺；未验证项标“未验证”，不以“应该没问题”替代结果。

## 给 AI 的界面任务模板

以下是本文的**项目采用模板／我的建议**，不需要每次把全部研究正文重复塞进任务；附本模板、任务涉及的规则和具体组件基线即可。

### 任务卡

- 用户要完成的事：〔具体目标与成功结果〕。
- 修改范围：〔页面／组件／状态〕；配置作用域与生效方式：〔全局／角色／账号／会话，即时／提交／重启〕。
- 信息架构：〔入口 → 分类页 → 分组或必要详情页〕；权威编辑位置：〔位置〕；其他入口：〔跳转方式〕。
- 参考：〔截图或实物、版本、状态、需要匹配的部分，以及精确复现／同页回归／仅借鉴结构风格〕。
- 基线：〔MewTypeUI 组件、token 和对应 Telegram 固定版本〕。
- 布局：〔默认与最小客户区逻辑尺寸〕；主验收为 Windows 125% 缩放；适用主题和文字放大：〔范围〕。
- 内容与状态：〔真实中文、长文本样本、适用的空／加载／失败／成功／禁用／展开／收起〕。
- 验收任务：〔能实际操作的步骤，以及必须核对的规则编号〕。

### 可直接粘贴的约束

```text
按本任务的用户目标与信息架构实现界面，先核对设置归属、作用域、继承和保存语义，再选控件；同一配置项在同一作用域只有一个权威编辑面，其他入口跳转到它。优先复用指定 MewTypeUI 组件与固定版本的 token，不自行换字体、间距、圆角、图标或动效体系。先用分组、对齐、留白和字重表达关系，每增加一层可见容器都应有明确语义；主要内容默认可见，折叠最多一层，页面导航默认从分类页加必要详情页两层开始，例外说明具体理由。标签可预测，陌生图标保留可见名称，常驻说明在默认宽度和文字大小下最多一行，窄窗与大字模式不得靠缩字或裁掉关键信息达标。明确 padding、同级间距和宽度约束；等距嵌套量四边，适用时按实际轮廓内缩计算同心圆角；统一文字基线、图标资产盒与命中区。使用真实中文和本任务适用的全部状态，同一组件的宽窄、浅深和展开收起遵守同一套规则。采用动效时同时实现进入、退出、打断与减少动态效果，退场完成前保留绘制内容，关闭后不得残留输入拦截。交付时以任务实操、布局测量、同条件截图和必要录屏对选定的适用项逐项给出通过、不通过或未验证，修到相关规则满足即结束，不用“已美化”“更高级”替代证据。
```

### 验收清单

每次只选本任务适用项形成验收表，其余省略；若跳过已选的必查项才说明原因，未验证不能记作通过。

- [ ] **任务可达**：按真实用户目标找到了设置；入口名与内容相符，无反复误入。
- [ ] **归属唯一**：配置项与作用域明确；其他入口指向同一权威编辑面。
- [ ] **继承正确**：具体对象的有效值与来源清楚；恢复继承真正取消本级覆盖。
- [ ] **生效清楚**：即时保存、提交保存或需重启的规则一致，成功与失败状态真实。
- [ ] **层级可读**：分组有语义；没有无意义嵌套卡片或为凑项数拆出的页面。
- [ ] **文字必要**：标签稳定可见，说明无重复，关键条件未藏入占位符或 Tooltip。
- [ ] **图标有用**：图标含义、资产、线重与对齐一致，陌生动作不靠猜。
- [ ] **尺寸有据**：已记录客户区、缩放和单位；gap、padding、宽度与 token 一致。
- [ ] **几何正确**：等距块四边一致，同心公式边界明确，文字基线与图标光学修正统一。
- [ ] **输入可用**：命中区足够且不重叠，键盘顺序、确认、取消和焦点恢复符合任务。
- [ ] **状态完整**：适用的空、加载、错误、成功、禁用、长中文和继承状态均有证据。
- [ ] **变体一致**：默认与最窄窗口、相关主题和展开收起没有各自补出一套布局。
- [ ] **动效完整**：进入、退出、快速反转和减少动态效果可用，内容无提前清空或透明残层。
- [ ] **比较可复现**：精确复现或回归对比的条件一致，跨产品参考按约定的组件、结构和 token 比较，差异有具体位置与原因。
- [ ] **交付诚实**：逐条给实际结果和证据，未验证项明确列出，范围内的重复缺陷处理了共用根因，超出范围的问题另行记录。
