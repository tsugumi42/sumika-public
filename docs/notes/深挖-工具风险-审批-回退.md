## 给 Sumika 的做法（可直接拿去写规格）

**一、工具自己声明风险，审批按声明查**

1. 三家里，真正让"工具自己声明"的只有 DeepSeek（`isConcurrencySafe`、`timeoutMs`）和 Codex（`supports_parallel_tool_calls`、每个运行时自己报"要不要批准"）。Hermes 的工具注册项根本没有风险字段，靠写死的名字集合；而且 DeepSeek 对没人管的新工具（含 MCP）是默认直接执行，只有 Codex 的 MCP 是"没注解就要批准"。Sumika 要学的是 Codex 这一条：**没声明就当最危险**。
2. 做法：新增 `daemon/tools/spec.ts`，每个工具登记一份 `ToolSpec`：`effects`（`self` / `read` / `write` / `exec` / `net`，至少一项）、`audience`（`owner-console` 或 `any`）、`parallel`、`timeoutMs`、`paths(args)`（要碰的路径）、`classify(args)`（powershell 按命令收窄）。`tools.ts` 的 `NEEDS_APPROVAL` 整个删掉，`gate()` 改成按 `daemon/tools/policy.ts` 的 `decide()` 查。
3. 判定顺序固定为：渠道（`forAudience`，第一层，不变）→ 硬禁止清单（在 YOLO 之前，不止管 powershell）→ 受保护路径（写入永远问，YOLO 也问，不能记住）→ 主人写的规则表（`deny` > `ask` > `allow`，取最严）→ 三档模式 → 默认问。没声明的工具：手动、自动、YOLO 三档都问，且只发给主人 × 控制台。
4. `parallel` 直接落到 pi 现成的 `AgentTool.executionMode`，默认 `sequential`；`timeoutMs` 用包一层 `execute` 的办法，不指望 pi 自己超时。
5. 测试：注册一个没声明的假工具，新代码必须"要问"，放回旧代码它直接执行所以必红；再加"把默认分支从问改成放"的故意改坏。QQ 那条单独写：任何非控制台听众拿到的工具名集合恒等于三个记忆工具，且 `declare({effects:['exec'], audience:'any'})` 必须抛错。

**二、审批分级**

1. DeepSeek 只有"允许一次 / 拒绝"，没有记忆、没有撤销、拒绝理由是固定句子；Hermes 是 once / session / always / deny，"始终允许"存成配置里的一份清单，**粒度是危险模式的类别**（偏粗：它自己的注释就是因为这个原因，才不让智能审批的“通过”按类别记忆）；Codex 的"始终允许"是**命令前缀**，并有一份"这些前缀永远不许被设成永久允许"的禁止名单（`rm`、`sudo`、`bash`、`python`、`powershell` 等）。Sumika 取 Codex 的粒度，加上 Windows 的禁止前缀。
2. 做法：决定从 `approve: boolean` 改成 `choice: 'once' | 'conversation' | 'always' | 'deny'` 加可选的 `reason`。"允许这个对话"只存内存，键是完整的（工具 + 规范化命令 + 工作目录；文件工具是绝对路径），对话结束或后台重启就没了。"始终允许"存 `data/config/tool-grants.yml`，键是"命令前缀"或"目录前缀"，**含管道 / 重定向 / 分号 / 子表达式的命令，不提供"始终允许"**；界面设置页要有"已允许的操作"清单，每条能撤销，手改文件也立刻生效（Hermes 每次检查都和磁盘对一遍）。
3. 拒绝带原因：拒绝按钮旁一行可选输入，原因原样拼进给模型的话里（Codex 的 `Denied { rejection }`、Hermes 的 `/deny <原因>` 都是这样），并保留现在那句"不要换个方式重试"。审批卡快捷键：Enter 允许一次、Esc 拒绝，必须带输入法保护（`isComposing` / keyCode 229 / `repeat` / 焦点在输入框里都不触发），按住 Enter 不能把排队的下一张卡也批掉。
4. 永久允许（ADR-021 只取代了"没有跳过审批的开关"，没有批准过"永久批准"）要先写 ADR，规则存哪、粒度多细由主人定。档位名字建议跟 Codex 一致：每次都问 / 低风险自动 / 完全放开，选"完全放开"要勾一次"我知道风险"；YOLO 建议只放内存、重启回落（需要主人点头）。
5. QQ：审批和授权都只在 `gate()` 里查，而 `gate()` 只会碰到 `forAudience` 发出去的工具，QQ 渠道的对话实例里压根没有这些工具；`decide` 只收控制台 WebSocket；`tool-grants.yml` 本身属于受保护路径，模型改不了。

**三、文件检查点和回退**

1. 只有 Hermes 有真正的回退，而且默认关（`HM hermes_cli/config_defaults.py:498-499`）。Codex 的 ghost snapshot 只剩兼容旧配置的壳；DeepSeek 的 workspace-changes 只做改动对比，不能恢复。
2. Hermes 的办法是：每轮第一次写文件（或遇到看起来会删改文件的命令）之前，把**整个项目目录**存进一个独立的 bare git 库（用 `GIT_DIR` / `GIT_WORK_TREE` / `GIT_INDEX_FILE` 指过去，屏蔽全局 git 配置，所以不碰用户自己的 `.git`）。恢复前先再存一份"回退前快照"，所以能撤销撤销。
3. **Sumika 不照搬整目录快照**，建议改成"只存被改的那个文件的旧内容"：`tools.workdir` 默认是用户目录（`SK daemon/plugins/tools.ts:67`），主人的项目目录里有大量视频和 3D 文件，整目录 `git add -A` 会撞上 Hermes 自己的 5 万文件 / 单文件 10 MB 上限；另外选型体检说这台电脑直接起外部程序头几次要卡 5～12 秒，每次写文件前起 git 不现实。做法：`write` / `edit` 批准后、执行前，把旧文件按内容哈希复制进 `data/checkpoints/objects/`，在 `index.jsonl` 里记一行（对话、工具调用 id、路径、改前哈希、改后哈希）；全是纯 TypeScript，不起外部程序。
4. 恢复：单个文件、或"撤销这一轮的所有改动"；恢复前先把现在的内容也存一份；如果文件在 Sumika 写完之后被主人手改过（当前哈希 ≠ 记录的改后哈希），跳过并列出来，不覆盖（照 Hermes 的 agent-write ledger）。清理：每个路径最多 20 份、总量 500 MB、14 天（Hermes 是 20 / 500 MB / 7 天），后台空闲时清；检查点库永不进 git，也不存 `data/` 下的东西。
5. powershell 的改动先不自动存（路径不可知），第二期再做"能从命令里读出明确路径的"；默认开不开请主人定（我倾向 write / edit 开，因为只复制被改的文件，代价小；powershell 不开）。

**接口**

```ts
type Effect = 'self' | 'read' | 'write' | 'exec' | 'net'   // self = 只写她自己的记忆
interface ToolSpec {
  effects: Effect[]                    // 必填，不能为空
  audience: 'owner-console' | 'any'    // 'any' 只允许 effects 全是 'self'

  classify?(args: any): Effect[]       // powershell 用：只读命令收窄成 ['read']
  describe?(args: any): { title: string; subject: string; preview?: unknown }
```

**判定顺序（`decide()`）**

1. 渠道：`forAudience` 先筛（不变）；`gate()` 再核一次 `spec.audience`（纵深防御）。
2. 硬禁止：`HARD_DENY` + 主人写的 `deny` 规则 → 直接拒，不看模式。清单要小而准（格式化 / 分区 / `bcdedit` / `vssadmin delete` / 改 Defender / 删盘符根 / 往 Sumika 自己的 `data/`、配置、角色卡写）。**注意：这会改变 ADR-021"灾难性命令即使 YOLO 也要问"的结果（变成拒绝），要主人决定**；也可以折中为"灾难性的仍然问、任何模式都不能自动、不能记住"，硬拒绝只给配置文件和 `data/`。
3. 受保护路径：写入 → 永远问，YOLO 也问，只给"这一次"；读取 `data/`、`.env*`、`.ssh`、`.aws` → 问（现在 `read` 工具读 `data/` 里的密钥不用批准，内容会进模型上下文）。Hermes 的 ①（配置文件直接拒绝）和 ②（改变行为的文件永远问）都适用：Sumika 的 `data/config/sumika.yml` 里有 `tools.approvalMode`，模型如果能写它，就能把审批关掉。
4. 规则表 `tools.rules`：`[{ tool, match: { prefix | pathPrefix }, decision: allow|ask|deny, reason }]`，取最严（deny > ask > allow）；`reason` 显示在审批卡和给模型的拒绝话里（学 Codex 的 `justification`）。
5. 三档模式，按 `effects` 而不是名字：
   - 手动：`self` 放行；其余全问（`read` 现在是放行，保持现状：读工作目录放行，读受保护路径问）。
   - 自动：`read`、写入且所有路径在 `workdir` / `autoApproveDirs` 内且不受保护、`exec` 且 `classify` 为只读 → 放行；其余问。
   - YOLO：已声明的放行；没声明的仍问。
6. 兜底：问。

## 2. 审批分级

### 2.1 DeepSeek

- **结果只有四种**：`allowed-once` / `rejected` / `cancelled` / `unavailable`；**没有** allow-always、记忆、撤销（自己的 README 明说，`DS interaction/user-approval/README.md:154`）。`DS interaction/user-approval/src/types.ts:32`。
- **请求不带工具参数**：答复者只看到工具名、理由和调用 id（`README.md:155`），所以卡片里的命令内容是"工具自己提供的详情槽"，不是审批服务给的。
- **策略 `ask` / `never` 记在会话日志里**（一条 `approval/policy` 事件，最后一条算数，`DS interaction/user-approval/src/index.ts:40-45,243-259`）；切换时给模型追加一条"审批策略从 X 改成 Y（用户改的）"的消息，同时在系统提示词里附新状态，**追加在历史后面而不是改前缀**（`:162-195`）。这和 Sumika 的 ADR-022（只追加）一致，Sumika 切模式时可以照做。
- **审计**：每次问都写一对日志事件 `approval/asked` + `approval/decided`（`DS interaction/user-approval/src/types.ts:34-60`；`index.ts:215-234`）。
- **档位**：预设表默认两项——`workspace-write` + `ask`（"在工作区里写，更宽要批准"）和 `danger-full-access` + `never`（"完全访问，不提示"）（`DS interaction/permission-presets/src/index.ts:188-197`）；界面名叫"仅可查看 / 工作区内修改 / 完全权限"（`DS client/ui-permission-presets/src/client/locales.ts:12-14`，`presentation.ts:10-19`）。选"完全权限"要通过风险确认框，复选"我已了解风险"（同文件 `locales.ts:36,74`）。
- **自动审查（实验，默认关）**：每次工具调用前，用当前这个模型再发一次请求打风险；低风险放行，中风险要主人明确授权过才放，高风险一律拒；被拒的再问用户；每次多花一次模型请求，没有缓存和重试（`DS experimental/auto-review/README.md:48,87-91`）。
- **拒绝原因怎么回给模型**：固定句子——`the user rejected tool "<名>"` / `approval for tool … was cancelled` / `… no approval channel is available`，没有用户填的理由（`DS core/tools/src/index.ts:1761-1773`）。
- **审批卡**：整块替换输入框（"接管输入区"）：顶上一条状态"等待审批"，正文大标题是理由（没有就写"工具 X 请求越权执行"），下面是工具自己的详情槽（命令 / 补丁），底部两个按钮 `拒绝`（描边）和 `允许一次`（主色）（`DS client/ui-approval/src/client/ApprovalPanel.tsx:59-85`；文案 `locales.ts:4-10`）。
- **快捷键**：Enter 允许一次、Esc 拒绝（`DS client/ui-approval/src/client/index.ts:82-86`）；处理函数忽略：焦点在输入框 / 下拉 / 可编辑区、按了 Ctrl/Meta/Alt/Shift、`event.repeat`、输入法正在组字（`isComposing` 或 `keyCode 229`）、刚结束组字的那一次按键、焦点在按钮上的 Enter（`ApprovalPanel.tsx:46-58`）。**这些保护 Sumika 必须抄**（主人用中文输入法）。

### 2.2 Hermes Agent

- **四个选择**：`once` / `session` / `always` / `deny`，另有 `timeout`、`cancelled`（"提示没送达"，不算用户拒绝）（`HM tools/approval_prompt.py:20-41,69-80`）。
- **记在哪、什么粒度**：
  - `session`：内存里每个会话一个集合，键是 `pattern_key`（`HM tools/approval.py:253-256,401-414`）。
  - `always`：同时进永久集合并写进配置 `command_allowlist`（`approval.py:387-391,419-501`）。`pattern_key` 是**危险模式的名字**（"recursive delete" 这一类），不是具体命令；代码注释解释了智能审批的"通过"为什么不按类别记忆：怕一条无害命令把同类别后面的命令都盖过去（`approval.py:771-773`）；这也说明类别粒度确实偏粗。
  - 插件要求审批的工具：键是 `plugin_rule:<工具名>:<理由的哈希前 12 位>`，不同理由各记各的（`approval.py:1121-1146`）。
  - 手写进清单的条目是命令原文或通配（如 `podman *`），但**含 shell 操作符的复合命令不能靠清单放行**（要识别引号内外，`-c`/`-e` 这类把引号内容交给另一个解释器的也算）（`HM tools/approval_floors.py:134-204`）。
- **怎么撤销**：直接删配置里 `command_allowlist` 的那一行；每次检查前都会把磁盘上的改动对一遍，所以删了立刻生效，不用重启（`approval.py:353-368,470-485`）。**没有界面撤销**（没查到）。
- **哪些情况根本不给"记住"**：智能审查拒绝但主人覆盖的、受保护的指令文件写入、硬禁止——只给"这一次"（`approval.py:796-833`；`file_tools_write_guards.py:333-343`）。
- **拒绝原因**：网关 / 聊天界面里 `/deny <理由>`，理由原样拼进给模型的话（`approval.py:120-121,142-176,887-890`）；统一的"BLOCKED：用户没同意，不要重试、不要换说法、不要换个工具达成同一结果"，超时则加"沉默不算同意"（`approval.py:701-710`）；界面另有一句给人看的 `user_summary`，与给模型的话分开，免得点了拒绝像是"用户做错了什么"（`approval.py:524-547`）。
- **超时**：默认 300 秒（推送通知可能几分钟才看到）（`HM tools/approval_context.py:305-323`）。
- **连续被拒的熔断**：只统计"自动审查模型"的连续拒绝（默认 3 次后在工具结果里追加"停下来问用户"），不统计人的拒绝；只改工具结果文字，不动历史（`approval.py:62-115,927-929`）。

### 2.3 Codex

- **决定有八种**：批准 / 批准并改规则（命令前缀）/ 批准且本会话内同类自动批准 / 批准 MCP 工具并永久改策略 / 网络规则修正 / **拒绝（带原因 `rejection`）** / 超时 / **中止（停掉当前回合，等用户下一句话）**（`CX protocol/src/protocol.rs:4264-4302`）。注意"拒绝"和"中止"是两件事：拒绝了让模型换个办法继续，中止是整个回合停下。
- **会话缓存键（"允许这个对话"）**：整个服务内存里一个 `ApprovalStore`，键是序列化的结构体，缓存的只有"本会话内批准"；一次改多个文件的补丁要所有文件都已批准才跳过提示（`CX core/src/tools/sandboxing.rs:41-118`）。具体键：命令 = 执行环境 + 可执行名 + **完整命令** + 工作目录 + 是否 tty + 沙箱权限 + 额外权限（`CX core/src/tools/runtimes/unified_exec.rs:97-105`）；写文件 = 环境 + **单个路径**（`runtimes/apply_patch.rs:40-43`）；MCP = 服务器 + 插件 + 连接器 + 工具名（`mcp_tool_call.rs:1804-1825`）。桌面端文案却写"允许在此对话中使用以 {命令} 开头的命令"（`CD zh-CN-7ba80cbb133d.js` 字符偏移 901026，键 `execApprovalRequest.allowConversation.commandPrefixInfo`）。**两处对不上，分别引，别替它们对齐**。
- **"始终允许"（跨会话）**：
  - 命令：往 `<codex_home>/rules/default.rules` 追加一行 `prefix_rule(pattern=[…], decision="allow")`（`CX execpolicy/src/amend.rs:65-79`；路径常量 `CX core/src/exec_policy.rs:54-56,874`）。**粒度 = 命令前缀的 token 列表**。
  - 建议的前缀有禁止名单：`bash`/`sh`/`zsh`/`cmd`/`powershell`/`pwsh`（含 `-c`、`-Command`、`-File`、`-EncodedCommand`）、`python`/`python3`/`node`/`ruby`/`perl`/`php`/`lua`/`deno eval`/`bun run`/`npm run`/`pnpm run`/`yarn run`、`env`、`git`（整个 git 光杆）、`rm`、`sudo`、`osascript`……整词相同才算禁止，所以 `git status` 可以设成永久允许而光杆 `git` 不行（`CX core/src/exec_policy.rs:57-143,977-1016`）。
  - MCP：写进用户配置的 `mcp_servers.<服务器>.tools.<工具>.approval_mode = "approve"`（插件 / 连接器各有路径）（`CX core/src/mcp_tool_call.rs:2394-2488`）；**粒度 = 服务器 + 工具**。且只有该服务器处于 `auto` 模式才给这个选项；管理员设成 `prompt` / `writes` 时，"本会话 / 永久"会被降成"批准这一次"（`mcp_tool_call.rs:1804-1833,2300-2315`）。
  - 撤销：改规则文件 / 配置；**界面上的撤销没查到**。
- **拒绝原因怎么回给模型**：`Denied { rejection }` 原样变成工具错误（`CX core/src/tools/approvals.rs:440`）；默认值是字面的 `denied`（`protocol.rs:4304-4310`）；超时给一段"自动审查超时"的指示文字；中止直接结束回合（`approvals.rs:441-447`）。
- **权限档位**（桌面端文案，`CD zh-CN-7ba80cbb133d.js`）：
  - **请求批准**（偏移 776277）："编辑外部文件和使用互联网时始终询问"。
  - **帮我批准**（偏移 777088，实验）："仅对检测到的风险操作请求批准"——后台用另一路模型给每个动作打风险再决定；被它拒绝的会话里能用 `/` 命令挑一条"批准一次重试"；多次被驳回会终止本轮并提示加上下文或换权限模式；首次出现审批时有一张"想减少审批提示吗？"的卡片（偏移 86569）。
  - **完全访问权限**（偏移 776802）："可不受限制地访问互联网和你电脑上的任何文件"；启用要过确认框（"选中后……无需请求批准的情况下读取和编辑文件，包括执行可能具有破坏性的命令"，键 `settings.agent.permissionsMode.fullAccess.confirm.body`）。
  - **自定义**：用 `config.toml` 里写的权限；被 `requirements.toml` 禁用的档位在下拉里置灰并提示来源。
  - 设置里另有"批准策略"：`从不请求审批` 等（偏移 1531595）。
- **审批卡**（`CD app-initial-df84a35d942d.js`，字符偏移 14085556–14089738 一段）：上面是标题（"允许 ChatGPT 运行此命令？"）和一个带"原因"标签的小节，再下面是工具给的详情（终端 / 网络 / 请求权限）；底部是一个表单：左边可选的前置按钮（**"始终允许"**，描边）和**"拒绝"**（描边），右边主按钮**"允许一次"**带分裂下拉，下拉里是"允许一次"和**"允许此对话"**；窄屏时纵向堆叠、按钮占满宽。
- **快捷键**：命令 `approval.approve` 默认 `Enter`、`approval.decline` 默认 `Escape`（字符偏移 5292799）；处理函数在焦点位于对话框 / 菜单里、或焦点已经在某个按钮 / 链接上按 Enter、或焦点在按钮上按空格时**不触发**（偏移 14083356 附近的 `Wbd` 函数）。第一轮写的"Enter 批准 / Esc 拒绝"已核实。

## 3. 文件检查点和回退

### 3.1 Hermes（唯一有真回退的）

- **是什么**：不是工具，模型看不到；是运行时的透明基础设施（`HM tools/checkpoint_manager.py:1-12`）。**默认关**，要 `hermes chat --checkpoints` 或配置打开，理由写在配置注释里："大多数用户不会用 /rollback"（`HM hermes_cli/config_defaults.py:495-499`）。
- **存什么、什么时候存**：每个对话回合里，**第一次** `write_file` / `patch`（或终端命令像是会改删文件）之前，把**整个工作目录**存成一个提交；同一回合同一目录只存一次（`checkpoint_manager.py:805-807,920-948`；触发在 `HM agent/tool_executor.py:95-114,1036-1048`；回合开始重置在 `HM agent/turn_iteration_prep.py:380`）。"像是改删文件"的判断是一条正则：`rm`、`rmdir`、`cp`、`install`、`mv`、`sed -i`、`truncate`、`dd`、`shred`、`git reset|clean|checkout`，加上覆盖式重定向 `>`（`HM agent/tool_dispatch_helpers.py:52-67,102-104`）。
- **存在哪**：`~/.hermes/checkpoints/store/`，**所有项目共用一个 bare git 库**，靠内容寻址去重；每个项目一个分支引用 `refs/hermes/<项目路径哈希>`、一个单独的索引文件 `indexes/<哈希>`、一份 `projects/<哈希>.json`（工作目录、创建 / 最后使用时间）；`info/exclude` 里是默认排除表（`node_modules`、`dist`、`build`、缓存、虚拟环境、**`.git/`**、二进制、大媒体、压缩包、`.env*`、日志……）（`checkpoint_manager.py:13-49,97-158,509-580`）。
- **怎么不碰用户自己的 `.git`**：用环境变量 `GIT_DIR`（指向影子库）+ `GIT_WORK_TREE`（项目目录）+ `GIT_INDEX_FILE`（每项目单独索引）把 git 指过去，**项目目录里不写任何文件**；并且屏蔽用户的全局 / 系统 git 配置（`GIT_CONFIG_GLOBAL`/`SYSTEM` 指向空设备、`GIT_CONFIG_NOSYSTEM=1`），免得用户配了提交签名、凭据助手之类，在后台反复弹窗；`gc.auto=0`，提交身份固定、不签名；排除表里包含 `.git/`，嵌套的 git 仓库只记成"子模块指针"不记文件，并在提交说明里注明"嵌套仓库没有被捕获"（`checkpoint_manager.py:316-354,561-571,1519-1531`）。Windows 上起 git 隐藏控制台窗口（`:405`）。
- **跳过什么**：根目录和用户家目录不存（`:931-934`）；超过 5 万个文件的目录不存（`:164,1429-1432`）；单文件超过 10 MB 的从索引里剔除（`:1476-1478,1580-1621`）；容器后端不存（路径属于容器）（`:809-821`）。
- **恢复**：`/rollback` 列出检查点（序号、时间、原因、改了几个文件 +/-），`/rollback N` 整份恢复，`/rollback diff N` 先看差异，`/rollback N <文件>` 只恢复一个文件（`HM tools/checkpoint_manager.py:950-989,1638-1673`；命令在 `HM hermes_cli/cli_commands_mixin.py:528-621`）。恢复前会检查路径不能是绝对路径、不能用 `..` 跳出工作目录（`checkpoint_manager.py:190-205`）、提交号只能是 4–64 位十六进制（不会被当作 git 选项，`:174-187`）。
- **恢复前再存一份**：真正动手前先拍一张"回退前快照（正要恢复到 xxxx）"，所以"撤销撤销"可行（`:1277-1278`）；而且清理这张快照的数量上限要等恢复完成后再做，免得刚拍的快照把要恢复的树挤掉（`:1379-1381`）。
- **别覆盖主人的手改**：每次 `write_file` / `patch` 成功后记下"写完后文件的哈希"（`record_agent_write`，`HM agent/turn_explainers.py:147`），整目录恢复（默认的"安全模式"：不是 `--all`、也不是单文件，`HM hermes_cli/cli_commands_mixin.py:610`）时，当前哈希 ≠ 记录的 → 说明主人后来手改过 → **跳过并列出**；Hermes 从没写过的文件也不动；Hermes 新建的、检查点里没有的文件才会被删除，但超过大小上限被排除的文件**不删**（"留着一个旧文件的代价小于删掉唯一一份"）（`checkpoint_manager.py:827-918,1251-1316,1371-1376`）。
- **清理**：每个项目最多 20 个检查点（引用重写 + 回收旧提交）、整个库最多 500 MB（超了就每个项目轮流丢最旧的）、后台清扫（每 24 小时最多一次，**不在启动路径上**因为 `git gc` 可能卡几十秒）按 `retention_days: 7` 删久未使用的项目；**绝不自动删"孤儿"**（工作目录不见了可能只是移动硬盘没插、VPN 断了），孤儿只能手动 `hermes checkpoints prune`；删除孤儿前还要核对父目录的设备 + inode 和"父目录里确实有别的东西"（`config_defaults.py:498-517`；`checkpoint_manager.py:1623-1635`；`HM tools/checkpoint_maintenance.py:37-120`）。每次 `git` 调用超时 30 秒（`checkpoint_manager.py:161`）。
- **记忆 / 技能的写入审批是另一回事**：`memory.write_approval` / `skills.write_approval` 打开后，Agent 写记忆和技能不直接落盘，而是存成待审文件 `pending/<类别>/<id>.json`，用 `/memory pending` 之类审阅；后台复盘产生的永远暂存（`HM tools/write_approval.py:1-10,74-92,201-216`）。这对 Sumika 的"她们自己写记忆 / 人设"的担心有参考价值，但不是文件检查点，本轮不展开。

### 3.2 DeepSeek 和 Codex

### 3.3 Sumika 怎么做

**为什么不照搬整目录影子 git**（这一条是我的判断，不是源码里读到的）：

1. `tools.workdir` 默认是用户目录（`SK daemon/plugins/tools.ts:67`），Hermes 自己会跳过家目录和根目录；主人的项目目录里有视频、3D 工程，会撞上 Hermes 的 5 万文件、10 MB 上限，等于大部分时候存不了。
2. 选体检结论：这台电脑上后台直接起外部程序头几次要卡 5～12 秒（`SK docs/archive/notes/对照汇总-2026-10-18.md` 第四节）；每次写文件前起 git 不现实。
3. Sumika 的写入都带明确路径（`write` / `edit`），只需要"这个文件改之前长什么样"，不需要整个目录的快照。

**方案**：纯 TypeScript 的"改前旧版本"仓库，不起任何外部程序。

```
data/checkpoints/
  objects/<sha256 前两位>/<sha256>     # 旧文件内容，内容寻址，天然去重
  index.jsonl                          # 一次写入一行
  lock                                 # 写索引和清理时的锁
```

`index.jsonl` 一行：`{ id, ts, conversation, character, toolCallId, tool, path, existedBefore, beforeSha, afterSha, size, kind: 'write'|'pre-rollback' }`。`afterSha` 在 `afterToolCall`（pi 有这个钩子，`SK node_modules/@earendil-works/pi-agent-core/dist/types.d.ts:94-107`）里补上，它就是 Hermes 的 agent-write ledger（"Sumika 写完后文件长什么样"）。

**要改的文件**

| 文件 | 改什么 |
|---|---|
| 新 `SK daemon/tools/checkpoints.ts` | 存、列、预览差异、恢复、清理；全是纯函数 + 文件读写 |
| `SK daemon/plugins/tools.ts` | `gate()` 放行后、执行前，对 `effects` 含 `write` 且 `paths(args)` 非空的调用调用 `checkpoints.capture(...)`；`afterToolCall` 补 `afterSha` |
| `SK daemon/plugins/console.ts`、`SK web/src/types.ts` | WebSocket：`checkpoint.list` / `checkpoint.diff` / `checkpoint.restore`（单文件、整轮）|
| `SK web/src/ui/chat.tsx` | 写文件的工具卡片上加"撤销这次改动"；回合底部"撤销这一轮的 N 处改动" |
| `SK daemon/config.ts`、`SK sumika.example.yml` | `tools.checkpoints: { enabled, maxPerPath: 20, maxTotalMb: 500, retentionDays: 14, maxFileMb: 10 }` |
| `SK docs/subsystems/tools.md`、`SK docs/决策记录.md` | 参考页 + ADR（动了真实数据目录结构，AGENTS.md 要求写"怎么撤回"） |

**规则**

- 只在 `write` / `edit` 批准之后、真正写之前存；**powershell 不自动存**（路径不可知；第二期只处理命令里能直接读出明确路径的 `Remove-Item` / `Move-Item` / `Set-Content` / 重定向，路径落在工作目录内才存）。
- 不存的：超过 `maxFileMb`（界面上写一句"太大，没存旧版本"，不要悄悄跳过）；`data/` 下任何东西、`.env*`、密钥文件（这条比 Hermes 严：Hermes 的默认排除表只排了 `.env`，Sumika 的 `data/` 里有密钥，`HM tools/checkpoint_manager.py:148-152`）；新建的文件记 `existedBefore:false`（恢复 = 删除这个文件）。
- 恢复：
  1. 路径必须在索引里出现过且是绝对路径，不接受用户手填路径（照 Hermes 的路径校验思路，`HM tools/checkpoint_manager.py:190-205`）。
  2. 当前内容的哈希 ≠ 该文件记录的 `afterSha` → 说明被手改过 → **默认跳过并列出**，界面上给"仍然覆盖"的二次确认。
  3. 动手前先把当前内容也存一份（`kind:'pre-rollback'`），所以能撤销撤销（照 Hermes `:1277-1278`）。
  4. "撤销这一轮"按这一轮所有 `toolCallId` 倒序逐个恢复，恢复完整轮才清理数量上限（照 `:1379-1381`）。
- 清理：每个路径最多 `maxPerPath` 份、总量 `maxTotalMb`、超过 `retentionDays` 的丢掉；**后台空闲时清，不在工具调用的路径上做**（照 `:1624-1625` 的注释）；对象文件没有任何索引行引用时才删；找不到原路径的索引行**保留**（和 Hermes 一样，不自动当孤儿处理，移动硬盘可能只是没插）。
- 默认值：**`write` / `edit` 开，`powershell` 不开**（我的倾向：只复制被改的文件，代价很小；但这会往 `data/` 里复制主人的文件内容，所以请主人点头）。Hermes 是默认关。

**怎么测**（临时数据目录；不碰真实 `data/`、不碰 MaiBot / AstrBot 的文件）

| 测什么 | 放回旧代码 / 改坏后 |
|---|---|
| 写一个已存在的文件 → 索引多一行、对象文件内容 = 旧内容；恢复 → 文件回到旧内容 | 旧代码根本没有检查点 → 红 |
| 新建文件 → 恢复 = 删除 | 把 `existedBefore` 判断去掉 → 红 |
| 写入后主人手改，再整轮恢复 → 该文件被跳过并出现在 `skipped` 里 | 去掉 `afterSha` 比较 → 红 |
| 恢复前存了 `pre-rollback`：恢复后再"恢复到回退前" → 回到恢复前的内容 | 删掉 `pre-rollback` → 红 |
| 路径穿越 / 不在索引里的路径 → 拒绝 | 去掉校验 → 红 |
| `data/` 下的文件、超过 `maxFileMb` 的文件 → 不存，并在返回里说明 | 去掉排除 → 红 |
| 清理：超过 `maxPerPath` 后最旧的丢，整轮恢复期间不被清掉 | 在恢复前就清理 → 红 |
| 写入 `index.jsonl` 到一半崩溃（截断最后一行）→ 读取时忽略坏行，不整体失败 | 去掉容错 → 红 |
| 放大十倍：上万条索引、100 个同内容文件 → 对象只存一份；列出 / 恢复的耗时记在提交说明里 | — |

**怎么保证 QQ 渠道照样拿不到执行类工具**

- 检查点只在 `gate()` 放行 `write` 工具之后触发，而 QQ 听众拿不到写工具；恢复接口只接控制台 WebSocket。
- 检查点目录在 `data/` 下，属于受保护路径；恢复写回的是用户原路径，仍然要过一遍 `decide()`（写入受保护路径照样要问）。
- 恢复不是工具，模型调用不到；它不会成为 QQ 渠道的任何入口。
