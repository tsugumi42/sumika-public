# 对照：模型配置怎么设计——opencode、oh-my-pi、Codex CLI、Hermes Agent（2026-11-09）

> 挂：[规格-模型配置](../规格-模型配置.md)。起因：主人 2026-11-09“现在的模型页太依赖 magpie……完全就不是一个正常 agent Harness 应该有的模型配置设计”。
> 做法：`gh` 取最新，浅克隆到 `_external\_mc\`（`opencode`、`omp`、`codex`、`hermes` 四个目录），读源码和各家自带的配置说明；本机原有的 `_external/opencode`、`oh-my-pi` 等克隆没用，可能是旧的。
> 版本：opencode（`anomalyco/opencode`，原 sst/opencode 已改名）dev 分支 （2026-11-08）；oh-my-pi（`can1357/oh-my-pi`）main （2026-11-09）；Codex CLI（`openai/codex`）main （2026-11-09）；Hermes Agent（`NousResearch/hermes-agent`）main （2026-11-08）。
> 证据标记：[读码] 读了定义或实现；[读文档] 只读了该项目自带的说明；[推断] 按文件名、导入推的，没逐行读。

## 一句话结论

| 项目 | 结论 |
|---|---|
| opencode | 服务商和模型是**两层带覆盖的目录**：内置目录（models.dev 快照，能联网刷新）+ 用户配置覆盖；模型引用写成 `provider/model#variant`，服务商 ID 不能含 `/`，所以按第一个斜杠切开不会错。没有跨模型备选链，只有同模型重试。 |
| oh-my-pi | 最完整的一家：`models.yml` 定义服务商和模型（可手写、可自动发现），`config.yml` 里 `modelRoles` 按用途分配（十几个岗位），`retry.fallbackChains` 按岗位、具体模型或服务商通配写备选链，`[]` 表示明确不回退。界面是 `/models` 的"岗位"视图。 |
| Codex CLI | 服务商是 TOML 表 `model_providers`，字段偏**连接和认证**（地址、环境变量里的 key、命令取 key、请求头、重试和空闲超时）；协议只有 Responses 一种；自定义服务商**不自动发现模型**，除非给了 `model_catalog_url` 或本地目录文件，否则用兜底元数据并警告。用途只有主模型和 `review_model`，没有备选链。 |
| Hermes Agent | 最接近 Sumika 的使用方式：`model` 是主模型，`providers` 是命名端点，`auxiliary.<任务>` 给每个后台任务单独指模型（默认 `auto` = 跟随主模型），`fallback_providers` 是有序备选链；桌面端设置页有"测试"按钮发现模型、备选链编辑器、后台任务行和"固定了已不用的服务商"提醒。 |

## 1. opencode

读的是 `packages/schema/src/config/provider.ts`、`config/model.ts`、`config/agent.ts`、`config/compaction.ts`，`packages/core/src/config/plugin/provider.ts`、`model-resolver.ts`、`model-retry.ts`、`models-dev.ts`、`credential.ts`，`packages/app/src/settings/`、`providers/`。

- **服务商怎么定义**：[读码] 配置里 `providers.<id>`：`canonical`（以另一个服务商为蓝本）、`name`、`env[]`（认证用的环境变量名）、`package`（用哪个适配包，即协议）、`compatibility`、`settings`（含 `baseURL`）、`headers`、`body`（额外请求体）、`models{}`。认证方式登记成"集成"：手填 key、环境变量、OAuth；凭据存在数据库表里（`core/src/credential.ts` 的 `CredentialTable`），配置文件里不放 key。
- **模型目录怎么来**：[读码] 内置一份 models.dev 快照（`core/src/models-dev/snapshot.txt`，发布时尽量换成联网取到的），能联网刷新（`models-dev.ts` 的 `refresh`）；少数服务商（Copilot、Azure、ChatGPT、Modal）另外请求自己的 `/models`（`core/src/github-copilot/models.ts`、`modal/models.ts`、`plugin/provider/azure.ts`）。用户配置的 `models.<id>` 在目录上叠加，可以 `disabled`、改 `modelID` 做别名。顺序是：内置目录 → 外部插件改写 → 用户配置覆盖（`config/plugin/provider.ts` 注释里写明"显式模型覆盖放在晚位"）。
- **能力和上限放哪**：[读码] 每个模型一条：`limit{context,input,output}`、`cost{input,output,cache,tier}`（每百万 token 美元）、`capabilities{tools,input,output,temperature,reasoning{supported,toggle,effort[],budget}}`、`variants`（同一模型的思考档位等变体，由 `capabilities.reasoning` 推出）。
- **按用途选模型**：[读码] 顶层 `model`（默认）；每个 agent 一个 `model`（`config/agent.ts`）；旧配置的 `small_model` 被迁成 `agents.title.model`（`core/src/config/normalize.ts:137-151`）。压缩配置只管开关、保留量和余量（`config/compaction.ts`），没有单独的压缩模型。
- **回退链**：[读码] 没找到跨模型备选链。`model-retry.ts` 只是同模型重试（间隔 2 秒起、每次最多 10 秒、最多 10 次；本机没网另算一小时窗口）。只看了模型解析、重试、agent 三处，没全仓排查。
- **引用格式**：[读码] `provider/model#variant`；服务商 ID 和模型 ID 的正则在 `config/model.ts` 里写死（服务商不含 `/`、`#`）。
- **界面**：[推断] `app/src/providers/connect/dialog.tsx`：服务商选择对话框，分"已连接 / 热门 / 其他服务"，带搜索，选中后填 key 或走 OAuth；`app/src/settings/models/models.tsx`：按服务商分组的模型列表，可搜索、分组可折叠（折叠状态持久化）、每个模型一个开关；`providers/models/select-dialog.tsx`：选模型的弹窗。

## 2. oh-my-pi（omp）

读的是 `docs/models.md`、`docs/settings.md`（"Models"一节）、`packages/coding-agent/src/session/retry-fallback-chains.ts`、`config/model-registry.ts`（只读了文档指向的位置）、`packages/tui/src/overlays/model-selector.ts`。

- **服务商怎么定义**：[读文档] `~/.omp/agent/models.yml` 的 `providers.<id>`：`baseUrl`、`apiKey`、`api`（线路：`openai-completions`、`openai-responses`、`anthropic-messages` 等一长串）、`auth`（`apiKey` / `none` / `oauth`）、`headers`、`authHeader`、`discovery`、`models[]`、`modelOverrides`、`compat`。`apiKey` 的写法：先当环境变量名查，没有再当字面值；以 `!` 开头表示"执行命令取 stdout"，命令十秒超时、进程内缓存、失败退避 30 秒，**读目录时不执行命令**。取 key 的顺序有七层（运行时参数 > 配置 > 已存 OAuth > 登录存的 key > 扩展兜底 > 环境变量 > 其他存的 key）。
- **模型目录怎么来**：[读文档] 合并顺序：用户配置定下覆盖和自定义 → 内置目录（`packages/catalog`）→ 缓存和运行时发现的行 → 自定义 `models` → 用 `modelOverrides` 收尾；后台发现重跑一遍，用户写的永远压在发现结果上面。发现类型 `discovery.type`：`ollama`、`llama.cpp`、`lm-studio`、`openai-models-list`（读 `{baseUrl}/v1/models`）、`proxy`、`litellm`。探测超时：本机回环 150–250 毫秒，远程 10 秒，可逐个服务商改。`/models` 行里报告了上下文、输出上限、思考档位就用报告的；什么都没报才回落到内置参考，再不行用 128000 上下文、32768 输出的通用值。
- **能力和上限放哪**：[读文档] 每个模型 `contextWindow`、`maxContextWindow`、`maxTokens`、`input[]`（text、image）、`reasoning`、`cost`、`compat`（`supportsStore`、`supportsDeveloperRole`、`supportsReasoningEffort`、`maxTokensField`、`extraBody` 等逐项兼容开关；未知键只警告不拒收）。
- **按用途选模型**：[读文档] `config.yml` 的 `modelRoles`：`default`、`smol`、`slow`、`vision`、`plan`、`commit`、`tiny`、`memory`、`task`、`advisor`，另有按"模型种类"的岗位 `image`、`web`、`speech`、`dictation`、`judge`。岗位值可以是逗号分隔的几个候选（取第一个可用的，不是失败重试）；`@smol` 这类别名引用别的岗位；`tiny` 没设时回落到 `smol`，`memory` 回落到 `tiny`。预设 `modelPresets` 把整套岗位分配存成一个名字，一键切换。每个模型还可以有自己的 `compactionModel`、`contextPromotionTarget`。
- **回退链**：[读文档、读码] `retry.fallbackChains`，键可以是岗位名、具体模型选择器或服务商通配；值是选择器列表，`[]` 明确"不回退"；种类岗位没设链时用内置优先级。有"回到主模型"的策略（冷却到期或永不），状态在 `retry-fallback-chains.ts`。
- **引用格式**：[读码] `provider/modelId`，按第一个斜杠切；一个 `isLiteralModelId` 钩子处理模型 ID 自己带斜杠或冒号的歧义（`model-selector.ts`）；后缀 `:high` 带思考档位，`@upstream` 带路由。
- **界面**：[读文档] `/model` 打开"模型中心"：岗位视图 + 各服务商目录；岗位视图里编辑岗位分配和它的备选行；`omp models`、`omp models refresh` 命令行同样能列、能强制刷新。没读 TUI 的具体渲染。

## 3. OpenAI Codex CLI

读的是 `codex-rs/model-provider-info/src/lib.rs`、`config/src/config_toml.rs`、`config/src/types.rs`、`protocol/src/config_types.rs`、`protocol/src/openai_models.rs`、`model-provider/src/models_endpoint.rs`、`models-manager/src/model_info.rs`。没有图形设置页层可对照，TUI 的 `/model` 只确认存在，没读。

- **服务商怎么定义**：[读码] `config.toml` 的 `[model_providers.<id>]`，类型 `ModelProviderInfo`（`lib.rs:149`）：`name`、`base_url`、`env_key`（环境变量里的 key）、`env_key_instructions`、`experimental_bearer_token`（注释写"不鼓励，有安全顾虑"）、`auth`（命令取 token：`command`、`args`、`timeout_ms`、`refresh_interval_ms`，`protocol/src/config_types.rs:570`）、`aws`、`query_params`、`http_headers`、`env_http_headers`（请求头的值来自环境变量，没设就不带）、`request_max_retries`、`stream_max_retries`、`stream_idle_timeout_ms`、`supports_websockets`、`capabilities`（覆盖能力）。`wire_api` 目前只有 `responses` 一种（`lib.rs:117`）。内置服务商：openai、amazon-bedrock、gcp、ollama、lmstudio（`lib.rs:757`）。
- **模型目录怎么来**：[读码] OpenAI 走官方后端的目录；**自定义服务商只有设了 `model_catalog_url` 才发现模型**（`models_endpoint.rs:292`）；否则读 `model_catalog_json` 本地文件（`config_toml.rs:410`），都没有就用兜底元数据并警告 "Unknown model … fallback model metadata"（`model_info.rs:97-99`）。
- **能力和上限放哪**：[读码] 目录条目 `ModelInfo`（`openai_models.rs:428`）：`slug`、`display_name`、`supported_reasoning_levels`、`default_reasoning_level`、`context_window`、`max_context_window`、`auto_compact_token_limit`、`input_modalities` 等；用户还能用 `model_context_window`、`model_auto_compact_token_limit` 在顶层覆盖。
- **按用途选模型**：[读码] `model`、`model_provider`、`review_model`（只给 /review 用）；`[profiles.<名>]` 可以整套换 `model`、`model_provider`、推理档位等。没有后台、压缩、识图岗位。
- **回退链**：[读码] 配置结构里没有（`config_toml.rs`、`profile_toml.rs` 搜 fallback 没有命中）。
- **认证存放**：[读码] `cli_auth_credentials_store`：`file`（默认，`CODEX_HOME/auth.json`）、`keyring`、`auto`、`ephemeral`（`config/src/types.rs:138`）。

## 4. Hermes Agent

读的是 `cli-config.yaml.example`（配置样例，注释即规格）、`website/docs/integrations/providers.md`、`website/docs/developer-guide/model-provider-plugin.md`、`providers/base.py`、`agent/model_metadata.py`，以及桌面端 `apps/desktop/src/app/settings/` 下的 `custom-endpoints-settings.tsx`、`fallback-models-field.tsx`、`aux-task-rows.tsx`、`model-settings.tsx`、`providers-settings.tsx`。

- **服务商怎么定义**：[读码] 内置服务商是插件（`providers/base.py` 的 `ProviderProfile`：`name`、`api_mode`、`aliases`、`display_name`、`signup_url`、`env_vars`、`base_url`、`auth_type`、`default_aux_model`、`fallback_models`），用户可往 `$HERMES_HOME/plugins/model-providers/` 丢目录覆盖同名内置。配置里 `providers:` 是命名端点：`base_url`、`key_env`（环境变量名）、`api_key`、`key_cmd`（每次请求前执行命令取短期 token，到期前缓存）、`api_mode`（`chat_completions` / `codex_responses` / `anthropic_messages`）、`extra_headers`、`extra_body`（合并进该服务商的每个请求）、`request_timeout_seconds`、`models.<id>.{timeout_seconds,context_length}`、`session_affinity_header`。key 存在 `~/.hermes/.env`。
- **模型目录怎么来**：[读码] `providers.<名>.models` 手写 + 服务商 profile 的 `fetch_models`（带 `hermes-cli` UA，因为有的网关对默认 UA 返回 403）+ models.dev（`agent/models_dev.py`）。上下文长度的解析顺序写在 `agent/model_metadata.py:2211-2220`：用户配置覆盖最先 → 持久缓存 → 自定义端点的 `/models` 和本机探测 → 服务商专属目录 → models.dev → 硬编码默认 → 256K 兜底。
- **能力和上限放哪**：[读码] `model.context_length`（"留空，自动探测；探测错了才手填"）、`models.<id>.context_length`；输出上限不让用户配（"服务商自己的事"）；推理档位 `reasoning_effort` 按任务配。
- **按用途选模型**：[读码] `model.default` + `model.provider`；`auxiliary.<任务>`：`vision`、`web_extract`、`compression`、`title_generation`、`session_search`、`approval`、`mcp`、`curator`、`background_review` 等，每个 `{provider, model, timeout, reasoning_effort, extra_body…}`，**默认 `provider: auto` = 跟随主模型**；委派子代理另有自己的 `delegation.fallback_providers`。
- **回退链**：[读码] 顶层 `fallback_providers:` 是 `{provider, model, …}` 列表，按序尝试（限流、服务端错误、认证失败）；`hermes fallback` 命令行可交互编辑。
- **界面**：[读码] 桌面端设置页：`custom-endpoints-settings.tsx` 有"测试"按钮，请求 `/models`，成功后把模型填进下拉；测试成功时会把**实际能返回 `/models` 的那个地址**（比如用户没写 `/v1`，实际在 `<根>/v1`）存下来，否则测试绿了、实际请求全 404（该文件注释引用 #65488）。`fallback-models-field.tsx` 是备选链编辑器，只改 provider 和 model 两格，其余手写的键（`base_url`、`key_env`、`api_mode` 等）原样保留，否则自动保存会把本地网关的备选链改写成公共服务商（注释引用 #89184）。`aux-task-rows.tsx` + `model-settings.tsx`：每个后台任务一行，可选"跟随主模型"，并检测"某任务固定到了和当前主服务商不同的服务商"（`staleAuxAssignments`），提醒"几个月前固定过、现在还在向已不用的服务商计费"。

## 对 Sumika 有用的做法（汇总，采用情况见规格）

1. 服务商是一等对象，`providers.<id>` 一张表；key 不在配置里放明文：omp 的环境变量名 / 命令、Codex 的 `env_key` / `auth.command`、Hermes 的 `key_env` / `key_cmd`、opencode 的凭据库。四家都有"环境变量"这一条；三家有"命令取 key"。
2. 目录 = 发现 + 手填覆盖，覆盖永远压在发现结果上面（omp、opencode）。能力以服务商报告为准，没报告再手填，最后才是通用兜底（omp、Hermes）。Codex 的"自定义服务商不发现，用兜底并警告"是反面例子：可用但不好用。
3. 引用格式：opencode 和 omp 都按第一个斜杠切 `provider/model`，服务商 ID 约束成不含斜杠；omp 为"模型自己带斜杠"留了判定钩子。
4. 用途分配：omp（岗位表 + 预设）和 Hermes（`auxiliary` 每任务一块 + "跟随主模型"）；Hermes 的"跟随"在没选后台模型时比 Sumika 现有"没选就不跑"更省事，但与 ADR-098 冲突，见规格拍板问题。
5. 备选链：omp 按岗位、模型、服务商通配；Hermes 全局一条加委派一条；二者都有"明确空表 = 不回退"（omp 的 `[]`，Hermes 委派的 `[]`），与 Sumika 已有 `fallbackModels` 的"省略继承、`[]` 禁用"一致。
6. 界面：测试按钮分类报告并把"实际能用的地址"提示出来（Hermes）；备选链编辑器不丢手写字段（Hermes）；服务商页和模型页分开、模型按服务商分组带搜索和开关（opencode）；岗位视图把"每个用途用哪个模型"放一张表（omp、Hermes `aux-task-rows`）；固定了已不用服务商的提醒（Hermes）。
7. 未知兼容字段只警告不拒收、保留原样（omp）；请求头里的秘密值也走引用（omp 的 `!cmd` 同样适用于 `headers`、Codex 的 `env_http_headers`）。
