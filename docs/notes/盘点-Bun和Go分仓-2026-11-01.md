# 盘点：Bun 和 Go 分成两个仓库（2026-11-01）

> 2026-11-01 后来改了两处：Go 的对拍录像由 Go 自己录、不回 sumika-bun 重录（ADR-225 第 3 条）；sumika-bun 只推到私有远端做备份、本机不留（ADR-226 第 2 条），文中"在 sumika-bun 里重录""去旁边的 sumika-bun 找"的说法以 ADR 为准。

> 主人 2026-11-01："把这个仓库的bun那一整套和go完全分离干净变成两个仓库吧 完全忘记做这个了，这俩是不是应该是完全不一样的东西"。
> 主会话派一个分身盘点并在本地做出来：主仓库分支 `chore/split-bun`，新目录 `<本机项目>/sumika-bun`。盘点时 main 在 e60b7e5c。只读了文件，没查进程、没碰定时任务、没读 `data/`。
> ADR 草稿在第六节，编号由主会话占；落地结果在第七节。

## 结论

可以干净分开。真正连着的只有四处，都已有解法：

1. **Go 的对拍录像是 Bun 生成的**（`native/internal/turn/testdata/golden` 等十几份），改 `prompts/` 就要用 Bun 重录（a4753eba 是一次）。分完以后在 sumika-bun 里重录，写回主仓库。
2. **一个平常就跑的 Go 测试会起 Bun 代码**：`native/internal/secrets` 的 `TestOpenBunInterop` 跑 `bun run testdata/write-bun.ts`，它 import `daemon/util/secrets.ts`。只要机器上有 bun，删了 daemon/ 它就红。（已被 ad31c5bf 删除，ADR-225）
3. **表二的 Bun 壳**：`cmd/bench-t2`（默认 `-shells go,bun,omp`）和 `cmd/bench-shell` 的对照子测试（要设 `SUMIKA_BENCH_BUN=1`）拼的路径是 `<主仓库>/scripts/bench-t2/shell-bun.ts`，它 import 十几个 daemon 模块。
4. **Bun 后台可能正从主工作区跑着**（ADR-208），数据目录、配置都按"代码目录下的 `data/`"找。分支合进 main、主工作区一签出，daemon/ 就没了：已经起来的进程靠内存里的代码还能跑，但看门脚本重启、设置里的"重启"都会拉不起来。所以**先让 Bun 停下或从新目录起，再合并**。

## 三、Bun 后台现在怎么跑、分出去以后怎么跑

仓库里能看到的起法：`启动后台-看门.cmd`（`cd /d "%~dp0"` 后 `bun scripts/supervise.ts`，看门脚本再起 `bun daemon/main.ts`，崩了自动拉）；`package.json` 的 `start`、`supervise`、`dev`；本机的 `.claude/launch.json`（不进 git）里有 `sumika-daemon`、`sumika-web` 两个预览项，用的是临时数据目录，不是主人平时那份。

Bun 从**代码目录**找这些东西（root = `daemon/` 的上一层）：

- 配置：`SUMIKA_CONFIG` → `<SUMIKA_DATA_DIR 或 root/data>/config/sumika.yml` → `root/sumika.yml`（daemon/config.ts:217-220）。
- 数据目录：`SUMIKA_DATA_DIR` → `root/` + 配置里的 `dataDir`（默认 `data`，daemon/main.ts:80）。
- 备份目录：配置里的 `backup.dir` 相对 root 解析（main.ts:157）。
- 出厂提示词 `root/prompts`、示例卡 `root/characters/example`、`root/embed/bridge.py`、`root/vendor/bin`、网页 `root/web/dist`。

所以换到 `<本机项目>/sumika-bun` 起，`root/data` 就不在了，几种指法：

1. **目录联接（推荐，要切的话）**：`sumika-bun\data` 联到 `sumika\data`。不加环境变量、不改配置，和现在跑的一样。风险：删 sumika-bun 时要用资源管理器（只删联接），不要用 Windows PowerShell 5 的 `Remove-Item -Recurse`（会顺着删到真数据）。
2. `SUMIKA_DATA_DIR`（**不推荐**）：它在 Bun 里是"隔离运行"的开关，不只换路径：关掉找本机 QQ 和协议端目录（main.ts:163、qq-local.ts:30，配置里没写 protocolDir 时连不上），忽略配置的 `backup.dir`（main.ts:157），和现在跑的不一样。
3. `SUMIKA_CONFIG` 指到真实配置：配置里的 `dataDir` 还是相对新目录解析，除非它写的是绝对路径（没读配置，没核实）。

另外两处要知道：配置的 `backup.dir` 如果写的是相对路径，从新目录起会相对新目录解析（同样没核实）；本机的更新检查 `code-rules/_tools/check-updates.ps1` 会扫 `上级代码目录` 下每个不以 `_` 开头的目录，sumika-bun 装了依赖以后会出现在"项目依赖"里，退役的仓库不该跟着升级。

## 四、计划

### 4.1 做法

- 主仓库 tsugumi42/sumika 留 Go（native/）、共用的提示词 / 示例卡 / 示例配置 / embed / 文档、脚本运行时和钩子；Bun 后台、网页、Electrobun 壳和只属于它们的脚本、测试分到 `<本机项目>/sumika-bun`，远端暂定私有的 tsugumi42/sumika-bun（建不建等主人）。
- 新仓库不带历史（照 ADR-222）：第一个提交是 main 上那一刻的文件原样（目录结构不变，相对路径都还成立），README 写明从哪个提交切出来、已退役、只当历史资料；第二个提交是让它单独成仓要改的几处（下面列）。主仓库历史不改写。
- 共用的东西：**拷一份快照，以后不同步**（建议）。理由：Bun 已退役（ADR-203），剩下的用处是存聊天记录、私聊只回主人；跟着主仓库改提示词，Go 那边新加的写法 Bun 未必认得（LESSONS"换了输出格式的提示词，要和读它输出的解析代码同时生效"）；快照逐字节一样，Bun 里注入测试按提示词算的哈希（daemon/util/injection.ts:14）不变，已经过的群不用重考。主人的自定义提示词在 `data/config/prompts/`，两边照样共用。代价：和待办"提示词两边共用，照常改"冲突，Bun 停之前在主仓库改的出厂提示词不会到 Bun 那边，要主人定。
- Bun 仓库单独成仓要改的：对拍生成器（`go-golden-*`、`gen-go-*`、`bench-t2/approve.test.ts`、从 native/ 搬来的 `gen-asent/dialog/gate.ts` 和 secrets 的 `write-bun.ts`）的输入输出改成主仓库（`SUMIKA_MAIN`，不设就是旁边的 `../sumika`），`go-golden-turn` 的提示词也从主仓库读（录像要和主仓库的提示词对得上）；package.json 去掉 `lefthook`（退役仓库不装钩子）和 `check:docs`，`bun install` 更新锁文件。
- Go 要跑 Bun 代码的两处（secrets 对拍、bench 的 Bun 壳）走一个只给工具和测试用的小包 `internal/bunrepo`：先看 `SUMIKA_BUN_ROOT`，不设就从 git 找主工作区、取它旁边的 sumika-bun；找不到时 secrets 对拍算红（有 bun 时）、bench-shell 的对照子测试（设了 `SUMIKA_BENCH_BUN=1`）算红、bench-t2 开跑前就报错。登记进 arch_test 的 toolOnly。（secrets 对拍已被 ad31c5bf 删除，ADR-225）

### 4.2 切换顺序

1. 在新目录装依赖、过类型检查（不启动）。
2. 主仓库分支上删掉、改干净引用，`check:docs`、`go build ./...` 过。
3. **Bun 停下或已从新目录起以后**，才把 `chore/split-bun` 合进 main。如果离 Go 接管小号、Bun 停写只差几天，最省事是不切，等 Bun 停了再合。
4. 合并后主工作区里会剩下没进 git 的旧产物（`web/dist`、`web/public/fonts`、`web/public/twemoji`、shell 的编译结果），分支的 `.gitignore` 把 `/daemon/`、`/web/`、`/shell/` 整个忽略，不会冒进 `git status`；要不要删由主人定。主工作区的 `node_modules` 在下一次 `bun install` 时按新的 package.json 收掉 Bun 的包。

主人那边要做的一步（以后重启 Bun 时从新目录起；先停掉现在的 Bun：在看门脚本的黑窗口里按 Ctrl+C，再按任意键关掉）。在"命令提示符"（cmd）里逐行执行：

```bat
cd /d <本机项目>/sumika-bun
rem 作用：数据目录指到原来那份（目录联接，不复制、不移动数据）
mklink /J <本机项目>/sumika-bun\data 仓库根\data
rem 作用：打包 7720 的网页（web/dist 不进 git，新目录里要打一次）
bun run build:web
```

以后起 Bun：双击 `<本机项目>/sumika-bun\启动后台-看门.cmd`（不再用 sumika 里那个，合并后它就没了）。依赖和 rg、fd 已经在新目录里装好了；要重装就在同一个目录执行 `bun install --frozen-lockfile`。

## 五、要主人定的

1. **远端仓库**：建不建、叫不叫 tsugumi42/sumika-bun、私有还是公开。建议建成私有（默认收紧，ADR-222 同样做法），推之前用主仓库的隐私扫描过一遍。
2. **什么时候合并 / 切换**：建议等 Bun 停写（Go 接管小号、切换日）再合 `chore/split-bun`；非要先合，就照第四节先从新目录起 Bun。
3. **共用文件怎么给 Bun**：建议快照、不同步（理由见 4.1）；另一个选项是把 sumika-bun 的 `prompts/`、`characters/` 也做成联接指回主仓库，Bun 跟着主仓库的提示词走，代价是 Go 那边的提示词改动可能 Bun 不认、注入测试的哈希一变已开口的群要重考。
4. **对拍录像以后谁来定标准**：短期照旧由 Bun 重录（在 sumika-bun 里 `SUMIKA_MAIN=...` 跑生成器）；长期可以让 Go 自己的测试带更新开关、不再和 Bun 比（Bun 已退役，"和 Bun 一样"的意义越来越小）。要不要改、什么时候改，主人定。
5. **表二的 Bun 壳还要不要**：现在保留（去 sumika-bun 找），`-shells` 默认值没改；Bun 壳读的是快照的提示词，以后主仓库改了提示词，Go 壳和 Bun 壳就不是同一份提示词在比。
6. **sumika-bun 要不要进更新检查**：`check-updates.ps1` 会扫到它。建议在脚本里跳过它（或者目录改名成 `_sumika-bun`，但主会话给的名字是 sumika-bun，没改）。
7. **本机 `.claude/launch.json` 的两个 Bun 预览项**：`sumika-daemon`（`bun daemon/main.ts`）、`sumika-web`（`bun run dev:web`）指的是主工作区里的代码，合并后点开就报错。它不进 git、是主人本机的配置，没动；要的话改成在 sumika-bun 里起，或者删掉这两项。
