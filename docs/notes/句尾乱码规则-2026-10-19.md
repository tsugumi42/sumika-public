# 句尾乱码规则（2026-10-19）

Luna（gpt-6-luna，Codex 线路）的回复有时在整段话的最后多吐几个字：私用区或从没分配过的码位、零宽字符、和前文不搭的外文字母、落单的右引号、句尾顿号，偶尔还有色情、博彩推广里常见的词。不清的话会原样发进 QQ 群，也会留在她的历史里被她自己学走。和"】【"（调研-GPT输出的】【乱码（私有存档））是同一类问题。

- 规则：`daemon/util/tail-junk.ts` 的 `dropTailJunk`（纯函数）。
- 接在哪：`daemon/plugins/agent.ts` 的 `message_end`，见[参考页](../subsystems/agent-and-console.md)。
- 离线量：`scripts/try-tail-junk.ts`。正负样本、候选和逐条明细在 `data/dev/garble/`（不进 git）。本页不放任何原话，举例都是编的，或者只写码位、文字类别。

## 规则

只看整段话的结尾。乱码只出在整段话的最后，句中的不动，多个文字块时也只看最后一块（剥空了或只剩空白才看前一块）。从末尾往前一层一层剥"肯定是乱码"的几类，每剥一层先去掉末尾的空白，碰到别的就停。

### 删

QQ 群、QQ 私聊、主窗口都删：

| 类别 | 怎么认 | 为什么能删 |
|---|---|---|
| 私用区 / 未分配码位 | 私用区 U+E000～F8FF、第 15～16 平面，落单的代理项，第 4～13 平面（U+40000～DFFFF） | 第 4～13 平面 Unicode 从来没分配过字，私用区没有约定就显示不出来。U+F8FF 除外：苹果设备上是苹果 logo，打得出来 |
| 零宽字符 | `\p{Cf}`：零宽空格、零宽不连字、零宽连字、方向控制、BOM、软连字符 | 看不见，正常不会出现在整段末尾。旗帜 emoji 结尾的标签字符 U+E0001、U+E0020～E007F 除外 |
| 落单的右引号 | 末尾是"”"，前面没有没合上的左引号（"“"或半角"） | 引号没开就关 |
| 句尾顿号 | 末尾正好一个"、" | 按标点规范（GB/T 15834），顿号只在句内并列的词之间 |

只在 QQ 群删：

| 类别 | 怎么认 | 为什么只在群里删 |
|---|---|---|
| 外文碎片 | 末尾一串外文字母（字母或附标，不属于汉字、拉丁、希腊、假名、谚文、注音），紧挨着前面的是汉字，前文别处没有外文字母 | 会误删两类正常写法：解释外语词（汉字后面直接跟一个泰文、天城文的词）、网上的装饰字母（ღ、ฅ 这类）。群里乱码丢人、外语少，删；QQ 私聊里她的话几乎都是对用户说的，和主窗口一样乱码只有用户看得到、聊外语的可能大，只记数 |

群还是私聊看会话 id（`qq:group:` 开头的是群，和思考档位用的是同一个判断）；别的渠道、认不出来的都按不是群算，只记数。

### 只记数，不删

这几类像乱码，但会撞上正常写法，或者正样本不到 20 条（LESSONS"判定类规则"）。文字原样，照样发出去，包括色情、菠菜类的词。

| 类别 | 怎么认 | 为什么不删 |
|---|---|---|
| 垃圾词 | 最后一个分句里有词表里的词（9 个色情、博彩类的词） | 正样本 13 条，不到 20；和"在线""色彩""集群"这类正常词撞字 |
| 英文串 | 结尾一串拉丁字母，前文有汉字、别处没有拉丁字母 | "……OK""ASAP"、温度单位都会撞上 |
| 怪字"巜" | 末尾是"巜" | 只见过 1 条 |
| 别的平面的未分配码位 | 基本平面、第 1～3 平面、第 14 平面里 `\p{Cn}` 的 | 可能是运行时还不认识的新 emoji、新汉字 |
| 符号串 | 同一个 `\p{So}` 连写 4 个以上（默认画成彩色 emoji 的不算，三个的不算） | 只见过 1 条；"♪♪♪"这类正常写法离得很近 |
| 隔着空格的外文碎片 | 外文碎片和汉字之间隔着空格 | "中文 空格 外语词"是群里常见的正常写法 |
| 落单的 `**` | 末尾正好两个星号，整句里两个一组的星号是单数 | 会撞"傻**"这类屏蔽词 |
| 连着的句尾顿号 | 末尾两个以上"、" | "、、、"常被当省略号用 |
| QQ 私聊、主窗口的外文碎片 | 同上面"外文碎片"，不在群里 | 见上 |

### 不删也不记

外文碎片前面是括号、标点、emoji 的（颜文字末尾的外文字母，比如"(๑•̀ㅂ•́)و"）；整句都是外文、或前文别处也用了外文字母的（"ಠ_ಠ"）。

## 在 message_end 里的先后

1. 剥句尾乱码。
2. 清"】【"；清掉了东西就再剥一次乱码。编的例子："好的 U+5FFFF】【"清掉"】【"以后乱码露在末尾。
3. 平台的 `asSent`（QQ 去句尾句号，ADR-110、ADR-114）。排在最后："……。U+5FFFF"的句号要等乱码剥掉才在末尾。

三步一轮，循环到这句话不再变为止，最多 16 轮（真实 822 条最多 2 轮；"。乱码"交替 n 对要 n+2 轮，复核实测；到了上限还在变就停、记一行 warn）。去句号会连句号前面的空白一起去，露出前两步该清的东西，只跑一轮的话清完再清一遍还会变。编的例子："好的 U+5FFFF。""嗯……。U+200B。""收到】【 。"，都要去掉句号以后才清得到。不再变的时候 asSent 也不会再改它，所以 `sendOut` 的兜底不会再改库。

都在拆"[不说]"之前，理由跟着一起清。存进库的、发出去的、留在她实例历史里的是同一句。`segments.original` 记第一次去句号之前那句（asSent 真改了才有），这时已经剥过乱码、清过"】【"。

整段清完什么都不剩、或只剩空白（这一步没有工具调用）：当成这一轮不说，不存、不发，轮完从她的实例历史里拿掉。

删了或记了数时：
- 日志记一行：类别、码位，原来结尾的 40 个字（看不见的字写成码位）。日志留 14 天。
- 这一步的 `model_runs` 连回复一起存，`response_json.tailJunk` 带清之前的全文、删了什么、记了什么。留 7 天。

## 已知会错的形状

真实数据里都没撞上，等日志里攒到再看：
- QQ 群里的外文碎片：解释外语词的句子、装饰字母会被删（见上）。
- 落单的右引号：开、闭都打成"”"的输入法写法（"”走吧”"）会被删掉结尾那个。
- "<乱码>。"：乱码在句号前面，第一轮不算结尾、不剥；QQ 去掉句号以后下一轮剥掉，发出去的、库里的是干净的。但 `segments.original`（第一次去句号之前那句）里乱码还在：不去句号时存的就是这样。主窗口不去句号，乱码一直夹在句号前面留着。
- 前面某一步已经说过话（说了一句又调了工具）、最后一步全是乱码：整轮从她历史里拿掉，前面发出去的那句也一起没了。"[不说]"原来就是这样处理的，群里调工具很少。

按设计不剥的几种（复核 2026-10-19 小事第 5 条，编的形状，都核对过）：
- 零宽字符夹在闭引号前面（"他说“走吧 U+200B”"）：末尾是闭引号、引号是合上的，不剥，零宽留在引号里。
- "好的】【 U+5FFFF】【"：原样不动。清"】【"时第一个"【"和第二个"】"配成了一对，两处都不算多吐的（main 上原来就这样），乱码也就露不到末尾。
- 不是最后一段的段尾（"先烧水 U+5FFFF"空一行"再下面条"）：只看整段的结尾，不剥；QQ 里这一段会单独发成一条，乱码就在那条末尾。822 条候选里分了段的 176 条，前面某段段尾带乱码的 0 条。
- "[不说] 插不上话 U+5FFFF。"："[不说]"不去句号，乱码夹在句号前面一直露不出来，闸门记下的理由带着乱码；这句不发出去。
