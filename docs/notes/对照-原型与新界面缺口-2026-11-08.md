## 二、数据流与"原型长这样"的共同前提

[读码] 原型 `view.go:161` 起，`app.view` 画 `navigation | 会话列表（Split 可拖）| 聊天（可再 Split 出右栏）`；窄于 713（`breakpointNarrow`）折成三层（列表→聊天→资料），窄于 1006（`breakpointWide`）右栏改成盖在聊天上的抽屉。聊天列、气泡、输入框来自 `internal/chatui`，正式程序已复用；**其余全部是原型自己的 `app` 方法**：`nav` `sidebar` `compactSidebar` `header` `side` `drawer` `settings` `plugins`、控件 `segment` `switchControl` `lookSlider` `choice` `textField` 与令牌表 `tokens.go`。

[读码] 正式新界面 `workbench_view.go:93` 的 `workbenchView`：72 宽导航 + 固定 300/220/无 的 `convList`（旧界面同一个函数，`dialogs.List`）+ `workbenchChat`（`mewchat.Header` 标题栏 + `chatui` 消息列 + `chatui.Composer`）。没有右栏位，没有拖分隔条，没有三层折叠；记忆、运行、设置三页走 `pageShell`（`ui.go:92`），是旧界面页。

## 六、移植顺序建议

原则：先做"每天都看的骨架"，再做"一整栏"，最后做设置。每步能单独撤回（ADR-083）；每步都带下面验收清单对应的区域。

1. **第 0 步（不写界面）：令牌与配色单一来源**。决定正式窗口用 `chatui.Tokens`+`palette`（原型）还是 MewTypeUI `theme`（正式）。规格-新界面主线 §3 已留这个未解项，P 分支要做的也是它；不先定，后面每个区域都会再返工一遍。量：大，但它决定 B、C、D 的配色。
2. **C 会话列表（含 C1 分段、C2 新建群聊的新位置、C3 选中色）**。主人点名；改动集中在 `convlist.go`、`workbench_view.go`，可复用原型的 `segment`、`avatarSized`、行的画法。**新建群聊建议**：放在搜索行右端的"+"图标钮（32×32，圆形悬停底，和"收起会话列表"钮同一族），不占行；弹出沿用 `groupDialog`。不推荐放进分段控件内（会被误认为第三个分段）。需要主人看一眼位置再定（这是原型没有的新设计）。
3. **B 导航 + D 标题栏 + A1 顶行统一**：量小，但和 C 同屏，一起做才对齐；顺手加头像、状态副标题。
4. **A2/A3/I：布局骨架**（列表宽公式、可拖、窄窗三层、断点）：C 做完后补。
5. **G 右栏 + A4 抽屉**：成员先做，活动先放空态（没接口）。
6. **E、F：消息列外壳与输入栏**：多数在 `fix/newui-real`，等它合并后复测再补剩下的（回到最新、出现动画、壁纸）。
7. **H 设置页**：最后，且要等设置注册表（规格-设置页）；不要为了像而把旧页换皮。
