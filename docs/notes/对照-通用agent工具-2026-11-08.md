## 二、建议补的工具（五格）

五格：建 / 看 / 改 / 完成或取消 / 删。"已有"表示 Sumika 现在就有，"在做"表示待办已列。

A. 向主人提问（ask_user，对应 AskUserQuestion / question / request_user_input）
- 建：模型提出问题，给出 2–4 个选项，可写自由回答；发到本地私聊界面。
- 看：界面列出待答问题和状态（待答 / 已答 / 已取消）。
- 改：主人答之前可以改选择；答后模型已经读过，就只能再追问新问题，不改旧答。
- 完成或取消：主人选择或输入后结果回到模型；取消、超时或模型撤回时写明原因。
- 删：不提供删除，已答的留在记录里，避免改写历史；只在界面上收起。

B. 忘掉记忆（forget，对应待办"忘掉某条记忆"）
- 建：remember 已有，本项不重复。
- 看：memory_search 已有。
- 改：remember 的 replaces 已有，用来改正记错的条目。
- 完成或取消：写入层已有撤销，工具要把撤销暴露出来（撤销一条误删的记忆）。
- 删：forget(编号) 做成软删，进归档，可撤销；删的是主人明确的约定或边界时要主人确认。

C. 定时任务的列出、暂停、恢复、删除、改（对应 opencode 的 schedule_* 五件套，Claude 的 CronList / CronDelete）
- 建：schedule_next 在做，本项只指它的管理面。
- 看：列出所有定时任务、下次时间、上次结果。
- 改：改时间或内容。opencode 没有这一格，Claude 只能删了重建，建议补一个 update。
- 完成或取消：pause / resume；一次性任务跑完自动标为完成；取消就是暂停或删除。
- 删：delete 之前列出受影响的任务名，并走审批，主人确认后才删，删后不再提醒。

D. 子代理的列出与续跑（task_list / task_resume，对应 Claude 的续跑、Codex 的 list_agents）
- 建：task 已有。
- 看：task_list 列出本会话的子任务和状态；task_result 已有。
- 改：追加指示在做，本项不重复。
- 完成或取消：task_cancel 已有；达到上限结束的子任务标为 partial，task_resume 接着跑（Claude 的做法）。
- 删：未核实 Sumika 的子任务结果清理策略，先查 native/internal/subagent 再定。

- 没有核对的项都在表里标了"未核实"。
