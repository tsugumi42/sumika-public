# 调研：Agent 设计的行业现状（2026-11-04）

这批研究的主要价值是可复用的设计边界与验收方法，适用于以后不同模型、语言和 Agent 框架；具体产品参数、协议版本和默认权限必须按版本重查。
Windows MXC 的 2026-10-07 GA 公告属实，但 Codex 的原生 PSEC 路线、MXC 通用后端和 Windows Sandbox 是不同层次，不能互相代称。
当前优先级应是把已有检查点、任务、结果存储、预算、追踪与回放接通；本地两份规格已经覆盖了不少 ChatGPT 所建议的项目，不应重复开工。
本次完成 60 项重点核对：已核实（官方）53，已核实（论文或社区实测）6，未核实 1，不符 0。官方确认不代表本次实际运行过产品；论文与作者实验也没有在此复现。

## 三、隔离与运行环境：重点是 Windows

**行业常见做法〔ChatGPT 推测／归纳；依据 Q01—Q03、Q08—Q10〕**：审批决定能否执行，OS 边界限制获批进程能触及什么；任务目录分开可变工作文件。三者组合使用。提示词、命令前缀匹配、独立进程和 worktree 都不能单独证明 OS 隔离。

### 3.1 MXC 的日期、后端和真实可用性

**已核实（官方）**：微软公告确为 **2026-10-07**，正文写 “now generally available”。MXC 是把资源策略映射到具体隔离后端的执行层，公告同时区分 Process、Session、WSL 和实验 MicroVM。[公告][S01]

**已核实（官方）**：支持页所列 MXC v1.0.0，Windows V1 SDK 可用 ProcessContainer、IsolationSession、WSLc；Windows Sandbox、MicroVM、Hyperlight 仍实验且不能从 V1 SDK API 创建。后端可用、某个 SDK 操作可用、某项策略能强制执行，是三个问题；官方要求 runtime discovery 和正反两类验证。[支持矩阵][S02]

**已核实（官方）**：Codex Windows 文档区分 `mxc`、`elevated`、`unelevated`。MXC 所列 Windows 能力起点为 24H2 `26100.9278`／25H2 `26200.9278`；`0.162.0+` 是文中一次性探测命令的条件，不是整个 MXC 首发版本。[Codex 文档][S03]

**已核实（官方）**：Codex `rust-v0.162.0` 适配器专用 **PSEC + BaseContainerRunner**，明确不调用旧 AppContainer dispatcher、不改宿主 ACL、不建沙箱用户、不请求提权。它用实际 create/close probe；deny path 还需 `PSE_SUPPORT_FS_DENY`。显式 `windows.sandbox=mxc` 严格失败，命令失败不切换后端；偏好 MXC 的选择逻辑可在能力不可用时选既有后端。[固定实现说明][S04]

同一 README 明确：host loopback 能力为双向；前台进程正常结束或取消时，剩余后代也会被结束。LSP、watcher、devserver 需要更长寿命的 owner。微软总览说 Process 后端可含 AppContainer，与 Codex 这个拒绝旧 fallback 的适配器不是相同范围，不能用一个产品名抹平差别。

### 3.2 Claude 产品、独立运行库与容器

**已核实（官方）**：Claude Code 内置 shell sandbox 当前仍支持 macOS、Linux、WSL2；原生 Windows 命令 unsandboxed。Read/Edit/Write、MCP、hooks、LSP 等另走执行路径；默认允许读取多数主机文件和继承环境，需单独配置凭据保护。[产品文档][S05]

**已核实（官方）**：独立 `sandbox-runtime` 主线 package 为 0.0.81，README 标 Windows alpha；使用专用账户、受限 token、ACL/ACE、WFP 和 bundled `srt-win.exe`，首次安装有 UAC。README 还列出 Schannel 不兼容、系统服务代发网络及 token 变化等边界，不能只摘“Windows 已支持”。[README][S06]、[package][S105]

**已核实（官方）**：OpenHands 可每会话启容器，但若 bind mount 同一个 host workspace，文件仍共享。容器分开不能代替 workspace 分开。[运行文档][S16]

**新兴方向〔已核实（官方）〕**：除统一策略层外，另一个实用变化是凭据留在执行边界外。E2B Secrets 的 2026-10-07 发布文、10-22 更新说明，由沙箱外代理为指定 HTTPS 目的地注入请求头；把真实密钥直接放环境变量则仍可被沙箱内代码读取。[E2B][S12]

**现在做什么〔ChatGPT 推测／工程判断〕**：MXC 值得单独做原生候选验证，暂不直接选成默认后端。把 shell、Skills、stdio MCP、LSP、hooks、内置文件读写的入口列清，分别核对身份、文件、网络、环境和寿命；验证策略拒绝确实生效。优先由可信 Go 后台持网关／QQ 凭据，工具拿窄业务接口；本机 loopback 入口仍需鉴权。远端执行端、WSL/Docker 可作为真实任务需要时的选择，不因沙箱名相同就把 PowerShell 任务换成 Linux。本文不改变已有执行权限。

## 四、并行工作隔离、检查点与回退

### 4.1 工作隔离

**已核实（官方）**：Git worktree 分开 HEAD、index 和工作文件，共享部分 Git 管理状态。Claude 有会话／子代理 worktree 与选择性复制 ignored 文件；Cursor 提供 setup-worktree 和多候选任务，并明确不推荐把依赖 symlink 回主树。[Git][S13]、[Claude][S15]、[Cursor][S14]

**ChatGPT 推测／工程判断**：依赖下载 cache 可以共用，可写 node_modules、venv、临时目录、测试库、端口、浏览器资料和后台服务应有任务归属。源码分开不会让两个 `localhost:3000` 或两份仍指向生产库的 `.env` 自行隔离。合回需要共同基线、串行集成和组合验证；失败保留成果，清理先停归属进程，再回收目录。

**新兴方向〔已核实（官方）〕**：E2B 当前 SDK 的 fork 短暂停源实例、保存完整内存快照后创建多个实例；filesystem-only snapshot 则冷启动，没有原进程与连接。Daytona v0.165.0（2026-04-14）发布 CoW fork 和 snapshot，但该公告不足以证明完整内存恢复。[E2B SDK][S22]、[Daytona][S23]

**现在做什么〔工程判断〕**：沿本地调研优先普通 Git worktree／任务目录、显式资源登记、交回 commit/diff 与人工集成；暂不引入多文件系统 CoW 管理器或运行环境 fork。初始化昂贵且确有多候选实验后，再量其节省是否抵过快照和恢复成本。

### 4.2 检查点：各家的覆盖范围不同

| 实现〔均为已核实（官方）〕 | 保存与恢复 | 必须保留的限制 |
| --- | --- | --- |
| [Claude Code][S17] | 启动 turn 的用户 prompt 建 checkpoint；保留最近 100 个文件快照点；支持代码、对话或两者；默认约 30 天清理 | 只由 Bash 改过、未被编辑工具跟踪的文件不覆盖；被主会话编辑工具跟踪后，后续 Bash 修改可一起退。多数子代理其他文件不退；symlink/hardlink 跳过；mid-turn 消息无独立文件点 |
| [Cline 产品文档][S18] | 文档说每次工具后 shadow Git，文件、任务或两者可恢复；[多根页][S19]说 checkpoints 禁用 | 新 SDK 固定提交实际为 stash-compatible 对象、私有 refs 和独立 index；有 HEAD fallback。不能把文档的完整描述套在所有 SDK 路线，见 Q12 |
| [Cursor][S20] | 重要修改前保存相关文件快照；恢复文件，保留聊天；独立于正常 Git 历史 | 文档不能证明任意外部文件、副作用或数据库都被捕获 |
| [OpenCode TUI][S21] | `/undo` 回退最后用户消息、后续回复及文件修改，`/redo` 恢复 | 文档明确文件撤销依赖 Git 项目；不等于每会话独立 worktree |

**已核实（官方）**：Cline SDK `7a7878c` 的快照使用 `refs/cline/checkpoints/<session>/<runCount>`；失败可能记录 `head_fallback`，不同于正常 `head_clean`；恢复发现 HEAD 相对基线已变则拒绝文件恢复，仍可只恢复聊天。[捕获][S99]、[恢复][S100]。这支持本地读码结论。

**ChatGPT 推测／工程判断**：产品应分别说明文件、对话、执行状态、运行环境四类恢复。已发 QQ、远端 API 写入、已提交数据库事务、token 费用和审计事实不随本地文件回退消失。影子 Git 本身就是内容寻址的一种实现，不必把“影子 Git”和“内容寻址”当互斥选型。

**已核实（官方）**：活跃 SQLite 有在线 Backup API；WAL checkpoint 是日志归并，不是任意时间点的产品回退。WAL 不适合作跨主机网络文件系统共享库。[Backup][S92]、[WAL][S93]

**现在做什么〔工程判断〕**：复用本地既有字节快照规格：写前持久化、后态可信版本、恢复前预览与冲突校验、逆操作、partial/interrupted、真实账本不退款。该规格已定义 shell 有界扫描和覆盖排除项，比 Claude 文件工具跟踪更宽，也更贵；应按规格性能验收再判断取舍。Windows 单文件占用、CRLF、链接、多个文件部分成功及恢复后 LSP 失效都要进入验收；不以“有检查点”承诺所有副作用可撤销。

## 五、人机交互：插话、计划、审批和进度

### 5.1 插话、排队和取消

**已核实（官方）**：Claude 普通消息在正在运行的工具调用完成后进入同一 turn；命令和 `!` shell 通常等 turn 结束。Ctrl+Enter 立即发送从 v2.1.275 提供；v2.1.281 起可后台化的任务继续运行，其他工作才中断。[交互说明][S24]。Cursor 也明确区分排到当前任务之后、下一工具调用时 steer。[Agent overview][S20]

**已核实（官方）**：OpenAI Responses 的 GPT-6 WebSocket steering，`accepted` 只表示入队，不表示模型已消费；等待当前 output item 和已启动托管工具结束，有客户端工具结果／审批时保持 pending。断线后队列不随原 response 持久保存；token／工具限制按 continuation response 分别计算。[API][S26]

**已核实（官方／草案）**：ACP v2 Draft 区分消息插入、前台 running/requires_action/idle、后台 live work；插入也不承诺持久化或已进入模型。前台 idle 不意味着后台全停。[生命周期][S27]

**ChatGPT 推测／工程判断**：Sumika 保留现有队列，明确“排下一件事、修改当前任务、停止”的动作及接收／注入状态。接受用户纠正后不偷偷更换已启动工具参数，也不重跑已完成工具。UI 用“正在停止／已停止／转后台”，不要把取消父进程当成整树已退出。

**已核实（官方）**：Go CommandContext 默认 Kill 当前 Process，未保证后代全退出；Job Object 可管成组进程，但有 breakaway 和特殊创建路径条件。[Go][S122]、[Job Objects][S111]。Windows 的输入法组合输入与终端快捷键需要单独验收；这是工程建议，不是本轮实测。

### 5.2 计划和任务清单

**已核实（官方）**：Cline Plan/Act 分调查与执行，并保留对话；Cursor Plan Mode（2025-10-07）把计划做成可编辑产物；Claude Plan 的真实命令权限仍受权限模式和其他配置影响，不能只看模式名。[Cline][S29]、[Cursor 发布][S112]、[Claude][S28]

**ChatGPT 推测／工程判断**：计划、清单与真实运行对象分开存。计划写目标、范围、验收及待决问题；清单项关联产物和证据；后台状态决定工具是否在跑。普通陪聊／小查询不加规划流程；跨模块工作复用既有规格。实现了只读承诺就由执行层落实。计划同意不能替代权限判断，也不应让已授权工作再过重复确认。

**新兴方向〔依据上述官方实现的工程归纳〕**：计划逐渐成为可保存、可修改、跨会话续用的产物；不据此认定正式 spec 流程普遍更快。进度卡优先展示目标、运行／等待状态、当前活动、需要用户的决定；不把清单 4/5 换算成工程完成 80%。

### 5.3 审批

**已核实（官方）**：Claude 权限规则为 deny → ask → allow；v2.1.234 起运行中修改可从下一工具调用生效。OpenCode V1 的 always 为本会话，V2 为持久项目规则，且不能盖过配置 deny。[Claude][S30]、[V1][S31]、[V2][S32]

**已核实（官方）**：Codex auto-review 用独立 reviewer 审查边界请求，不能替代独立文件／网络限制。Claude auto mode 2026-03-24 发布、7-10 更新 GA；当前文档写 v2.1.283 起交互终端／VS Code 的内置起始模式为 auto，但设置、模型和管理策略仍影响实际会话。[Codex][S33]、[发布][S34]、[模式][S28]

**新兴方向〔已核实（官方）；效果未复现〕**：模型审查器减少人工审批，但有额外推理、延迟和误判。OpenCode V1 `--auto` 是放过原本 ask 的静态策略，不能与分类器审查等同。

**现在做什么〔工程判断〕**：先检查既有审批卡是否清楚显示动作、真实路径／目标、范围、寿命与规则。参数变更使旧批准失效；取消任务使旧审批失效；多端同时决定由后台只提交一次。可逆性只能是判断因素，文件快照不能抵消已发消息。模型审批器等真实误判样本和现有回放能评测时再考虑，不据行业默认值改变 Sumika 权限。

## 六、多端与富交互结果

**行业常见做法〔工程归纳；Q23—Q26〕**：手机作为现有任务的监督入口；会话在哪里、工具在哪里、状态存哪里、如何传输分别设计。

**已核实（官方）**：Claude Remote Control 的执行与文件留本机，仅出站 HTTPS，但 transcript 存 Anthropic 服务；电脑需在线。Cursor Remote Control 的 Agent loop 在云端、工具在电脑，不能把两个产品都描述为纯本地循环。[Claude][S35]、[Cursor][S36]

**已核实（官方）**：Alma relay 转发 HTTP/SSE/WebSocket；WebRTC/TURN 对应实时浏览器画面，不证明聊天走 P2P。开启 E2EE 的桌面从 0.4.329 起拒绝 relay 明文请求；自托管 relay 没官方 App 签名团队的 APNs 凭据不能给官方 iOS App 推送。[relay][S37]。HAPI SSE 契约有事件游标、补放和 gap 后拉快照，并要求正确处理重复投递和版本。[契约][S38]

**已核实（官方）**：MCP Apps 在 2026-01-26 成为官方扩展，工具可关联隔离交互 UI；界面不必每次由模型生成。A2UI 负责声明式 JSON 到可信组件；目前 React/Lit/Angular 稳定，Flutter/SwiftUI 为 Alpha，Compose 有版本限制。[MCP Apps][S39]、[A2UI renderer][S40]。旧 2025-11-25 MCP Elicitation 包含 form/URL；它是指定旧版事实，不能跳过 Q36 的新版协议迁移直接套用。[Elicitation][S117]

**新兴方向〔工程归纳〕**：从手机发起独立任务走向多端共同监督已有任务；从纯文字结果走向固定卡片、声明式表单、隔离工具 App。没有证据支持“WebRTC 自动总是直连”“原生 renderer 已全覆盖”“某手机框架普遍最省电”。

**现在做什么〔ChatGPT 推测／工程判断〕**：先统一任务、审批、结果的稳定 ID、版本、重连游标与补快照，再做手机入口。PWA 适合验证聊天／审批；原生或 RN 的理由应来自通知、语音、分享、平台体验等真实需求。既有 Go/mygo 不因 A2UI 有协议就已有 renderer；先把选择、问题、diff、任务和结果映射到少量稳定控件，QQ 做文字／链接回退。MCP HTML App 真有需求再配受控 WebView2 桥。按钮、刷新和重连都不能重做外部动作。

## 七、Agent 循环、上下文与缓存

### 7.1 压缩与信息保存

**已核实（官方）**：Anthropic 的 2025-09-29 上下文工程文章组合 compaction、结构化笔记、子代理和按需检索，并承认压缩可能丢关键细节。OpenAI compaction 返回不透明加密项；显式接口返回的整个 compacted window 应作为后续输入，不能只抽其中一个项。OpenCode V2 文档保留摘要加最近约 15,000 tokens，完整消息另存；后台压缩仍标 experimental。[Anthropic][S41]、[OpenAI][S46]、[OpenCode][S47]

**ChatGPT 推测／工程判断**：持久历史、任务状态、模型这次的上下文是三种数据。把长原始结果移出输入后保留稳定引用，不能让摘要变成唯一事实源。保留目标、最新纠正、禁止项、决定及原因、未完成项、产物版本和待消费消息；模型写“完成”须能关联到真实结果。

**新兴方向〔已核实（官方）；收益待本地量〕**：服务端压缩减少客户端摘要格式负担，但降低跨供应商可移植性；提前后台压缩可换延迟，但额外花 token，须绑定历史水位并接回后续新事件。

**现在做什么〔工程判断〕**：复用已有续跑对拍，把同一轨迹在同一边界分叉，比较原上下文、旧工具输出遮蔽、现有摘要与候选摘要。验收任务完成、约束保留、事实错误、原文回查、重复探索和整个任务费用；不只测压缩率或摘要文风。四批材料里未进入本次重点核对的论文效果数字不作为选型依据。

## 八、子代理、Skills、MCP 与 hook

**已核实（官方）**：OpenAI Agents SDK 区分 `Agent.as_tool()` 的主代理掌控与 handoff 的接管；也区分模型自主和代码编排。Claude SDK 子代理把大量探索留在独立上下文，主上下文接最终结果。[编排][S110]、[Claude loop][S52]

**ChatGPT 推测／工程判断**：陪伴型 Sumika 宜保持主角色负责交互，把查资料、定位、复核做有界子任务。任务契约包含目标、范围、证据、交付、权限、预算、停止条件。并行收益要同总预算比较；复核拿原始要求和产物，不能只看作者解释。并行写入接 worktree，计算资源接既有重活锁，不因此引入第二个调度器。

**已核实（官方）**：Skills 采用名称／描述→完整 SKILL.md→附属资源三层披露；`allowed-tools` 仍为实验字段，宿主支持不同。Anthropic Tool Search 的 `defer_loading` 延迟 schema，程序化工具调用让程序过滤和聚合中间结果。[Skills][S10]、[advanced tool use][S50]

**已核实（官方）**：MCP **2026-07-28** 更新页标 latest，相对 2025-11-25 移除协议会话和 initialize/initialized，改为每请求 `_meta` 携版本／能力；Tasks 移官方扩展；删除旧 SSE 恢复与重投递。断流按新 request ID 重发协议请求不等于允许重做业务副作用；应用仍需操作去重与结果核对。[changelog][S49]。不可信服务器的 annotations 不能当强制授权。[Tools][S97]

**已核实（官方）**：Claude hooks 包含工具前、工具后、失败、Stop、子代理与压缩阶段，并明确不同事件的决策能力。[hooks][S48]。Cline Plan guard 等本地读码材料也说明“工具前拒绝”与 OS 沙箱是不同防线。

**ChatGPT 推测／工程判断**：同步权限／预算守卫在副作用前完成；后置审计失败不抹掉已执行事实；Stop 质量检查须有预算和有限继续次数。hook 的事件 ID、调用 ID、参数版本、超时、能否改参数及失败策略需明确，模型 hook 用于语义质量，金额／路径／授权由确定性层判断。

**新兴方向及现在做什么〔工程判断〕**：工具检索和程序化调用已有产品实现，但先量 schema 占用、选错工具与延迟再增加动态检索；技能说明不能自授权限。MCP 新规范变动值得开兼容核对项，先列真实服务器支持矩阵再决定切换，不能以一页 latest 文档认定所有已装 server 已升级。服务商专属工具编排只在适配层接，不为它改写整个 Go 循环。

## 九、结果处理、可靠性、预算与持久执行

**已核实（官方）**：Anthropic 工具设计文建议分页、范围、过滤和可操作截断提示；当时写 Claude Code 默认结果 25,000 tokens，这只是 2025-09-11 文章快照，不是通用最佳阈值。OpenCode V2 的输入裁剪与完整历史存储分开。[工具设计][S51]、[compaction][S47]

**ChatGPT 推测／工程判断**：已有 rtk 应接在“原始结果→变换→模型可见内容”的同一路径。退出码、状态、长度、截断范围、结果引用和精确报错保真；模型／UI／磁盘预算分别控制。达到显示上限仍要排空管道；真达到磁盘上限则明确标缺失。Windows PowerShell 编码、ANSI 控制码、中段错误、超长单行和重启后回查都值得放进样本。

**已核实（官方）**：OpenAI Python SDK 默认对连接错误、408、409、429、5xx 有两次重试及退避；LiteLLM Router 提供限流、冷却、回退和跨部署路由。[SDK][S109]、[Router][ROUTER]

**ChatGPT 推测／工程判断**：统一总期限、取消和尝试账本，避免 SDK×网关×上层嵌套重试放大。认证／参数错误、配额耗尽、上下文超限、暂时故障、外部结果未知分别处理；跨模型路由在完整可恢复边界重建输入，不能把半截工具参数接着执行。缓存、图片、工具、结构化输出、usage 完整性和取消恢复分别声明能力。

**已核实（官方）**：Claude SDK `max_budget_usd` 覆盖子代理，但成本在响应后检查，最后一个响应及在途子代理可越过阈值；相关 enforcement 要 v2.1.217+。Pydantic AI 费用／token 也有响应后检查，缺 usage 时已知数是下界。[Claude][S52]、[Pydantic][S53]

**ChatGPT 推测／工程判断**：父任务派发前原子预留，返回后结算。可再分配额为总额减已结算和所有在途预留；摘要、复核、重试、子代理均进入同一账本。未知费用不记零；预算停止派新任务与最终实际账单是不同承诺。临近上限预留收尾预算，不因切入口／重启而重置原任务花费。

**已核实（官方）**：LangGraph 节点重试为 at-least-once，检查点不把外部副作用变成 exactly-once；文档要求副作用前持久化稳定幂等键、缺回执视 unknown 并核对。Temporal 同样要求 Activity 幂等。[LangGraph][S54]、[Temporal][S55]

**新兴方向及现在做什么〔工程判断〕**：持久执行的关键不是换一套框架，而是保留任务 ID、逻辑操作 ID、尝试 ID、意图、回执、预算、授权版本和结果位置。QQ API 是否真支持幂等键／可靠查询，本次未审，不得仅靠本地 ID 承诺一次发送。先在现有 Go/SQLite 任务与追踪中验证“动作成功、结果落盘前崩溃”；确有跨机器 worker、复杂等待和运维需求再考虑完整 Temporal。网络输出未知不能自动重跑整轮。

**ChatGPT 推测／工程判断**：现有追踪优先回答“模型真正收到什么、实际发生什么、第一处分歧在哪”。保存原始结果引用、rtk／压缩版本、截断范围、最终模型可见载荷摘要／受控原文、请求与调用 ID、审批和回执。完整输入含隐私，按既有权限、脱敏、保留期保存；只记录 hash 不能重新构造原文，须写明回放可达到的程度。

回放至少分三种：查看旧轨迹；固定模型／工具响应测内核；固定初始环境真模型重跑测能力。OpenAI ScriptedModel 官方测试页也明确，内存脚本只能证明 SDK 拥有的编排，外部协议／模型／沙箱需真实适配层验证。[测试页][S95]

**现在做什么〔工程判断〕**：复用已有追踪库和对拍，不先部署另一套观测平台。费用保留原始 usage、标准化桶、价格版本、实际模型、actual/estimated/unknown；每次真实尝试只结算一次，父子汇总不重复。trace 导出不是唯一预算事实源。审批等待、队列等待、实际执行分别计时；Windows 睡眠、断网、退出导出有独立事件。
