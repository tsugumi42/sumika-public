## 三、分期对照

### 001　拟物按钮 `[原文]`

- **作者的做法**：五个层级 primary / secondary / tertiary / ghost / text。每个有底色的按钮由五层材质叠成：渐变面（上比下亮 6～8%）、1px 描边、顶部高光（inset）、底部暗线（inset）、两层外阴影（接触影 `0 1px 2px` + 抬升影 `0 4px 10px -3px`）。悬停：面亮一档，抬升影变 `0 8px 16px -5px`。按下：下移 1px、渐变上下翻转、外阴影收到 `0 1px 1px`、顶部高光变内阴影；静止和按下的 inset 层数保持一样，阴影才会平滑过渡不跳。时长：transform 120ms、阴影 140ms、颜色 160ms。所有长度写成 `u = 字号 / 14` 的倍数（md：14px 字、高 40、内距 18、圆角 10；lg：16px 字，高 45.7、圆角 11.4）。色值：primary 深石板 `#404859 → #273042`，其余是浅灰；光从正上方，只用中性灰，不加光泽、发光和大范围模糊。
- **我们现在**：悬停叠 `hover`、按下叠 `press` 底色，按钮再缩 .97（图标圆钮 .96），ADR-349 试用中（总则第五节 L3 状态表）；按钮高 32、圆角 12；“阴影随层走，组件不自己写阴影值”，分界“优先留白和底色差，其次细边，最后才是阴影”，浮起风格是 ADR-324（总则第四节）；总则第一节写“纯灰中性色（我们带一点冷暖）”是外来组件要改掉的样子。`[读文档]`
- **建议怎么落**：不引入。网页里的按钮走总则的状态表；长度随字号缩放我们已有（`base.css` 里写成 `calc(var(--x) * var(--px))`，`[读码]`）。唯一可记的一条：如果以后哪个控件真的画了 inset 阴影，静止态和按下态的层数要对齐，否则阴影过渡会跳。落到哪一步：无。
- **和我们规则冲突的**：提示词里每个数都是写死的色值和像素（设计令牌不写死值）；五层光影是“阴影堆出质感”，和 ADR-324；按下是下移 1px，ADR-349 是缩放，两种手感不并存。
- **引子**：写了五层级、`#404859→#273042`、五层材质、`translateY(1px)`、`u = 字号 / 14`，和原文一致；把阴影写成“1px 接触影 + 4px 弥散升起影”，省掉了模糊和扩展值，算简化，不算错。

### 002　级联菜单的安全区域与延时 `[原文]`

- **作者的做法**（页面要点 + 提示词）：
  - **打开延时 220ms**：悬停某一行后才生效（文件夹行开子菜单，普通行关掉更深的子菜单），离开前取消，触屏立即。
  - **安全三角**：顶点是指针“上一个”位置（记最近两次 pointermove，取较旧的一个当顶点，三角才不会缩成一点），另外两点是子菜单靠近一侧的上下两角；而且指针要在父菜单朝子菜单那一侧的最后 `min(90px, max(56px, 父宽的 43%))` 以内。在这个区里，经过的行不高亮、不开自己的子菜单。**页面要点没提这条“最后一段”的限制，提示词里有。**
  - **安全窗口**：区内悬停的行不马上切换，每 80ms 复查一次，指针离开区、或者从开始悬停算起满 **1200ms** 才切换（指针停在区里也终会切）。
  - **关闭延时 360ms**：指针离开锚点、所有层和安全区之后整个菜单关闭，回来则取消；点外面立即关。
  - 拖拽物经过文件夹行，420ms 才开；指针进了子菜单，保护结束。
  - 行的高亮必须由组件状态（hovered / active / skipped）驱动，不用 CSS `:hover`，否则安全区里经过的行照样亮。
  - 几何：子菜单向右，和父菜单重叠 8px，第一行对齐父行；放不下翻向左，安全区改用子菜单的右边。层宽 210～260px，最大高 `min(420px, 100vh − 24px)` 自带滚动，内距 6、圆角 12、1px 描边、`backdrop-filter: blur(18px) saturate(135%)`；行高 32、圆角 8、行距 4。
  - 动效：子菜单透明度 170ms、transform 360ms，曲线 `cubic-bezier(0.2, 1.45, 0.35, 1)`（有过冲），起点 `translateX(-8px) scale(0.88, 0.98)`；根层起点 `translateY(-6px) scale(0.96, 0.86)`；文件夹图标开合 460ms；亮暗主题切换颜色交叉渐变约 500ms。
  - 键盘：方向键走行，右键 / 回车开文件夹，左键退一层，Esc 全关并把焦点还给锚点；`menu` / `menuitem` 角色，`aria-expanded`。
  - 工程做法：时间值集中成命名常量；安全区数学放纯函数并写单元测试（三条边叉积的符号判点在三角内）；可选的调试覆盖层默认关。
- **我们现在**：mygo v0.8.3 的 `ui/popovermenu.go:560-580` 指针一移到另一项就收起子菜单，没有延时、没有三角判断；Sumika 只有悄悄话右键“引用▸”一个子菜单；菜单有两套实现（mygo 的 `ui.Menu` 和 winshell 手画的 `menuItems`，审查第四节）。`[读文档]` 弹层进出场 180 / 130、缩放 .98、Y 6（过渡动画 3.1、A13）；菜单项高亮由指针和键盘直接更新、不做动画（E3、铁律 1）；浮层现在是实色（总则第二节第 4 层、第三节第 5 条）。
- **建议怎么落**：落网页规格第七节第 5 步“菜单一套实现”。①把安全区做成纯函数加单测，三个延时进令牌（命名建议 `motion.submenu-open 220`、`motion.submenu-switch 1200`、`motion.submenu-close 360`，另有 80ms 复查间隔和 420ms 拖拽打开）。②选菜单库时拿上面这几条当验收项；我印象里 Radix 的子菜单带类似的“指针宽限区”，没读源码，**拿不准**，若库自带就只补延时。③动效和几何全换成我们的：进出场 `menu-in / menu-out` 180 / 130、缩放 .98、Y 6，行高圆角按控件档和同心公式，不用它的 1.45 过冲曲线和 .86 的起始缩放（过渡动画 3.1：高度不过冲，颜色不回弹）。④键盘部分和我们总则“Esc 退层、焦点回触发钮”一致，照用。
- **和我们规则冲突的**：`blur(18px)` 的菜单面（浮层现在实色，要不要扩到浮层玻璃是总则末尾要主人拍板的一条；网页规格第四节第 2 条玻璃少而小）；过冲曲线；主题交叉渐变 500ms 对我们过渡动画 D5 的 320ms；提示词给了两套写死的主题色值，我们用令牌。
- **引子**：写了“以倒数第二个采样点为顶点”“悬停 220ms 打开、安全区内停留超 1200ms 切换、移出 360ms 后关闭”，和原文一致；图里没拍到的部分（80ms 复查、深度限制、拖拽 420ms）无法核对。

### 003　ASCII 与像素抖色 `[原文]`

- **作者的做法**：给指定图片 / 视频叠 ASCII 字符画或 4×4 Bayer 有序抖色，实时生成，附控制面板（遮罩、配色、采样强度、大小、间距）。推荐值：ASCII 遮罩 90 / 取样暗部 / 强度 100 / 大小 37 / 间距 0；Dither 遮罩 88 / 强度 100 / 大小 15 / 间距 0。字符表从空到满 17 级；取样 480px 长边的小画布、约 12000 个样点取 8% 和 92% 分位；画布像素比封顶 1.6、约 2048×2048；视频逐帧重绘。五种调色板各四个色标。
- **我们现在**：没有对应场景。
- **建议怎么落**：不做。落到哪一步：无。

### 007　中英文排版的 CSS 设置 `[原文]`

- **作者的做法**（十条开关，都是渐进增强，不加 polyfill；中文规则用 `:lang(zh)` 限定）：
  1. 标题均衡换行 `text-wrap: balance`（只给短文本，Chrome 最多均衡 6 行）。

  - 4、5 不换行和省略加悬停全文：照用（`.quote-text` 已有省略，补悬停全文）。

### 009　浮层组件的选择规则 `[原文]`

- **作者的做法**：六种东西各管一类：Tooltip（给指针所指内容补文字，纯文字，常用于被截断的长文本、纯图标按钮、禁用控件；要放操作就改成点击打开的 Popover）；跟随指针的提示（在一块区域里持续给信息，常用于图表）；Popconfirm（对单个不可逆操作就地二次确认，从点的按钮长出来）；Dialog（必须停下来确认或完成的：影响大、影响别人、批量、需要先做另一个决定，或不需要参照页面的短表单）；Drawer（长表单、需要对照页面内容、想用横向空间，**绝不用来确认**）；整页（主任务或要有可分享的链接）。几个问题定一类：能撤销吗 → 直接做加撤销入口（toast 或回收站）；不能撤销：是自己的单个项且有按钮可锚 → Popconfirm，影响大 / 别人 / 批量 / 还要决定 → Dialog；表单短且不需要参照 → Dialog，长或要对照 → Drawer，主任务 → 页面；触屏上悬停出的东西必须能点按到。行为要求：Tooltip 首个约 500ms 后出现、移到邻居时立刻出，悬停和键盘焦点都触发，不出视口、一次一个、`aria-describedby`；Popconfirm 从按钮长出、Esc 或点外面关闭、焦点回按钮、确认钮写动作名；Dialog 用 `showModal()`、焦点困在里面、写清影响了谁和什么不可撤销、按钮写具体动作（例如移除成员）而不是确定；Drawer 从附着边进入、页面仍可见、改动实时显示、有关闭钮和 Esc、关闭前有未保存改动先问。流程要求：先给表格等点头再改，缺组件（撤销 toast、popover）停下来问。
- **我们现在**：总则第六节第 7 条写明“没有什么场景用哪种结构、哪种浮层、哪种设置控件的决策表”；界面模式规范 §5 第 1 条“撤销优先于确认框”标【新提议】、第 4 条审批类走审批卡不另开确认框（ADR-281）、第 11 条“确认框和撤销的分界”待主人同意（会改原型里的“重置”和“重启接收”）；设计语言“错了撤销、不弹确认框”；对话框 220 / 160（过渡动画 A16）；悬停提示 150 / 100，暖机沿用 mygo 的 400ms（A17、第十节）；对话框宽 420、取消叫“算了”（总则 L2、设计语言）。我们**没有**就地确认（popconfirm）和撤销提示条的网页组件；界面模式规范说 mygo 的 Toast 有动作按钮（【既有】）。`[读文档]` 审批卡“拒绝并说明原因…”没用危险样式（审查第四节）。
- **建议怎么落**：把“三个问题”改写成总则里新增的“浮层选型表”，填第六节第 7 条的缺口，和第 5 步“菜单规范”一起写；没有的组件（就地确认、撤销条）按它自己的规矩“停下来问主人”，不擅自加。提示的暖机时间取我们现有的 400ms，原文的 500ms 只差 100ms，不改。
- **和我们规则冲突的**：没有。“先出表再改代码”是给 Agent 的流程要求，不是我们的产品规则。

### 010　液态玻璃 `[原文]`

- **作者的做法**：六层叠加：投影、模糊 + 提亮、边缘折射（SVG 位移贴图，越靠边压得越多，红光比蓝光多偏折一点）、着色（透明度按背景复杂度自动调）、边缘光（左上和右下各一道再向内缩一道）、文字着色（浅色玻璃用正片叠底，深色用叠加提亮）。推荐参数：浅色着色白 6%～22%，blur 2px、saturate 180%、brightness 1.06；深色着色 `rgb(20 20 24)` 16%～38%，blur 2px、saturate 160%、brightness 0.8；折射边宽 `min(44px, 短边 / 3.5)`、不小于 4px，偏移为 1.1 倍边宽，色散红 +15% 蓝 −15%。适应背景：在面下 5×3 网格采样，去掉最暗和最亮各两点取平均，亮度低于 0.5 就换浅色字（现用字色距这条线 ±0.05 内保持不变，防闪），深色模式永远浅字；着色密度 = 0.55 × 背景与字色亮度的接近度 + 0.7 × 纹理 + 0.3 × 色度；保留饱和度 = 1 − 0.75 × 色度（不低于 0.45）；背景、主题、面位置变了才重新采样；背景读不到（视频、跨域）就按主题定字色并用最密的着色。可调：浅、深各一个着色浓度（0～1.5），小于 1 时亮度提升同步变薄。无障碍：对比度在最忙最暗的背景上检查，不够就加密度而不是加字色不透明度；尊重 `prefers-reduced-transparency` 和强制颜色，降级成同色实底。工程：`backdrop-filter: url()` 只有 Chromium 画，先 `CSS.supports` 检测；小于 32px 的面、带 `will-change` 的面不做折射；位移贴图按半径和边宽缓存。**着色浓度按密度分档，附注写了 step 4，是 4% 一档还是 4 个档，我拿不准。**
- **我们现在**：玻璃只给第 2 层（标题栏浮条、窗口三键、输入框），内容层不用，不叠玻璃，玻璃本身不上色（只有主要动作上强调色），“降低透明度”或设置选实色时全部变实色（总则第三节第 1、2、3、6、8 条）；mygo 现在的液态玻璃是叠内容色 20% / 35%、通透度 0.6（同节第 5 条）；玻璃面板进出场每帧要不要重算模糊没验证（过渡动画第八节第 8 问）；网页规格第四节第 2 条：玻璃少而小、不叠两层、滚动区本身不用。`[读文档]`
- **建议怎么落**：落网页规格第七节第 3 步（输入框胶囊、标题浮条）。①基础只取三件套：背景模糊 + 饱和 + 亮度，010 的推荐数当起点，真窗口亮暗各看一眼再调；②自适应字色：只在“壁纸变、主题变、面的位置变”时采样一次，**不在滚动时采样**（010 自己也是变了才采样，但我们的玻璃下面是不断滚动的消息列，每帧采样和第四节冲突）；③降级照总则第八条，只补网页写法（`prefers-reduced-transparency` 兜底实色）；④折射边和色散不做，理由：贵、只有 Chromium、而且在会滚动的聊天底下每帧重算背景（网页规格第四节第 2 条）；⑤文字着色用 `mix-blend-mode` 会让实际对比度随背景变，总则要求的“12 种模式对比 ≥ 4.5”的检查量不到它，**不用**，字色走令牌；⑥“着色浓度”两个设置要不要加，不急，我们外观设置里已有玻璃开关。`[要实测]` `backdrop-filter` 在 WebView2 里叠三件套的帧耗时；`prefers-reduced-transparency` 在 WebView2 的行为；`@property` 和 `linear()` 在壳里的行为。
- **和我们规则冲突的**：`mix-blend-mode` 字色（对比度检查）；每帧采样背景（第四节）；把玻璃铺到卡片、菜单、浮层（总则第三节第 2、5 条：浮层现在实色，是否扩到浮层要主人拍板）；原文说带 `will-change` 或自己合成层的面（它举的例子是菜单、动画面板）不做折射；我们的浮条和输入框是否会被提升成独立层我没查，如果是，折射在这里本来就不适用（`[推断]`）。

### 011　按场景选择缓动曲线 `[原文]`

- **作者的做法**：七种曲线加角色：Linear 只给进度条、转圈这类“在运行”的东西；Ease-out `(0, 0, .58, 1)` 给进场（toast、菜单、弹窗、抽屉）；Strong ease-out `(.22, 1, .36, 1)` 给点击后马上到位的小东西（图标、文字、选中胶囊）；Ease-in `(.42, 0, 1, 1)` 只给退场；Ease-in-out `(.42, 0, .58, 1)` 给原地换位置的东西（标签下滑动的指示条、轮播翻页、锚点平滑滚动），不用于进场；Overshoot `(.34, 1.56, .64, 1)` 过冲约 10%，给小而活泼的确认（勾选、点赞、角标弹出、开关拇指），不用于大面板，不用于一天重复很多次的动作；Spring 用 `linear()` 采样 `(0, .32, .78, 1.04, 1.09, 1.06, 1.02, 1, .99, .99, 1)`，给松手后的归位，优先用动画库自己的弹簧带上松手速度。时长：小界面进 150～250ms、出 120～200ms；中等（对话框、带内容的弹出）250～350ms；大或全屏 350～500ms；弹簧和过冲取约 1.5 倍；退场比进场短。角色规则：进场位移 8～24px、从 96% 长出、透明度比位移早一点；退场是同一路径反着走；内部小元素可以晚 100～200ms 用 Strong ease-out 跟进；手势中 1:1 跟手、松手用弹簧；悬停和按下 100～150ms ease-out，永远不动画布局；只动 transform 和 opacity（filter 少用）；减少动态：保留透明度变化，去位移缩放，弹簧和过冲换成 150ms 淡入；新动作从当前位置打断旧动画。
- **我们现在**：令牌里只有 `ease.standard (.4, 0, .2, 1)` 和 `ease.route (.22, 1, .36, 1)`，网页端还没有 `ease.out`、`ease.in` 的具体值（`native/internal/design/tokens/primitive.tokens.json` 的 `ease-base`）。`[读码]` 过渡动画 3.1 表写“进 `EaseOut`、出 `EaseIn`”，并写明 `EaseIn` 取 `(.42,0,1,1)`，“第一批真机看过再微调”（该表下方）；四家对照 6.1 把退场曲线 `ease.exit` 列为待定三选一；过渡动画第十节写“现在退场沿用进场的曲线 = 方案 C，改只需动 `chatui.PopTransition` 一处”，也就是**规格表里写的是 A，代码里实际是 C**。`[读文档]`
- **和我们对得上的**：Strong ease-out 与我们的 `ease.route` 数值完全一样；原文的 Ease-in 就是我们规格里写的 `EaseIn`，也就是方案 A；时长区间覆盖我们所有档（弹层 180 / 130、对话框 220 / 160、面板 230 / 200、展开 230 / 200，对话框略短于它写的“中等 250～350ms”，不改）；弹层位移和缩放比它克制（它写从 96% 长出，我们 .98 / .985）；反馈 140、按下 120 与它的“悬停按下 100～150ms”一致；手势跟手、松手用弹簧带速度即我们的铁律 1；“只动 transform 和 opacity”即网页规格第四节第 1 条；减少动态留淡入去位移即 ADR-124（它把淡入定为 150ms，我们 ADR-124 是“时长照常”，四家对照 6.3 第 7 条已列）。
- **冲突**：①它把 Overshoot 给勾选、角标、开关拇指，我们 B5 勾选框定了 140ms 淡变、进页面已勾的静止（过渡动画 B5），四家对照 6.3 第 2、3 条要求不加更弹的曲线，不用；②“内部元素晚 100～200ms 跟进”是一种面板内部的错开，不等于列表错开，但字面上和“错开不做”挨着（四家对照 6.3 第 4 条），不借；③它写的 Ease-in-out `(.42, 0, .58, 1)` 和我们的 `ease.standard` 不同，我们原地移动用弹簧，不新开令牌。
- **建议怎么落**：网页令牌补 `ease.out`、`ease.in` 两条（值取原文，`ease.in` 与过渡动画 3.1 注里写的相同）；弹簧在 CSS 里用 `linear()` 采样表示的话 `[要实测]` WebView2 支持和性能（四家对照提到 Arc 用 37 点采样，`foundation.css:88-90`）。退场曲线见第五节第 1 条。落到哪一步：令牌在第 3 步前补齐，每步新写的进出场按它。
- **引用一句原文（本笔记唯一一句）**：原文给 Ease-in 的理由是“慢起、越来越快，干脆地离开”。

### 012　消息气泡的材质与动效 `[原文]`

- **作者的做法**（只摘和我们有关的，材质的 CSS 不抄）：
  - **气泡盒**（六种材质共用）：字 28px / 行高 38、内距 17×26、2px 描边、半径 38（单行是胶囊，换行是圆角矩形），**只用圆弧，不用 superellipse**；我方在右、对方（AI）在左、离两边 48px；长消息在固定宽度 680px 里排版，一开始就按这个宽度排。同一个人连发形成一组：组内间距 4px，组间 16px；每个气泡标记 single / first / middle / last，加入或离开一组时圆角用 **200ms** 过渡：Aqua、拟物、Cirrus 在两个气泡相贴处把发送者一侧的角缩到 10px；纯色和渐变每个气泡保持圆，只有一组最后一条有“尾巴”（两个伪元素：一个突出 12px 的色块，一个用页面背景色挖出的弧），成为组尾时 160ms 淡入。

  - **删除**：长按先按到 .94～.97 再抬到 1.02～1.04，其他气泡暗到 35～50%；菜单从气泡下方按材质方式出现；删除时气泡按材质方式消失（260～420ms）并**立刻移出布局**；上方的消息向缺口补位：离缺口最近的约 60ms 后先动，每往上一条晚 50～80ms；每条落到下面一条上时，如果还在往下运动，就翻转速度、保留 20～45%，让它向上弹回一点，不陷进下面那条；缺口两边是同一个人时合成一组。
  - **保持**：只动 transform、opacity、filter（玻璃用 backdrop-filter）；新动作从当前位置打断；减少动态时保留淡入、去位移缩放和模糊，点阵停成一帧，线程立即就位；用户没上滚时线程钉在底部。
- **我们现在**：气泡是第 1 层内容层，实色（总则第二节）；圆角 `--chat-r1`，合组相贴角固定 6（ADR-285 第 3 条），合组条件同一发送人且间隔小于 900 秒（规格-界面令牌第 103、104 行）；`base.css` 里最大宽度 75%、`overflow-wrap: anywhere`、合组靠 `join-prev` / `join-next` 改角，没有进场动画和过渡。`[读码]` 规格里没有“尾巴”一条（我 grep 了“尾巴 / tail”，没找到，`[读文档]`）。新消息进场 Y 8 + 140ms 淡入（别人 `Smooth`、自己 `Bouncy`）是 mygo 的 C1；草稿原地换成正式消息 C2；“正在想”并进同一个气泡、点后面追加文字、宽度过渡（过渡动画第六节）；不开平滑跟随、每帧直接贴底（C10、C11，主人 10-24）；铁律 3（不引起列表跳动）、4（虚拟列表里动高度要受条件限制）、5（行级动画走状态驱动）。网页规格第四节第 1 条（只动 transform / opacity）、第 4 条（流式按帧合并，只重排最后一段）、P6（流式长回复）。

### 014　卡片删除的四种消失效果 `[原文]`

- **作者的做法**：Burn（2s）、Plume（1.4s）、Blocks（1.5s）、Peel（1.2s）四种，由 WebGL 着色器和网格画在列表上方一个不收输入的画布上；删除时先读元素矩形、拍下它的图像，再隐藏真实元素（虚拟列表下一次更新元素就没了，所以必须先做）；周围的项也做反应（热浪扭曲、冲击回弹、被拉向贴纸）；剩余项用弹簧补位，`progress = 1 − exp(−7t)·cos(6t)`、520ms，只用 transform，而且在效果还没结束时就开始补位（Burn 900ms、Plume 720ms、Blocks 240ms、Peel 640ms）；同时最多 3 个，超过用淡出；减少动态、渲染器不可用、超过 3 个时：220ms 淡出加 4% 缩小，然后补位；撤销时立刻停掉那个效果；焦点移到下一项，读屏要念“已删除”；作者要求先读项目、一个一个问清、等点头再动手。
