# 盘点：该做成钩子的设计（2026-11-04）

结论：Sumika 需要统一的是挂点、插件身份、撤销和执行语义；现有 turn.Registry、渠道 Chain、Observer 已经有可复用的骨架，不宜另造万能事件总线。
该迁出的首批逻辑：三处发送守卫、入库回调套层、本地链接专用回调、工具重复提醒、计划/报时上下文贡献、出站统计与提醒。
不迁出的底线：身份和听众构造、可见性过滤、policy/approval、平台发送硬门、预算、事务去重、交付状态机；这些可以发通知，但不能靠可卸载订阅者保证正确。
顺序建议：①出口发送前守卫；②入库观察与本地消息接入；③工具结果提醒；④上下文贡献；⑤交付事件上的统计与提醒。先等 K1～K5 整合，避免重做身份、排空、工具结果和完成核验。
风险最大的两处：当前 guard-full 会钳制所有 QQ 来源，不能把“链接展开不查记忆守卫”误当成“可绕发送硬门”；OnSettled 不是送达，更不能成为停止后的自动续跑入口。
本文是只读盘点与建议，不是新 ADR、实施规格或启用许可；未运行产品、模型、构建、测试或性能量测。

## 四、统一挂点建议（我定的工程草案）

### 4.1 三种执行语义，使用同一插件身份和注册归属

1. **贡献/改写**：顺序运行，生成候选副本；只有宿主接纳后提交 OnAccepted。消息变换只能作用于被授权的内容字段，不修改原始入站事件。最终内容确定以后才做所有安全检查。
2. **限制**：只返回无意见或拒绝/更严要求，不提供“覆盖别人批准”的 allow。安全检查错、超时、异常一律拒绝当前动作。作用于当前生产者适用范围；一个拒绝不可被后面的钩子改成放行。
3. **观察**：只读已经确定的事实，返回值不影响事实；订阅者自己排受管工作。普通统计/提醒失败记日志，不重发、不改成功/失败。正确性必需的结算仍是宿主同步步骤，不伪装成可丢 observer。

**Message.Intercept 的 Took/Passed 是另一种已经存在的竞争语义**：首个接管者停止后续接话者，失败可以继续交内核。它不等价于安全限制的拒绝；统一注册管理，不强行把两种 Verdict 合成一个 bool。

每次注册带可信 `PluginID + RegistrationID/generation + hook kind + scope/source selector`。主线程发布有序注册快照；默认 append，同点确需优先级时沿 Chain 的“整数小先、同级注册序”，不再支持任意 before/after 依赖图。宿主固定的阶段顺序不能由插件调换；插件不能把自己优先级设在账号/权限/事务校验之前。

接口继续用 Go 强类型 Registry 方法和撤销函数；第四节名字是统一目录名，不要求变成字符串 API。`OnTool` 继续贡献受宿主验证的工具声明。共享的是注册身份、撤销和诊断，不要求 channel import turn 或 memory import channel；各层定义自己的小接口，由 app 组合。避免为“统一”在基础 `kernel` 包里放具体插件/渠道执行逻辑。

### 4.3 发消息的固定阶段与可信来源

建议固定为：可信生产者入口绑定 → 平台账号/动作/会话硬校验 → 获准的内容变换 → 最终长度/动作校验 → 适用的 Send.Check → 事务落计划与正文 → 回合 Commit（适用时）→ 排队 → 每次真实发送前复查硬门 → 发送/回声统一结算 → 投递通知。

- ADR-257 要的来源是**能力绑定**：宿主给角色回复生产者、repeater、link-reader 各一个绑定生产者身份的出口端口；插件参数里不给可选的 SourceKind/PluginID/Origin 来冒充。普通字符串 `automation:xxx` 校验不足，见 C19。绑定来源也不代表获得某个群/账号的发送授权。
- 检查适用面按可信生产者与内容来源，而非 Quote/Forward 形状。记忆守卫默认只管她用模型生成的回复（ADR-257）；链接展开（ADR-251）按自己名单和统一平台硬门。复读按 ADR-257 的默认适用面处理，不暗中留下原 CheckRepeat 调用。
- 守卫在“最终可见文字”上检查整计划/同回合累计上下文，不能变成逐段不关联的检查；改写必须先结束，检查后禁止再改字。重试发送复用已经审过的冻结正文，硬门每次复核。若等待期间授权或安全策略版本变化，不沿用旧审核结果，拒绝/重新审核的采用边界由宿主控制。
- 插件停用不是默认授权放宽：不再接受新工作，撤销旧代次能力。对已接纳且声明需要某检查的在途计划，检查摘除应使该计划失效，不能退成“现在没有 handler，所以自动通过”。下一份明确由宿主发布的能力快照才定义后续功能是否仍可用；平台硬门从来不受插件开关影响。
- 接法迁移不顺带改守卫算法。`memory/outbound.go` 的嵌入失败字面退路、确认失败按相似度拦截是已有 ADR-186 路线；统一 runner 自己调用失败则拒计划，不能把这两层失败混成一个默认值。
- 本地私聊的已流式正文无法通过渠道出口事后拦回。保留现行本地私聊记忆守卫豁免，不声称 Send.Check 保护了已显示文字；若以后要审核本地显示，必须另定缓冲/显示契约。本地群聊、QQ 私聊、QQ 群不能借这个豁免。

### 4.4 和现有插件、链、观察者及 ADR-238 的统一

| 现有机制 | 迁移后归属 | 要删除的重复接法 / 要保留的边界 |
|---|---|---|
| `turn.Plugin/Registry` | 同一插件注册上下文，继续提供 typed turn 挂点 | 不复制第二张全局 plugin map；同名重新启用是新 RegistrationID，旧回合不能绑定新工具 |
| `channel.Chain` | 同一管理器登记的 Interceptor 列表快照 | 保留 Took/Passed、Priority、场合、触发器；不用通用安全 hook 的 fail-closed 策略覆盖它 |
| `channel.Observer`、`OnLocalStored`、withMedia/Forwards/Backfill | typed Stored/Seen/Observe 发布，各自资料权限和投递保证独立 | 删除消费者专用 app 套层和本地 links 特判；不能把三种不同范围压成一个“所有消息广播” |
| `memplugin` | 一个 memory 插件 owner，功能子项包含 recall/tools/summary/send-check | 可管理功能状态和依赖；不能把关“记忆自动整理”误当摘掉发送审查；没有满足必需检查的来源保持拒绝 |
| `linkplugin.New/Setup/Close` | Start/Stop 同归一代插件寿命，外部服务能力受管 | 当前 Setup 无 cleanup、worker 自 New 启动需迁全；纯 StopPlugin 不够。新一代不接收上一代下载/OnAccepted 结果 |
| 出口/审批/存储硬服务 | 宿主必需服务，插件页可显示依赖和故障，不能当普通可摘安全钩子 | OnPart/Persist/Commit 的正确性路径不改成 best-effort；平台锁、暂停、健康保留 |
| 以后 WASM | 以同一挂点目录做受限适配，版本化 DTO + 能力端口 | ADR-238 已定 wazero 方向，不在本次发明 ABI/装载器。WASM 不拿 Go 指针、DB、Live、adapter、任意文件/网络；只给声明且主人批准的资料/动作。能力缺失必须拒绝，不退全权 |

内置 Go 插件本身仍是受信任同进程代码，注册契约不是内存沙箱。将来 WASM 的隔离必须由 host import 能力实现；仅在 manifest 写“只读”或把回调命名为 Observer 都不构成隔离。

## 七、按收益排序的改造建议

大小是静态粗估，非工时承诺/量测结果：S=约 2～4 个生产文件、一个主要入口；M=约 5～10 个文件、跨层接线；L=多类生产者和持久/生命周期契约迁移。文件数仅表达规模区间，不能当实施后的实际改动统计。都包含受影响测试/文档同步；不包含真实外发、付费模型或 WASM 实现。

| 顺序 | 改什么 / 依据 | 收益 | 粗估 / 前置 / 必须证明 |
|---|---|---|---|
| 1 | **发送守卫归唯一 Send.Check**：C15～17、M01/M06、A03；ADR-257 已定 | 新增发送生产者不再到三处补守卫；按来源而非 payload 形状 | **L**：三条旧调用、可信出口绑定、guard-full 依赖和启停一起迁；等 K1～K5。临时库证明角色回复被拦、链接展开不误套记忆守卫、任一 veto/错误阻断、平台硬门仍管所有来源、累计和转发节点不漏 |
| 2 | **入库观察归同一注册与寿命，接上本地入口**：T04、C03～07、L01、A06 | 去掉 withX 套层与本地 links 特判；插件页能停全一个功能 | **M～L**：Stored/Seen/Observe 分层，媒资/转发/链接/补录 bookkeeping 四类消费者；先复用 K1。证明各标签覆盖、双号只工作一次、队列满不堵入库、停插件后零新网络/写库，本地群入口明确验证 |
