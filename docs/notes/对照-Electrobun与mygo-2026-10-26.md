# 对照：网页 + Electrobun 壳 vs mygo 原生界面（2026-10-26 实测）

> 照 规格-界面对比（私有存档） 量的。甲 = 现在的网页界面（`web/dist`）装进 Electrobun 2.0.4 壳（系统 WebView2）；乙 = `native/` 的 mygo + CrychicUI 原型（mygo 0.6.4、CrychicUI 10-25 的 `926ffc3`）。两边都只读连同一个 7720 后台、同一个真实 QQ 群（约 1 万条）、同一台机器、窗口 1640×900，交替各跑 3 遍。原始数据在主工作区 `data/dev/shell-compare/`（每项一个 `<时间>-<项>/summary.json`，加上 `log*.txt`），脚本在 `scripts/shell-bench/`。
>
> 参考了：对照-Flutter与mygo（私有存档）（同一套量法和 10-24 的数）、调研-Go做壳和后台的取舍（私有存档）；组件对照和社区库是 Sol（codex/gpt-6.1-sol，只读）读源码、搜社区写的，原文在 `data/dev/shell-compare/sol-组件对照-20261026.md`、`sol-社区库-20261026.md`，主会话抽查过出处（见第四节）。

> 背景，不是规则（2026-11-19，P0-5）：这是网页 + Electrobun 对 mygo 的实测对照，ADR-353 已被 ADR-359 取代，后台和界面都留在 Go + mygo；现行规则看[开发指导/界面与交互](../开发指导/界面与交互.md)和[设计语言](../设计语言.md)。

## 一、结论

1. **性能、占用乙全面领先，差距不是一点点**：启动快一倍，内存只有甲的七分之一到十分之一，滚动、拖滚动条、流式出字的明显卡顿（超过 33 ms 的帧）甲有几十到上百帧，乙基本为零。
2. **但乙画得比甲简单**（原型里卡片是一行字、头像是一个字母、没有表情回应和小黄脸，见截图），差距里有一部分是这个原因；乙做全以后会慢一些，慢多少没量。
3. **组件**：大部分有现成的或能拼；两样要自己写、工作量大（虚拟长列表里跨屏选中文字、源码保真的提示词实时预览编辑器），视频要带 libmpv（LGPL）。
4. **拍板条件**（规格第五节）：第 1、2 条乙满足；第 3 条（主人手滚手点）等主人；第 4 条"没有做不出的"——严格说都做得出，但有两样是大活，要主人掂量。

后台那一侧（后端 Agent 那条线量的，同一份真实私聊回放、假网关、三遍中位；`data/dev/shadow/202610252353/bench.md`）：启动到能接第一句 Bun 1079 ms、Go 47 ms；每句（不算模型）中位 Bun 11～12 ms、Go 6 ms；常驻内存 Bun 155～165 MB、Go 46～50 MB。Bun 那边只装了主窗口要的插件，真实整个后台更大；每句差的几毫秒用户感觉不到，差得明显的是启动和常驻内存。

**口径和不公平的地方**（都写着，不挑对哪边有利的说）：
- 甲量"帧间隔"（rAF），乙量"每帧耗时"（MYGO_FRAME_STATS），不是同一个量，只比方向；"超过 33 ms"这种明显的卡两边能比。
- 甲碰到顶会自己接着加载，比乙多加载了 7%～15%（11400～12200 对 10588～10631 条），对甲不利。
- **乙画得比甲简单**：卡片是一行字、头像是一个字母、没有表情回应 / 小黄脸 / 闸门标记；对乙有利，差距会缩小多少没量。
- 甲流式那项三遍共用一个临时后台，会话越来越长，后两遍要画的更多，对甲不利。
- 乙切会话、切设置的"画完"是近似的（数据读完 + 两次切换之间最重的那一帧），不含等下一次刷新的时间。
- 开发时的热更新（甲有 Vite 热更新、乙每次重新编译重开）没量。
- 边界情况（[清单](清单-常见边界情况-2026-10-26.md)）里"加载到一半切走""窄窗口下的交互"只截了图，没量；乙原型的功能不全，很多情况甲能测、乙测不了。

## 三、壳本身（甲）

- Electrobun 2.0 的 npm 包只是引导程序，运行时和工具链（Hutch 0.28.1）第一次运行时从 GitHub 下载并核对 SHA-256；没网时跑不了。
- 安装器要用 Windows 自带的 tar（Git Bash 里的 GNU tar 会把 `C:` 当成远程主机）；默认主目录 `~/.hutch` 被 npm 引导程序先占了，用 `HUTCH_HOME=<本机开发目录>\hutch`。
- `build/stable-win-x64/…/launcher.exe` 是安装器的一部分，单独双击报"安装包不完整"；能直接跑的是 `--env=dev` 打出来的。
- 用系统 WebView2 = 和 Edge 同一个内核：在浏览器里看到的掉帧，装进壳里照样有（上面的数就是壳里量的）。

## 四、组件够不够（第 4 条）

Sol 对了网页界面用到的六十多样东西（`sol-组件对照-20261026.md`），主会话抽查了三处属实：CrychicUI 的 `VideoFrame` 只有封面和控件、没有解码（`media/video_frame.go:18`）；mygo 解 GIF 只取第一帧（`docs/ui/image.md:19`）；虚拟列表只能选中已经画出来的段落（`docs/ui/text.md:68`）。另外它指出网页那边其实也没接 Mermaid，这一项不算差别。

缺的那几样，社区有没有现成的（`sol-社区库-20261026.md`，主会话用 GitHub 接口核对了 mygo 0.6.4、PR #124 / #464、两个库的许可证）：

| 缺的 | 现成的 | 要做多少 |
|---|---|---|
| 动图（GIF、APNG、动态 WebP） | 有：Go 自带 `image/gif`、`gen2brain/pngn`（MIT）、`gen2brain/vpx/webp`（BSD），都不用 cgo | 小：补按帧换图的播放 |
| 视频 | `gen2brain/go-mpv`（MIT，purego 不用 cgo）+ libmpv（LGPL）；mygo 作者自己有两个视频 PR 没合并 | 中：要随程序带 mpv 的 DLL |
| Mermaid | `zkrebbekx/go-mermaid`（MIT，纯 Go） | 中：不支持中文字体，要补（网页那边本来也没接） |
| 文字里夹小图（小黄脸） | mygo 自带富文本编辑器的行内附件 | 中：复制还原原字符要补 |
| 虚拟长列表跨屏选中文字 | 没有 | 大：按消息记位置的选区 |
| 源码保真的提示词实时预览编辑器 | 没有 | 大：扩展 mygo 编辑器的显示映射 |

## 五、拍板条件对照（规格第五节，先写死的）

| 条件 | 结果 |

| 1. 第 5、6 项卡帧，乙比甲少一半以上 | 满足（滚动 177～251 对 0～24 帧；拖动 8～10 对 0 帧超过 100 ms） |
| 2. 第 4、5 项内存，乙不比甲高 | 满足（空闲 87～89 对 631～639 MB；滚动峰值 635～655 对 1656～1766 MB） |
