### 1.2 一轮怎么走

[读码] 主干流程如下；这里的 sampling 是一次模型请求，turn 是可以多次 sampling 的用户回合。

1. 提交入口在 `start / steer / start-if-idle` 三种模式间决策；这是接受输入的决定，不等于 hooks、历史持久化和模型调用已经完成。出处：C `core/src/session/turn_input.rs:1-6,264-307`。
2. turn 前检查上下文预算，必要时压缩；记录输入及 hooks 上下文；捕获第一次 step。出处：C `core/src/session/turn.rs:200-224,359-405,1457-1487`。
3. 采样前消费允许送达的 pending input，然后捕获该次请求的模型设置、环境、MCP binding、规则文件、扩展目录和最终工具 router。出处：C `core/src/session/turn.rs:489-565`；C `core/src/session/step_context.rs:22-50`。
4. 克隆模型可见历史、构造 `Prompt`，发送模型请求。`Prompt` 包含 input、tools、parallel_tool_calls、base_instructions、output_schema。出处：C `core/src/session/turn.rs:584-604`；C `core/src/client_common.rs:21-41`。
5. 按流事件输出正文、思考和工具活动；收到完整工具项后启动工具，不必等整条响应结束。工具 future 进入有序收集器。出处：C `core/src/session/turn.rs:3033-3164`；C `core/src/tools/parallel.rs:272-340`。
6. 流结束后收齐工具结果并记入历史；工具要求继续或有 pending input 就再次采样；达到窗口条件先压缩。否则执行 Stop hooks，hooks 可补上下文要求继续。出处：C `core/src/session/turn.rs:610-751,753-779,2698-2725,3585-3605`。

[读码] 核心不是一个不断读取可变全局配置的循环，而是每次请求捕获一个 `StepContext`。其中 `settings`、`mcp`、`tool_router`、`loaded_agents_md` 和 `environments` 属于同一个请求视图；live grants 仍通过原 turn 的 accessor 读取。出处：C `core/src/session/step_context.rs:22-82`。

## 2. 工具系统

### 2.1 定义、注册和执行

[读码] 工具实现 `ToolExecutor<ToolInvocation>`：提供工具名、schema、是否允许并行和 handle。核心工具再实现 `CoreToolRuntime`，补 hooks 参数、环境选择、readiness、工具搜索元数据、取消后的收尾义务等。注册后以 `RegisteredTool`/`ToolRegistry` 为基础，最终生成 `ToolRouter`；扩展工具、MCP 工具及客户端动态工具都汇入同一路由规划。出处：C `core/src/tools/registry.rs:56-143`；C `core/src/tools/handlers/unified_exec/exec_command.rs:92-133`；C `core/src/tools/spec_plan.rs:122-132,353-399,401-430,1634-1664`。

[读码] `ToolCall` 的身份是 `ToolName { namespace, name } + call_id + payload`，payload 可为 function/custom/tool-search；某些要求原生审查的工具保留完整原始调用。Debug 刻意不打印参数正文。出处：C `core/src/tools/router.rs:48-66,274-338`。

### 2.2 同一次响应里多个调用怎么并发

[读码] `ToolCallRuntime` 每组持有一个 `Arc<RwLock<()>>`。允许并行的调用取读锁，不允许并行的调用取写锁；因此同组可以“并行一段 → 独占一个 → 再并行”，不必仅因出现一个独占调用就把整组退化成串行。等待工具 readiness 在取锁前完成。出处：C `core/src/tools/parallel.rs:49-55,176-188,272-331`。

关键代码，C `core/src/tools/parallel.rs:285-299` 的分支摘录：

```rust
let guard = if supports_parallel {
    Either::Left(lock.read().instrument(trace_span!("tool_dispatch.parallel_lock")).await)
} else {
    Either::Right(lock.write().instrument(trace_span!("tool_dispatch.exclusive_lock")).await)
};
```

[读码] 上面摘录压平了源码换行，分支和方法未变。是否并行由 runtime 声明，不由模型给一个布尔参数决定；router 对未注册工具的并行能力默认返回 false。`exec_command` 声明允许并行，不能据此推导 shell 命令之间没有文件冲突。出处：C `core/src/tools/router.rs:256-260`；C `core/src/tools/handlers/unified_exec/exec_command.rs:121-123`。

[读码] **执行完成顺序与回填顺序分开。** 工具在 `tokio::spawn` 内运行；外层 `FuturesOrdered` 按加入顺序提供结果，`drain_in_flight` 按此顺序持久化到会话历史。慢的早期调用会延迟后面已完成结果进入历史，但工具完成状态和 readiness trace 可先被记录。出处：C `core/src/tools/parallel.rs:272-340`；C `core/src/session/turn.rs:2892,3158-3164,2698-2725,3585-3595`。

```rust
if let Some(tool_future) = output_result.tool_future {
    in_flight.push_back(tool_future);
}
```

[读码] 这三行出自 C `core/src/session/turn.rs:3158-3160`，收集器定义见同文件 2892 行。

[推断] 在这条调度路径中没有参数级依赖 DAG：按调用顺序回填不意味着同批 B 能引用 A 尚未产出的结果。依赖应拆成下一次模型请求，或在 Code Mode 程序中显式等待再调用下一工具；独占锁只能约束执行重叠，不能推导业务依赖。核对位置：C `core/src/tools/parallel.rs:272-331`；C `core/src/session/turn.rs:3158-3164,3585-3595`；C `core/src/tools/code_mode/execute_handler.rs:47-100`。

### 2.4 输出截断和回填

[读码] shell 输出有两层边界：采集层的 HeadTailBuffer 保留首尾并记 `omitted_bytes`，模型输出层按请求 max_output_tokens 和模型 truncation_policy 取更小预算。当前 unified exec 常量是默认输出 10,000 tokens、采集上限 1 MiB、最多保留 64 个进程。不能把采集上限误写成每次都向模型发送 1 MiB。出处：C `core/src/unified_exec/mod.rs:72-79`；C `core/src/unified_exec/output.rs:11-58`；C `core/src/tools/context.rs:521-590`。

[读码] `ExecCommandToolOutput` 分开保存 raw_output、process_id、exit_code、wall_time、original_token_count；模型正文带运行或退出状态和截断提示，历史插入再执行统一 payload 截断。`response_text` 为 metadata 和截断标记预留预算，避免二次截断损坏已经截过的输出。结果通过 call_id 对齐，function/custom 输出保留类型差异。出处：C `core/src/tools/context.rs:427-459,521-620`；C `core/src/context_manager/history.rs:584-602`。

[读码] 取消不总是直接丢 future：声明 `finishes_on_cancellation` 的 runtime 要观察 token 并发布自己的终态；普通调用在取消时可 abort，并生成 aborted result。已经到达终态或 dispatch 已完成则保留完成结果。出处：C `core/src/tools/registry.rs:63-67`；C `core/src/tools/parallel.rs:367-410`。

## 3. 上下文压缩、缓存和 token 计量

### 3.1 触发条件

[读码] 预算至少有两条：配置的 auto-compact 范围预算，与模型可用完整窗口。范围可为 Total，或 BodyAfterPrefix（减去该窗口的 prefill_input_tokens）；完整窗口为 resolved_context_window × effective_context_window_percent / 100。两条任一达到就需要压缩。启用 token-budget 配置时，fallback buffer 影响范围预算，但不突破完整窗口。出处：C `core/src/session/context_window.rs:53-115`。

[读码] turn 前会检查，工具往返后也会检查；post-turn 另有百分比阈值，默认零即禁用。模型切换到较小窗口、或前后模型都声明且不同的 comp_hash，也可以在新请求前触发以前模型的压缩路径。不存在一个适用于所有模型的固定“80%/90% 到点”。出处：C `core/src/session/turn.rs:687-738,1457-1530`；C `core/src/session/context_window.rs:112-120`；C `core/src/config/mod.rs:667-671,4572-4575`。

[读码] 决策和执行分层：ToolOrchestrator 先看 Skip/Forbidden/NeedsApproval/NeedsHumanApproval 等 requirement，必要时经用户或 Guardian 审核，再选择 sandbox 并执行。沙箱拒绝后，提升权限的重试需重新审查它实际申请的 authority，不能把旧审批任意复用到更大权限。网络审批也有独立开始与收尾。出处：C `core/src/tools/orchestrator.rs:1-3,53-121,145-245`。

[读码] 核心适配层把 SandboxExecRequest 转成 ExecRequest，带 permission_profile、工作根、网络策略和 executor sandbox。读到的本地分支含 MacosSeatbelt 与 WindowsRestrictedToken/提权后端；Linux 有独立 linux-sandbox 工作区模块，但本次未逐层审计其 syscall/隔离实现，不评价各平台等强。出处：C `core/src/sandboxing/mod.rs:1-7,49-74,117-193`；C `Cargo.toml:87`。

### 8.4 会话持久化、恢复和撤销边界

[读码] rollout 的 canonical 记录是 JSONL；RolloutRecorder 通过 mpsc 向后台 writer 投递 AddItems/Persist/Flush/Shutdown，Flush 和 Shutdown 有 ack。writer 持有锁和 terminal_failure，失败能反馈到后续 API，而不是只 fire-and-forget。SessionMeta 含基础指令、动态工具、环境/来源和 history 关联。出处：C `rollout/src/recorder.rs:1,77-158,163-194`。

[读码] 恢复会重建历史、retained context、Guardian checkpoint、previous settings、WorldState baseline 和 window IDs。只有最新且字段完整、契约允许的 compaction 才能作为 replay 截止点；否则回放更多输入，不拿更早 checkpoint 假装替代更新的状态。出处：C `core/src/session/rollout_reconstruction.rs:11-27,54-93`。

[读码] 有 thread/revert，但该 API 路径要求非 ephemeral、Paginated thread；停止旧 runtime 后修改 thread store，再 reload 并保留订阅。这是会话历史回退。结合 GhostSnapshotConfig “已不再生成”的实现说明，不能将其描述为自动撤销任意文件改动或外部副作用。出处：C `app-server/src/request_processors/thread_processor.rs:2248-2308,2388-2450`；C `rollout/src/recorder.rs:100-107`；C `core/src/config/mod.rs:238-244`。

[读码] 已追到的失败恢复主要是：请求重试、Retry-After、WebSocket → HTTPS、auth ownership 重建和压缩模型专用回退。可选 UnboundedConnectionRetries 对特定连接失败从 5 秒倍增到 60 秒，不增加普通请求的所有重试预算。未在已读主循环发现“任意模型错误按模型列表依次降级”的统一调度器，因此不写成通用多模型自动 fallback。出处：C `core/src/responses_retry.rs:23-25,88-181`；C `core/src/client.rs:683-695,728-746`；C `core/src/compact_model_fallback.rs:10-37`。

### 8.7 用量、费用与可观测性

[读码] token usage 按 response/turn/thread 归因，缓存读写和 reasoning 单列。`run_turn`、接收流、tool dispatch 的 parallel/exclusive lock、结果 ready、compaction 等有 span；通道排队、工具执行和模型等待可以分别观测，不能仅靠总耗时反推。出处：C `protocol/src/protocol.rs:2505-2548`；C `core/src/session/turn.rs:2932-2955,3585-3595`；C `core/src/tools/parallel.rs:285-313,334-350`。

[读码] app-server 有 TurnCostWorker，从后台按 turn/response 查询费用，不只在本机按一个硬编码单价乘 token。它受 OTLP exporter 等条件控制，不是每种 provider 默认都可用；poll interval=150 秒、请求 timeout=15 秒、最多跟踪 4,096 个 turn，每次查询最多 100 个。源码中费用观测任务与普通对话主路径分开。出处：C `app-server/src/turn_cost_worker.rs:1-31,88-144`。

[文档] OTEL 提供日志、trace 和 metric exporter，默认日志 exporter=none；agent final response 文本导出另需 log_agent_responses=true，默认 false，文档明确说 best effort 而非 exactly once。不能因为有 tracing 就写成用户的所有提示和结果默认上传。出处：C `otel/README.md:1-17,119-149`。

## 10. 这一家突出的设计（不宣称其它家都没有）

1. **每次采样固定一份能力视图。** `[读码]` StepContext 将模型、环境、规则、MCP 和 router 放在同一捕获点（C `core/src/session/step_context.rs:22-50`）。`[推断]` 好处是模型看见的工具与随后执行的 handler 可按同一版本解释，插件刷新和切模型不容易造成前后错配；live grants 单独绑定原 turn，避免把权限当普通静态配置。
2. **并发执行和有序历史分离，独占只做局部屏障。** `[读码]` RwLock 准入 + tokio task + FuturesOrdered（C `core/src/tools/parallel.rs:272-340`；C `core/src/session/turn.rs:2698-2725,3158-3164`）。`[推断]` 好处是保留确定历史顺序，同时允许相邻的并行工具重叠；代价是有序回填存在队首阻塞，且工具必须正确声明副作用并发性。
3. **上下文是有类型和基线的 WorldState。** `[读码]` section 有稳定 ID、Snapshot、Absent/Unknown/Known 状态和差量渲染（C `core/src/context/world_state/mod.rs:198-277,306-323`）。`[推断]` 好处是规则/权限变化和压缩后重注入有明确位置，减少重复前缀和恢复时猜测旧状态；不是依靠一串临时字符串判断是否注入过。
4. **推测压缩带采用校验和费用责任。** `[读码]` 候选绑定历史/模型/hash/auth owner，安装过期结果可拒绝，已消耗费用仍结算（C `core/src/session/async_compaction.rs:1-3,24-38,155-196`；C `core/src/compact_remote_v2_installation.rs:29-60,81-87`）。`[推断]` 好处是后台优化不会静默替换掉后来的会话，代价显式可观测。
5. **工具发现与工具执行不另立两套权限。** `[读码]` 曝光枚举、deferred 搜索、Code Mode 嵌套映射都来自最终 router；搜索先过滤允许工具再限量（C `core/src/tools/spec_plan.rs:310-318,988-1011`；C `core/src/tools/handlers/tool_search.rs:282-333`）。`[推断]` 好处是大工具目录可以延迟 schema，同时保持命名空间和执行身份一致；目录发现不是权限升级。
6. **把工作继续、输入排队和真实取消分开。** `[读码]` StartOrSteer/StartIfIdle、Steer/Mailbox、QueueOnly/TriggerTurn、TUI 队列及持久 QueueStore 各有结构（C `core/src/session/turn_input.rs:264-307`；C `core/src/session/input_queue.rs:87-143`；C `ext/queue/src/service.rs:40-71`）。`[推断]` 好处是用户意图和 agent 消息可以分别表达，不必把每条新输入解释成 kill-and-restart。
7. **审查具有独立的证据和复用契约。** `[读码]` Guardian 输入包含动作、parent transcript、当前策略和图像预算，reviewer 复用 key 跟踪父状态/指令（C `core/src/guardian/review_session_prompt.rs:25-90`；C `core/src/guardian/review_session_setup.rs:60-148`）。`[推断]` 好处是能解释审查究竟基于什么批准，权限升级时能重审，优于把审查当一次没有上下文契约的普通聊天。
8. **原始采集、模型输出和日志预算分开。** `[读码]` raw_output、omitted_bytes、输出 token policy、日志渲染和历史截断各有边界（C `core/src/unified_exec/output.rs:11-58`；C `core/src/tools/context.rs:442-459,521-590`）。`[推断]` 好处是既能控制 token，又能知道结果不完整，避免把“工具已成功但内容被截断”混成执行失败。
