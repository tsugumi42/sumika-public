## 数据核对口径与拆除前提

计数按字段存在判断，不把字段存在直接解释为 true。JSON 查询先以 `json_valid` 保护。下面是本次计数使用的主要口径；只读 URI 和 query_only 是连接前提，SQL 本身不包含修改。

```sql
-- 每个活跃聊天库分别统计；仅返回计数。
WITH e AS (
  SELECT CASE WHEN json_valid(segments_json)
              THEN segments_json ELSE '{}' END AS j
  FROM events
)
SELECT count(*) AS events,
       sum(json_type(j, '$.import_meta') IS NOT NULL) AS imported,
       sum(coalesce(json_array_length(j, '$.import_meta.legacy_segments'), 0) > 0)
         AS legacy_events,
       sum(coalesce(json_array_length(j, '$.import_meta.legacy_segments'), 0))
         AS legacy_segments
FROM e;

-- 单值 scope 兜底是否仍有活跃数据需求；episodes 同式，把前缀改成 e:。
SELECT count(*) FROM facts f
WHERE NOT EXISTS (
  SELECT 1 FROM item_scopes s WHERE s.ref = 'f:' || f.id
);
SELECT count(*) FROM facts f
WHERE NOT EXISTS (
  SELECT 1 FROM item_scopes s
  WHERE s.ref = 'f:' || f.id AND s.scope = f.scope
);
```

D01 要彻底去掉的是**常驻读旧格式的需求**，不是只删 import_meta 字段：中立段必须先表达目前旧段补给的媒体身份、有效 hash、展示元数据、图片占位规则；原始/未知内容需有可审计保存方式。D02 要保留未发送/撤回语义。D03 要保持披露范围和导入事实保护；不能把兼容收口变成放宽权限。以上均为后续建议，本次没有执行转换。

## 建议的先后

以下只排新增事项，已知名册/固定提示词/NoFuse/十分钟及正在删的导入器不重复占名额。

| 顺位 | 条目 | 为什么先做 | 完成时应看到什么 |
|---:|---|---|---|
| 1 | **A01 审批预览与编辑执行不一致** | 直接影响主人批准的内容，风险高于命名和历史注释。 | 同一编辑计算驱动预览与实际写入；字面美元、多项定位、模糊匹配和重叠失败语义一致。 |
| 2 | **C01 新角色缺正式建库路径** | 影响干净安装和新增角色的核心记忆能力，删除导入器本身解决不了。 | Go 能为合法新角色创建当前 schema，再按授权开写；不依赖先造 Bun 库。 |
| 3 | **C02 旧网页端口阻止 Go 开库** | 可以连历史浏览都挡住，且端口监听并非数据占用证据。 | 无关服务占旧端口不再决定 Go 是否可启动；真实数据排他保护仍有效。 |
| 4 | **C03 密钥恢复仍指向 Bun** | 启动失败时给出的恢复路径不可用；换机/便携场景还缺正式解锁能力。 | 报错给出当前可行步骤，Go 密钥能力和暂不支持的情况说清楚，不要求复活旧后台。 |
| 5 | **B07 记忆评测默认读旧数据** | 会让后续修改在过时资料上拿到“好成绩”，影响其他改动的判断依据。 | 默认评测与选定 Go 数据组同源，旧快照只在显式历史实验时使用；独立题集来源可用。 |
| 6 | **A06 以最早事件时间猜消息来源** | 属于身份/来源语义；“照搬、没有验证”仍在运行路径里。 | human/external/未知的证据和消费者含义明确，不拿交接启发式充当身份事实。 |
| 7 | **D01 历史双格式的一次性规范化** | 37,123 条事件仍带 import_meta，不能靠删包收尾；需先让 Go 数据自足。 | 展示、媒体核对、记忆图槽不再读旧段，370 个 video hash 候选等经过身份/有效性核对，不丢元数据。 |
| 8 | **D02/D03 收口已完成迁移的兼容路径** | 旧 backfill/selftest 已有 tags；589 条记忆都有范围组。这里有数据支持的简化机会。 | 保留那 1 行未发送语义；缺范围组变成明确完整性问题；备份读取与当前运行契约分开。 |
| 9 | **B01～B06、E06 建立 Go 自己的基线和生成来源** | 旧工具清单、双轨录像、强制 Bun 字段和不可用生成器会持续阻碍后续清理；B06 还影响生产文本规则。 | 当前 Go 合约成为正确答案，安全/状态回归保留；Unicode、声明、图标各有明确维护来源。与 A02/A03 等行为调整配套。 |
| 10 | **E01～E05/E07、C04 修正现行导航和阶段说明** | 成本相对小，能避免下一轮又照旧网页、旧 ctx、切换日和旧计量公式开工。 | 总设计、AGENTS、待实施规格与实际 Go 入口对齐；正式数据布局和记忆上线阶段不再含糊。 |

A02/A03/A04/A05/A07 涉及广泛工具和模型边界，适合在基线转为 Go 契约后分项收口；不能以“去 Bun”为由一把替换字符、数字、差分和预算规则。D04 与 R07 可在独立资源打包工作中一起解决，但不因此扩大为重做整套界面。
