分两份独立估算：

1. **抽检窗口**：`-cursors seed -since 2026-10-29`。只在每次运行自己的记忆副本种游标，从窗口起点前的最后一条 seq 往后跑；报告必须标明“不是真实游标”。窗口上界来自冻结聊天副本，不存在 `-until` 参数。统计发现未来时间戳或 seq 与日期显著倒挂时，先核对实际覆盖范围，不能声称这是严格按事件时间切出的闭区间。
2. **上线积压**：`-cursors real`，不带 `-since/-last`。用同一冻结基线中真实游标，量每个会话还会处理多少行。无游标会话一批也不跑，生产启动通常从最新处立游标；零调用不能证明历史没有该记的事。近七天抽检通过不等于历史积压已抽检通过：若要补更早历史，先对那段补估算及抽检，或由主人选 `latest` 放弃那段。

$char = 'suzune' # 待主会话核对铃音实际 id

        $src = Join-Path $source $rel

对 baseline 的每个 `.db` 在主人授权后用只读 SQLite 做 `PRAGMA integrity_check`，每个都必须为 `ok`；下面统计脚本也做这件事。WAL 文件保留到检查完成，不手删 WAL/SHM；只读打开可能依 SQLite 环境使用副本旁的 SHM，不影响真实源库。工具会在自己的运行副本迁移 `memory.db`、重建全文索引。baseline 始终不送进 `Memory.Open(Writable:true)`。

### 主会话要跑的只读统计命令

仍在 PowerShell 7；沿用上一节变量。Bun 只作为脚本与 SQLite 运行时，不启动已退役的 Bun 后台。统计只开 baseline，不读 `$source`；不打印正文、姓名或号码，只列本地会话 id、数量和日期。

```powershell
$env:SUMIKA_SHADOW_BASELINE = $baseline
$env:SUMIKA_SHADOW_CHARACTER = $char
$env:SUMIKA_SHADOW_SINCE = '2026-10-29T00:00:00' # 按本机本地时区
$statsCode = @'
import { Database } from "bun:sqlite";
import { readdirSync } from "node:fs";
import { join } from "node:path";
const base = process.env.SUMIKA_SHADOW_BASELINE;
const char = process.env.SUMIKA_SHADOW_CHARACTER;
const since = new Date(process.env.SUMIKA_SHADOW_SINCE).getTime();
if (!base || !char || !Number.isFinite(since)) throw new Error("统计参数缺失或日期非法");
const chatDir = join(base, "go", "chat");
const files = [join(base, "go", "trace.db"), join(base, "go", "characters", char, "memory.db"),
  ...readdirSync(chatDir).filter(x => x.endsWith(".db")).map(x => join(chatDir, x))];
for (const file of files) {

  try {
    const rows = db.query("PRAGMA integrity_check").all();
    if (rows.length !== 1 || Object.values(rows[0])[0] !== "ok") throw new Error("副本完整性失败：" + file);
  } finally { db.close(); }
}
const chat = new Database(join(chatDir, "local.db"), { readonly: true, strict: true });
const mem = new Database(join(base, "go", "characters", char, "memory.db"), { readonly: true, strict: true });
const iso = x => x == null ? null : new Date(Number(x)).toISOString();
const localPrivate = conv => {
  if (!conv.startsWith("console:")) return false;
  const p = conv.slice(8).split(":");
  return p.every(x => x && x.trim() === x) && (p.length === 1 || (p.length === 3 && p[1] === "topic"));
};
try {
  const heads = chat.query(`SELECT DISTINCT e.conversation FROM events e
    JOIN observations o ON o.event_seq=e.seq WHERE o.character_id=? AND e.channel='console'`).all(char);
  const count = chat.query(`SELECT count(*) AS event_rows,
    sum(CASE WHEN e.kind='message' THEN 1 ELSE 0 END) AS message_rows,
    sum(CASE WHEN e.kind='message' AND EXISTS (SELECT 1 FROM observations o
      WHERE o.event_seq=e.seq AND o.character_id=?) THEN 1 ELSE 0 END) AS seen_message_rows,
    sum(CASE WHEN e.kind='message' THEN length(e.text) ELSE 0 END) AS raw_text_chars,
    min(e.created_at) AS first_at, max(e.created_at) AS last_at
    FROM events e WHERE e.conversation=? AND e.seq>? AND e.created_at>=?`);

  const result = heads.filter(x => localPrivate(x.conversation)).map(({conversation: conv}) => {
    const c = cursor.get(conv);
    const read = (after, start) => {
      const r = count.get(char, conv, after, start);
      return {...r, first_at: iso(r.first_at), last_at: iso(r.last_at)};
    };
    return {conversation: conv, has_cursor: c != null, cursor: c?.last_seq ?? null,
      all: read(0, 0), window: read(0, since),
      backlog: c == null ? null : read(c.last_seq, 0)};
  });
  console.log(JSON.stringify({character: char, since: iso(since), rows: result}, null, 2));
} finally { chat.close(); mem.close(); }

bun --eval $statsCode | Set-Content -LiteralPath (Join-Path $run 'stats.json') -Encoding utf8
if ($LASTEXITCODE -ne 0) { throw '只读统计失败，不能继续估算' }
```

`stats.json` 的时间输出为 UTC ISO，`frozen-at.txt` 带本地偏移；展示给主人时转换为同一时区并标明。`all.message_rows` 是本地私聊消息总数，`window.message_rows` 是抽检窗口条数，`backlog.message_rows` 是真实游标后的条数。`seen_message_rows` 只数角色见过的消息；这些仍含撤回、自检等，**不是**最终喂给模型的有效条数。`event_rows` 用来覆盖事件分页限制；`raw_text_chars` 不含图片描述、转义及提示词前情，只能粗估。空集的 sum 为 null 按 0 解读。

不能用 `MAX(seq)-last_seq` 当消息条数：seq 是平台库里跨会话增长的，现有报告 `behind` 正是 seq 差值，可能高估。本脚本用 count(*)，后面的确切批数交生产切批估算。

### 公式与 -spend

设每个会话 i：

- M_i：选定窗口中消息条数，优先同时报“全部 / 该角色见过”；R_i：生产实际读取的事件行数。
- B = 200：每批最多读取事件数；L = 6000：保留正文的码点上限。`memory.batchEvents = 40` 是排程触发门槛，**不是**调用批大小。
- C_i：真正送模型的正文总码点（每条超长先截到 6000；图片描述和转义计入）。

人工粗估：Q_count = Σ ceil(M_i / 200)；同时给字符压力估计 Q_chars = Σ ceil(C_i / 6000)，Q_rough ≈ Σ max(ceil(R_i / 200), ceil(C_i / 6000))。**这不是精确值或严格上界**：逐条装批的剩余空间、过滤、全占位跳过、已完成 job、等图都会改变它；SQL 的 raw_text_chars 也不是 C_i。不要只拿消息数除以 40，更不要按 seq 差算钱。

**最终调用估算 Q 用下面无模型运行的 `summary.json.model_calls`**。这是空生成器被调用的次数，代表生产切批需请求模型的次数，实际付费调用仍为 0；`batches` 包含只推进游标、没调用模型的批，不能替代 Q。确认 `cap_hit=false`、所有 session.err 为空、没有等图未完成后才采用。估算的提示词前情没有真跑新增候选，token 估计会偏差；调用批数一般不因模型返回内容改变，但报错、恢复及再次运行另计。

**我定的余量：S = Q + max(2, ceil(0.10 × Q))，仅 Q>0 时使用；Q=0 不付费跑。** 这不是主人已定的固定预算。若主人给金额上限，同时报告模型实际单价与输入/输出 token 假设；取不到价格写“金额未知”，不硬换成人民币。首批调用的输出、延迟和 usage 只在已报告预算内观测，不能在估算阶段偷偷调用一次。

例子（全为演算，不是实测）：三个会话消息数 420 / 80 / 0，忽略字数时 Q_count=3+1+0=4；若生产估算实际为 Q=7，则 S=7+2=9。字符切批可能多于 4，所以真跑用 9，不用 4。真实游标和 seed 估算各有自己的 Q；不相加伪装成一次运行的额度。
