### 1.2 状态、写入位置与生效图例

### 3.7 重复编辑与重复显示

[读码] 当前正式界面没有发现同一持久配置键在两个页面均可改：模型只有 M，外观只有 A，资源根只有 DP。不能为了套原则虚报“双入口写冲突”。现有问题是：

| 情况 | 现状 | 重排约束 |
|---|---|---|
| vision.model | 记忆页读真实配置值，模型页另一行只显示禁用原因 | 唯一归属模型/图像理解；其他页链接 |
| 模型/角色状态 | 模型页编辑，运行页角色行与聊天资料快照可能仍是旧值 | 状态来自同一发布快照；角色详情只读+跳转模型行，符合 ADR-238 |
| 资源根 | 运行页与数据页都能看，仅数据页能改 | 运行给摘要+打开数据位置；允许重复读，不复制编辑器 |
| 开机自启 | 托盘能改，通知页 runtime 项没接实际值 | 设置与托盘共用同一 OS 命令/状态；讨论是否保留双控制面见 Q4 |

| 职业工具权限 vs 全局审批 | 只在演示里看似两套可改 | 不把职业表当作能覆盖固定执行边界的授权；先定继承和拒绝优先级 |

## 五、新结构树（建议，按 MewTypeUI 替换后的目标）

### 5.1 安放规则

1. 高频动作留在会话：发消息、停止、审批、选择回复对象、搜本会话、建话题/建群。低频且跨会话的偏好进设置（A/F）。
2. 一个持久字段有一个编辑器；其他页展示实际值并定位过去（S238）。“哪里能找到”可以有多个入口，“数据归谁保存”只有一份。
3. 右侧栏只回答“这个会话/这一轮/这个角色”；运行页回答“整个程序/所有后台作业”；设置回答“以后怎样运行”。
4. 左侧主导航按工作对象分段；设置内11类分三组，组标题不增加点击层级。常用字段从分类页直接可达；少用细项最多一层展开或独立详情。编辑弹框不再嵌弹框。
5. 各树节点的“为什么”在括号里；未实现的枝条都是目标，不应在产品显示可点的假按钮。业务能力未完成前只显示明确状态和可做的下一步。

### 5.2 主导航与会话树

```text

├─ 会话：本地 / QQ（先做；常用会话随时可达，平台不与角色混作身份）
│  ├─ 本地 → 会话列表
│  │  ├─ 搜索当前会话目录；私聊 / 群聊切换（沿用 ADR-086）
│  │  ├─ 私聊 → 日常（角色常驻，可折叠）
│  │  │  ├─ 各角色日常 → 一次点击开聊天
│  │  │  └─ 新建角色 → 进入角色创建流程；不在此复制人设编辑器
```

### 5.5 高频任务的落点与四场合边界

| 任务 | 本地私聊 | 本地群聊 | QQ 私聊 | QQ 群 |

### 7.3 复用ADR-249的是保存/生效方法，不是无限写权限

每个新设置页先写自己的类型化白名单和消费者表，不做“任意YAML路径编辑器”。可复用：来源定位、内容版本检查、原文小补丁、config/history、重新解析自检、原子替换、发布不可变运行快照、异步错误回到原行、切页/换源不接受旧结果。新增页不得直接修改App.cfg或为换一个值重建Hub。

生效时刻必须逐类落实：

| 类别 | 应有行为 | 不能承诺的事 |
|---|---|---|
| 模型/思考/上下文 | 沿现有ModelRuntime，一轮一版，下一轮使用 | 不把在途旧参数标失败，也不在一轮中混版 |
| 工具/审批/项目上下文 | 新决策/新回合读取冻结版本；有效授权与配置值分别显示 | 不能给已经在跑的命令补一份新授权，不能抹掉待审批状态 |
| 整理/召回/重排 | 新作业读新参数；已有作业用原版结束；角色实际启用前提照旧 | 不能“保存”就绕过首次备份/抽检，不能把表达学习不存在说成已开启 |
| 插件 | 先拒收新工作→取消/等待→卸载；能安全重启的才标热更新 | 不支持的必须显示重启范围；卸载后旧作业不能继续触库 |
| 嵌入后端/模型 | 明确向量版本、索引重算/模型池切换和守卫可用状态 | 不能套聊天模型的“下一轮换ID”就当全部完成 |
| QQ连接/账号绑定 | 由宿主协调连接与旧历史归属；独立方案后再写 | 不自动改真实SnowLuma，不自动启发送，不隐藏接收中断 |
| 数据根/恢复 | 根位置按既有重启合同；迁移/恢复另有完整事务与撤回 | 不把改sumika.root说成搬了数据，也不承诺所有页都免重启 |

普通保存的即时反馈分“正在保存/未保存（错误）/已保存且下一次使用/已保存但未生效（原因）”，值回显来自后台返回快照。人设和多字段编辑保留显式保存；单项开关/选择沿模型页即时保存；删除/权限放宽不直接沿用普通开关节奏。

## 九、和研究铃音讨论的结果（2026-11-04）

评审全文：[评审-界面信息架构](评审-界面信息架构-2026-11-04.md)（它按准则 A～F 编号逐条给意见，c 节是修改后的完整树，167 个末级项注了作用域和"改 / 跳 / 看 / 命令"）。主会话核对后：

- **采纳，落地时按评审 c 节的树做**（我定的，都不涉及权限默认值）："同一个值只存一份"和"只有一个编辑位置"分开写；右侧栏三块改名"资料 / 活动 / 请求详情"，工作面板按任务出现；开机自启移出通知，放进设置主页的"启动"小组；"伙伴"改"角色与记忆"；"高级"按内容拆成"压缩阈值""聊天实例与回收""确认与隔离"；整个领域没有真实闭环就不放入口，已有功能受阻才留状态和恢复入口；请求详情只显示那一次请求实际用的值，没快照就说不知道；群资料顶栏和右栏打开同一个编辑面；"切换角色"拆成打开别的角色的会话、@ 点名、筛选查看三件事；插件参数收进各插件详情。
