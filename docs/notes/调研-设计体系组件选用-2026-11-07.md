# 调研：成熟设计体系怎么定"什么时候用什么"（2026-11-07）

> 起因：主人 2026-11-07"这 UI 好像现在也没有一套统一的规范……完全就是你寻思他怎么做，那他就怎么做"。工作流三路只读调研（已有规则、现有代码用法、成熟设计体系的选用指引）后起草、再核对。本文是调研原文，规范见 界面模式规范（私有存档）。

> 背景，不是规则（2026-11-19，P0-5）：这是成熟设计体系怎么选控件的调研；现行规则看[开发指导/界面与交互](../开发指导/界面与交互.md)和[设计语言](../设计语言.md)。

## 结论

主人要的"统一规范"，核心是一张"情境 → 组件/结构"的选型表。mygo v0.8.1 已经有大部分需要的控件，下面的表都对着它的真实函数名写。调研里有几处官方页面没抓到正文（M3、Apple 分段控件等），相关条目已标"未验证"，不能当成官方原文引用。

## 一、mygo v0.8.1 现有控件（已核对源码）

源码位置：`<Go 模块缓存>\pkg\mod\github.com\egoist\mygo@v0.8.1\ui\`（由 `native/go.mod` 的 `github.com/egoist/mygo v0.8.1` 解析得到）。

- 列表：`List` + `ListState`（list.go:1-37 的注释，只构建可见行，按锚点定位）；`ListBuilder` 在 list_builder.go。
- 表格：`Table(c, s *ListState, columns []TableColumn, n, cell)`（api_gen.go:2557；table.go:10 TableColumn）。
- 网格：`GridView(c, s *GridState, n, minWidth, height, item)`（api_gen.go:1603；gridview.go:10 GridState，注释"如 List 的行那样选择、定位"）。
- 没有瀑布流 / Masonry：在 ui 包里搜不到 Waterfall、Masonry 任何实现（grep 结果为空）。
- 分栏：`Split`、`SplitPercent`、`SplitVertical`、`SplitVerticalPercent`（api_gen.go:2417-2457；split.go:3,16,21,30）。
- 侧栏：`Sidebar(c, selected *string, fn)`、`SidebarSection(c, title, open *bool, fn)`、`SidebarItem(c, id, icon, label)`（api_gen.go:2298-2326；sidebar.go:24,40,99,159）。Sidebar 的注释写明"辅助技术看到 tree，分区持有条目"。
- 树：`Tree`、`TreeItem`（api_gen.go:3001,3069；tree.go:37,46,84）。
- 分段：`Segmented(c, selected *int, labels...)`（api_gen.go:2189），注释写明"作为视图切换：点击或方向键选择，辅助技术看到 radio group，用 Label 命名"。
- 标签页：`Tabs(c, selected *int, labels...)`（api_gen.go:2580）。
- 开关：`Switch(c, on *bool)`（api_gen.go:2499）；按钮式开关：`Toggle(c, on, label)`、`ToggleGroup`（api_gen.go:2857,2892）。
- 对话框：`AlertDialog(c, open, title, message, buttons...)` 返回按钮序号（api_gen.go:914）；`DialogBase`（api_gen.go:1378）注释：点遮罩或 Esc 关闭。
- 菜单：`Menu`（menu.go:137）、`PopoverMenuButton`（popovermenu.go:138）、ContextMenu、PopoverMenu。
- 提示：`Toast` + `AddToast`（toast.go:21）。
- 没找到：SearchField、Chip、Card、Badge、Pill、Sheet、Drawer 的独立构造函数（grep 无命中；可能在别的名字下，标未验证）。

## 二、选型表（情境 → 推荐 → 理由 → 来源）

| 情境 | 推荐组件/结构 | 理由 | 来源 |
|---|---|---|---|
| 左边选会话，右边看内容（会话列表 + 聊天） | `SplitPercent` 包两个 `List`/区域 | Apple：分栏用于宽窗口，供多栏并排；M3 的 list-detail 规范页 404，未能核对正文 | Apple split views（只看到搜索摘要，未抓到正文）：https://developer.apple.com/design/human-interface-guidelines/split-views.md ；mygo split.go:3,21 |
| 平台账号、分组、顶层导航 | `Sidebar` + `SidebarSection` + `SidebarItem` | Apple：侧栏承担顶层导航，位于分栏的前导栏；账号切换可放在侧栏顶部（"账号"作为一区） | Apple sidebars（只看到搜索摘要）：https://developer.apple.com/design/human-interface-guidelines/sidebars.md ；mygo sidebar.go:24,99 |
| 同一批内容换一种看法（全部 / 未读 / 群 / 私聊，互斥） | `Segmented`（2 到 5 项） | Apple 的分段控件用于同一内容的视图切换；mygo 注释写的正是这个用途 | mygo api_gen.go:2189 注释；Apple segmented controls 正文未取到，未验证细节 |
| 几个并列的大分类（如文件夹、话题分区），需要切换内容区 | `Tabs` | 每个标签对应一块独立内容，适合数量少且固定的分类 | mygo api_gen.go:2580；M3 chips/tabs 页 404，未核对官方选型 |
| 分类很多、会增减（文件夹、话题、群组分组） | `Sidebar` 分区 + `SidebarSection` 可折叠 | 多了不能靠标签横排，侧栏分区能折叠；与 Telegram 文件夹"很多后要分类"的做法一致 | mygo sidebar.go:99；Telegram 官方 folders 页（见第三节） |
| 多选筛选（同时选"未读"和"群"） | `ToggleGroup` 包多个 `Toggle` | 互斥用 Segmented，可叠加用 Toggle 组 | mygo api_gen.go:2857,2892 |
| 平台账号选择条（如 QQ / 本地，数量少） | `Segmented`（横向，≤ 4 项）；多于 4 个改用 `PopoverMenuButton` | 账号是"在哪个账号下"的互斥选择，与视图切换同型 | mygo api_gen.go:2189、popovermenu.go:138 |
| 置顶会话 | 列表顶部固定一个"置顶"分区（列表内的分组，不另建组件） | Telegram 的置顶按文件夹独立，每个文件夹内置顶数不设上限（官方页原文"as many pinned chats as you like"） | telegram.org/blog/folders（摘要） |
| 设置里的开关（开 / 关） | `Switch` | 即时生效、单一状态；对应 M3 "switch vs checkbox"，但 M3 页未取到，未验证 | mygo api_gen.go:2499 |
| 操作型按钮式开关（如"置顶""静音"的当前态，图标按钮） | `Toggle` | 按下 / 放开状态，适合工具栏 | mygo api_gen.go:2857 注释 |
| 需要用户确认（删除、覆盖） | `AlertDialog`（一句话 + 两个按钮） | 短确认用 alert；多字段输入用 `DialogBase` 自己搭 | mygo api_gen.go:914；Apple alerts 正文未取到，未验证 |
| 需要在当前界面里做一件有范围的小任务（如选会话去转发、填参数） | `DialogBase`（面板）；Apple 的 sheet 用途与此相近 | Apple split view 页提到 sheet 用于"请求少量信息或简单任务"（摘要，未核对正文） | mygo api_gen.go:1378；Apple presentation 页（摘要） |
| 数据型、多列、需要排序（如记忆条目、审批记录） | `Table` + `ListState` | 表格适合同一字段对齐比较的数据 | mygo api_gen.go:2557；table.go:10 |
| 图片、卡片、媒体集合（以图为主，不要求逐行对比） | `GridView` | 等宽网格，适合缩略图；mygo 没有瀑布流 | mygo api_gen.go:1603；gridview.go:10 |
| 瀑布流（图片高度不一） | 没有现成组件，需要自写，或先用 `GridView` 等宽替代 | mygo v0.8.1 里搜不到 Waterfall / Masonry | 源码搜索结果（ui 包无命中） |
| 层级树（文件夹、角色分组） | `Tree` + `TreeItem` | 可展开层级 | mygo api_gen.go:3001,3069 |
| 操作完成的轻提示 | `Toast` + `AddToast` | 不打断操作 | mygo toast.go:21 |
| 右键或更多菜单 | `ContextMenu`、`PopoverMenu` | 动作列表 | mygo menu.go:137，popovermenu.go:138 |
| 搜索框 | 未找到 `SearchField`，需要确认 | 会话筛选的搜索部分缺组件；可能要自写一个输入框配图标 | mygo 源码搜索无命中，未验证 |

## 三、聊天应用惯例

- Telegram 文件夹（官方页，已抓取摘要）：https://telegram.org/blog/folders
  - 文件夹是会话列表的分类标签，可左右滑动切换；可以按类型（频道、群、未读）或单独加入会话。
  - 置顶按文件夹独立，每个文件夹置顶数"不设上限"（页面原文"as many pinned chats as you like"）。
  - 文件夹功能 2020-03-30 随更新上线（页面日期）。
  - 页面没有给出文件夹数量上限，也没有给出创建步骤的细节。
- Telegram 话题（forum topics）：搜索结果里没有官方页面，未验证，不能给出行为细节。
- Discord、Slack 的会话列表、账号切换：本次没有完成调研（没有抓到官方页），这部分是空白，需要单独查。
- 账号切换器：本次没有找到可靠来源，只能说 Telegram 桌面版的多账号做法未验证。
