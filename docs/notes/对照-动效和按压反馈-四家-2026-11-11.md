**退场是否比进场短**：Arc 全部更短（菜单 130 对 160、对话框 160 对 240、标签面板 120 对 240、提示条 180 对 240）；animate-ui 对话框和面板出 0.2s 对进 0.4s；HeroUI 容器 100 对 250；Codex 菜单 .1 对 .15；我们也是。dotUI 的 standard 一档两边相等（100/100），smooth 一档更短。**没有哪一家反过来**。

**退场用什么曲线**——四家并不一致，这点值得真机比一下：
- 我们规格写 `EaseIn = (.42,0,1,1)`，“第一批真机看过再微调”（`规格-过渡动画.md:72`）。
- Arc 定义了一条强加速的 `ease.exit = [.7,0,.84,0]`（`motion-tokens.ts:6`），但**这次读到的组件里没有一处用它做进出场**（只在 `password-field.tsx:33` 一处），菜单、对话框、提示条的退场用的全是减速型 `ease.standard = [.22,1,.36,1]`（`dialog.tsx:32`、`dropdown-menu.module.css:24`、`toast-stack.tsx:88`），靠时间短（130 ～ 180ms）取胜。
- animate-ui 的 `ease.away = (.33,.17,.67,.5)`，近乎匀速，理由是“别在界面上用 ease-in，开头慢，正是用户盯着看的时候”（旧笔记第四节“退场曲线”行，`tokens.md:118`）。
- 我们的 `ease.route = (.22,1,.36,1)` 与 Arc 的 `ease.standard` 数值完全相同。

## 四、错开、模糊、形变

**错开（stagger）**
- Arc：令牌 `char .016 / word .04 / line .08 / item .035` 秒，注释“总错开保持在约 0.4s 以内”（`motion-tokens.ts:21-22`）。用处：卡片文字按词（`card/card.tsx:56`）、数字滚动每位延迟 `min(序号 × item, .25)`（`animated-counter/animated-counter.tsx:84`）、柱状图 `min(item, .32/条数)` 与 `.36/条数`（`bar-chart/bar-chart.tsx:247,251`）、热力图波浪总长封顶（`activity-heatmap/activity-heatmap.tsx:58`）。**每处都有总量上限**。提示条堆没有错开（弹簧同时重定向，`toast-stack.tsx:241`）。
- animate-ui（二手）：效果类默认不错开，要错开手动传 `holdDelay`；只有提示条堆展开时每条晚 30ms；列表“搜索结果不级联”（`list.md:63`）。
- HeroUI、Codex：未核实（没找到提到）。流式文字淡入 .7s 是整体，不是错开。
- 我们：不做列表错开进场（ADR-024 同系的默认，`规格-过渡动画.md:227`）；流式字“按词 140ms，词间只错开 8ms”是现有的唯一例子（`设计语言.md:393`）。

**模糊（blur）**
- Arc：令牌 `subtle 2 / soft 4 / text 8` px，注释“保持小而短”（`motion-tokens.ts:23-24`）。用在文字和图标替换：标题 / 提示条文案新字从 4px 模糊升起、旧字 2px 淡出（`dialog.tsx:38`、`toast-stack.tsx:89-90`）；提示条图标 2px（:91）；卡片进场（`card.tsx:56`）。**按钮标签替换明确写了“不模糊”**（`button.tsx:28`）。静态的遮罩背景模糊 7px（`dialog.module.css:1`），有“降低透明度”时改实色（`dropdown-menu.module.css:34`，另一个媒体查询）。没有任何大块内容做动态模糊。
- animate-ui（二手）：对话框内容 4px、标签面板 5px、折叠 2px、提示条 4px，减少动态时**保留**模糊；旧笔记结论是大块的不借（`filter` 会掉帧，还会让元素成为 fixed 子元素的包含块）。
- HeroUI、Codex：未核实。
- 我们：只有“她说话时新出来的字”一处在用（`设计语言.md:393`），另一处是表情包悬停；`check-hover-blur` 脚本还在 sumika-bun。

**形变（morph）**
- Arc：按钮标签换了，槽宽用弹簧 `morph` 跟到新标签的实测宽度，首次测量和字体切换不动（`button.tsx:48-67`）；下拉触发钮宽度同理（`dropdown-menu.tsx:36`）；标签指示块 `layoutId` 共享布局（`tabs.tsx:90`）；标签面板高度从旧面板弹到新面板（:126）；提示条类型变了，图标 .6 缩放 + 2px 模糊换位、整条高度弹簧变形（`toast-stack.tsx:254-257,369-372`）；另有 `confirm-morph`、`expandable-card` 等组件，这次没读。
- animate-ui（二手）：指示块用 Web Animations 手写，被打断时带速度接力；列表增删用 FLIP 让位（`reflow` 500/40）；数字滚动每位一个弹簧（质量 .4，不过冲）。
- HeroUI：未核实。Codex：模型选择滑块有过渡，细节未核实。
- 我们：mygo 的 `ContentTransition`（`Morph` 逐字变形、`Numeric` 逐位）和 `Transition.Match + Fly` 已备好（`规格-过渡动画.md` 第二节表）；看大图飞出、主题交叉渐变在 ADR-304。

## 五、减少动态效果的处理

| 家 | 做法 | 出处 |
|---|---|---|
| Arc | **每个组件自己分一条“只淡入淡出”的路**：对话框关 / 开都改成 120ms 淡入淡出（`dialog.module.css:30-34`）；菜单去掉位移缩放，只留 120ms 线性透明度（`dropdown-menu.module.css:35-37`）；标签面板换成 120ms 原地交叉淡化，指示块时长 0（`tabs.tsx:100-104,90`）；提示条位置缩放直接跳，透明度 160ms 淡（`toast-stack.tsx:247-251`）；按钮不缩放、转圈改为 .01ms 一次（`button.tsx:109`、`button.module.css:39`）；开关不拉长不滑（`switch.tsx:40,44`）。README 一句话：“用简单的淡入替代位移”（`README.md:678`）。`foundation.css` 里没有全局减少动态规则（我 grep 过，没找到），是逐组件处理 | 同左 |
| animate-ui（二手） | 去掉位移、缩放、尺寸、布局动画；保留透明度、颜色、模糊 | `references/tokens.md:210-214` |
| HeroUI（二手） | 进出场逐处加 `motion-reduce:animate-none`，倾向整体去掉 | `modal.css` |
| Codex（二手） | 18 处 `prefers-reduced-motion` 规则，细节未核实 | 旧笔记 Codex 第 359 行 |
| 我们 | `--motion` 乘数（Bun 时代）；Go 这边靠 mygo `ReduceMotion`：淡入淡出留、位移缩放折叠归零，纯透明度和颜色通道要手写 `NonMotion: true`（`规格-过渡动画.md` 3.3） | ADR-124 |

和我们的差别：Arc 减少动态时把淡入淡出**缩短**到统一的 120ms（`duration.instant`），ADR-124 写的是“时长照常”。差别很小，但新 ADR 要写清楚按哪个。

## 六、综合建议

| `motion.menu-in` / `motion.menu-out` | duration | 180 / 130ms | 菜单、下拉、选区条、资料卡 | `规格-过渡动画.md:60`；Arc 菜单出场也是 130（`dropdown-menu.module.css:24`） |
| `motion.dialog-in` / `motion.dialog-out` | duration | 220 / 160ms | 对话框 | `规格-过渡动画.md:62`；Arc 出场 160（`dialog.tsx:32`） |
| `motion.panel-out` | duration | 200ms（进沿用 `motion.panel` 230） | 右栏、抽屉退场 | `规格-过渡动画.md:63` |
| `motion.expand-in` / `motion.expand-out` | duration | 230 / 200ms | 展开收起，高度不过冲 | `规格-过渡动画.md:64` |
| `motion.theme` | duration | 320ms | 主题交叉渐变 | `规格-过渡动画.md:67`（ADR-304 区间 300 ～ 400） |
| `ease.exit` | cubicBezier | 待定，三选一：A `(.42,0,1,1)`（规格现写）；B `(.33,.17,.67,.5)`（animate-ui `ease.away`）；C 直接用 `ease.route`（Arc 做法，靠时间短） | 所有退场 | 见第二节末；`规格-过渡动画.md:72` |
| `scale.press-icon` | number | .96 | 只有图标的按钮（正圆小钮） | Arc `button.tsx:23`（≤ 48px） |
| `scale.press` | number | .97 | 普通按钮 | Arc、animate-ui、HeroUI 三家一致 |
| `scale.press-wide` | number | .985 | 宽按钮（整行、长条按钮） | Arc `button.tsx:23`（> 220px）；我们的阈值按自己的尺寸档重定，不照搬 48 / 220（未核实我们各档按钮的实际宽度） |
| `spring.press-release` | 不新增，直接用 `spring.smooth` | — | 松手回弹，设置里选了“回弹”就用 `spring.bouncy` | 见 6.2 |

不加的（以及为什么）：
- Arc 的 `snappy / smooth / morph` 视觉时长弹簧：我们的 `spring.smooth` 约 0.17s，比它们快；沿用，只有真机觉得面板或形变太急再加一条慢档（我按公式估算，要视觉约 0.4s 的临界阻尼大致是刚度 ≈ 210、阻尼 ≈ 29，**未实测，仅估算**）。
- Arc 的 `ease.enter [.16,1,.3,1]`、Codex 的 `(.19,1,.22,1)` / `(.23,1,.32,1)`：和 `ease.route (.22,1,.36,1)` 的差别都在 0.03 以内，不另开令牌。
- Arc 的 `ease.inOut [.65,0,.35,1]`：我们没有对应的“屏内移动”场景用它，不加。
- 弹层缩放起点 .98 / .985（我们已有）比 Arc（.97 起、对话框 .96）和 animate-ui（.9 / .8）克制，不改。

可选、**和已定规矩冲突**（见 6.3）：`motion.stagger-item 35ms` + 总量上限 `motion.stagger-max 400ms`（Arc `motion-tokens.ts:21-22`）；`blur.subtle 2 / soft 4 / text 8`（Arc :24）。

### 6.2 “按下缩放”的推荐参数

- **比例**：图标钮 .96、普通按钮 .97、宽按钮 .985（上表三枚令牌），分档按钮尺寸档而不是现量宽度。理由：Arc 的注释“每种尺寸读起来是同样的一推”，三家主流都是 .97。
- **按下**：`motion.press`（120ms）+ `ease.route`；**松手**：弹簧 `spring.smooth`（不过冲）。设置里选“回弹”时松手改 `spring.bouncy`，这与 ADR-152“回弹只给位移和缩放”相容，不是新例外。不推荐 animate-ui 那种按下就会过冲 7% 的弹簧。
- **颜色反馈垫底**：所有按钮保留 `:active` 换底色 / 透明度（Arc `button.module.css:28-31`；Codex 也是换深色底），缩放是叠加的，不是替代的。这样不缩放的控件（触发浮层的、禁用的、减少动态时）仍有回应。
- **例外清单（不缩）**：
  1. 触发浮层的按钮（菜单、下拉、弹层、对话框的触发钮、药丸菜单）：浮层可能在按下瞬间量触发钮的矩形，缩小会让浮层偏位。出处 Arc `button.tsx:93-97`、`button.module.css:5-6`。我们的 mygo 浮层是否也在按下瞬间量锚点：**未核实**，实现前先在 `ui.NewTester` 里验证。
  2. 禁用、加载中、`aria-disabled`（Arc `button.tsx:97,109`）。
  3. 开关：不缩，拇指的处理要主人定（见 6.3）。
  4. 大面积可点的东西：消息气泡、会话列表行、卡片、菜单项、标签页、分段按钮——**这条是我的推荐，Arc 没有明文**（它只对按钮分档，没提列表行）；这些已有选中块 / 高亮块在做反馈。
  5. 窗口标题栏三键、输入框、滑块手柄、拖拽中的东西：我的推荐，**未在四家找到出处**。
  6. 减少动态效果时：不缩，只留颜色反馈（Arc `button.tsx:109`，与 ADR-124 一致）。
- **实现前要验的**（都未核实）：缩放是否只改画，不改布局和点击范围（否则按在边缘会抖）；按下后指针移出按钮时是否像 Arc 开关那样立刻松手（`switch.tsx:55-56` 有 `onPointerLeave`，按钮的 Motion `whileTap` 默认行为我没查）。
