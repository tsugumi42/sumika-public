# 调查：mygo 界面为什么难写

调查日期：2026-11-06。仓库只读；报告与采集材料均在本目录。百分比按“涉及某原因的返工提交数 / 返工提交总数”计算，允许多标签，不能相加，不代表工时占比、事故数或框架总体缺陷率。

## 结论

排前三的原因是：需求和参考没有落实到实际画法，13/39（33.3%）；手工布局、尺寸和绘制几何出错，13/39（33.3%）；展示数据、异步状态和组件应用逻辑漏项，12/39（30.8%）。代表证据分别是 `7285e9f1` 把自拼原型整体换回 CrychicUI、`68b63f0c` 修复上一轮把图标按两轴拉变形、`45ce81db` 修复转发动图误用正文可见区。补入 mygo-m3e 拆仓前史后，同三项分别为 24/76（31.6%）、23/76（30.3%）、17/76（22.4%），排序基本不变。

证据不支持“主要因为 omp 不会加载 skill”。当前 omp v18.16.0 默认发现项目的 `.claude/skills` 和 `.agents/skills`；MewTypeUI 公用派活规则明确引用了 Sumika 的 mygo skill，多份任务要求读固定版本源码。能证明任务带了要求，不能证明历史每一轮读了正文。按逐提交保守映射，官方 skill 的具体规则直接覆盖 7/39（17.9%）；加上按其验收要求可提前发现的另外 4 项，为 11/39（28.2%）。这是有条件的反事实覆盖数，不是实测避免率。

还发现 skill 自身的一处陈旧说明：v0.7.4 官方模板和项目副本都称绑定值在构建配置后更新、局部派生值会在通知前丢失；同版本文档、实现和本轮独立探针则证明，构造器返回时已经应用输入，局部副本可以用 Changed 当场写回。探针退出 0，写回值为 true，Changed 通知恰好 1 次。因此“读过 skill”也不能替代核对当前源码；这不是项目忘记同步上游。

mygo 确实增加难度：绘制原语分别吸附像素，路径先栅格化后变换，早期抬层与鼠标穿透接口有限，软件 Tester 不能证明 D3D11 真窗口呈现代次正确。指定路径口径里，框架或组件库限制涉及 4/39（10.3%），生命周期、身份、线程和构建时序误用涉及 7/39（17.9%）；加前史后两类各 15/76（19.7%）。“限制”包含设计契约和缺少便利接口，不能全部叫作上游 bug。

[INFERENCE] 决策上，先改变交付方式比单纯换一个有官方 skill 的框架更直接：稳定视觉基线，用完成的组件族交付完整场景，以真窗口、逐帧交互和独立参考几何验收。换到 React/Flutter 能减少部分底层绘制和生态工作，但不会自动解决需求理解、照错参考、数据契约、跨层状态和验收目标错误。

## 1. 范围、口径和方法

- 日期：2026-10-24 00:00 起，至本次采集时存在的本地可达引用。
- Git：`log --all --since-as-filter=2026-10-24T00:00:00 --no-merges --max-count=10000`，结合路径、说明与 show。以哈希去重，合并提交不重复计数。
- Sumika：宽筛取得 142 个触及根包 Go 文件或依赖清单的提交，其中包含后台/ctl，不是“142 个界面提交”；27 个符合范围的 fix/revert，另加有明确返工证据的，共 28 个。
- MewTypeUI：57 个非合并提交，fix 11 个，全部纳入。
- 独立 mygo-m3e：3 个非合并提交，分别为 初始导入、 注释 ADR 号、 上游评估文档；没有 fix/revert。
- 主口径共 39 个返工提交。普通 feature、计划内组件迁移、升级与补测试不自动算返工。

M3E 是组件库研发支线。MewTypeUI `docs/architecture.md` §1 的设计调查记录当时 Sumika 的 go.mod 未引用 mygo-m3e；不能把这条支线全部试验成本理解成正式程序已经上线、再整体替换了一遍。

### 1.2 归因规则

归因依据提交正文、实际改动及任务/复盘，关键框架机制回源码核对。没有具体证据，不因为出现 bug 就自动加 e，不因为用了 Draw 就自动加 a。

| 类别 | 口径 |
|---|---|
| a | 已有合适组件/基础能力，却另拼一套 |
| b | 框架或组件库的行为限制、平台差异、缺功能；可与应用误用重叠 |
| c | 构建、身份、状态寿命、线程、回调/输入时序误用；也包括 UI 异步发布的取消代次，不等于全是过期 Element |
| d | 与需求、规格或实际使用中的参考不符；含文案。用户明确调整偏好也可能触发 d，不能全部读成 AI 理解错 |
| e | 有具体证据证明负载、时间、对象、分支或原生呈现验收不成立 |
| f | 布局约束、尺寸、比例、字体行框、坐标、裁剪、绘制几何错误 |
| g | 由依赖升级造成的适配返工，本批未找到这种因果关系 |
| h | 展示契约、资源、异步应用状态、颜色角色、普通应用逻辑，逐条说明 |

这是对历史记录的人工编码，有解释空间。可重算底账为 `classifications.csv` 与 `statistics.json`。

## 5. 框架本身：规模、资料、升级和限制

### 5.1 API 与资料有多大

实际 go list 返回 `<Go 模块缓存>/pkg/mod/github.com/egoist/mygo@v0.7.4`。

## 8. 如果继续用 mygo，要改什么做法

以下均为调查者建议 [INFERENCE]，本次未修改任何项目规则或代码。

1. **任务明确正文入口和固定源码。** Sumika、独立库及 worktree 都给 skill 的可访问入口；交回关键 API 实际来源。修正时序段与当前实现的不一致，目录可发现性不代替阅读，更不代替核对源码。不再新增一套泛泛长 skill。
2. **一个组件族、一个完整任务先验完。** 如转发中打开动图、嵌套返回、点遮罩只关一层，把可见区、取消和退场一起做完。初轮六路未验完集中到整合轮，已有直接返工证据。
3. **参考写关系和状态，不只抄数。** 区分画布、墨迹、命中区、字体行框、尾槽、悬停/选中、进退场/打断。替代图形保留自身比例，允许登记与官方轴差，不能为凑两轴把它拉扁。
4. **应用组合现成组件，底座缺口收在共用处。** 文字、对象、链接、选区共用排版，正文/转发/查看器不各算一套；RetainedBody 是正确方向，但当前预算仍需如实对待。
5. **逻辑、原生、参考各量自己的对象。** Tester 管逻辑/软件几何与时钟；真窗口管平台与 GPU；独立参考管是不是用户要的画法。不能只让实现和同一份可能抄错的 token 互相证明。
6. **验完再交回。** 沿用已有前台等待、按命令拿锁；未跑和超预算写未通过，用户不应成为每个普通交互的第一位测试者。
7. **小步升级并重评旧绕法。** 本批升级没迫使重写，非首要矛盾；但 IgnoreInput、ImageSize、动图能力出现后，应核对旧补丁是否已可删除。

成效看同一完整场景在目标尺寸/倍率、亮暗、真实顺序下是否满足视觉、状态和原口径性能预算，不看增加了多少规则和测试。

## 9. 如果换，这些原因还在不在

以下为 [INFERENCE]；本轮没有做新的同功能原型或开发效率对比。

| 原因 | React＋成熟库 | Flutter＋成熟库 | nsh/Rust＋TSX |
|---|---|---|---|
| a 没用现成组件 | 仍会发生，可选库更多但仍会选错/重造 | 同样，历史原型已发生 | 先核真实组件覆盖；有官方 skill 只帮助正确使用 |
| b 底层/平台限制 | 标准 DOM/弹层减少手画；Canvas 精确复刻仍有成本 | 成熟布局绘制减少补底座；自定义 paint 仍有字体/比例/裁剪 | TSX 不等于浏览器，需核文本、布局、DPI、窗口、GPU |
| c mygo 特有规则 | 替成 hooks 依赖、key、闭包、卸载取消 | 替成 Key/State、build 副作用、mounted、异步取消 | 替成自身运行时/所有权规则，仍需固定版本资料 |
| d 需求/参考不符 | 仍在 | 仍在 | 仍在，skill 不知道用户想要哪个画法 |
| e 错对象/目标验收 | DOM/截图/实际壳仍须区分 | Widget 测试不代替平台表面与 IME | 仍须真窗口闭环 |
| f 手工几何 | 标准组件少算一些；精确 Telegram/替代图形仍会错 | 成熟组件及热重载有利，自绘仍需独立量 | 取决布局/文字 API，不能凭示例下结论 |
| h 数据/应用状态 | 头像身份、转发元数据、取消/可见区仍在 | 同样 | 同样，除非重设计数据/状态契约 |
| 反馈循环 | 热更新、检查器和资料通常更方便 | 保状态热重载有历史收益 | 本轮未量，需同完整负载比较 |

换的价值前提是减少自己维护组件/绘制层、获得成熟组件与更短反馈循环。只把 Go 绘制语法改 TSX，同时继续自造整套组件、模糊参考、延后真窗口验收，前三类原因仍会留在项目里。
