### 四个工具的描述

| 工具 | 模型实际得到的说明 |
|---|---|
| `read` | 文件或目录；文本带行号；图像和 PDF 直接给模型；大文件分段读；优先一次较大读取，具体内容先 `grep`。参数写明 `offset` 从 1 开始、`limit` 默认且上限为 2000。 |
| `edit` | 保留缩进，不复制 `1: ` 行号前缀；解释 CRLF/LF；说明精确匹配、有限的宽容匹配、唯一匹配及 `replaceAll`。 |

| `grep` | 用途是定位代码、符号和文本；解释 ripgrep 正则和 literal；通过 `path`、`include` 缩小范围；参数含 glob 示例及大小写默认值。 |

1. **恢复链要测到成功。** 参数错 → 修改参数后成功；匹配重复 → 增加上下文后只改目标；内容变化 → 重读后成功；不能只断言错误里含“重读”。
2. **描述必须符合执行。** 验证 read 行号与截断、grep 默认上限、PowerShell 默认 120 秒和封顶 600 秒、edit 同一原文件多块替换语义。
3. **公开说明书跨渠道可读，私有能力不串。** 主窗口、QQ 主人私聊、群友触发分别抓完整请求和工具清单；QQ 不能靠“读帮助”变成读任意本机文件。
4. **缓存检查比完整前缀。** 未变更的旧消息、系统提示和工具声明保持稳定；第二轮只追加变化；插话、压缩重建、换权限档后分别检查。
5. **说明书入口要能独立使用。** 无源码 checkout、安装目录有空格/中文、离线、文档不存在、相对引用、`../` 越界都要覆盖。
6. **提醒检查触发与去重。** 正常闲聊不发 todo 提醒；用户停止后不自动继续；同参数但结果变化不按“无进展”提醒。

真实模型比较建议用现有提示作 A、候选提示作 B，同一模型和参数、同一批任务交替跑。先用主力 DeepSeek v4.1 flash，每题各跑三次；差异接近再用另一模型复核。任务至少覆盖：找文件、分段读取、重复匹配、重叠 edit、PowerShell 引号、超时、产品配置问答、QQ 无本地能力。测完成率、错误调用数、恢复成功率、总输入/输出 token、耗时和缓存用量；不要只测提示本身短了多少。**推断**；沿用现有真实模型验收口径：`S/docs/规格-Go后台.md:380`。

### 9.3 四个工具的中文描述候选

以下保持现有参数形状，不引入 selector、hashline、后台 job 等未实现协议。容量默认值沿用当前声明。依据：`S/native/internal/tools/declarations_gen.go:9`、`:11`、`:15`、`:16`。**推断**。

**read**

> 读取文件内容，支持文本和图片。需要查看已知文件时使用；查找文件名用 find，查找内容用 grep。文本最多返回 2000 行或 50KB，先到的为准。大文件用 offset、limit 分段读取；被截断时按结果提示继续。

参数说明：

- `path`：文件路径，相对当前工作目录或绝对路径。
- `offset`：开始读取的行号，从 1 开始；省略时从第一行读取。
- `limit`：本次最多读取的行数；返回量仍受总大小限制。

**edit**

> 在一个文件中替换一处或多处文本。先读取相关内容，把原文填进 oldText；不要带输出里的行号。所有替换都匹配调用开始时的同一份文件，每个 oldText 必须唯一，各处不能重叠。相邻或重叠修改合成一项，远处修改保持分开。匹配失败时先检查最新内容，不要原样重试。

参数说明保留 `purpose`、`path`、`edits[].oldText/newText`；`purpose` 继续用中文、30 字以内。不要新增 `replaceAll` 来绕开唯一匹配约束。参考 pi 的同一原文件多块协议和现有实现。出处：`P/dist/core/tools/edit.js:10`、`:22`；`S/native/internal/tools/declarations_gen.go:15`。**推断**。

**powershell**

> 在当前工作目录执行 PowerShell 命令，返回标准输出、错误输出和执行状态。专用工具能完成的文件读取、搜索和编辑优先用专用工具。每次调用都是新进程，上一条命令的变量和目录变化不会保留。默认超时 120 秒，最多 600 秒。输出超过 2000 行或 50KB 时保留末尾预览，并提供完整输出文件。超时或被停止后，先确认操作是否部分完成，再决定是否重做。

`timeout`：

> 超时秒数。省略或非正数时使用 120 秒，超过 600 秒按 600 秒执行。

这里如以后改参数校验为拒绝非正数，描述也要同步改，不能先写更严格的承诺。出处：`S/native/internal/tools/shell.go:34`。**读码确认 / 建议**。

**grep**

> 在文件内容中搜索文本或正则，返回路径、行号和匹配行。找文件名用 find。默认遵守 .gitignore、区分大小写，最多返回 100 个匹配或 50KB；长行会截断。先用 path 和 glob 缩小范围；找普通文本时可设 literal=true，避免把标点当正则。需要上下文时读取匹配位置。

参数应保留现有 `ignoreCase`、`literal`、`context`、`limit` 的真实含义，不混用 OpenCode 的 `caseSensitive` 或 omp 的 `case`。出处：`S/native/internal/tools/declarations_gen.go:11`；对照 `P/dist/core/tools/grep.js:11`。**推断**。

### 9.4 错误反馈改成“事实 + 执行状态 + 下一步”

参考 DeepSeek 的恢复链和 OpenCode 的歧义匹配反馈；不要为工具描述另建一套只改文案、不对应错误类型的规则。出处：`D/packages/fs/tool-fs/src/error.ts:21`；`O/packages/core/src/tool/plugin/edit.ts:281`。**推断**。

| 情况 | 建议反馈 |
|---|---|
| 参数错误 | `参数 timeout 无效：需要秒数。没有执行。请修改参数后重试。`——仅用于实际拒绝执行的校验错误。 |
| 文件不存在 | `找不到文件：…。请检查路径，或用 ls/find 确认文件位置。` |
| edit 找不到文本 | `没有找到 edits[1].oldText，没有写入。请重新读取相关片段，保留实际缩进和换行后再改。` |
| edit 多处匹配 | `edits[0].oldText 匹配了 N 处，没有写入。请增加能区分目标的上下文。` |
| edit 重叠 | `edits[0] 与 edits[1] 重叠，没有写入。请合并为一项。` |
| 只读工具超时 | 保留现有“缩小范围、少读一点、分步做”的建议。 |
| 执行类工具超时 | 保留已产生输出；说明可能部分执行，要求确认状态后决定是否重做。 |

只有实现保证未写入时，才能说“没有写入”。不能把“工具返回错误”统一翻译成“没有执行”；尤其超时、进程被杀和写后处理失败。Sumika 现有总超时提醒已经区分只读和有副作用工具，应保留。出处：`S/native/internal/turn/loop.go:697`、`:734`；`S/native/internal/turn/hub.go:1200`。**读码确认 / 建议**。

Crush 和 DeepSeek 的先读/版本检查值得作为以后文件修改稳健性的依据；本次不能把 Sumika 的“建议先读”写成已有的强制版本守卫。当前读到的 edit 错误主要是文本匹配反馈。出处：`C/internal/agent/tools/edit.go:283`、`D/packages/fs/tool-fs/src/edit.ts:125`、`S/native/internal/tools/edit.go:238`。**读码确认 / 建议边界**。
