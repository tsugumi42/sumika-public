# Sumika 界面设计规则盘点（只读，未改任何仓库文件，未运行构建）

## 结论

仓库里已经有不少设计规则，覆盖几何、令牌、层级、颜色、字阶、间距、状态、动效、文案和检查流程。但这些规则基本都在回答"东西怎么画"，没有回答"这种场景该用哪种页面结构和哪种组件"。主人说的分栏、网格、瀑布流、卡片流、设置列表这类选择，没有被映射到场景。另外，窗口断点、栏宽、圆角、列表选中样式等关键数值，文档之间互相矛盾，代码现行值也和部分文档不一致。

## 三、缺口（重点：没有"什么情况用哪种页面结构 / 组件"的决策指南）

- **G1 没有场景到页面结构的决策表**。现有只有主窗口四栏表（信息架构:24–29）和 1.4 页面骨架表（规格-交互原型:50–65），都只覆盖 5 个固定页面。没有任何一处说明：单列、双栏、三栏、详情页、全屏查看、卡片流、网格、瀑布流、分组折叠列表、设置页、统计页、插件页各在什么情况下用。待办也确认主人在等这份规则：docs/待办.md:71（"等主人写什么情况用哪种组件的规则"）和 :359（界面模式规范，未写）。
- **G2 没有数据形态到组件的映射**。设计语言 §八.3 到 §八.5 的"什么时候用"只针对组件本身（如 Table 用于运行页明细，Masonry 用于表情包和图片墙）。没有规则说明：同构的 N 条记录该用列表、卡片网格、表格还是瀑布流；记忆、学到的说法、表情包、群友、插件各该用什么。组件库清单 docs/archive/规格/组件库清单.md:80 只有一句"瀑布流 → 记忆、学到的、表情包"，是 Web 时代的计划。
- **G3 没有列表形态分类**。行、卡、网格、瀑布、分组折叠、卡堆审核（SwipeStack，见 设计语言 §一.8 和 组件库清单:86）在文档中都只是零散出现，没有一张"形态 × 用途 × 选中和悬停怎么做"的表。原型标注（docs/notes/原型-主人标注-2026-11-05.md 设置页段）明确写过"不能强制只用一种列表"，但没有规则说明哪种选项用哪种列表。
- **G4 没有卡片、行、气泡、块的判断规则**。索引 R023 只说"有独立对象或交互语义才是卡片"；设计语言 r-2 列了"工具卡片、普通卡片、弹出卡片"，没有使用清单。
- **G5 没有浮层选择规则**。设计语言 §二 列了层级，但没有说明：哪种操作用菜单、弹出卡、确认框、侧边面板、还是全屏查看。Sheet 只说 floating 与否（设计语言:324）。
- **G6 设置页没有"选项类型 → 控件 / 列表样式"映射**。规格-交互原型 1.4 写了"精确优先加模糊候选"，原型标注写了"不同选项有不同展示"，设计语言 §八.4 有 Slider、NumberField 等控件，但没有映射表。缺口盘点 docs/archive/规格/界面缺口盘点.md:72–82（同类同级但不统一、分类不明确）说明 Web 时代已出现这个问题。
- **G7 状态处理没有按页面类型的模板**。只有通用状态（索引 R071–R073）和"空、错、加载要有"的要求（设计自查:23），没有"每种页面的空态文案和下一步"的模板。
- **G8 没有"窗口宽度 → 哪些栏可见 → 哪些页面变层"的单一表**。见 C2。一张表都没有，导致代码和文档各写一套。
- **G9 过程、工具、审批的组件族没有总表**。散在 ADR-281、286–288、设计规格第四、五节。设计语言 §8.1 只有叠层规则，没有过程气泡、工具卡、审批卡的组件表。
- **G10 mygo 侧没有可检查的设计一致性清单**。mygo-ui SKILL 的五项验收管的是行为、几何、帧耗时，不管"用的是不是规定的那种结构"。设计自查 §五第 18 条依赖的 check-census 脚本已随 Web 退役（docs/设计自查.md:41、:44–55）。
- **G11 同类不统一的问题没有防回归机制**。缺口盘点列出的 Web 时代问题（标题三套、小图标按钮三种尺寸、空状态八种写法、卡片家族重复、列表行高 26–56）都是"没有通用 token 或没有统一规则"造成的。mygo 新界面没有对应检查。
- **G12 数据可视化的结构规则只在 Web 时代**。设计语言 §八.5（ChartCard、StackedBars 等）是 Web 组件，mygo 侧未见图表规则。
