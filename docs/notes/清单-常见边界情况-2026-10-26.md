# 清单：常见边界情况（从两周的修复记录里整理，2026-10-26）

> 起因：主人 2026-10-26："我更希望你能够自己去发现这些边界的情况……一开始尽量多考虑一些实际情况里面会经常出现、反馈比较多的那种情况"。
> 来源：2026-10-12 以来 1241 个提交的标题和正文（号码、群名先打了码，少数纯数字的提交号也被误打成了【号码】）、LESSONS.md、docs/待办.md；Sol（codex/gpt-6.1-sol，经 omp，只读）整理，主会话抽查了 20fc2fe1、447d97e7、e565ffec、97a71b4a 四个提交，都对得上。
> 用法：写规格的"已知的坑"、写测试之前，按总表的"动手前问自己"过一遍和这次改动相关的几类；新踩的坑归进对应的类，次数往上加。

统计按“每类中的不同提交”去重，同一提交修了两类边界会分别计入。另发现打码文件把少数纯数字提交号也替换成了“【号码】”；这些记录只能用日期和标题定位，不能还原哈希。反复出现的问题会区分“同一现象连续补修”和“不同功能踩同一种坑”。
**最常漏的不是某个特殊输入，而是“正常条件只成立了一半”：数据到了但页面没更新、消息发出但回包没到、取消了但旧任务还活着、同一个角色却处在不同会话。**

统计口径：

- 次数按**不同提交记录**计，同一提交在同一类只计一次；涉及多类边界的，分别计入，所以各行不能相加当作总修复数。
- 只计标题或正文明确体现边界问题、修正行为的提交；普通新增功能、纯调研、重复记载同一次修复的文档不另计。以下是**本次确认的保守计数**，不把关键词命中数当作事故次数。
- `LESSONS.md` 和待办用于补充背景、检查未解决的同类问题，不把同一问题再加一次。历史修复不代表当前已彻底解决。
- 打码误伤了少数纯数字提交号；此类记录按日期、标题区分。表中优先列可辨认的哈希，每类最多 8 个。

**2．每类展开：实际发生过什么**

**① 布局遇到尺寸、嵌套、缩放和主题变化。**  
这类问题是局部样式在理想尺寸下成立，组合进真实页面后失效。

- `20fc2fe1`：窗口在 821～845 宽时，图文气泡已经缩小，图片仍固定 320 宽，伸出气泡并被闸门标记压住。
- `41300e9b`：浮层挂到 `body`，离开 `.su` 的样式作用域，字体、盒模型、滚动条等基础样式全部失去。说明“组件本身正确”还不够，要验证它实际挂载的位置。

**② 文本的表示和变换会互相影响。**  
这类问题不是“字符串里有奇怪字符”，而是多个合法写法与处理步骤组合后破坏不变量。

- `ae5775af`：`好。\n。` 清一遍和清两遍不同，导致实例历史、存库文本与实际发送文本不一致。
- `388b6977`：文件尾部剩半个 UTF-8 字符，收尾用了另一个解码器，字符被悄悄丢掉；预期行为应是替换字符。
- 对此最有用的检查是：**清两遍等于清一遍；未命中部分保持原样；分块处理与整段处理一致。**

**③ 测试依赖了偶然样本，或通过条件不能证明目标。**  
这类边界发生在验证本身：测试绿了，实际没有覆盖所声称的行为。

- `a2d4cbd7`：在本地页按旧快捷键，然后断言“还在本地”，无论快捷键是否失效都会通过。
- `d205f29c`：检查直接点第一个 QQ 会话，后来最新会话变成私聊，测试仍等群聊专有元素。
- 待办还记录了造数据缺少“两角色同群、闸门标记、识图结果”，所以量不出真实群聊的滚动问题。

**④ 生命周期结束后，异步工作没有一起结束。**  
这类问题是“对象已经失效，任务却还持有它”。

- `74c60159`：分段回复尚未发完就关闭插件，第二段发送失败后又访问已经收掉的服务，错误甚至被算到下一个测试头上。
- `b863a3de`：插件关闭时没有清掉退避定时器，关闭以后又拉起 Python。
- 待办里的 plan-bar 收尾 EBUSY 与这类问题相邻，但其具体根因仍未确定，不能直接判成同一个 bug。

**⑤ 状态归属维度不够。**  
这类问题是原本只支持一个对象的状态，被直接拿来支持多个对象。

- `447d97e7`：停止或释放一个会话，按角色取消审批，连同角色另一个会话正在等的审批一起取消。
- `bc4f3b74`：两个角色都判断同一条群消息，前端只按消息序号保留第一条，另一个角色的结论被覆盖。
- 四种场合必须分开；“群聊”不能自动等同于“有外人”，本地群聊与 QQ 群的规则确实不同。

**⑥ 权限判断与执行对象不一致。**  
这类问题是授权检查漏掉了资源的真实身份、调用入口或范围。

- `9031d318`：检查把 `~\.ssh\config` 当作工作目录下叫 `~` 的目录，工具执行却会展开到用户目录，受保护路径检查失效。
- `b081f380`：批准过删除某个目录后，同类灾难性命令去删另一个盘，也被直接放行。
- `9352f75a`、`254f6821` 还说明：按钮禁用不能替代接口端的状态约束。

**⑦ 上限计算遗漏了对象，或取错了那一段。**  
这类问题是预算存在，但限制的集合、顺序或单位不对。

- `aaacbd89`：超过两万次模型调用后，正序 `LIMIT` 留下最早两万条，最新调用反而看不到。
- `c7fc0bbe`：转发展开的 1500 字预算只扣普通文字，不扣卡片标题、文件名和 @ 名称。
- `9e25aa2f`：最近 30 个事件不等于 30 条可用聊天；通知、没说出口的内容和本轮重复追加项占掉了名额。

**⑧ 数据到达与可用之间还有阶段。**  
这类问题是把占位、接口成功或局部完成当成最终完成。

- `050f5d73`：识图等待到点后，不管图是否看完都保存 `seen`，“还没看清”被永久写死。
- `14f7bad3`：接口已经恢复出厂，页面还没重画，检查立即读取编辑器，读到旧内容。
- 图片加载、列表测高、会话列表返回和 DOM 重排都属于同一类阶段差异。

**⑨ 交互必须考虑转换中的状态和事件归属。**  
这类问题不是静止截图能看出的，需要检查操作前后及中间帧。

- `4794c95a`：关看大图时立即卸载，已有退场样式没有机会执行。
- `cdc05879`：识图详情里的输入框正在打字，背后的看大图仍响应方向键和 `+ - 0`。
- `d29e306d`：Windows 输入法结束后补发一次普通回车，原有 `isComposing` 守卫没有拦住，可能误批准审批。

**⑩ 失败前可能已有成果，失败后也可能有迟到结果。**  
这类问题需要保留部分结果，并选择正确的重试单位。

- `9a79df18`：头像刷新失败，却释放旧图并更新刷新时间，导致已有头像长时间 404。
- `66a1cab2`：十条审核结果中一条格式坏了，整个批次不动，之后不断挑中同一批，重复花钱。
- 待办还保留“再看一遍失败会覆盖好描述”，说明旧好结果的保护尚未处处成立。

**⑪ 一份业务事实在不同位置变成不同口径。**  
这类问题是局部计算各自合理，合起来却互相矛盾。

- `b47ab1ac`：发送前兜底清理覆盖了已有 `segments.original`，所谓“原话”变成了中间处理结果。
- `1b8b8f78`：明细有缓存写入和思考 token，14 天后汇总时没带上，两项数据随明细清理而消失。
- `b4856679`：文件编号超过 `2^53`，普通数字丢精度，去重把不同文件当成同一个，统计少算。

**⑫ 运行环境是输入的一部分。**  
这类问题来自工作目录、URL 编码、平台 API、命令行版本及打开方式。

- `e565ffec`：SQLite URI 的路径含 `#`，后面连 `mode=ro` 一起被截掉，只读打开竟可能变成创建可写库。
- `d2046b82`：同一段 JSON 参数在 PowerShell 5.1 和 7 的引号传递不同，两份说明需要相反的转义写法。
- `ab2e06e9` 的盲评页也说明：本机文件存在，不代表用户从应用内打开页面时能访问。

**⑬ 并发需要验证具体交错，不只是“同时跑很多次”。**  
这类问题常出现在检查状态与修改状态之间。

- `97a71b4a`：两句话同刻到达，都看到实例没在输出，一起进入；后一轮覆盖接收端，前一轮回复存库却没发到 QQ。
- `be786e20`：补录还没填完洞，实时新消息先到，把“最后一条”推到洞后面，之后永远补不到缺口。
- `92a30a2f`：两个角色同时改同一个文件，各读到旧内容，后写入覆盖先写入；需要按真实文件身份排队。

**⑭ 更新不可能总是原子完成。**  
这类问题发生在新旧前后端、旧页面资源、复用实例和旧持久化记录之间。

- `a67ca46f`：前端已打包、后台未重启，新字段不存在，直接读 `.length` 使整个设置区崩溃。
- `d8cf0348`：重新打包删掉旧分包，已打开页面仍按旧文件名加载，失败后整个窗口白屏。
- LESSONS 还记录过提示词先换格式、后台仍用旧解析器，27 张识图结果全部被拒绝；这条是两端更新时序的直接证据，不另把 LESSONS 记载加一次。

**⑮ 真实语言会撞破人工规则。**  
这类问题是把示例、子串或少量样本误当成通用语义。

- `eb17e497`：昵称 `ro`、`te`、`seek` 被 `pro`、`test`、`deepseek` 命中，英文别名需要词边界。
- `94110c04`：单字说法被“至少两个字”过滤，“草”“唉”等真实表达大量误判。
- `51eeaa63`、`c7b2f760`：模型把“敬礼＝收到”“插不上话”等提示词例子当成固定答案，到处套用。

**⑯ 少量、空值与非法值有独立语义。**  
这类问题最容易被只造“正常的几条数据”的测试漏掉。

- `5df1b437`：新群只有一两条消息，列表装得下一屏，第一项一直是 0，没有状态变化，永远触发不了加载历史。
- `c86cfcfc`：全员禁言的 `user_id=0` 被当成真实群成员，显示“0 被禁言”，还查询 0 号资料。
- `2d42ed37`：一个坏字段让整份预设选择作废；而缺失、`null`、空串和数字在原实现中并不是同一种回退含义。

**⑰ 其他。**  
这些记录有明确修正，但没有足够证据把它们说成某种业务边界。

-：上一提交只误建空角色卡，这次补上内容；它首先是交付遗漏。
- `3742ea38`：修类型错误又引入变量重名；`e31ea61e`：重构后遗漏一处调用，把时间戳函数源码打印成文件名。
- 日期写错、报告误述检查输出也放这里，不冒充“时区 bug”。

**⑱ 兼容协议不等于实际契约相同。**  
这类问题必须对具体协议端、资源服务和版本验证。

- `9c398d5b`：给 SnowLuma 传了 NapCat 的翻页参数，不报错，但每次返回最新一页，历史翻不下去。
- `7f83fb45`：里层转发依赖协议端先取外层建立内存缓存；协议端重启后，本地缓存的外层反而使这一步被跳过。
- `535a03ea`：一个地址 404 并不能证明图片过期，换正确的群图地址还能取到。

**⑲ 缓存必须明确复用内容与失效条件。**  
这类问题同时有“该保留的丢了”和“该更新的没更新”。

- `4c920e09`：设置了会话标识，不代表请求实际带了 `prompt_cache_key`；真实调用只命中网关自己的固定前缀。
- `4dd1ff7e`：实例复用只比较角色卡版本，不比较提示词和预设，网页已保存，下一轮仍使用旧内容。
- 待办中 QQ 群仍发现改提示词未立即换上的实例，说明不能只凭私聊路径通过就宣称所有场合生效。

**⑳ 时间有时区，也有精度和采样时刻。**  
这类问题不只出现在显示日期时。

- `e981aef1`：JS 与 SQLite 的日期口径不同，测试只在本地 0～8 点把同一天拆成两天。
- `52be8cc3`：影子回放把时刻写成 UTC，第一次 55 句全部不同，改成 `+08:00` 才对上。
- `93c80e10`：结果目录只精确到分钟，同一分钟连跑两遍，后一遍覆盖前一遍。

**㉑ 隐私保护会被复制、改名和旁路结构绕开。**  
这类问题不一定发生在最终聊天输出。

-：配置改名成备份文件后，原先只匹配原文件名的忽略规则失效，含令牌文件出现在待提交列表。
- `01aa9775`：最终聊天内容没进仓库，抽样脚本和规格却写进真实群名。
- 待办里的记忆正文携带 QQ 号，是同类未完成事项：结构化字段脱敏，不代表正文也安全。

**4．这个项目最容易漏的三类**

1. **异步阶段、并发与生命周期交错。** 收消息、识图、回合、审批、发送、补录各有自己的完成时刻，而代码多次把某一阶段完成误当成整件事完成。
2. **状态归属与四种场合的差异。** 单角色、单会话能用后，名字、颜色、审批、记忆和闸门仍不断暴露少一维的问题，待办中也还存在同类缺口。
3. **真实组合条件下的界面与验证。** 窄窗口、多角色、图文混排、晚到高度和真实数据经常同时出现，单独组件、静止截图及简化假数据无法覆盖这些组合。
