## 1. OpenCode v2

### 1.1 抓网页

模型工具 `webfetch`：

| 项目 | 当前实现 |
|---|---|
| 参数 | `url`；`format=text|markdown|html`，默认 `markdown`；可选 `timeout`，大于 0、最大 120 秒 |
| 默认超时 | 30 秒 |
| 响应上限 | 5 MiB；声明长度或实际流超过上限都报错 |
| HTML 转 Markdown | 自己用 `htmlparser2` 写转换器，不是 Turndown |
| 文本转换 | `htmlparser2` 收集文本，跳过 script/style 等活动内容 |
| 编码 | `new TextDecoder().decode(body)`，此处没有按响应 charset 选解码器 |
| PDF、图片 | 拒绝；测试明确把附件支持留到有类型化结果以后 |
| UA | `Mozilla/5.0 ... compatible; OpenCode-User/1.0; +https://opencode.ai` |
| 缓存 | 此工具与正文收集函数内未找到跨请求正文缓存 |

出处：`OC/packages/core/src/tool/plugin/webfetch.ts:14`、`:24`、`:60`、`:128`、`:145`；`OC/packages/core/src/tool/http-body.ts:4`；`OC/packages/core/src/tool/html-markdown.ts:1`、`:50`；`OC/packages/core/test/tool-webfetch.test.ts:592`。【读码确认；缓存为限定范围的查找结果】

转换器保留标题、列表、引用、代码、表格、链接、图片引用等结构；隐藏子树会被压掉，跨行跨列表格退成按行文本。它不是正文抽取算法，`nav/header/footer` 仍在普通块元素集合里。出处：`OC/packages/core/src/tool/html-markdown.ts:3`、`:24`；`OC/packages/core/test/tool-webfetch.test.ts:389`、`:397`、`:411`。【读码确认】

### 1.2 SSRF、重定向与审批

- 只校验 HTTP/HTTPS；请求前按最初 URL 调 `permission.assert`。出处：`OC/packages/core/src/tool/plugin/webfetch.ts:72`、`:117`。【读码确认】
- **明确允许 localhost**。测试名就是 `accepts localhost URLs with the same requested-URL permission check`。不能把它描述成公网安全抓取器。出处：`OC/packages/core/test/tool-webfetch.test.ts:455`。【读码确认】
- 跟随重定向，测试明确说明“只批准请求的 URL”。已读代码中没有逐跳公网地址检查、DNS 固定。出处：`OC/packages/core/test/tool-webfetch.test.ts:472`；`OC/packages/core/src/tool/plugin/webfetch.ts:76`、`:117`。【读码确认】
- 遇到 `403 + cf-mitigated: challenge` 时，改成 UA `opencode` 再请求一次；普通 403 不重试。出处：`OC/packages/core/src/tool/plugin/webfetch.ts:63`、`:130`；`OC/packages/core/test/tool-webfetch.test.ts:610`、`:633`。【读码确认】
- Agent 默认权限含 `webfetch/websearch allow`；仍经过权限服务，配置可改成询问或拒绝。出处：`OC/packages/core/src/plugin/agent.ts:85`；`OC/packages/core/test/config/agent.test.ts:189`。【读码确认】

系统说明仍有“遇到跨主机重定向提示就再抓新 URL”的文字，但当前工具测试证明会自动跟重定向。**应以实现和测试为准，不能据这句说明认定存在跨主机拦截。**出处：`OC/packages/core/src/plugin/system-prompt/meta.txt:51`；`OC/packages/core/test/tool-webfetch.test.ts:472`。【读码确认】

### 1.3 网络搜索

当前注册了 **Exa、Firecrawl、Parallel、Tavily、TinyFish** 五家搜索插件。不是旧版“只有 Exa”。出处：`OC/packages/core/src/plugin/websearch/index.ts:1`。【读码确认】

三层已经分开：

1. 工具 `websearch({query})`。
2. `WebSearch.Service` 管提供方选择、会话偏好和限流冷却。
3. 各插件实现请求与结果转换。

统一结果含 `url`、可选 `title/content`、可选发布日期，发布日期用 Unix 毫秒。出处：`OC/packages/core/src/tool/plugin/websearch.ts:23`；`OC/packages/core/src/websearch.ts:35`、`:57`；`OC/packages/schema/src/websearch.ts:23`。【读码确认】

Tavily 适配器固定：

```text
POST https://api.tavily.com/search
search_depth: basic
chunks_per_source: 3
max_results: 8
timeout: 25 秒
```

有 key 用 Bearer；没 key 用 `X-Tavily-Access-Mode: keyless`；带 `X-Client-Name: opencode2`。返回 `title/url/content`。这个 keyless 接法是 OpenCode 的具体集成，不能据此假定 Sumika 也可免 key。出处：`OC/packages/core/src/plugin/websearch/tavily.ts:8`、`:50`、`:59`、`:72`。【读码确认／推断】

第一次未选提供方时会向用户征求搜索许可，可选择一家、禁用，或允许自动选择。自动选择并非每次乱换：维护会话偏好，429 时按 `Retry-After` 冷却并尝试别家；未提供有效冷却时间时默认 60 秒。显式选定一家时不走这个自动切换。出处：`OC/packages/core/src/tool/plugin/websearch.ts:67`、`:121`；`OC/packages/core/src/websearch.ts:142`、`:184`、`:224`。【读码确认】

### 1.4 不可信内容与用量

搜索正文直接拼成 Markdown 标题、链接、内容；抓取结果直接返回转换后的正文。**在这两个工具的输出函数里没找到专门的不可信内容前缀或边界包装。**出处：`OC/packages/core/src/tool/plugin/websearch.ts:146`；`OC/packages/core/src/tool/plugin/webfetch.ts:150`。【读码确认；仅限已查输出路径】

在 `WebSearch.Service` 和 Tavily 适配器中找到的是返回条数、请求超时、429 冷却，未找到按用户／日／金额的本地预算。429 冷却不是消费上限。出处：`OC/packages/core/src/websearch.ts:93`、`:184`；`OC/packages/core/src/plugin/websearch/tavily.ts:59`。【读码确认／推断】

## 2. Crush

### 2.1 两条抓取路径

Crush 同时有普通 `fetch` 和搜索子代理里的 `web_fetch`，限制不同。

| 项目 | 普通 `fetch` | 子代理 `web_fetch` |
|---|---|---|
| 参数 | `url`、必填 `format=text|markdown|html`、可选 `timeout` | 只有 `url` |
| 超时 | 默认客户端 30 秒；参数最大夹到 120 秒 | 默认客户端 30 秒 |
| 网络读取上限 | 100 KiB | 5 MiB |
| 大结果 | 转换后再截到 100 KiB | 超过 50,000 字节写临时 Markdown 文件，提示用 view/grep 读 |
| HTML 转换 | `html-to-markdown`；text/html 模式另用 goquery | 先删噪声元素，再用 `html-to-markdown` |
| 编码 | 非 UTF-8 报错 | 非 UTF-8 报错 |
| UA | `crush/1.0` | 固定 Chrome 120 浏览器 UA |
| 审批 | 调用 `permissions.Request` | 内层工具不逐次审批 |

出处：`CR/internal/agent/tools/fetch.go:20`、`:44`、`:80`、`:99`、`:118`、`:134`、`:141`；`CR/internal/agent/tools/web_fetch.go:24`、`:51`；`CR/internal/agent/tools/fetch_helpers.go:20`、`:46`、`:54`；`CR/internal/agent/tools/fetch_types.go:12`、`:26`。【读码确认】

普通 `fetch` 的可选 120 秒不代表真能等 120 秒：默认 `http.Client.Timeout` 仍是 30 秒，两者取先到者。出处：`CR/internal/agent/tools/fetch.go:51`、`:103`。【读码确认／推断】

转换库实际依赖是 `github.com/JohannesKaufmann/html-to-markdown v1.6.0`。子代理清理 `script/style/nav/header/footer/aside/noscript/iframe/svg`；这比直接转 HTML 干净，但也会误删放在这些元素里的有效正文。出处：`CR/go.mod:15`；`CR/internal/agent/tools/fetch_helpers.go:81`。【读码确认／推断】

### 2.2 边界与安全

- 普通 `fetch` 只做 URL 字符串的 HTTP/HTTPS 前缀检查；默认客户端没有自定义 `CheckRedirect` 或固定 IP 的 `DialContext`。子代理 helper 也直接 `client.Do`。在这两条路径中未找到公网地址校验或逐跳重查。出处：`CR/internal/agent/tools/fetch.go:44`、`:71`、`:121`；`CR/internal/agent/tools/fetch_helpers.go:25`、`:36`。【读码确认】
- 两条路径都 `io.LimitReader` 后直接读，没有多读 1 字节判断“刚好到上限”和“真的超限”。子代理 helper 没返回截断标记。普通路径在转换后才判断长度，可能把网络阶段已经截断的 HTML 当成完整转换结果。出处：`CR/internal/agent/tools/fetch.go:134`、`:185`；`CR/internal/agent/tools/fetch_helpers.go:46`。【读码确认／推断】
- 普通路径按字节切字符串，转换后截断没有再保护 UTF-8 边界。出处：`CR/internal/agent/tools/fetch.go:186`。【读码确认】
- 两条路径都只接受 HTTP 200。没有看到 PDF 提取或图片解码分支；不能把 PDF／图片按字节读入描述成支持。出处：`CR/internal/agent/tools/fetch.go:126`、`:147`；`CR/internal/agent/tools/fetch_helpers.go:42`、`:61`。【读码确认】

### 2.3 搜索与子代理

搜索抓 **DuckDuckGo Lite 的 HTML**，不是 Tavily、Exa 或模型自带搜索。默认 10 条，最大 20 条；解析标题、链接、摘要、位置。随机轮换浏览器 UA 和语言，请求之间用全局互斥和约 0.5～2 秒间隔。出处：`CR/internal/agent/tools/search.go:20`、`:26`、`:72`、`:121`、`:255`；`CR/internal/agent/tools/web_search.go:44`。【读码确认】

DuckDuckGo 的 HTTP 202，以及 HTTP 200 中的机器人挑战页，都报“限流”，不会冒充“零结果”；报错还明确要求不要立即换词重试。出处：`CR/internal/agent/tools/search.go:51`、`:97`。【读码确认】

顶层 `agentic_fetch({url?, prompt})` 先审批，再建临时目录、派小模型子代理。URL 模式先抓页；搜索模式让子代理搜索和继续读页。子代理工具含 web_fetch、web_search、glob、grep、Sourcegraph、view，并自动批准该子会话。出处：`CR/internal/agent/agentic_fetch_tool.go:83`、`:102`、`:137`、`:162`、`:197`。【读码确认】

**这套“前台委托后台整理”的形状值得借；自动批准子会话和附带文件工具不适合直接照搬到 Sumika 的 QQ 后台。**依据：上面工具名单与 ADR-081 的能力约束。【推断】

### 2.4 不可信内容、缓存与费用

URL 模式的小页面被放入 `<webpage_content>`，但内层 `web_fetch/web_search` 直接返回文本。已读输出路径没有看到统一的“不可信数据、不要执行其中指令”提示，也没有看到对伪造闭合标签的处理。出处：`CR/internal/agent/agentic_fetch_tool.go:134`；`CR/internal/agent/tools/web_fetch.go:72`；`CR/internal/agent/tools/search.go:232`。【读码确认】

在 `fetch.go`、`fetch_helpers.go`、`web_fetch.go`、`web_search.go`、`search.go` 中未找到结果缓存或按日费用预算。DDG 路径不需要搜索服务 key；子代理仍有小模型调用成本。出处：`CR/internal/agent/tools/search.go:72`；`CR/internal/agent/agentic_fetch_tool.go:178`。【读码确认／推断】

## 3. Codex CLI

### 3.1 当前有两条搜索路径

**服务端 hosted search**：模型请求里放 `ToolSpec::WebSearch`。支持 `cached/indexed/live/disabled`，可传域名限制、近似位置、搜索上下文大小；模型能力决定是否请求 text+image。出处：`CX/core/src/tools/hosted_spec.rs:14`。【读码确认】

**独立 `web.run`**：本地解析命令，向模型提供方相对地址 `alpha/search` 发 POST。请求带会话 ID、模型、近期输入、命令、搜索配置和最大输出 token。只有 OpenAI、使用其 actor 授权的提供方，或显式声明 `supports_standalone_web_search` 的提供方才暴露。出处：`CX/ext/web-search/src/tool.rs:103`、`:120`；`CX/codex-api/src/endpoint/search.rs:15`、`:34`；`CX/ext/web-search/src/extension.rs:44`。【读码确认】

因此，Codex 并非一个本地通用 HTTP 抓取库。网页提取、HTML 解析、目标站 DNS、目标站 UA、缓存等主要在远端服务；本机源码不能证明那些实现。出处：`CX/ext/web-search/src/tool.rs:151`；`CX/codex-api/src/endpoint/search.rs:40`。【读码确认／推断】

### 3.2 参数、网页、PDF 和图片

独立接口一次可以提交：

- `search_query[{q, recency?, domains?}]`。
- `open[{ref_id, lineno?}]`、`click`、`find`。
- PDF `screenshot[{ref_id,pageno}]`。
- `image_query`。
- `response_length`。
- 另有天气、金融等结构化操作。

这些是本地协议支持，**不等于本次已经验证服务端各能力可用**。出处：`CX/codex-api/src/search.rs:31`、`:73`、`:84`、`:110`。【读码确认】

工具没有 OpenCode 式的 `format` 和每次请求 `timeout` 参数。输出 token 上限取工具调用的截断预算；返回的正文由服务端给出。出处：`CX/ext/web-search/src/tool.rs:120`；`CX/codex-api/src/search.rs:9`。【读码确认】

默认配置解析回落到 `Cached`；权限关闭等场景还有按轮选择模式的逻辑，不能说“所有情况下永远 cached”。`cached` 是远端检索模式，不是本地 URL 缓存。出处：`CX/core/src/config/mod.rs:3981`、`:3213`；`CX/ext/web-search/src/extension.rs:91`。【读码确认／推断】

### 3.3 安全、不可信内容与预算

- 独立 executor 中没有逐次询问目标网页的审批步骤；端点访问仍走 Codex 的 API 网络路由，集成测试会验证托管网络策略能禁止搜索端点。出处：`CX/ext/web-search/src/tool.rs:103`；`CX/core/tests/suite/code_mode.rs:530`、`:552`。【读码确认】
- 不能从本地的 API 端点安全策略，推导远端抓取已经逐跳防 SSRF；本次未找到远端实现。出处：`CX/codex-api/src/endpoint/search.rs:34`。【推断】
- `SearchOutput.contains_external_context()` 返回 true；当启用 `memories.disable_on_external_context` 时，内核把会话标成受外部上下文污染。实际交给模型的正文仍是服务端字符串，这里没有额外套标签。出处：`CX/ext/web-search/src/output.rs:26`、`:30`；`CX/core/src/tools/registry.rs:1063`。【读码确认】
- 已读搜索接口有输出 token 控制，没有找到按人、群、日的消费预算。实际套餐和搜索单价不在这些代码里，不能由源码确定。出处：`CX/codex-api/src/search.rs:9`；`CX/ext/web-search/src/tool.rs:127`。【读码确认／未查明】

## 4. omp

### 4.1 网页归入 `read`

当前网页入口是 `read({path})`，URL 可带行号范围和 `:raw`；不是另一个供模型调用的传统 `fetch({url,format,timeout})`。URL 分支交给 `fetchReadUrl/executeReadUrl`。出处：`OMP/src/tools/read.ts:806`、`:1760`。【读码确认】

| 项目 | 当前实现 |
|---|---|
| 超时 | `fetchReadUrl` 取 30 秒基值，再经工具超时配置夹取 |
| 网络读取 | 通用 `loadPage` 默认 20 秒、50 MiB；上层会传自己的 timeout |
| 预览 | 默认最多 300 行，另过通用字节上限；超出保存 artifact，供继续读 |
| 编码 | HTTP charset 优先；HTML／未知类型可嗅探前 2 KiB 的 meta charset；不认识则回 UTF-8 |
| 重定向 | 通用 loader 使用 `redirect: "follow"` |
| UA | curl、TextBot、Chrome 依次尝试；部分拒绝状态换 UA；最后的 429 可等待后再试一次 |

出处：`OMP/src/tools/fetch.ts:1718`、`:1794`；`OMP/src/web/scrapers/types.ts:40`、`:42`、`:107`、`:137`、`:155`；`OMP/src/web/response-body.ts:6`。【读码确认】

超时要注意范围：通用 loader 给每次尝试单独建 timeout；读取页、站点适配、格式探测和后备转换可能增加请求。不能把“30 秒基值”直接当成所有后备路径共享的严格墙钟上限。出处：`OMP/src/web/scrapers/types.ts:117`；`OMP/src/tools/fetch.ts:1108`、`:617`。【读码确认／推断】

### 4.2 HTML、PDF、图片与缓存

HTML 转换默认顺序：

```text
native → trafilatura → lynx → Parallel → Firecrawl → Jina
```

还有站点专用 scraper、`.md`／LLM 友好地址探测、内容协商等路径。因此不能把 omp 简化成“Turndown 抓网页”。Turndown GFM 确实用于部分 scraper 的基础转换，但通用首选是 native。出处：`OMP/src/tools/fetch.ts:253`、`:298`、`:324`、`:1141`；`OMP/src/web/scrapers/types.ts:229`。【读码确认】

### 6.2 本地 HTTP 抓取

默认 5,000,000 字节、100,000 字符、30 秒、5 次重定向。出处：`DS/packages/web/web-fetch-http/src/index.ts:45`。【读码确认】

安全链：

1. URL 最长 2048，HTTP/HTTPS，禁止 URL 用户名密码。出处：`DS/packages/web/web-fetch-http/src/policy.ts:12`、`:25`、`:49`。【读码确认】
2. 解析完整 DNS 答案集；任一地址非公网即拒绝。IPv4-mapped IPv6 按内嵌 IPv4 分类。出处：`DS/packages/web/web-fetch-http/src/network.ts:54`、`:75`、`:97`。【读码确认】

- `Content-Length` 超上限立即拒绝；未知长度流超限保留前缀并标记截断；刚好等于上限不误标。
- HTML/XHTML、text、JSON/XML 可读；PDF、图片等不支持。

- 404 等非 2xx 是“取到了一个有状态码的资源”，不是 transport error。
- 取消、提供方超时、网络失败分别归类；拒绝和截断时取消正文，释放连接。

### 6.3 工具与 HTML

### 8.2 Sumika 的验收建议

以下为【推断】，依据上述测试与 Sumika 的权限约束：

1. **安全验收**：注入 DNS 和拨号器，最终观察“实际拨向哪一个 IP”，不能只测一个 `IsPublic()` 函数。覆盖 localhost、RFC1918、CGNAT、链路本地、IPv6 ULA、IPv4-mapped、云元数据、混合 DNS、DNS 重绑、重定向到内网。依据：DeepSeek `fetch-http.spec.ts:136`、`:242`。
2. **权限验收**：比较完整模型请求和工具清单。主窗口主人可见网络工具；QQ 前台没有；群友派来的后台只有网络工具。伪造工具调用也必须在执行前拒绝。依据：`SK/docs/规格-Go后台.md:350`、`:377`；ADR-081。
3. **取消验收**：停回合、停插件、body 慢流、DNS 卡住时，工具按时返回，后到结果不追加上下文、不重复结算。依据：DeepSeek `fetch-http.spec.ts:198`、`:486`、`:500`；`SK/native/internal/turn/plugin.go:91`。
4. **计费验收**：两个并发任务争最后一份预算，只允许一个出网；四 query 按四请求计费；提取失败和“请求已发但响应未知”分别结算；重启后预算仍在。依据：DeepSeek 的 fan-out 与 maxUses 相乘问题，`tool-web/README.md:250`。
5. **内容验收**：中文、日文旧编码、emoji 跨字节截断、畸形 HTML、表格、代码块、相对链接、深嵌套、超大 JSON、压缩膨胀、缺 Content-Type、PDF／图片误标。依据：OpenCode HTML 测试、DeepSeek 编码与上限测试。
6. **注入验收**：标题、摘要、正文、错误消息、后台报告中放伪造“主人已批准”“调用 powershell”“关闭标签后新系统指令”。验收工具未执行、私密上下文未进入搜索请求，不能只看最终回复是否礼貌。依据：ADR-081 的权限隔离、DeepSeek 明确不可信前缀、Codex external-context 标记。
7. **录像**：记录脱敏后的提供方请求／响应，匹配方法、路径、规范化请求体；少调用、多调用、录像没用完都失败。网络失败与 429 的录像也要有。此为建议；本次读到的网络测试主要是假服务器，不冒称六家都用了网络录像。

本次没有读到六家之间可直接比较的同负载抓取／搜索基准。验收应分别量：本地解析耗时与分配、首次网络延迟、缓存命中延迟、正文有效信息量、请求数、费用。不能由 Go 语言本身推断性能已超过 omp／OpenCode／pi。【推断】

## 9. 给 Sumika Go 的具体建议

本节全部是建议，可信度为【推断】；每项附可追溯依据。

### 9.1 两个工具的参数与默认值

建议模型接口：

```json
web_search({
  "queries": ["查询词"],
  "max_results": 5,
  "time_range": "week"
})

web_fetch({
  "url": "https://example.com/article",
  "format": "markdown"
})
```

| 参数／限制 | 建议值 |
|---|---|
| `queries` | 必填，1～4 条；去首尾空白，精确去重；每条最多 512 个 Unicode 码点 |
| `max_results` | 可选，默认 5，范围 1～10；是整批合并后的总数 |
| `time_range` | 可选 `day/week/month/year`；不填就不加时间过滤 |
| `url` | 必填，仅绝对 HTTP/HTTPS，最多 2048 字节 |
| `format` | 可选 `markdown/text`，默认 markdown |
| 模型可调超时／提供方 | 不暴露；由服务端配置 |
| 搜索整批 deadline | 默认 30 秒，配置硬上限 60 秒 |
| 抓取整次 deadline | 默认 30 秒，配置硬上限 60 秒 |
| 本地响应正文 | 解压后最多 5 MiB；多读 1 字节识别超限 |
| 提供方 JSON | 解压后最多 5 MiB；错误体最多 8 KiB |
| 搜索交给模型 | 总共最多 12,000 码点，每来源摘要最多 1,000 码点 |
| 抓取交给模型 | 默认 12,000 码点，配置最大 50,000 码点；显式标截断 |
| 全局在途网络请求 | 起步 4；单后台任务 2；两者可配置 |

依据：DeepSeek 的小工具接口、多 query 合并和部署超时；omp 的短摘要；OpenCode／DeepSeek 的约 5 MB 网络上限。上述数值是 Sumika 起步建议，不是抄来的行业统一标准。出处：`DS/packages/web/tool-web/src/search.ts:19`、`:258`；`DS/packages/web/tool-web/src/fetch.ts:1`；`OMP/src/web/search/index.ts:78`；`OC/packages/core/src/tool/html-markdown.ts:50`。

不提供 `html` 模式：首个 Tavily Extract 本来只支持 Markdown／text；工具不需要暴露执行脚本、cookie、自定义请求头或 POST。普通网页引用和图片链接可以保留，但不自动下载页面里的图片。依据：Tavily Extract 官方接口；OpenCode 在有附件类型前明确拒绝二进制，`tool-webfetch.test.ts:592`。

### 9.2 Tavily 首个适配器

搜索固定请求建议：

```json
{
  "search_depth": "basic",
  "topic": "general",
  "chunks_per_source": 2,
  "include_answer": false,
  "include_raw_content": false,
  "include_images": false,
  "include_usage": true
}
```

`max_results` 取本次受服务端限制后的值；`time_range` 有才发。不启用自动提深度，也不在零结果后偷偷去掉时间条件重试。依据：OpenCode basic 接法；omp 将 recency 与 news 分开的经验，但不借其自动放宽时间约束。出处：`OC/packages/core/src/plugin/websearch/tavily.ts:59`；`OMP/src/web/search/providers/tavily.ts:75`、`:228`。

抓取发 `/extract`，单 URL，basic，指定 format，`include_images:false`、`include_usage:true`。上游提取超时建议 20 秒，外层总时限 30 秒，留出网络和解析时间。必须检查 `results` 与 `failed_results`；HTTP 200 也可能没有任何成功结果。依据：[Tavily Extract 官方接口](https://docs.tavily.com/documentation/api-reference/endpoint/extract)。【读文档作为依据】

**不要伪造原网页 HTTP 200、最终 URL 或完整性。**Tavily 服务响应成功只代表提取服务处理成功。它没给原站状态，就返回 `origin_status:null`；没承诺最终地址，就保留请求 URL 和提供方返回 URL 两个字段。依据：DeepSeek 直连适配器的合成状态陷阱，`DS/packages/web/web-deepseek-api/src/fetch.ts:22`、`:45`。

官方当前计费：

- basic Search 每请求 1 credit；advanced 每请求 2 credits。
- basic Extract 每 5 个成功 URL 1 credit；advanced 每 5 个成功 URL 2 credits；失败提取不收费。
- 免费档每月 1,000 credits；按量价当前为每 credit 0.008 美元。
- Extract 的 `usage.credits` 可能暂为 0，因为累计成功提取尚未满 5 次。

依据：[Tavily Credits & Pricing](https://docs.tavily.com/documentation/api-credits)、[Extract 接口](https://docs.tavily.com/documentation/api-reference/endpoint/extract)。【读文档；价格属于当前文档，不写死为永久单价】

### 9.3 Go 三层接口

建议保留两个小能力接口，不把所有服务的参数铺到模型 schema：

```go
type SearchProvider interface {
    ID() string
    Available() bool
    Search(context.Context, SearchRequest) (SearchResult, error)
}

type FetchProvider interface {
    ID() string
    Available() bool
    Fetch(context.Context, FetchRequest) (FetchResult, error)
}
```

分工：

- **工具层**：校验模型参数；按调用者权限进入服务；包装不可信文本；输出预算。
- **服务层**：选提供方、整批并发和去重、deadline、缓存、用量预留与结算。
- **提供方层**：密钥、HTTP 协议、响应解析、上游限制与实际用量。
- **本地 HTTP transport**：专门负责 URL／DNS／拨号／逐跳限制；不复用“可以访问本机模型服务或 MCP”的宽松客户端。

依据：DeepSeek `web/src/types.ts:102`、`web/src/index.ts:140`；其固定 IP 网络只用于公开抓取、不套到所有程序网络访问，`web-fetch-http/src/network.ts:177`。

结果建议统一保留：

```text
provider、request_id、sources/title/url/snippet/published_at
requested_url、returned_url、origin_status（可空）
content_kind（html/markdown/text）、content
truncated、truncation_reason、usage
```

不要强求 provider answer、发布日期和原站状态，缺了就缺了。`html/markdown/text` 要区分，避免把 Tavily 已经转换过的 Markdown 再转一次。依据：DeepSeek 可选 source 字段、统一正文类型，以及其直连 Markdown 适配。出处：`DS/packages/web/web/src/types.ts:50`、`:94`；`DS/packages/web/web-deepseek-api/src/fetch.ts:45`。

配置显式选 `search_provider:tavily`、`fetch_provider:tavily`。缺 key 清楚报错，不自动转 DDG、模型搜索或另一付费提供方。依据：DeepSeek 明确选择规则比随机候选链更易控制费用和数据去向，`DS/packages/web/web/src/index.ts:176`。

### 9.4 防 SSRF：具体实现边界

**本地 HTTP 提供方应做到以下链条；给 Tavily 发 URL 也先做本地 URL／地址预检，但不能声称已控制 Tavily 的远端拨号。**

1. `net/url` 解析，限定 HTTP/HTTPS；拒绝 userinfo、IPv6 zone、非法端口、控制字符。规范化域名时做 IDNA；不接受 Windows 路径、UNC、`file:`。URL fragment 不发给服务端。依据：DeepSeek `policy.ts:25`。
2. 默认只开放 80/443。其他公网端口只能由本地主人配置；localhost、`.localhost`、`.local`、单标签内网名直接拒绝。此为 Sumika 额外收紧，避免公网抓取变成任意端口探测。
3. 用 `net.Resolver.LookupNetIP` 取 A/AAAA，`netip.Addr.Unmap()` 后检查全部结果。**不能只用 `IsPrivate()` 或 `IsGlobalUnicast()`**；另拒绝回环、链路本地、CGNAT、未指定、多播、保留／基准／文档等非公网地址及云元数据目标。依据：DeepSeek 用完整地址分类而非仅 RFC1918，`network.ts:54`、`:97`。
4. DNS 任一答案不允许，整组拒绝；空答案、解析失败不放行。处理 IPv4-mapped、IPv6 过渡／翻译地址；支持 NAT64 时必须检查映射后的 IPv4，否则该类地址先拒绝。依据：DeepSeek `network.ts:87`、`:114`。
5. 自定义 `http.Transport.DialContext`：对原域名解析、检查，然后只拨验证过的数字 IP；保留原请求 Host，TLS 仍验证原域名。**校验完成后不能再按域名拨一次。**依据：DeepSeek `network.ts:191`、`:268`。
6. 使用手动重定向循环；关闭客户端自动跟随。只跟同源，最多 5 跳；每跳重查 URL、地址、预算与剩余时间。跨源返回明确的新目标，由下一次工具调用重新进入权限和预算。依据：DeepSeek `provider.ts:67`、`:89`。
7. 不带 cookie、Authorization、系统登录凭据；URL 输入不能决定 API key、代理或提供方 base URL。产品 UA 建议 `Sumika/<version>`。依据：DeepSeek `provider.ts:1`、`:119`。
8. `Proxy:nil`，不要自动吃环境代理。代理专门由主人配置；代理无法证明远端解析／地址约束时，严格公网模式拒绝走该路径，提示改用 Tavily。不要照 DeepSeek 代理分支跳过域名检查后仍标称完整防护。依据：DeepSeek 的代理例外，`provider.ts:125`。
9. 传输共用受限连接池；新建连接都走受限拨号。总 deadline 覆盖 DNS、连接、响应头、body、转换；解压后的正文另计字节上限。依据：DeepSeek 取消覆盖完整请求与正文，`provider.ts:58`、`:191`。

Windows 上的 Clash／Mihomo fake-IP 可能让公网域名解析到保留地址。应明确报“受限地址／代理解析不兼容”，不要为可用性把整个保留网段放开。此项本机代理行为未实测，列入验收而非既定事实。【推断】

Tavily Search/Extract 的 API endpoint 是受信配置，不是模型参数；Bearer 请求禁止重定向到别的端点，避免凭据跟随跳转。模型传入的 URL 即使预检通过，远端后续重定向和 DNS 仍由 Tavily 控制；这是明确的外部服务信任边界。依据：DeepSeek 外部 API 适配器使用 `redirect:"error"`，`web-search-exa/src/provider.ts:108`。

### 9.5 HTML 用哪个 Go 库

**建议本地转换先选 `github.com/JohannesKaufmann/html-to-markdown`，以本次实际读到的 v1.6.0 为可核实基线；解析与字符集处理用 `golang.org/x/net/html`、`html/charset`。**依据：Crush 已在 Go 生产路径使用该转换器，`CR/go.mod:15`、`CR/internal/agent/tools/fetch_helpers.go:150`。【推断】

具体处理：

- charset 按 HTTP 声明、BOM／HTML meta 处理；未知明确编码报错，不悄悄乱码。
- HTML parse 后删 script/style/template/iframe/object/embed 和隐藏子树，再转换。
- 不一概删 header/footer/nav：文档页和文章正文可能在这些节点；若要正文模式，单独评估正文抽取，不拿标签删减冒充 Readability。
- 相对链接以最终 URL 解析；Markdown URL 限定可展示协议。
- 给输入字节、DOM 深度、节点数、输出码点都设上限；超限返回可解释错误或截断标志。
- PDF、图片报明确的能力不支持；不把二进制当 UTF-8 解码。

依据：Crush 的 Go 库接法与粗略删噪声，DeepSeek 的 charset／隐藏内容／深度保护，OpenCode 的转换边界测试。出处：`CR/internal/agent/tools/fetch_helpers.go:81`、`:150`；`DS/packages/web/tool-web/src/fetch.ts:31`、`:244`；`DS/packages/web/web-fetch-http/src/policy.ts:118`。

本次没有读取该 Go 库 v2 的源码或跑基准，故不把“v2 更快／更完整”作为选型事实。Tavily 首个适配器拿到的已经是 Markdown，此库只用于本地 HTML 提供方，不增加一次无用转换。【推断】

### 9.6 用量上限放服务层

**硬预算放 Web 服务层；上游实际计量由提供方层交回；子代理只分配任务预算，不能另开一个不受约束的通道。**

原因：工具调用数、搜索 query 数、上游请求数、原生服务端搜索数、credit、模型 token 是不同计量单位。DeepSeek 的 4×5 就证明只限返回来源不够。依据：`DS/packages/web/tool-web/README.md:250`。

建议：

- 维度：发起人、群／会话、平台、提供方账号、全局；全部额度同时满足才派发。归属使用可信渠道事件里的原始发起人，子代理重派不改归属。依据：ADR-081／082，`SK/docs/决策记录.md:747`、`:759`。
- **出网前原子预留**最大可能消费，完成后按实际结算；HTTP 已发但超时未知的调用留作待核对，不能马上全额退回。并发限额不能“先调用、后加计数”。
- Tavily 内部用整数微 credit，或分别计 search 请求和成功提取数；不要把 Extract 的暂时 `credits:0` 当免费。
- 服务端自动重试、换提供方、模型服务端多次搜索都消耗同一份任务预算；初始默认不自动换付费方、不自动重试计费请求。
- 达限返回 `WEB_BUDGET_EXCEEDED` 和可恢复时间；后台停止查网，前台可说明“本次额度到了”，不提示模型想办法绕过。
- 账本持久化。缓存命中不记上游 credit，但仍受权限与频率限制。

以上实现建议依据 ADR 的多维限制、DeepSeek fan-out、omp 的多候选与二次搜索路径。出处：`OMP/src/web/search/index.ts:238`、`OMP/src/web/search/providers/tavily.ts:228`。

起步参数建议：QQ 每人每天 20 次搜索、40 个提取 URL；每群每天 60 次搜索、120 个提取；QQ 平台每天 100 次搜索、200 个提取；共享 Tavily 账号按自然月 900 credits 硬停，给免费档留余量。全部可在主窗口改。**这些是待采用的起步建议，不是已定额度；主人主窗口的显式研究任务可用单独配置，但不能绕过账号全局硬预算。**依据：ADR-082 数值不写死；Tavily 免费档 1,000 credits/月。

### 9.7 插件、QQ 和缓存

- 编译内置 Web 插件，`Setup` 经 `OnTool` 注册两个工具；先给 `policy.Specs` 增加联网类别、时限和可并行声明。不能只注册名字，也不能把 `net` 冒充 `self`。现有 `Audience:"any"` 的语义注释是 self，新增 QQ 后台需要扩展策略表达。出处：`SK/native/internal/policy/policy.go:17`、`:62`；`SK/native/internal/turn/plugin.go:249`。【推断】
- `ToolCall` 当前有角色、会话、turn、听众，没有可见的“子代理身份／原始发起人／委托预算”字段。接 QQ 后台时需要可信执行身份，而不是让模型参数带 `is_owner`。`For(Audience)` 只能在现有 policy 放行后收紧，不能突破 owner-console 限制。出处：`SK/native/internal/turn/plugin.go:85`、`:96`。【读码确认／推断】
- QQ 前台只有派活入口；后台只有 web_search/web_fetch，不给本地 read、shell，也不给能定位本地文件的 artifact 路径。后台报告保留来源 URL、不可信属性和截断状态，不能升级成系统指令。依据：ADR-081、Crush 的委托形状及工具名单差异。
- 搜索不放进 `OnContext` 自动执行。`OnContext` 最多追加说明或已完成任务通知；真正网络请求走工具。网页正文、搜索结果、后台报告都只在历史末尾追加，不回改旧前缀。依据：`SK/docs/规格-Go后台.md:341`；`SK/native/internal/turn/plugin.go:37`。【推断】
- 建议服务层成功结果内存缓存：搜索 TTL 5 分钟，抓取 TTL 10 分钟，总容量 16 MiB；键包含提供方、凭据作用域、权限档和全部结果参数。相同在途请求合并；一位等待者取消不应取消其他等待者。缓存命中前仍做当轮授权。此为起步建议，主要为减少重复费用和延迟。
- 不把 QQ 群友任务与主人私密任务共用可枚举结果空间；本地缓存页不向 QQ 暴露文件系统路径。依据：规格要求按权限档分实例，`SK/docs/规格-Go后台.md:350`；omp artifact 是本地编码场景，不宜直接移植到 QQ。
