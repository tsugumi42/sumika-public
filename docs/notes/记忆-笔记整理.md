## 一、先说结论（给赶时间的人）

1. **权限是第一层，价值判断排第二。**（24、25、22、44）先确定"此人/此群当前有权知道什么"，再决定记什么、记起什么、怎么说；"权限否决高于价值评分"；检索**之前**过滤，不靠让模型"忽略"；所有读取路径（检索、回放、日志、注入面板、摘要、联网搜索词、子 Agent）走同一个检查。
2. **一条记忆要同时带三种东西：来源、范围、时间。** 来源（source_room、audience_at_origin、speech_act、是否转述/引用）、范围（谁能用、用于什么、是否被要求"别再提"）、时间（发生时间、写入时间、valid_from/invalid_at、被谁推翻）。Sumika 现在有来源（source_seqs）和一档粗的范围（三档可见性），**时间只有 status**，是最大的缺口。（01、03、24、25、10-04 双周研究 LAPSE）
3. **记忆写入不是"总结一遍然后存"，是一次分类决策。** 先判语用事件（自述/承诺/边界/态度/引用反讽/共同事件/谣言），再从固定动作表里选（忽略、只留工作记忆、待定、存片段、更新事实、设交互规则、撤销），不让模型自由改所有层。硬触发（边界、纠错、删除、约定）立即生效，其余按事件量批量整理。（25；评估页已采纳）
4. **事实、观点、推测、转述、玩笑要分开存；"据 A 说 B……"不是 B 的事实；摘要和画像只是视图。**（01、03、06、25、22）
5. **多模态：描述不是事实。** 识图结果拆成"可观察的"和"解释的"，只有通过复核的描述才进长期记忆，人名/作品名必须有外部证据，发现错了要能级联撤销。（35、28）

## 二、分维度汇总

每条后面括号里是出处：基础/扩展编号 + 短标题。"现状"指 Sumika 目前文档里写的。

### 2.1 空间维度：作用域、可见性、隔离、共享

**笔记的结论**

- **四个独立问题**：记忆真不真 / Bot 访问过没有 / 用户对 Bot 说过没有 / 现在能不能对当前受众说。同一人属于两个群不等于两个群的内容能互通。（扩展 24｜跨群、私聊与多人关系的信息边界）
- **八层判断"能不能谈"**：主体、来源和最初受众、现在的听众（@A 不等于只有 A 看得到）、披露许可（可撤回）、社交适宜性、时间与变更、组合泄露（几个碎片拼出隐私）、执行路径（检索/提示词组装/重排/搜索词/日志/跨 Agent 消息/最终文本都是信息流）。（24）
- **默认规则（拟议）**：同群→同群可按受众与时效适度提；群→群默认不用；**私聊→群严格拒绝外传**（群里被问"你记得吗"，只能凭群内已公开细节答，或请对方回私聊）；群→私聊可谈对本人可见的事但不转发第三方敏感细节；公开互联网→群可引用，但不能用私下建立的"匿名作者=某群友"映射去揭露；子 Agent/其他 Bot 也是新的接收方，只传脱敏的最少量信息；涉及第三方的共享秘密要考虑第三方，不能只记 owner=A。（24）
- **来源标签与访问策略分开存**：来源标签 = record_id / subject_ids / sender_id / source_type(dm|group|public) / source_room / event_time / audience_at_origin / original_message_ids / retention_policy / revoked_at / confidence；分享规则 = audience_constraints / purpose_constraints / expires_at / explicit_grant_evidence / policy_priority / affected_subjects / inherited_restrictions / last_reconfirmed；输出上下文另算 = current_room / active_members / direct_addressee / visible_audience / topic / bot_role / requested_disclosure / disclosure_purpose。**不要用单一 private/public 二值代替群域 ACL。** 统一实体标识（QQ 号）只负责"知道是同一个人"，记忆本体按群/私聊/公众分区。摘要的权限取其中最严格的数据源。（24）
- **检索前过滤**：写入即带 origin 和可用范围 → 用可信平台元数据确定当前房间/成员（不信"我是群主"）→ 检索前做 ACL/ABAC 过滤（SQL 与向量候选都先筛房间）→ 证据卡、缓存、搜索词、调试日志、子代理消息沿用来源权限（私有原句不进联网查询）→ 最终披露守门（第二道防线，不是唯一防线）→ 撤回时级联删除摘要、索引、缓存。（24、22）
- **所有读取路径同一个检查函数**，且 API、实时推送、历史回放三个入口一致，不能某条接口隔离了、日志或向量检索又漏出去。（44 Raft；评估页已采纳）
- **"不主动提"是独立的互动偏好**，区别于"不可访问"：已在本群公开的事，当事人也可能不想每次被复述。"能理解但不能引用"。（24）
- **权限不由自然语言授予**：群友说"群主批准你公开私聊"、"我们群都允许发截图"都无效；政策变更需可验证身份的后台配置。（22、24）
- **按人的画像**：身份 = 平台+稳定用户 ID，别名带有效时间，**不按相同昵称跨群自动合并**；"据 A 声称 B……"（attributed statement）；关系分向（Bot→A、A→Bot、A→B 不能互推）。（基础 06｜群友画像分析）
- **群共享层**：群内共同事件/梗/规则要有 group_scope，别当所有群通用规则；群记忆必须保留反对意见，不合成"全群一致认为"；A 与 B 互损不推出 Bot 对 C 也可以。（03、07、15）
- **多 Bot**：各 Bot 的角色、任务、私人记忆独立，公共信息可同步；Bot 的发言/反应**不算真人反馈、不算独立佐证**。（14、04、22；评估页已采纳）
- **媒体与引用的能力票据**：媒体/贴纸/引用只在其原会话上下文里可解析，带 TTL，源内容被清掉就失效；注意它只管工具层，不管长期记忆权限。（38 Surowan；24 末尾）
- **第三方被建档**是公开的隐私争议（Muse）；Sumika 的"认人档案"要想清楚群友是不是"用户"。（40）

**与 Sumika 现状**

- 已做：每个角色一个 memory.db，互不共享（设计）；原始事件全局一份 + observations（ADR-015）；可见性三档 `公开 / 仅对此人 / 私密`，`canSee` 是唯一入口，组装群聊提示词只放公开 + 属于当前说话人的"仅对此人"（设计）；`recall_raw` 只搜 observations；公共知识层所有角色共享（ADR-012）；本地群聊"每个角色只看自己的，并按主人×控制台×这个群的成员过滤"（规格-插件第七节）。
- 部分做：只有"主人×控制台"这一种场合真正实现；群聊/QQ 私聊的过滤是设计，代码层只在第一阶段验证过主人场景（subsystems/memory.md）。
- 没做：source_room / audience_at_origin、按群的 ACL、第三方共同持有、"不主动提"、撤回级联到摘要/向量/缓存、联网搜索词过滤、组合泄露审查、attributed statement、关系分向、别名有效期。

### 2.2 时间维度：多种时间、有效期、被推翻、遗忘

**笔记的结论**

- **至少三种时间**：发生时间（event_time）、观察/写入时间（observed_at）、有效期（valid_from / valid_to 或 invalid_at）。再加 temporal_scope（正在/暂时/曾经/计划/已停止）和 certainty。（01、03、25、10-04 双周研究）
- **LAPSE 的发现**：现成的记忆写入器（mem0、Graphiti、Letta 等）会把"正在、暂时"压成长期事实（381 对句子，3 个 writer 对进行时句出现 244 次单向压平）。所以 schema 不能只有 content + updated_at，摘要文本本身也要保留"目前/曾经/计划/已经停止"。（10-04 双周研究｜LAPSE，arXiv 2609.36457）
- **被推翻**：新信息推翻旧信息时建 supersede 版本链，保留旧事件对应的历史有效期，而不是覆盖；"上月不喜欢恐怖游戏、本月玩了恐怖游戏"只证明玩过，当前偏好待确认，旧事实保留。（01、06、03）
- **检测冲突是难点**：TWIST 基准里 flat-RAG 抓到 76–97% 真矛盾但把 16–43% 安全草稿误标为冲突；保守系统几乎不误报但只抓约 42%。建议 20–50 条本地小测试（superseded 旧事实是否仍覆盖当前状态、无冲突是否乱报警、跨项目串召回、时间条件）。（10-04｜TWIST）
- **遗忘**：论文把"遗忘/追踪过期"算作记得好的一部分（Memora：长程系统经常重复用已失效或被推翻的记忆）；MemoryAgentBench 把选择性遗忘与检索、在线学习分开评测。（25）ChatLuna 的 EMGAS 有随时间衰减与剪枝，HippoRAG 有 TTL 和过期清理，但"真实可用性需要样本测试"。（45）MaiBot 旧行为学习有"用进废退"：冷却、衰减、失败 ≥3 次且分数低于门槛可禁用。（37）
- **计划/约定过期后**：过期的计划不再是当前约定，但历史事件仍可能值得存成经历；临时情绪不升为常态。（25）
- **使用侧的时间**：玩笑/称呼/仪式要记 last_bot_used、最近一次谁发起、当前疲劳、冷却；被明确叫停立即停止，不等冷却。（27）
- **内容时效**：转发的帖子/截图要带真实发布时间，两年前的公告不能当今天的更新。（13）
- **反刍时间尺度（候选参数，论文没证明）**：立即（边界、纠错、"别再提"、撤回、时间敏感约定）→ 10–60 分钟按消息簇事件量触发 → 每天聚合 episode、引用校验、冲突梳理 → 每周或证据够时归纳群规/偏好/共同梗，保留反例；定期清理，随时可撤销。评估页：**这些周期只是候选值，实现时实测再定。**（25；评估页）

**与 Sumika 现状**

- 已做：facts 有 `status`（active/candidate/superseded/revoked）、`superseded_by`，更新只追加不覆盖；检索时间加权 `×(1 + 0.2·e^(−天数/30))`；快速通道写入"下周三考试"类约定；每日维护"去重 / 矛盾检查 / 过期，默认只报告不删"（设计③）；会话安静 10 分钟或 40 条触发总结。
- 没做：valid_from / invalid_at / temporal_scope / certainty / observed_at 字段（现在只有 status 和 source_seqs 对应的消息时间）；摘要提示词里保留时间语义的要求；L1/L2 的 TTL 状态；真正的遗忘/衰减（现状的时间加权只加分，不会让旧记忆降级或退场）；使用侧的 last_used/冷却；周/日不同周期的反刍；冲突检测测试。

### 2.3 数据分层与流水线

**笔记的结论**

- **01 的六层**：Raw event log / Working state（目标、约束、计划、进度；任务结束生成 checkpoint）/ Episodic / Semantic / Procedural（经验证的流程，保留反例）/ Belief-hypothesis（推断，不升级为明确事实）。**摘要只是索引与派生，不能替代原文。**（基础 01）
- **25 的 L0–L5**：L0 权限内原始事件与引用锚点 / L1 在线工作记忆（秒–数十分钟）/ L2 事件候选与临时重要状态（分钟–小时，带 TTL、provisional）/ L3 情景 Episode（小时–天）/ L4 持久语义、群规范、操作经验（天–周，要多次证据或明确可靠声明）/ L5 可审查的高层反思（周期，标支持与反例，可撤销）。同一条信息在不同层有不同用途，物理存储可共用。（扩展 25）
- **知识 / 行为 / 表达是三个互不取代的学习闭环**，加上长期记忆共四条线：知识告诉她 A 喜欢什么，行为告诉她 A 吐槽时是安慰还是接梗，表达告诉她怎么说。HippoRAG/EMGAS 这类解决的是提取/结构化/检索/遗忘，不自动解决"玩笑接错了"的归因。（29、45）
- **真相源与索引分离**：canonical 数据保持人可读、可备份，FTS/向量/图都是可重建的派生层，坏了重建；本地 store 要 checkpoint、restore 前 integrity_check、迁移失败回滚。（10-04｜MEX、TRW）
- **MemFit 的结构**：每个 turn 原样追加，segment summary 只做索引不替换原文，写入阶段不调 LLM；读取时再组合 BM25 + dense + PRF + cross-encoder（论文称写入阶段 LLM 调用减少 81–87%，代价移到读取侧；没有 10 万/100 万条的实验）。（10-04）
- **三种记录分区**：调试日志（短期，无正文）/ 原始事件（唯一事实来源，一份）/ 模型调用审计（最贵最敏感，默认短期）；共享原始事件 ≠ 共享角色记忆；每个 Bot 另记 observations 和 memory_operations（含 revoked_at）。（34；ADR-015 已采纳）
- **总架构的职责顺序**：接收媒体 → 视觉事实检查 → 权限范围内检索背景 → Planner 决策 → Replyer → 可观察结果 → 经审查的经验/记忆更新；统一接口 SourceEvent → MediaEvidence → AuthorizedMemory → ActionChoice → OutboundMessage → OutcomeEvent → LearningCandidate。（29）
- **行为经验用 sidecar，先只记录不学习**：episode（group_scope、thread_id、trigger_message_ids、role_state、bot_action、whether_adopted、subsequent_evidence_ids、feedback_interpretations、uncertainty、policy_version）→ learned_policy（scene_predicates、permitted_actor_and_audience、suggested_action、expected_effect、evidence_for/against、confidence、failure_modes、last_used、usage_cooldown、enabled）；反馈强弱：明确纠正 > 明确赞同 > 非明示参与变化 > 沉默；先离线回放评测、可人工撤销。（37、基础 04）
- **交互偏好策略**与画像分开存：policy_id / scope(user|group) / condition / preferred_behavior / avoided_behavior / evidence_ids / source_type(explicit|observed|inferred) / valid_from,to / contradictory_examples / overrides；优先级：当前明确请求与群规 > 历史明确偏好 > 多次低风险观察 > 角色默认。（基础 05）
- **群画像 / 群规范 / 仪式**各是独立的小结构，都带 evidence_ids、样本数、不同发言者数、反例、置信度、expiry。（15、07、27）

**与 Sumika 现状**

- 已做：原始事件（events.db）→ observations → 总结（episodes）→ 长期记忆（facts）→ 认人档案（people，仅建表），对应笔记 L0/L3/L4 的主体；记忆服务可替换（ADR-010 之后 `memory.ts` 的接口）；FTS/向量是派生层可重建；三种记录分开（ADR-015/026）；`candidate` 状态相当于 Belief/待定；公共知识层（ADR-012）有"四档可信度"（主人确认 / 随口答 / 群里学到 / 网上查到）。
- 对应但不同：笔记的 Working state / L1/L2，在 Sumika 里被"上下文纪元快照"部分承担（规格-插件第七节），但规格明确"压缩不是第二套记忆系统，摘要不写回长期记忆"。
- 没做：Procedural 记忆、L5 反思、行为 episode 与策略、交互偏好策略（现在只有 facts 的 preference/boundary 两种 kind，无 condition/scope/overrides）、群画像/群规范/仪式、图/实体桥接（ADR 评估页决定推迟）。

### 2.4 写入时机与重要性

**笔记的结论**

- **先辨语用事件，不按长度/情绪打分**：自述事实 / 未来承诺 / 互动边界 / 态度观点（只作当轮情绪）/ 引用代言反讽 / 多人共同事件（关系只记候选）/ 虚构事实或恶意教梗（重复出现 ≠ 真）。（25）
- **重要性分九项判断**，不是一个分数：即时行动/风险、未来再利用价值、变化与新颖性（**推翻比重复更值得检查**）、自述可信度、时效性、群内共享程度（刷屏不算多主体佐证）、场合/权限（**权限否决高于价值评分**）、角色关联、不确定性与错误固化代价。没有通用阈值。（25）
- **动作集**：ignore_for_long_term / working_only / hold_candidate / save_episode / upsert_fact / set_interaction_policy / update_prior / retract_or_delete；不让自由文本模型随意改动所有层。（25；评估页已采纳，Sumika 的 `upsert_fact | candidate | revoke` 是其子集）
- **写入流程**：先存原始事件 → 判断是否值得提取（明确状态/偏好/事实变化优先于闲聊）→ 结构化候选，在作用域和时间内查已有条目，分"新增/修正/暂存/忽略" → 来源核对（直接陈述 > 可信多次佐证 > 模型推测；笑话、引述、假设句默认不生成强事实）→ 推翻则建版本链；撤回级联清理派生。（01）
- **信任序**（写入门槛）：平台元数据 > 管理员确认的政策 > 用户对自己的明确陈述 > 多次独立观察 > 单人单次声称 > 外部未验证评论 > Bot 自己的推断；同来源刷屏要去重；个人偏好不由他人投票覆盖；重大事实或规范改写需独立佐证、可靠来源或当事人同意。（22）
- **写入时的反例**："好烦，一百字骂手游公司"长期偏好低；"以后别叫我这个外号"字很少但立即进互动政策。（25）
- **去重**：exact hash → FTS 近重复候选 → 小范围语义/LLM 判断；别全库 O(N) cosine。（10-04｜Memori）
- **行为/表达学习的写入**：先记 episode，不自动学；归因要先确认 Bot 真的采用了该行为（旧 MaiBot 的做法），不确定输出空；抽象不能太宽，要带禁用反例。（37、04）
- **何时触发总结**：以事件量触发比固定"每条调用一次"更划算；MaiBot 旧行为学习是被上下文裁切触发（聊天少则不触发）。（25、37）

**与 Sumika 现状**

- 已做：快速通道（构思时发现明确事实或约定当场写入）；后台总结：安静 10 分钟或新增 40 条触发，输出 `{episode, ops[]}`，ops 只能是 `upsert_fact / candidate / revoke`，zod 校验不合法整批丢弃；事实、观点、推测、玩笑分开存（设计）；总结提示词排除"我是 AI、没有记忆"的套话（LESSONS）；`remember` 工具给角色用。
- 没做：语用事件分类（speech_act）、九项重要性、信任序/source_type、独立佐证去重、写入时的"修正/暂存/忽略"四分、hold_candidate 的 TTL、"设交互规则"这个动作（现在 preference/boundary 在 facts 里）、行为 episode。

### 2.5 检索与注入

**笔记的结论**

- **中文检索**：FTS5 unicode61 对连续中文不是真分词；trigram 对 1–2 字词不友好；建议写入/查询统一用中文 bigram 或预分词（或自定义 tokenizer）；先把 BM25 + project/type/time 硬过滤 + 精确实体 boost 调好，向量只在词法低置信、跨语言、同义改写时补；融合用 RRF 或 rank merge，不直接加 BM25 与 cosine 原始分数。（10-04）
- **规模数据**（Memori，Apple M4 Pro）：FTS5 10 万条 1.49 ms，50 万 7.5 ms；暴力向量 10 万 172 ms，50 万 904 ms；10 万条库约 425 MB，100 万约 4.15 GB。10 万级先到瓶颈的是向量扫描。（10-04）
- **检索拆开评测**：候选召回 → 重排 → 覆盖优先的证据包 → 最终回答，LLM 只当 reader；分别记 candidate recall、rerank 后 recall、最终注入、最终回答；完整保留错误链路 raw → candidate → retrieved → injected → answer。（10-04｜Auditable LTM；基础 01）
- **回查原文**：候选摘要命中 → 原始消息 span 回查 → 对比来源/时间/状态 → 回答；检索信心不足回读原始日志，仍不能确认就答"不知道"。（01）
- **要不要检索，用廉价外部特征门控**（陌生词、时效、新梗变体、链接截图、直接 @、对抗语言），不靠模型自报不确定性；社会歧义或权限问题要保守而不是去搜；静态常用梗、本周新梗、本群特殊用法分开缓存、不同失效。（19）
- **并行预取**：许可范围内的记忆检索、候选梗召回、媒体元信息可与"想不想接"并行，用不上就丢。（33）
- **提旧事前四问**：有语境关联吗？证据属于当前群可公开信息吗（不跨群/私聊偷带）？旧事还有效吗、会不会让人尴尬？没把握就不引用。偶尔"你之前好像提过"需要真实来源。（03、24）
- **注入去重与版本**：辞典条目带 id + revision，在保留的上下文里检查 id+revision 防重复注入，更新或被清走后可再注入；以不可信文本块注入，不拥有系统指令权。（38 Surowan；评估页已采纳）
- **证据卡给弱模型**：简明的、带来源与时间与不确定点的卡，而不是长篇叙述；网页正文缩成证据。（19）
- **使用侧提醒**：笑话/称呼要看冷却与疲劳，不是想起就用。（27）

**与 Sumika 现状**

- 已做：全文前 20（trigram OR；不足 3 字用 LIKE）+ 向量前 20（sqlite-vec，qwen3-embedding-0.6b，1024 维）→ RRF（k=60）→ 时间加权 → `canSee` → 前 8 条、总长 ≤ 1200 字；`pinned`（有效约定和边界 ≤ 600 字）；已给过的不重复；只有出现新记忆/固定要点变了/满 15 分钟报时才追加"参考信息"（ADR-022）；注入面板记录每轮注入内容（`model_runs.injected_json`）；`recall_raw` 回查原文。
- 与笔记不同：现状**每轮都做 FTS + 向量两路**，笔记建议词法优先、向量按需、检索本身按特征门控；现状用 trigram + LIKE 兜底，笔记建议 bigram/预分词。
- 没做：检索门控、证据卡字段（verified_world_facts、uncertainty、expiry）、检索各阶段分开评测、中文 query 小基准、revision 防重复。

### 2.6 多模态

**笔记的结论**

- **识图结果不是事实，是候选。** MaiBot 默认路径是 VLM 直接生成 ≤100 字平文本描述并写入，没有证据结构；最小回归样本是"黑灰发带泪光的二次元人物被描述成奥特曼扛怪兽"。（35、28）
- **观测卡**：observable（媒介类别、可见主体种类与数量、发色、眼睛状态、配饰、动作与相对位置、可读 OCR、构图，各带 evidence_region/crop_ref）与 interpretations（情绪、语用、作品/角色、梗义，带候选和不确定）分开；source（media_id、群域权限、文件哈希、VLM 名称与版本、prompt_hash、生成时间、是否通过校验）；forbidden_assumptions。输出结构还可以是 observations / OCR / identity_candidate / temporal_events / emotion_candidates / meme_intent / evidence_frames / uncertainties / contradiction_flags。（35、28）
- **分级复核**：快路径（低成本 VLM/动漫 tagger 短卡，缓存成功结果）→ 结构检查（画种、主体数量、OCR 矛盾、突然叙述完整事件=异常，用规则）→ 触发二次验证（错误前提、角色名会影响回复或持久记忆、tagger 与 VLM 强冲突、OCR 出现疑似指令）→ 无偏复核（第二模型独立描述，不喂第一个模型的故事；同模型两次同样幻觉不算佐证）。强矛盾不用多数投票，降级为较粗的真描述。（35、28）
- **引用门控**：事实确定才写入图片事实索引；作品名/人名需公开出处、权威角色资料或本地标注；未识别的图只存哈希/可观察向量与 provisional 描述；**后来确认错误要标 superseded/invalid 并清除由它导出的标签、缓存、剧情联想、人物关联**。VLM 自报名字不算确认。（35、28）
- **图片相似 ≠ 同一个梗义**；image_embedding 与文本 embedding 不能混用。（28）
- **动图**：按真实容器检测，合成帧（GIF/WebP/APNG 的 disposal/blend，APNG 的 default_image 不是动画首帧），contact sheet（编号+时间戳+帧时长）+ 少量原分辨率关键帧，timeline；动态表情在表情/图片 ID 之外加 motion_signature、usage_context。评估页：**多帧分析推迟到第四阶段，先用单帧 + 缓存。**（28、29、38；评估页）
- **转发/链接**：转发者态度与原帖内容分开存（A 转发"新角色会删除"可能是反讽谣言）；带发布时间；打不开就说未验证；截图可能被裁掉上下文。（13）
- **媒体能力票据**见 2.1。

**与 Sumika 现状**

- 已做（规格层面）：每个媒体一个资产记录（哈希、描述、文字识别、候选人物带置信度、分析模型版本、来源消息），上下文里放 `[asset:编号] + 一句描述`，要细看时工具回查原图，"描述不等于原图"；图片 60 天未被看过且未被引用才清 blob、留文字描述，表情包一直留（ADR-026，ADR-029 改成现在先都留着）；媒体按内容哈希只存一份。
- 没做（至少文档里没有）：观察 vs 解释分层、分级复核、引用门控、错误描述的级联撤销、motion_signature、转发者态度与原文分离、发布时间字段。

### 2.7 学习（表达、黑话、行为、交互偏好）

### 2.8 成本与评测

**笔记的结论**

- 写入时不调 LLM（MemFit：LLM 调用减少 81–87%），把成本移到读取侧；反刍按**事件量**触发优于固定每条调用。（10-04、25）
- 弱模型降级链：本地缓存 → 小模型 → 有条件检索 → 强模型 → 不确定时简短回应/沉默；日志分记触发原因、检索成本、证据时间、动作、文本、失败原因；指标含"每群每天成本"、检索请求数、P95。（19）
- 识图：别每图调用两三个昂贵模型，规则能挡的不用 LLM，高风险才二次；动图视觉预算与聊天预算分开。（35、38）
- 速度起步 SLO（建议值，不是真人数据）：快路径 P50 ≤ 2s / P90 ≤ 5s，普通短回复 P50 ≤ 4s / P90 ≤ 8s；并行预取；用 `cached_tokens` 确认缓存存在。（33；ADR-011/016 已采纳）
- 日志保留候选：调试 7–30 天，完整 prompt/response 3–14 天，群原文 30–90 天，派生长期记忆需可查看/更正/删除并带到期。（34）
- 评测不是单一"答对率"：写入（覆盖/无根据提取/重复）、更新（supersede/冲突）、召回（Recall@5、错误来源率、时间正确率）、回答（正确/拒答正确）、系统（p50/p95/成本）；跨群泄露率应接近零；各篇给了 30～200 条人工标注的小评测集设计。评估页：**200/80 条标注集推迟，先从 MaiBot.db 挑 20～30 段真实片段做回放样本。**
- SQLite：WAL 单写者、checkpoint 饥饿；备份用在线备份 API；媒体不塞主库。（34）

**与 Sumika 现状**：model_runs 已记 cached_tokens；后台总结用便宜模型（`models.background`）；记忆预算起步值在规格-插件第七节（场景摘要 1K～3K、检索长期记忆 2K～4K、最近完整消息 8K～16K、群聊增量 1K～4K，预留 8K～12K）；没有记忆专用评测集和回放样本。

## 四、笔记写于 10-12，之后 Sumika 有了新决定，哪些结论要按新决定修正

按我读到的 10-13 到 10-15 的决定逐条核对（来源：规格-插件、决策记录、待办、设计）。

### 4.1 消息来源分类（规格-插件「消息来源」，10-15）

新决定：每条消息带 `origin`：`character`（她自己说的）/ `automation:<插件>`（插件自动发的，不算她说的，不当学习素材）/ `human`（真人登录她的号手动发的）/ `external`（以前别的程序用这个号说的，如 MaiBot 时期）/ `owner` / `peer`。记忆整理与学习按来源过滤。

要修正：
- 笔记里的"Bot 自己的话"一概当"Bot-generated inference"（22 信任序最后一档）太粗：`human`/`external` 不是她说的，应该按"主人替她说过什么"这类事实保留，学习时单独开关，不能落到"她的推断"上。（22、29、37）
- 37 的 `observed_behavior`（他人）/ `self_reflection`（她自己）的二分，要对应 `character` 与其他来源；`automation:*` 的回声根本不进学习。
- 14/04 的"Bot 反应不算真人反馈"，在新分类下精确成：`owner` / `peer` 的反应才算反馈；`character` 之间的（本地群聊里别的角色）、`automation:*` 的都不算。
- 25 的 `self_reported_or_quote` 需要补一个 origin，否则"主人用她的号说的话"会被存成她的自述。

### 4.2 四种场合（本地私聊 / 本地群聊 / 平台私聊 / 平台群聊，规格-插件第七节，10-15）

新决定：能看的记忆、工具、压缩重点、缓存特点按场合不同；本地群聊是主人 + 几个角色，**每个角色只看自己的记忆**，并按"主人 × 控制台 × 这个群的成员"过滤，私聊里的东西不带进来；角色私有的东西（思考、检索到的记忆、工具结果）不进共享记录，也不进别人的摘要。

要修正：
- 24 的默认规则只考虑了"群 / 私聊 / 公开"（QQ 视角）。要补一个**本地群聊**场合和**本地私聊（控制台，全部记忆可见，主人）**；24 的"受众集合"在本地群聊里是"主人 + 这几个角色"，不是人类群友。
- 24 把"子 Agent/多 Bot 也是新的接收方"当附带说明；在本地群聊里这是核心路径（一个角色读共享记录、另一个角色也读）：共享记录必须只含"可共享部分"，角色各自的记忆检索结果不能进去。
- 14 的"Bot 不算真人反馈"在本地群聊里要区分主人与角色。
- 笔记（06、10）里的"关系"是 Bot ↔ 群友；本地群聊里还有"角色 ↔ 角色""角色 ↔ 主人"，笔记没覆盖。
- 平台群聊的"两次开口之间的消息先压成摘要"，这份摘要是否进记忆，笔记没说；规格选择"不写回长期记忆"。

### 4.3 上下文压缩纪元（规格-插件第七节）

新决定：一个纪元内严格只追加；压缩、换模型、角色卡改了、空闲后重建，都开新纪元；压缩不是第二套记忆系统，摘要不写回长期记忆、不改角色卡；摘要里的事实带消息编号以便回查校正（防滚雪球）；新学到的东西只在下一次开纪元时进固定部分；后台压缩提交前检查纪元/版本/模型/边界。

要修正：
- 01 的 Working state、25 的 L1/L2、29 的"在线工作记忆"和纪元快照职责重叠。设计时要决定：**纪元快照就是 Working state**（不入库、可重建），L2 的"事件候选"（约定、边界、纠错）才是写进 `facts` 的 `candidate`。
- 25"边界立即生效"、35"发现识图错了立刻标 invalid 并清掉派生内容"，与"一个纪元内不改历史、已经发出的内容不偷偷改写"冲突：已经注入到历史里的那段错误描述，不能原地改，只能在下一条追加一条更正（ADR-022 现有机制：固定要点变了才拼参考信息），或等下个纪元重写。笔记没考虑这一点。
- 24"摘要的权限取最严格数据源"要落实到纪元快照上：平台群聊的快照不能带私聊来源的内容；快照里写进去的事实必须带消息编号和可见性。
- 01/25 说"摘要只是索引不是真相"，与规格的防滚雪球相合；但 25 L3 的 Episode 又把"对完整交互片段整理"当作记忆层，需要说清它和纪元快照是两件事（Episode 是长期层，会被检索；快照是上下文视图）。

### 4.4 只追加的缓存约束（ADR-022）

新决定：每轮变化的内容只能追加在末尾，不插入、不改写；没有新记忆时这一轮什么都不加；实例重建时从事件库恢复的历史不含参考信息，会重新给一遍。

要修正：
- 19/33 的"证据卡、并行预取、推测式预取"，输出必须只能追加到尾部；预取结果"用不上就丢"在 Sumika 里是真正的丢弃（没追加就没缓存代价），但一旦追加就不能撤回。
- 24 的"撤回后级联删除摘要、索引、缓存"在 Sumika 里要加一条：**已注入历史的内容不能撤，只能在新纪元前追加更正**；因此"检索前"过滤比"事后撤回"重要得多，应该把检索前过滤做扎实，把事后撤回当兜底。
- 27/25 的"使用侧冷却""疲劳"需要每轮判断，但判断结果只能以"追加一句参考信息"的形式表达，或者落在这一轮提示词最末尾，不能改系统提示。
- 38 的"id+revision 防重复注入"与 ADR-022 的"同实例里已给过的不再重复"是同一个机制，可以统一成一张"本实例已注入的 (ref, revision)"表。

### 4.5 角色职业、顾问（规格-插件 七点五，10-15）

新决定：职业是和角色分开的智能体身份；顾问是独立会话、独立模型，只看**自上次以来新增的部分**，意见只追加在主会话末尾，包成 `<advisory>`；平台群聊里顾问只读能看到的群消息，不看本地文件；顾问发言算角色发言。

要修正：
- 24 所说的"子 Agent 也是新的接收方"直接适用于顾问：顾问的输入必须是经过权限过滤后的增量，**顾问意见本身也是带来源权限的派生内容**（它引用了私聊内容就不能进群）。
- 22 的投毒防护：顾问读到的内容里夹带的指令要整轮丢弃（规格已写）；顾问的建议不是独立佐证，也不应被总结写成事实。
- 记忆归谁：职业是"和角色分开的身份"，那么顾问/职业有没有自己的记忆、能不能看被审查角色的记忆，笔记没有讨论，需要另定。

### 扩展 24｜跨群、私聊与多人关系的信息边界：情境完整性、受众权限与记忆隔离（P0）

**核心结论**
- 记忆真不真、Bot 访问过没有、用户对 Bot 说过没有、现在能不能对当前受众说，是四个独立问题。同一人属于 A 群和 B 群，不等于 A 群的话可以在 B 群用；即使在某群公开，也不默认允许跨群转述（情境完整性，Nissenbaum）。
- 判断"能不能谈"拆成八层：主体（关于谁）、来源和最初受众、现在的听众（@A 不等于只有 A 看得到）、披露许可（可撤回）、社交适宜性、时间与变更（退群、撤回、取消授权要让摘要/向量/缓存跟着失效）、组合泄露（拼图推断）、执行路径（检索、提示词组装、重排、搜索词、日志、跨 Agent 消息、最终文本都是信息流）。
- 默认规则（拟议）：同群→同群可按受众和时效适度提；群 G1→群 G2 默认不检索 G1 的私有记忆；**私聊→群 严格拒绝外传**（群里被问"你记得吗"只能基于群内已公开细节答，或建议回私聊）；群→私聊可讨论对本人可见的事，但不转发第三方敏感细节；公开互联网→群可引用，但不能用私下建立的"匿名作者=某群友"映射去揭露；子 Agent/多 Bot 也是新的接收方，只传脱敏后的最少必要信息；涉及第三方的共享秘密要考虑第三方（不能只记 owner=A）。
- 数据结构：来源标签（record_id / subject_ids / sender_id / source_type(dm|group|public) / source_room / event_time / audience_at_origin / original_message_ids / retention_policy / revoked_at / confidence）与允许分享规则（audience_constraints / purpose_constraints / expires_at / explicit_grant_evidence / policy_priority / affected_subjects / inherited_restrictions / last_reconfirmed）**分开存**；输出上下文另算（current_room / active_members / direct_addressee / visible_audience / topic / bot_role / requested_disclosure / disclosure_purpose）。**不要用单一 private/public 二值代替群域 ACL**；统一实体标识只负责"知道 A 在各处是同一账号"，记忆本体按群/私聊/公众分区；摘要的权限取其中最严格数据源。
- 检索前过滤的最小架构：写入即带 origin 与可用范围 → 以可信平台元数据确定当前 group_id / dm_user_id / 成员（不信自然语言"我是群主"）→ **检索前**做 ACL/ABAC 过滤（SQL 和向量候选都先筛房间，不能"先检索出来再让模型忽略"）→ 证据卡、缓存、搜索词、调试日志、子代理消息沿用来源权限（私有原句不进联网查询）→ 最终披露守门（第二道防线）→ 更正与撤回要级联删除派生摘要、索引、缓存。
- 另存"不主动提"作为独立互动偏好（区别于不可访问）；"能理解但不能引用"；高风险才需要确认，其余默认遵守作用域并选泛化回答或沉默。
- 附 Surowan 的媒体/引用能力票据（绑定会话、带 TTL，源内容被 GC 后不能解析），可迁移成 QQ 媒体访问票据；但只管工具层引用，不管私聊原文和派生画像。

**对 Sumika 的直接建议**：可见性不要停在三档标签；记忆要带 source_room、origin_audience、subject_ids；检索前过滤；"不主动提"单列；撤回级联；联网搜索词不带私有原句。评测：120 个中文多房间情境，泄露率应接近零（MuPPET 思路：每条信息 × 每个受众成员检查）。

**与现状**：部分做了。`canSee` 是唯一入口（公开 / 仅对此人 / 私密三档），`recall_raw` 只搜 observations（A 搜不到 B）。没做：按群/房间的 ACL（只有"主人 × 控制台"一种场合被实现）、source_room / audience_at_origin、第三方共同持有、"不主动提"、撤回级联到摘要/向量/缓存、联网搜索词过滤、组合泄露审查。冲突：现状三档标签与笔记"不要用 private/public 二值"直接冲突；设计文档"仅对此人 = 当前说话人"在群里会被"其他群友也看得到"这一点挑战（@A 时全群可见）。

### 扩展 25｜对话重要性判断与多层记忆反刍：实时写入、事件升层和遗忘（P0）

**核心结论**
- 先辨语用事件，不按长度/情绪打分：自述事实、未来承诺/任务、互动边界/群规、态度/观点（只作当轮情绪，不升为"永远讨厌"）、引用/代言/反讽/角色扮演（要 attribution 和 speech_act）、多人共同事件（关系只记候选）、虚构事实/恶意教梗（重复出现不等于真，话多的一个人不等于全群共识）。
- 重要性不是一个分数，分九项判断：即时行动/风险、未来再利用价值、变化/新颖性（推翻比重复更值得查）、自述可信度（本人 > 转述 > 梗化 > 推断）、时效性（与长期价值拆开）、群内共享程度（刷屏不算多主体佐证）、场合权限（**权限否决高于价值评分**）、角色关联、不确定性与错误固化代价。没有通用"超过 7 分就记"。
- 五级生命周期 L0–L5：L0 权限内原始事件和引用锚点；L1 在线工作记忆（秒–数十分钟，话题结束自然过期）；L2 事件候选与临时重要状态（分钟–小时，带 TTL、provisional、证据锚点，显式边界立即生效）；L3 情景 Episode（小时–天，去重、分话题、分人归属）；L4 持久语义/群规范/操作经验（天–周，要多次证据或明确可靠声明，有置信度、过期、反例、supersede，跨群作用域不扩大）；L5 可审查高层反思（周期，标支持与反例，不贴心理标签，可撤销）。
- 反刍节奏（候选参数，论文未证明）：立即（直接纠正、"别再提"、撤回、时间敏感约定→直接更新可执行状态或访问控制）；短周期 10–60 分钟按消息簇事件量触发；每天按群/个体聚合 episode、引用校验、冲突梳理、输出有限新长期候选；每周或证据够时归纳群规/偏好/共同梗；定期清理、随时撤销，重要不等于不可删。
- 数据字段：source_event_id / stream_id / group_id / speaker_id / subject_ids / audience_scope / speech_act / evidence_span / self_reported_or_quote / event_time / observed_at / valid_until / significance_reason / future_utility / novelty / urgency / social_impact / confidence / supported_by / contradicted_by / status(candidate, confirmed, disputed, expired, revoked) / permission_policy / memory_layer / supersedes。动作集：ignore_for_long_term、working_only、hold_candidate、save_episode、upsert_fact、set_interaction_policy、update_prior、retract_or_delete；不让自由文本模型随意改所有层。
- 例："好烦，一百字骂手游公司"长期偏好低；"以后别叫我这个外号"字少但立即进互动政策。
- 证据：Generative Agents（近期性×重要性×相关性，反思）、AgeMem、Hindsight（world/experience/observation/opinion 四网）、A-Mem、PERMA（偏好随事件积累，一次倾向不升永久人格）、Memora（遗忘感知准确率：重复使用已失效记忆）、MemoryAgentBench（检索/在线学习/长程理解/选择性遗忘分开评测）。

**对 Sumika 的直接建议**：总结提示词增加语用事件分类和 status；加"互动政策"（边界）通道且立即生效（现有"快速通道"与此对应）；候选 → 确认，不一次写成事实；时间尺度反刍分层；评测集 200 条。

**与现状**：部分做了。已有：fact kind（fact/promise/preference/boundary）、status（active/candidate/superseded/revoked）、superseded_by、source_seqs、快速通道、`candidate` 操作、会话安静 10 分钟/40 条触发总结、每日维护只报告。没做：L1/L2 工作记忆与 TTL（valid_until）、speech_act/attribution、重要性多维评分、L5 反思、周/日不同周期反刍、"不主动提"、disputed/expired 状态、遗忘衰减（只有检索时的 30 天时间加权）。基本不冲突，是细化。

### 扩展 35｜识图结果可信性：证据原子化、冲突复核与阻止错误图片记忆（P0）

**核心结论**
- MaiBot 当前 image_manager 用 VLM 直接生成 100 字平文本描述并写入、同步 A_Memorix，调用路径里没有结构化证据、逐项置信或第二模型校验；最小回归样本：黑灰发带泪光的二次元人物被描述成"奥特曼扛怪兽"。
- **可信观测卡**：observable（媒介类别、可见主体种类/数量、发色、眼睛状态、配饰、动作与相对位置、可读 OCR、构图，各带 evidence_region/crop_ref）与 interpretations（情绪、语用、作品/角色、梗义，带候选与不确定）分开；source（media_id、群域/权限、文件哈希、VLM 名称与版本、prompt_hash、生成时间、是否通过校验）；forbidden_assumptions（没看见的角色/怪兽/武器/情节、名字）。
- 分级复核：快路径（低成本 VLM/动漫 tagger 短观察卡，缓存成功结果）→ 结构检查（画种、主体数量、OCR 矛盾、突然叙述完整事件=异常，用规则不用 LLM）→ 触发二次验证（错误前提、角色名会影响回复或持久记忆、tagger 与 VLM 类别强冲突、OCR 出现疑似指令）→ 无偏复核（第二模型独立描述原图/裁剪，再比对原子命题；同模型两次同样幻觉不算佐证）。
- **引用门控**：事实确定才写入图片事实索引；作品名/人名必须有公开出处、权威角色资料或本地标注证据；未识别图只存哈希/可观察向量和 provisional 描述；**后来确认错误要标 superseded/invalid 并清除由它导出的标签、缓存、剧情联想、人物关联**。

**对 Sumika 的直接建议**：媒体资产记录加"观测 vs 解释"分层、模型版本、prompt hash、校验状态；人名不经验证不进记忆；错误可级联撤销。

**与现状**：部分做了/方向一致。规格-插件第七节"媒体资产记录（哈希、描述、文字识别、候选人物带置信度、分析模型版本、来源消息）、描述不等于原图"与此吻合。没做：观察卡 vs 解释分层、分级复核、引用门控、错误级联撤销（目前只写在规格里，未实现）。

### 基础 01｜通用 Agent 记忆：即时工作记忆、长期记忆与准确性

**核心结论**
- 数据分六层：Raw event log（append-only，正常更新方式只追加，但可合规清除）/ Working state（当前目标、约束、计划、进度，任务结束生成 checkpoint，不能无期限当长期事实）/ Episodic（事件边界、因果证据）/ Semantic（subject/predicate/value/source/evidence/confidence/valid_from/valid_to/observed_at/supersedes）/ Procedural（经多次验证的流程，保留反例与撤销）/ **Belief / hypothesis（模型推断，不升级为当事人明确事实）**。摘要只是索引与派生，不能替代原文。
- 写入更新流程：先存原始事件 → 再判断是否值得提取（明确状态/偏好/事实变化优先于闲聊）→ 结构化候选，在人/项目/聊天作用域和时间内查已有条目，分"新增/修正/暂存/忽略" → 来源核对（直接陈述 > 可信多次佐证 > 模型推测；笑话、引述、假设句默认不生成强事实）→ 推翻时建 supersede 版本链并保留旧事件的历史有效期；撤回/删除级联清摘要与索引 → 只注入少量仍有效的相关证据；检索信心不足回读原始日志，仍不能确认就答"不知道"。
- 检索：低成本 BM25/FTS（中文预分词或 bigram）+ 实体/项目/时间过滤 + 精确 ID boost，再按需语义候选与 rerank；高可靠路线是"候选摘要命中 → 原始消息 span 回查 → 对比来源/时间/状态 → 回答"，高风险更新要人审。多 Agent 独立命名空间和权限，项目级知识可共享，个体偏好、私密会话默认隔离。
- 评测：写入覆盖率/无根据提取率/重复率，更新的 supersede/冲突消解，召回 Recall@5、错误来源率、时间正确率，回答与拒答正确率，p50/p95 与成本；从 50 个带证据的中文问题起步，完整保留错误链路 raw → candidate → retrieved → injected → answer。HaluMem 说明错误多发生在抽取与更新阶段，只测最终答案不够。
- 另一篇（页面 3efdfb6e…，"CJK FTS、MemFit、supersede 与耐久性工程"）被链接，本次未读。

**对 Sumika 的直接建议**：增加 Working state / checkpoint 层和 Belief 层；Semantic 条目补 valid_from/valid_to/observed_at；评测集按"错误链路"存。

**与现状**：大部分已有雏形或已做：事件日志只追加、facts 有 status/superseded_by/source_seqs、`recall_raw` 回查原文、FTS trigram + 向量 + RRF、"拿不准就回查原文，查不到就说不记得"（设计三原则）、注入面板记录 injected。没做：Working state 层（上下文压缩的纪元快照在规格-插件第七节里，部分对应，但明说"压缩不是第二套记忆系统"）、valid_from/valid_to 有效期字段（现只有 status）、Procedural 记忆、Belief 单独一层（现用 status=candidate 近似）、写入时的"新增/修正/暂存/忽略"四分、删除的级联（派生可重建，原则上可行）、记忆评测集。

### 基础 06｜群友画像分析：事实、观点、关系、时间与隐私边界

**核心结论**
- 用"按主体、来源、有效时间分开的事实账本"，单段自动总结画像只是便捷视图，不是唯一真相源。Bot 的关系感知（主观层）、群友主动陈述、群体共识是三层，可能冲突。不推断/存储敏感属性、私密关系、脆弱信息；画像不是心理诊断。
- 画像数据模型：Identity（平台+稳定用户 ID，群内昵称别名带有效时间，**不按相同昵称跨群自动合并**）；Self-reported facts；**Attributed statements**（A 说 B 喜欢某游戏 → 存"据 A 声称 B…"）；Observed patterns（统计描述+时间窗口）；Relationship（Bot→A、A→Bot、A→B 分向记录，方向不能互推，标签可撤销）；Hypothesis（单独低置信，对外不用肯定语气）；Group facts（A/B 立场并存，不合成"大家觉得"）。
- 变化例子：上月"不喜欢恐怖游戏"、本月"玩了某恐怖游戏" → 只证明玩过，旧事实保留，当前偏好待确认。互相开玩笑只记为"在这些场合存在玩笑互动"，不推断深层感情。
- 更新：先解析谁说的/说的是谁/是否引用反讽扮演/有无相反证据；事实变化走 supersede；支持按人查看、人工更正/删除、跨群分享许可；清除时同步清衍生索引、摘要、缓存。
- 论文数据：GroupMemBench 最强系统仅 46% 综合准确率；PersonaMem 前沿模型仍常用过期偏好；MaiBot A_Memorix 画像默认刷新兜底 30 分钟、活跃窗口 72 小时（配置值以本机为准）。最小评测：30 用户 × 5 问（自述/转述/玩笑引用/时间更新/未知拒答）+ 跨群 30 个权限测试。

**对 Sumika 的直接建议**：people 表（目前只建表）要按这七类拆；加 attributed statement；别名带有效时间；关系分向。

**与现状**：没做/部分做。设计里"认人档案：QQ 号、外号别名、印象、关系、最近一次互动"只是一张表，第一阶段"只建表"。facts.subject 有 owner/self/其他 id，可承载主体归属，但无 attributed 标记、关系分向、别名有效期、Hypothesis 分层。信息架构里"她知道的关于你 / 还不确定的"两层与 Self-reported / Hypothesis 对应。

### 扩展 34｜本地多角色 QQ Bot 的日志、原始消息与模型调用追踪：SQLite 事件溯源

**核心结论**
- 三种记录必须分区：A 调试日志（短期，不含正文与凭据）；B 原始事件（唯一事实来源，同一消息多角色看到只存一份）；C 模型调用审计（完整请求/响应，隐私与体积成本最高，默认短期、限权）。"共享原始事件不等于共享角色记忆"；每个 Bot 在 bot_observations / memory_operations 记自己看到了什么和做了什么记忆操作。
- 示意 schema：source_events（event_id、platform、room_id、actor_id、event_type、platform_message_id、happened_at、received_at、payload_json、visibility_scope、erased_at）、message_segments、media_assets（sha256、source_scope、erased_at）、message_links、reaction_events、model_runs、memory_operations（op_id、bot_id、scope、source_event_id、memory_id、operation、value_json、revoked_at）、bot_observations。提醒：通知/表情贴图可能没有稳定 message_id，UNIQUE 约束不能当全类型去重。
- 事件溯源与删除：逻辑上 append-only 但个人内容不能永远不可删；用 tombstone + 可真正删除/加密清除（crypto-shredding）的原文和媒体；删除顺序：授权→标记失效→删文件/密钥/载荷→清理 FTS/缓存/备份/图谱节点/导出副本→再次搜索确认无残留。
- SQLite：WAL 单写者、checkpoint 饥饿、FTS5 中文要比较 trigram/jieba，FTS 与向量删除要一致；媒体不塞主库，用文件 + sha256；备份用在线备份 API。
- 保留期候选：调试 7–30 天，完整 prompt/response 3–14 天，普通群历史 30–90 天，派生长期记忆需可查看/更正/删除并带到期与权限标签；账号令牌不进 model_runs。

**对 Sumika 的直接建议**：已基本照做；补"删除作业链"和"删除后再搜确认无残留"；memory_operations 记 revoked_at。

**与现状**：已做大半（ADR-015、ADR-026）：events.db 全局一份 + observations，三种记录分开，保留期 90 天/60 天图片（比笔记 30–90 天的上限略长，群原文 90 天后压缩归档不删）。没做：删除作业链（tombstone/crypto-shredding）、撤回级联到 FTS/向量/摘要；"从不重写已写下的历史"（ADR-026）与"个人内容可删"需要一个明确的例外条款。

### 扩展 03｜群体共同背景与关系感：公共事件、群内梗与分人记忆（P1）

**核心结论**
- 接"又来了"这类省略句需要可溯源的事件、人物归属、时间与范围；可以记聊天里的共同经历，不能虚构线下经历。GroupMemBench：最佳系统平均 46.0%，知识更新 27.1%，术语歧义 37.7%（合成数据，非真实 QQ）。
- 区分五类：公开事件（"曾说准备画某角色"≠现在还在画）、观点及说话人（B 的立场不能归到引用它的 C）、共享语境、社交规则（本群特有，不通用）、临时与冲突（计划取消保留更新链；不同人反对同一事不合成"全群一致"）。
- 事件单元字段：event_id / group_id / speaker_id / audience_scope / source_message_ids / occurred_at / observed_at / **factuality(observed|reported|inferred|disputed)** / topic / claim / confidence / valid_until / supersedes / access_policy。关系只存可观察的互动事实与明确偏好，"关系很铁""讨厌 A"当推测不固化。

**对 Sumika 的直接建议**：facts 加 factuality 与 valid_until；"群公共事件/共享语境"需要一个按群的事件层（与 ADR-012 公共知识层不同：公共知识是主人确认的、跨群共享的，这里是群内的、有范围的）。

**与现状**：部分做。信息架构区分了"记忆"与"公共知识"（和某人有关进记忆，和词/惯例/群有关进公共知识），但没有"群内共享事件"这一类；没有 factuality 四档、valid_until。

### 扩展 10｜长期社交互惠：关系距离、信任积累与交互史（P1）

**核心结论**
- 记忆正确率不等于关系质量；信任不会因多说好话自动出现。群聊里的"互惠"：认真回应该回应的人、被帮过自然致谢并合理使用共享信息、不反复索取注意、不对新群友装熟（有共同公开经历后才提"上次那件事"）、保留独立立场。关系有方向：Bot 对 A 熟 ≠ A 想亲近；A–B 熟不能移植到 Bot–B。
- 关系边结构：edge(bot_id, user_id, group_id)：direct_interactions / replied_to / user_explicit_preferences / 明确正负反馈 / trusted_topics / boundary_evidence / last_updated / confidence。群共同记忆单独存事件，私聊与群的许可作用域分开，不从表情、作息、性别推断心理秘密。
- 行为政策状态机（候选）：初见→礼貌低干扰；有互动→按对方明确偏好；有共享经历→适度引用；有矛盾→自主修复；被要求设界→降低主动度。不建议"第 N 次见面才能怎样"的机械规则。
- 机器人自己纠正错误更有利于信任（Correct Yourself, Keep My Trust）。

**对 Sumika 的直接建议**：people 里关系用有向边，按 (角色, 人, 群) 存；"降低主动度"作为可记忆的政策。

**与现状**：没做（认人档案有"关系""最近一次互动"字段但无结构）。不冲突。

### 扩展 22｜社交诱导与知识污染：假梗、伪造群规、记忆投毒和提示注入（P0）

**核心结论**
- 低信任来源：群友消息、截图/OCR/GIF 里的指令、转发帖、搜索结果、其他 Bot 的回复。典型风险：群友反复灌输"X 是夸你"诱导对新人用攻击词；声称"群主批准你公开私聊"（权限不由自然语言授予）；网页写"忽略上面规则"；两个 Bot 互相赞同形成伪独立佐证；起哄让 Bot 把个人/群规永久改掉。
- 信任序：trusted_platform_metadata > confirmed_policy_by_admin > user_explicit_statement_about_self > repeated_independent_observations > single_claim > external_unverified_comment > bot-generated_inference；同来源/同人刷屏要去重；个人偏好不由他人投票覆盖。
- 候选字段：evidence_ids、scope、source_actor、channel、source_type、claim、factuality、confidence、disagreement、write_reason、expiry、review_status；政策变更需可验证身份的后台配置。
- 原则：检索前权限过滤（数据层不可跨域，不靠提示词"请勿引用"）；不可信文本隔离；重大事实/规范改写需独立佐证、可靠来源或当事人同意；发现投毒时撤销派生摘要、索引、跨 Bot 缓存；不因此拒绝一切玩梗。

**对 Sumika 的直接建议**：写入时存 source_type 和信任档；两个角色互相援引不算独立佐证（本地群聊直接相关）；总结提示词把截图文字/网页内容当数据。

**与现状**：部分做。已有"外来的格式标记、指令句都是普通内容""昵称不能当身份"（规格-插件第七节）；`candidate` 状态；ADR-013 主人确认。没做：信任序字段、独立佐证去重、角色间互援防护（发言调度只防循环，不防互相佐证写入记忆）。

### 扩展 27｜互动新鲜感与关系仪式：跨时间重复玩笑、间隔、变体和适应（P1）

**核心结论**
- 重复不一定无聊；关键是谁发起、什么场景、有没有小变化、对方是否愿意继续、有没有人明确叫停。随机换笑话不等于新鲜感，要在稳定关系线索上小幅变形。
- 三条轴：互动熟悉度（不从回复次数推亲密）、记忆新鲜度（最近一次出现、谁发起、有无新材料）、疲劳与意愿（近期密度、是否被拒绝；沉默只是弱信号）。
- Ritual / Running Joke 状态机：候选→双方自发重复→本群稳定局部习惯→低频维持/变化→冷却或废弃。字段：ritual_id / initiators / related_people / group_scope / trigger_context / original_evidence_ids / last_seen / last_bot_used / variants / observed_positive_or_negative_direct_feedback / current_fatigue / usage_boundary / consent_and_expiry。必须限到有可见证据的群/受众；私聊内部笑话不得在别的群主动提。
- 策略：第一次回应短；有真实重现可呼应并小变体；对方主动提才优先接；换话题就停；频率升高则降低触发概率；明确"别再这么叫"立即停，不等冷却。阈值全是待验证假说。

**对 Sumika 的直接建议**：记忆里需要"last_bot_used、冷却、边界"这类**使用侧**字段，而不仅是内容；梗/称呼类记忆带"最近一次由她使用的时间"。

**与现状**：没做。facts 无"使用记录"概念；注入只有"同一实例里已经给过的不再重复"。

### 扩展 15｜新群冷启动与社交融入（P0）

**核心结论**
- 两种冷启动：New Group（群规、惯用语全未知，不能把别的群经验当当前群事实）和 New Person（已知群风格，不知此人是否接受调侃，不能用熟人习惯代替新人许可）；有授权历史可预读 vs 零观察要区分。
- 五阶段：观察期（只读有权限的公告/近期聊天/置顶，没材料就保守）→ 候选群体模型（规范、话题、发言动作、术语、关系网；每项带 evidence_ids、样本数、不同发言者数、反例、置信度）→ 机会识别（低风险、能理解、有贡献）→ 轻量参与 → 反馈更新（明确纠正/认可是强信号，沉默弱；转群后可重置）。
- 最小群画像 JSON：group_id、history_access、known_rules[{rule, source, confidence}]、topic_candidates[{topic, supporting_speakers, confidence}]、style_hypotheses[{feature, evidence_count, confidence}]、candidate_entry_points、prohibitions（跨群搬运私事、冒充真人、推测新人隐私）。
- 评测：0/5/20/100 条可见消息四档；诱骗测试：一个人刷屏"我们群都爱被骂"不应学成全群规则，别的群复制来的聊天不能不带作用域覆盖本群事实。

**对 Sumika 的直接建议**：按群的"群画像"作为独立记忆层，带样本数/不同发言者数；新群默认不带任何别的群的记忆。

**与现状**：没做（第三阶段内容）。与四种场合设计"平台群聊：旁观为主"相容。

### 扩展 07｜群体潜规则与社交边界（P0）

**核心结论**
- 规范分五类：显式规则（高优先，不能被多数样本覆盖）、描述性模式（概率特征，非命令）、互动许可（A–B 互损不推 Bot–C 也可）、话题与边界、变化（新人、管理员纠正、梗过时）。
- 规范记忆字段：norm_id / group_id / type(explicit|observed|inferred) / applicable_context / behavior / audiences / supporting_message_ids / counterexamples / confidence / last_observed / expiry / override_priority / sensitive_risk；每条至少留反例或适用边界；单人刷屏和 Bot 自己的话不算群体共识；不盲从排斥/欺负新人的恶意惯例。
- 接入：Bot 说话前检索"这个场景的可用规范"，不是最近流行词；明确规则高于推断；允许新证据推翻。LoSoNA 基准是合成、单轮，不能外推。

**对 Sumika 的直接建议**：与 15 合并成"群规范/群画像"层；公开的群规与群公告优先。

**与现状**：没做。信息架构里"群规矩"在职业/引导编辑里提到过，但没有数据结构。

### 扩展 38｜Surowan 塑料碗源码对照：持续群聊、记忆隔离、辞典与动图设计

**核心结论**（Telegram agent bot，Apache-2.0；对照研究，未运行）
- 数据三分：messages + message_revisions（平台事件版本）/ invocations、model_calls、agent_messages（审计）/ conversation_contexts、context_messages（跨调用的实际 Agent transcript）；默认不记完整原始报文；隔离回放不执行发送/记忆副作用。Context 是**丢弃式 GC（按 checkpoint），没有做摘要反刍，也没有事实晋升**。
- 能力引用：媒体/贴纸/引用只能在其原 Conversation Context 中解析，带 TTL 且源消息仍在保留段内；新 Context 不能借别的群的 ref。注意它管的是工具层引用，不管长期记忆权限。
- 群级辞典：global/group 范围、同名多义与别名共存、scope 权限校验、**修订号（revision）防并发覆盖**、按需/积极注入、在保留 Context 里查 id+revision 防重复注入（更新或 GC 后可再注入）；以不可信文本块注入；匹配只用 literal substring，无 embedding；融合由辅助模型提出、管理员确认后写入。
- 紧凑消息渲染（718 字符 JSON → 151 字符，仅字符数对比），用户原文不能伪造框架头；Bucket 合批 + 长活 Invocation + 热注入。
- 动图：设计稿（storyboard 最多 12 帧、按帧 duration 合成），代码里目前仍只取一张代表帧，不能当已实现。

**对 Sumika 的直接建议**：辞典/公共知识条目加 revision 与注入去重；媒体访问票据；回放无副作用；已发出内容的注入去重用 id+revision（与 ADR-022"同实例已给过的记忆不重复给"同一路子）。

**与现状**：多数已采纳或同向：三分（ADR-015）、公共知识层（ADR-012）、"已给过不重复"（ADR-022）、紧凑历史格式（规格-插件第七节"省 token"，且强调昵称转义）。没做：revision 防并发覆盖、媒体能力票据、副作用隔离回放。

### 扩展 45｜ChatLuna：Koishi 多模型、角色预设、记忆图谱与 Agent 扩展审计

**核心结论**（AGPL-3.0，只能参考思想不能抄代码）
- 长期记忆扩展有可替换的层：basic（向量/文本）、**HippoRAG**（向量 docstore + KG 索引，SimHash 与近义/实体桥接，部分路径用模型抽三元组）、**EMGAS**（Episodic Memory Graph + 激活扩散，**随时间衰减与剪枝**），有过期清理、JSON 持久化。机制存在于代码，但语义正确率/误记率未测。
- Agent 扩展里确认已实现的只有 MCP 工具目录懒加载（search_mcp_tools / invoke_mcp_tool 按需披露 schema，利于弱模型），Skills/Scheduler/Sub-Agent 标"规划中"。
- 要学的：长期记忆做成**可替换层**、图结构事实召回、实体桥接、TTL 与衰减；但必须保留来源事件和强群域 ACL，**跨群相似文本检索不能绕过权限**；不要混淆长期记忆（提取/结构化/检索/遗忘）与行为学习（因果归因）。实测计划：同一匿名语料比较 basic / HippoRAG / EMGAS 的跨日、纠错、反讽误记、跨群隔离和 P95。

**对 Sumika 的直接建议**：记忆服务做成可替换接口（现状已是："对外只有写入动作和检索，做成可替换的服务"）；衰减/剪枝可参考 EMGAS，但要放在"可重建派生层"里；先不上图。

**与现状**：同向。memory.ts 已是可替换服务；没有衰减/剪枝（只有 `×(1 + 0.2·e^(−天数/30))` 的检索时间加权，且**只加分不遗忘**）；没有图/实体桥接。

### 扩展 40｜Meta Muse：持续个人记忆、关系画像与 Sentinel 权限闸

**核心结论**（闭源产品+官方文章+第三方报道，只取原则）
- "某人在群里说了一句"要分四类：原始事件、可供回忆的候选人物事实、群内限定用法、长期角色偏好；谣言/反讽/玩笑不当属性。
- 人物关系画像只能在来源受众范围内复用；私聊/群里的私人抱怨不因人物相同在别群披露。第三方（非用户）被间接建档是公开的隐私争议点。
- 后台自主搜索/主动社交要有可回溯的触发理由和**打扰预算**；"知道"不等于"该说"。回复、群公告、转发私聊等是不同权限级别；模型判断对不等于有权限（Sentinel 与主代理隔离检查外部动作）。
- 拟验证："用户明确否认历史事实时，派生社交记忆是否一同失效"。

**对 Sumika 的直接建议**：记忆写入时第三方（非主人、非对话者）事实的处理要单独考虑；用户否认事实 → 级联失效派生。

**与现状**：同向。权限分层（只有主人×控制台能执行）已有；第三方记忆未单独处理。

### 扩展 28｜多模态理解质量闸：关键词抽取、误识校验、GIF/APNG/视频时序（P0）

**核心结论**（记忆相关部分）
- 失败案例同 35：黑灰长发二次元女生被描述成"奥特曼扛怪兽"；这类描述不能继续生成情绪、角色设定、表情标签，也**不能进入长期图片记忆**；写入长期图片记忆前必须有复核或高可靠来源锚点。
- 输出结构：observations / OCR / identity_candidate / temporal_events / emotion_candidates / meme_intent / evidence_frames / uncertainties / contradiction_flags；分 grounded_observations 与 unverified_interpretations 两组；长描述应由已验证关键词拼出，不许模型在中间补怪兽/设定；强矛盾不能多数投票（共享视觉盲点），降级为"黑发二次元人物在哭笑"。人物名/原作/梗需另查图搜和上下文，VLM 自报名字不算确认。
- 第二模型要换一种盲问法，不喂第一个模型的错误假设。
- 动图：按真实容器检测（不依赖扩展名），合成帧（GIF/WebP/APNG 的 disposal/blend，APNG default_image 不是动画首帧），采样不只按 MSE；contact sheet（编号+时间戳+帧时长）+ 少量原分辨率关键帧；timeline；视频加 ASR/字幕；动态表情在表情/图片 ID 之外加 motion_signature、usage_context。MaiBot 现 GIF 转换：MSE 阈值最多 15 帧、目标高度 200 px 横向拼接，只处理 GIF。
- 路由：metadata → 静态图/普通帧 → 关键词证据卡 → 缓存 → 回复；动态媒体才抽帧；低置信且相关才二次 VLM；Windows 本地优先 CPU 解码以免抢显存。

**对 Sumika 的直接建议**：媒体资产记录里存"观测 / 解释 / 矛盾标记 / 复核状态"，只有通过复核的描述才进可检索的长期记忆；动图加 motion_signature。

**与现状**：规格已有"媒体资产记录"设想；实现程度未知（未核对代码）。"首次进入上下文的表示固定不变，开新纪元再换成引用"是缓存约束与笔记"错误可随时撤销"之间的潜在矛盾，见矛盾节。

### 扩展 13｜跨平台网络媒介理解：转发截图、来源、断章取义与内容时效（P2）

**核心结论**（记忆相关部分）
- 群里发链接的三层意思：原始内容（作者、发布日期、原始出处）、转发行为（推荐/吐槽/质疑/求证/引梗/围观）、群体回应；A 转发"新角色会删除"可能是反讽谣言，不等于 A 相信 → **转发者态度与帖子原文分离存储**，不能写成 A 的立场。
- 时效：两年前的公告当今天的更新；必须带真实发布时间；打不开链接要说未验证，不凭标题脑补；截图可能被裁掉上下文，降低断言强度。
- 高频群聊下资讯核查按风险触发，不是每个链接都重度联网。

**对 Sumika 的直接建议**：链接/转发内容的记忆存 source_url、发布时间、转发者意图（多解）；检索时带"内容时效"。

**与现状**：规格-插件第七节"工具结果首次进入前筛字段，完整原文存盘给编号可回查""昵称/外来格式是普通内容"同向；"链接解析"是 ADR-025 的群聊插件；记忆层没有 source_url/发布时间字段。

### 总览页与评估页的补充

- 总览核心结论：先"结构化群聊事件 → 分主体/分群记忆 → 来源与时间校验 → 分场景召回 → 发言与风格决策 → 反馈更新"，不要把一对一摘要 RAG 套到群聊；原始历史与提炼记忆分开；事实、立场、推测、角色自述分开；**发生时间与写入时间分开**；更新用版本链而非覆盖；风险：错误社会关系固化、把冷场当差评、跨群私事泄漏、社交反馈优化导致讨好和人设漂移。

### 更早的记忆研究｜Memory / RAG 双周研究 2026-10-04（页面 3efdfb6e-a293-812c-84d3-fac03eefc1fe，总览引为"现有资料衔接"，不在 51 篇之内）

**核心结论**
- **LAPSE（arXiv 2609.36457）**：记忆写入者会把"正在、暂时"压成长期事实（381 对句子，3 个 writer 对进行时句子出现 244 次单向"压平"，mem0/Graphiti/Letta 同样）。schema 不能只有 content + updated_at；至少要 valid_from、invalid_at、supersedes/superseded_by、source_time/observed_time、certainty、temporal_scope；摘要文本本身要保留"目前/曾经/计划/已经停止"。
- **TWIST（arXiv 2609.28575）**：测"该不该主动发现冲突""是否把旧事实当当前""误触发不相关记忆"；flat-RAG 抓到 76–97% 真矛盾但把 16–43% 安全草稿误标为冲突，保守系统几乎不误报但只抓 42%。建议 20–50 条本地小测试（superseded 是否覆盖、无冲突是否乱报警、跨项目串召回、时间条件）。
- **MemFit（arXiv 2610.00872）**：每个 turn 原样 append-only 写入，segment summary 只做索引不替换原文，写入阶段不调 LLM；读取时 BM25 + dense + PRF + cross-encoder；写入时 LLM 调用减少 81–87%，代价移到读取侧。
- **Memori v0.7.1**：Rust + 单 SQLite + FTS5 + 384 维 embedding + RRF 的基准：FTS5 100K 条 1.49 ms，500K 7.5 ms；暴力向量 100K 172 ms、500K 904 ms；100K 库约 425 MB。10 万级 FTS5 远不是瓶颈，**暴力向量扫描先到延迟上限**；去重别全库 O(N) cosine，用 exact hash → FTS 近重复候选 → 小范围语义判断。
- **Auditable Long-Term Memory**：检索拆成 候选召回 → 重排 → 覆盖优先的证据包 → 确定性脚手架，LLM 只当最终 reader；评测分别记 candidate recall / rerank 后 recall / 最终注入 / 最终回答。
- MEX / TRW：真相源（人可读文本）与索引（FTS/vector/graph）分离，索引坏了重建；本地 store 要 checkpoint、restore 前 integrity_check、迁移失败回滚。
- 中文 FTS：unicode61 对连续中文不是真分词；trigram 对 1–2 字词不友好；建议写入/查询统一用中文 bigram/预分词或自定义 tokenizer；先把 BM25 + project/type/time 规则调好，向量只在 lexical 低置信、跨语言、同义改写时触发；融合用 RRF 不直接加原始分数；维护 50–100 条真实中文 query（Hit@1/5、跨项目误召回、supersede 正确率、p50/p95、空查询误召回）。

**对 Sumika 的直接建议**：facts 补 valid_from / invalid_at / temporal_scope / certainty；摘要提示词保留时间语义；做 20–50 条 supersede/冲突/时间条件小测试；检索按层记录 candidate recall / injected。

**与现状**：部分做。已有：原文只追加 + 派生可重建、RRF（k=60）、全文 trigram + LIKE 兜底两字词、向量 sqlite-vec、superseded 链。与笔记**不同**：现状是"全文 + 向量**每次都两路并行**取前 20"，笔记建议向量仅在 lexical 低置信时触发；现状 trigram（笔记指出对 1–2 字词不友好，现用 LIKE 兜底）而笔记建议 bigram/预分词。时间字段只有 status，无 valid_from/invalid_at。

### 基础 04｜行为学习：场景→动作→结果、反馈归因与社交策略

**核心结论**
- 初期建设可追溯的"互动经验样本"和离线策略评测，不在线 RL。"之后有人回复""对方笑了""群变热闹"都是弱信号，没人回复也不一定失败；稳定人格底线与隐私/规范是约束，不因参与回报高被改。
- 单条经验结构：Context（话题 ID、被 @、氛围可观察特征、关系证据、说话者、Bot 最近 N 次发言、角色状态）/ Options（当时可用动作含"不说"）/ Action / Outcome（观察窗口内的直接回应、纠正、负反馈、话题延续、管理员干预）/ Attribution（强信号：直接纠正、明示要求；弱信号：沉默、点赞、活跃度）/ Learning record（规则候选、适用场景、支持例与反例、置信度、首次/最后验证、过期条件）。不能从单次巧合学硬规则。
- 失败模式：错误归因（A 回 B 却当成 Bot 得奖励）、奖励投机（刷屏）、**自我污染（多个 Bot 互相回话把彼此编造的评价变成训练信号）**、人设侵蚀。小实验：100～200 个事件标注，必须含"保持沉默成功"。

**对 Sumika 的直接建议**：行为经验记 episode；多角色同群时 Bot 的反应不计入反馈（评估页已采纳）。

**与现状**：没做；评估页已采纳"Bot 反应不算真人反馈"这一规则，但代码里尚无落点。

### 基础 02｜QQ 群聊角色扮演 Bot：社交记忆与发言架构

**核心结论**（记忆相关部分）
- Event = stream_id + message_id + timestamp + actor_id + reply_to + mentions + thread/topic 候选 + modality + source_visibility；Conversation state = 多个活跃话题、各话题最后回复者、氛围（低置信短期）、Bot 自己的注意力和最近发言。
- 记忆分三类：Personal（只存个人明确透露的事实/偏好 + 溯源）、Group（共同经历、群内梗与共识，**必须保留反对意见**）、Relationship（有方向、随时间变化、带证据）；Persona = 稳定设定 + 长期关系 + 短期情绪/注意力，情绪是行为生成变量，不是心理诊断。
- 入口按真实 sender_id、群 ID 解析，不从昵称猜身份；无法确认对象就不写强人际事实。召回：短期话题态 + 该话题关键事件 + 相关人物**有权读取**的记忆 + 局部梗/风格 + 稳定角色约束；禁止未经授权跨群串入；回复后弱反馈只累积候选。参与率不能单独当奖励。
- GroupMemBench：最佳系统平均约 46.0%，知识更新约 27.1%，术语歧义约 37.7%（合成基准）。

**与现状**：部分做。事件日志含 reply/引用（规格-QQ渠道），个人 / 群 / 关系三类里"群记忆"和"关系"没做；话题拆分（对话链）在待办里单列。

### 扩展 14｜多 Bot 共享群聊：合作、互相接梗、社交压力与防回声循环（P2）

**核心结论**
- 主体必须分开：真人 / 已识别 Bot / 身份未知账户；已知 Bot 的发言不能用来"证明真人觉得这个梗好笑"；各 Bot 独立角色和任务单独保存，公共信息可同步，私人记忆需显式授权和访问边界。
- 避免虚假奖励循环（A 接 B 的梗，B 又接 A，系统误以为社区活跃、不断强化策略）；每个 Bot 独立承担"是否调用工具、引用来源"，不能互相传播"它说过所以对"。
- 协调数据：actor_type、bot_id、bot_lineage/任务、human_initiated、thread_id、reply_chain_depth、recent_bot_share、per_user_interruptions、permissions、source_provenance。多 AI 会增加参与者感受到的群体压力（CSCW 2025）。

**对 Sumika 的直接建议**：本地群聊里别的角色的话不进"独立佐证"和"真人反馈"。

**与现状**：评估页已采纳；代码未必有落点（发言防循环有，记忆/学习侧的"只统计真人"未见）。

### 扩展 33｜QQ 群 AI 低延迟：真人回复节奏、快慢路径与缓存并行（记忆相关部分：成本与缓存）

**核心结论**
- 并行：许可范围内的记忆检索、候选梗召回、媒体元信息和上下文编排可并行，有足够信息时可推测式预取，结果不用就丢；角色基础约束和工具定义放稳定前缀，群内最近信息放动态尾部，简短证据卡代替长篇重复叙述；用 `usage.cached_tokens` 确认缓存真的存在。
- 快路径靠非 LLM 门控（平台元数据、回复/@、权限、撤回、简单重复）；Planner+Replyer 合并难诊断；指标含 memory_start/end、cached_tokens、context_refresh。
- 起始 SLO（建议值）：快路径 P50 ≤ 2s / P90 ≤ 5s；普通短回复 P50 ≤ 4s / P90 ≤ 8s；没找到可靠的中文 QQ 熟人群真人响应分布。

**与现状**：ADR-011、ADR-016 已采纳并细化。

### 扩展 44｜Raft：人类与 Agent 平权身份、频道权限、长期协作和安全代理（FSL 许可，只借思想）

**核心结论**
- 所有读取路径（HTTP、实时推送、历史回放）都走同一个 canUserAccessChannel；日志/向量检索不能成为另一个未隔离的入口。Agent 是独立 principal（ID、授权、私有记忆、访问 scope、审核记录），只能经明示共享渠道读别的群。权限不因同在一群而继承。
- 守护进程以短期代理令牌访问服务，模型不直接得到服务端凭据。

**与现状**：已采纳（`canSee` 是唯一入口，评估页里的"所有读取路径同一个检查函数"）。笔记强调的"回放、日志、向量检索三个入口一致"对应 Sumika 的 `recall_raw`、注入面板、控制台旁听面板——需逐一核对是否都经 `canSee`（现状文档只写了"所有读取路径都要经过它"）。

### 基础 05｜交互习惯学习：回复节奏、表达偏好与个体适应

**核心结论**
- 学的是**交互政策**，不是人的内在性格，与画像分开。层次：明确偏好（高权重，如"不要每句 @ 我"，记录原文、范围、是否长期）/ 习惯性表达（统计特征，不等于喜欢被模仿）/ 条件式互动习惯（公开群 vs 私聊、被直接问 vs 路过）/ 群体约定（与个体偏好分开存）/ 短期状态（忙、不想展开，只本段有效，不贴标签）。
- 偏好记录字段：policy_id / scope(user|group) / condition(topic, channel, audience) / preferred_behavior / avoided_behavior / evidence_ids / source_type(explicit|observed|inferred) / confidence / valid_from,to / last_confirmed / contradictory_examples / overrides。优先级：当前明确请求与群规 > 历史明确偏好 > 多次低风险观察 > 角色默认；任何阶段不突破跨群隐私与角色安全边界。
- 收到明确纠正，下次相似场景立即生效，但只针对当前话题的新指令不覆盖全局；对 A 的风格不传播成全群偏好；不用"没回=不喜欢"、不用黏性当奖励；显式拒绝记忆/清除偏好优先。PrefEval：能检索到偏好不等于回复里遵守；PersonaMem：能复述偏好与能在新场景应用要分别验证。

**与现状**：部分做。facts.kind 有 preference / boundary，pinned 把有效约定和边界（≤600 字）每轮放入；没做 condition / scope=群 / overrides / valid_to / source_type 三档。
