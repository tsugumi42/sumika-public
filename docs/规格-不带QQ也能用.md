# 规格：不带 QQ 也能用（P2-1，过渡）

> 状态：已做完（2026-11-16）。三步都已合 main：第 1 步 e6280c56，第 2 步 37835eb6，第 3 步文档见本提交所在的合并。过渡限制挂在待办 P2-1 条，根治是 P5-7。来源：后续路线 P2-1、质检 X-04（`data/dev/fable-review/总报告.md` 第 119 行）、ADR-262 第 1 条（本地和 QQ 各算一个平台，关掉 QQ 本地照常能用）。参考：盘点 `data/dev/research/盘点-无QQ账号进可写状态-.md`（下文“盘点第 N 条”指它）；[规格-多平台装配](规格-多平台装配.md)；ADR-209（双击只看历史）、ADR-227。根治是 P5-7（平台监督器，每个平台单独启停），这一步只做过渡。

## 开工卡

- **我理解成**：配置里没有 QQ 小号的机器（不管数据目录是不是全新的），打开 Sumika 就能本地私聊、本地群聊、写记忆；配了小号的全新目录，第一次启动也不再卡住，先初始化再照旧进只看历史。宿主多一个阶段“本地可用（QQ 没开）”，在这个阶段里，后台按接收模式打开，只是不装 QQ 那一块（适配器、令牌、发送锁、补录、收图、转发、名册里的 QQ 账号）。
  - 已经配了 QQ 小号的机器，启动、开始接收、停止接收的行为一格不变。
  - 正例：新装、配置里一个 QQ 小号都没有 → 双击 → 状态“本地可用（QQ 没开）” → 在本地私聊说一句，她照常回、照常能“记住”。
  - 反例：
    - 把“没有账号”当成放宽 QQ 发送门的理由；
    - 整个跳过 `openChannel`，关机和链接插件拿到 nil；
    - 在 `app` 里到处写 `a.account == ""`；
    - 全新目录不管三七二十一都 `paths.Init`，把旧布局目录、没恢复完的目录也初始化了。
- **领域正统做法**：
  - 一个宿主带多个可独立启停的“通道 / 平台运行体”，主体（会话、存储、内核）不依赖任何一个通道在不在。比如 Matrix 和 Telegram 的桥接器、Home Assistant 的集成，单个集成没配置或加载失败，核心照常运行，状态页写清“这个没开”。
  - 我们的根治版是 P5-7。这一步先在装配处把 QQ 收成一个可选单元（`openQQUnit`），作为 P5-7 的缝。
- **最省事的字面做法够不够**：只删 `app.go:311` 那句“receive 必须指定 -account”不够。同一条路上还有四个硬停点和一个会 panic 的地方（盘点第 0 条：`pickAccount`、`checkModels` 读空角色、`tokens[0]` 越界、名册校验、补录 typed-nil）；而且全新目录在只看历史这一步就失败，托盘按钮也是灰的。
- **不做什么**：
  - 不做每个平台单独的开关和设置项（ADR-262 第 2、3 条，P5-7）；
  - 不改已有 QQ 小号的用法；
  - 不删 `qq` 平台库的登记（过渡期照旧建 `qq.db`，盘点第 4 条）；
  - 不改 QQ 发送门的任何一项；
  - 不做首次设置向导（P2-8）。
- **用户能看能试的验收**：见“验收”第 1、2 条。

## 设计

### 1. 数据目录“还没初始化”是一种明确的错误

- `paths` 加一个可以用 `errors.Is` 判断的 `ErrUninitialized`。只在这两种情况下返回：
  - 目录不存在；
  - 目录存在、没有 `sumika-data.json`、不是旧布局（`ErrLegacy`）、不是没恢复完（`ErrRestoreIncomplete`），**而且顶层只有白名单里的东西**：`config/`（配置就放在这里，主人或向导可能先写好配置）、`characters/`（角色卡）、`models/`（嵌入模型的默认位置）。
  - 只要有别的东西，比如 `go/`、`shared/`、任何 `.db`、`backup/`、`logs/`，就**不算**没初始化，照旧报“没有身份证”。理由：有数据、只是丢了身份证的目录（包括更新的版本建的），不能被盖上格式 1。
  - 身份证读坏了，也不算“没初始化”，照旧报原来的错。
  - 今天 `cmd/sumika-go/main.go:156-166` 和 `app.openDataDir` 各有一套“目录不存在就 `Init`”的判断，改成都调这一个函数，不另造一套。
  - 别处不许再靠匹配错误文字来判断。
- 只看历史模式（archive）**从不初始化**，照旧报错（`startup_test.go:49-57` 钉着：不建目录、不建库、不读令牌、`alerts == nil`）。
- 接收模式（含下面的“只开本地”），遇到 `ErrUninitialized` 才调 `paths.Init`；其余错误照旧失败。今天 `openDataDir` 只给“目录不存在”的情况 `Init`，改成照这个错误判断（`app.go:1027-1041`）。

### 2. 后台：只开本地（`app.Options.LocalOnly`）

- `Options` 加 `LocalOnly bool`，只在 `Mode == Receive` 时有意义。
  - `LocalOnly` 为真时 `Account` 必须为空，否则报参数错误。
  - `LocalOnly` 为假时，照旧要求 `Account`，`TestReceiveRequiresAccountBeforeStores` 的意思不变，只改报错文字里的建议。
- **QQ 收成两段，顺序和今天一样**（今天的顺序是：校验和取值在开库之前，`app.go:402-415`；装配在开库之后，`channel.go:125/170`）：
  - **建库前的一段** `prepareQQ()`：`pickAccount`、URL 检查、`a.account`、`a.character`、`tokenFor`。账号非空时，缺 URL、缺令牌、号没配置，都照今天一样在建库之前失败，不许挪到建库之后。
  - **装配处的一段** `openQQUnit()`：`checkModels` 里 QQ 角色那部分、`snowluma.NewWS`、名册里的 QQ 账号条目、`takeSendLock`、`openBackfill`、收图 `media`、转发 `forwards`，以及远程审批和链接展开里绑定 QQ 账号的部分。
  - `LocalOnly` 时两段都不调。账号非空时，每一种失败的先后顺序都和今天相同。
  - `openChannel` 照常建 `gate`、`outlet`、`intake`、`chain`、`pipeline`、`responder`、`modeOf`（关机、链接插件、提醒、远程审批、`checkQQSend` 都要用，盘点第 3 条），只是名册里没有 QQ 账号、出口里没有 QQ 适配器。
  - 这一处标 `临时：P2-1 过渡，P5-7 换成平台监督器`，挂待办。
- `a.alerts` 挪到账号判断之前建（今天在账号块里，盘点第 3 条那张表）。
- **空单元的 nil 坑一个个堵**：补录、收图、转发在 `LocalOnly` 时不建，桌面补录页拿到的是 nil，回“这次没开 QQ”（`desktop_backfill.go:146-153` 已有这一支）；`tokens` 保持 nil；不依赖“没有 QQ 事件就不会调到”。
- **`a.character` 是空串时**：
  - 本地回合用会话里的角色，不读 `a.character`，要有测试证明；
  - `displayCharacters` 的文案改成“这次没开 QQ”，不再标“没有接收”；
  - `selftestCharacter` 照旧退回目录里的第一个角色。
- QQ 发送门一个字都不改（`send.go`、`channel.go` 的 `qqSendMode`、`checkQQSend`）：没有 QQ 单元，QQ 的两格就是不收不发。
- **空对空**：本地会话的 `AccountID` 本来就是空串，`LocalOnly` 下 `a.account`、`a.character` 也是空串。任何没有先判断渠道、就直接拿它们去比较的地方，会从“永远不相等”变成“相等”。
  - 第 1 步先把非测试代码里所有拿 `a.account`、`a.character` 做比较的地方列成清单，至少包括 `clientinfo.go:48`、`lifewire.go:171`、链接的 `outletMode`、`remoteapproval.go:46`、`qqOwnerConv`。逐处写清“空对空会不会成立、成立了会放开什么”。
  - 会成立的，在比较前加“账号非空”的判断，或者先判渠道。每一处都有测试。

### 3. 宿主：多一个阶段“本地可用（QQ 没开）”

- 新阶段 `phaseLocal`，界面文字是“本地可用（QQ 没开）”。
  - `Mode` 是 `Receive`，有 `Reader`、有 `Memory`。
  - `ctlproto` 的状态和 `sumika-ctl status` 的显示跟着加这一种，`Receiving` 为假。
- **启动**（`host.start`），规则只看“配置里有没有 QQ 小号”，每次启动结果都一样，不随“是不是第一次”变：
  1. **配置里一个小号都没有**：直接开“只开本地”（`pickReceiveAccount` 在开后台前就知道结果，不用先开一次只看历史），它遇到 `ErrUninitialized` 会初始化目录 → `phaseLocal`。
  2. **配置里有小号、目录已初始化**：照旧开只看历史 → `phaseArchive`。这是主人现在的情况，一格不变。
  3. **配置里有小号、目录是 `ErrUninitialized`**：调一个只做初始化的函数 `app.InitDataDir`（写身份证、建空的平台库和 trace，然后关掉），再照第 2 条开只看历史。只看历史本身照旧不初始化。这样第一次和以后每次启动，都停在同一个阶段。
  4. 其它失败照旧进 `blocked`。
- **示例卡**：只有“这次启动刚初始化了目录、而且配置里一个小号都没有”时，才从资源根复制自带示例卡到 `characters/example/card/`：先把整张卡写进同目录的 `characters/.example-tmp-*`，全部写完再改名过去；目标已存在不覆盖；源文件必须是普通文件（链接、目录不复制），每个不超过 1 MiB。有小号的全新目录不复制——小号绑的角色由主人自己放卡。
- **宿主里所有判断阶段的地方**：第 2 步先 grep 所有 `phase*` 的比较和 `Mode != Archive` / `Mode == Receive` 的判断，例如 `host.go:473` 把“不是 archive”当成 blocked。逐处写清 `phaseLocal` 在那里算什么，列进交回。
- **开始接收 QQ**（托盘、`sumika-ctl receive start`、自动接收）：
  - 今天只从 `phaseArchive` 出发。改成从 `phaseArchive` 和 `phaseLocal` 都能出发，挑小号的规则不变：显式给的，或者配置里恰好一个；零个和多个照旧不能开，写原因。
  - 从 `phaseLocal` 出发时，先关掉“只开本地”，再按完整接收打开。注意这是**关掉一个正在写的后台**：只看历史没有回合，本地可用是有回合的。
    - **手动开始**（托盘、`sumika-ctl receive start`）：本地有回合在跑时拒绝，写明“本地有回合在跑，等它结束再开始接收”，不切断回合。
    - **自动接收**：在拆后台之前先做便宜的检查，不拆后台。检查项：选得出小号、配置里有 URL 和令牌、协议端地址能连上（TCP 连一下就断）、本地没有回合在跑。都过了才拆；没过就留在本地，按原来的重试间隔下次再查。不许“关本地 → 开完整失败 → 再开本地”这样来回拆，那样会反复切断回合、重启嵌入。
  - 打不开时，照旧回到出发时的阶段：从本地出发就回本地，从只看历史出发就回只看历史，不进 `blocked`。除非连出发时的阶段都回不去，那才进 `blocked`，和今天一样。
- **停止接收 QQ**：照旧回只看历史（主人现在的用法不变）。“停止以后本地照常能写”属于 ADR-262 的完整做法，P5-7 再做；规格写明这是已知的过渡限制，挂待办。本地可用阶段调“停止接收”不动后台：回“现在没在接收 QQ（只开了本地）”，阶段、本地私聊、正在跑的回合都不受影响。
- 托盘的“开始接收 QQ”在 `phaseLocal` 时：有可选的小号就能点，没有就灰着，提示照旧是 `NoRecv`。
- 自动接收（`autoreceive.go`）：判断条件从“当前是 `phaseArchive`”改成“当前是 `phaseArchive` 或 `phaseLocal`”。

### 4. 命令行 `sumika-go`

- 加 `-local-only` 参数，等于 `LocalOnly`；和 `-account` 同时给就报用法错误。
- 不给 `-account` 也不给 `-local-only`，照旧报“要 -account”（`main_test.go:51-68` 的意思不变），只在用法说明里加一行 `-local-only`。

## 验收

1. **全新目录、没有小号**（app 层）：
   - 目录存在，`data/config/sumika.yml` 里没有 `qq.accounts`，没有身份证，`LocalOnly` 打开以后：
     - 身份证写好了，local 库可用；
     - `a.adapter == nil`、名册里没有 QQ 账号、`a.backfill == nil`；
     - 本地私聊发一句，经假模型有回复；
     - `remember` 能写（P1-3 的默认开）；
     - 关掉再打开，照旧能用。
   - 再加一条：目录不存在时同样能用。
2. **宿主**：
   - 零小号的配置，宿主启动后停在 `phaseLocal`，本地私聊可写；全新目录和已初始化目录结果相同；
   - 有一个小号的配置，宿主启动后停在 `phaseArchive`（不变）；全新目录先初始化、再进 `phaseArchive`，第二次启动结果相同；
   - 本地有回合在跑时手动开始接收：被拒绝，回合不受影响；
   - 自动接收在协议端连不上时：留在 `phaseLocal`，不拆后台，回合不受影响；
   - 有一个小号时，从 `phaseLocal` 开始接收，进 `phaseReceiving`，失败的话回 `phaseLocal`；
   - 两个小号、没指定时，开始接收照旧被挡；
   - `sumika-ctl status` 显示“本地可用（QQ 没开）”。
3. **四种场合 × 三种入口**（高风险，AGENTS 第 7 条）：一张表测全。
   - 行：本地私聊、本地群聊、QQ 私聊、QQ 群，再加两行：空账号、空角色（设计第 2 条“空对空”清单里会成立的每一处）。
   - 列：只开本地、完整接收（一个小号）、只看历史。
   - 每格断言能不能写、发送门结果。
   - 完整接收那一列的结果必须和改动前一模一样：`send57_*`、`send57_more_*`、`send_taskrun_*` 原样通过，预期不改。
4. **不该初始化的照旧报错**：下面这些目录用“只开本地”打开都报原来的错，不写身份证、不写任何文件：
   - 旧布局目录；
   - 没恢复完的目录；
   - 身份证读坏的目录；
   - 有数据（`go/` 或任何 `.db`）、只是没有身份证的目录。
   - 只有 `config/`、`characters/`、`models/` 的目录：会初始化。
5. **账号非空时的失败照旧在建库之前**：显式给了没配置的小号、小号没写 URL、取不到令牌，三种都在建库之前失败（`assertNoStores` 那套断言）。
6. **改坏检查**：
   - 把 `LocalOnly` 的判断改成“任何 QQ 单元失败都退回只开本地”，验收 3 的完整接收列要红；
   - 把 `ErrUninitialized` 的判断改成“任何 `paths.Open` 错误都初始化”，验收 4 要红。
   - 证据存 `data/dev/review-p2-1/`。

## 禁止的偷懒写法

- 在 `send.go` 或 `qqSendMode` 里加“没有账号”的分支。
- 整体跳过 `openChannel`。
- 用错误文字匹配判断“没初始化”。
- 只看历史模式里初始化目录或建库。
- 为了过测试改 `send57_*` 的预期。
- 把 `qq` 从平台登记里去掉。

## 已知的坑（照盘点）

- `tokens[0]` 越界（`channel.go:170`）。
- 补录、收图、转发拿到 typed-nil。
- `a.alerts` 建得太晚。
- 托盘和 `NoRecv` 一个字段兼两种意思：“没有号”和“号太多没指定”，要拆开。
- 停止接收以后本地也跟着不可写（过渡限制，P5-7）。
