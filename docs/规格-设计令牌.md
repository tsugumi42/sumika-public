## 一、要解决什么

界面写法在 Bun、Go 两条线上都反复不统一。Go 里现在有三套令牌加一套文档词汇：`chatui.Tokens`（578 处引用，按 字号 ÷ 15 缩放）、`winshell.Geometry` 和 `winshell.Palette`（630 处，按 ÷ 16）、`cmd/sumika-proto` 的包级变量（194 处），文档里还有 `surface`、`s2`、`r-ctl` 这套名字。同一份默认设置下：正文 16 对 15、行高 25.6 对 22.5、间距 8.5 对 8、气泡圆角 18.8 对 16、控件高 38.3 对 40 / 32 / 36、面板动效 230 对 250 毫秒（方案笔记里的临时测试）。

目标：

1. 设计语言有**一个源头**，和编程语言无关；Go 的常量由它生成，以后 TS 加一个生成目标即可。
2. 源头自带兜底：缺了的退回上一层，生成器把错误挡在提交前。
3. 写死值有检查拦着，不再靠自觉。
4. 每个组件有语言无关的规格、能运行的例子和画廊，一份例子同时用来展示、测试、截图。

不在本规格里：主题编辑页（简单档、复杂档，要先问主人，待办“主题编辑分简单、复杂两档”）、外观页滑块改名、高对比模式的配方、网页版展示站的部署。

## 三、令牌文件

### 3.1 三层

| 层 | 文件 | 放什么 | 谁能引用 |
|---|---|---|---|
| 原料 | `primitive.tokens.json` | 中性色配方、语义色原色、角色色默认值、间距 / 字号 / 圆角 / 控件高的基础刻度、动效时长、曲线、弹簧 | 只有语义层和生成器 |
| 语义 | `semantic.tokens.json` | 按用途起名，名字用设计语言那套（第四节） | 所有组件 |
| 组件 | `component.tokens.json` | 某个组件自己的量，默认是语义层的别名 | 只有该组件所在的包（生成器按 `$extensions.sumika.owner` 检查） |

组件层一个令牌都没写的组件，直接用语义层；写了的必须是语义层的引用或第 3.3 节的计算，不许写字面量（生成器拦）。

### 3.2 模式（Resolver）

`resolver.json` 照 Resolver 2025.10 写，modifier 有三个，只覆盖**原料层**：

| modifier | 取值 | 覆盖什么 |
|---|---|---|
| `appearance` | `light`（默认）、`dark` | 中性色和语义色配方的亮度、彩度倍数；字重各减 40；阴影 |
| `neutral` | `cool`（默认）、`plain`、`warm` | 中性色相和彩度：250°/0.008、250°/0.002、70°/0.008 |
| `wallpaper` | `on`（默认）、`off` | 聊天区底色和她的气泡：有壁纸时聊天底 = 窗口底、气泡 = 内容层；没壁纸时聊天底 = 内容层、气泡 = 凹块（Bun chat.css:116-120；第 2 步写令牌时发现 chatui 按这个设置切换，原规格漏了） |

语义层和组件层不分模式：深色字重减 40、深色阴影这类随模式变的值，原料层各放一份（`primitive.weight.*`、`primitive.shadow.*`），语义层的 `font.weight.*`、`elevation.*` 只是它们的别名。生成器把 2 × 3 × 2 = 12 种组合都算出来，生成 12 份表。高对比留作以后加的第三个 modifier，现在不写空壳。

### 3.3 三个计算（只有这三个能做算术）

规范里没有算术，计算写在令牌的 `$extensions.sumika` 里，`$value` 写**默认模式、默认设置下算好的结果**，读不懂扩展的通用工具照样拿到一个合法值；生成器核对 `$value` 和自己算的一致（不一致报错，防止手改漂移）。

1. **palette**（颜色）：原色直接写 DTCG 的 `{"colorSpace": "oklch", "components": [L, C, H]}`；算出来的颜色在 `$extensions.sumika` 里写下面五种之一（参数可以是数，也可以是指向数的引用）：
   - `"neutral": {"l": 明度, "k": 彩度倍数}`：中性色，色相和彩度取原料层 `neutral.hue`、`neutral.chroma`；
   - `"alpha": ["{颜色}", 不透明度]`：同色换不透明度；
   - `"shift": ["{颜色}", 明度差]`：oklch 明度加减；
   - `"reach": {"base": "{颜色}", "min": 对比度, "away": 方向, "against": ["{底色}", …]}`：沿明度往 `away`（+1 变亮、−1 变暗，原料层 `contrast.away` 随亮暗翻转）推到对每个底色都达标，推到头也不够就报错（现行 `chatui.reach`）；
   - `"over": {"fg": "{颜色}", "bg": "{颜色}", "k": 浓度}`：sRGB 里叠色，`k` 省略时用前景自己的不透明度。

   模式可以枚举（12 种），所以这些颜色在**生成期**算完、写成表。只有角色色是运行时输入：`accent.recipe.*` 存配方，运行时 `design.AccentOf(角色色)` 按配方算（现行 `chatui.deriveAccent`、`strongOf`）。
2. **scale**（缩放）：每个尺寸令牌标一个轴 `"axis": "text" | "space" | "radius" | "fixed"`。系数 `kt = 字号 / 16`、`kd = 疏密 / 8 × kt`、`kr = 圆角 / 12 × kt`；**默认设置下系数为 1，所有尺寸都是整数**。缩放后取整到整数逻辑像素；设备像素对齐交给 mygo（绘制时每条边按设备像素取整，`ui/paint.go:170` 的 `snap`），令牌不再二次对齐：二次对齐会把 125% 下默认的 6、18 改成 6.4、18.4。
3. **concentric**（同心）：只有三种写法：`{"wrap": [里层, 距离]}` = 里层 + 距离；`{"inner": [外层, 距离]}` = max(min(`radius.inner-min`, 外层), 外层 − 距离)（下限不超过外层：圆角滑块拉到最小时外层可能只有 3，里层不能比它圆）；`{"half": [尺寸]}` = 尺寸 / 2。先缩放、再同心、最后对齐像素。

每个计算在 `native/internal/design/testdata/vectors.json` 里有一组标准输入输出（每个计算至少 20 组，含边界值），Go 实现跑它；以后的 TS 实现跑同一份。

例：

```json
{
  "radius": {
    "ctl": { "$type": "dimension", "$value": { "value": 12, "unit": "px" },
             "$extensions": { "sumika": { "axis": "radius" } } },
    "1":   { "$type": "dimension", "$value": { "value": 18, "unit": "px" },
             "$extensions": { "sumika": { "concentric": { "wrap": ["{radius.ctl}", "{space.s1-5}"] } } } }
  }
}
```

### 3.4 生成器

- `native/internal/design/gen/`（Go 程序），`design` 包里写 `//go:generate go run ./gen`。用 Go 不用 Bun：生成产物是 Go，构建界面不该多依赖一个运行时。
- 产物 `native/internal/design/tokens_gen.go`，头一行 `// Code generated by internal/design/gen from tokens/*.tokens.json. DO NOT EDIT.`，生成后跑 gofmt，统一 LF。
- **必须报错退出**的情况（每种一个坏输入样例做测试）：引用不存在的令牌、循环引用、同名（含生成后 Go 名字撞车）、`$type` 和值不符、组件层写字面量、组件层直接用原料、组件令牌引用别的组件（按 `owner` 查）、`$value` 和计算结果不符、resolver 引用不存在的集合或取值、扩展里出现不认识的键、对比度要求解不出来。
- 不做运行期读 JSON：数值在生成期定死。
- 组件令牌被 `owner` 以外的 Go 包引用，生成器看不到，由第七节的 archcheck 查（第 5 步上线）。
- `go run ./gen -fix`：把算出来的令牌（中性色、对比度、同心）的 `$value` 改写成算出来的值再生成；改配方后跑它，不带 `-fix` 时不一致就报错。

## 五、兜底

| 兜底 | 什么时候 | 做法 | 验收 |
|---|---|---|---|
| 别名兜底 | 生成期 | 组件层没写的退回语义层；第 3.4 节那些错误直接报错。生成出来的 Go 没有“缺字段”，所以不做运行期查缺 | 坏输入样例逐个红 |
| 通用工具兜底 | 交给别的工具时 | `$value` 永远是默认模式的合法值 | 生成器核对 `$value` |
| 主题桥 | 运行期 | `design.Theme(模式, 设置, 字体) ui.Theme` 是全仓**唯一**构造 `ui.Theme` 的地方；没专门画过的 mygo 控件（焦点环、滚动条、读屏）也用我们的颜色和圆角。现在 `winshell.NewTheme`、`chatui` 的 `MenuTheme` 合进来 | archcheck 第 7.5 条 |
| 特效降级 | 不支持、关掉、减少动效 | 每个特效和组件写“降级成什么”：超椭圆 → 圆弧（Windows 现状）、玻璃 → 实色、弹簧和位移 → 只淡入、壁纸 → 纯色 | 组件规格的“降级”一节都有对应的目录例子 |

## 六、组件规格和 API 约定

### 6.1 组件规格的格式（`docs/组件规格/<族>.md`）

每个组件一节，固定七段：**结构**（几块、谁包谁，配一张线框）、**尺寸档**、**状态**（平时、悬停、按下、键盘焦点、禁用、加载、选中、错误，不适用的写“不适用”和原因）、**令牌**（用到哪些，组件层新加的写出别名）、**键盘**、**降级**、**例子**（对应的目录 ID）。不写 Go 代码，换语言照样能用。

### 6.2 Go 组件 API 约定（照 CrychicUI，按我们的情况改）

1. `func Name(c *ui.Context, 必填…) ui.Element`；可选项放最后的 `NameOptions`，零值就是默认样子，不用可变参数串布尔。
2. 容器把内容放在最后一个 `func()`，在选项之后；有多个动作的返回多个具名 `ui.Element`，根元素在前。
3. 有状态的组件由调用方给 key（`c.Key`）；自己的私有状态放 `ui.Local`；元素不跨帧保存。
4. 绑定值的组件收 `*T`，用户改了就在返回的元素上 `SetChanged`。
5. 每个交互组件的状态切换用 `motion.*` / `spring.*` 令牌，不写毫秒；“减少动效”交给 mygo。
6. 组件里出现的文字由调用方给。
7. 编程错误直接 panic，信息写 `"包: 组件 %q 需要……"`；不吞错误。
8. 尺寸、颜色、动效只从 `design` 取（第七节检查）。

## 七、检查

全部做进 `native/internal/archcheck`（它在每次 go-verify 里都跑），用 Go 的语法树而不是正则。

| 编号 | 拦什么 | 范围 |
|---|---|---|
| 7.1 颜色 | `ui.RGB` / `ui.RGBA` / `ui.Hex` 调用、`ui.Color{…}` 字面量 | 界面包（`internal/chatui`、`internal/winshell`、`internal/uikit`、`internal/catalog`、`cmd/sumika-proto`、`cmd/sumika-gallery`、根包里 import 了 `mygo/ui` 的文件），不含测试和生成文件 |
| 7.2 尺寸 | 元素方法 `Padding*`、`Margin*`、`Gap`、`Radius`、`Width`、`Height`、`Min*`、`Max*`、`FontSize`、`Border`、`Shadow`、`Left/Top/Right/Bottom` 的参数里出现数字字面量；只放过 `0`、`1`（细线）和乘除 `2` | 同上 |
| 7.3 动效时长 | `ui.Animation{}`、`ui.ElementTransition{}`、`ui.SpringOptions{}` 字面量里的数字，以及传给 `Animate*`、`Transition` 的时长字面量。行为计时（“已复制”显示多久、防误点）写成具名常量，不拦 | 同上 |
| 7.4 藏数 | 界面包里 `float32` 类型或无类型浮点的包级常量、变量（防止把数挪成 `const pad = 7` 绕过 7.2） | 同上 |
| 7.5 主题桥 | 构造 `ui.Theme{}`、调用 `ui.LightTheme()` / `ui.DarkTheme()`、给 `ui.Theme` 值的字段赋值（`th := *c.Theme(); th.Radius = …` 这种复制再改）。菜单等派生主题也由 `design` 提供 | 除 `internal/design` 外全仓 |
| 7.6 分层 | 第二节的层次只许往下引用；`internal/design` 只依赖 mygo 和标准库 | 全仓 |
| 7.7 令牌类型 | 名为 `Tokens`、`Palette`、`Geometry` 的类型只许 `internal/design` 声明 | 全仓 |
| 7.9 时长常量 | 界面包里 `time.Duration` 类型的包级常量、变量，行尾必须有 `// 行为计时：<原因>`（“已复制”显示多久、防误点这类）；没有就红。动效时长只能来自 `motion.*`，堵住 `const mdFade = 130 * time.Millisecond` 再塞进 `ui.Animation` 的绕法 | 界面包 |
| 7.8 生成新鲜度 | 测试里在内存跑生成器，和提交的 `tokens_gen.go` 比字节（统一 LF 后） | `internal/design` |

放行：同一行末尾 `// 微调：<原因>` 或 `// 自有尺寸：<原因>`，原因不能为空（例：滑块轨道、时间刻度自己的尺寸）。

基线：`native/internal/archcheck/testdata/design_baseline.txt`，一行 `文件|函数|编号|次数`，**只许变少**；新文件、新函数、次数变多都红。迁完一族删一族的行。7.7 的基线现在是 `chatui.Tokens`、`chatui.Palette`、`winshell.Geometry`、`winshell.Palette`；7.5 的基线现在是 `winshell.NewTheme`、`chatui` 的菜单主题和原型的主题构造；薄壳删掉时一起删。

## 九、禁止的偷懒

- 组件里写死颜色、尺寸、动效时长；把数字挪成包级常量、函数参数默认值或 `t.S2 + 3` 来绕过检查。
- 用 `c.Theme().Space(1.5)` 这类 mygo 主题倍数代替命名档。
- 在 JSON 里手写算好的数而不标轴或计算（`$value` 只是结果的副本）。
- 为了过检查往基线里加行、改放行注释的格式、扩大放过的数字。
- 运行期读令牌 JSON，或拿 `ui.LightTheme()` 的默认值兜底缺的语义色。
- 薄壳期间新代码用旧名字（`S2`、`SpaceSmall`、`Ink`……）。
- 迁移时顺手改数值：第 2 步数值一个都不许变，变化只发生在第 3 步主人挑过之后。
- 目录例子用占位数据，或只摆平时一种状态。

## 十一、已知的坑

- mygo 绘制时每条边各自按设备像素取整（`paint.go:170`），125% 下两个 6 的内边距可能画成 7、8 个物理像素；要严格相等的地方（四边等距）在第 4 步用真窗口截图量。
- `cmd/sumika-proto` 的包级变量在 `init` 和 `applyLook` 里重算，迁移时它也改成读 `design`，不然原型和正式界面又是两份。
- `chatui` 几乎每个文件都引 `Tokens`，薄壳要保持字段名不变，否则第 3 步的提交会碰到全部文件。
- 颜色计算在 Go 的 `float64` 下做，`vectors.json` 的期望值写到 sRGB 的 0～255 整数，避免以后 TS 实现因为浮点差一位就红。
- Windows 上 `gofmt -l` 对 CRLF 不准，新鲜度测试先统一换行再比。
- 根包里有 43 处写死尺寸散在设置、链接页面等文件，旧界面退役前有的不值得迁，进基线就行。
- Resolver 2025.10 的 `version` 取值规范自己就不一致（表里 `2025-10-01`、正文 `2025-11-01`），`resolver.json` 写 `2025-10-01`，生成器只要求有这个键。
- 数（配方、浓度）在生成代码里用 float64：0.9 截成 float32 会让叠色取整差一档（第 2 步对拍时踩过）。chatui 自己把 diff 淡底浓度存成 float32，所以暖色亮色下 `color.danger-text` 和 chatui 差一档，对比度照样过线，对拍测试里登记了这一处。
- DTCG 颜色模块支持 oklch 来自发布公告，颜色模块 4.2 节原表没抓到；第 2 步写生成器前再核一次 `colorSpace` 的拼写。
