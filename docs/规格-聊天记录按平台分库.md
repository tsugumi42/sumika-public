## 一、要什么、不要什么

- **分**：Go 后台的原始聊天记录按平台各一个库文件。本地（主窗口、本地群聊、本地话题）一个，QQ（实时和补录的消息、通知、平台消息号、补录进度、人、群、表情包这些 QQ 独有的表）一个，以后 Telegram、微信各一个。平台独有的表只在那个平台的库里。
- **不分**：长期记忆（每个角色一份，跨平台，带可见性）；运行记录 trace（回合、步骤、模型调用、闸门判断，一个共享文件）；角色卡、配置。
- **Bun 不动**：Bun 冻结，`data/shared/events.db` 一个库到退役为止。Go 不写它（`CheckDBPath` 照旧拦）；只读打开它做对拍、第 7 步导入。

## 二、文件和登记

- Bun 退役前 Go 的库都在 `<数据目录>/go/` 下：
  - `go/chat/local.db`、`go/chat/qq.db`，以后 `go/chat/telegram.db`、`go/chat/wechat.db`；
  - `go/trace.db`（共享）。
  - 角色的记忆库照记忆线自己的安排（`characters/<id>/` 下，见规格-记忆-v2 13.1），这份规格不管。
- 切换日（Bun 退役）把 `go/chat/` 搬进数据目录规格第三节的结构（`shared/chat/`），同时改那一节；挂在待办"切换日"那条。
- **平台名**：小写字母、数字、连字符，1 到 32 个字。只在一处登记"渠道 → 平台"：`store` 包里的 `PlatformOf(channel) (string, error)`，和它旁边的 `PlatformOfConversation(会话) (string, error)`（取会话串第一个 `:` 前的渠道再查 `PlatformOf`；内核很多入口只拿得到会话串，后端会话 2026-10-27 提的）。现在登记两条：`console`（主窗口、本地群聊、本地话题，凡是 `Audience.Channel == "console"` 的都算本地）→ `local`；`qq` → `qq`。没登记的渠道返回错误，不落进别的库。
- `paths`：加 `ChatDB(platform)`、`GoTraceDB()`；原来的 `EventsDB()`、`TraceDB()` 改名 `BunEventsDB()`、`BunTraceDB()`，只给只读对拍和导入用（`core-check`、`memory-eval`）。`snowluma.GoDBPath`（`<数据目录>/go/events.db`）删掉，和 `paths.EventsDB()` 两处矛盾的说法统一成上面这一套；`CheckDBPath` 对每个平台库都查一遍。

## 四、引用规矩

1. seq 只在一个库里唯一。任何地方存或传 seq，都和会话一起；按会话的渠道（`PlatformOf`）选库。草图附录第 3 条"(channel, seq) 一起存"升级成这一条。
2. 只按 seq 查库的两处要补会话：`store.EventRow`（闸门 `gate.go:525` 调）加会话条件，选错库时取到空、不会取到别的平台那一行；记忆的 `EventSource.Revoked(seqs)` 改成带会话（现在没有调用方，趁早改）。
3. 一条消息只能引用同一平台里的消息：`reply_to`、`event_links` 两端都在同一个库。本地话题回复 QQ 消息这种跨平台引用暂不支持；要做时另写 ADR。
4. 不用改的（都已经带会话）：记忆的 `facts`、`episodes`、`summary_state`、`memory_jobs`、`fact_evidence`；trace 的 `steps.event_seq`、`gate_decisions.seq`、`outbound_hits.event_seq`、`gate_state`（键是角色加会话）；内核的 `Live.seen`、`done`、`turnSeqs`（挂在会话下面）；`turn.Seen`。
5. 闸门规则和档位里的 `'*'`（所有群）照旧是"所有平台的所有群"；第二个平台接进来时再定要不要按平台分，挂待办。

## 六、禁止的偷懒写法

- 不许"取不到平台就落到本地库"：没登记的渠道报错（LESSONS"兜底的分支只能收紧"）。
- 不许各处自己拆会话串选库：手上有 `Channel` 的（中间件的 `Conv.Channel`、内核的 `Audience.Channel`）用 `PlatformOf`；只有会话串的（内核的压缩、插话、停止、补读，记忆的事件来源）用 `PlatformOfConversation`。别处不许再写拆串选库的代码；记忆包自己的 `ChannelOf` 只管记忆的范围判断，不拿来选库，两者的拆法要一致（memsource 里有一个对照测试）。
- 不许只按 seq 查库；不许把裸 seq 存进新表而不带会话。
- 不许每个平台建一个 Hub；不许 `SweepInterrupted` 跑不止一次（第二次会把正在跑的回合当成上一个进程没收尾）。
- 不许改 `migrations/events/0001_baseline.sql`；不许在 Go 侧以读写方式打开 Bun 的 `shared/` 下的库。
- 不许用 ATTACH 做跨库联查：需要跨平台的（记忆翻原话、启动扫描）在 Go 里分别查再合并。

## 七、已知的坑

- 每个库 `SetMaxOpenConns(1)`：事务里不能再碰同一个库的别的连接，更不能顺手查另一个平台的库。现在的事务都在一个库里，加新事务时照这条。
- goose 的版本表：通用迁移和平台迁移如果共用一张版本表，编号会撞，见第三节。
- trace 共用一个连接：几个平台的 `Store` 拿的是同一个 `*sql.DB`，`Close` 只关一次；测试里"关两次"要不报错。
- 跨库合并按时间排：同一毫秒的两条要有确定的先后（平台名、seq），不然两次查的结果顺序会变。
- 关机顺序（待办装配那条）不变，只是"关库"一步变成关几个平台库、一个 trace、各角色的记忆库；记忆插件停掉以后才关，因为事件来源拿着这些库的连接。
- `AppendPlan` 一个事务写事件、她看到了、出站计划和段：出站计划必须和事件在同一个平台库，选库时按会话选，不按账号选。
