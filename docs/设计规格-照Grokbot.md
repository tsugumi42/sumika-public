## 二、设计哲学

1. **用相邻底色和留白分层，线只标边界和可操作的对象。** G-L `els[0]` 侧栏 rgb(245,243,242)，C1 body 画布 #f9f8f7，`els[73]` bot 气泡 rgb(240,239,237)、无边框无阴影；O-L `els[149]` 选择卡才加 0.8px 暖黑 8% 细线。
2. **文字先分主次，再用字重；辅助操作退到第二层。** G-L `els[72]` 发言人 14/21、500，`els[74]` 正文 15/22.5、400；分组 `els[18]` 用 #858585，普通图标 `els[5]` 用 #636363。主标题无需大色块。
3. **强调色标当前动作和一对一关系，群聊靠头像与名字认人。** G-L `els[120]` 发送圆钮 #0890ff，P1-L `els[85]` 用户气泡为粉色，P2-L `els[83]` 为橙色；G-L/G-D `els[87]` 则为 #070707/#5a5a5a。色彩不铺满导航和工具过程。
4. **大圆角装说的话，较小圆角装可操作的层，连续内容只收紧相邻角。** G-L `els[113]` 输入框 R24；P2-L `els[85,93]` 连续气泡相邻左角 R6、其他 R24；O-L `els[149,153,154]` 是卡 R20、选项外侧 R12/内侧 R4、字母标 R6。
5. **聊天居中限宽，列表紧凑，正文留呼吸；不把所有区域做成同一种密度。** G-L `els[113]` 输入框宽 752，`els[23]` 会话行高 36，`els[73]` 气泡内边距 8/16；O-L `els[153]` 可点击选项高 44、内边距 12。
6. **消息流只放说的话和需要人看、选、确认的对象；本机动作必须留下可见凭据。** O-L `els[149–164]` 选择卡和 `els[93,97]` 完成回执提供了两种信息形状；“过程在背后做”来自主人 2026-11-06 的观察，静止截图不能单独证明。Sumika 按 Lorca commandCard 的等待 / 运行 / 输入 / 结局结构给本机命令和写入留卡，读搜默认进状态和活动页，具体分界见第五节。

## 五、推导组件与过程、审批边界

以下全部是 P；每个组件必须复用第三节令牌。静止/悬停/按下/焦点/禁用继承第四节顺序，表内列额外业务状态。隐藏面板不能取消任务、批准动作或改变外平台可见性。

### 5.1 哪些藏、哪些留卡、哪些审批

主人2026-11-06补充：普通工具在背后工作，只把需要看的、选择的、确认的和完成的对象发出来；因为动作发生在自己的电脑上，本机过程不能全藏。Lorca提供结构参照，但权限仍以 ADR-269、ADR-277 与[工具与审批](subsystems/tools.md)为准。

| 事件类别 | 默认消息流 | 标题栏 / 右栏活动 | 审批 |
|---|---|---|---|
| 明确只读的read/find/grep、普通搜索、读网页 | 不逐次插卡；连续读搜折成一行放活动页，可由显示选项投影到消息流 | 标题一条“正在查资料”；活动显示“读了3个文件，搜了2次”，可展开真实步骤 | 走既有Gate；受保护位置即使只读也可能需批，需批则升为待确认卡 |
| 思考、普通模型请求 | 不插“思考完成”卡；回复文本按正常消息显示 | 标题“正在想”；活动列阶段/耗时；后台模型页仅显示后台真实公开给本机的字段 | 不从思考内容推导批准，不用正文冒充工具状态 |
| 本机shell命令（包括只读shell）、写/改文件 | 必须有操作卡，等待→运行→完成/失败/未知；全文或diff可展开 | 状态一行 + 活动详情；输出摘要留卡，完整输出到右栏终端/预览 | 按模式和风险过Gate；本地群每次批。自动允许仍留卡并写明理由 |
| 远端纯取数工具 | 默认藏过程，用户需要的产出才结果卡 | 可展开来源与结果 | 不新增豁免，按原工具权限 |
| 对外发送、发布、删除或其他改变状态的工具 | 需要审批时先待确认；完成后回执，不能因“是插件”藏掉 | 活动留真实结局 | 后台决定需不需要批；不因工具名字像“搜索”就判只读 |
| 选择题、草稿确认、可查看产出 | 放选择/待确认/结果卡；结局在原对象上更新 | 右栏提供详情跳转 | 普通问答没有执行权；执行审批必须绑定真实单据 |
| 普通错误、等待输入、无法继续 | 需要主人处理则卡片或提示条；只读取数的中间失败留活动 | 标题显示“等你确认/输入”或失败原因，优先于泛泛“工作中” | 未知结果不重试执行、不显示成功，后台决定恢复路径 |

### 5.3 审批卡的完整状态

本地私聊的可用批准档由后台现有策略提供；本地群按ADR-269只给本次决定，不显示“以后都允许”；外平台按ADR-277实施前不提供执行批准按钮。以下外观不会开放任何权限。

| 状态 | 卡片内容 / 可操作性 |
|---|---|
| 等待 | 标题“角色甲想修改文件”；一行可信来源、账号/会话、目的；命令全文或diff可在决定前读全，风险文本fg1；拒绝与允许分开。折叠预览不是授权全文 |
| 提交中 | 当前决定按钮禁重复，编辑区只读；关闭只关详情，不等于拒绝；后台失败则保留真实待处理状态和错误，不假报结局 |
| 已允许 | 标“已允许一次”或后台实际自动允许理由；决策按钮消失。执行卡独立显示“尚未开始/运行/完成”，不能提前换完成勾 |

| 平台页输入 | 标注记录、补充给角色；多角色可选对象 | 明确显示“添加标注”及对象，不套“发送到QQ”的按钮意义；前台/后台分配、群友可见性继续待定，不由视觉规格擅自决定 |
| 设置 | 分类+搜索、主区max756；窄时去留白，再返回分类；效果下有预览 | 皮肤换为中性层/细线/R20节卡，控件按内容选，不把所有条目铺成同一列表 |

标题栏与输入框都按真实Bounds预留，初始值用于首帧，量到变化后主动请求下一次布局；不能等用户下一次输入才补空位。消息滚动锚点以稳定消息ID保持。关闭右栏只改视图，不改任务状态。

## 九、已知的坑、禁止写法与验收

### 9.1 已知的坑 / 禁止的偷懒写法

- 不能把C1根初值、后置body、C2桌面StyleX和C3商务表单混成一套“实测主题”；不能把所有JSON bg透明当成白底。
- 不能把可见元素的矩形当完整层级树；O回执内有过渡中的隐藏编辑节点、坐标超出父框。卡片外高以可见终态为准，待确认另验。
- 不能把父按钮opacity1和内部视觉层opacity.4混作一个值；也不能把不同业务状态当成dark样式差异，或从静止截图断言禁用的触发条件。
- 不能因正文出现“同意”“工具完成”就批准或改状态；状态取可信后台事件，显示文本没有授权效力。
- 不能让“显示过程”开关、活动页、全局待办、宠物窗绕过Gate或外平台结果范围；也不能为界面清爽藏掉本机命令和写入卡。
- 不按角色名合并任务；多账号、群聊多角色、切聊天、迟到回包、弹窗关闭、版本改变都要保持准确归属。卡片终态不倒退，未知不变成功。
- 不让Enter在IME、编辑器、上层弹层里穿透成发送/批准；关闭详情不等于拒绝。高风险批准入口隔离沿用ADR-277。
- 不用缩小字体和点击框解决窄窗溢出；长名称、长英文、三层嵌套、十个角色、上万条历史、大字与深浅主题要组合验。不是所有信息都能单行截断，决定前必须可读全。
- 不从Lorca复制GPL组件代码，不把作者的紧凑11px输出搬成本规格默认；不参考MewTypeUI或mygo-m3e，也不保留Telegram皮肤作为兼容验收线。

### 9.2 原型 / 实现时的验收标准

本次文档验证不冒充以下实现验收。按交互原型规格（私有存档）使用编造数据和假后端，每项产出布局数值或事件记录；真窗口再走相同场景。

| 组件六态 | ui.NewTester依次触发idle/hover/pressed/selected/disabled/focus；记录命中框、墨迹框、底色、边线，深浅各一次；无额外布局位移 |

本次已做的文档/能力核验：32项JSON取值断言、18项触发编号、9个本地文档链接、61项原始中文长文本比对通过；候选色对比度由sRGB公式计算。mygo v0.7.4的离屏Tester在深浅色×560/360 DIP、125%下四组通过：选项461.40/294.40宽、44高；一次选择后禁用项不能再改变决定，并实际渲染含半透明线、分角和后景Blur的表面。该探针只验证所用基础能力，不是Sumika原型、原生D3D11、真窗口焦点或超椭圆视觉验收。

## 十、待主人定

1. **显示普通工具 / 搜索过程的选项形态。** 默认按本次要求：普通过程不进消息流，读搜在标题状态和右栏活动折叠；本机命令/写入卡、审批、需看的结果保留。建议分别提供“在消息流显示普通工具过程”“在消息流显示搜索过程/原始结果”两个显示选项（初始关），开后也是折叠摘要，详情仍去活动/结果；两个开关还是一个、全局还是按会话记、是否展示全部原始搜索结果待主人定。它们不得隐藏必需审批，也不得更改外发范围。
2. **替代颜色与系统中文字体的实物效果。** 第三节是可实施候选；角色bubble映射、fg3对比、顶部/底部渐变的透出程度在原型预览后定。数值已区分实测与P，不当已获确认的品牌方案。
3. **组件库怎么落地。** ADR-280已经停止Telegram目标（后又被 ADR-283 修正：分栏和窄窗折叠照 Telegram、设计和配色照 Bun 版、消息内渲染照 Grok bot）；沿现库改或另起仍待定。本规格只规定语义/画法/状态，不据此引入依赖或复制Lorca。
4. **沿用其他规格的未决项。** 平台页标注发前台还是后台、群友是否可见，按标注板和交互原型规格继续讨论；ADR-277第7条执行结果范围仍待定，实施前按收紧边界。本文不替这些问题作新授权。

待量的动态状态不是“先随便实现”：已有静态状态照证据做，未见的表面用明确P在假后端原型呈现，待主人触发后按同一证据表替换；不得在真实运行版用假数据补缺失接口。
