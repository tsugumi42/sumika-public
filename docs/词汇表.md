# 词汇表

> 一个概念只用一个词（ADR-140，借 dsh `docs/glossary.md` 的做法）。写规则、规格、ADR、提交说明、复述主人的话时照这里的说法；代码里的名字在每条后面。
> 起因见 对照-dsh与Magpie开发流程-2026-10-23（私有存档）：一个"群"字同时指"说话的形式"和"有没有外人"，ADR-123、ADR-139 两次都在这上面弄混。

## 场合：渠道 × 形式

| 词 | 意思 | 代码 |
|---|---|---|
| **渠道** | 消息从哪来：**本地**（主窗口）或**平台**（现在只有 QQ） | `channel`：`'console'` 是本地，其余是平台 |
| **形式** | **私聊**（她和一个人）或**群聊**（好几个人） | `scene`：`'private'` / `'group'` |
| **场合** | 渠道 × 形式，一共四种：**本地私聊**、**本地群聊**、**QQ 私聊**、**QQ 群** | `Place`：`'local-private'` / `'local-group'` / `'platform-private'` / `'platform-group'`（`daemon/util/place.ts`；平台现在只有 QQ，说的时候叫 QQ 私聊、QQ 群，值名不写死 QQ，ADR-144） |
| **有外人** | 她说的话会被所有者和自己的角色以外的人看到。现在只有 QQ 群算 | `hasOutsiders(place)` |
| **所有者在场** | 这一轮的听众里有所有者：本地私聊、本地群聊、所有者的 QQ 私聊（旧名“主人在场”，ADR-384） | `Audience.privateOk` |

- **不单说"群里""私聊里"**：规则在本地群聊和 QQ 群不一样时，要写"QQ 群"或"本地群聊"；真正的分界是"有没有外人"时，就写"有外人的地方"。两边一样时写"群聊（本地和 QQ 都是）"。
- **复述主人的话时**，涉及场合的四种都点到："本地私聊 / 本地群聊 / QQ 私聊 / QQ 群，分别是……，对吗"（AGENTS「动手前先读」第 5 条）。
- 本地群聊现在只有场合提示词（`scene-home-group`），还没有入口。`placeOf` 先看渠道，所以它的会话 id 带了 `:group:` 也不会被当成 QQ 群（`test/place.test.ts`）。

## 所有者和称呼（ADR-384）

| 词 | 意思 | 代码 |
|---|---|---|
| **所有者** | 这台 Sumika 归谁：能批准执行、私聊算“所有者在场”的那个人。界面上直接说“你”，文档、规格、代码注释说“所有者”。旧名“主人”只留在开发笔记和历史 ADR 里 | `ActorKind == "owner"` |
| **称呼** | 某个角色怎么叫所有者，是人设的一部分，写在角色卡里；空着时是“用户” | 卡 `ownerName`、提示词宏 `{{owner_name}}` |

## 别的容易混的

| 词 | 意思 | 不要和它混 |
|---|---|---|
| **右侧栏** | 主窗口第 ④ 栏：本轮注入、她在想什么、子代理、资料（代码里叫 `side`）；旧名"心声栏"（ADR-146） | 会话列表（第 ② 栏） |
| **主窗口** | 本地的那个界面（7720，读 `web/dist`；改名见 ADR-081） | 开发服务器 7721 |
| **会话** | 一串连着的消息，有一个会话 id（`console:<角色>`、`qq:private:<她的号>:<对方>`、`qq:group:<群号>`） | 实例（同一个会话可以重建好几次实例） |
| **实例** | 一个角色在一个会话里常驻的对话（pi 的 Agent），固定前缀 + 追加的历史 | 会话 |
| **记录器** | 挂在平台中间件链上的插件：进出的每条消息原样存一份原始记录，不改消息也不拦消息，排在守卫前面（被拦下的也记）（ADR-267） | 补录（从平台拉取漏掉的历史，是另一件事）；记忆（从聊天里提炼出来的） |
| **可见范围** | 旧设计用 `scope`（`owner` / `conv:` / `person:` / `public`）限定哪些场合能想起；ADR-242 后同角色不再按场合过滤，这些标签保留来源和披露、证据关联规则（规格-记忆 3.3） | 场合是当前入口；来源范围标签不等于召回或披露授权 |

## 团队（ADR-354）

角色带着后台代理一起干活的整套结构叫**团队**（Agent Team）。队员共用、不分角色；“团队”指这一次队长和被派到的队员。开发流程里派的“子代理”（`.claude/agents/`）不在此列。

| 词 | 英文 | 意思 | 旧名，不再用 |
|---|---|---|---|
| **队长** | Leader | 角色理解需求、开工单、安排队员、把结果用自己的口吻带回会话时的身份；角色本身不改名 | 前台角色 |
| **队员** | Worker | 按工单干活的后台代理 | 执行者、后台执行者、产品里的子代理 |
| **顾问** | Advisor | 复核、出主意的后台代理（`agent.advisor`） | 复核代理 |
| **工牌** | Badge | 一个后台代理的设定：用途、触发、工具上限、提示词、模型档、结果去向 | 执行者档案、代理定义、帮手档案 |
| **工单** | Ticket | 工作（Work）下派给队员的一单活 | — |
