## 一、做什么、不做什么

这一版做：

1. Go 后台 MCP 客户端。支持 stdio、Streamable HTTP。
2. 显式配置、密钥引用、凭据重载、连接状态、工具发现、调用、取消、关闭和有界恢复。
3. 固定的 `mcp_search`、`mcp_call`、`mcp_result_read` 入口。远端工具存在运行时目录，不逐个塞进模型 tools。
4. MCP 目录内的 BM25 搜索。先搜到完整参数 schema，再调用。
5. 默认每次审批，默认串行（“每次审批”已被 ADR-330 改为：卡片在“这一次”之外加“这个对话”“记住”，同一类按服务器加原始工具名、认服务绑定加 schema，变了再问；见[规格-审批分级](规格-审批分级.md)第七节）。审批、执行、超时共用同一个宿主解析结果；实际提交前原子复核。
6. 文本、图片、`structuredContent`、`isError` 和大输出的完整处理。
7. Go/mygo 现有审批卡上的 MCP 目标和参数展示。设置管理接口供本地使用，不另做一套管理网页。

这一版不做：

- 旧 HTTP+SSE。Streamable HTTP 的 SSE 响应仍在支持范围内，不能混称旧 SSE。
- resources/list、resources/read、资源订阅、prompts、OAuth、sampling、elicitation、MCP tasks。
- Code Mode、脚本批量调用、通用工具搜索框架。
- 自动扫描其他客户端的配置目录，自动安装服务器或运行 `npx -y`。
- Codex TOML、OpenCode JSON/JSONC 的导入器。需要时显式转换，不宣称兼容。
- QQ 前台或后台实际获得 MCP 工具。QQ 子代理按 ADR-205 排在后面，本版只留清楚的授权边界。
- Bun 后台和网页的新功能。

依据：ADR-180；新调研 §7、§9；差距笔记 §三。BM25 本版只服务 MCP，后续通用工具搜索复用这一实现，不再建第二套。

### 2.1 库和协议

```text
github.com/modelcontextprotocol/go-sdk v1.8.0
```

核对结果：

- `native/go.mod:1` 当前为 Go `1.27.3`，没有 MCP SDK，也没有 `mark3labs/mcp-go`。

采用 SDK 的标准初始化协商，不自行探测后再起第二个 stdio 进程。不自写另一套版本协商。支持的协议日期以固定版本源码和传输验收结果为准；当前资料不足，不在这里编造完整日期列表。实施第一步必须补齐该列表及兼容测试结果，不能以“SDK 支持”代替证明。

### 2.3 固定入口与运行时目录

三个固定入口：

```text
mcp_search      { query, server?, limit?, cursor? }
mcp_call        { tool, schemaDigest, arguments }
mcp_result_read { result, offset?, limit? }
```

- `mcp_search` 只查本地已发布目录，不临时连服务，不调用远端工具。分页响应返回不透明 `nextCursor`，末页为 null。
- `mcp_call` 的 `tool` 是公开 ID。`schemaDigest` 来自搜索结果；模型不能自行指定服务器 URL、command、权限或时限。
- `mcp_result_read` 分段读取此前存下的 MCP 结果，不接受文件路径或任意 URL。

目录项至少保存：

```text
serverID、rawToolName、publicID
原始 inputSchema、outputSchema、annotations
bindingDigest、schemaDigest、catalogRevision、connectionGeneration
description、可用状态
```

目录先完整构建和校验，再原子发布。调用按保存的映射路由，绝不拆公开名反推 server/tool。

`bindingDigest` 覆盖传输类型、实际 command/args/cwd、有效环境、URL、headers、有效凭据指纹和本地策略版本。摘要中涉及秘密的部分使用宿主私有随机键计算 HMAC；摘要和日志不暴露原值。凭据指纹来自本次成功解析的有效值，不把引用名或密钥文件修改时间当成凭据版本。换服务端点、有效凭据、启动参数或授权范围，旧绑定失效；凭据变化的检测入口和生效边界见 §2.6。

`schemaDigest` 覆盖原始输入 schema。仅工具描述变化不取消已批准调用；输入契约变化必须重新搜索、重新审批。

依据：新调研 §6、§9.2；DeepSeek 的原始路由与公开名分开、完整换代；`native/internal/secrets/secrets.go:35`、`:42`、`:109` 的快照语义。

### 2.4 审批与执行共用一次解析

现有 `Gate.Check` 按工具名查策略，`KindOf` 对普通工具生成 `tool:<name>`。直接套用会让 `mcp_call` 的授权覆盖全部远端目标，不能采用。

出处：`native/internal/approval/approval.go:98`；`native/internal/policy/policy.go:531`。

增加受限的宿主解析步骤：

1. 检查当轮身份、场合和固定入口是否可用。
2. 查当前目录，检查 `include`、`exclude`、schema 摘要、服务绑定。
3. 校验参数，冻结参数副本和具体目标。
4. 生成内部 `ResolvedCall`：含目标、参数摘要、有效策略、执行时限、调用者权限档、服务撤销代次和插件生命周期。
5. 内核用它审批。批准后再核对身份、权限、绑定、schema 和目录有效性；变化即撤销，不能沿用旧批准换目标。
6. 执行和 `within` 使用同一个 `ResolvedCall`，不重新按名字取另一份策略。取得服务执行槽、完成必要重连后，在向传输层提交前，再原子复核当前调用身份、权限、目标映射、绑定、schema、连接代次、服务撤销代次、插件生命周期、取消和超时状态。

提交前复核与配置撤销必须共用同一服务的同步边界。复核通过至提交给传输层之间，不能再出现可让撤销先完成、旧调用随后才提交的空隙。传输层若有内部等待队列或延迟派发，尚未实际派发的请求仍须受取消和撤销约束，不能把“加入 SDK 队列”当成远端已收到。

配置撤销同时使在途审批和已批准但尚未提交的调用失效。复核失败返回明确的未执行原因；绑定或 schema 变化须重新搜索、重新审批，不能静默重绑。若调用已先提交，后到的撤销不能宣称撤回成功，按已提交调用的取消和结果未知规则处理。

只开放给编译进程序的宿主代码。模型参数、MCP annotations 都不能构造有效策略。未解析、解析失败、审批服务缺失，一律不执行。

普通工具保持集中登记策略；原有 `Gate.Check`、`within` 的调用点统一迁移到共用的有效策略路径，不留 MCP 绕过审批的旁路。MCP 专用目标字段不做成用户可任意扩权的通用钩子。

本版 `mcp_call` 只给“允许这一次 / 拒绝”。不提供对话授权、永久授权、`readonly-free`。手动、自动、YOLO 三档均逐次问。`include` 是可见范围，不是免审批名单。

每个服务的远端调用全局串行，跨角色、跨会话也不能同时调用同一服务。排队可取消。取消或超时后，若旧请求是否终止无法确认，不释放为可继续执行的状态：

- stdio 先关闭旧连接并回收进程树，只有确认旧进程树全部退出后才能恢复调用。无法确认则停在不可调用状态，不起新代。
- HTTP 调用提交后，断线、超时或取消造成终止状态未知时，该服务进入调用隔离状态。关闭 HTTP 连接、取消本地请求、DELETE 会话、重新握手成功，均不视为远端执行终止证明。
- HTTP 隔离期间拒绝该服务后续 `mcp_call`，不得发送；可继续展示本地目录和诊断。隔离按逻辑 serverID 保留，不能通过同名服务换连接、重载配置、删除后重加或重启宿主自动解除。已提交但没有终止证明的记录须能在重启后恢复隔离。
- 解除 HTTP 隔离只接受可对应到旧请求、明确证明执行已结束的服务端状态核对，或已认证主人在本地管理入口查看“旧调用可能仍在执行”的说明后明确确认。普通重连不是该确认；模型和服务器 instructions 不能代替主人。没有可用核对能力时保持隔离。
- 主人确认解除属于明确接受结果未知风险，不是宿主已经证明旧调用结束；保留解除依据，不把旧步骤改成成功。后续新调用仍须重新审批。

解除入口（2026-11-15，质检 X-08、后续路线 P0-3）：`sumika-ctl mcp status` 列各服务的状态和被隔离的旧调用（原因、时间）；`sumika-ctl mcp release <服务> --reason "原因" --accept-unknown-risk` 解除，原因必填、必须明确带接受风险的开关。旧行改成 `risk_accepted`，`reason` 列的 JSON 备注里记解除人、时间、原因，不删、不改成成功；服务正有调用在进行时拒绝；解除后按配置补连并撤掉提醒。入口只在主人的本地管理入口，模型工具清单里没有它（`TestMCPReleaseIsNotAModelTool`）。设置页的解除入口等 MCP 管理页（阶段 3）一起做。

启动收尾（已由 ADR-382 定，放宽了原来“本机服务也要确认进程树退出后才恢复”只在线上成立的做法）：留痕在派发时记下传输种类和进程号。启动时只收尾别的进程留下的 `dispatched`，别的状态（`unknown`、`terminated`、`risk_accepted`）原样不动——`unknown` 带着当时的原因，也可能是“已终止没写进库”“旧进程没能确认退出”才保持隔离的，重启不能让它悄悄恢复。收尾结果：
- 传输种类恰好是 `stdio`（副作用就在本机进程树里）、且是 Windows（宿主退出时 Job 的 KILL_ON_JOB_CLOSE 结束整棵进程树）：记 `terminated`、原因“程序退出”，不再挡。
- 其余一律改 `unknown` 继续挡，等主人解除：远端 HTTP；`stdio-remote`（进程在本机、副作用在别处：命令或参数里有 mcp-remote、supergateway、mcp-proxy、docker、podman、nerdctl、kubectl、wsl、ssh、plink，名单在 `mcpclient/bridge.go`，这类进程树没了不代表对方没在执行）；没记传输种类的旧行；reason 不是合法 JSON 或传输种类不认识的行；不保证子进程随宿主退出的平台。认不出的服务照本机处理（名单不求穷举）。
- 这个假设（进程树退出 = 副作用结束）不适用于上面那些桥接类型。在线路径（调用超时、被停止后关进程树再记 `terminated`）有同样的前提，规格 2.4 已认可，这次不动，只在这里写明。
- 状态从不记成功。

本机服务自动重连：调用失败（已确认进程树退出并记 `terminated`）、或没有调用时进程退出、管道断，按 0.5、1、2、4、8 秒退避最多重连 5 次，连续运行满 30 秒才重新计数；用完停在“次数用完”，说明原因，主人修好后用 `sumika-ctl mcp reconnect <服务>`。被隔离的服务不重连（`Connect` 先查留痕）；主人显式连接、停用、改配置让正在进行的重连作废；关机等重连循环退出；绝不重放 `tools/call`。 关旧连接时没能确认本机进程树退出（强杀失败、等不到整棵树退出；管道已经关了之类的小错不算）就记“旧进程未确认退出”，调用失败的收尾也不记已终止：之后任何连接（自动、`mcp reconnect`、解除后补连）都被拒，状态显示次数用完类的说明，只有重启 Sumika 才清——规格 2.7 的“无法确认则不起新代”。

本版不增加 MCP tasks 或通用远端状态查询协议。隔离解除所需的状态核对没有可靠实现时，只提供上述本地主人确认入口。

依据：新调研 §9.2、§9.5；`native/internal/turn/loop.go:551`、`:703` 的审批与执行分离；pi-mcp `dist/transports/transport.d.ts:8` 明确取消不能撤回已派发消息，`streamable-http.js:199` 的关闭只中止本地请求并尽力删除会话。

### 2.5 配置和兼容范围

配置放：

```text
<数据目录>/config/mcp.json
```

由 `paths` 统一提供路径。全局默认关闭；没有文件等同于关闭，不自动创建真实配置。

主结构采用 Claude、pi 常见的 `mcpServers` JSON。Sumika 策略放 `sumika` 字段：

```json

  "sumika": {
    "enabled": false
  },
  "mcpServers": {
    "docs": {
      "command": "C:/Tools/node.exe",
      "args": ["C:/Tools/docs-mcp/server.js"],
      "env": {
        "DOCS_TOKEN": "${secret:mcp.docs.token}"
      },
      "sumika": {
        "enabled": false,
        "include": ["search", "read"],
        "exclude": [],
        "startupTimeoutMs": 30000,
        "catalogTimeoutMs": 30000,
        "callTimeoutMs": 60000,
        "qqEnabled": false
      }
    }
  }
}
```

Streamable HTTP 条目用：

```json
{
  "type": "http",
  "url": "https://example.invalid/mcp",
  "headers": {
    "Authorization": "Bearer ${secret:mcp.docs.token}"
  },
  "sumika": {
    "enabled": false,
    "include": ["search"],
    "qqEnabled": false
  }
}
```

规则：

- 兼容 `mcpServers` 的 `command`、`args`、`cwd`、`env`、`url`、`headers` 常见字段；不宣称兼容其他客户端全部语义。
- 支持显式读取指定 `.mcp.json` 或 pi `mcp.json`，做本地预览和转换。不能自动读后立即启动。
- 导入项默认禁用。缺少 `include` 时可预览，但不能启用。（**已被审批规格 8.4（ADR-342）改为**：直接写进 `mcp.json` 的片段，`include` 缺省是全部工具、总开关和服务的 `sumika.enabled` 缺省是开，主人 2026-11-09 同意对齐社区写法；`mcp_search`、逐次审批、`exclude` 不变。）
- `include` 必填，按原始工具名精确匹配。空数组表示零工具。没有通配符；`exclude` 优先。（**已被审批规格 8.4（ADR-342）改为**：缺省是全部，`["*"]` 同义；写了的照旧精确匹配，空数组仍是零工具。）
- 同名服务整条替换，不拼 args、env、headers。禁用项保留，不因其禁用而复活另一来源。
- JSON 重复键拒绝。顶层格式错误使本次重载失败；单服务字段错误只禁用该服务，其他合格服务照常。
- 新文件半写、解析失败时保留上个完整配置。显式禁用、删除、收紧权限必须在配置生效的同一同步边界撤销对应可用目录、在途审批和已批准但尚未提交的调用；不能只取消仍停在审批卡上的请求。
- 配置重载同时执行 §2.6 的凭据重载；引用名不变不能省掉有效值复核。
- 相对路径按配置文件所在目录解析，不按进程工作目录。
- 不支持 `$(cmd)`、反引号、动态 headers helper、隐式 shell 展开。
- 不读取项目内配置自动覆盖数据目录配置。

依据：新调研 §4、§5、§9.4；旧深挖“MCP”第 2、3 条；提交前交错见 §2.4。

### 2.6 密钥和进程环境

引用语法：

```text
${secret:名字}  → secrets.Store.Get
${env:NAME}    → 显式读取宿主环境变量
```

没有隐式 `${NAME}`。引用缺失、密钥库锁住或损坏时，该服务进入 `config_error`，不得改用空串或其他账号凭据。

`native/internal/secrets/secrets.go:1`、`:35`、`:109` 只有只读 `Open/Get`，Store 是打开时的快照，`Get` 不会重新读取文件。本版复用它，不新增密钥写入功能，不另存明文 token。需要新增秘密时，可用现有受支持的密钥管理入口，或由主人设置环境变量。

本地管理接口提供显式“重载 MCP 凭据”入口；启动、配置重载和该入口均重新 `secrets.Open`，读取新快照，重新解析引用并计算每服务有效凭据指纹。该入口不必先断开 ready 连接才能使用。

重载期间先封住受影响服务的新提交；重载与 §2.4 的提交检查使用同一撤销边界：

- 有效值不变，保留原绑定和连接，解除临时提交屏障。
- 有效值变化，立即撤销旧连接绑定、在途审批和已批准但尚未提交的调用，撤下可调用目录，关闭旧连接。新凭据建连、重新发现后，才能重新搜索和审批；旧批准不能迁移。
- 重新打开或解析失败，服务进入 `config_error`，旧凭据不得继续供新调用使用；保留脱敏诊断，不退回旧快照维持可调用状态。
- 已提交调用不能因凭据重载宣称已撤回；按 §2.4 处理取消、进程回收和 HTTP 隔离，凭据变化不清除隔离。
- `${env:NAME}` 读取当前宿主进程可见的环境；操作系统外部修改环境但未进入该进程的，不承诺热生效，需重启宿主后重新解析。

本版不承诺自动检测密钥文件变化。仅修改密钥文件、尚未执行重载时，不宣称旧绑定已经失效；密钥轮换流程必须包含显式凭据重载或宿主重启。MCP 状态接口给出最近一次重载结果，不能以文件时间代替有效凭据变化检测。

stdio 默认不继承全部宿主环境。暂定保留 Windows 正常启动所需的 `SystemRoot`、`WINDIR`、`ComSpec`、`PATH`、`PATHEXT`、`TEMP`、`TMP`；其余仅显式配置。环境变量名按 Windows 大小写不敏感规则合并。测试中的 HOME、TEMP、TMP 均指向临时目录。

HTTP 每服务独立 headers 和连接。默认 HTTPS；本机开发 HTTP 仅允许明确配置的回环地址。远端明文 HTTP 不支持。URL 不得携带 userinfo 或 token 查询参数；禁止自动跟随重定向，避免授权头流向其他端点。

日志、审批卡、状态页、错误、stderr 均先脱敏。凭据只在启动、上述重载和必要建连的解析阶段进入私有快照，不进入可展示的配置快照。服务 stdout 是 UTF-8 协议，不做命令行窗口的代码页转换。

依据：`secrets.go:35`、`:42`、`:109`；新调研 §9.2、§9.4 的凭据与连接绑定要求。显式重载补足现有快照接口没有版本通知或自动更新能力的缺口。

### 2.7 生命周期和默认值

插件 `Setup` 只注册入口，不等待网络。第一次合格的本地主窗口回合，或主人显式连接时，后台启动已启用服务。`OnContext` 只读快照，不等待握手。

| 参数 | 暂定值 | 依据 |
|---|---:|---|
| 握手加首次完整 tools/list | 总计 30 秒 | OpenCode、Codex、omp 的 30 秒量级；新调研 §1、§3、§4 |
| 后续目录刷新 | 总计 30 秒，包含全部页 | OpenCode 目录预算；避免逐页重置 |
| 工具执行 | 60 秒 | pi 内置扩展、DeepSeek；不采用 OpenCode 12 小时 |
| 可配置执行时限 | 1～600 秒，不允许 0 | 本地交互的暂定上限；超过需另定长任务契约 |
| 同时建连 | 最多 4 个服务 | 新调研 §9.5 的起步建议，待性能验收 |
| 重连间隔 | 0.5、1、2、4、8 秒 | 参考 omp；增加有界最后一级 |
| 连续故障恢复 | 最多 5 次 | 防止崩溃循环 |
| 稳定后重置恢复预算 | 连续运行 30 秒 | 参考 omp 熔断窗口、DeepSeek 稳定窗口 |
| 正常关闭 | 关输入后等 2 秒，再给强制回收 3 秒 | OpenCode 关闭宽限、DeepSeek 5 秒关闭屏障 |
| 单条接收消息 | 16 MiB | OpenCode、pi；不能代替图片解码预算 |
| stderr 环形尾部 | 64 KiB | pi |
| 模型文字投影 | 合计 20 KiB | pi，包含结构化 JSON 和提示文字 |
| 搜索条数 | 默认 8，最大 20 | 新调研 §9.2 的建议 |
| 搜索响应 | 合计 64 KiB 最终 UTF-8 字节 | 本轮暂定宿主预算；与调用结果分开，允许完整 schema 通过分页读取 |
| 单项完整 inputSchema | 32 KiB 紧凑 JSON 的 UTF-8 字节 | 本轮暂定宿主预算；给身份、说明及分页包装留余量，禁止截 schema |
| 每次 `OnContext` 的 MCP 注入 | 合计 8 KiB 最终 UTF-8 字节 | 本轮暂定宿主预算；目录和 instructions 仅作提示，详细 schema 走搜索 |
| 图片宽、高 | 各不超过 8,192 像素 | 本轮暂定宿主预算；限制极端长边，须在完整解码前检查 |
| 单张图片 | 最多 4096 × 4096 像素，预计解码缓冲最多 64 MiB | 本轮暂定宿主预算；按至少 4 字节/像素计，具体解码器需要更多时采用更高估算 |
| 单次结果图片解码 | 预计解码缓冲合计最多 64 MiB，串行解码 | 本轮暂定宿主预算；防止多张图片分别合格却合计绕过限制 |
| 目录防护 | 每服务最多 1,000 页、10,000 个工具、32 MiB 解码后目录 | 页数参考 pi；数量和总量为暂定宿主预算 |

KiB、MiB 均按 1,024 进制。新增搜索、上下文和图片预算是本轮为补足可执行契约设的工程起点，没有外部实测最优值依据；实施验收须报告实际上下文与解码资源开销。图片的 64 MiB 指受控解码缓冲预算，不代表整个宿主进程的峰值内存。

超时只接受有限正整数。工具执行预算不含人工审批；包含服务串行队列等待、必要重连和远端执行，不逐段重置。排队和重连消耗预算后，提交前仍须执行 §2.4 的原子复核。

连接状态：

```text
disabled → disconnected → connecting → ready
                         ↘ config_error / needs_auth / failed
ready → recovering → ready / failed
任意状态 → stopping → stopped
```

调用隔离是独立于连接状态的服务级状态。连接 `ready` 不等于允许调用；HTTP 隔离不会因连接换代、稳定窗口或故障预算重置而清除。

- 401、403 进入 `needs_auth`，不自动开浏览器、不反复重连。
- 协议错误、业务 `isError` 不当作网络断线循环恢复。
- 每服务连接 single-flight。旧代本地连接关闭未确认，禁止起新代；stdio 还必须确认旧进程树退出。HTTP 本地关闭完成不证明远端调用结束。
- 工具调用一旦提交给传输层，断线、超时、取消均可能结果未知；绝不自动重放 `tools/call`。HTTP 终止状态未知时进入 §2.4 的隔离。
- 连接恢复、目录重列可以重试。必须核对 SDK 的会话失效处理，确保它不在宿主不知情时重发工具调用，也不在取消或撤销后派发内部排队请求。
- 自动恢复耗尽后等待主人显式重连或配置变化，不无限起进程；显式重连仍受调用隔离约束。
- 插件停止先封入口、取消审批、未提交调用和恢复计时，再关闭连接与进程，等待清理。晚到回调不能写目录、结果或成功结局。未确认终止的已提交 HTTP 调用保留隔离记录。

目录通知每服务合并：一次刷新运行时，新通知只置 dirty；完成后最多安排一次尾随刷新。发布前核对当前连接代次。分页重复 cursor、重复 rawName、总预算超限均拒绝整次更新。刷新失败保留旧目录供诊断，但标为不可调用，不能冒充新目录。

### 2.8 Windows 进程托管

采用 Job Object 管整棵进程树。挂起创建，加入设置 `KILL_ON_JOB_CLOSE` 的 Job，再恢复。Job 分配失败时终止尚未恢复的进程并报错，不退成只杀直接子进程。

- 按最终环境的 PATH/PATHEXT 解析程序。
- `.exe` 用 argv 直接启动。
- `.cmd/.bat` 走专用 cmd 参数编码，关闭 delayed expansion，拒绝 NUL、CR、LF。（已做，`launch_windows.go`：`cmd /d /v:off /s /c`，参数逐个加双引号，另拒绝双引号和百分号，末尾反斜杠加倍；用真的 `npx.cmd` 试过。）
- 不能 `strings.Join(args, " ")`，不能统一外套 PowerShell。
- stdout、stderr 分别持续排空。stdout 仅协议；stderr 留限长、脱敏诊断（内存里只留末尾几 KB 给握手失败的原因用；完整的另写一份 `data/logs/mcp/<服务id>.log`，按大小轮转、抹凭据，已被审批规格 8.6 补充）。
- 关闭任务由插件生命周期托管，不能因请求者取消而遗弃。
- 检测到无法受控的包装程序或 Job 逃逸，终止该服务，不把它记成可安全托管。

现有 `native/internal/bench/job_windows.go:79` 已有挂起启动、Job 和清理经验；其采样追踪用于评测，不能当作防止逃逸的安全保证。商店版 pwsh 跑出 Job 是已知实测问题，见规格-表二执行器 §九。MCP 必须单独验收真实启动链。

依据：新调研 §3、§4、§5、§9.6。

### 2.9 工具名和 schema

公开 ID：

```text
mcp__<server>__<tool>
```

只含 `[A-Za-z0-9_-]`，最多 64 个 ASCII 字节。原始身份清洗或截长有损时，加原始 `(serverID, rawToolName)` 的 SHA-256 前 12 位后缀，并为后缀预留空间。即使有哈希，也检查最终碰撞；碰撞时整次目录更新失败，不任意丢一个工具。

按公开 ID 稳定排序，连接返回顺序不影响名称。白名单始终匹配 rawName，审批同时展示 serverID、rawName、公开 ID。

原始 inputSchema/outputSchema 原样保存，模型投影另建：

- 固定 `mcp_call` schema 的 `arguments` 是 JSON object。远端 schema 由搜索结果作为数据返回，不进入供应商的工具声明转换。
- 原始输入根必须符合 MCP 的 object 契约。缺少 object 类型且形状明确时可作最小兼容补全；不能把显式 string、array、boolean 根强改成 object。
- 保留组合、enum、`additionalProperties` 和局部 `$ref`。拒绝需要联网解析的外部 `$ref`。
- 不无界展开递归引用，不丢根约束，不把全部字段改成 required。
- 调用前按原始输入 schema 校验。校验器不支持且无法保持语义时，该工具不可调用，并给出诊断。
- 搜索返回完整 inputSchema，以最终响应中该 JSON 值的紧凑序列化计 UTF-8 字节，不另把 schema 转成双重转义字符串。超过 32 KiB 时返回该项的 `schema_too_large`，保留原始 schema 供诊断，不悄悄裁掉约束后让模型猜。该工具本版标为不可调用，模型不能猜摘要绕过搜索。
- schema 在单项上限内，但连同必要身份字段仍无法装入一页搜索响应时，返回该项的 `search_item_too_large`，本版同样不可调用；不能无限返回指向同一项的游标。说明等可选搜索字段按 §2.10 省略，不能靠改 schema 解决。

依据：新调研 §1、§3、§6、§9.7。固定入口避免每家模型各自重写远端 schema，但不能省掉调用前校验。32 KiB 单项上限及 64 KiB 响应预算为 §2.7 的暂定工程值，不是 pi 的 20 KiB 调用结果预算。

### 2.10 工具搜索

本版实现 MCP 专用 BM25：

- 索引公开名、原始名、服务名和 description。
- 暂定 `k1=1.2`、`b=0.75`，采用常见 BM25 起步值；不是调研测出的最优值。
- 英文按字母数字词切分，统一大小写；中文采用字与相邻双字词。规则固定，测试不依赖系统分词环境。
- 同分按公开 ID 排序。结果数量默认 8，最大 20；每页还受响应字节预算约束，实际条数可以更少。
- 先按当轮权限、白名单和可用状态过滤，再排序。被拒绝的工具名称、说明、schema 都不能进入结果。
- 空查询返回稳定排序的目录分页，不联网；空目录与连接中、连接失败分别返回。
- 正常搜索结果含 publicID、serverID、rawName、description、schemaDigest、完整 inputSchema 和 annotations。不可调用的超限项返回身份、状态和明确错误，不伪装成已提供完整 schema。
- 不把搜索命中项临时加入模型 tools。下一次搜索也不移除旧消息。

搜索响应采用 `items`、`nextCursor` 和必要状态字段。游标绑定查询、server 过滤、limit、参与查询的目录版本，以及当前调用者的角色、会话、权限档和权限版本；游标本身不携带可直接泄露的私有目录数据。后续页仍做当轮鉴权，不能把持有游标当授权。

继续读取时沿用原 query、server 和 limit。参数不匹配返回明确错误；目录版本、绑定、可用状态或权限变化时返回 `cursor_invalidated`，要求从第一页重查，不悄悄把旧位置应用到新目录。非空查询按同一排序分页，空查询按公开 ID 分页；同一有效快照内逐页无遗漏、无重复。末页 `nextCursor=null`。

每页完整响应最多 64 KiB，按宿主最终交给模型的搜索结果 UTF-8 字节计，包含说明、标识、JSON 转义、错误、状态和分页字段。先为响应包装及游标预留预算，再加入完整条目；下一项放不下就留给下一页。不能让通用工具结果截断器截掉 schema 或分页字段。

description 和 annotations 是搜索投影的可选说明，预算不足时可整字段省略，并标明省略；原值留在目录。完整 inputSchema 不截断。单项本身超限按 §2.9 返回错误项并推进游标，不让一个坏项堵住后续目录。空结果和错误响应同样受总预算约束。

目录说明和服务器 instructions 只通过 `OnContext` 追加。instructions 标成外部不可信资料，不升格为系统规则。按“绑定＋内容 hash”去重；工具调用进行中收到变更通知，只换内部快照，下个回合或插话钩子再追加说明。

每次 `OnContext` 的 MCP 输出合计最多 8 KiB，按最终追加文本的 UTF-8 字节计，包含标题、来源、版本、分隔和省略提示；所有服务共用该预算，不能每个服务各拿 8 KiB。按 serverID 稳定排序装入完整说明段。instructions 单段或剩余预算装不下时整段省略，不截成可能误导的半段；模型得到有界的省略说明，本地状态给出具体服务和原因。去重状态区分“已完整注入”和“因预算省略”，不能把省略记成模型已读过原文。目录细节仍通过搜索分页取，不将完整目录塞进钩子。

依据：待办“工具搜索先用 BM25”；新调研 §4、§5、§9.7；LESSONS“每轮变化只能末尾追加”。`native/internal/turn/plugin.go:37` 的 `ContextFn` 没有字节预算，MCP 插件必须自行执行本节约束。pi `dist/extensions/mcp/tools.js:30`、`:139` 的 20 KiB 仅用于调用结果文字，不能作为搜索或 instructions 已有预算的证据。

### 2.11 返回内容、大输出与持久化

当前 `tools.Result` 只有 `Text`、`IsError`，不能接上 SDK 就声称支持图片。

出处：`native/internal/tools/exec.go:25`；新调研 §9.7。

本版扩展端到端结果契约：

- 保留现有文本字段的普通工具行为，增加有序内容块和完整结果引用。内置工具、插件、步骤持久化、历史重建、模型编码全部迁移到同一契约。
- 原始 `content`、`structuredContent`、`isError`、`_meta` 保存到完整结果。`_meta` 默认不进模型。
- 模型按原顺序得到 text、image。图片检查 MIME、base64 和实际格式，使用现有媒体存储，不把 base64 当文字；完整解码前的资源检查见下文。
- 当前模型不支持图片时返回明确占位说明，保留图片供本地主人查看；本地查看仍执行同样的解码预算，不能另走无界预览。
- `structuredContent` 存在时追加一次 JSON。只有 text 可解析且与它语义相等时才省去重复 JSON；不做模糊相似去重。
- `isError=true` 必须让步骤和模型结果都为失败。空 content、只有 structuredContent、失败但有正文分别处理。
- `resource_link` 只给 URI、名称、来源和“本版不读取资源”的说明。embedded resource 的 text 可作结果文字；blob、audio 和未知内容块保留原始值，模型得到明确的不支持说明。
- 不因结果里出现 URL、文件路径或资源链接就自动下载、打开、执行。
- 错误正文保留经脱敏的服务端说明，不改写成成功。

图片处理必须先在原始消息上限内验证 base64，再用不完整解码像素的格式头读取路径取得真实格式和宽高。无法在有界头部解析中确认尺寸、格式不支持或 MIME 不匹配时，拒绝模型图片投影，不能先完整解码再检查。

完整解码前检查：

- 宽、高均为正，且各不超过 8,192。
- 用防溢出的算术计算总像素，不超过 4096 × 4096。
- 预计解码缓冲至少按 4 字节/像素计算；格式、位深或所选解码器需要更多时采用更高估算。单张及单次结果合计均不超过 64 MiB。
- 同一结果串行解码，不并行分配所有图片缓冲。会产生额外帧或合成画布的格式须把所需缓冲算入预算；不能可靠估算和约束时拒绝该格式的模型投影。
- 所选解码器若不能在分配前落实预算，不能仅凭“已读尺寸”宣称安全支持；须改用能约束的路径，或明确拒绝。

超限返回 `image_decode_budget_exceeded` 的明确占位说明，保留受原始消息上限约束的原始图片和结果供诊断；不完整解码、不生成无界缩略图、不把拒绝处理改写为远端业务 `isError`。占位说明计入模型文字预算。16 MiB 压缩消息上限不能代替这些解码限制。

完整结果放：

```text
<数据目录>/go/mcp/results/<随机结果ID>/
```

元数据在 `go/trace.db`，带角色、会话、turnID、toolCallID、服务绑定和可见权限。只有成功落盘并登记后，模型才收到结果引用。存储失败返回宿主存储错误，并说明远端可能已经完成，不能重新调用来“补保存”。

文字投影合计 20 KiB，UTF-8 安全截中间，暂定前后各半。明确写原始字节数、截断事实和不透明结果 ID；这些提示也占预算。完整文字以未截断、固定顺序的 UTF-8 正文保存，后续分段读取的偏移始终针对该正文，不能因读取包装或模型投影变化而变化。

完整文字通过 `mcp_result_read` 分段取：

- offset 默认 0，按完整正文的 UTF-8 字节计，必须是有限非负整数，且不大于正文总字节数。非法字符边界返回错误，不悄悄偏移。
- limit 默认 20 KiB，上限 20 KiB，必须是有限正整数，表示本页正文 UTF-8 字节上限，不包含响应包装。
- 页尾在 `offset+limit` 与 EOF 之间取不超过上限的最远完整字符边界，向前收齐，不能输出半个汉字或 emoji。
- 若尚未到 EOF，但 limit 小于下一个完整字符所需字节数，返回 `limit_too_small` 和所需最小字节数，不能返回不前进的成功页。
- 响应含 `text`、`startOffset`、`endOffset`、`nextOffset`、`eof` 和 `totalBytes`。偏移区间为 `[startOffset,endOffset)`；`nextOffset=endOffset`。`eof` 当且仅当 `endOffset=totalBytes`。offset 恰为 EOF 时返回空正文、相同起止偏移和 `eof=true`。
- 模型直接用 `nextOffset` 续读，不按包装文本长度推算。每页包装和必要 JSON 转义不属于正文偏移，也不占正文 limit；必须完整保留，不能再被通用截断器裁掉。
- 从 offset 0 持续按 `nextOffset` 读到 EOF，拼接各页 `text` 后的 UTF-8 字节必须与完整正文逐字节相等。

该读取入口只允许访问当前角色、当前会话可见的结果；本地管理查看走独立主人权限。不给模型真实磁盘路径。完整结果跟随对应 trace 记录的删除生命周期，不另设自动短期失效，避免历史引用无故断掉。

依据：新调研 §5、§9.7；常见边界情况清单②、⑦。图片尺寸、像素及解码缓冲上限采用 §2.7 的暂定工程值；UTF-8 分页边界和续读位置是保证完整读取的契约，不由包装文字推导。

## 三、谁能用

身份由入口和事件来源的 `ActorKind / ActorID` 认。名字叫“主人”、零宽字符、引用行头、服务器 instructions、模型参数均不能产生主人身份。

当前 `Audience` 没有 ActorKind/ActorID，只有渠道、场合和听众字段；不得假装现成就有调用者认证。装配层必须从已认证的入口和事件身份建立内部调用者信息，再随回合和工具调用传递；`PrivateOK`、`OwnerAsked` 不能单独当主人凭据。

出处：`native/internal/audience/audience.go:8`；`native/internal/turn/hub.go:131`、`:173`；LESSONS“写入、兜底、显示”。

| 场合 | 本版默认 | 搜索、instructions、完整结果 |
|---|---|---|
| 本地私聊 | 仅已认证主人在主窗口可用；服务还须显式启用、填白名单 | 只进对应权限档；调用先问，可记到这个对话或记住（ADR-330） |
| 本地群聊 | 不提供三个入口，不触发建连 | 不注入 MCP 私有目录、instructions 或工具结果 |
| QQ 私聊 | 前台和后台均不给；主人本人发话也不自动获得 | 不返回本机路径、配置、目录或本地主窗口结果 |
| QQ 群 | 前台和后台均不给，群友冒充主人无效 | 同上；禁止从历史重建、摘要、结果 ID 旁路泄露 |

`qqEnabled` 默认 false。当前版本遇到 true，报告“QQ 后台尚未接入”，仍不开放。以后子代理版必须同时满足：

1. 主人对具体服务、工具显式标记“QQ 能用”。
2. 后台任务的委托身份由宿主签发，不能从文字推导。
3. 按派活的人、会话和听众过滤。
4. 本地执行能力默认仍关闭；不能因为有 QQ 白名单就给 stdio 或任意本地文件访问。
5. 结果回传和发送过渠道守卫。

这是保留 ADR-081 的显式开放路径，本版不提前扩大默认权限。

权限下降时切换权限档，不能修改同一实例中已有前缀来“清洗”结果。同时撤销受影响的在途审批、已批准但尚未提交的调用和旧搜索游标。摘要材料不带 MCP 私有结果、instructions 和目录。直接调用管理接口、伪造旧 toolCall、猜结果 ID，均再做同样鉴权。

## 四、禁止的偷懒写法

- 只放开 `OnTool` 名称检查，不迁移 Gate、超时、调度和执行身份。
- 把所有远端工具写进全局 `policy.Specs`，或把 annotations 当宿主策略。
- 以 `readOnlyHint`、`idempotentHint` 自动免审批、并行或重放。
- 给 `mcp_call` 存 `tool:mcp_call` 的宽授权。
- 审批展示一份参数，执行时重新解析另一份。
- 只在批准后检查一次，排队或重连后不在提交前原子复核。
- 只取消审批卡，不撤销已批准但尚未提交的调用。
- 把 HTTP 关连接、DELETE 会话或重连成功当成远端调用终止证明。
- 将凭据引用名、旧 Store 快照或密钥文件时间当作当前有效凭据版本。
- 只隐藏模型 tools，不隔离目录、instructions、历史、摘要和结果读取。
- 把空数组解释成默认工具。（缺失当全开已被审批规格 8.4 放开；空数组仍是零工具。）
- 为抓错误输出再启动一次原命令。
- 直接继承全部环境，或让配置值执行 shell。
- 超时后重发 `tools/call`，或把“可能已执行”写成“没有执行”。
- 只杀 cmd.exe；Job 失败后静默退成弱清理。
- 截断原始结果、不保留完整内容，或给 QQ 一个本机全文路径。
- 丢掉 structuredContent、isError、图文顺序、根 schema 约束。
- 用调用结果的 20 KiB 预算代替搜索、`OnContext` 或图片解码预算。
- 截断搜索 schema、丢掉分页字段，或让游标跨目录、权限版本继续使用。
- 用压缩图片字节数判断解码内存，完整解码后才检查尺寸。
- 目录变动时重写 system、替换已有消息或临时添加再撤掉工具声明。
- 本版没有 resources/prompts/OAuth，却声明相应客户端能力。
- 无有效性能对照仍计算“最佳值”，或把“不适用”计作通过。

| M18 | 20 KiB 前后、大 structuredContent、读全文分页、跨会话猜 ID；正文含跨 20 KiB 边界的汉字和 emoji，按 nextOffset 读到 EOF 后拼接正文与完整正文逐字节相等；非法 offset、过小 limit、offset 恰为 EOF 分别符合契约，包装不计入偏移 | 移除总预算、字符边界、续读位置或结果鉴权 |
| M19 | 结果保存失败后不出现成功引用，不再次远端调用 | 先回成功再落盘或调用补偿重试 |
| M20 | 连续回合、目录变更、工具循环；原有消息及 tools 字节不变，新增信息只在末尾 | 原地改 system、历史或动态 tools |
| M21 | 主人本地调用后切本地群、QQ 私聊、QQ 群，并夹压缩、重建；完整请求无私有标记 | 复用错误权限档或把结果送摘要 |
| M22 | Windows 有/无命令行窗口，exe、cmd、空格中文路径、空参数、引号、尾反斜杠和特殊字符，服务器收到精确 argv | 拼接命令、错误 cmd 转义 |
| M23 | Windows 根进程先退出、孙进程持管道、强杀宿主、Job 分配失败，后代全部回收或启动失败 | 只杀直接子进程、先恢复再分配 Job |
| M24 | 关闭一个会话不取消另一个会话审批；停插件则全部取消，已批准但未提交调用也失效且不执行迟到批准 | 按角色误取消或遗漏插件取消、提交屏障 |

输出必须包含测试名、通过/失败/跳过数，以及针对保护本身的改坏记录。新增功能不能拿当前实现输出自动生成期望值。

### 6.2 实际冒烟

用隔离数据目录启动实际 Go 程序，连接两个测试服务器：

- 一个真实 stdio 进程，带孙进程和 stderr 输出。
- 一个回环 Streamable HTTP 服务，提供 JSON/SSE、会话失效、先写后断线及忽略取消持续执行的行为。

经实际主窗口完成：连接、搜索及游标续页、审批允许、拒绝、取消、批准后排队撤销、ready 期间凭据轮换和显式重载、图文结果、超预算图片拒绝、截断后按 nextOffset 读全文、停止插件、重启程序。观察工具调用计数、完整模型请求、trace 结局、结果文件和进程退出。

HTTP 旧调用持续运行时，再提交另一次调用，观察服务器没有收到第二次请求；关闭和重连后仍保持隔离。核对隔离诊断、主人明确解除入口及重启后的隔离恢复，不能只验原调用未重放。

运行 `go vet ./...`、`go test ./...`；MCP、审批、结果链和生命周期测试在 Windows 与 Linux 跑 `-race`。只改 Go 和文档不跑 Bun `check:ui`；mygo 审批展示必须在实际界面核对目标、脱敏参数和按钮范围。

### 6.3 性能量法和过线

新调研 §8 没有取得三家可横向比较的 MCP 基准，不能预先指定“最快的是谁”，也没有证明三家中一定存在符合本规格完整 schema 搜索契约的对照。

同机、同一服务器实现、同一目录、同一输出，比较 Sumika、omp、OpenCode v2、pi。记录版本与源码提交；omp、pi 当前调研版本分别为 18.13.1、1.4.0，正式测量以实际版本为准。每个客户端使用隔离配置，不读主人的真实客户端目录。

正式测量前，逐项固定验收口径：

- 有效对照客户端、版本和能力等价条件，包括搜索排序、schema 完整度、鉴权、结果字段和发现路径；不能测完后才挑对照。
- 起止事件、成功条件、冷/热状态、负载规模和超时；故障或缺能力的运行不能当成更快的样本。
- 无 MCP 的自身基线、采样窗口、基线扣除方法和受测进程范围。
- 若没有等价对照，先报告绝对值和不适用原因。该相对指标标为“待定门槛”，不得把无对照计作通过，也不得无限等待一个不存在的最佳值。补定有明确单位、负载和完成事件的绝对门槛或另一有效对照后，另跑验收，才纳入过线判断。

规模分别测：

- 0、10、100 个服务。
- 每服务 10、100、1,000 个工具；零服务不套用每服务工具数。
- 空结果、1 KiB 文本、20 KiB 文本、超过预算文本、图文混合。
- 冷启动、热搜索、热调用、目录通知风暴、反复连接关闭。

客户端按轮换顺序跑三遍，不能同时互相抢资源。热路径预热后每遍至少 1,000 次；冷启动每遍至少 30 次。远端测试程序记录收到与发回时刻，拆出服务耗时；人工审批等待单列，不混进调用速度。

零服务的完成事件是“MCP 初始化完成且确认没有待启动服务”，不是“目录可调用”。非零服务从宿主发起测到全部目标服务握手及完整目录发布、可调用；失败和超时单列，不以首个快服务完成代替全量完成。没有对应初始化事件的对照须先提供可观察的等价事件，否则该对照不适用。

CPU 和内存统一按各客户端自己的无 MCP 基线扣除，不能拿 Sumika 的基线去扣另一客户端：

- 基线使用同版本、同配置和同宿主负载，仅关闭 MCP；按相同预热、操作次数与采样窗口测整棵客户端进程树。
- CPU/次为同窗口总 CPU 时间减自身基线，再除以已完成操作数；原始总量和差值均报告。
- 峰值私有字节为负载窗口峰值减自身匹配基线窗口峰值；稳定私有字节在相同静置及 GC 条件下取相同统计口径后相减。采样间隔、窗口、统计口径在测量前固定。
- 客户端启动的 stdio 测试服务器及其后代归入测试服务器，HTTP 测试服务器也单列；两者均从客户端树归属中剔除，避免重复计数。客户端自己的辅助进程仍计入客户端开销。
- 原始值与扣除值同时报告。差值为负或处于测量噪声内时，不当成负开销优势；基准最佳增量为零或无法稳定区分零时，相对倍数没有有效分母，按无有效相对门槛处理，补定绝对容差后再验。

| 指标 | 量法 | 暂定过线 |
|---|---|---|
| 不启用 MCP 的开销 | 对照同一 Go 程序关闭/未装配 MCP，量首个请求、CPU、私有内存 | 不创建 MCP 进程、连接、后台轮询；首个请求不等待 MCP |
| 冷建连和完整目录 | 非零服务从宿主发起到全部目标目录可调用；零服务到初始化完成，分别记 p50/p95，不混算 | 有有效对照时，p95 不高于该负载最佳等价值的 1.10 倍；无对照或无有效分母则待定门槛 |
| 热搜索 | 等价名称/说明查询取前 8 条，含完整 schema 序列化；固定相关性题集 | p95 不高于具备等价搜索能力的最佳值 1.10 倍；无等价能力则报告绝对值及不适用原因，待定门槛 |
| 热调用宿主开销 | 从已批准到本地结果可读，减服务器测得执行时间；不混人工等待 | p95 不高于有效等价对照最佳值 1.10 倍；无对照或无有效分母则待定门槛 |
| CPU 和内存 | 按上述统一规则测整棵客户端进程树并扣自身基线；测试服务器单列；记录 CPU/次、峰值及稳定私有字节 | 各有效增量指标不高于同等能力最佳值 1.10 倍；无有效对照或分母则待定门槛 |
| 模型输入 | 捕获同任务完整请求，用同一 tokenizer；含发现和调用两步，对照自身无 MCP 输入计算增量 | MCP 引入的累计 token 不高于最佳等价按需发现路径 1.10 倍；无等价对照则相对项待定门槛；固定 tools 字节数不随目录规模增长单独验 |
| 通知风暴 | 刷新被屏障阻塞时发送 1,000 次通知 | 同时最多一次刷新，解除后最多一次尾随刷新；目录最终正确 |
| 生命周期泄漏 | 预热后连接/关闭 100 轮，再静置并强制 GC；记录线程、句柄、goroutine、进程 | MCP 子进程和连接为 0；受控资源回到自身基线，无逐轮增长 |
| 长时间运行 | 测试服务持续 24 小时，交替查询、刷新和断线 | 无无限恢复、无目录错代、无重复调用；资源无持续线性增长 |

1.10 是暂定验收容差，不是已有实测优势。对照的是每个指标在预先确定的有效候选中各自最好的客户端，不挑一家的弱项当标准。提供功能不同、启动工具数量不同、结果丢字段的运行不能用于该项排名。

绝对时间、分配次数和峰值仍须报告，不能只报倍数。最终逐项给出“通过 / 未过 / 待定门槛”和依据；有待定门槛的必验指标时，不宣称性能验收全部完成。无对照的绝对值报告可以先完成，但必须补定并实际执行可判断的门槛，才能关闭该项。

若目标未过，先定位具体开销；不能以“机器忙”放宽门槛。BM25 另有固定相关性题集，性能过线不能靠少返回 schema、少做鉴权或降低搜索质量。

依据：新调研 §8 未取得横向实测，§4、§5 的按需发现形态不等于完整 schema 的等价 BM25 搜索；规格-Go后台 §8.2 的明确预期和可判定验收要求。基线扣除及零服务事件是本轮补定的测量口径，不是已有性能结论。

## 七、分几步做

每步单独提交，提交包含对应测试、说明和可撤回边界。生产总开关保持关闭，最后一步才具备完整可启用条件。

1. **SDK 和协议接通。** 固定版本，补支持协议日期和 stdio/HTTP 实际冒烟；核对 SDK 内部重试、排队及取消派发语义；只有测试入口，不装配生产。撤回不影响现有功能。
2. **配置、密钥引用与进程托管。** 接 `paths`、只读 secrets、显式凭据重载、有效值指纹、状态机和 Windows Job。抽取共用进程代码时同步迁移 bench 调用者，保持其原有验收。撤回该提交即恢复原调用。
3. **宿主解析与逐次审批。** 固定入口策略、调用者身份、`ResolvedCall`、服务级串行、提交前原子复核、未提交调用撤销和有效时限一并接通；所有普通调用者完成迁移。只用测试服务器验收，不开放真实服务。
4. **完整结果链。** 更新 tools、turn、llm、store 和历史重建，打通文本、图片解码预算、structuredContent、isError、带 nextOffset 的全文读取。普通工具输出回归不变。
5. **运行时目录与 BM25。** 命名、远端目录分页、防护、原子换代、带快照与权限绑定的搜索分页、独立搜索和上下文预算、末尾追加。目录变化不得改变模型 tools。
6. **恢复、启停和管理装配。** 完成迟到回调、关闭等待、配置收紧、HTTP 调用隔离及其重启恢复和明确解除、实际审批卡、插件启停。通过本地管理接口可诊断、重载凭据和重连；重连不自动解除隔离。
7. **端到端和性能验收。** 完成第六节全部契约、实际界面冒烟和三家对比；正式测量前固定有效对照、完成事件和自身基线。无等价对照的必验指标须先补定可执行门槛并实测，不把“不适用”计作完成。更新规格状态、参考页插件表/接口表、Go 后台结果契约、待办和路线图；依赖选型留 ADR。

各步按依赖逆序撤回。不留临时兼容别名、动态注册旁路或旧结果编码路径。回滚不得自动启动原来禁用的服务，也不得删除已有完整结果或自动清除未确认终止的 HTTP 调用隔离记录。

## 八、要主人定的

这一版保持默认关闭、白名单必填、本地主窗口专用、调用逐次审批，不需要新增权限默认值的拍板。（2026-11-09 ADR-330 主人拍板放宽：加“这个对话”“记住”两档，场合不放宽，见规格-审批分级第七节。）

以下发生时再单独定：

1. 启用真实服务，尤其本机会执行代码的 stdio command。要列实际命令、端点、凭据来源和允许工具；不能以验收名义改真实配置或替主人启动。
2. 将某个服务、工具标为“QQ 能用”。属于后续子代理版，需按具体委托人和回传听众定范围；不得整服默认放开。
3. 增加免审批、并行、OAuth、付费服务，或让 MCP 工具对外发送消息。分别说明放宽范围、费用或实际收件对象后再定。
4. HTTP 调用终止状态未知、又没有可靠状态核对时，是否明确接受风险解除该服务隔离。必须针对实际旧调用展示结果未知事实，由已认证主人在本地确认；不能提前替所有未知调用默认同意。

这些决定不阻塞隔离目录内的实现、测试服务器验收和不花模型费用的性能对比。

## 这一轮改了什么（2026-10-28 复核以后）

- 采纳复核 1（高）：区分 stdio 进程退出证明与 HTTP 本地关闭；补 HTTP 调用隔离、重启恢复、明确解除条件，以及旧调用持续时第二次不同调用不得发送的 M10 验收。
- 采纳复核 2（高）：补取得执行槽、必要重连后的提交前原子复核；配置撤销覆盖已批准但未提交调用，M8 增加批准后排队再收紧配置的交错。
- 采纳复核 3（高）：依据 `secrets.Store` 的打开时快照语义，补显式凭据重载、重新 Open、有效值指纹和旧绑定撤销；明确文件修改未经重载不承诺自动生效，M5 覆盖 ready 期间同名引用轮换。
- 采纳复核 4（中）：为 `mcp_search` 增加 cursor、nextCursor、快照与权限绑定和失效错误；M16 覆盖超过 20 项目录逐页无遗漏、无重复。
- 采纳复核 5（中）：独立定义搜索响应 64 KiB、单项完整 schema 32 KiB、每次 MCP OnContext 注入 8 KiB 的暂定工程预算，补计量、超限、说明省略和分页推进规则，不借用调用结果 20 KiB 冒充已有依据。
- 采纳复核 6（中）：定义正文 UTF-8 偏移、页尾字符对齐、实际起止偏移、nextOffset、eof 和过小 limit 错误；M18 要求跨汉字及 emoji 边界分页后逐字节还原全文。
- 采纳复核 7（中）：补完整解码前的图片尺寸、像素、预计解码缓冲及多图合计预算；暂定长边 8,192、单图 4096 × 4096 像素、单图和单结果解码缓冲 64 MiB，M17 验证小压缩图片在完整分配前被拒绝。
- 采纳复核 8（中）：补测量前固定有效对照、完成事件和自身基线扣除；零服务以初始化完成为终点，无等价对照或有效分母时报告绝对值并标待定门槛，不计通过。
- 同步更新包职责、权限撤销、禁止写法、已知的坑、实际冒烟、实施步骤和主人解除隔离的入口要求；本轮只读核对，未修改仓库文件、未运行服务或测试。

## 复核意见里没采纳的

无。复核 1～8 均成立，全部采纳。新增预算数值均标为暂定工程值及其依据；HTTP 隔离的主人确认被明确写成接受未知风险，不等同于远端终止证明。
