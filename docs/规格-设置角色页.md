## 一、先说人话

设置左边现在是九个固定分类，里面是整份配置的只读列表，一个角色的东西散在好几页：说话用哪个模型在"模型"页（键名 `characters.suzune.model` 原样显示），QQ 小号绑给谁在"平台账号"页，记忆写入有没有她在"记忆和学习"页，人设正文哪里都看不到（它在角色卡文件里，设置读接口按规矩不给）。

要做的是：左边九个分类下面加一个"角色"小节，每个角色一项（头像色块 + 名字）。点进去是一整页，只讲这一个角色：

1. **她是谁**：名字、ID、主题色、头像。
2. **她在哪**：本地（默认接入）、QQ（绑了哪个小号、现在有没有在接收）。
3. **她用什么模型**：说话、话题、后台。
4. **她的记忆**：写入有没有开、整理有没有开（只看，不改）。
5. **群聊里的提醒**等角色级开关（只看）。
6. **人设**：角色卡全文，分成身份 / 行为 / 表达 / 私下四块，旁边是历史版本。

第一步只看，不改任何东西。第二步开始能改，一项一项开：先开人设（最不碰别的东西），再名字和主题色，再模型，账号绑定和头像最后、而且要主人先点头。**页面是给主人自己改自己的角色用的：界面不替主人改人设里的任何一个字，不自动润色、不提示"建议这样写"。**

## 三、技术路线

### 3.1 页面怎么摆

- 左边分类栏（`navigation.VerticalTabs`）下面加一个"角色"小节：每个角色一行，头像色块（`display.Avatar`，没有图片就是色 + 首字）+ 名字。选中项统一用现在的 `a.realTab` 这一个整数：0～8 是原来的九页，9 起是第 i 个角色（i = 9 以后的偏移），不另开第二个选中状态。角色多了（十个）左栏自己滚动。
- 右边一页：页头是名字（副标题：ID + "只读"/"可编辑"），下面六组 `layout.Section`：她是谁 / 她在哪 / 模型 / 记忆 / 群聊 / 人设。每行"名字在左、值在右"的排法沿用 `row()`（`settings.go` 里已有）。
- 用 CrychicUI 现成的，先读各自签名再用（LESSONS「接现成组件库」）：色块 `display.Avatar`；摘要行 `data.PropertyGrid` / `data.KVTable` 或现有的 `row`；人设全文第一步用只读的多行文字（`ui.Text(...).Selectable()` 放进 `ui.Scroll`），第二步换 `input.AutoTextArea` 或 `input.MarkdownEditor`（二选一，2a 开工时试一次再定，选的理由写进提交说明）；历史版本 `data.VersionList`；差异预览 `code.DiffView`；二次确认 `overlay.ConfirmDialog`；主题色 `color` 包里的选色组件。手写的地方在注释里写"为什么没用现成的"。
- 每一页的数据只在打开这页（或点"刷新资料"）时读，读在后台 worker，不在界面线程读文件。读不到的一格单独标"读不到：原因"，不让整页空掉（规格-界面接Go后台 4.2 第一条）。

### 3.2 第一步：只读接口

**不往 `ReadSettings` 里塞角色卡。** 规格-界面接Go后台 4.6 和 `api.Setting` 的注释都写明角色卡正文不是设置读接口的附带能力。所以在 `api.Reader` 上**另加一个方法**（名字暂定）：

```go
ReadCharacterPage(ctx context.Context, id string) (Result[CharacterPage], error)
```

`CharacterPage` 只含：

- 身份：`ID`、`Name`、`Color`（卡上现在的值）、`ShownName`（界面启动时读的那份，用来标"已改未刷新"）、`HasAvatarFile`（第一步恒为 false）。
- 配置：`Model` / `Topic` / `Background` / `GroupReminder` 各一个 `{Value, Configured, Running, RunningKnown}`（`Running` 只在接收中才有，来自 `App` 开始时那份 `cfg` 的快照，不是再读一遍文件）。
- 账号：本角色绑的账号列表，每项 `{MaskedID, Receiving bool}`（号打码，用 `config.MaskID`；没有令牌、没有地址）。
- 记忆：`WriteListed`、`SummarizeListed`（配置里列了没有）；`WriteRunning`：**第一步固定为"尚未接入"**。
- 人设：`Raw`（`character.md` 原文，读到 256 KiB 为止）、`Blocks`（身份 / 行为 / 表达 / 私下 四块的字数，用 `persona.Split` 的结果数 rune，不新写一份拆分）、`History`（`card/history/` 的文件名、时间、大小，最近 200 条）。读历史里某一版的正文是另一个调用（`ReadCharacterCardVersion(id, versionID)`），第一步也可以只做到列表。

实现落在 `internal/desktopread/character.go`（新），读卡一律经 `internal/persona` 的 `CardDir` / `readCard` 一类现有函数，不另写一套路径拼接；`desktopread.Reader` 多一个字段，`demo_reader.go` 和 `api/api_test.go` 里的 `compileReader` 这两个别的实现者同一个提交里补上这个方法（演示数据用 `cmd/desk-fixture` 那套编的卡）。

**谁能看到**（这是页面要给主人看自己的人设，但要把范围钉死，写进注释和测试）：

- 只有本机桌面程序的这一页调用它。`sumika-ctl`、托盘菜单、日志、提醒（`alert.Hub`）、`status` 回复**都不带**角色卡正文，也不带历史版本的内容；以后加命令行命令时同样不加（和 `gate set` 不接 `speak` 同一个理由：命令行是 Agent 也能调的）。
- 页面显示的人设文字不写日志、不进错误信息（读失败只写"读不到 <角色 id> 的卡：<系统错误>"，不带内容）。
- 演示模式（`-demo`）只显示编出来的卡，读的是 `desk-fixture` 造的目录，不读真实数据目录。

顺手修一处现有的不一致：`desktopread/settings.go` 把 `characters.<id>.topic` 标成 `supported: true`，但 Go 里没有地方读它（上表）。改成 `false`，并在 `settings_test.go` 里钉住（旧代码放回去会红）。

### 3.3 第二步：怎么写

写之前的共同前提（任何一个写入口都先过这几道，缺一道就不写、不改任何文件）：

1. 不是演示模式；数据目录过得了 `paths.Open`（有身份证，和 `desksettings.SetAutoReceive` 一样）；
2. 打开页面时记下目标文件的"修改时间 + 大小 + 内容哈希"，保存时再比一次，对不上说明有人在外面改过（编辑器、同步工具），拒绝并说"卡在外面被改过了"，给"重新读取"和"仍然覆盖（旧的先存进历史）"两个按钮（后者只对人设卡开，配置文件只给"重新读取"）；
3. 同一个进程内一把写锁（卡和配置共用一把，串行）；
4. 写文件用现有的 `desksettings` 那套"同目录临时文件 → `Sync` → `renameOver`（Windows 上被别的程序打开时短时间重试）"。**不要把 `renameOver` 复制第二份**：2a 开工时先把它挪到一个小包（暂定 `internal/atomicfile`），`desksettings` 改成调它，行为和测试不变，再往上盖卡和配置的写入。后台每轮读卡，Go 的 `os.ReadFile` 在 Windows 上打开时不带 `FILE_SHARE_DELETE`，所以"后台正在读卡的那一瞬间改名会失败"是真会发生的事，不是理论上的；第一个测试就测它（见七）。

#### 3.3.1 写人设卡（2a）

- 保存 = ①读当前 `character.md` 的字节；②和编辑框内容比，一样就什么都不做（不留历史，ADR-133 第 2 条的做法）；③不一样：先把当前这份原样拷进 `card/history/<时间>-character.md`（文件名格式要对齐 Bun 写过的；Bun 的命名代码本机没有，**开工时克隆 sumika-bun 读 `card-edit.ts`，把真实格式写回这一节**；读历史时对不认识格式的文件照样列出来、按修改时间排、不删不改）；④临时文件 → 改名盖过去。
- 保存的字节 = 编辑框里的字节（规格-提示词预设 验收第 1 条的同款）。换行：原文件是全 CRLF 的，写回仍是 CRLF；编辑框内统一显示 LF；原文件混着两种换行的，保存前提示一次"这张卡的换行不统一，保存会统一成 LF"。`## 身份` 这类标题名一字不差，页面**不校验、不改写、不拦保存**（ADR-133 第 4 条：这个编辑界面不接任何考试），只在编辑框下面用灰字列出"系统认出了哪四块、各多少字、没认出的标题"，让主人自己看。
- 历史版本：列表按时间倒序；"换成这一版"= 把现在的先存进历史，再把选中的写成当前（同一条保存路径）；"复制"= 复制到剪贴板；"删除历史版本"**第二步不做**（历史只增不减，需要清理由主人在文件夹里手动做；以后要做再走问题清单）。最早的一版在列表里标"最早的一版"，不叫"出厂"（ADR-134 的"出厂"只对示例卡有意义，真卡是主人自己写的；示例卡复制成 `example/card/` 时那份才是出厂版）。
- 保存后不重启任何东西：下一轮对话自己读到新卡。页面上写明这一点——**接收中保存，下一条 QQ 回复就会用新卡**（二次确认里也写，问题 1）。
- 只改 `character.md`。`character.yml` 走 3.3.2，两个文件不在一次保存里一起写（一个提交只做一件事；也免得半写）。

#### 3.3.2 写 `character.yml`（2b：名字、主题色）

- 只开 `name` 和 `color` 两个键。不整份 `yaml.Marshal` 覆盖（会丢注释和其他键，如旧写法的 `model` / `models`）：用 3.4 的"逐行编辑"。旧写法的 `model` 键页面不碰，只在发现它存在时显示"这张卡里还有旧写法的 model，配置里没写时才会用它"。
- 同样先把当前 `character.yml` 拷进 `card/history/<时间>-character.yml`。
- `name`：不能为空，不能只有空白，首尾空白去掉；其他不拦（不限制长度以外的字符，但最长 32 个字，超了不让存并说原因）。保存后在提示里列出这次改名的影响（见六）。
- `color`：只接受 `#rrggbb`（选色组件给的就是这个）。读到卡上已有的别的写法（`oklch(...)` 等）时原样显示、不转换，主人没动它就不写回。

#### 3.4 写配置（2c、2d）：`sumika.yml`

> 已被 ADR-249 改为：模型页能写的范围扩到全局后台模型和思考、三个场合的思考、上下文几项（见[规格-模型设置页](规格-模型设置页.md) 3.1）；本节的写法（只换一小段、自检、`config/history/`）照用。

ADR-249 已授权模型页按[模型设置页 3.1](规格-模型设置页.md#31-页面能写的键adr-249-第-3-条)的白名单写回，话题模型仍只读。只开放这一小部分；`memory.write.*`、`qq.*`、`tools.*`、`group.*` 不由这一页写。模型页的共用解析、补丁写回与快照实现在 `internal/config`、`internal/app`、`internal/turn`。

**为什么不能用 YAML 库整份读出来再写回去**：2026-11-02 拿 `sumika.example.yml` 试了 goccy/go-yaml v1.19.2（`parser.ParseBytes(..., parser.ParseComments)` + `yaml.PathString(...).ReplaceWithNode` + `file.String()`）：

- 什么都不改，输出和原文也不是逐字节相同（示例文件是 CRLF，输出变成 LF，11978 字节对 12406 字节）；
- 换成 LF 的版本再试，只改 `defaults.backgroundThinking` 一个值，有 51 行不同：1 行是想改的，另外 50 行都是"行尾注释前面用来对齐的多个空格被压成一个"；注释和键的顺序保留了；
- 往 `characters: {}` 里加一个角色：写出来缩进是 12 个空格，原来注释掉的示例块被留在新内容下面，位置很怪。

所以**不用库来写，只用库来找位置**：

1. 用 goccy 的 `ast`（带 `Position` 的行和列）找到目标键的值落在哪一行哪几列；
2. 只替换那一小段文字（或在同级最后一个键后面新加一行、缩进跟着同级；`characters: {}` 这种空的写法，把那一行换成块写法再加），其余字节原样不动，**包括换行风格（全 CRLF 就写 CRLF）和行尾注释前的对齐空格**；
3. 写之前自检，不过就不写：把改完的整份文本用 `config.LoadIn` 同一套规则解析（`check()` 过），再和改之前的解析结果逐键比，除了想改的键别的都一样；再逐行比，改动的行数在预期范围内（改已有键 1 行，新加键最多 N 行）；
4. 写之前先把当前配置文件原样拷进 `config/history/<时间>-sumika.yml`（命名沿用 2026-10-19 的 `20261019-102751-sumika.yml`）。里面可能有明文令牌或 `${变量}`，和原文件同样对待：不进日志、不进界面、跟着 `config/` 一起被备份。

配置文件找哪份：只写 `config.Config.Source` 记着的那份（`SUMIKA_CONFIG` → `config/sumika.yml` → 项目根）。`Source` 为空（根本没有配置文件，全部是默认值）时**不替主人新建**，页面写"还没有配置文件，请先复制 sumika.example.yml"；`SUMIKA_CONFIG` 指到数据目录之外的文件时照写但在页面上标出路径。

模型的值怎么选：只能从**模型列表**（接收中从 Magpie 拉到的那份）里选，不给自由输入。原因是启动时 `checkModels` 会查"要连的角色的模型在不在列表里"，不在就整个接收起不来（受阻、回到只看历史）；一个手滑填错的名字会让下次"开始接收"失败。archive 模式没有模型列表（页面不为这页联网，规格-界面接Go后台 4.6），所以 **2c 的模型保存按钮在没有列表时是灰的**，并说原因。说话用的 `model` 不能清空（空 + 卡里也没写 = `ErrNoModel`，这个角色再也说不了话）；`topic`、`background` 可以清空，清空 = 删掉这个键。

#### 3.5 和正在跑的后台怎么协调

> 已被 ADR-249 改为：模型、思考、上下文保存后不用重启接收，下一轮生效（[规格-模型设置页](规格-模型设置页.md) 3.4）；下面"要重启接收才生效"那句只对账号绑定还成立。

- 写**卡**：不用停任何东西（后台每轮读卡，改名盖过去是原子的）。
- 写**配置**（模型、思考、上下文）：ADR-249 的运行快照保存后发布，下一轮 / 下一次后台调用使用；正在运行的回合和提前压缩用旧版做完。不重启接收；archive 显示“下次开始接收生效”，只允许改思考和上下文，模型选择禁用。
- 写**账号绑定**（2d，若开放）：必须先停接收，页面在接收中直接灰掉并说"先停止接收"；不提供"停了再改再开"的一键，免得一键断流（问题 3）。
- 页面上"配置值"和"运行值"一直分开显示（`api.Setting` 已有 `Configured` / `Effective` 两套语义）：保存以后配置值变了、运行值没变，就是它们不同的样子。

### 3.6 状态与"刷新资料"

`CharacterView`（名字、颜色、模型）是 `App.Desktop()` 建的时候读一次的快照；规格-界面接Go后台 4.2 定的是"由'刷新资料'显式重读"。角色页保存名字 / 主题色以后**自己触发一次刷新**（同一个函数），并在页面上标"界面上的显示名已更新"；会话列表里的名字下一次重画就变。不做文件监听（规格 4.2：不顺带引入卡热更新机制）。

## 五、禁止的偷懒写法

- 不把 `character.md` 或它的任何一块塞进 `ReadSettings` / `api.Setting`。
- 不把人设正文、历史版本内容放进日志、错误信息、`sumika-ctl` 的任何回复、托盘菜单、提醒。
- 不整份 `yaml.Marshal` 覆盖 `sumika.yml` 或 `character.yml`（注释、对齐、旧写法的键都会丢；上面有量过的数）。
- 不在演示模式写任何东西；不在没有身份证的数据目录里写（也不顺手建 `go/`、`card/history/`）。
- archive 不联网、不能改模型；ADR-249 允许模型页保存思考和上下文。人设卡写入不在本次范围。
- 不替主人改人设：不自动补标题、不自动去掉 `<!-- -->` 注释、不统一标点、不"帮你润色"、不在保存时修剪句子；唯一允许的字节变化是换行风格的统一（并且要先提示）。
- 不在保存时校验人设内容、不接注入测试、不因为字数多少拦保存（ADR-133 第 4 条）。
- 不复制 `renameOver`（先挪成共用的小包）。
- 不用 `sleep` 等重启；不在界面线程读写文件；不用定时轮询去看卡有没有变。
- 不自己拼路径：卡的位置经 `paths.Paths.CardDir` / `persona.CardDir`；角色 id 进路径之前先过和 `memory.write` 一样的规矩（不能空、不带 `/ \ : ..`），并且必须是 `characterIDs()` 列出来的某一个，不能是页面传进来的任意字符串。
- 不在页面上提供"新建角色""删除角色""改 ID"（ADR-085 的迁移还没有 Go 版；新建角色的向导是另一份规格）。

## 六、已知的坑

对着边界情况清单过了三类，再加这个功能自己的。

**多角色 / 多账号 / 多会话不能混**
- 页面按"角色 id"取数据，不按显示名或下标。两个角色重名（`name` 一样）时页面标题后面一律带 ID，列表里也带。
- 一个角色可以绑多个账号（`check()` 只查"账号不重复"，不查"角色不重复"）：账号一格是列表，不是单个值；一个账号只能给一个角色，页面不提供把同一个号给两个角色的入口。
- 宿主一次只接收一个号。角色 A 绑了号、但现在接收的是角色 B 的号时，A 页上写"没有接收"，不能写"接收中"。
- `qq.groups`、`qq.privateAllow`、`qq.memoryAll`、`qq.owner` 是**所有角色共用**的，不是某个角色独有的（配置里没有"这个群归哪个角色"的键）。角色页只给一行链到"平台账号"页，不要在每个角色页里复制一份看起来像角色独有的列表。群档位（只记录 / 试运行 / 说话）存在运行记录库的 gate 规则里，同样不画在这里。
- 改绑定 `qq.accounts[].character` 的数据含义我**没有核实**：同一个会话（`qq:private:<她的号>:<对方>`）里以前她说过的话，按什么归属（`events.actor_id`、观察表）、新角色接手后模型的历史会不会把旧角色的话当成"自己说过的"，需要实现前先读 `internal/store`、`internal/history` 查清楚。没查清之前 2d 不开（问题 3），只显示。

**两端版本不一致、热更新后拿旧状态**
- 界面显示的名字 / 颜色是启动时的快照，卡上现在可能不一样：页面同时拿卡上现在的值和快照比，不同就标出来，不悄悄只显示其中一个。
- 配置值和运行值要分开显示，保存以后"已保存，未生效"必须看得出来；重启接收失败（比如新选的模型起不来）时，按现有宿主的做法回到"只看历史"并写原因，页面把这条原因原样显示在"模型"一组下面，不另编一句话。
- 记忆整理里她的自称（`memory.Options.Name`）只在启动时读：改名以后下一轮对话用新名字，但后台整理在重启接收之前还用旧名字，二者暂时不一致。页面保存名字时一定提示这件事。
- 用户在页面外（编辑器）同时改卡：保存前比对修改时间、大小和哈希（3.3），对不上就拒绝。
- 新页面配旧的后台：`ReadCharacterPage` 在旧版 `Reader` 上不存在时，页面显示"这个版本的后台还不支持角色页"，不崩（桌面程序和后台是同一个 exe，现在不会发生，但 `Reader` 是接口，保留这个分支并测它）。

**空、缺字段、零值**
- 没有 `color`、没有 `model`（卡里和配置里都没有）、没有 `character.md`（`readCard` 容忍它不存在）、`character.md` 是 0 字节、有 `character.md` 但一个标题都没有（整篇当一块，旧写法）、有 `card/` 但没有 `card/history/`、旧布局（卡直接放在 `characters/<id>/` 下没有 `card/`）：每一种页面都要有明确的显示，不显示空白也不显示假默认值。**旧布局的卡 2a 不写**（`persona.CardDir` 会回退到旧位置，历史目录该放哪没有规矩），页面只读并说明。
- `character.yml` 坏了（`checkYml` 不过）：这个角色整页只显示"这张卡读不到：<原因>"，其他角色不受影响（`displayCharacters` 已经是这样，页面沿用）。
- 配置里有 `characters.<id>` 但数据目录里没有这个角色的文件夹：不在角色列表里（列表来自文件夹），但在"模型"页的键名列表里还是会出现；角色页不为它建一页，只在"模型"页那一项后面写"没有这个角色的卡"。
- 配置里 `qq.accounts[].character` 写了一个不存在的角色 id：在"平台账号"页本来就能看到，角色页不管；"模型"页可以顺手标红。

**改名字的影响面**（保存名字时在提示里列出来；ADR-085：名字只是显示用，ID 才是数据里的编号）
- 流到的地方只有三处：提示词里的"你是{{name}}"（下一轮）、`memory.Options.Name`（重启接收后）、`CharacterView.Name`（刷新资料后）。
- **不会**改写已经存进记忆库的文字：记忆里指到她的地方用的是 `character/<id>`，不是名字，所以身份没乱；但旧事实里写进去的旧名字还是旧名字，别的角色记忆里提到她的名字也不会变。
- 群里"叫到她的名字"的别名表（`channel.GateConfig.Aliases`）现在**没有接到装配里**（`internal/app` 里没有赋值），将来接的时候，改名要不要同步别名表，要在那时的规格里定，这里先不假设。

**写文件的坑**
- Windows：后台每轮读卡时，改名盖过去可能报"拒绝访问"或"共享冲突"，重试到时限还不行就保留编辑框里的内容、告诉主人"现在没存上，稍后再点保存"，**不丢主人正在编辑的文字**。
- 保存到一半崩了：临时文件留在 `card/` 里（`character.md.tmp-*`）。启动时不清理它们（可能是别的进程的），页面不把它们当成历史；`desksettings` 现在对这件事的处理照搬。
- 杀毒、同步工具（OneDrive 等）扫到 `card/` 时，临时文件名会被打扰：名字用 `.tmp-` 结尾加随机串，和 `desksettings` 一致。
- 备份：`card/` 和 `config/history/` 本来就在每日备份的范围里（规格-数据目录与备份 5.3.0），历史条数多了会让备份变大：人设卡很小，不当问题；配置历史每次保存一份，也不当问题。

## 七、验收

测试一律用临时数据目录和**编出来的**角色卡（名字、人设、号码全编，不读真实 `data/`，不用真实角色卡内容；`characters/example/` 那张示例卡可以用）。

**第一步（只读）**

1. `ReadCharacterPage` 对一个编出来的数据目录：名字、颜色、模型（配置值 / 运行值 / 没在接收）、账号（打码）、四块字数、历史列表，每一项各有一个测试；账号一格测不出完整号码、令牌、地址（编造令牌和号码，搜整个返回值和日志，要 0 处）。
2. 形状表（每格"处理了 / 不可能 / 测了"，都要有）：行 = 没有 `color`、没有 `model`、`character.md` 不存在 / 0 字节 / 无标题 / 四标题齐全 / 大于 256 KiB、没有 `card/history/` / 有历史 / 历史里有不认识的文件、旧布局、`character.yml` 坏、两个角色同名、一个角色绑两个账号、没有任何账号、配置里的角色在文件夹里不存在、`SUMIKA_CONFIG` 指向不存在的文件；列 = 页面的每一个读入口（页头、身份、账号、模型、记忆、人设、历史）。
3. 谁能看到什么：四种场合（本地私聊、本地群聊、QQ 私聊、QQ 群）逐一确认读接口没有新发送 / 执行能力、QQ 选哪个账号不改变任何会话的受众；`sumika-ctl` 的 `status`、`logs`、`gate list` 的回复里搜编造的人设句子，要 0 处（改坏检查：故意让 `status` 带上卡，这个测试必须红）。
4. `settings_test.go`：`characters.<id>.topic` 不再是"Go 已启用"（旧代码放回去要红）。
5. 用 `ui.NewTester` 量：十个角色的左栏、一个角色的整页，量元素数、布局无溢出（名字 32 个字、人设几万字都不撑破）、选中项切换、空状态（没有任何角色 / 读不到）；`MYGO_FRAME_STATS=all` 量打开角色页和切换角色的帧耗时，汇报量出来的数，不写"看着不卡"。"放大十倍"：十个角色、每张卡 100 KB、每个角色 200 条历史，三遍，报：打开页面到出内容的毫秒数、元素数、最大帧耗时、读文件的字节数（只应读当前这一个角色）。
6. 设计自查（`docs/设计自查.md`）过一遍；不过的条目写进提交说明。

**第二步（写），每个入口都要真跑一次"红"和一次"过"**

7. 写卡（2a）：保存的字节等于编辑框的字节；内容一样不留历史；不一样历史里多一份、内容是改之前的原文；"换成这一版"之后当前 = 那一版、被换掉的那份在历史里；CRLF 的卡写回仍是 CRLF；外部同时改过 → 拒绝且文件没变；写到一半（临时文件写成功、改名前）故意失败 → 旧卡完好、没有半个文件、编辑框内容还在；演示模式、没有身份证的目录 → 拒绝且目录里什么都没多。
8. Windows 专项（真文件、真进程，不靠注入的假错误；LESSONS「造的数据上量不出的问题」）：一个子进程循环用 `os.ReadFile` 读卡，同时保存 200 次，要么成功要么重试后成功，不能出现"保存成功但内容是旧的 / 空的 / 一半的"；再测一次读者长时间不放手（持有句柄超过 2 秒）时，保存报失败而旧卡完好。
9. 写配置（2c）：用 `sumika.example.yml` 的副本和一份只有两三个键的短配置各测：改一个值，别的字节完全不变（逐字节比，包括 CRLF 版和 LF 版、行尾注释前的对齐空格）；`characters: {}` 加第一个角色；已有 `characters.a` 加 `topic`；清空 `topic` = 删键；写完用 `config.LoadIn` 读回，值对、别的键没动；自检不过（故意构造一个改完会让 `check()` 报错的值）→ 不写；`config/history/` 里多一份改之前的原文。
10. 改坏检查：拆掉"改名盖过去"的重试、拆掉"保存前比对哈希"、拆掉"配置写之前的逐键自检"、拆掉"写之前先备份"，各拆一次，对应的测试必须红（拆的是被测的保护本身，不是另造一个泄露）。
11. 真实模型 / 真实文件：2c 做完要在主人的真实配置**副本**上试一次改模型，再用副本启动一次接收（`checkModels` 过）；真实配置本身由主人在场时才动。

## 八、分步

每一步单独提交、能整个撤掉；先做完一步到能天天用，再开下一步。

**第一步：只看（1a → 1b）**

## 九、要主人定的问题

默认都取收紧的一侧；标"我定的"的是我暂时这么定，主人没说过。

1. **人设保存要不要二次确认？** **主人定的（2026-11-02，ADR-236）**："我觉得二次确认只在没有主动点保存的时候提示"。点"保存"就直接存（旧版照样进 card/history/），页面上常驻一行"接收中保存，下一条 QQ 回复就用新卡"；只有改了没保存就要离开（切页、切角色、关窗口）时提醒，给"保存 / 不保存 / 留下继续改"。
2. **只看历史（archive）模式下，能不能改人设卡？** 默认不能（archive 的意思就是只读地看）。代价是不在接收时没法改人设。想放开的话，只放卡，不放配置。
3. **改账号绑定要不要做？做的话必须先停接收吗？** 默认：2d 不做；做的话必须先停接收，页面不提供一键重启。另外要先查清"改绑以后同一个会话的旧历史怎么算"（上面六）。
4. **允许页面改写 `sumika.yml` 的范围。** **主人定的（2026-11-02，ADR-238）**：只限 `characters.<id>.{model,topic,background}`，别的键永远不写。
5. **头像要不要做、做的话放哪。** **主人定的（2026-11-02，ADR-236）**："要的，最好还有历史头像（只存一张缩放为最大512px最小128或者256px，看实际需求大小的webp格式之类的）"。做：上传或替换时先进裁切编辑框出正方形（主人 2026-11-02："上传替换的时候应该是要过一次手动编辑裁切缩放的，所以正常来说应该是存成一个正方形的"，ADR-237），存 card/avatar.webp，边长 512px（原图更小就按原尺寸），换头像时旧的进 card/history/；上传原图不留。用 CrychicUI 的 `account.AvatarEditor` / `media.AvatarUpload`。2e 从"默认不做"改成要做。
6. **`characters.<id>.*` 搬走还是两边都显示？** **主人定的（2026-11-02，ADR-238）**：在模型页一张表里改（行是角色、列是说话 / 话题 / 后台模型）；角色页只显示她现在用的模型，旁边链到模型页。原来我定的"搬到角色页"作废。
7. **"私下"那一块要不要显示？** 默认显示，并标"群聊不拼进提示词"。主窗口只有主人自己看得到，隐藏它没有保护谁。
8. **改名字要不要同时通知记忆侧重开？** 默认只提示"重启接收后记忆整理才用新名字"，不自动动任何东西。
9. **页面显示人设全文，这件事本身。** 我定的：另开一个读接口，不放宽设置读接口，也不放进命令行；范围就是上面 3.2 写的"谁能看到"。规格-界面接Go后台 4.6 原来只写了"角色卡正文不是设置读接口的附带能力"，没有说主窗口自己的专页能不能显示，这里需要主人确认一次。
10. **记忆写入、群聊提醒能不能在页面里开关？** 默认永远只看：记忆写入按 ADR-228 要主人亲自点头并抽检，群聊提醒要和注入测试考的时候一致（ADR-121），都不适合一个开关随手拨。
11. **要不要有"这个角色不上本地"的开关？** 现在没有对应的配置键，也没有人提过；默认不加（不为说不出理由的设置加开关，设计语言第十一节）。
12. **历史里最早的一版叫什么。** 我定的：叫"最早的一版"，不叫"出厂的"（真卡是主人自己写的；ADR-134 的"出厂"只对示例卡成立）。
