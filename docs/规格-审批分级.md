## 一、四种回答

审批卡上：**允许一次**（原来的"批准"）/ **这个对话里都允许** / **始终允许** / **拒绝**（可以写一句原因）。

- **这个对话里都允许**：本地私聊的写进 `data/go/approval-sessions.json`，重启后还在（2026-11-10，8.6）；只管这个会话、同一类操作。
- **始终允许**：记在 `data/config/tool-grants.yml`，所有会话都算；设置里看得到、能撤销；手改文件、重启后照样读。`data/` 是受保护路径，她自己改不了这个文件。
- **拒绝**：写了原因就原样告诉她："主人拒绝了这个操作，原因：……。不要换个方式重试同一件事，先问主人想怎么做。"

## 二、"同一类"怎么算

| 工具 | 同一类 | 卡片上怎么写 |
|---|---|---|
| `powershell` | 命令里用到的每个命令名（`git` 带上子命令，如 `git push`），按出现顺序；全都一样才算同一类 | 「git push」 |
| `write`、`edit` | 同一个目录（不含子目录） | 「D:\Notes 里的文件」 |
| 其他（没登记的） | 工具名 | 「mcp__x__y」 |

- `powershell` 那行已被 ADR-115 改为：`npx`、`bunx`、`pnpm dlx` 这类下载来跑的带上包名（「npx cowsay」，第 1 条）；"这个对话里都允许"另外记着当时那条命令碰到的工作目录外面的目录，之后同一类命令要改的东西看得清、碰到的外面都落在这些目录（或下面）里才放行，写到别的地方照样问；"始终允许"没有目录，只管工作目录里的（第 3 条）：碰到外面的卡片不给"始终"，最多"这个对话里都允许"，以前点过的"始终"也只管里面，不为它改 `tool-grants.yml` 的格式（ADR-117 第 1 条）。`git commit -m $msg` 这类值是内容的参数用变量不算看不清，点过"这个对话"以后手动、YOLO 都不再问（ADR-117 第 2 条）。卡片写成「set-content」动到 D:\out 里的。

## 三、哪些不给"始终" / 不给"这个对话"

- **受保护路径**（数据目录、密钥）：只能"允许一次"（ADR-080）。
- **灾难性命令**（格式化、分区……）：只能"允许一次"或"这个对话里都允许"（ADR-081），不给"始终"。点了"这个对话"也只管当时批准的目录（ADR-115 第 3 条）：批准了删 `C:\Users\me`，删另一个盘照样问。
- **没登记的工具**：不给"始终"。MCP 另有登记：`mcp_call` 按服务器加原始工具名、认目标版本记，见第七节（ADR-330）。
- **命令**有下面任何一样的，不给"始终"：
  - 管道 `|`、分号 `;`、`&&`、`||`、重定向 `>`；
  - 拆开看有"看不清"的地方（变量当目标、`iex`、别的程序……，规格-工具权限 ①c）；
  - 用到这些命令：`rm`、`del`、`erase`、`rd`、`rmdir`、`ri`、`Remove-Item`、`powershell`、`pwsh`、`cmd`、`python`、`py`、`node`、`bun`、`bunx`、`npx`、`npm`、`iex`、`Invoke-Expression`、`Start-Process`、`curl`、`irm`、`iwr`、`reg`、`sc`、`net`、`shutdown`、`format`、`diskpart`、光杆的 `git`（没有子命令）；
  - 改系统状态、装到用户目录、改全局配置的（`mustAsk`，ADR-115 第 4 条）；碰到工作目录外面的（ADR-115 第 3 条）。
- YOLO 下拆不开、动态执行、编码过又带删除的命令只能"允许一次"；目标从管道来、没写死、参数绑不上的删除能给"这个对话"（ADR-115 第 5 条）。

## 四、判定里放在哪（ADR-330 重排了生态工具的位置，现行顺序见第七节 7.2）

（2026-11-09 又加了用户写的 deny、allow 规则：deny 在场合后面、先于一切放行，allow 在授权后面、越不过受保护路径和灾难性命令，见 8.3；输入框按会话切档只改“按模式”那一步用哪一档，见 8.2。）

规格-工具权限 ①a 的顺序里加一站：受保护路径（只能一次）→ 灾难性（有"这个对话"的授权、碰到的外面也都在当时批准的目录里就放行，否则问）→ **授权（这个对话 / 始终）有就放行** → 按模式 → 兜底问。放行时工具卡片上写"你允许过：……"。

## 五、界面

- 审批卡：左边"拒绝"（旁边一个小箭头：拒绝并告诉她原因），右边"允许一次"（主按钮）+ 小箭头（这个对话里「…」都允许 / 始终允许「…」，不能给的不出现）。
- 键盘：卡片上有焦点、或者焦点不在输入框里时，回车 = 允许一次，Esc = 拒绝（回车**已被 ADR-106 改为**：只在焦点在审批卡里、或者页面上没有焦点时才算，卡片弹出后 500 毫秒内不认；焦点在别的按钮、链接、刻度上时，回车照常点那个东西）；中文输入法选字（`isComposing`、keyCode 229）、按住不放（`repeat`）不算（2026-10-19 ADR-106 复核加：输入法选完字（`compositionend`）100 毫秒内的回车也不算，Windows 的 Chrome 有时紧跟着补发一个 keyCode 13 的回车）；一次只对最上面那张还没处理的卡起作用。加进 `check:ui`。
- 设置里"已允许的操作"：一行一条（什么、哪天允许的），每条能撤销。

## 六、验收

- 判定表：授权（一次性不记、这个对话只在这个会话、始终所有会话）、受保护路径不给授权、灾难性只吃"这个对话"、不许"始终"的命令。
- 授权文件：写进去、重启（重建 Tools）读得回来、撤销以后又要问。
- 拒绝原因原样到她那里。
- 界面：卡片四个选项、回车和 Esc、输入法选字时的回车不算。

### 7.1 两档：`policy.Spec.Tier`

| 工具 | `Tier` | 手动 | 自动 | YOLO | 卡片上的范围 |
|---|---|---|---|---|---|
| `web_search`、`web_fetch` | `open`（默认放行） | 放行 | 放行 | 放行 | 不问，没有卡 |
| `mcp_call` | `scoped` | 问 | 问 | 放行 | 这个对话 / 记住 |
| `task` | `scoped` | 问 | `reader`、`research` 放行，其余问 | 放行 | 这个对话 / 记住 |

- `open` 只管“只读地查公开资料”。`web_fetch` 的安全边界（防 SSRF、内网、大小、时限、预算和用量）在服务自己那里，一条都不因此放宽；放行之前的“场合”判定也照旧（总开关、可信身份、提供方、目标限制不满足仍 deny）。
- `scoped` 的 YOLO 和别的工具一致：不问。旧写法把这四个工具排在模式判断前面，YOLO 也问，已去掉。
- `task` 的有效果按代理类型算（`taskEffects`）：`reader` 只读本地、`research` 只查公开网页，按只读；`worker` 和认不出的按最宽（读写、命令、联网）。**只管“派出去问不问”**，子任务的每一步照常过门。

### 7.2 判定顺序（`policy.Decide`）

渠道（可用场合）→ 只碰自己的记忆 → **不是主人发起的只问一次** → **默认放行档** → 受保护路径 → 后台自己的地址和端口 → YOLO 下拆不开、动态执行又带删除 → 灾难性命令 → 授权（这个对话、记住）→ **范围档** → 按模式 → 兜底问。

- “不是主人发起的”排在默认放行和授权前面：`Env.NotOwner`（`ActorKind` 非空且不是 owner，或场合是群，或会话里带 `:group:`）为真时，默认档、授权、YOLO 一概不吃，只问一次、不给范围档。身份按 `ActorKind` 认，不按名字、不按 `PrivateOK`（ADR-269 不能破）。空身份（内部调用、测试）当会话来判，场合由第一步挡。
- 授权先于模式：点过“记住”的 `mcp_call`，手动、自动档也不再问。
- 跑 Sumika 自己的遥控器 `sumika-ctl` 里会改状态的子命令，排在“后台自己的地址和端口”旁边（3.5b）：任何档位只能批一次，不吃 YOLO、不吃授权，也不产生授权键；只读的照档位走。判定方式、防什么不防什么和名单见[规格-本机控制接口](规格-本机控制接口.md)（ADR-382）。

### 7.3 同一类和规则认的目标版本

| 工具 | 同一类（`Kind.Key`） | 规则认的版本（`Rule.Guard`） | 卡片上怎么写 |
|---|---|---|---|
| `mcp_call` | `mcp:<服务器>/<原始工具名>` | 服务连接指纹加参数 schema 摘要：`<fingerprint>:<schemaDigest>`（指纹由服务 ID、类型、地址、命令、参数、工作目录和环境变量、请求头的键名算出，不含凭据值和进程随机量，重启后不变） | 「服务 的 工具」 |
| `task` | `task:<代理名>`，代理名要匹配 `^[a-z][a-z0-9_-]{0,31}$` 且参数类型是字符串，否则不给范围，只能批这一次 | 无 | 「派 reader 子任务」 |

- MCP 选“服务器加原始工具名”而不是只按服务器：同一个服务器里有只读查询也有删除，不能一点全放。ADR-330 没说更细，这里自己定。`Gate.CheckMCP` 算，因为 `Decide` 拿不到解析后的目标。
- **服务器自称只读（MCP annotations 的 `readOnlyHint`）不拿来放宽**，只在卡片上标一句“服务器自称这个工具只读（没有核实）”。理由：这是对方自己说的，服务器可以随时改口，也可以说谎；Sumika 对 MCP 的信任边界在“主人加了白名单”这一层，工具级的信任由主人点“记住”给（规格-MCP客户端 2.4）。测试：`TestMCPReadOnlyClaimDoesNotRelax`。
- 规则的 `Guard` 对不上就不算数，重新问并在卡片上说明“这个工具的服务或参数定义变了，之前的放行不算了，再看一眼”。服务重连、schema 变、绑定变都会触发。
- 子任务权限不会因此超过派它的人：`task:<代理名>` 的规则只管“派这一类”，不进子任务自己每一步的判定；子任务的写、命令照常用自己那一类的规则，派它的人没放行过的它也拿不到。子任务的身份、授权按它自己的内部会话算。测试：`TestTaskGrantDoesNotWidenChild`。

### 7.4 批准之后、执行之前：复查（Pinky 第 1 点）

- `Gate.Clear`：问之前先给目标取指纹（`targetPrint`：联接解析到哪里；写、改文件时还有文件内容的哈希；从无到有也算变），主人批准之后再取一次，不一样就**作废这次批准、从头再判再问一轮**（卡片带 `Retry`，说明“批准之后目标变了，这是现在的样子，再看一眼”）。最多再问 `staleAskLimit = 3` 轮，一直在变（日志文件）就放弃，告诉模型等稳定了再做。命令和参数在这次调用里是冻结的，不比；命令会碰的文件内容主人在卡片上没看到，也不比。
- 放行之后、真正执行之前还隔着“等执行槽”：`Clearance.Recheck` 在执行前再查一遍，指纹变了、规则被撤销了就不执行，把原因作为这一步的结果交给模型。靠规则放行的（这个对话、记住）也带 `Recheck`：**撤销立刻生效，已经放行、还没开始执行的那一步也作废**。
- MCP：`Valid()` 复查（服务重连、schema 变了）在批准前后各查一次，变了回“MCP 目标已经变了”，让模型重新 `mcp_search` 拿到新摘要再调，下一次调用会重新问（没有可以再问的同一个目标）。
- 现状核对（先写的测试）：批准写文件后文件被改了，以前**静默照批准的内容执行**（卡片上的预览已经过时）；批准 MCP 后 schema 变了，以前已有 `Valid()` 复查。现在写文件变了回到再问，MCP 保持。

**给模型看的结果状态**（`approval.go` 的常量，一处定义）：

| 结局 | 模型看到的话 | 要点 |
|---|---|---|
| 批准（一次） | 结果后追加“（主人批准了这一步。）” | 只给模型看，步骤输出不带 |
| 批准（这个对话、记住） | “（……主人允许过这一类，这次没有再问。）” | 默认放行、模式放行不说 |
| 拒绝 | “主人拒绝了这个操作……。不要换个方式重试同一件事，先问主人想怎么做。” | 写了原因就原样带上 |
| 过期 | “主人一直没有处理审批，审批过期了，这个操作没有执行。要做的话先跟主人说一声。” | 没执行 |
| 取消 | “操作被取消了（主人发了新消息或对话被中止），没有执行。” | 没执行 |
| 批准后目标变了 | “批准之后目标变了，这次没有执行。先重新看一眼现在的样子再决定；重新发起会再问主人。” | 没执行 |
| 一直在变 | “目标一直在变，问了几次都对不上……等它稳定了再做。” | 没执行 |
| 规则刚被撤销 | “放行这一类的规则刚被主人撤销了，这次没有执行；重新发起会再问主人。” | 没执行 |
| MCP 目标失效 | “MCP 目标已经失效，这次没有执行；重新 mcp_search 再调用，会重新问主人。” | 没发出去 |
| MCP 调用出错、结果不明 | “MCP 调用出错或结果不明（……）：可能已经在对方那边生效了。先用只读的方式确认现状，不要盲目重试。” | 可能已生效 |

准入阶段的这些结局（拒绝、过期、失效、调错参数）是这一步的结果（`turn.Refusal`），不让整轮回复出错；停止和取消照旧交给调度器。

### 7.5 放行留痕（Pinky 第 3 点）

- `Decision.By`（卡片按哪一档批的）、`Clearance.By`（这次是哪一档放的）：`once` 一次批准、`conversation` 这个对话、`always` 记住、`default` 默认放行、`mode` 手动 / 自动 / YOLO 的模式规则、`self` 只碰她自己的记忆（不算放行，不留痕）。
- 会写、会跑命令、会联网的放行，以及主人回答过的，写进这一步的 `approval_json`：`{"decision":"approved","by":"once"}`、`{"auto":"…","by":"default"}`，靠规则放行的再带 `rule`、`label`。写失败只记日志、不拦（默认放行就是为了不打断）。老记录没有 `by`：批准的当一次、自动的当模式。
- 给主人看的一句（`approval.RuleText` / `turn.StepRule`）：“你批准了这一次”“这个对话里允许过「…」”“记住的规则：「…」”“默认放行，不用问”或模式的原话。画在这一步展开以后的底部一行，平时不占地方（设计语言第十一节：常驻最多一行，细的折叠）。

### 7.6 放行规则页（B19：看得到、清得掉）

### 8.3 B11：用户能写的 allow、deny 规则（`ask` 和作用范围见 8.7）

- **参考和采用**：Claude Code 的 `permissions.allow / deny`（工具名加括号里的匹配，deny 优先）；opencode 的 `{action, resource, effect}` 规则集；Codex 的 execpolicy。采用 Claude Code 的写法，自己映射到 Sumika 的工具；没采用它的“规则里的 Bash 等于 Sumika 的 shell 工具全部形态”：命令只认拆得开的。
- **写法**（`policy.ParseUserRule`，写错了说明错在哪、能写什么，不悄悄当成别的）：

| 写法 | 管什么 |
|---|---|
| `Bash(git status:*)`、`Bash(go test *)`、`Bash(npm run build)` | `powershell` 工具；`:*` 或结尾 ` *` 是命令前缀（按词边界，`git status` 不盖住 `git statusx`），不带 `*` 是整条；`Bash` 不带括号是所有命令；也认 `PowerShell(...)` |
| `Write(src/**)`、`Edit(docs)` | `write`、`edit`；路径按工作目录算，也认绝对路径、`~/`、`//绝对路径`；`**` 跨目录、`*`、`?` 不跨；不带通配的当文件或目录本身（目录盖住里面） |
| `Read(secrets/**)` | `read`、`ls`、`grep`、`find` |
| `WebFetch(domain:example.com)`、`WebSearch` | `web_fetch`（域名和子域名）、`web_search` |
| `Task(reader)` | 派这个名字的子任务 |
| `mcp__服务器`、`mcp__服务器__工具`（`*` 通配） | `mcp_call` 的某个服务器或某个原始工具名 |

- **判定里的位置**（`policy.Decide`）：渠道（可用场合）→ **deny 规则** → 只碰记忆 → 不是主人发起的 → 默认放行 → 受保护路径 → 自己的端口 → YOLO 拆不开 → 灾难性 → 记住 / 这个对话 → **allow 规则** → 范围档 → 按模式 → 兜底问。也就是：deny 先于一切放行（连默认放行的查网都能拦）；allow 排在受保护路径、灾难性命令、自己的端口、不是主人发起的后面，**越不过它们**；deny 排在场合后面，QQ 渠道里调用这些工具本来就被挡，回话不泄露规则原文。
- **命令的比法**：先按 `&&`、`||`、`;`、`|`、`&`、换行拆成段。**deny**：任何一段命中就拒，另外原文里按词边界出现前缀（引号里的、嵌套的）也拒，宁多勿漏。**allow**：每一段都要被某条放行规则盖住，并且命令拆得开（不是 Opaque、没有看不清的、没有方法调用风险）、没有 mustAsk、没有重定向 / 子表达式 / 反引号 / 单个 `&`；碰到工作目录外面的还要在允许目录里（和“记住”同一套 `covered()`）；否则放行规则不生效、照常问。
- **路径的比法**：deny 对字面路径和联接解析后的真实路径都比（联接绕不过去）；allow 要两边都在规则里。按字符比（路径里有中文，端到端测试查出过按字节拼正则的错）。
- **存储**：和“记住”**同一份** `data/config/tool-grants.yml`，同一个 `Grants`：条目多两个字段 `pattern`（原文）和 `effect`（`allow`、`deny`，没写当 allow）。手写时只写 `pattern`（和 `effect`）就行，不用编 key；写错的规则跳过、原因留在 `Grants.BadRules`，启动时写日志并提醒（写错的拒绝规则不会拦，要让人知道），条目仍在列表里能撤销。不另起文件，规则页和撤销、“最近用过”、重启读回都复用。
- **放行留痕**：靠规则放行的 `By` 是 `rule`，步骤上写“你写的放行规则：Bash(git status:*)”，给模型的状态句也说明；撤销立刻生效（`Recheck`，放行之后还没执行的那一步也作废）。deny 的话原样交给模型：“你设的拒绝规则「…」不让这一步做。不要换个方式重试同一件事，先问主人想怎么做。”
- **界面**：设置 · 工具与审批的“放行规则”里，规则一行一条，写明“你写的规则 · 允许 / 拒绝”，能撤销；列表下面有“写一条规则”：输入框加“允许”“拒绝”两个按钮，写错了说清楚、输入留着。QQ 和别的渠道没有这个入口。
- **形状 × 入口**（四种场合：本地私聊、本地群聊、QQ 私聊、QQ 群）：

| 形状 | 本地私聊 | 本地群聊 | QQ 私聊、QQ 群 |

### 8.4 B5：MCP 配置能跑社区片段

- **参考和采用**：Codex（`rmcp-client` 的 `program_resolver`：Windows 上用 `which` 加 `PATHEXT` 解析 `.cmd`）、Claude Desktop 和 Claude Code 的 `mcpServers`（`command`、`args`、`env`、`url`、`headers`，`${VAR}` 展开）、官方 MCP SDK 的默认继承环境变量集。不做：自动运行没写进配置的东西；OAuth 和 sse（总表 B23、B24）。MCP 是执行第三方代码，配置本身就是用户写的，不额外加门；调用仍要先 `mcp_search`、逐次审批（或“记住”）。
- **配置**（`data/config/mcp.json`）：
  1. 可以直接贴 `{"mcpServers": {...}}`：总开关 `sumika.enabled`、每个服务的 `sumika.enabled` 不写就是开，`include` 不写就是全部工具（`["*"]` 同义）；写了 `false` 或名单的照旧生效，`exclude` 仍优先。**这推翻了 MCP 规格里“`include` 必填、缺失不能当全开”**（该规格的相关句子已标“已被审批规格 8.4 改为”）。
  2. `type` 可以不写：有 `url` 没 `command` 当 http；`http`、`streamable-http` 都认成 http；`sse` 报“Sumika 只连 stdio 和 Streamable HTTP”；两样都没写报“既没写 command 也没写 url”，不等到启动才报。关着的占位条目写得不全不拖垮整份。
  3. `${VAR}`、`${VAR:-默认}` 按系统环境变量展开，`command`、`args`、`env`、`url`、`headers` 都认；`${env:X}`、`${secret:X}` 照旧；没设置又没默认就报变量名，不回退成空字符串。
  4. `command` 光写程序名（`npx`、`uvx`、`node`）不再拼到配置目录下，启动时按 PATH 和 PATHEXT 找；带路径分隔符的相对路径仍相对配置文件。
- **启动**（`mcpclient/process.go`、`launch_windows.go`）：`.exe`、`.com` 直接启动；`.cmd`、`.bat`（`npx.cmd` 之类）走 `cmd.exe /d /v:off /s /c`，参数逐个加双引号，带双引号、百分号、换行、空字符的参数直接拒绝并说是哪个程序，末尾反斜杠加倍；别的后缀（`.ps1`、`.py`）报“写成解释器加脚本”。仍在 Job Object 里，挂起创建、整棵进程树随 Job 收掉。继承的环境变量加了 `APPDATA`、`USERPROFILE`、`LOCALAPPDATA`、`HOMEDRIVE` 等（npx、uvx 要用），仍不带 API 密钥，别的变量在 `env` 里自己写。用真的 `npx.cmd --version` 试过。
- **启动失败写明原因**：握手失败的错误现在带原因一句话：找不到命令（缺 Node.js 还是 uv）、程序路径不对、启动后立刻退出（带退出码）、超时（提示 `sumika.startupTimeoutMs`，第一次 npx 下载包可能超过 30 秒）、没按 MCP 协议回话；再加 stderr 最后四行（最多 400 字）。凭据值（`env`、`headers` 里的值）和 `token=…`、`Authorization: …`、`Bearer …` 一律抹成 `***`，控制字符去掉。错误经现有提醒（`mcp:<服务>`）显示。stderr 只留 4 KB 在内存里，没有写单独日志文件（原审计建议写文件，这里改成进错误原因；要日志文件另开）。
- **测试**：`mcpclient` 的 `TestParseCommunitySnippet`、`TestParseSnippetErrorsAreExplained`、`TestResolveProgramReasons`、`TestRedact`；Windows 的 `TestCmdQuote`、`TestStdioViaCmdShimOnPath`（PATH 里的 `.cmd` 垫片，参数带空格，完成握手拿到目录）、`TestStartFailureReasons`（找不到命令、退出带 stderr 且凭据抹掉、超时提示、`.py`）。
- **形状 × 入口**：MCP 工具只在本地私聊（主人 × 主窗口）可见可用（`Visible` 的场合过滤、`CheckMCP` 的场合判定没动）；本地群聊、QQ 私聊、QQ 群：不可能（`TestEcosystemAudienceUnchanged`、`TestMCPApprovalNotOwnerNeverAutoAllowed` 照旧）。形状：缺（没写 command 或 url）处理了并测了；空（空 args、空 env、空名单）空名单仍是零工具；0（超时 0）取默认；类型错误（`type` 乱写、参数里有双引号和百分号）处理了并测了；敌对（参数借 cmd 注入、错误里漏凭据）处理了并测了。
- **stderr 单独日志文件**（2026-11-10，已合 main，见 8.6）：每个 stdio 服务一个 `data/logs/mcp/<服务id>.log`，不混进主日志。没做：http 传输失败的原因（只加了超时一句）；`.mcp.json` 导入预览（MCP 规格 210 行）；按 cmd 垫片以外的方式运行 `.ps1`。

### 8.5 B7：项目说明的信任改成问一次记住

- **参考和采用**：Codex（`trust_level` 按目录记，不信任就不读 AGENTS，`core/src/agents_md.rs`）、pi（`project-trust.ts` 和 `/trust`）、Claude Code（工作区信任问答）。采用：按目录问一次、记住、能撤销。没采用：把父级目录的说明（`code-rules/AGENTS.md`）也读进来（Codex 也不读，只沿 `.git` 找到的根里找，不改文件名候选、沿 `.git` 找根、`@import` 这些已经对齐的部分）。本来就是项目说明规格第五节计划的“问一次的界面”，当时先用配置顶着。

  4. 同一目录同时只问一次（别的会话在问就等它）；界面没有在看审批卡（没有桌面订阅）就不问，不空等；卡不进步骤记录（它不是哪一步工具调用，`WireApprovalSteps` 跳过 `project_trust`）。
  5. 客户端自知（`projectContextState`）的说法跟着改：不信任时说“还没有信任……会问主人一次，答记住就不再问”。
- **和 `feat/session-cwd` 的关系**：那一条线把工作目录改成按会话选。信任按“这个会话的工作区根的真实路径”认，不绑定全局工作目录，所以会话换目录以后自然按新根重新问或沿用已有的记住；`askProjectTrust` 只用 `ContextIn.Workspace`，不读 `a.workdir()`。合并时 `app.go` 的 `ApprovalRuleOf`（本线，按会话）和那边的 `ApprovalRuleFor`（按目录）要并成一个（说法按会话的档和目录一起算），`approval.Gate` 的会话目录授权和这边的 `ModeFor`、`userRules` 在 `approval.go`、`decide.go` 会有文字冲突。

### 8.6 重启保留、MCP stderr 日志、`/trust`（2026-11-10，已合 main）

> 状态：2026-11-10 做在分支 `feat/perm-tail`，已合 main。三件都是 ADR-342 之后“没做”的小项，主人要求“引导加简单兜底，别做得太紧太复杂”，所以都用最简单的办法。

**一、会话审批档和“这个对话”的放行重启保留**（`approval/session_state.go`）

- **存哪**：一个 JSON 文件 `data/go/approval-sessions.json`（照提醒表 `data/go/reminders.json` 的做法：整份、临时文件换名写，写到一半被杀原文件原样留着）。没有用数据库表：只有几十行，不占迁移号，也不用在 local 库和别的库之间选。内容是 `modes`（会话 → 档）和 `conv`（“这个对话”的规则，带当时的工作目录和批准过的外部目录）。
- **何时写**：`SetSessionMode`（输入框药丸切档，包括“跟随默认”去掉覆盖）和 `ConvGrants` 的加、撤；放行时的“最近用过”时间不写（它只影响规则页排序，不值得每次放行都写盘）。什么都没有了就删文件。
- **读回来时再筛一遍**：只认 `console:` 开头、不是 `:group:` 的会话；档必须是 `manual`、`auto`、`yolo`；规则必须有 key，范围固定成“这个对话”。QQ 会话、群聊、子任务（`internal:`）、手写塞进去的不认识的档，一律丢掉。也就是：重启恢复出来的东西不会比重启前更多，群聊里即使被塞了 yolo，`Decide` 里“不是主人发起的”仍排在档位前面（8.2）。
- **其余不变**：工作目录对不上的旧授权仍不算数（`Match` 比目录）；撤销、回到默认都会写下去，重启不回来；受保护路径、灾难性命令、自己的端口都排在“这个对话”前面，和以前一样。
- **失败**：文件读不了当没有，重启后各会话回到默认档；格式坏了改名成 `.坏-<时间>` 留存并提醒（后台提醒“各会话的审批档读不了”）；写不进去时当场照常生效，药丸切档那一次会返回“这次运行里已经生效，但没写进文件”，放行的写失败写一行日志。
- **没做**：已经不存在的会话的条目不清（量很小，规则页能看见、能撤）。
- 测试：`approval` 的 `TestSessionStateSurvivesRestart`（档、批准过的外部目录、换目录不算数、撤销后重启不回来、清空删文件）、`TestSessionStateHostileFile`、`TestSessionStateCorruptFile`、`TestSessionStateSaveFailureKeepsMemory`、`TestSessionStateNonLocalNotWritten`；`app` 的 `TestDesktopApprovalSessionSurvivesRestart`（真重开一次后台：药丸档、规则页、放行都在；撤销后再重开都没了）。

**二、MCP 服务的 stderr 单独写日志文件**（`mcpclient/stderrlog.go`）

- **放哪**：`data/logs/mcp/<服务id>.log`，每个 stdio 服务一个；超过 1 MiB 换新文件，旧的依次改名 `.1`、`.2`，一共留 3 份；服务重启接着写同一个文件（免得反复崩的服务把旧日志挤掉）。不混进主日志。没有配置键：目录固定，不加开关。
- **每行**：带时间，抹凭据后再写（握手失败原因用的同一套 `scrub`：`env`、`headers` 的值，`token=`、`Authorization: …`、`Bearer …`、`api_key=` 之类，控制字符去掉），一行最多 2000 字，一直不换行的 64 KiB 当一行写下去。文件 0600。
- **服务 id 当文件名**：只留字母数字和 `._-`，别的换成 `_`，不能以点开头，最长 80；`../../evil` 之类跑不出日志目录。
- **失败**：目录建不出来、磁盘满，这一次启动里不再写，也不影响服务运行和握手失败原因（`io.MultiWriter` 的另一路是内存里的末尾几 KB；日志那路的 `Write` 永远回成功）。
- **顺手修的真 bug**：`process.go` 里脱敏用的两条正则（`bearer|basic`、`token|secret|password|api_key…`）里的 `\b` 被误存成了退格字符（0x08），整个仓库的 MCP 脱敏只有 `Authorization:` 那一条真的生效，`token=…`、`password: …` 这类原样漏到握手失败原因里。已改回 `\b`，`TestStderrLogRedactsAndKeepsLines`、`TestStdioStderrGoesToLogFile` 盯着。同类问题在 `app/log.go` 第 68 行还有一处（`\bEOF\b` 同样是退格字符，“EOF”类日志归不到“连接断开”），不在这次范围，已挂待办。
- 测试：`mcpclient` 的 `TestStderrLogRedactsAndKeepsLines`、`TestStderrLogRotatesAndKeepsFew`、`TestStderrLogAppendsAcrossRestarts`、`TestStderrLogFileNameIsSafe`、`TestStderrLogBrokenOrOffOrHuge`，Windows 的 `TestStdioStderrGoesToLogFile`（真起往 stderr 说话的 `.cmd`：日志有内容、凭据抹掉、握手失败原因照旧、没设日志目录不写文件）。

**三、`/trust`**（`app/project_trust.go`）

- **做什么**：项目说明那张“读取项目说明”的卡答了“拒绝”（或 3 分钟没理），这次运行里就不再问。`/trust` 把这个会话现在工作区的这条“不再问”清掉，**下一次发消息时**她重新弹那张卡（允许一次 / 记住 / 拒绝）。**不当场替主人信任**：信任只能是主人在卡上点的，`/trust` 本身不写任何规则（`TestSlashTrustReasksAfterDeny` 查规则页为空）。没有当场弹卡，是因为斜杠命令的处理函数里没有回合身份，伪造一个不如等下一轮自然弹。
- **几种回复**：已经信任了 → 分三种说：记住过的指给“撤销去放行规则页”，这次运行里允许过一次的说“重启后会再问”，配置里的信任根说“去配置里改”（测了前两种）；目录里没有说明文件 → 说不用信任；项目说明整体没开 → 说没开；带多余参数 → 拒绝并说它针对当前工作目录；工作目录现在用不了 → 说原因。
- **入口**：主人在本地私聊输入框（命令表只在这里认，`slashEligible`，旧测试 `TestSlashOnlyEligibleInLocalPrivate` 盯着）；`sumika-ctl trust [--character <id>]`（自检话题，只带 `--character`，不带参数；经 `internal/ctlserver` 校验，被拒的请求不碰后端）。注意：ctl 那条按该角色**自检话题**的工作目录算（没绑就是全局默认目录），所以只有它和主会话用同一个工作区根时才能清掉主会话的那条；信任本来按真实路径认，不按会话。

### 8.7 `ask` 规则和规则的作用范围（2026-11-10，分支 `feat/perm-ask`）

> 状态：做完，待合 main。补 8.3 当时“没做”的两样：Claude Code 的 `ask`（强制每次问），以及规则只对某个项目、某个会话生效。只加“更严”的 ask 和“更窄”的范围：**不让任何原来要问的调用变成不问**。

**参考和采用**（出处：Claude Code 官方文档 `https://code.claude.com/docs/en/permissions` 与 `settings-reference`，2026-11-10 用 context7 查）：

- Claude Code：`permissions.allow / ask / deny`，评估顺序 deny、ask、allow，第一个命中的决定结果，规则多具体都不改顺序；匹配到的 ask 规则哪怕有更具体的 allow 也照样问；PreToolUse 钩子返回 allow 也绕不过 deny 和 ask；规则来自 user、project、local、managed 几层设置文件，跨层也是 deny 先于 allow。采用：三种效果和 deny > ask > allow 的顺序，ask 的写法和 allow、deny 完全一样（同一套 `Bash(...)`、`Write(...)`、`mcp__...`）。Sumika 的钩子本来就不能批准（`userhooks` 没有放行出口），不用另挡。
- 没采用：按设置文件分层。Sumika 的规则都在一份 `tool-grants.yml`，作用范围改成每条规则自带 `project`、`session` 两个可选字段，更直接，规则页一眼看到。managed 层没有对应物。
- **会话范围是 Sumika 自己加的**：Claude Code 的 local 层是“项目里不进 git 的个人设置”，不是会话。
- 我们已有的：`policy.Decide` 的判定顺序、`Grants` 存规则的同一份文件、规则页、`Gate.ParentOf`（子任务找派它的会话）。

**数据形状**（`policy.UserRule`、`approval.Rule`、`api.ApprovalRule`、`tool-grants.yml` 条目）：

| 字段 | 意思 |
|---|---|
| `effect` | `allow`、`ask`、`deny`（没写当 allow） |
| `project` | 可选。绝对路径（盘符或 UNC）。规则只对工作目录是它或在它里面的调用生效 |
| `session` | 可选。会话号。规则只对这个会话生效 |
| key | 没有范围时和以前一样 `rule:<effect>:<原文>`；有范围在后面加 `@dir:<归一后的目录>`、`@conv:<会话号>`，所以同一原文在不同范围里是各自独立的规则，不会互相顶掉 |

两个范围都写要同时满足。全部可选，旧文件不用改，**没有存储迁移**（不是数据库表，是 yaml 的可选字段，所以也没有取迁移号的事）。手写 yaml 只写 `pattern`、`effect`、`project`、`session` 就行（`effect` 大小写不分）。

- **换回旧 exe 的风险**：旧版本不认 `project`、`session`，会把带范围的 allow 读成全局放行。所以程序写文件时，带范围的 allow 的 `effect` 写成 `allow-scoped`（旧版的效果校验不认它，会整条丢掉并在启动提醒里报“写错了”，只会多问）；新版读回来当 allow。ask 规则旧版同样不认（丢掉，等于回到没有这个功能）。手写文件想要同样的保护就照写 `effect: allow-scoped`，写 `allow` 加范围新版也认。
- 记号：规则原文里不能出现 `@dir:`、`@conv:`，项目目录和会话号里不能有 `@`（key 用它们拼，免得两条规则撞成一个 key 后一条被悄悄吞掉）；项目目录不收 `\\?\`、`\\.\` 这类设备路径写法（和普通写法的工作目录比不上，写进去永远不命中）。

**判定顺序**（`policy.Decide`）：整个原有流程（7.2、8.3）不动，得到结论以后再过一道 ask：

- 结论是**拒绝**，或本来就**只问一次**：原样返回，一个字不碰。所以受保护路径、`.sumika` 目录、自己的端口、不是主人发起的这些卡，范围档一个都不会因为 ask 规则变多，场合不对的 `deny` 也不会变成弹卡。
- 结论是**问**但本来带范围档（普通手动档的问、灾难性命令的“只给这个对话”）且某条 ask 规则命中：仍是问，范围档收成“只这一次”（`Limit: once`、`Sticky`），原因保留，带上规则 key（别在 ask 规则底下记下一条授权：以后撤了规则它就悄悄放行了）。只会更严。
- 结论是**放行**（默认放行的查网、记住、这个对话、放行规则、档位）且某条 ask 规则命中：改成 `ask`，`Limit: once`、`Sticky`（卡上只有“这一次”，不给“这个对话”“记住”：规则要每次都问，给了范围档只会记下一条被规则压住的授权）。
- 结果就是 deny > ask > allow：deny 在原流程里先判；ask 压过一切放行；没命中 ask 的放行照旧。
- **匹配比拒绝规则一样宽**（`policy.MatchAsk`）：命令任何一段命中、原文里按词边界出现、分析器给的命令名（含别名）命中都算；路径连联接解析后的真实路径都比；对上级目录的递归搜索也命中。多问一次比漏问好。放行规则仍是严的那一套（每段都盖住、拆得稳）。
- 靠 ask 问出来的，步骤记录 / 卡片的原因写“你设了“每次都问”的规则「…」”，规则页上这条的“最近用过”跟着更新（`Grants.Touch`）。

**作用范围怎么匹配**（`UserRule.scopeApplies`，只管 allow 和 ask；deny 不分范围，永远全局）：

- 项目：调用的工作目录（`Env.Workdir`，就是会话当前的工作目录）归一后（统一斜杠、去掉 `.`、`..` 和结尾分隔符、不分大小写）等于项目目录或在它下面，按目录边界比（`D:\Work` 不盖住 `D:\Work2`）。工作目录还要看联接、符号链接解析后的真实路径：allow 要字面和真实路径**都**在项目里（不能靠联接绕进来），ask 任一边在项目里就算（多问）。比的是工作目录，不是被碰的文件路径：碰到项目外面的文件，仍由 Write、Read 规则自己的路径匹配和“允许目录”管；相对路径的规则（`src/**`）照旧按会话工作目录展开，不按项目目录展开。
- 会话：会话号完全相等（区分大小写）。ask 规则还认**子任务**：子任务（`internal:<任务号>`）沿 `Gate.ParentOf` 一路往上（最多四级、防环）找到派它的会话，那个会话设的 ask 对子任务也算数，免得靠派子任务躲开；**allow 规则不继承**（子任务只吃全局的和它自己会话的放行，同 `TestTaskGrantDoesNotWidenChild` 的思路）。
- **看不出场合时**（工作目录是空、会话号是空：内部调用、对拍、MCP 调用拿不到工作目录）：allow 不生效（范围不明就不放行，只会多问），ask 照样生效（范围不明照样问）。两边都往“多问”的方向走。
- 写进去之前校验（`ParseScopedRule`）：项目必须是绝对路径；拒绝规则不能带范围（范围只会让拒绝变窄）；MCP 规则不能带项目（`mcp_call` 的判定拿不到工作目录，可以带会话）；会话号不含空白控制字符和 `@`。手写文件写坏了（范围写错、或 `project`、`session` 写成数字、列表这类不是文字的）：ask 规则当全局生效（多问），allow 规则整条不生效（多问），deny 带了范围当全局（多拦）；原因都留在 `Grants.BadRules`，启动时提醒。域名规则：拒绝、ask 把主机名末尾的点（`example.com.`）当同一个域名，放行规则不放宽。
- 目录不存在、会话已删：只是字符串比较，不报错也不放大——对 allow 是永远不命中（多问），对 ask 是规则不再碰到任何调用（规则页写“这个对话已不在，规则不会再生效，可以撤销”，由主人撤）。不自动清理，免得悄悄删规则。

**界面**（设置 · 工具与审批 · 放行规则）：

- 规则行：名字是原文；下面一句“你写的规则 · 允许 / 每次都问 / 拒绝 · 只在项目 D:\… · 只在对话 白羽 · 记下 · 最近用过”，右边“撤销”（点了立刻生效，同 7.6）。带范围的同一原文是各自一行。

- 说明文字常驻一行（设计语言第十一节）。
