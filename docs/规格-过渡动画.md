## 一、结论先说

- 盘点 **70 处**状态变化（按钮族等同类只记一行，写明覆盖哪几处）。其中 **硬切 37 处，部分有动画 7 处（含硬切的那一半），已经有动画 12 处，明确不做 12 处，现在没有这个控件 1 处，待实测 1 处**（逐类编号见 4.6）。真正要补的是前两类共 44 处。
- 现状的底子其实不差：颜色类悬停（`ControlMotion` 140ms）、开关、分段指示、新消息进场、悬停操作条、窄窗三层进场、过程箭头旋转都已经有；缺的是三大块：**浮层（菜单、下拉、对话框、选区条、斜杠面板）进出场全是硬切**、**所有“换内容”（切会话、切页、切设置分类、切右栏选项卡）全是硬切**、**所有展开收起（过程气泡、工具卡、目标行）的内容是硬切，只有箭头在转**。
- mygo v0.8.3 把这些要的积木基本备齐了：`Transition` 的 `Enter / Exit / Collapse / Position / Size / Match / Fly`、`ContentTransition`、`AnimateTo / Spring / Jump / Keyframes`、`ChildExit`、`ScrollIntoView` 的 `Animation`，面板挂在 `Overlay / PopoverBase / DialogBase` 里同样能播进出场（mygo 自带的 `overlay_transition_test.go` 证实）。真正的难点只有两个，都和**虚拟列表**有关：行里的高度变化会不会让滚动跳；以及 `List` 不触发行的进场。第五节铁律专门回答这两个。

### 3.2 谁拥有 token

时长、曲线、弹簧继续放在 `chatui.Tokens`（聊天区用）和 `winshell`（外壳用），**不再各写一份常量**：新增的 `Exit` 时长、幅度和 `EaseIn` 加在这两处现有位置，不另开包。外壳和聊天区同一件事（比如菜单）共用外壳的那份，聊天区通过宿主传进去。

### 3.3 减少动态效果（ReduceMotion）怎么走

mygo 的规则已经大体符合 ADR-124，我们只管三件事：

1. **mygo 替我们做的**：`AnimateTo / Spring` 到终点（`motion.go:339`）；`Transition` 保留淡入淡出，位移、缩放、折叠归零；`FollowAnimation` 直接到底；`ScrollIntoView` 的动画直接到位；`Spinner` 自带。
2. **要我们补的**：纯透明度、颜色混合的 `AnimateTo` 通道必须写 `NonMotion: true`，否则减少动态时淡变也变成硬切，违反 ADR-124。现在已知漏的：`winshell/settings.go:317` 开关的 `thumb` 颜色通道、`chatui/hoverbar.go:89`、`mediabubble.go:148`、`bubble.go:302` 的淡入通道、`chatui/process*.go` 的 `chevron`（箭头旋转是位移，不带，这条对）。新写的一律走下面这组命名的 `Animation` 值，不再现场拼：
   - `AnimFade`：140ms、`EaseStd`、`NonMotion: true`（颜色、透明度）
   - `AnimMove`：弹簧，`NonMotion` 不开（位移、缩放）
3. **自己计时的东西**（`quote.go:185` 的高亮闪、`bubble.go:713` 的点、`loadui.go:55` 的骨架）必须读 `c.Preferences().ReduceMotion`：点和骨架已经读了；高亮闪是颜色脉冲不是位移，按 ADR-124 保留，不改。以后新增的自绘动画一律要读。
4. **应用级开关**：Go 这边的 `desksettings` 里没有“动效”设置（设计语言九的“动效速度”和“动效：关”是 Bun 的），现在只认系统。要不要加见第八节问题 3。
5. **测试**：每个新动效至少一条 `NewTesterWith(..., TesterOptions{Preferences: ui.Preferences{ReduceMotion: true}})` 的断言：淡入淡出还在、位移为 0、终点一致。

## 五、铁律

1. **跟手的不加延迟。** 拖分栏（`Split`）、拖滑块、拖选文字、滚动、键盘输入回显、键盘上下选中，一律直接更新；拖动中用 `Jump`，松手后才用弹簧并带上松手速度。列表折叠如果要动宽度，只在 Ctrl+B 和点放大镜这类切换上动，拖到 130 以下的收起不动。
2. **退场保留内容。** `Exit` 靠 mygo 拷贝上一帧；由布尔状态驱动的（抽屉）要让元素活到出场放完，期间不读实时数据、不收点击和焦点，Esc 在拷贝上不再响应。放完才算“已关好”，中途再打开从当前进度倒回。
3. **不引起列表跳动。** 动画只动透明度、变换、颜色，不动会让别的东西重排的尺寸，除非满足第 4 条。消息列底边跟着输入框高度走，输入框里的展开收起（C23、C24、C28）会逐帧推消息列，必须在 Tester 里量消息列可见首行位置的跳变（`scrolltop_test.go` 里量跳变的写法可以直接照用）。
4. **虚拟列表里不动高度造成滚动跳变。** 行里的高度变化（C5、C6、C7）和 ADR-304 第 4 条要求的“过程气泡展开要动”冲突，调和方式：
   - **只在行顶可见、且列表没有贴着末尾跟随时**才动高度。这时行上方的东西不动，只有它下面的行被推下去，和展开的预期一致。
   - **列表贴着末尾（`FollowEnd` 吸着底）或行在视口上方时，硬切高度，只让内容淡入。** 否则吸底会把整屏往上顶，看上去所有消息一起跳。
   - 动画用**固定高度盒**（`AnimateTo("h")` 驱动一个 `Height`，内容在盒里裁剪），保证每一帧列表看到的行高是单调变化的，不要靠内容自己撑开。
   - 验收：Tester 里 `Advance` 逐帧，读展开行上方可见首行的 Y，要求全程不变；贴底时断言硬切。如果量出来有跳变，这一项退回“硬切加内容淡入”，不硬上。
   这一条是第八节问题 1，推荐按上面做。
5. **`List` 里行级、气泡级的动画一律走状态驱动，不挂 `Transition` 的 `Enter`**（第二节坑 1）；非列表的区域（外壳、设置页、输入区、浮层）正常用 `Transition`。
6. **性能预算。**
   - 基线：S7 验收万条历史 p95 7 到 11ms（旧界面 14 到 20ms）。加动画后同场景 p95 不超过 16ms（60Hz 一帧），播放动画那几帧单独量，不平均掉。
   - 怎么量：真窗口 `MYGO_FRAME_STATS=all`，帧耗时写标准错误（`native/README.md`：演示模式和 e2e 构建）；Tester 里用 `Advance(d)` 加 `Frame()` 取起点、中途、终点三帧（`headless.go:337`、`:531`），照 `overlay_transition_test.go` 的写法，值落在预期区间。
   - 静止后不要帧：动画放完、什么都没动时 `Tester.FramePending()`（`headless.go:537`）必须为假，否则是动画没收尾在空转。
   - 只动透明度、变换、颜色；液态玻璃、磨砂面板（`glass.Glass / glass.Blur`）挂进出场时，要实测它每帧会不会重算模糊（mygo-music 的做法是把模糊底图预制成小图再叠）；没验证前不给带材质的大面板（标题栏、输入框）加尺寸过渡。
   - 同时在播的动画别堆：一次切换最多一个“面板级”加若干“反馈级”。
7. **明确不做的和理由。**
   - 键盘导航、输入回显、菜单项高亮、滑块、拖选：跟手，加了就变钝（A7、B6、C22、E3）。
   - 频繁变化的数字（用时秒数、token、未读数）：直接更新（E4）。
   - 历史消息、回滚重新挂上的行：不播进场（C1）；草稿、待发、三个点换成真消息：原地换（C2）。
   - 窗口宽度过阈值时的整套布局切换：mygo 不播，也不值得手写（A8）。
   - 流式回复变高的平滑跟随：主人 10-24 不喜欢（C10、C11）。
   - 加载更早的消息插在上方：不动正在看的行（C30）。
   - 拇指拉长、列表错开进场、翻板对话框、大块模糊：ADR-305 定了只在液态玻璃材质开，本规格不做。按下缩放已被 ADR-349 改为所有材质都开（试用中）。
   - 设置里的材质、字号、圆角滑块：低频或跟手（D6、D7）。

## 八、要用户拍板的问题

1. **过程气泡展开能不能动高度。** ADR-304 第 4 条要“外壳先变内容再浮现、不过冲”，虚拟列表又怕滚动跳。推荐按第五节铁律 4：行顶可见且没贴底时动，否则硬切加内容淡入，量出跳变就退回硬切。
2. **新消息、流式要不要开平滑跟随（`FollowAnimation`）。** 2026-10-24 你说过不喜欢底边一鼓一缩；推荐继续不开，新消息的“出现”靠现有的上移 8 淡入。你要是想再试，用 `SUMIKA_FOLLOW=glide` 并排对比。
3. **要不要加应用级“动效”设置。** Go 这边现在只认系统“减少动态效果”，设计语言里的“动效速度 0.8 / 1 / 1.25”和“动效：关”是 Bun 的，没搬过来。推荐加一项三档（跟随系统 / 减少 / 关），放第 3 批之后，统一读一处。
4. **会话列表折叠要不要动宽度。** 推荐：Ctrl+B 和点放大镜时内容淡入加宽度 230ms，拖动不动；松手收起时的吸附动画等 Telegram 式拖动折叠那条线一起定。你 2026-11-09 要的“像 Telegram 那样直接拖动折叠展开”现在 `DragList` 已经会在拖到 130 以下收成头像列，缺的是中间状态和吸附，见待办新条。
5. **主题交叉渐变用什么办法。** mygo 没有整窗颜色接力。候选：(a) 切换瞬间截一张旧窗口的图盖在上面淡出（要确认 mygo 能不能读回窗口像素，`ui.Canvas` 和 `Painter` 都没查到读回接口）；(b) 把所有背景换成按新旧调色板 `AnimateColor` 混合，改动面是整个 `Palette`；(c) 不做，只保留切换瞬间。推荐先花半天验证 (a)，不行再选 (b) 的缩小版（只混底色和气泡色）。
6. **`RouteMotion` 从 250ms 对齐到 230ms。** 设计语言九和 ADR-155 写的是 230，代码里是 250。我会在第 1 批直接对齐，不另问，除非你想留 250。
7. **右栏“浮动”的范围。** 你 2026-11-09 说“窗口比较窄的时候展开可以变成浮动在聊天区上”，现状：中等宽度（713 到 1006）右栏已经是盖在聊天上的抽屉，更窄（小于 713）是整层替换聊天（三层）。你说的“比较窄”是想让更窄的档也变成抽屉而不是整层替换，还是只想把中等档那套做好？我理解成前者、同时后续所有档都支持“浮动”和“挤开”两种，只差是否挤开气泡。请确认。
8. **液态玻璃上的进出场。** 浮动右栏、对话框、菜单做成带模糊的玻璃面板后，进出场时每帧要不要重算模糊没验证。第 1 批实测后再定：太贵的话玻璃面板只做淡入淡出、不加缩放。
9. **三栏右栏开关挤开还是浮动。** 现在三栏（大于 1006）开右栏会挤窄聊天区，动画要逐帧重排所有气泡，风险高。推荐第 4 批先把浮动做好，三栏默认保持“硬切加右栏内容淡入”，等你定要不要给三栏也做成可选的浮动。
