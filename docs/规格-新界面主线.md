## 一、依据与范围

依据 ADR-316：`cmd/sumika-proto` 工作台布局与 `internal/chatui` 是界面主线；旧根包界面只修影响日用的问题。显示不退化、同一后台、十倍数据不比旧界面慢以后才替换。过渡期在同一个 exe 中切视图，默认旧界面。

参考与采用：

- [新界面缺口地图](notes/盘点-新界面缺口地图-2026-11-07.md)：先补展示段，旧界面已有的图片、视频、文件、卡片、转发不能列为第二版。
- 后端类型和转换盘点（私有存档）：`api.MessageView`、宿主 `msg`、组件 `chatui.Msg` 职责不同；不改后台 DTO，不让展示层再解析旧 JSON。
- [mygo-music 拆解](notes/拆解-mygo-music-界面和动效-2026-11-07.md)：采用 ADR-304 已定的来源几何与退场生命周期规则；不在纯函数搬移时夹带动效改造。
- [常见边界清单](notes/清单-常见边界情况-2026-10-26.md)：本次重点为文本表示、空值、预算、缓存身份和迟到结果。
- [回合循环与主窗口参考](subsystems/agent-and-console.md)、[界面接 Go 后台](规格-界面接Go后台.md)、[设计语言](设计语言.md)：分别管现有实现、后台契约与视觉规则。

S0～S7 做显示与读取接线。发送、编辑、回应选择器、附件、引用回复发送、思考/工具过程真实数据、设置页重做不在此范围；正式页面不能拿 proto 假动作冒充已接入。`Steps` 在没有真实过程接口时为 nil。S8 切默认和删除旧界面另定实施规格；本规格不授权改权限、真实配置或数据。

## 二、分层与唯一缓存

数据流：`api.Reader` → 根包 `msgFromView` → 后台线程计算 `msg.blocks` → 旧界面或 `chatui` 绘制。正文无段时同样在转换阶段调用 `textBlocks`，不是每帧再算。

只新增 `internal/segview` 一个纯排版包；不建 `chatview`、`imgcache`、资源登记表或全局句柄分配器。宿主转换与媒体胶水放根包 `chatview.go`、`chatmedia.go`；工作台组合放 `workbench_view.go`。

- `msg.blocks` 是唯一的段排版缓存。S2 后它改为共用 `[]segview.Block`；新旧视图读同一切片，按不可变数据使用。
- 不加 `msg.chat`，不在 `chatui.Msg` 上另算 Segs→Blocks；构建消息参数只是引用现成块与元数据。回应等必要投影在现有转换阶段完成，不在每帧扫描整页。
- 根包 `attach`、`WatchConversation` 保持一份订阅。分页、流式、转发节点都沿原来的后台投影与发布入口；`gen/srcGen` 防迟到规则保持。
- 消息版本替换时，正文块与宿主凭据一起替换；滚动与展开状态沿已有消息身份规则保存。`Snapshot.Version` 不跨订阅比较。
- 两个视图各有 ListState；切视图按消息 ID 及行内偏移恢复锚点，不重建宿主或订阅。

### 2.1 S1：只搬纯函数

S1 新建 `internal/segview/inline.go`，搬 `Run`、`FaceRef`、`LinkRef` 及 `LinkRuns`、`CleanText`、`FaceFallback`。`trimInline` 中裁剪 runs 的循环抽为 `TrimRuns([]Run) []Run`，仍原地裁剪、无额外复制；根包保留组块包装。

根包直接使用导出类型和函数，不留别名或转发包装。`seg`、`block`、`blockKind`、`blocksOf`、`textBlocks`、`atText`、`imageNote`、`notesOf`、号码处理在本步留原处：它们依赖 DTO、宿主或块容器。`internal/linkreader` 和 `internal/config` 当前不 import `api`，但不因可以搬就扩大本步。

这一步仅改变依赖位置，不改变段模型。`blocksOf` 主分支整体搬移属于 S2，不能和 S1 合成一个提交。

### 2.2 S2：换段类型再搬完整排版

`segview` 不 import `api`、`desktopread`、mygo 或 MewTypeUI。下表是目标模型，不是 S1 已实现的字段：

| 当前字段 | segview 表示 | 规则 |
|---|---|---|
| Kind、Text、Target、Ref | 同名 string | 保留 DTO 种类，不另造种类翻译 |
| Media | HasMedia、HasHash bool | 不存 hash；见三态表 |
| Cover | HasCover、HasCoverHash bool | 封面凭据同理，不允许任意哈希取封面 |
| Download | CanDownload bool | 凭据与 downloadKey 留根包 |
| DurationMS、Size | 同名 int64 | 0 保持未知，不编时长或百分比 |
| Width、Height | 同名 int | 0 保持未知，绘制采用现有占位比例 |
| Animated、Sticker | 同名 bool | 动图与贴纸语义保留 |
| FetchState、FileKind、MediaState、Issue | 同名 string | 不改变状态优先级 |
| Summary、Name、Links | 同名字段 | 名字/摘要回退、链接顺序保留 |
| Card | *Card，Title/Description/Source/URL | 四个字段完整保留 |
| Forward | *Forward，Title、Lines [3]string、Count、Missing、State | 缺失数与读取状态不能丢 |
| 根包 position | Position int | 消息内原段下标，0 是有效第一段 |

| 图片事实 | 排版结果 |
|---|---|
| 有凭据、有 hash | 图片块，可与相邻图片成组 |
| 有凭据、无 hash | `[图片没下载下来]`，即使 MediaState 是 pending/nomedia 也不覆盖 |
| 没凭据 | 按 MediaState 选择占位；emoji 且 Ref 非空先走商城表情名字壳 |

MediaState：空/nomedia → 尚无本地媒体；too-big/too_big → 太大；expired → 过期；forward_limit → 图片太多；pending → 正在下载；blocked → 主机不允许；not_image → 文件不是图片；其他（含 outbound-released）沿旧代码显示没下载下来。Issue 非空先插旧记录提示。

`Block` 保留 Kind、Runs、Imgs、Text、Card、Video、VideoIndex；Card 也承载转发，Video 也承载文件，先保持语义以便逐字节对照。Kind 的八类为 Inline、Images、Note、StickerNote、Card、Forward、Video、File。`AtText` 改成接 Target/Name；`ImageNote` 改接 HasMedia/MediaState，判断不变。完整 `BlocksOf`、`TextBlocks`、`TrimInline` 与 displayName 在这一步搬移；`notesOf` 仍由宿主处理。

S0 的稳定 JSON 输出描述可见排版语义、原段位置和媒体三态，不把 Go 类型名或资源 hash 当成布局。S2 只适配测试输出器，保留旧根包 `TestBlocksOf` 等行为测试；禁止重录基线消除类型迁移差异。

### 2.3 媒体：宿主回调，不建登记表

S3/S4 给 `chatui.Host` 注入一个 `MediaResolver` 接口。方法按用途分 `Image(messageID, position, cover, wantPx)`、`Face(id)`、`Download(messageID, position)`；返回 chatui 自有的就绪/加载/失败状态、ui.Image 和说明。动作（下载、取消、打开、看图、展开转发）也是宿主回调。接口只供 UI 线程查询现有状态和请求宿主安排后台工作，不同步读盘/解码。

messageID 在当前宿主会话/转发节点作用域内解释；Position 指向同一 `msg.segs` 的原段，不能用 hash 定位交互。根包把原 `api.MediaRef/VideoDownloadRef`、downloadKey、转发路径留在消息数据与既有 store 中。换源、换会话、换版本沿现有取消与代次守卫拒绝旧回调；不把位置带到另一份快照继续用。没有全局 key，也没有随分页销毁但被消息缓存引用的登记表。

`images.go` 和 `faces.go` 实际含 ui 依赖，整体留根包。复用现有静态/动态图读取、像素预算、档位、淘汰和 missing 不重试；不声称它们是纯数据包。`media_download.go` 的 `downloadPresentation` 返回 `content.MediaStatus`，根包在 S4c 映射为 chatui 枚举，不能让 chatui 引用 MewTypeUI。准备媒体、启动播放器、文件打开都留宿主。

## 三、消息映射与绘制契约

S3 在 `chatui/group.go` 明确新增：`Msg.Blocks []segview.Block`、`Msg.Markdown bool`、`Msg.Notes []string`；`Quote` 新增 `Owner bool`、`Gone bool`、`Target string`、`Preview bool`；`Reaction` 新增 `Face string`。Quote 不新增 Segs：沿旧 `quoteOf/displayPreview/oneLine` 算好摘要，已有 Name/Text 足够承载，避免又排一份引用块。

| 来源 | 新界面规则 |
|---|---|
| msg.id、actor、mine、who、at | 对应 ID、Sender、Self、Name、time.UnixMilli；Self 在本地私聊/本地群聊为主人在右，QQ 私聊/QQ 群为角色在右，修正现有字段注释 |
| msg.md | Markdown；不能仅凭 Self 判断角色 Markdown |
| msg.blocks | 直接传 Blocks；有段按块，无段已在宿主排成块；角色 Markdown 复用现有正文逻辑 |
| msg.color string | S3 在根包加颜色转换；按现有合法十六进制角色色解析为 sRGB，再转 chatui.OKLCH；空/非法值用零值与 NameID 回退，不能把 string 当 OKLCH |
| recalled、unsent、partial、aborted | Notes 直接沿 notesOf 顺序生成，可同时有“被打断”和“已撤回”；部分未知不显示“没发出去”。State 用撤回 > 被打断 > 明确失败 > Sent，不能因单枚举丢掉并列小字 |
| Reply Ready | quoteOf 的名字、压缩摘要、owner、target、preview 映射；空名“某人”、空摘要“[消息]” |
| Reply Loading/Failed/Unsupported；只有 reply 段但没有 ReplyTo | Gone，保持旧“原消息不在本地”；Loading 改文案另排，不夹在重构里 |
| Reply Recalled/Stale | 旧 quoteOf 不使用，不新增推断状态；整页过时由原宿主状态栏负责 |
| Reactions | 保留既有 Emoji/Count/Mine/By，复用 chatui/reactions.go；按 Ref 首见顺序合组，ActorKind+ActorID 去重，无 ActorID 用通知 ID |
| ReactionView.Ref | 没有 kind 字段。沿 unicodeReaction：十进制码位在 0x2000～0x10FFFF 且非代理区才转字符，否则 Face 保存平台编号 |
| Version、Source、权限凭据 | 留根包，不进 chatui；新视图不另订阅 |

S3 颜色转换必须测试有效色、空值、非法值及 sRGB↔OKLCH 数值回转。正式主题从宿主注入 Tokens：S5 先列 MewTypeUI → chatui.Palette/尺寸/动效逐字段对照。当前已读 Tokens，尚未证明完整映射；映射不了的语义色列明缺口再定，不擅自换掉用户主题或用默认色覆盖（默认主题改为原型预设，见 S5 一节）。它不阻塞 S0/S1。

## 四、显示对齐清单

S7 逐项对照，任何一项缺失不能切默认：

1. 原序图文、连续同样式文字合并、首尾空白、U+FFFC 清理、20 个正文链接预算与点击/复制。
2. @ 全体、显示名、无名号码回退；小黄脸图/字符/文字回退；超级表情；无图商城表情独占壳。
3. 图片三态、所有 MediaState、相邻图组、静态/动图/贴纸、尺寸未知占位、档位 128～1536、原图查看及失败反馈。
4. 视频封面、时长、下载进度/取消/重试/播放；文件名、大小、类型、下载及完成后的对应显示。
5. 语音占位；未知段占位；Issue 提示；reply 段不重复画。
6. 卡片标题/描述/来源/链接；合并转发标题、三行、数量/缺失、展开与嵌套返回。
7. 引用名字/摘要、主人色、跳转、原消息缺失；转发引用只读预览。
8. 回应药丸、小黄脸/Unicode、人数去重、悬停名单与头像/数字规则。
9. 撤回保留正文、没发出去、被打断、部分未知；角色 Markdown；发送人名、主人名、头像失败首字回退。
10. 时间、分组、分页锚点、实时尾随、选择与复制、源切换、加载/错误/过时状态。

完整设置、输入/审批等日用功能迁移仍是 S8 切默认的前置，不能用本规格的“显示对齐”冒充日用替换全部完成。旧界面未有的功能在缺口地图保留，不扩大 S0/S1。

## 六、资源、窗口与已知边界

- 生产字体按 ADR-322 用原型预设的文渊圆体，不沿宿主主题（放法见 native/README.md「界面字体」），Twemoji 未安装时用文字；不从 `_external/sumika-bun` 偷读资源。S6 去掉 proto 的 bunPublic 默认路径，只在开发工具显式环境变量下读外部资源；要内置字体另带许可证提交。
- 正式窗口复用 shell.ready、单实例、托盘、关闭隐藏、退出；不用 proto 的独立退出流程。系统圆角遵守 ADR-284。
- scene 假数据留 cmd/sumika-proto；正式 -demo 注入根包 demoReader，失败不能回落 mock。
- 空白裁剪不能丢 Face/Link 的结构；链接预算在整条消息内共享，不能每段重置。
- HasMedia 与 HasHash 不合并为一个布尔值；即使 hash 为空也保留凭据存在的事实。Position=0 不能作为“无媒体”哨兵。
- 消息块和宿主媒体来自同一版本；换源不能复用旧凭据。图片/视频读取失败不得吞错或伪造成功。

量法：`native/scale_frames_test.go` 的 `TestScaleFrames`，加 `MYGO_FRAME_STATS=all` 让 mygo 把每一帧的 build、layout、paint、present 耗时写到标准错误，按分段标记统计 p95。命令：`SUMIKA_S7_FRAMES=workbench,legacy SUMIKA_S7_RUN=1 MYGO_FRAME_STATS=all go test -v -short -count=1 -run 'TestScaleFrames$' .`，第二遍把顺序倒过来，第三遍同第一遍。数据是 10 个角色轮流说话的 1 万条消息（长短不一，约二十分之一带多行，五十分之一很长），窗口 2048×1030、像素比 1.25，旧界面是 `chatView`，新界面是 `workbenchChat`，同一份数据。每遍按顺序走四段：从底部滚轮上翻 400 步、跳到第 5000 条再翻 300 步（每步 300 DIP）、从底到顶每 25 条跳一次共 400 跳。证据存档在主工作区 `data/dev/s7-frames/`（原始日志、统计脚本、统计输出）。

### 9.2 做了什么

组件在 `internal/chatui`（不依赖后台类型），接线在根包 `workbench_composer.go`、`workbench_attach.go`：

- **输入区** `chatui.Composer`：每个会话一份草稿（根包 `app.composers`，换数据源时清掉）。由若干引用卡（`Cards`）加主输入框（`Main`）组成，发出去的顺序就是添加的先后，普通文字块永远排在最后（主输入框在最下面）。纯方法 `AddQuote`、`Remove`、`Esc`、`Attach`、`Detach`、`Blocks`、`Check`、`Begin`、`Accept`、`Reject` 不用窗口就能测。
- **发送**（私聊）走 `api.LocalInputs.SubmitLocal`：提交有回音，收下才清草稿；被拒时所有块原样保留、解除只读，错误里的"第 N 块："对应到出错的那张卡，原因写在卡上，改动这一块的文字后消失；认不出是哪一块的写在输入区上方。只有一个普通块且没附件时仍用 `Text`，和旧输入一字不差。本地群聊仍只发文字（旧的 `SendLocalGroup`）。
- **停止、审批**：停止用 `StopLocalRun`；审批卡用 chatui 自己的审批块（`Host.ApprovalCard`），只摆"允许一次"和"拒绝"（后台只认这两种，`Host.ApprovalOnce` 藏起"更多选择"）。她的回复草稿在输入区上方以气泡显示，没有字时是"正在输入"。
- **选区条**（`chatui/selection.go`）：消息正文里选中文字松手，稳定 150 毫秒后在松手位置下方浮出"回复 / 复制"。选区文字里的行内表情换回表情名，与复制出来的一致。偏移只在"这条消息就是一整段、选区文字对得上"时传给后台，其余传 0，让后台按文字找。只有本地私聊真实后台才摆"回复"，本地群聊、QQ、演示数据只留"复制"。
- **附件**：粘贴图片先在输入区挂一个"保存中"的方块，后台 `api.LocalImageSaver.SaveLocalImage` 把 PNG 存进 `go/media/local/`（内容寻址）并返回 `Path`，再换成缩略图；保存中不能发送。新图还没有事件，拿不到媒体凭据（凭据要对上会话里已有的事件），所以附件用 `Path` 不用 `Media`。粘贴或拖入的文件和文件夹只记路径；路径不存在的不挂并说一句；一块最多 16 个；同一块里同一路径只挂一次。粘贴挂在粘贴所在的块，拖入挂在最近有焦点的块（卡或主输入框）。链接就是普通文字，由现有的链接展开处理。
- **发出去的气泡**（`chatui/parts.go`）：按 `Parts` 的顺序画。引用块写被引的人和那一段（最多三行），回复文字和附件小条跟在后面；普通块只有文字和附件。点引用块滚回原消息（复用 `jumpTo`，不在已加载的会往上翻页找）并高亮被引的那一段 2.5 秒；`SnippetFallback`（选中的文字没对上、退回了原文开头）的不高亮；被引的那条看不到时只留回复文字加一句"引用的消息已经看不到了"。分块消息不再画拼起来的正文和顶部的单个引用。

### 9.3 边界情况

| 情况 | 处理 |
|---|---|
| 长片段 | 引用卡里最多三行；发出去的气泡里最多三行；后台已截到 1000 字 |
| 片段里有表情占位 | 换回表情名再传，对不上原文时后台退回原文开头（`SnippetFallback`），气泡里不高亮 |
| 引用已撤回或看不到的消息 | 发送时后台拒收，错误标在那张卡上并写"引用的消息已经看不到了"；读回时 `Unsupported` 只画回复文字 |
| 拖进多个文件、不存在的路径 | 存在的都挂上，不存在的在输入区上方说"找不到：路径" |
| 发送中又加卡 | 提交没回音时已有的块只读，新加的卡不受影响；收下后只删发出去的那几块 |
| 空卡 | 一个字没写的卡不发，标"写点针对这一段的话再发"，不悄悄丢掉；Esc 删最后一张空卡，有字的卡不删 |
| 同一段重复引用 | 不重复加卡，焦点给已有的那张 |

### 9.4 已知缺口

- 角色回复在工作台里已走 markdown（S8 前置，见上面“S8 前置补两件”）。Markdown 正文里的选区条已接上（`selection.go` 的 `mdSelectable`）：之前读选区没问题，是 `selectionTool` 没人画，上一位在 Tester 里看不到条才误以为读不到选区。选中的是渲染后的文字（不含 Markdown 记号），偏移留 0 让后台按文字在原文里找；选中的文字跨越加粗、链接等格式时，可能和后台原文（markdown 源码）对不上，会落到 `SnippetFallback`。被引片段的高亮要在 markdown 块里另做（mygo 没有给选区范围上色的接口）。
- 选区条锚在"松手的位置"，mygo 没有公开选区的几何；键盘（Shift+方向键）扩展选区时锚在上一次松手的位置。
- 没有"附件"按钮和文件选择对话框；拖入链接文字、粘贴到输入框之外、附件删除撤销、↑ 回忆历史没做。
- 粘贴的图片给模型的还是文字占位（`[图片：名字]`），真图由 `feat/real-images` 接。
- 草稿只在内存里，关窗口就丢。

### 10.6 查清楚的根因和已知缺口

- **拖字号时整页横向抖**：不是滚动条（mygo 的滚动条浮在内容上不占宽）。导航栏宽原来是 `48×字号比 + 2×内距`，随字号缩放，整页的版心跟着横向挪，拖滑块时滑块从手底下跑掉。改成固定 72；带刻度的滑块自己的尺寸也不跟字号走。无跳动测试 `assertNoLayoutShift`（可复用，`layoutshift_test.go`）已覆盖外观页切换、分类切换、会话分段切换。
- **分段选中块滚动时飞出**：在 Tester 里按“滚动 + 推进时间”逐帧量，旧组件库（CrychicUI）的分段控件选中块和轨道的相对位置 120 帧完全不变，**没有复现**；用户看到的是真窗口。新界面自己的分段控件选中块画在轨道的 Draw 里，不用 mygo 的 `Transition{Match}`，纵向不会和选项错开，横向只在换选项时才弹簧滑动，测试逐帧断言对齐。推测是旧组件库用共享元素过渡（Match）加上真窗口里的滚动层，需要真窗口里再看一眼；没有最小复现就不往对方仓库发 issue，已把 `zz` 复现测试删掉。
- 下拉和菜单项悬停高亮：新壳的下拉、“+”菜单用中性 Selected，强调色只给选中；字体下拉每项用自己的字体显示；滚动条用半透明令牌（正文色 32%）。mygo 的滚动条本来就浮在内容上、不占宽，“平时隐藏、靠近才显”的行为是 mygo 自己的，没有再包一层。
- **没做**：设置页其余九个分类和记忆、运行两页的内部还是旧组件库画的（经 `legacyPage`、`legacySettingsBody` 两个桥装进来，archcheck 已把桥限制在这两处）；模型选择器（旧页内部的全窗对话框）改分组下拉菜单没做；`desksettings` 里字号合法范围保持 8～40（设置页只给 12～20）；Bun 版的视觉没有逐项对（原型有的以原型为准）；真窗口的 GPU present、系统按钮避让、`glass.Glass` 在真窗口里的样子没法在 Tester 里验。
- **输入框玻璃**：`chatui.ComposerHost` 新增 `Surface` 钩子，输入框外框的材质由外壳给；`fix/newui-real` 的大块输入框也要走这个钩子（外框别再画 `Background(Fill)`），合并时保住它。

### 10.7 和别的线的对接

- `fix/newui-real`：f9b06922（导航换 `dialogs.Rail`）已撤回，导航以本分支为准；本分支删了 `workbenchView`/`workbenchChat` 的旧写法，`workbenchChat(c)` 留作只画聊天区的入口（测试用）；`chatmedia.go` 的 `chatHostFor` 取令牌的三行已换成 `a.chatTokens()`，它那边加的 `h.Media`、`h.ViewRect` 两行不冲突；输入框“与消息列同宽、最大 752”要去掉最大宽度，宽度由外壳的 `WidthPct`（外观里的私聊区、群聊区宽度）给。
- `fix/proto-palette`（`internal/lookpreset`）：颜色一律从 `winshell.NewPalette(t)` 这一处取，预设合进来后只在这个函数换来源；`Kit` 的令牌来自 `chatui.Derive`。
- `fix/image-bubble`：粘性头像、“跳到最新”按钮、滚没滚到底按“列表可见区减去浮层”算，浮层高度由 `State.OverlayInsets()` 给（`a.wbOverlayInsets()`），上边是标题栏高，下边是输入区（含引用卡、附件条）实测高加内距：可见底边 = 列表框下沿 − bottom，可见顶边 = 列表框上沿 + top。

### 10.8 聊天区宽度（消息列和输入框同宽，可配置）

外观设置里“私聊区宽度”“群聊区宽度”两个滑块（40%～100%，步长 5），存桌面设置 `look.privateWidth`、`look.groupWidth`，越界或坏值整份 look 回默认。本地群聊和 QQ 群走群聊那项，本地私聊和 QQ 私聊走私聊那项。默认：群聊 100%（对方贴左、自己贴右，两边拉满，只留内边距）；私聊没设（存成 0），按原型的居中版式画，最宽 752，外观页滑块上显示它现在相当于百分之几（取整到 5，夹在 40～100），拖动之后才存成百分比，不再封顶。聊天栏窄于 520 时百分比不再缩，直接铺满（协调者说“窄窗口直接铺满”，这里取 520 为界：640 的窗口聊天栏有 640，百分比仍生效，480 才铺满）。宽度只影响消息列和输入框，两者同宽、边线对齐；气泡自己的最大宽度（比例）不变。粘性头像、“跳到最新”按钮跟着列宽走，位置按 `OverlayInsets` 算。测试 `workbench_shell_width_test.go`：四种窗口宽度 × 三档百分比 × 群聊私聊，断言输入框和消息列同宽对齐、群聊 100% 时头像贴左内距且自己的气泡贴右内距、拖滑块时滑块不抖。

## 十一、列表分隔条拖动和右栏浮动（`feat/panel-float`，2026-11-09，状态：已合 main）

起因：主人 11-09 说“对话列表能不能像 Telegram 那样直接拖着折叠、展开”“窗口窄时右栏展开变成浮在聊天区上的效果，后续可能都做成浮动，只差挤不挤开气泡，主要是为了好做液态毛玻璃”。参考：Telegram 的列表拖动数值照 `docs/notes/对照表-Telegram数值-2026-11-03.md`（列表 260～540、拖窄成头像列）；交互参考 `拆解-Codex桌面版-交互.md` 的“拖拽调宽”（折叠阈值、松手决定去留）。外观不照搬。采用：松手才决定去留、拖动时宽度直接跟指针；没采用：Telegram 的自动收头像档位（对照表第 51 行写了它不采用，这里的 130 阈值是自家规则）。

### 11.1 拖动原来不好用的根因

1. 抓取宽度只有 6：mygo 的 `ui.Split` 把手宽写死成 `Spacing × 1.5`（`split.go:78`），我们的 `SplitSize = 1` 只是布局里留的 1 像素线，和抓取范围无关；平时线是透明的（分隔条只在悬停时亮强调色），用户看不到“这里能拖”。指针其实是有的（实测 ew-resize 出现在线两侧 −2～+3，共 6），是“太窄且不可见”。
2. 不跟手：Split 每帧从“上一帧实际布局的宽”加位移，而 `split.Changed()` → `DragList` → `Plan` 每帧把 `ListWidth` 改写；拖到 130 以下的那一帧列表立刻变成 62，下一帧从 62 起算，指针却还在 100 附近，分隔线和手脱开；从头像列往回拖要多拖一段才跟上。每帧还写偏好、调 `OnPanes`。
3. 拖动和松手没有区别：拖到一半就切模式，没有“松手才落位”的过程，也没有过渡。

### 11.2 做法（列表）

- 自己的抓取条 `list-grip`（`frame.go` 的 `listGrip`）：宽 `ListGrab = 10`，以分隔线为中心（实测 −5～+4.5，9.5 DIP），`Absolute` 叠在两栏上、不占布局宽度，`ew-resize` 指针，`ZIndex(2)`。悬停和按下时画 2 宽的强调色线（透明度用 `ControlMotion` 渐变）。mygo 自带的 Split 保留，只剩键盘方向键调宽（它给 `RoleSplitter` 焦点）。
- 先建抓取条再量列表宽，所以读得到这一帧指针的位移，不晚一帧。拖动中：`d.raw` 累加位移（不夹），显示宽 = `clamp(raw, 头像列宽, 上限)`，用 `Jump("list-w")` 直接设，没有动画；指针回到范围内就又跟上，不会和分隔线脱开。上限 = `min(ListMax, 窗口宽 − 导航 − ChatMin − 分隔线)`，右栏并排时再留 `SideMin`。
- 内容按显示宽换：显示宽 < `ListCompactDrag`(130) 画头像列，否则完整列表；窄于 `ListMin`(260) 时完整列表保持 260 宽、靠左露出，不重排（拖动时内容不跳）。会话列表的滚动条往里缩 `ListGrab/2`，不被抓取条抢。
- 松手那一帧才定：raw < 130 收成头像列，否则展开、宽 = `clamp(raw, 260, 上限)`；写 `Panes.ListRatio` / `Compact`、调一次 `OnPanes`。只按不动不改偏好。落位用 `AnimateTo("list-w", 目标, RouteMotion)` 从松手时的宽滑过去（系统开了“减少动态效果”则一步到位）。
- 双击抓取条、Ctrl+B 切换头像列也走同一个 `AnimateTo`，有过渡。设置页的分类栏不受影响（只在聊天页的分栏出现）。
- 限制：mygo 的 Split 有 `minPane = Spacing × 10 = 40` 的硬夹；自己的抓取条用头像列宽 62 作下限，不受它限制，键盘方向键仍受。

### 11.3 右栏呈现方式（挤开 / 浮动 / 整层）

`PanelMode`（`layout.go`）：`PanelPush` 挤开、`PanelFloat` 浮动、`PanelLayer` 整层。`Kit.SideMode(w)` 按窗口宽给：并排放得下（≥ 998）挤开，Medium（705～997）浮动，Narrow（< 705）整层——只让窄窗口浮动，宽窗口行为不变。聊天区给右栏预留的宽由 `Kit.SideReserve` 决定：挤开且开着 = 右栏宽 + 分隔线，其余是 0（浮动不让，消息列、输入框宽度不变）；`Plan`、`columns`、`sideShownRight` 都按模式问，不再直接看档位。以后别的面板（列表等）要切浮动，照这个函数加模式，不再各自写判断。

### 11.4 浮动面板的规格

- 位置：离窗口上、右、下各 `floatGap = SpaceSmall`（8），宽 = 右栏设定宽（292～392）；圆角 `RadiusCard`（33），顶行的选项卡胶囊和聊天标题条同一条线（顶行上边距补足到 `windowInset`），顶行里的圆角按同心规则（外圆角 − 内距）。
- 材质：`Kit.Glass(…, LevelInput, 卡片色)`，液态、磨砂、实色三档都跟、“降低透明度”退实色；阴影用新的 `Kit.FloatShadow`（0,8,24，浅色 .16、深色 .5），比 `CardShadow` 深、散得开。没有暗色遮罩。
- 层级（写死，设计语言第二节第 3 层）：聊天区 < 浮动面板 < 窗口三键胶囊 < 弹窗（`Overlays`）。面板盖住聊天右边一段，含标题条和输入框的右端；要用被盖的部分先关面板。不盖的部分照常可点、可滚、可打字。
- 三键：胶囊在同一个浮层里画在面板上面，位置和聊天区那只重合（开关面板不跳，实测同一个框）；面板开着或退场中聊天区不画自己那只，面板撤掉后同一位置交还。面板顶行让出胶囊的宽（`windowRoom`）。
- 关闭（主人 2026-11-09：“不太需要单独的x，直接点外边就会自己缩回去了”）：点面板外面收起，这一下照样落到下面的东西上；点三个键不算外面，内容开的大图盖在上面时不收（`SideSpec.KeepOpen`）。还有 Esc（`OverlayShortcut`，焦点在输入框里也有效；合并转发嵌套时先问 `SideSpec.Escape`，退一层，最外层才关）、Ctrl+\。没有单独的关闭钮。
- 进场、退场：自己做（浮层和内容同一帧新出现，mygo 的 Transition 进场不播）：第一帧在右边外面、全透明，之后滑回原位淡入，`RouteMotion`；退场滑出去淡掉，动画结束前内容照 `float.spec`（最后开着时的 `SideSpec` 副本）画，不跟着宿主新状态变空。退场用 `Settled` 判断结束再撤浮层。
- 档位切换：拉宽到挤开、拉窄到整层或换页，浮动面板直接撤掉（不播退场），右栏在新档位的最终位置出现；拉窄回浮动只播一次进场。状态（`SideOpen`、`Layer`）原样保留。
- 合并转发：沿用 `Layer == LayerSide` 判断可见；右栏选项卡、检查器进的都是同一个 `side()`，无变化。Narrow 整层行为不变。

### 11.6 没做 / 后面

- 列表本身也做成浮动（主人说“可能”）：`PanelMode` 已是扩展点，列表要加模式时照 `SideMode`/`SideReserve` 加；窄窗口三层不动。
- 退场内容用 `SideSpec` 副本里的闭包，宿主已清掉的状态（如合并转发栈）可能让退场帧的内容变空白一行；目前合并转发退场只剩标题行的淡出，没复现错乱。
- 抓取条的键盘焦点环和读屏名用 mygo Split 自带的那一个；自己的抓取条只有读屏标签。
- 浮动面板里的液态玻璃浓度用输入框那档（0.35），只在测试器的合成里看过，真窗口的实际通透度要主人看一眼。
