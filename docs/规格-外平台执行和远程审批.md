## 一、目标、依据和范围

例子：主人在 QQ 群让她整理文件，这条可信主人消息启动任务；完整命令或文件差异发主人私聊。主人可以在私聊回复“同意”，也可以在原群引用后台的那条审批提示回复“同意”。群友发一样的话不能申请执行或代批。任务完成，群里只有后台生成的完成状态，详细结果给主人。此处结果范围沿 ADR-277 第 7 条暂按建议，仍待主人确认。

## 三、先列权限和输入覆盖表

### 3.1 四场合 × 发起人 × yolo

“发起人”指后台冻结的直接触发消息作者，非当前模型、历史中提到的人、谁在房间里。表管本地文件读取、执行、写文件的申请资格；记忆、MCP、技能、网络各自已定的许可不因本表扩大。角色格指角色消息引起另一角色行动，非“模型生成了一次工具调用”。

| 场合 | 直接发起人 | yolo 关 | yolo 开 |
|---|---|---|---|
| 本地私聊 | 主人 | 沿现有 manual/auto 与同源授权；需要问的交主人 | 沿现有本地 yolo，硬门照问 |
| 本地私聊 | 角色 | 无主人来源的自主激活不授予执行；本地私聊正常响应主人仍算上一格 | 同左，不能凭模型身份借主人 yolo |
| 本地私聊 | 群友 | 当前本地私聊没有这个输入入口；若将来接入，默认无执行资格 | 同左 |
| 本地群聊 | 主人 | 可申请，按 ADR-269 每次人工批准执行/写文件 | 可申请；ADR-269 明定本地群没有免审批档，yolo 不跳过本地群逐次人工审批 |
| 本地群聊 | 角色 | 可申请，卡上写“不是主人发起的”及真实来源；执行/写文件每次人工批 | 同左；不吃 yolo、对话授权或始终授权 |
| 本地群聊 | 群友 | 当前无外部真人成员入口；若收到已认证的非主人本地成员，按 ADR-269 非主人来源每次问 | 同左；不得转成主人 |
| QQ 私聊 | 主人 | 可申请；执行/写文件逐次问，不继承本地 auto/已有授权 | 仅该平台显式开启时，使用与本地相同的 yolo 判定；硬门照问 |
| QQ 私聊 | 角色 | 不给本地能力；不生成可批准的执行单 | 同左 |
| QQ 私聊 | 群友 | 不给本地能力；不生成可批准的执行单 | 同左 |
| QQ 群 | 主人 | 可申请；执行/写文件逐次问，详细审批与结果走主人私聊 | 该平台显式开启后用同一 yolo 判定；结果仍不公开 |
| QQ 群 | 角色 | 不给本地能力；主人在群里、被 @ 或点过别单不改变此格 | 同左 |
| QQ 群 | 群友 | 不给本地能力；不得先生成执行单再靠主人“补批”升级发起人 | 同左 |

本地群沿 ADR-269 第 1 条的“没有免审批的档”：主人发起也逐次人工；角色发起还要标来源、不吃任何自动放行。ADR-277 第 6 条“本地照旧”未明确撤销这项，因此按已有较严规则实现，不自行解释成本地群主人免审批。

所有格另取交集：来源资格 ∩ 已授工具/目录 ∩ 当前执行器能力 ∩ 本次决定。只要任一拒绝，不得靠另一个入口、模型、授权文件或 yolo 放行。身份缺失、mixed、未登记平台、撤权、停止及不可落实的限制一律收紧。

### 4.2 来源记录和收紧规则

宿主在接受输入时建立不可由模型参数构造的来源记录：Invocation、直接触发事件 ID 集、原始平台 sender ID、接收账号、场合、根来源种类（人工入站/客户端/角色/自动化）、当前主人绑定版本。ID 与平台命名空间同时比较；不同平台同号或同名不关联。Access 只是签发句柄，不接受模型 JSON 里的 owner、platform、authority 字段。

QQ 私聊除了会话对方是主人，还要核对这条事件真实作者是主人；不能只用 AudienceOf 的 partner 推断。QQ 群以宿主选定的直接触发集为准：每条均是可信主人发言且没有角色/群友指令混入才签权；无法拆清的混批不签。OwnerAsked 继续服务于旧披露逻辑，不能单独作为执行凭证。

主人根下的模型工具调用及受限子代理可以继承来源；它们执行时仍各自经过工具门。另一角色接话、群友插话、定时任务、后台整理、补录、自检、被转发的旧主人文字不能继承这个资格。缓存实例复用也不能沿用上一轮来源，工具清单和授权版本随当前输入核验。

## 五、统一审批单、认证和一次消费

### 5.1 冻结字段、参数和存储

扩展现有 Request，宿主内部保存完整冻结动作；卡片只是投影。模型的 purpose 作为说明，不能参与“已批准”的判断。

| 字段/参数 | 约定 |
|---|---|
| ApprovalID | 复用宿主唯一 ID；不使用 provider call ID 或短前缀作主键，已用 ID 不重新注册 |
| Invocation / Trigger | 完整 Scope、Input/Root/Run/Tool/Attempt、Generation 和第四节来源记录 |
| ActionDigest | SHA-256：版本化结构序列化后的工具绑定、实际参数、真实 CWD、执行端、读写根、执行 profile、环境授权引用及版本；purpose 不代替参数 |
| 文件修改/脚本 | write 内容、edit 原/新字节、目标前态哈希；直接执行的任务脚本保存批准版及哈希。脚本不可在批准后被替换成新版再跑。原地工程命令无法冻结全部依赖，按第八节进程隔离，不宣称哈希冻结整个工程 |
| Nonce | `crypto/rand` 生成 32 字节，原值仅保留在进程内的审批单，持久化只存摘要；不当明文口令广播到群、不进普通日志。私聊裸回复由已认证 route 在服务端关联这张单的 nonce，不要求主人手抄；nonce 本身不能替代人的认证 |
| CreatedAt / ExpiresAt | 远程单：创建时起 300 秒，排队、分段、改投都计入，不续期。所有入口看同一截止时间；本地来源继续用既有 approvalMinutes |
| Route | route ID/代次、平台、接收 bot 账号、主人平台 ID、私聊详情的各段消息 ID/回执、可选原群提示的会话与消息 ID；私聊与原群可共享同一代次，一次只能有一个有效远程 route 代次 |
| 决定证据 | 当前可信 Principal、原入站 EventID/平台消息号或客户端操作 ID、route 代次、ApprovalID、ActionDigest、nonce 摘要、明确选择和接收时间；不接受模型自报 |
| 选择 | 平台回复只 once/deny；不提供“本平台都通过”“所有待批通过”。本地既有 conversation/always 按现行许可范围保留，外平台不复用 |
| 容量（我定的工程上限） | 活动远程单每根最多 16、全宿主 128；超出返回 busy，不丢掉旧单、不批准。候选回复最多 1 KiB UTF-8，超长不调用辅助模型 |

trace 中增加审批追加事件（请求、投递绑定、路由失效、决定、一次消费），与同一 Invocation 的 steps 关联；steps.approval_json 只作现有投影。不另造“QQ 审批库”或第二套状态机。迁移号实施时在主线占号，不在规格预占数字。原始事件只追加；活动索引/快照可重建，失败写入不能把批准当成功。完整输出复用 ResultStore，不塞进审批事件。

nonce、活动单、入口索引以哈希键查找；不为每条普通聊天全扫所有卡片。时间、终态、route 有效性在同一认领临界区检查；锁外发消息，持久化完成前绝不启动工具。

### 5.2 身份认证和群引用

平台批准证据只从已核验账号的适配器入站产生。核对：连接所绑定平台/账号、真实 message 类型、非自身号、sender 类型＋主人登记 ID、当前登记版本、已入库的新事件、正确 route。拒绝 self、message_sent、outbound echo、receipt、notice/reaction、backfill/selftest、模型输出、工具结果、转发/OCR/引用里的同意。重复平台事件使用唯一键认领，多个角色观察同一条也只能认领一次。

客户端 Principal 由宿主认证层提供，带 DeviceID、主人角色和配对修订；本机桌面走现有受信入口，手机将来经配对凭据接同一决定端口，不按手机消息正文认主人。每次决定查当前配对状态，取消配对后缓存会话、在途点击和重连凭据立即失效；其他客户端可继续处理同一单。已经批准但尚未派发的动作若依赖已撤销凭据则取消；已发生的副作用不能伪称撤回。执行节点身份和机器人/模型工具句柄没有批准角色；取消配对的事件不交给模型来决定是否生效。

按有序段提取批准正文：允许文本和一个真实 reply 段；普通批准精确为 trim 后“同意”，拒绝精确“拒绝”或“不同意”。不做子串匹配，不剥零宽字符后把“不像同意”的东西变成同意，不从卡片、图片或转发里拼出批准。

群回复必须有且仅有一个 reply，Target 精确命中后台保存的审批提示消息 ID，连同平台、接收账号、群会话和 route 代次一起比。引用普通模型消息、别单、别群、别账号的同号都失败；不信 reply 载荷自报作者，不通过 get_msg 的正文像不像审批来认单。

群里可引用的是后台生成的最小提示：“这一步已发你私聊确认。看过后可引用本条回复同意。”不含命令、路径、文件名、屏幕或 nonce。必须先确认主人私聊完整详情已经送达，才让这条群提示成为可批准绑定；群提示发不成仍可在私聊批。平台没有有效消息回执/回声认领 ID 时不建立群绑定，不能退到“最近一条”。

### 5.3 私聊直接回复和迟到歧义

只有正确主人私聊 route、完整详情已确认送达、当前恰有一张可批单且不存在歧义时，直接“同意”绑定这张单。审批候选先截走，不能让普通私聊处理把正在等待的根任务打断再取消审批。零单回“没有待确认操作”，多单先列编号与非敏感摘要问“批哪一单”；不按最新、最早、模型猜测或队首选择。明确回答“同意 <完整编号>”可作为私聊多单的选择＋本次同意；私聊引用原审批消息也可精确选单。

同一私聊 route 曾出现过期、拒绝、取消、投递结果不明、改投或并行多单时，设置歧义标记。即使后来只剩一张，也不把无目标“同意”转给它；要求明确编号或引用后完成本次决定。这个标记不因 TTL 到期、重启或来了新单自动清除，避免重启重新误批；普通无审批聊天仍正常。

平台 Time 只用于拒绝明显早于审批投递的旧回复，不能拿整秒时间或可伪造时间证明人看过当前单；缺时间或顺序无法确认的无目标回复走明确选单。一次消息在入库后就冻结候选的 ApprovalID/route，异步处理时不能重查“现在唯一的一张”。

**仍有无法由后台证明的情况**：A 批完、B 发出后，主人新发一条无引用“同意”，实际想说 A，平台给出的信息与“想批 B”完全一样。时间戳、单槽、排队和一次性 nonce 都无法消除人的指代歧义。文末给出需拍板的处理，不能把这项写成严格防串单已验收；ADR-277 的私聊便利规则与“任何迟到回复绝不碰新单”须明确安全边界。

自然语言辅助仅在身份和单号已确定、非危险动作、上述确定性格式未命中时考虑；只输入这一句及冻结单摘要，输出 approve/deny/unclear 候选，不能选请求、改参数、签 Principal 或写 Approvals。unclear、超时、错误、条件句、改范围继续等；拒绝候选不自动放行。是否启用及模型选择见文末，第一步确定性“同意”已经覆盖必需体验。

### 5.4 结算、截止与派发

单的决定只有 pending → approved / denied / expired / cancelled，一经结束不回 pending。route 投递中/待明确选择属于 pending 的可批条件，不是另一个批准状态机。决定成功后发布所有入口的同一终态；终态提示投递失败不回滚决定，不重复执行。

批准提交前核对 now < ExpiresAt、同进程代次、父根仍有效、参数摘要、nonce、route 和本人资格；到期点（等号）拒绝。计时用宿主单调时钟约束 300 秒，墙钟用于显示及持久化，墙钟倒退不延长等待。不能只靠定时器及时运行。

approved 只让相同 ToolID/AttemptID 消费一次；实际派发前再次核对取消、当前授权代次和冻结对象，记录 consumed 再交给执行器。nonce 和同意不能换工具、换参数、换执行端或换文件目标。批准不等于已经执行；批准后被停止可保持批准事实，工具记未派发/取消。

进程重启：pending 追加 interrupted/cancelled，不恢复可批；approved 但未确认执行结局的保持未派发或结果不明，不能凭新进程推测“没跑过”再跑。记录 consumed 与 OS 副作用无法合成一个事务，承诺最多派发一次，不承诺崩溃场景恰好执行一次。停止/关机使用现有 Lifetime、Approvals.Drain，排空决定写入、在途投递和子进程后关库。

## 六、完整审批私聊投递与改投

后台从冻结动作生成完整详情：谁引起、原场合、工具、执行端、真实 CWD、完整命令或内容/diff、读写范围、为何需问、是否有限权限、截止时间、编号。模型可补一句目的，但不能控制必填字段。输出按平台能力分段，每段带同单编号与页序；完整详情未确认送达不接受远程批准。长到平台放不下时，交同一编号的主人专用详情/配对客户端；明确提示未完整送达，不截掉关键参数后仍让“同意”生效。

| 情况 | 行为 |
|---|---|
| 原平台主人私聊许可已开、连接可用 | 发主人登记 ID 对应私聊；不得从群管理员、昵称或最近联系人推接收人 |
| 原平台私聊权限未开 | 不为审批偷偷开权限。群里最多提醒“这里批不了”；从用户已配置的备用主人私聊 route 依序找可用目标 |
| 原平台投递明确失败 | 记录失败；允许同一单改投下一条已许可的主人私聊，不改动作、不续期 |
| 部分发送或结果不明 | 未证明详情完整，不启用批准绑定；不自动重发结果不明的消息。可由后台确认回声/回执后激活，或作废旧 route 再明确改投 |
| 改投另一平台 | 必须已有该平台主人 ID、许可、适配器和硬发送条件；新的 route 绑定该平台的可信 sender。只跨送审批，执行来源仍为原 QQ 任务 |
| 改投成功 | 旧 route 和旧群引用绑定失效；新私聊关联同一 ApprovalID/ActionDigest/ExpiresAt。桌面仍看同一单 |
| 没有可用远程 route | 在线的合格配对客户端可承接同一单；也没有客户端则 denied/unavailable，按不通过，不默认等到自动允许 |
| 原群只记录、发送总开关关、未获真实群发送授权 | 审批不能绕开硬发送门；不在群发提示，可用获准的主人私聊/客户端承接，否则不执行 |

备用 route 的配置是显式的有序 `平台＋接收账号＋主人私聊`，默认空；不枚举联系人或向所有绑定平台广播。群提示只能在真实确认发送完整详情后说“已发你确认”，发送失败不能冒称已发。群引用跨平台不能直接引用另一平台消息；若允许原群继续批，必须由后台在原群发布并绑定新提示，且不扩大可见内容；默认旧提示作废。

高危动作不因平台远程而一刀切禁用：本次执行器不能触达的主人私聊、另一台已配对客户端可以批。批准入口、平台 token、主人绑定、审批库/配置、调试口/命名管道及客户端输入控制权必须在执行器可达范围之外。遮住桌面审批卡、加一句“不要点”不算隔离；当前被控制桌面上的批准操作拒绝。没有合格入口时保留 pending 直到期限或按不可用结束，不加指纹，不退到裸跑。

## 七、平台 yolo、配置与结果听众

### 7.1 设置及判定顺序

拟加 `tools.platformYolo: {}`，值为平台名 → bool；QQ 起步为未配置/false。`true` 选择同一套本地 yolo 算法，不把外平台伪装成本地、不继承本地 conversation/always 授权、不改变其文件/网络能力。具体平台目录能力仍按本次任务批准；不附加账号、目录、有效期等主人没有选定的新一层“受限远程自动”模式。已有 `tools.approvalMode` 继续管本地。

设置界面显示“QQ：使用与本地相同的 YOLO 规则”，下方一行说明账号风险和仍需人工批准的动作，详项折叠。开关只接受已认证主人客户端设置动作，模型/技能/群消息不能改；不要求多一次指纹。按现有配置白名单写回方式，先 Parse 校验，保存成功后发布新修订。未知平台名、null、字符串 true 等错类型报错，不能回默认成功。

配置实施同提交按 `native/internal/config` → `sumika.example.yml` → runtime/tools 参考页 → 本节对账。拟加有序备用 route 配置 `tools.approvalRoutes`，默认空；平台具体主人 ID 复用其登记，不在这里复制密钥或第二份 owner。远程 TTL 固定常量，不增加与 approvalMinutes 竞争的配置键。

决策顺序：来源资格 → 本次工具/目录与执行器能力 → 不能自动批准的硬门 → 当前来源专属授权 → 模式 → Ask/拒绝。QQ yolo 关闭时执行/写文件每次问；开启时工作目录内、目标看得清的普通动作可按原 policy 自动允许，受保护路径、自身后台、拆不开的危险命令等照原规则问。权限错误、沙箱不可用和非主人来源始终拒绝，不能变成“yolo 放行”。自动结果记录实际 reason 与当时平台配置版本，不冒称主人本次点过同意。

配置由 true 改 false、主人绑定撤销、平台停用时使相关未执行授权失效并取消待批；由 false 改 true 不补批已挂起单，下一次新调用才按新快照判。不得修改全局 Gate.Mode 后执行再改回来。外平台手工输入 conversation/always 值属于非法选择，不能沿用本地宽授权。

### 7.2 执行结果谁能看到（ADR-277 第 7 条暂按建议）

| 来源场合 | 原会话显示 | 完整结果 |
|---|---|---|
| 本地私聊 | 现有工具卡、结果 | 主人客户端，精确原任务范围 |
| 本地群聊 | 保持已定本地群成员规则；非主人发起来源标清 | 不因此公开到 QQ 群；个别外平台执行结果不能借本地群回流 |
| QQ 私聊（主人） | 批准、运行与真实结局，可展示详情 | 同一主人私聊或主人客户端；不给其他私聊借用 |
| QQ 群（主人发起） | 后台固定状态：“已完成，详情已发你私聊”仅在详情确认送达后使用；否则“已完成，详情请在本机查看”；失败/取消/结果不明分别说清 | 主人私聊或本机；路径、命令输出、文件内容、截图、长错误和子代理结果默认群友不可见 |
| QQ 私聊/群（非主人发起） | 需要回应时仅说明当前来源不能执行 | 没有本地执行结果 |

**结果不能先放进群模型上下文再靠提示词不说。** QQ 群执行任务建立与公开群上下文隔离的主人工作域，保持原 Trigger/Root/来源不变；任务的工具结果、后续推理、完整结论、task_result 和 result_read 均只在该工作域。公开回合得到无详情的任务状态，不能把同一段续写同时发到群和私聊。原群历史、压缩、召回资料、角色接话和普通导出不得带私有工作域结果；按实际出站目的地保存原文和观察关系，禁止把私聊详情挂到群事件的隐藏段。

复用 ResultStore 的精确 Scope 检查，并给已认证主人客户端提供后台授权的详情查询；不能把 QQ 群 Scope 全部升级为能读全文。主人另说“把这份发群里”是另一次明确披露，只授权指定结果/片段和指定群，继续走唯一出口与检查，执行批准不能当披露批准。不在本次增加群友默认可见开关。

## 八、沙箱第一步与派出代理限制

### 8.1 自管任务目录和真实限制

通过 Paths 在宿主选定自管根下建立 `tasks/<RootID>/work`、`tmp`、`outputs`。RootID 是宿主生成的安全 ID，不把群名、用户名、模型标题或外来路径拼进目录；同一根复用自己的目录，另一根不能读写。现有工作成果不自动迁移，显式选项目的任务可批准额外目录，不默认挂整个用户目录。

任务目录与审批控制数据分离：即使都位于所选数据根下，有限权限执行器只拿明确任务子目录，不能拿其父目录读写权。policy 的全 data 保护不能简单把整个数据根从 ProtectedDirs 删除；只在已签任务能力中授权精确 task 叶子，角色卡、聊天、密钥、审批数据仍受保护。

文件类窄工具用实际根/文件句柄落实读写范围；Windows 联接、符号链接和硬链不得把指定目录授权扩大到另一个对象。递归列/搜/找共用该边界，不让 rg/fd 启动于父目录后自行跟到外面；只读文件工具的搜索子进程也属于执行器边界。写入前后使用现有 mutation/检查点的对象和内容核验，批准期间前态变化需重提预览。

自由命令必须由能落实该 profile 的有限权限执行端运行；仅 CWD、AST 看起来只读、Job Object、venv、清空环境变量都不足以替代。执行端必须报告实际可强制的读、写、网络和控制面隔离能力；需要的项缺一就拒绝这一次，不直接调用现有 startPowerShell 裸跑，也不自动换 WSL/另一台机器。

日常起步 profile（我定的工程约束）：仅任务目录可写，宿主显式输入与必要工具/系统运行库只读；不继承宿主整份环境或凭据；不授予网络及控制桌面的能力。环境只白名单给系统启动必需变量、选定工具 PATH，以及落在任务 tmp 的 HOME/USERPROFILE/TEMP/TMP。某变量缺失导致启动失败照实报告，不重新继承宿主环境。需要网络/额外项目输入必须在本次动作和能力中明确，执行器做不到就拒绝，不把 HTTP_PROXY 当网络隔离。

PowerShell 保留现有默认 120 秒、最大 600 秒与取消/进程树回收；有限权限不可用应在派发前失败，不能为了“不超时”回宿主跑。Windows 后端未有足够源码与本机验证支持选定现成产品，选型见文末；先做窄文件工具和无 shell 子代理可独立交付，不能把这当成 QQ 命令执行全部完成。

任务 tmp 在停止并确认进程树退出后清理；work/outputs 保留为用户成果，不自动当缓存删。正常、失败、取消、崩溃恢复都报告残留文件及体积；清理只操作宿主绑定的本任务目录，不跟外来链接递归删除，不引入全盘清理器。

### 8.2 子代理按任务冻结能力

在现有 `task` 申请中补结构化委派范围：Tools（明确工具 ID 集）、ReadRoots、WriteRoots、AllowShell；由宿主按父当前权限取交集并在任务审批详情展示。模型可提出范围，不能自行授予；缺范围不能解释成父全部 Workspace。空 ReadRoots/WriteRoots/Tools 分别表示没有该能力，不是全盘或自动默认。

复用 Authority/Delegate 的不可伪造句柄和父撤权检查，扩展 grant 保存工具集、真实目录根及执行 profile；内部任务通过同一 Hub、预算和 Lifetime。来源继承已批准父根，子任务不是“角色接角色的新外平台发起”，但也不继承批准过父另一条命令的 nonce。深度沿当前上限 1，子代理不能再派，不能通过 task_cancel/task_result 读写别人的任务。

| 活的形状 | 工具清单与实际执行 | 读/写边界 |
|---|---|---|
| 只读本地资料（reader） | read/ls/grep/find，和必要的精确授权结果读取；没有 write/edit/powershell/MCP/记忆写入 | 只读批准的输入根，不能枚举或读取父其他目录；WriteRoots 空 |
| 改指定文件的 worker，不需要 shell | 只给本任务需要的 read/write/edit 子集；即使默认 worker 旧定义含 local.exec，也必须裁掉 | 读批准输入，写指定叶子目录；搜索不能追出边界 |
| 确实需要命令的 worker | 明确 AllowShell 且父有 local.exec、执行 profile 可落实才给 powershell；命令仍逐次过 Gate | OS 执行端限制同一根，不能用 python/PowerShell 绕文件工具目录限制 |
| 公共网络研究（research） | 只在原有网络/研究授权已开时给 web 工具；不给本机文件和自由 shell | 沿原有公共委派范围；本规格不因主人 QQ 可执行就自动打开 web/MCP |

三处都要执行同一范围：给模型的工具声明、prepare/真实调用前、文件与进程实际执行。只藏工具名、依靠代理提示词、只检查一次 Start 不合格。父撤权/停止、工具注册被替换、目录根失效后不再派发；已在跑的通过现有取消排空，不伪称副作用已经撤销。结果回主人工作域或原许可域，不能发给触发之外的群友/另一角色。

## 九、禁止的偷懒写法

- 只看 PrivateOK、OwnerAsked、昵称或会话对方就给执行权；把 QQ 听众硬填 console 来通过 Gate/生态工具/结果读门。
- 模型调用 approve 工具、解析模型的“主人说同意了”、任意自然语言命中“同意”子串；让小模型选择或制造批准对象。
- 群聊不核对引用消息复合键，私聊多单取队首；过期、拒绝或取消后把同意移到另一张单；不同平台同名自动关联主人。
- 只隐藏批准 API，执行器却能读 token、改 owner/审批数据、连批准管道或控制批准窗口；仅绑定 localhost 就宣称执行器碰不到。
- nonce 是短可猜码、复用 nonce、只判 TTL 不判已用；只判已用不判期限；只靠 UI 禁用或定时器拒绝过期。
- 批准后重新从模型 JSON 取参数、从会话当前 CWD 取目录，或调用时换成另一个脚本；私聊投递失败仍提示“已发给你”。
- 在全局 Gate 上临时切 Mode；给外平台套用本地 always；因为 yolo 开就移除身份、目录、控制面或 ResultStore 门槛。
- 详情先进入群模型、群事件隐藏字段或公共摘要再靠守卫擦；输出发群后再撤回；把“执行许可”当“群内披露许可”。
- 把任务目录、Worktree、venv、Job Object 或 shell AST 当完整沙箱；所需限制不可用时回 startPowerShell 直接跑；把 Windows 命令偷偷转 Linux。
- 新建 QQ 专用审批状态机、重复持久化全文、保留 owner-console 兼容别名让新旧判定并存；漏迁移评测/对拍的权限预期。
- 出错吞掉当取消成功、回“已完成”；结果不明自动重跑副作用；审批回调/发送 goroutine 不接错、不排空。

有权限保护的新增永久测试按任务规矩先拆掉那道保护，记下对应哪条测试变红，再恢复；不能靠另加泄漏打印冒充拆掉隔离。至少拆：sender 类型/ID 核验、引用绑定、期限比较、一次消费、子目录根、结果 owner 域、无裸跑分支。确定性并发用屏障，不改为几百毫秒碰运气。

端到端冒烟使用临时数据与假的 OneBot WebSocket、编造身份、实际工具/文件系统/进程。场景：主人群消息 → 请求 → 私聊完整详情 → 引用群提示批准 → 实际产物 → 群状态＋主人详情；再走私聊直接批准、多单选择、私聊未开改投第二假平台、停止/重启。普通模型可以由本机假服务产生确定调用，但真实审批、Gate、执行器、数据库和出口必须运行。再以一条真实远程模型任务验证新工具确实进入模型声明、结果进入正确的私有工作域；模型成本与数据隔离沿任务要求。真实 QQ 发送另需主人当次授权，不连接生产来跑自动验收。

资源量测按[性能与效率标准](notes/标准-性能与效率-2026-11-03.md)，这里新增的是我定的项目预算，不宣称行业标准：

| 测量项 | 固定负载、阈值与留证 |
|---|---|
| 审批本地反馈 | 10 角色、1 万条编造背景消息、128 活动单；提交决定到权威快照更新 P95 ≤100 ms，统计存储提交与投递排队；平台网络/人工等待另列，不能混作后台 CPU 延迟 |
| 普通消息旁路 | 同负载无审批消息时不得线性扫描单表或增加模型调用；量每条分配、耗时、CPU 和数据库查询数，与旧版同机交替三遍 |
| 执行启动 | 分离任务目录创建、有限权限准备、实际程序运行；冷/热各三遍，报告 P50/P95、CPU、Private Bytes、Working Set、进程/句柄；没有统一沙箱耗时合格线，选型前冻结具体可接受预算，不能借社区故障数字放宽 |
| 生命周期与文件 | 成功/失败/取消后子进程 0、活动审批与 nonce 索引释放、tmp 无活动残留；记录 work/outputs、trace/WAL、结果文件的数量与字节，写明必须保留的产物。崩溃残留按真实恢复规则单列 |
| 客户端 | 审批卡创建/决定反馈遵循标准中的 100 ms 目标；10 角色/128 单列表不卡主线程，量实际布局状态与帧耗时。当前规格任务不画界面，不给出未运行的帧率结论 |
