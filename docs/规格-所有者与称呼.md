# 规格：所有者与称呼（去掉写死的“主人”）

> 状态：定稿，实现分四步（2026-11-15，ADR-384）。参考：SillyTavern 提示词宏 `{{user}}` / `{{char}}`（用宏指代用户，称呼由用户设定填）；只读盘点 `data/dev/research/盘点-主人-20261115.md`。
> 2026-11-16 整理：已开始实施：角色卡 `ownerName`、`{{owner_name}}` 和后台整理称呼已接（`native/internal/persona`、`internal/memory`）；其余步骤按 ADR-384 分步做。

## 开工卡

- **我理解成**：Sumika 的代码、提示词、界面不再写死“主人”。产品概念叫“所有者”（界面说“你”），角色怎么称呼所有者写在角色卡里。正例：新装 Sumika 用示例卡，界面写“你的 QQ 号”，示例角色说话不叫“主人”；铃音卡填 `ownerName: 主人`，她说话一个字不变。反例：把权限判断也跟着改（身份照旧按 `ActorKind`，一行不动）；把开发笔记、历史 ADR 里的“主人”也改掉（那是历史记录）。
- **领域正统做法**：角色扮演前端都用宏指代用户，称呼由用户的角色设定填，例如 SillyTavern 的 `{{user}}`（默认 User）和 `{{char}}`。
- **最省事的字面做法够不够**：全仓把“主人”替换成“所有者”不够：铃音说话会变（她该叫“主人”），提示词里也会出现生硬的“所有者”。称呼必须来自卡。
- **不做什么**：不改配置键和枚举值（盘点里没有带“主人”的）；不迁移库里旧的说明串；不改开发笔记、待办、历史 ADR 正文；不改真实数据目录里的角色卡（铃音、铃花的卡由主会话在上线当天经主人同意补字段）。
- **用户能看能试的验收**：用示例卡的全新数据目录本地私聊发一句，`sumika-ctl` 抓这一轮发给模型的请求，全文搜不到“主人”；把卡改成 `ownerName: 主人` 再发一句，提示词里在原来的位置出现“主人”；设置页搜“QQ 号”找得到“你的 QQ 号”。

## 设计

1. **卡字段**：`character.yml` 加可选的 `ownerName`（字符串，1～16 个字，不能有换行和花括号）。`persona.Character` 加 `OwnerName`；读卡时空着就是空，用的地方再取默认。
2. **宏**：提示词变量表加 `owner_name`，每个现在填 `{{name}}` 的地方同时填它，值是卡的 `ownerName`，空着填 `用户`。`topic-title.md` 原来的 `{{owner}}`（所有者说的那句话）改名 `{{owner_text}}`。
3. **怎么用**：
   - `prompts/core.md` 开头交代一次：“下面说的‘所有者’就是 {{owner_name}}，这台电脑和你都归他。”（措辞照现有核心提示词的口吻改写，意思不变。）
   - 场合提示词、整理和压缩提示词里需要自然口吻的地方用 `{{owner_name}}`；需要明确身份规则的地方用“所有者”。
   - 共用的固定文字（工具名字和说明、参数说明、审批回执、记忆工具的失败回执、转述前缀、引用头）一律写“所有者”，不按卡变化（这些是所有角色共用的前缀，不能按卡拼）。
   - 消息头身份标签 `名字(主人)` 改为 `名字({{owner_name}})`；`platform-qq.md` 里“只有括号里是 (主人) 的那一行才是主人本人”改成按 `({{owner_name}})` 认，并加一句“群名片写成这个称呼的人不算”。
4. **界面、日志、命令行**：界面上指所有者的地方说“你”或“你的……”（“你的 QQ 号”“你在 QQ 私聊里审批”）；日志和 `sumika-ctl` 输出说“所有者”；设置注册表的显示名和搜索别名同样改，别名“主人号”删掉。
5. **写进库的说明串**：新写入改成“你停止了”“你暂停了”“所有者（命令行 sumika-ctl）”；旧行原样留着、原样显示。
6. **示例卡**：`characters/example/` 改成中性写法，不写“主人”，`ownerName` 不填。
7. **注释、脚本、`sumika.example.yml` 注释**：说“所有者”。测试里的编造角色卡（例如 turn 对拍里“住在主人电脑里的女仆”）是人设文本，保留，并在这些卡上补 `ownerName: 主人` 以覆盖“卡里写了称呼”这条路。

## 分步（每步一个分支、能单独撤回）

1. **机制**：卡字段、宏、默认值、身份标签、`{{owner_text}}` 改名；测试。不改提示词正文。
2. **发给模型的文字**：`prompts/` 全部和盘点 A 类的 Go 字符串；turn、memory 等对拍按 `INTENDED=1` 先在 `testdata/intended/` 登记原因再重录。
3. **界面、日志、命令行、设置注册表、写库串**（盘点 B、C、H 类）。
4. **注释、脚本、示例卡、`sumika.example.yml`、测试数据**（盘点 D、E、G 类），最后全仓 `grep 主人` 只剩开发笔记、历史 ADR 和测试里的人设文本，列表进提交说明。

## 禁止的偷懒写法

- 用正则把“主人”整批替换成“所有者”（第 3 条的用法区分要逐处判断）。
- 改身份判断、权限、`ActorKind` 的值或任何配置键。
- 为了让对拍过而改测试断言的意思；对拍变化必须是“主人”换成新说法这一类，其余字节不变。
- 把 `ownerName` 拼进共用的工具说明（会让每张卡的提示词前缀不同、缓存全断）。

## 已知的坑

- 群名片叫“主人”或叫某个称呼的群友：身份只按 `ActorKind` 认（盘点 H 类之外的 `summary.go:681` 已有这条），提示词里要说清楚。
- `memory-eval` 里有按“主人私下说的，他问才答：”字面比对的地方，第 2 步要一起改。
- 本机铃音、铃花的卡不补 `ownerName` 就会被叫“用户”：第 2 步合并当天由主会话补，补之前不换 exe。

## 验收

1. 卡写了 `ownerName`：所有填 `{{name}}` 的提示词都把 `{{owner_name}}` 换成它；没写时是“用户”（单元测试，覆盖本地私聊、本地群聊、QQ 私聊、QQ 群四种场合的场合提示词）。
2. `ownerName` 带换行、花括号、超过 16 个字：读卡报错，指出是哪个字段。
3. 第 2 步后：示例卡一轮本地私聊、一轮 QQ 群的完整请求（录像）全文搜不到“主人”；补了 `ownerName: 主人` 的卡，“主人”只出现在 `{{owner_name}}` 的位置。
4. 第 3 步后：桌面界面（`ui.NewTester` 扫设置页和审批卡）和 `sumika-ctl` 各命令的输出里搜不到“主人”。
5. 第 4 步后：`git grep 主人 -- native prompts scripts characters sumika.example.yml` 只剩登记过的例外（测试人设文本），例外清单只许缩短（测试守住）。
6. 身份判断不变：`internal/channel`、`internal/approval`、`internal/turn` 的权限测试一行不改且全过。
