# Sumika 使用说明

本文适用于当前 Windows 桌面程序。Sumika 仍在开发中，尚无面向普通用户的安装包；本文以已编译的 `sumika.exe` 和准备好的数据目录为起点。编译方法见 [桌面程序说明](../native/README.md#编译和打开)。

## 1. 了解 Sumika

Sumika 是在本机运行的角色 AI 程序。你可以在桌面窗口里与角色进行本地私聊，或创建包含多个角色的本地群聊。连接 QQ 小号后，后台可以保存配置允许接收的 QQ 消息，并按现有发送规则决定是否回复。每个角色的人设和记忆保存在本机数据目录中，生成回复时使用模型网关提供的模型。

| 部分 | 作用 |
|---|---|
| 桌面程序 | 显示会话、聊天记录、设置和后台状态，并通过 Windows 托盘控制接收与退出。 |
| Go 后台 | 与桌面界面运行在同一个程序中，负责保存消息、调用模型、处理工具和审批。日常使用不需要再启动一个后台程序。 |
| Magpie 网关 | 向 Sumika 提供模型列表和模型调用接口。默认地址为 `http://127.0.0.1:3425/v1`。 |
| SnowLuma 协议端 | 登录 QQ 小号，向 Sumika 提供 QQ 消息和收发接口。Sumika 只连接它，不负责安装、启动或登录。 |
| QQ 小号 | 角色在 QQ 中使用的账号，需要在配置中绑定角色。当前一次接收一个小号。 |
| 数据目录 | 保存配置、角色卡、记忆、聊天库、媒体、桌面设置和日志。默认位于根目录下的 `data/`。 |

QQ 消息经过 SnowLuma 进入 Go 后台，再显示在桌面窗口中。需要生成回复时，后台向 Magpie 请求模型；允许发送的 QQ 回复经 SnowLuma 发出。本地私聊和本地群聊的消息保存在本地聊天库中，不会转发到 QQ。

相关文档：[桌面程序说明](../native/README.md)、Go 后台装配（私有存档）、[界面接 Go 后台](规格-界面接Go后台.md)。

## 2. 第一次启动

### 放置程序和资源

根目录用于查找配置和程序资源；数据目录用于保存个人数据。两者不是同一个概念。以下以 `D:\Sumika` 为根目录，默认数据目录为 `D:\Sumika\data`。

1. 将程序及配套资源放在你有写入权限的文件夹中，例如 `D:\Sumika`。保留配套资源的目录结构，不要只移动一个 exe 文件。
2. 确认根目录中有 `sumika.example.yml`。
3. 将已有的 Sumika 数据目录放在根目录下，命名为 `data`。如果使用其他位置，按下文的数据目录规则指定。

如果 exe 位于根目录中，可以直接双击。如果 exe 位于项目的 `native/` 子目录中，也可以直接双击：程序会从 exe 所在位置向上查找包含 `sumika.example.yml` 的目录，不依赖你从哪个文件夹打开它。

需要指定其他根目录时，优先使用界面：

1. 双击 `sumika.exe`。
2. 打开“设置”→“数据”。
3. 在“重启后使用的根目录”下填写路径，例如 `D:\Sumika`。
4. 单击“保存数据位置”。
5. 确认出现“已保存，重启生效”。
6. 从托盘菜单退出 Sumika。
7. 重新双击 `sumika.exe`。

这个操作将路径写入 exe 旁的 `sumika.root`，不会搬迁数据。即使后台未能加载，也可以打开这一项修正路径。

也可以用记事本手动创建 `sumika.root`：保存为 UTF-8 文本，只写一行目录路径，不加引号，确保文件名没有多余的 `.txt` 后缀。相对路径以 exe 所在目录为起点；例如 exe 在 `D:\Sumika\native` 时，写 `..` 表示 `D:\Sumika`。文件留空表示使用 exe 所在目录，**不会继续向上查找**。非空路径必须指向已有目录，且该目录内必须有 `sumika.example.yml`。

桌面程序按以下顺序确定根目录：命令行 `-root` → exe 旁的 `sumika.root` → 向上查找 `sumika.example.yml` → exe 所在目录。如果快捷方式中指定了 `-root`，需要移除它，保存的 `sumika.root` 才会生效。

### 准备配置和连接

1. 在资源管理器中打开根目录。
2. 复制 `sumika.example.yml`。
3. 将副本放到数据目录的 `config` 文件夹中，命名为 `sumika.yml`。默认完整路径为 `D:\Sumika\data\config\sumika.yml`。已有配置时先备份，保留原配置中的个人设置。
4. 用文本编辑器打开副本，按示例中的注释填写配置。YAML 的缩进使用空格。
5. 核对 `magpie.baseUrl` 与 Magpie 的服务地址一致。
6. 在 `characters` 中为已有角色填写 Magpie 中实际存在的模型 ID；角色 ID 应与数据目录中的角色文件夹名一致。
7. 在 `qq.accounts` 中配置接收用的小号，填写 `id`、绑定的 `character`、SnowLuma 的 `url` 和访问令牌 `token`。Go 后台要求显式填写 `url`，不会自动查找协议端地址。令牌也可以引用环境变量，或使用已经配置好的加密密钥。
8. 启动 Magpie，确认所选模型在 Magpie 中可用。
9. 启动 SnowLuma，并登录配置中的 QQ 小号。
10. 双击 `sumika.exe`。
11. 右键单击 Windows 通知区域中的 Sumika 图标，选择“查看后台状态”，核对根目录、接收用的小号和提示信息。
12. 需要开始聊天和接收 QQ 时，选择托盘菜单中的“开始接收 QQ”。菜单可能在文字后显示已打码的小号。

仅查看已有历史时，不需要连接 Magpie 或 SnowLuma。当前本地发送也依赖“接收中”模式，不能只开启本地聊天而跳过 QQ 接收配置。配置里恰好有一个小号时，桌面程序自动选用它；配置了多个小号时，需要用启动参数 `-account` 指定一个。

从零创建数据、角色和 QQ 接入的一站式向导还没做。复制示例配置不会创建角色、数据目录标记或聊天库。“只看历史”只打开已有 Go 数据，不负责建库；如果看到“不是 Sumika 的数据目录，或者还没初始化”或“打开已有 Go 历史”相关错误，应先完成数据准备。旧 Bun 数据也需要按导入文档转换，不能直接当作 Go 聊天库使用。

### 数据目录和配置文件的查找规则

普通使用保持默认路径即可。排查位置不符时，再检查以下覆盖项：

| 项目 | 优先顺序 |
|---|---|
| 数据目录 | 启动参数 `-data` → 环境变量 `SUMIKA_DATA_DIR` → 配置的 `dataDir`；默认是根目录下的 `data`。相对 `dataDir` 以根目录为起点。 |
| 配置文件 | 环境变量 `SUMIKA_CONFIG` → 启动时选定数据目录中的 `config/sumika.yml` → 根目录中的 `sumika.yml`。尚未读取配置时，未指定数据目录则先查 `<根目录>/data/config/sumika.yml`。 |

`sumika.example.yml` 是供复制和参考的文件，程序不会直接把它当作个人配置读取。不要通过修改示例文件来更改自己的设置。

相关文档：[桌面启动与数据位置](../native/README.md#编译和打开)、[运行时参考](subsystems/runtime.md)、[示例配置](../sumika.example.yml)、从 Bun 导入历史（私有存档）。

## 3. 日常打开、接收和退出

### 打开主窗口

1. 双击 `sumika.exe`。
2. 如果程序已经在运行，等待原来的主窗口显示。

程序默认进入“只看历史”。勾选“启动后自动接收 QQ”后，程序会在启动时尝试进入“接收中”。

| 状态 | 可以做什么 |
|---|---|
| “只看历史” | 查看已有聊天记录和本地媒体，不连接 QQ，不读取网关模型列表。本地消息不能发送。 |
| “接收中” | 接收并保存 QQ 消息，启用本地私聊、本地群聊发送和模型调用。QQ 是否自动回复仍取决于配置、权限和发送检查。 |
| “后台没在运行” | 后台启动受阻。打开“运行”页查看原因；此时不能按正常后台状态使用聊天功能。 |

### 使用托盘菜单

右键单击 Windows 通知区域中的 Sumika 图标，选择需要的操作。图标可能收在通知区域的隐藏图标列表中。

| 菜单文字 | 作用 |
|---|---|
| “打开主窗口” | 显示并聚焦已有窗口。 |
| “查看后台状态” | 打开“后台状态”，查看当前阶段、原因、“QQ 连接”和“没恢复的提醒”。 |
| “开始接收 QQ” | 从只看历史切换到接收模式。开始失败时会尝试回到只看历史，并显示原因。 |
| “停止接收 QQ” | 关闭接收后台，回到只看历史。本地发送也随之停止可用。 |
| “启动后自动接收 QQ” | 决定下次启动后是否自动尝试接收，默认不勾选。这个开关不会立即开始或停止当前接收。 |
| “开机自动启动” | 控制 Windows 登录后是否自动启动 Sumika，默认不勾选。要登录后自动接收，还需同时勾选“启动后自动接收 QQ”。 |
| “退出 Sumika（后台和界面一起退出）” | 收尾并退出整个程序。 |

单击窗口右上角的关闭按钮或按 Alt+F4，通常只会隐藏窗口，后台继续运行。需要退出或替换程序文件时，使用托盘的退出项。如果托盘创建失败，关闭窗口会退出程序。

### 使用 sumika-ctl

`sumika-ctl.exe` 用于控制已经打开的桌面程序，不会替你启动 `sumika.exe`。不熟悉命令行时，使用上面的托盘菜单即可。

1. 在资源管理器中打开包含 `sumika-ctl.exe` 的文件夹。
2. 右键单击文件夹空白处，选择 Windows 的“在终端中打开”。使用 PowerShell 执行下列命令，一次复制一条。

查看后台状态、QQ 连接、提醒和数据目录：

```powershell
.\sumika-ctl.exe status
```

开始接收 QQ，并等待本次切换结果，默认最多等待 60 秒：

```powershell
.\sumika-ctl.exe receive start --wait
```

停止接收，回到只看历史：

```powershell
.\sumika-ctl.exe receive stop
```

查看桌面日志最后 50 行：

```powershell
.\sumika-ctl.exe logs -n 50
```

请求退出后台和界面：

```powershell
.\sumika-ctl.exe quit
```

如果没有 `sumika-ctl.exe`，可在安装了 Go 的开发环境中，从项目的 `native` 文件夹执行以下编译命令，再使用上述命令：

```powershell
go build -o sumika-ctl.exe ./cmd/sumika-ctl
```

相关文档：[托盘与窗口](../native/README.md)、[Go 命令行工具](subsystems/go-tools.md#sumika-ctlagent-怎么操作开着的程序)、[本机控制接口](规格-本机控制接口.md)。

## 4. 使用聊天界面和设置

### 查找会话和历史

1. 在左侧导航中选择“本地”或“QQ”。
2. 在“会话列表”中选择一个会话。也可以在“搜索会话”中输入名称筛选。
3. 向上滚动查看已保存的较早消息；需要时单击聊天区的“加载更早的消息”图标按钮。

“本地”按“私聊”和“群聊”分段。本地私聊中，每个已加载角色都有自己的日常会话，即使还没有消息也可以打开。这里的搜索用于筛选会话，不是搜索所有消息正文。“加载更早的消息”读取本地已保存的记录，不是向 QQ 请求更早历史。

### 发送本地私聊消息和处理审批

1. 确认后台状态为“接收中”。
2. 打开“本地”。
3. 在“私聊”中选择角色。
4. 在输入框中输入文字。
5. 单击“发送”。

回复生成时会显示流式正文。需要中止时，单击“停止生成”。当前仅接入文字发送，图片、附件和引用输入还没做；输入框旁的“附件”不可用。切换会话时，各会话保留自己的未发送草稿。

需要审批的工具操作会在本地私聊输入框上方显示审批卡：

1. 阅读工具名称、操作对象和原因。
2. 需要查看完整内容时，单击“审批详情”。
3. 确认执行该操作时，单击“允许一次”；不执行时，单击“拒绝”。

“允许一次”只回答当前审批请求，不表示永久放行后续操作。

### 创建和使用本地群聊

1. 确认后台状态为“接收中”，且至少有两个资料可读的角色。
2. 打开“本地”。
3. 单击“新建群聊”。
4. 在“群聊名称”中输入名称。
5. 勾选 2～10 个角色。你会自动加入群聊。
6. 单击“创建群聊”。
7. 在打开的群聊输入框中输入文字。
8. 单击“发送”。

每轮最多由两位角色接话，不是所有成员都会逐个回复。需要停止整轮时，单击“停止生成”。已经保存的主人消息和角色回复会保留；发送失败的原因显示在输入区。本地群聊不提供本地执行工具，也没有审批卡。

### 查看 QQ 私聊和 QQ 群

1. 打开“QQ”。
2. 选择 QQ 私聊或 QQ 群会话。
3. 阅读已保存的记录。

这两类会话在桌面窗口中都只查看记录，没有手动发送入口。后台自动回复与桌面输入是不同的功能，开始接收不代表已经允许向所有私聊或群发送。

### 展开合并转发和查看大图

1. 单击消息中的合并转发卡片。
2. 在打开的聊天记录窗口中阅读内容。
3. 需要查看嵌套转发时，单击其中的转发卡片。
4. 单击“返回”回到上一层，或单击“关闭聊天记录”关闭窗口。Esc 在嵌套转发中返回一层。

已缓存的转发可以在只看历史时查看。尚未缓存的转发需要开始接收并通过 QQ 连接核验，才能向 SnowLuma 取回。出现失败提示时，可在连接恢复后单击“重试”；已经过期或协议端取不到的内容不保证能恢复。

查看图片：

1. 单击聊天或转发中的图片，打开大图。
2. 滚动鼠标滚轮缩放图片。
3. 按住并拖动图片查看其他区域。双击可以在适应窗口与原尺寸之间切换。
4. 同组有多张图片时，单击“上一张”或“下一张”。
5. 单击“关闭”、按 Esc，或单击图片外的遮罩区域关闭大图。

“原尺寸”是查看器的显示比例，不表示重新取得原始文件。大图使用经过尺寸限制的图像，继续放大可能变模糊。

### 调整外观

1. 打开“设置”→“外观”。
2. 在“深浅模式”中选择“跟随系统”、“亮色”或“夜间”。
3. 按需调整“强调色”、“收到的气泡”、“发出的气泡”、圆角、“基础字号”、“窗口材质”和“表面不透明度”。

有效的修改立即应用并自动保存，不用重启。亮色和夜间各保存一份自定义，编辑的是当前显示的版本。需要交换主题文件时，使用“导入主题”或“导出主题”，在系统文件对话框中选择 JSON 文件。“恢复默认”会清除两份自定义主题并恢复跟随系统。

字体和字号也在“设置”→“外观”里。字体默认是“文渊圆体”，选“系统字体”可换回系统字体；“基础字号”默认是 16，觉得小可以往上调。文渊圆体的字体文件放在程序旁边的 `fonts/` 文件夹里就能选到，文件名用 `WenYuanRoundedSCVF-subset.ttf`（常用字子集）或完整版 `WenYuanRoundedSCVF.ttf`。没找到时界面退回系统字体，外观里字体下面会有一行提示。

### 读取模型列表和换模型

1. 确认 Magpie 已启动，后台处于“接收中”。
2. 打开“设置”→“模型”。进入页面时会读取一次模型列表。
3. 需要刷新时，单击“模型列表”这一行。
4. 在“角色模型”中，单击目标角色的说话模型行；行名由角色名加“的说话模型”组成。
5. 在“搜索模型”中输入名称或能力关键词。
6. 选择需要的模型。

选完即保存，不用重启接收；下一轮使用新设置，正在生成的回合继续使用开始时的设置。需要设置后台任务模型时，使用角色的后台模型行或“全局后台模型”。角色后台模型选择“跟全局”时，使用全局后台模型。

“只看历史”时不读取网关列表，也不能选择模型；思考档位和上下文仍可保存，开始接收后使用。

### 调整思考档位和上下文

1. 打开“设置”→“模型”。
2. 在“按场合思考”中选择“本地思考”、“QQ 私聊思考”或“QQ 群聊思考”。“本地思考”同时用于本地私聊和本地群聊。
3. 选择思考档位。“关”表示关闭思考，其余档位从“最低”到“最高”；实际效果取决于模型支持的能力。后台任务的档位在“后台思考”中调整。
4. 需要调整上下文时，单击“上下文”中的对应数值行。
5. 输入数值。
6. 单击“保存”。

| 设置 | 含义 |
|---|---|
| “上下文长度上限” | 本轮可用的上下文窗口。填 `0` 表示“跟模型”，手动指定时至少为 1000 token。 |
| “留给回复和工具往返” | 为生成回复和工具调用往返预留的额度。 |
| “压缩后保留的原文” | 压缩后保留的近期原文额度，至少为 1000 token。 |
| “开始压缩的比例” | 达到该占用比例时开始压缩。范围为 `0.1`～`1`。 |
| “强制压缩的比例” | 达到该占用比例时强制压缩，不能小于开始压缩的比例。 |
| “本地闲聊自动压缩” | 控制本地闲聊是否自动压缩上下文。 |

这里的 token 是模型计算文本长度的单位，不等于中文字数。这些设置保存后也按新回合生效，不用重启。话题模型、话题压缩门槛和 Go 识图还没做，页面中对应项不可编辑。其他后台配置项大多只供查看，不能按可编辑设置使用。

## 5. 出现问题时

### 先查看后台状态和日志

1. 右键单击 Sumika 托盘图标。
2. 选择“查看后台状态”。
3. 阅读当前阶段后的原因，以及“QQ 连接”和“没恢复的提醒”。
4. 在资源管理器中打开实际数据目录下的 `logs` 文件夹，默认是 `data\logs`。
5. 用文本编辑器打开当天的 `desk-年-月-日.log`，查看出错时间附近的内容。

桌面界面和后台的日志都写在 `desk-<日期>.log` 中。无界面的 `sumika-go` 诊断入口使用 `go-<日期>.log`。也可以用上一节的 `sumika-ctl logs` 命令读取桌面日志。

根目录或配置读取失败时，程序可能还没能打开日志文件。这种情况先看“后台状态”和“设置”→“数据”中的错误，不要把“没有日志文件”当作没有错误。

### 理解设置提示

| 提示 | 含义和处理方式 |
|---|---|
| “读主题失败，已用默认” | 桌面主题设置读取或校验失败，界面已使用默认外观。这条提示本身不表示聊天记录损坏。查看提示后的原因；需要恢复外观时，在“外观”页使用“恢复默认”，并确认没有保存失败提示。 |
| “主题已应用，但没有存上” | 当前窗口已应用新主题，但写入文件失败。查看原因，检查数据目录是否可写、文件是否被占用；不能认为下次打开仍会保留本次修改。 |
| “已保存，重启生效” | 根目录路径已写入 `sumika.root`。通过托盘退出并重新打开后使用新位置，保存不会搬数据。 |
| “配置文件在外面改过，已重新读取” | 页面打开后，配置被其他程序修改过。Sumika 已重新读取配置，查看新值后重新选择本次要改的项。 |
| “已保存，部分没生效” | 配置已写入，但部分运行能力未能应用。按对应行给出的原因处理，并查看实际在用的值；不要把它当作全部成功。 |
| “后台没在运行” | 后台没有正常打开。根据状态页区分数据目录、配置、缺库或数据锁问题。已开的另一个诊断后台也会占用数据锁，应正常退出冲突程序。 |

### QQ 断线或记录不完整

1. 查看“后台状态”中的“QQ 连接”和提醒。
2. 在 SnowLuma 中确认小号仍然登录、协议端正在运行。
3. 如果仍处于“接收中”，等待自动重连；持续断线满 30 秒会出现提醒。
4. 如果已经回到“只看历史”，先处理状态页给出的退出原因，再从托盘选择“开始接收 QQ”。

适配器在接收模式内自动重连；如果整个接收后台已经退出，桌面宿主不会替你反复重新启动接收。出现“SnowLuma 连着但收不到 QQ 消息”时，需要在 SnowLuma 一侧处理接收状态，Sumika 不会替你重启它。

`qq.backfill.enabled` 开启时，连接恢复并核验通过后会尝试自动补录已有私聊和配置允许的群；`qq.backfill.groups` 控制群补录。这两项在 Go 中默认开启。补录消息只保存记录，不触发回复。

补录不保证补齐所有空档：私聊目前只能取一页近期历史，长时间离线可能超出范围；Go 从未保存过记录的新私聊也可能无法发现。缺口的界面标记和手动补录入口还没做。向上滚动只能查看已存记录，不能用来补回 QQ 侧缺失的历史。

### 模型不可用

1. 打开 Magpie，确认目标模型的 ID 和可用状态。配置中的模型 ID 必须与 Magpie 返回的 ID 一致，不能只凭显示名称判断。
2. 核对 `sumika.yml` 中的 `magpie.baseUrl`。
3. 如果无法进入“接收中”，根据状态页或日志中的“列模型”等错误处理连接；角色模型配置错误时，先修正配置，再尝试开始接收。
4. 能进入“接收中”后，打开“设置”→“模型”。
5. 单击“模型列表”刷新。
6. 如果当前模型提示“列表里没有了”，重新选择列表中可用的模型。

页面显示“连接失败”时，可能仍保留上次成功读取的列表；提示中会标出旧列表的读取时间。列表里存在一个模型也不保证服务商当前能完成请求，发送仍失败时需继续查看 Magpie 的调用错误和 Sumika 日志。

相关文档：[桌面程序说明](../native/README.md)、[运行时参考](subsystems/runtime.md)、[QQ 收图下载和断线补录](规格-QQ收图下载和断线补录.md)、[模型设置页](规格-模型设置页.md)。

### MCP 服务被隔离或断了

MCP 服务的一次调用发出去却没拿到结果（超时、被停止、断线、程序当时被关），Sumika 为了不重复执行有副作用的操作，会暂停这个服务并在“没恢复的提醒”里写明；重启、重连都不会自动解除。

1. 看是哪个服务、哪几次调用：在 PowerShell 里执行 `.\sumika-ctl.exe mcp status`。
2. 确认那几次调用对方已经结束，或者你接受“结果未知”的风险，再解除：`.\sumika-ctl.exe mcp release 服务名 --reason "写清楚为什么可以解除" --accept-unknown-risk`。原因必须写；旧调用的记录会保留，不会改成成功。
3. 本机启动的 MCP 服务（子进程）断了会自动重连最多 5 次；提醒里写“自动重连没成功”时，修好原因后执行 `.\sumika-ctl.exe mcp reconnect 服务名`。
4. 不要让模型替你执行第 2 步：这是你对风险的确认。

## 6. 数据和备份

### 找到个人数据

以下路径均相对于实际数据目录，默认是根目录下的 `data/`。聊天库以当前 Go 后台的路径为准。

| 路径 | 内容 |
|---|---|
| `sumika-data.json` | 数据目录的格式标记。不要手动创建或修改来跳过初始化、迁移检查。 |
| `config/sumika.yml` | 个人后台配置。使用外部配置路径时，以实际读取的文件为准。 |
| `config/secrets.bin` | 已配置的加密密钥。QQ 令牌也可能来自配置或环境变量。 |
| `config/history/` | 从模型设置页保存配置前留下的旧配置。 |
| `characters/<角色 ID>/card/` | 角色卡、人设及已有版本历史。 |
| `characters/<角色 ID>/memory.db` | 该角色的记忆库；没有配置记忆库的角色可能没有此文件。 |
| `go/chat/local.db` | 本地私聊、本地群聊的目录和消息。 |
| `go/chat/qq.db` | QQ 消息及相关记录。 |
| `go/trace.db` | Go 后台的回合、工具等运行记录。 |
| `go/media/` | Go 使用的本地媒体。 |
| `go/desktop-settings.json` | 桌面主题、分栏等设置，以及启动后自动接收的开关。 |
| `logs/` | 程序日志。 |

`sumika.root` 位于 exe 旁，不在数据目录内。Windows 的“开机自动启动”属于系统设置，也不在 `sumika.yml` 中。

### 每天自动备份

程序开着接收的时候，每天会自动备份一份：各个库（聊天记录、运行记录、记忆）、角色卡、配置、草稿等放进 `backup.dir`（不写就是数据目录旁边的 `Sumika-备份` 文件夹，建议放到另一块硬盘），媒体按 `backup.dailyMedia` 带（默认只带表情包和头像）。一份一个文件夹，里面有 `manifest.json` 写着带了什么、每个文件的校验值；做完会逐个核对，核对不过的那份标“没通过校验”，不算数。留最近 7 天每天一份、再往前 4 周每周一份，手动备份不会自动删。

- 看有哪些备份、占了多少、盘上还剩多少：`sumika-ctl backup list`。
- 现在就做一份（比如换 exe 之前）：`sumika-ctl backup now`（要带全部媒体加 `--media all`）。
- 备份是逐字节复制：配置里的明文令牌（`sumika.yml`、`mcp.json` 等）原样在备份里，所以备份文件夹要放在你自己的盘上，别同步到不信任的网盘。`config\secrets.bin` 里的密钥是按 Windows 用户加密的，换电脑或重装系统后没设主密码就解不开，要重新填。
- `backup.dir` 要写成一个专门放备份的文件夹：不能在数据目录里面，也不能是盘符根（`E:\`）或数据目录的上级，这样的写法备份会报错。数据目录里别人放的备份（`backup\`、`go\backup-swap-*` 之类）不会被每天备份再带一遍。备份文件夹还会被当成“受保护目录”：角色在本地私聊里读它也要先问你。
- 恢复成新目录：`sumika-ctl backup restore <备份名> --to <一个不存在或为空的新目录的完整路径>`（备份名看 `backup list`）。它只读备份、逐文件核对校验值，再把每个库打开查一遍完整性、对一遍各表行数，结果打印出来，也写进新目录的 `.restore\report.json`。**它不会改配置、不会换掉现在的数据目录**：核对通过后想用它，自己退出 Sumika，把 `--data`（或环境变量 `SUMIKA_DATA_DIR`）指到新目录再启动，原来的数据目录原样留着，不满意再指回去。核对没通过的目录里会留着 `.restore\incomplete.json`，Sumika 不会把它当数据目录打开。这条命令要 Sumika 在运行，每次都要你点一下。
- 每周自动抽验：Sumika 每周会拿最新一份好备份真的恢复到备份目录旁边的 `Sumika-抽验` 里、核对一遍、再把临时目录删掉，结果记在 `backup list` 总览的“上次抽验”里；超过 10 天没有通过的抽验或最近一次失败，自检（`sumika-ctl status`）会报 `backup.drill_stale`。想现在就验一次：`sumika-ctl backup verify`。
- 设置页里的备份列表和“切换到恢复出的目录”的按钮还没做。

### 备份和搬迁

1. 从托盘选择“退出 Sumika（后台和界面一起退出）”。
2. 等待程序退出；如果另有诊断后台使用这份数据，也将其正常关闭。
3. 用资源管理器将整个数据目录复制到另一块磁盘或备份位置。
4. 如果 `sumika.yml` 通过环境变量放在数据目录以外，再单独复制该配置文件。
5. 如果使用了 `sumika.root`，保存它的副本，并记录程序资源的位置。

复制整个目录可以同时保留聊天库、记忆、角色卡、配置和媒体。不要只复制一个正在使用中的 `.db` 文件代替完整备份。更换位置后，“设置”→“数据”只能改根目录指向，不会自动搬迁数据。

从“设置”→“模型”保存发生变化的配置前，旧配置会原样备份到：

```text
<数据目录>/config/history/<年月日-时分秒>[-序号]-sumika.yml
```

同一秒多次保存会使用不同文件名。这份历史只保护配置，不是聊天记录、记忆和媒体的整机备份。手动用编辑器修改配置时，不会触发这条自动备份流程，应先自行复制旧文件。

### 哪些内容不进 git

项目的 `.gitignore` 排除了 `data/`、个人 `sumika.yml`、日志、`.env`、配置旧副本，以及项目根目录下的 `Sumika-备份/`。因此，git 提交和推送不会备份你的聊天记录、角色卡、记忆或个人配置。仓库中的 `characters/example/` 只是示例卡。

这些忽略规则针对仓库约定的位置。把个人数据或备份复制到其他目录、改用其他名称时，不要假定它仍会被 git 自动忽略。配置历史可能包含令牌，应和个人配置一起保管。
