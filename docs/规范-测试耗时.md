# 规范：测试耗时

> 状态：2026-11-09 定。主人：“压到 1 分钟以内……耗时越短越好，在不影响测试质量的前提下。并且最好给一个标准或规范，用来引导后续新测试的创建。”
> 依据：[合并队列规格](规格-合并队列.md)、ADR-225（慢对拍交每日整套）、2026-11-09 实测（下面第四节）。

## 一、预算

都按 `go test -short`，机器不忙时量：

| 单位 | 预算 | 超了怎么办 |
|---|---|---|
| 一个包 | 60 秒 | 必须处理：找共同开销，或把慢的交给每日整套 |
| 一条顶层测试 | 3 秒 | 写清楚为什么要这么久，能拆就拆 |
| 一条子测试 | 0.5 秒 | 同一个夹具跑多组，不要每组都开一遍后台 |
| 每日整套 | 不设上限 | 它就是放慢测试的地方 |

量具：`bun scripts/go-test-times.ts [包…]`，打印每个包和最慢的测试。

## 二、写新测试时

先问这条测试要验什么，然后用能验到它的最小范围。

1. **能测函数就不开后台。** `app.Open` 约 0.2 秒，一个包几百条就是一分钟。判断逻辑抽成函数，表驱动测函数；只留一两条走完整路径。
2. **矩阵共用夹具。** 几十组参数不要每组都 `Open`。先建好，每组只改要变的那一点。
3. **不等真时间。** 不写 `time.Sleep`，不陪真实退避：退避、轮询、防抖做成可注入的选项，测试给 0 或用事件同步。墙钟等待还会在机器忙时误红（LESSONS）。
4. **不起真进程。** 起一次 PowerShell 要一秒左右，还要过杀毒。解析、分类、错误处理抽出来单测；真进程的全流程只留一条，放进每日整套。
5. **不现编程序。** `go build`、`go run` 一次十几秒。要编的放进每日整套。
6. **贵的东西只做一次。** `go list`、探测 shell、解析器进程，用 `sync.Once` 或包级缓存共用（`internal/archcheck` 是例子）。
7. **规模测试分开。** 上万条数据、竞态、压力测试放每日整套，合并时跑规模小的版本。
8. **等待的上限只防卡死。** 等屏障、等后台结果的时限给到一分钟左右，别写一两秒：改坏时流程是卡到测试放行的，上限长只是红得慢；写短了机器忙时误红。要验“不等某件事”，就让那件事卡到测试结束，不量多快（排查（私有存档））。

## 三、什么该放进每日整套

写 `if testing.Short() { t.Skip("原因，放在每日整套") }`，原因写清楚。适合放的：

- 现编 exe、跑 `go test`、`go run`。
- 反复起真实子进程（模型服务、pwsh 全流程）。
- 和 Bun 录像对拍（ADR-225）。
- 上万条规模、压力、竞态。
- 工具本身的对照（`bench-shell`）。

不能放的：判断权限、身份、可见性、谁能发什么的测试，改坏了当天合并就要红。这类慢就拆，不跳。

跳过不等于不测：每日整套（`go-verify --full`）照跑，红了第二天报告里会有。跳之前确认这条的核心判断有更小的测试覆盖，没有就先补。

## 四、已经做好的共同加速

新测试不用自己处理这些：

- 测试程序里所有 SQLite 连接都不等落盘（`store/fastsync_tests.go`）。这是开后台最大的一块。
- `turn.DetectShell` 探到一次就记住；命令解析器启动 3 秒后才预热，很快关掉的不起进程。
- `go-verify` 把最慢的几个包按记下的每条耗时分成“核数减 2”个进程、一个包一个包跑（`scripts/go-shard.ts`；2026-11-12 以前是按名字分六份）。包内已经 `t.Parallel` 的不分（internal/app）。
- server 的 Bun 整套按文件分进程跑（`bun test --parallel`，默认核数减 4、最多 8；2026-11-12 实测 133 → 35 秒，通过数一样）。不加 `--no-isolate`：没更快，还让文件之间串状态。新测试照旧一个文件一组，别把很多慢测试塞进同一个文件——并行是按文件分的。
- `go test`、`bun test` 排全机名额：开发中用 `bun ../scripts/slot.ts …`，直接敲等于绕开（AGENTS 验收）。

## 五、结果

| 包 | 压之前（挤在一起） | 现在（`go-verify` 的跑法） |
|---|---|---|
| 根包 | 273 秒 | 42 秒 |
| `internal/app` | 318 秒 | 35 秒 |
| `internal/memory` | 166 秒 | 23 秒 |
| `internal/turn` | 165 秒 | 20 秒 |
| `internal/embed` | 218 秒 | 进不了前十二 |
| `internal/bench` | 184 秒 | 进不了前十二 |
| `cmd/bench-shell` | 178 秒 | 进不了前十二 |
| `internal/archcheck` | 36～95 秒 | 7 秒 |

做法：测试库不落盘，慢的进程和编译交给每日整套（约 40 条，都是现编程序、起真实进程、对拍和规模测试；审批相关的没跳），超过一分钟的四个包分六个进程、一个一个跑。没有删断言。这 40 条没有逐条核对是不是都有更小的测试覆盖，每日整套照跑，有回归第二天能看到。

`go-verify` 跑完会提醒超过 60 秒的包。
