# 规格：外部程序的查找收到一处（P2-5）

> 状态：已做完（2026-11-16），两步都做了。实现时多出三处有意的变化，写在第 3、5 条末尾。来源：后续路线 P2-5、质检 X-15、X-34（块 I 第 330～350 行环境清单）。依赖 P2-3（[规格-环境自检](规格-环境自检.md) 第 3 条已建 `internal/toolchain` 登记表，只出报告）。参考：盘点 `data/dev/research/盘点-状态板和环境自检-20261116.md` 第 3 节“外部程序查找点”和坑 7、9。

## 开工卡

- **我理解成**：Sumika 运行时要用的外部程序（PowerShell、rg、fd、ffmpeg、ffprobe、git）只在 `internal/toolchain` 一个地方找，各处都向它要路径；找的顺序统一成“Sumika 自带的目录 → 配置里写的 → PATH → 系统安装目录”；`sumika-ctl doctor` 逐个写出用的是哪一个、什么版本。正例：把 ffmpeg 放进 `<资源根>/vendor/bin`，收视频和链接展开都用它；在 `qq.media.ffmpeg` 填了路径，链接展开也认（现在不认）。反例：现在这样，收视频读配置、链接展开只找 PATH，命令分析器只认 PATH 里的 `pwsh`、执行工具却会找到 Program Files 里的那个。
- **领域正统做法**：应用自带依赖优先（便携包把工具放在自己目录里），找不到再退到系统；路径解析集中在一处、结果缓存，调用方只拿结果（例：VS Code 的 `terminal.integrated.defaultProfile` 解析、Git for Windows 的 `bin/` 优先）。
- **最省事的字面做法够不够**：只给各处加一句“先找 vendor/bin”不够：五处各写各的，下次加程序又会漂移；架构测试拦不住新写法。
- **不做什么**：不打包这些程序（便携包是 P2-10）；不管用户在 MCP 配置里写的命令（那是用户指定的，照原样按 PATH 找）；不管 Bun 冻结线的 `bun` 查找；不管 `taskkill`、`rundll32` 这类 Windows 自带命令（登记成系统程序，绝对路径从 `%SystemRoot%` 拼）。
- **用户能看能试的验收**：见“验收”第 1、2 条。

## 设计

1. **查找顺序**（每个程序一样）：`<资源根>/vendor/bin/<名字>.exe` → 配置里写的路径（只有登记了配置键的程序：`ffmpeg`、`ffprobe` 读 `qq.media.ffmpeg`/`qq.media.ffprobe`）→ PATH → 这个程序的系统安装目录（PowerShell 7：`%ProgramFiles%\PowerShell\7`；Windows PowerShell 5.1：`%SystemRoot%\System32\WindowsPowerShell\v1.0`；git：Git for Windows 的标准安装根）。配置写了但文件不在：日志警告一次，接着往下找（和现在收视频的行为一致）。
2. **接口**：`toolchain.Lookup(name) (Result, bool)` 返回缓存的结果；`toolchain.Refresh(env)` 在宿主启动时和配置保存后重查（P2-3 已有的触发点）。调用方不再自己 `LookPath`。没有初始化时 `Lookup` 现查一次（测试和命令行工具用）。
3. **两个 PowerShell**：登记表里 `pwsh`（PowerShell 7）和 `powershell`（执行工具用的，先 7 后 5.1）保持两行。命令分析器向 `pwsh` 要；执行工具和钩子向 `powershell` 要。顺序按第 1 条，所以命令分析器从此也能用 Program Files 里的 PowerShell 7（现在只认 PATH），这是有意的行为变化。
   - 实现时加的第三行 `powershell51`（只找 Windows PowerShell 5.1）：给系统通知用。实测 PowerShell 7 加载不了 `Windows.UI.Notifications` 的类型，通知弹不出来，所以通知不能走“先 7 后 5.1”的 `powershell` 行。
4. **版本**：`Refresh` 之后在后台对找到的程序各跑一次取版本的命令（`pwsh -NoProfile -Command $PSVersionTable.PSVersion.ToString()`、`rg --version`、`fd --version`、`ffmpeg -version`、`ffprobe -version`、`git --version`，取第一行），每个最多 3 秒，结果缓存进 `Result.Version`；取不到写空、不算失败。`doctor` 的子项写成“<路径>（<来源>，<版本>）”。
5. **调用方改走登记表**：`policy/analyzer.go`（pwsh）、`tools/shell.go` 和 `app/shellcommand.go`（PowerShell、Git Bash）、`turn/turn.go` 的 `DetectShell`、`tools/search.go`（rg、fd）、`mediafetch/video.go` 和 `linkexpand/media.go`（ffmpeg、ffprobe；链接展开从此读 `qq.media.*`）、`watchdog/toast_windows.go`（系统 PowerShell）。行为上唯一有意的变化是第 1 条的顺序和第 3 条；其余找到的路径和现在一致（测试对照）。
   - 实现时的另两处变化：Git Bash 只从 `git` 那行的安装根推出 `bash.exe`，不再单独到 PATH 里找 `bash.exe`（只有 bash、没有 git 的布局不再支持）；rg、fd 不再去 `~/.pi/agent/bin`（别的软件的目录）找，只认自带目录和 PATH。
6. **架构测试**：`native/internal/` 非测试文件里，`exec.LookPath(` 只许出现在 `internal/toolchain`；`exec.Command(`/`exec.CommandContext(` 的第一个参数如果是字符串字面量且不是绝对路径，只许出现在 `internal/toolchain`。例外清单只许缩短，第一版登记：`mcpclient`（用户配置的命令）、`bunchild`（冻结线）。

## 分步

1. **登记表补全**：查找顺序（第 1 条）、`Lookup`/`Refresh`、版本（第 4 条）、系统程序登记；`envcheck` 的 `env.tools` 子项带版本；`doctor` 渲染带版本。测试：每个程序在“只有自带 / 只有配置 / 只有 PATH / 只有系统目录 / 都有”五种布局下找到的是对的那个；取版本超时不卡。
2. **调用方改走登记表**（第 5 条）和架构测试（第 6 条）。测试：每个调用方在同样布局下拿到的路径和登记表一致；链接展开读 `qq.media.ffmpeg`；命令分析器能用 Program Files 里的 PowerShell 7。

## 禁止的偷懒写法

- 调用方留着自己的 `LookPath` 作“兜底”。
- 取版本放在界面绘制或 `doctor` 命令执行时现跑。
- 为了让对照测试过，改测试去迁就新顺序却不在提交说明里写“有意的变化”。

## 验收

1. 测试布局：`vendor/bin` 里放一个假的 `ffmpeg.exe`、PATH 里另有一个：收视频和链接展开都拿到 `vendor/bin` 那个；`doctor` 的 ffmpeg 子项写“自带”。
2. `qq.media.ffmpeg` 写一个存在的路径、`vendor/bin` 没有：链接展开也用配置里的（现在不用）。
3. PATH 里没有 `pwsh`、Program Files 里有：命令分析器可用（`Analyzer.Status().Available`），`env.analyzer` 是正常。
4. 在 `internal/` 下新写一个 `exec.LookPath("ffmpeg")`：架构测试红。
5. 取版本：一个假程序睡 10 秒，`Refresh` 后 3 秒内版本那项放弃，别的程序版本照常有。
