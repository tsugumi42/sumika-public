## 一、目标、范围和不做的事

**目标**：Sumika 能同时配好几个模型服务商（本机网关、直连的云服务、本机 Ollama 一类），按用途给每件事指模型，一家连不上不拖垮别家；Magpie 只是预设服务商里的一家，没装 Magpie 的电脑也能完整使用（ADR-044 第 1 条）。

**范围**：服务商定义和认证、模型目录（发现 + 手填）、用途分配、备选链的引用格式、连接测试和发现失败的表现、设置页结构、迁移。

**不做**：Anthropic 原生、Responses 等其他线路；价格和用量展示（有需要时另立）；嵌入和重排；命令取 key、OAuth 登录；模型能力表内置或联网取；按模型的思考档位（`agent.thinking.*` 仍按场合配，不挂到模型引用上）；替换 `llm` 包的重试、看门狗和故障切换逻辑。

## 三、分层设计

```
服务商 providers     连到哪、怎么认证、有哪些兼容开关
   ↓
模型目录 catalog      每家发现的模型 + 手填覆盖 + 能力（上下文、看图、思考档位）
   ↓
用途分配 roles        说话、后台、识图、顾问、核验、子代理、压缩各用哪个模型
   ↓
备选链 fallbacks      主模型失败时按序换谁（全局 + 角色覆盖）
   ↓
角色覆盖 characters   某个角色单独的模型、后台模型、备选链
```

每一层只引用下一层的名字（服务商 ID → 模型引用 → 用途），不复制内容。

### 3.1 服务商

配置放 `providers:`（顶层，和 omp、Hermes 一样叫 providers）：

```yaml
providers:
  magpie:                         # 服务商 ID：小写字母、数字、- 和 _；不含 / # :；改 ID 等于换一个服务商
    preset: magpie                # 预设：带默认地址、说明和专属行为；可省（省了就是纯通用）
    name: Magpie                  # 显示名，可省（预设有默认）
    kind: openai-compatible       # 目前只认这一个（拍板问题 2）
    baseUrl: http://127.0.0.1:3425/v1
    auth: bearer                  # none | bearer | header；Magpie 预设自带公开的客户端标识，不用填 keyRef
    enabled: true
  deepseek:
    name: DeepSeek
    baseUrl: https://example.invalid/v1        # 示意
    auth: bearer
    keyRef: <密钥引用，写法见下面字段规则>   # 只放引用，不放明文；和联网搜索的 web.keyRef 同名同格式
    discovery: auto               # auto：GET {baseUrl}/models；off：只用手填
    headers: { X-Client: sumika } # 非秘密请求头；值也可以是引用
    compat: { cacheKey: false }   # 兼容开关，见下
    models:                       # 手填或覆盖，可省
      some-model:
        name: 某某模型
        contextWindow: 128000
        maxOutputTokens: 8192
        input: [text, image]
        reasoning: [low, medium, high]   # 能开的档位；[] = 明确不支持思考
defaultProvider: magpie           # 裸引用归谁（拍板问题 1）；迁移时 = magpie；服务商只有一个时可省
```

字段规则：

- `id` 在 `providers` 里唯一；`enabled: false` 的服务商仍保留引用，页面标灰，请求时报"服务商已停用"，**不静默换别家**。
- `baseUrl`：只认 `http://`、`https://`，必须有主机（沿用 `setting_file.go:68–81` 的校验）；去掉末尾 `/`；不做"自动补 `/v1`"，由测试按钮提示（第六节）。非回环地址的 `http://` 且带 key 时，页面写一行"key 会明文发出"，不拦（用户自己的局域网网关是正常用法）。
- `keyRef`：密钥引用，写法是 `${secret:名字}`（密钥库）或 `${env:名字}`（环境变量），名字约定见第五节。
- `auth`：`none`（不发 `Authorization`）；`bearer`（`Authorization: Bearer <key>`）；`header`（用 `authHeader` 指定的头名发 key，给 `api-key` 这类）。预设可以带**公开的默认 key**（见 Magpie 预设），它是标识不是秘密，不进密钥库。
- `headers`：不允许设置 `Authorization`、`Host`、`Content-Length`、`Content-Type`、`Accept`（保存时拒绝）；值可以是 `${secret:…}` 或 `${env:…}` 引用。
- `models.<id>` 的每个字段**单独**覆盖发现结果，没写的字段仍用发现的值（omp 的做法）。
- **未知字段**保留、不拒收，只在日志和设置页"诊断"里警告（omp 的做法）；保存时原样写回，不丢（Hermes 备选链编辑器那个事故的教训）。
- `kind` 目前只认 `openai-compatible`，别的值保存时拒绝并写明"这个版本还不支持该线路"。

**兼容开关 `compat`**（直连别家时避免请求被拒；omp 的 `compat`、Hermes 的 `extra_body` 同类）。通用服务商取保守默认，Magpie 预设取"和今天逐字节一致"的值：

| 键 | 作用 | 通用默认 | Magpie 预设 |
|---|---|---|---|
| `streamUsage` | 请求带 `stream_options.include_usage` | `true` | `true` |
| `cacheKey` | 带 `prompt_cache_key` | `false` | `true` |
| `longCache` | 带 `prompt_cache_retention` | `false` | M1 时从 `turn` 的请求构造读出现行值填入（我没读那一段，不当已定） |
| `store` | 带 `store: false` | `false` | 同上，M1 时读出填入 |
| `maxTokensField` | `max_completion_tokens` 或 `max_tokens` | `max_completion_tokens` | `max_completion_tokens` |
| `systemRole` | `auto`（按模型能开思考用 `developer`，否则 `system`）、`system`、`developer` | `system` | `auto`（今天的行为） |
| `reasoningEffort` | `auto`（模型报告或手填了档位才发）、`never` | `auto` | `auto` |
| `extraBody` | 合并进每个请求体的 JSON 对象，**不能覆盖** `model`、`messages`、`stream`、`tools` | 无 | 无 |

默认值是我选的起步值，没有逐家核实；每个直连服务商第一次连通后以"能不能请求成功"为准调整，不为单个服务商在代码里写特例。

**预设（preset）** 是一段程序内的数据，只含：默认显示名、默认 `baseUrl`、说明文字、`compat` 默认、专属行为开关。**预设不带任何模型名**（ADR-098）。第一版预设见拍板问题 4。

**Magpie 预设**的专属内容（不是只有地址）：
1. 公开的客户端标识 `magpie-sumika` 作为默认 key（`llm.Magpie()` 现在的写法，按 key 里 `magpie-` 后面那段认客户端）；
2. "连不上"提示"请确认 Magpie 已经打开"；
3. 读 `/models` 里的 `magpie_label`、`reasoning_levels` 等 Magpie 多给的字段（别家没有就是空，字段本身对所有服务商都可读，只是不再叫 `MagpieLabel`，改成通用的 `Label`）；
4. 读响应头 `x-magpie-provider`、`x-magpie-model` 作为"实际落到的渠道"（`llm.Route`，用于 trace 和用量），别的服务商不读；
5. 兼容开关的默认值如上表。

这些放在 `llm` 包的"方言"里（`Source.Dialect`），不放进通用结构，也不删。（2026-11-16 注：线上格式的拼装和解析已按 [规格-模型对话编解码](规格-模型对话编解码.md)（P2-6）收进“OpenAI 聊天”编解码器；请求头的保留名单已在 `llm` 里强制（不许覆盖 Authorization、Host、Content-Length、Content-Type、Accept）；这里的 Magpie 专属行为由 P2-7 改成预设数据时再改写本节。）

### 3.2 模型目录

**来源**（后面的盖前面的，字段逐个盖）：

1. 发现：`GET {baseUrl}/models`（`discovery: auto`），读 `id`、`display_name` / `name`、`owned_by`，以及这些能力字段（有就读，没有就空）：上下文（`context_length`、`context_window`、`max_input_tokens`，沿用 `llm.Model.Window()` 的取值顺序）、`max_output_tokens`、`modalities.input/output`、`reasoning`、`reasoning_levels` / `supported_reasoning_levels`；
2. 手填：`providers.<id>.models.<模型ID>`，每个字段单独覆盖；手填一个服务商不报告的模型，等于把它加进目录。

**能力表不内置，窗口和单次输出分四层取**（拍板问题 9，ADR-334）：用户覆盖、服务商报告、models.dev 缓存（只补空）、保守默认；每个字段单独取并记来源（`llm.Model.Limits`）。都没有时：窗口按 128000、单次输出按 32000，明确标"未知"，压缩硬线比例最多 0.75；看图按"不能"算（现状 `SupportsImages` 要求明确的 `image`）；思考档位未知时不发 `reasoning_effort`。

**缓存**：每个服务商一份 `<数据目录>/cache/models/<服务商ID>.json`（`paths.CacheDir()` 下，不进 git），内容 = 取到的时间 + `baseUrl` 的指纹 + 模型列表，**不含 key 和请求头**。写入是原子替换；读出时如果 `baseUrl` 指纹变了就丢弃。大小设上限（起步值：响应体 5 MB、5000 条），超了当"读不懂"处理。

**引用格式**（拍板问题 1）：
- 规范形式 `服务商ID/模型ID`，在第一个 `/` 处切；`服务商ID` 必须是已声明的服务商；
- 对象形式 `{provider: x, model: y}` 等价；
- **裸字符串**：如果它的第一段（第一个 `/` 之前，没有 `/` 则整串）恰好是已声明的服务商 ID 就当规范形式；否则整串是模型 ID，归 `defaultProvider`。保存新服务商时检查：它的 ID 不得等于任何已有裸引用的第一段，否则拒绝并列出冲突的引用；
- 引用解析后发给服务商的 `model` 字段是**不带服务商前缀的模型 ID**；
- 引用所指的模型不在目录里（发现 + 缓存 + 手填都没有）：值保留，页面标"不在列表"，运行时报"服务商 X 的列表里没有 Y（现在有 N 个）"；**不拿别的模型顶替**。

### 3.3 用途分配

配置键**保持现有位置**（不迁移、不改名），只是值的类型从"裸字符串"扩成"引用"（接受裸字符串和对象，规范写成字符串）。设置页把它们统一画成一张"用途"表（第七节）。

| 用途 | 键 | 没选时 | 能力要求（选的时候和运行时都检查） |
|---|---|---|---|
| 说话 | `characters.<id>.model` | 输入框拦住"还没选模型"（ADR-098） | 无；如果这轮带图片直发，要求能看图 |
| 后台 | `characters.<id>.background` → `defaults.backgroundModel` | 后台活不做，日志每种提醒一次（ADR-098） | 无 |
| 话题 | `characters.<id>.topic` | 跟随说话模型（现有文案） | 无；功能本身还没做 |
| 识图 | `vision.model` | 图不看（ADR-098） | **必须能看图**；选了不能看图的模型，保存时拒绝并说明，不静默收下 |
| 顾问、核验 | `agent.advisor.model`、`agent.verify.model` | 不能开启 | 无 |
| 子代理 | `subagents.model` | 同现状 | 无 |
| 压缩（新） | `agent.context.compactModel` | **跟随当次对话模型**（现有行为，拍板问题 8） | 上下文窗口不得小于压缩所需输入，不满足时保存提示 |

能力要求的检查点：①用户在设置页选择时，不满足的选项置灰并写原因；②保存时再校验一次（防止用手改 yml 绕过）；③运行时（如备选链里的某个模型不能看图）按故障切换规格第 7 条处理：不静默丢图。

### 3.4 备选链

沿用故障切换规格的路线和参数，只改两点：
- 链里每一项是**引用**（可以跨服务商），不再是裸 ID；
- 冷却表的键从"客户端来源内的模型 ID"改成"（服务商ID，模型 ID）"——同名模型在两家服务商之间不会互相冷却。规格里原来写的"按客户端来源内的模型 ID 冷却"已经是按来源分开的，所以本改动只是把"来源"换成服务商 ID，不改 60 秒、不改"只有哪几类错误可换"。

链里放"主人已经测过适合该用途的模型"，程序不自动探测、不硬编码模型名（原规格）。omp 的"按岗位分链"、"服务商通配"这一版**不做**，先保持"全局 + 角色覆盖"。

### 3.5 角色覆盖

不变：`characters.<id>.model`、`background`、`topic`、`fallbackModels`（省略或 null 继承，`[]` 禁用）。不增加角色级的服务商地址和 key（拍板问题 7）。角色卡仍不放模型（ADR-084）。

### 3.6 运行时

- `ModelRuntime` 持有按服务商 ID 分开的状态：每家一个 `llm.Client`、一份目录、一个状态（正常 / 连不上 + 原因分类 + 上次成功时间 / 认证失败 / 密钥未解锁 / 不提供列表 / 读不懂 / 已停用）。`CatalogError string` 换成按服务商的状态表。
- 发请求：`turn` 拿到引用 → 按服务商 ID 取 client → 发 `model = 模型ID`。装配处不再有一个全局 `a.llm`；`app.go:353` 的 `llm.New(llm.Magpie(...))` 换成"按配置构建一组 client"。测试仍可注入假的（现在注释里写的"假 Magpie 也可以直接给一个指过去的 `llm.Client`"要保留等价写法）。
- 生效时机沿用现有：保存后发布，下一轮对话使用，在途回合沿用各自版本（`ModelRuntime` 整体原子替换）；改服务商地址或 key 引用同样"下一轮生效"，不需要重启。
- trace、用量里的模型标识带服务商 ID（`服务商ID/模型ID`），Magpie 的实际渠道仍单独记（`x-magpie-*`）。
- 同一个服务商的目录刷新互斥，不同服务商并行；刷新带取消（关闭窗口、重复点击）。

## 四、迁移（不丢、不改、可回退）

1. **读取时合成，不写文件。** 加载配置时，如果没有 `providers:` 或其中没有 `magpie`，就在内存里合成 `providers.magpie = {preset: magpie, baseUrl: <magpie.baseUrl 或默认值>}` 并设 `defaultProvider: magpie`。此时所有裸引用都归 magpie，行为和今天**逐字节一致**（用现有的录像回归测试钉住：同一输入产生同一请求体和请求头）。
2. **第一次在界面里编辑服务商时才写 `providers:`。** 写入走现有的配置保存路径（备份到 `config/history/`、保留注释、原子替换、重读核对、失败回滚，见设置页规格 S2），把合成的 magpie 一并写成明文配置；`magpie.baseUrl` **留着不动**。之后 `providers.magpie` 在就以它为准，`magpie.baseUrl` 在设置页"诊断"里标"已被取代，不再生效"。
3. **引用不迁移。** 裸字符串保持原样；用户在界面里重新选一次模型时才写成规范形式。`fallbackModels` 同理。
4. **回退**：删掉 `providers:` 和 `defaultProvider:` 两节即回到第 1 步的行为；换回旧 exe 也能用（旧版忽略不认识的键）。设置页保存的备份在 `config/history/`，可以手动还原。
5. **不动真实数据的验证**：迁移测试只用临时目录里造的配置；给主人手动验证的步骤写在交付说明里（先备份 `sumika.yml`，再打开设置页），本规格不碰真实 `data/`。

## 五、密钥

- 配置里只有引用：`${secret:<名字>}`（密钥库）或 `${env:<名字>}`（环境变量）。格式、解析函数和 `web.keyRef` 共用（`kernel_wiring.go:66,288` 的 `ecosystemSecret` 抽成通用函数，不复制第二份）。
- 密钥库名字：`provider.<服务商ID>.apiKey`（和 `qq.<号>.token`、`web.tavily.apiKey` 同风格）。请求头里的秘密值：`provider.<服务商ID>.header.<头名>`。
- **写入能力用联网搜索规格 2.6 承诺补的那一份**（单项保存、沿用 v1 加密格式、保留 `wraps.password` / `wraps.recovery` 和未修改的条目、失败不覆盖旧文件、锁定时不新建文件顶掉旧库）。本规格不再做第二套。该能力没落地之前，设置页的 key 输入框置灰，写"请先用环境变量或在 Bun 里导入"，环境变量引用照常可用；所以第一版 M1～M3、M5 不受阻，M4 里"在界面存 key"这一项等它。
- 锁着、没有文件、条目缺失、值为空、格式坏分别报不同的话；`secrets.ErrLocked` 对应页面状态"密钥未解锁"，**不当成认证失败**。
- 密钥原文不进：配置文件、日志、错误信息、trace、录像、界面回显、URL、导入导出（导出只带引用名）。请求头不记录（`llmtest/record.go` 已不记请求头，保持）；服务商返回的错误体展示前先抹掉 key 值和 `Bearer …`。
- 只有"主人 × 主窗口"能改服务商（地址、认证、请求头、key 引用）；**设置工具**（客户端自知规格的白名单）不开放 `providers.*`，只开放"在目录里选模型"这一类字段，且必须是已有服务商里的模型。理由：改地址等于把请求和 key 发到别处。
- 改已有 key 的服务商的**主机名**时，页面要二次确认"key 会发往新地址"。
- 重定向：沿用 Go 默认，跨主机重定向不带 `Authorization`（要有测试钉住）。

## 六、连接测试和模型发现失败的表现

**测试按钮**（服务商详情里）一次做三步，逐步报告：
1. 解析和连接地址；
2. `GET {baseUrl}/models`，带认证；
3. 读目录，报"N 个模型，其中 M 个报告了上下文长度"。

结果分类（沿用设置页规格第三节第 6 条的口径）：

| 结果 | 页面怎么写 | 是否算失败 |
|---|---|---|
| 连上并读到目录 | 已连接，N 个模型 | 否 |
| 地址不对（域名解析失败、地址格式错、返回了 HTML 页面） | 地址好像不对：……。如果少了 `/v1`，试试 `<地址>/v1`（有"改成这个"按钮，**不自动改**） | 是 |
| 拒绝连接 | 连不上：对方没在这个端口监听（本机网关是不是没开） | 是 |
| 超时 | 超时：N 秒没回应 | 是 |
| 认证失败（401、403） | 认证失败：key 不对或没权限 | 是 |
| 密钥未解锁、没存 key | 还没有可用的 key：…… | 是 |
| `/models` 返回 404 或 405 | 连上了，但这个服务商不提供模型列表：请手动添加模型 | **否**，该服务商自动落到"只用手填"，不报红 |
| 返回 200 但读不懂 | 地址能连，但列表格式不认识 | 是，附前 200 字（已脱敏）|
| 限流、5xx | 服务商现在不可用：…… | 是，可重试 |

测试**不发聊天请求**（不花钱）。另有一个单独的"发一句话试试"按钮，选一个模型，发一次很短的请求，旁边写"会产生一次很小的调用"；失败时分类同上，加"这个模型不接受的参数"（把服务商返回的错误信息脱敏后给出，提示可能要改兼容开关）。

**探测时限**（起步值，可按服务商改）：回环地址 3 秒，其他 10 秒（omp 对本机用更短的探测，远程 10 秒）。目录响应有大小上限。

**发现失败的表现**（ADR-044 第 4 条：一家坏了不让整体起不来、不静默）：
- 每个服务商独立刷新、独立记状态，**一家失败不影响别家，不阻塞启动**；
- 失败时保留**上一份成功的目录（缓存）**，页面写"用的是 12:03 的缓存"和失败原因，缓存里的模型照常可选可用；
- 配置里引用了、但目录里（含缓存）没有的模型：标"不在列表"，不删除引用；
- 首次启动没有缓存且连不上：该服务商显示"连不上"，引用它的用途标红提示"服务商连不上"；
- 自动接收（`autoreceive.go`）：对"账号绑定角色的模型引用所指的服务商"，**有缓存且缓存里有该模型**就直接放行启动（第一次请求失败由备选链或报错处理）；没有缓存就沿用现在的"等它起来、重试"；不因为**别的**服务商连不上而阻塞；
- 日志每个服务商每种状态只记一次变化，不刷屏。

### 6.1 先落地的一步：目录不当启动门槛（P2-2，2026-11-15）

> 状态：做完（2026-11-15）。后台部分已合 main；聊天框那一行在分支 feat/p2-2-catalog-notice，随本提交一起入队。界面那一行的状态由宿主每 2 秒读一次 `App.CatalogState`（只读内存、不列模型），变了才发布；本地群聊的输入框上方也会显示。

只做上面“发现失败的表现”里不依赖多服务商的那一半；服务商还是只有 Magpie 一家（多服务商是 P2-7）。

**开工卡**

- **我理解成**：接收模式启动时列模型失败不再让整个后台起不来；用上一份落盘的目录照常跑，没有就带着“目录取不到”进接收中，发消息那一刻才报“模型来源连不上”。后台按退避自己重试，来源回来后不用重启。正例：Magpie 没开就启动 Sumika，能进接收中，本地私聊发一句，聊天框上方一行“模型来源连不上（127.0.0.1:3425）：打开 Magpie，或在设置 · 模型里换地址”，打开 Magpie 后一分钟内自动恢复，再发就能回。反例：列模型失败时偷偷换成空目录、什么也不说；或者一直卡着重试不让进接收中。
- **领域正统做法**：“发现失败不阻塞、保留上一份成功结果并标时间”是 omp 和 opencode 的做法（本规格第六节和[四家对照](notes/对照-模型配置-四家-2026-11-09.md)）；探测时限回环 3 秒、远程 10 秒照第六节。
- **最省事的字面做法够不够**：只把 `return failed(...)` 删掉不够：没有缓存时模型能力（窗口、看图）全丢；也没有恢复路径，来源回来以后还得重启。
- **不做什么**：不做多服务商、不做测试按钮（P2-7）；不改备选链；不改模型页布局，只在现有位置多显示“用的是几点的缓存”和失败原因。
- **用户能看能试的验收**：见下面“验收”第 1、2 条。

**做法**：

1. `llm` 列模型加时限和大小上限：回环地址 3 秒、其他 10 秒（只管列模型这一个请求，不影响对话请求）；响应体超过 8 MB 就报“模型列表太大”，不读进内存。
2. 每次列模型成功，把原始列表（解析前的模型项，不含用户覆盖）写到 `paths.ModelCatalogCache()`（`cache/model-catalog.json`，带来源地址和读到的时间）；先写 `.tmp` 再改名。来源地址变了，旧缓存不用（当没有缓存）。
3. `Open` 列模型失败：有缓存就用缓存，`ModelRuntime.CatalogError` 写失败原因，`ReadAt` 是缓存的时间；没缓存就用空目录加 `CatalogError`。两种都继续启动，不 `return failed`。
4. `checkModels`（账号绑定角色的模型在不在列表）不再挡启动：目录是好的、模型确实不在列表时，照旧报给用户（自检和日志各一次），但进接收中；目录取不到时不判断。真正发消息时 `hub.cardAndModel` 已有的 `UnknownModelError` 那条路负责报错；目录取不到时报错要换成“模型来源连不上：<原因>”这一类，不说“模型不存在”。
5. 后台重试：`CatalogError` 不空时按 30 秒、1 分、2 分、5 分（之后一直 5 分）重试列模型；成功就原子替换 `ModelRuntime`（照现有 `refreshModels` 的写法）、清掉 `CatalogError`、写缓存、日志记一行“模型来源恢复了”。日志每种状态变化只记一次。程序退出、切回只看历史时停。
6. `autoreceive.go` 的重试：列模型失败不再算“值得重试”的启动失败（因为启动已经不会因它失败了）；其余照旧。
7. 界面：聊天框上方一行提示（照设计语言第十一节“常驻最多一行”），文字“模型来源连不上（地址）：打开 Magpie，或在设置 · 模型里换地址”，带“去设置”按钮；用缓存时模型页那一节写“用的是 HH:MM 的缓存”。恢复后提示自己消失。

**验收**（每条对应测试或日志）：

1. 假模型服务关着启动：进接收中，`CatalogError` 非空；有缓存时模型能力取自缓存（窗口数和缓存一致）。
2. 启动后把假服务打开：退避时间内 `CatalogError` 清空、目录换成新的，不用重启（测试里用可注入的时钟或事件，不用真等）。
3. 列模型超时、超大响应、返回非 JSON：各报对的错，不卡住启动。
4. 缓存的来源地址和现在配置的不一样：不用。
5. 目录好的、绑定角色的模型不在列表：照常进接收中，自检报一次；发消息时报“不在模型列表”。
6. 目录取不到时发消息：报“模型来源连不上”，不报“模型不存在”。
7. 界面那一行：用 `ui.NewTester` 测出现、点“去设置”、恢复后消失。

## 八、禁止的偷懒写法

- 在代码里写死某个服务商的地址、key、模型名；预设里带模型名（ADR-098）。
- 把 Magpie 的专属字段（`magpie_label`、`x-magpie-*`、`magpie-sumika`）塞进通用结构、或者干脆删掉；它们归 Magpie 预设的"方言"。
- 让目录读不到就整体不可用，或者读不到时拿别的服务商、别的模型顶替；`defaultProvider` 只用于**裸引用的解析**，不是"失败兜底"。
- 引用解析用"取名字相同的第一个"（几个服务商有同名模型时会悄悄选错）；一律按带服务商的引用查。
- 冷却表、trace、用量里只记模型 ID 不记服务商。
- 为了让测试绿，把 `kind` 不认识的服务商改成 `openai-compatible`；把读不懂的字段删掉再保存。
- 在设置页一键"清空"服务商引用；保存时静默改写别的用途的值。
- 日志、错误信息、trace 里带 key、`Authorization`、完整请求头；把服务商错误体原样展示。
- 为直连某一家改 `llm` 请求体的默认值，让 Magpie 的行为也变了；所有新开关默认只对通用服务商生效，Magpie 预设保持现有请求逐字节一致。
- 设置工具开放 `providers.*`；让角色能带自己的 key。
- 用 `time.Sleep` 等目录刷新（用事件同步，LESSONS）；测试里读真实 `data/` 或打真实服务商。
- 内置一份"常见模型能力表"当事实来源。

## 九、已知的坑

1. **Magpie 的模型 ID 带斜杠**（`group/auto-…`）——裸引用和规范引用会撞，见拍板问题 1；引用解析必须有"首段是不是已声明服务商"的判断和保存时的冲突检查。
2. `/models` 各家返回不一样：有的只给 `id`；有的混着嵌入、图像、语音模型（不报 `modalities` 就分不出来）——不隐藏，用户自己选，能识别就标种类。
3. 地址带不带 `/v1`、末尾斜杠：测试时发现"加 `/v1` 才能读到"要**提示**，别自动改（Hermes 为此出过 #65488，它的做法是把实际能用的地址存下来；Sumika 先提示、由用户点）。
4. 缓存和地址绑定：地址变了缓存就是别家的，必须丢弃。
5. `reasoning_effort` 发给不支持思考的模型会 400 → 档位未知就不发；`stream_options`、`prompt_cache_key`、`store`、`developer` 角色同理——这就是兼容开关存在的原因。
6. 本机小模型的上下文：未报告时按 128000 算会让压缩触发得太晚；Ollama 默认 `num_ctx` 只有 2048（Hermes 样例配置注释里写的），不是服务商报告的值——"未报告"必须醒目，手填入口放在模型行上。
7. 同名模型在两家服务商：冷却、trace、用量、"不在列表"判定、选择弹窗的选中项都要按引用，不按名字。
8. 保存引用指向已删除/已停用的服务商：保留值、标状态、请求时明确报错；备选链里遇到这种项按"不可用"跳过并计入全链失败的说明。
9. 配置并发：设置页保存和手改 `sumika.yml` 同时发生，沿用现有的版本冲突（`ErrConfigVersion`）；`providers:` 整节作为一个修改单元带版本。
10. 密钥库锁着时 `${secret:…}` 取不出来：页面显示"密钥未解锁"，不是"认证失败"；启动不能因此崩，只是该服务商不可用。
11. `embed` 包复用 `llm.Source`；给 `Source` 加字段要保证它们的构造仍可编译、行为不变。
12. 老脚本和检查入口写死了 `http://127.0.0.1:3425/v1`（审计第 19 条列过 Bun 时代的脚本，我没查它们现在在哪；Go 侧 `cmd/` 下 `e2e-run`、`bench-*`、`soak`、`stress`、`guard-eval`、`memory-shadow`、`turn-check` 等的源码里提到 Magpie，是否都写死了地址我没逐个核实）——不在第一步改，但要列进影响清单，否则 `magpie.baseUrl` 无法真正退役。
13. 测试用的假网关（`llmtest`、`cmd/e2e-run/gateway.go`）按单一来源写；多服务商的测试要新增"两个假服务商"的装置，不要在原装置上塞分支。
14. 把 `ModelRuntime.CatalogError` 改成按服务商的状态表，会影响 `models.go` 里"模型列表为空，请刷新模型列表"这类文案和 `ModelsEditable` 的判定；"一家为空"和"全部为空"要分开处理。

## 十、验收标准

全部用临时数据目录和假 HTTP 服务（不依赖真实网关、不读真实 `data/`、不打真实模型）。

1. **兼容**：只有 `magpie.baseUrl`、没有 `providers:` 的旧配置，启动后所有用途的行为和请求体、请求头与改动前逐字节一致（用现有录像回归基线）。
2. **引用**：规范引用、对象引用、裸引用（归 `defaultProvider`）、首段恰是服务商 ID 的裸引用、含多个斜杠的模型 ID、指向不存在或已停用服务商的引用——解析结果和错误都有测试；保存会造成歧义的新服务商 ID 被拒绝并列出冲突。要扫的引用字段全集：`characters.<id>.model`、`background`、`topic`、`fallbackModels`，`defaults.backgroundModel`、`defaults.fallbackModels`，`agent.advisor.model`、`agent.verify.model`，`subagents.model`，`vision.model`，新增的 `agent.context.compactModel`。
3. **多服务商目录**：两个假服务商，一个正常、一个超时：正常的照常可用，另一个标"连不上"；启动不被阻塞；超时那家有缓存时缓存可用、无缓存时引用它的用途标红。
4. **发现的每种返回**：200 正常、200 读不懂、404 / 405（落到手填）、401 / 403、5xx、限流、返回 HTML、超大响应、慢响应、取消。
5. **缓存**：写入原子；`baseUrl` 变了就丢弃；不含 key；坏文件被忽略并重建，不崩。
6. **能力优先级**：手填逐字段盖过发现；未报告的字段在界面和运行时都按"未报告"处理；识图用途选不能看图的模型被拒绝；备选链里不能看图的模型遇到带图请求被跳过且不丢图（对接故障切换规格第 7 条）。
7. **备选链跨服务商**：同名模型在两家，冷却互不影响；全链失败列出所有尝试，服务商 ID 都在。
8. **密钥**：引用格式与 `web.keyRef` 共用一个解析函数；锁着、缺失、空值、损坏各报各的；key 不出现在日志、错误、trace、返回给界面的任何字段（用带"毒值"的假 key 全局搜一遍）；跨主机重定向不带 `Authorization`。
9. **测试按钮**：第六节表里的每一行都有一个用例；404 on `/models` 不报红；"少了 `/v1`"的提示不改配置。
10. **设置页**：用 `ui.NewTester` 验证布局和状态；选模型弹窗按服务商分组、搜索、置灰、状态角标；备选链编辑器保留未知字段；删除被引用的服务商被拒绝。按[设计自查](设计自查.md)验收，十个角色、上万条消息的场景不卡（ADR-056）。
11. **设置工具**：`providers.*` 不在白名单；选模型只能选目录里存在的。
12. **迁移回退**：写入 `providers:` 前有备份；删掉两节后行为回到合成状态；旧 exe 读含 `providers:` 的配置不报错（用旧版本配置解析函数的测试钉住"忽略未知键"）。
13. **形状 × 入口**（高风险改动，AGENTS 第 7 条）：

| 输入形状 | 读配置 | 设置页写 | 设置工具 | 目录发现 | 请求发出 |
|---|---|---|---|---|---|
| 空串、缺失、null | 要测：空引用 = 没选；缺服务商 = 合成 magpie | 要测：拒绝 | 不可能：只能选已有项 | 不适用 | 要测：没选就不发，说明去哪选 |
| 0、负数（超时、上限、上下文） | 要测：拒绝并指出键 | 要测 | 不可能 | 要测：服务商报告 0 当未报告 | 要测 |
