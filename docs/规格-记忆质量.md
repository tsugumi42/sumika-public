## 目标与范围

先按保存价值筛选，保留稳定偏好、近期有用状态、重要关系和经历；允许什么也不写。记忆仍使用现有表、角色与共用池。第一轮不实现自动整理旧库、独立复查队列、语义写入去重或调整召回预算，不启动真实服务、不改 data 或角色卡。

## 写入契约

- 整理提示词先判断用途、对象、来源、重复和寿命；不确定是否值得记则留聊天历史，不把 candidate 当杂物箱。模型语义判断必须单独评测，字段合法不代表值得保存。
- episode_record 只有字符串 yes 才保存经历；缺失、布尔、未知值不存，仍处理合法事实动作。
- remember 仅在主人本地私聊及 QQ 私聊可用；本地群、QQ 群及他人私聊继续拒绝。
- remember 必须关联看见的、未撤回、已发出的主人消息，模型需提供 source_quote（原话中的连续片段）。程序核对引用确实存在；失败不写。引用只能证明来源，不能证明提炼忠实，模型不因引用得到主人确认身份。
- remember 新条目标 ai；重复不升为 owner，不复活撤销条目；替换只能动 ai 的同主体有效事实，主人确认和历史导入条目受保护。候选可由有来源的 remember 提为 ai，不得升级成 owner。受保护的改错需日后接具体条目的主人确认动作，本轮返回明确未修改。
- 两个入口支持 temporal=stable/temporary、valid_until=带时区 RFC3339。后台旧的 now/plan/past/stopped 归一为 temporary，不得绕过过期；新提示词只生成 stable/temporary。valid_until 必须是未来时间且仅配 temporary；临时无精确日期默认七天停止当现状召回。到期不代表完成、不删除；复查时间与有效期分离的完整流程留后续。
- 缺少 temporal 的旧调用按 temporary 保守处理，防止旧会话参数使临时内容永久化；声明要求新调用显式给出 temporal。事实期限使用既有 valid_to 列，不增加表。已有库不改。

## 边界与验收

| 输入 | remember | 后台整理 |
|---|---|---|
| 无来源、冒充主人、已撤回、来源不匹配 | 拒写 | 沿用素材与身份规则 |
| 本地私聊 / QQ 主人私聊 | 按原授权，有来源才写 ai | 按原 places |
| 本地群 / QQ 群 / 他人私聊 | 拒写 | 按原 places |
| 字段缺、空、坏日期、过去时间 | 不提升权限；坏期限拒写 | 坏期限丢该条，合法邻居继续 |
| 有效 ai / owner / 导入 / 撤销 / 候选同文 | ai 不变 owner；保护 owner/导入/撤销 | 沿用保护 |
| 重启、共用池、到期 | 期限落盘且召回停止 | 同上 |

验证使用临时库；关键身份路径旧实现必须失败，并做一次拆保护的改坏检查。提示词采用隔离的真实样本小规模新旧对比，不把合成样本称为真实样本；不足正负各二十条不宣称完整质量验收。三轮同方向才说改善。未通过真实效果验收不得合主线或上线。

同文期限更新只接受更晚的本人来源，且不得改主人确认/导入条目；记修订，不把到期判为完成。共用池已撤销的主人事实不能通过 only_her 改成专属副本复活。

## 第二轮：来源绑定与相关旧记忆（2026-11-08）

状态：已在同一分支实现，第二轮相关6包短测及全模块vet通过；未合并主线、未部署。

依据：主人在流转分析和优先顺序后回复“好 继续”，按 ADR-314 的来源证据与相关旧记忆方向继续；本轮不改变写入授权、共享/披露范围，不迁移真实数据或开后台整理。

最小计划：先把本轮接纳的事件序号从内核传到工具，再让整理上下文优先选择相关事实；沿用现有 EventSource、全文/向量检索和每类条数上限。验证连续输入、插话送达前后、跨会话/角色隔离，以及旧相关事实超出最近窗口仍能进入上下文；测试只用临时库。

来源契约：
- ToolCall.InputSeqs 是内核绑定的只读副本，来自本轮输入及模型请求前已经送达的插话；排队但未送达的消息、角色回复、上一轮来源均不加入。每次模型请求冻结一次，工具参数不能伪造这份清单。
- remember 的 source_quote 只能匹配清单中同会话、已观察、可信主人、未撤回、非补录/自检且已发送的事件。没有清单拒写，不退回 LastSaid。读取源报错拒写；不符合身份/观察条件的条目不作为来源，清单中仍可使用其他合法匹配；多条不同正文均匹配同一短引文时拒绝歧义，要求更完整引用。
- 同文重复消息可选序号最新的一条；序号仅在既定会话所属平台库内比较。来源清单不授予权限，四种场合仍走原入口检查。

整理上下文：
- 复用现有全文与向量排序，内部整理模式不做前台门控、不重排、不回查每个候选的原话标签，不产生新的生成模型调用。
- 查询仅用本批已通过素材筛选的人类消息，最多1200码点（超长保留前后各约600）；向量查询单独有短超时，失败使用全文结果。角色自述不决定检索主题。
- 相关事实优先，剩余名额按原最近顺序补足，仍限制有效事实40条、候选20条；一条只出现一次。只取本角色及既有共用池，隔离、状态、过期检查仍有效；不借此扩大共享或披露。
- 相关排序只决定给模型看什么，不直接合并、提升或取代。模型输出仍受已展示编号、主体、证据和事务保护约束。

| 边界 | 程序行为 |
|---|---|
| 来源缺/空/非法序号、模型自报InputSeqs | 拒写或忽略模型自报，不回退到最近消息 |
| 另一会话/角色未观察、peer冒充owner、撤回、未发送 | 不作为来源 |
| 主人连续两句，第二句尚未进入模型请求 | 本次工具只可引用第一句 |
| 已送达插话 | 下一次模型请求包含对应来源；前一次请求的工具不扩权 |
| 本地私聊/QQ主人私聊 | 依原写入开关及绑定来源写入 |
| 本地群/QQ群/他人私聊 | 依原权限拒绝remember |
| 旧相关事实超过最近40/20窗口 | 相关检索命中时优先入上下文，上限不变 |
| 向量失败/无相关结果 | 全文或最近事实退路；不影响普通前台召回路径 |

不在本轮：稳定跨设备事件ID、自动复查队列、撤销向当前上下文广播、旧库清理、索引增量改造。

## 补充：remember 写的事实怎么保护（2026-11-08）

状态：已在 codex/memory-quality 实现；未合主线。修正上文"remember 新条目标 ai"一行。

- remember 新写的事实 `confirmed_by = 'owner_said'`（来源已绑定主人本人的原话，文字是模型提炼的，不是主人放行）。不借用 `owner`：界面的"你确认过"只留给主人亲手放行的；也不留 `ai`：整理会把它当"她自己攒的"取代或撤销，主人明说"记住"的事实就失去保护。选新值而不加列：保护判断本来就读 `confirmed_by`，白名单只认 `ai`，新值默认受保护，不需要迁移，旧库不动、只影响新写入。
- 谁动得了（`write.go` 的 `protectedFrom`，取代、撤销、候选提升取代都走它）：主人本人（`ByRemember`）任何有效的；remember（`ByRememberAI`）动 `ai` 和 `owner_said`，不动 `owner`、导入的；整理只动 `ai`。整理想取代它的候选攒够证据也不提升，计 `confirm_blocked_protected`。
- remember 同文再说一遍可以刷新期限（`refreshLifetime`），整理的同文合并不行。remember 提升同文候选也标 `owner_said`。
- 校验：`ByRememberAI` 的批只收 `owner_said`，别的批不许写这个值。
- 记忆页新增状态组 `said`（"你说过、她记的"），`GroupOf` 与 `factGroupSQL` 同步；隔离线（quarantine）对 `owner_said` 和 `owner` 一样不藏。
- remember 遇到同文的 `ai` 有效事实（来源已绑定主人本人的原话）：`confirmed_by` 从 `ai` 升成 `owner_said`，记一条 confirm 修订、计 `owner_said_upgraded`，范围和期限不动；`owner`、导入的、已撤销的不碰，整理的同文合并从不升。
- 留给日后：记忆页目前只读，没有主人放行入口，接上时按这一节的标记走。
