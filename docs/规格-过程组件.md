## 一、范围和场合

- **本地私聊、本地群聊**：过程全部看得见（ADR-281 第 3 条）。
- **QQ 私聊、QQ 群**：不显示这一族组件；角色在外平台只发进度短句（普通消息），审批变成提问（ADR-281）。本规格不管外平台。
- 不在这一族：网页搜索结果卡、多 agent 总览、通知中心的审批浮卡、桌宠窗。

## 二、放在哪、怎么排（ADR-287 起：折进一个能展开的气泡）

- 她这一轮在两段回复之间的思考、读搜、命令、改文件折进**一个过程气泡**（一条带 Steps 的消息就是一个过程气泡）。它就是她的一个气泡：底色、内距、圆角、有壁纸时的投影、和前后气泡相贴的角、组内组间距、头像（组末）、群聊名字（组里第一条的顶上）全照气泡的规矩。
- **宽度按内容收窄**：收起时是摘要那一行的宽；展开后按里面最宽的一块，最多到气泡最大宽和 32 个正文字宽里较小的那个（Bun `min(100%, 32em)`），再长的折行。展开着还在进行时只变宽、不变窄（输出滚动、"正在运行"换成"运行了"时不来回跳），做完或收起后重新按内容（主人 2026-11-07："平时不需要这么宽，只在需要的时候实时根据内容变宽"）。
- **收起时只有一行**（摘要行）：左边图标格子（进行中是三个点或转圈，完成后是这一轮最主要那一类的图标，角色色）、一句摘要、右边（失败角标 / 等批准时的剩余时间 / 箭头）。
  - 进行中，摘要写现在在干什么：取最后一个没结束的步骤——"正在想""正在读 a.md""正在搜 纸灯""正在运行 go test …""正在改 a.md""想运行命令""想改 a.md"（等批准的命令摘要行只写"想运行命令"，命令原文只在下面终端块里出现一次；2026-11-15 审批卡压成一张卡，见 3.5）。展开着进行中时摘要只写"进行中"、左边放这一步的图标不转圈（下面那一行已经写着在做什么、在转，主人 2026-11-07 同意）。
  - 做完，摘要写总结，按出现过的种类用"·"连起来："想了 3 秒 · 读了 2 个文件、搜了 1 次 · 运行了 1 条命令 · 改了 1 个文件"；只有一样时就是那一样。有失败的挂失败角标，不写字；展开后摘要行不再挂，只挂在失败的那一行上（主人 2026-11-07："那俩感叹号只留一个"）。
- **展开后**：摘要行下面隔 pv 是原来的各段（思考行、读搜行、命令块、改文件块），段间隔 s1；命令和改文件不再是独立的卡片，是气泡里的凹块（底色同引用块，离气泡边 pv，圆角同心）。
- **默认收起**；有等批准的步骤时**自动展开、点了也不收**（审批不能藏）；设置"进行中展开过程"开着时（默认关），这一轮还在进行就整段展开（想、读、命令、改文件都看得到），做完自动收成一行；进行中手动收起的单独记，做完以后不再自己展开（ADR-288，照 Alma 桌面版；原来的"想的时候展开思考"已被 ADR-288 改为这一条）。
- 等批准时剩余时间挂在摘要行右边（时钟图标 FS2 + "4:32"），审批块里只留谁引起的、原因和按钮。正式字体的数字不等宽（Tabular 不起作用），数字按最宽的数字留死宽（`chatui.DigitSlotWidth`），每秒逐位滚、从上面落下（规格-过渡动画第十一节，2026-11-15）。
- 展开收起：高度用“利落”弹簧、内容淡入淡出；箭头旋转用“灵敏”弹簧（2026-11-15，规格-过渡动画第十一节；列表贴底跟着新消息时高度硬切只淡入，铁律 4）。
- 进场：照气泡的 `Host.Appear`。

## 三、组件和状态

数值都是默认外观下的值，全部从令牌推出、随外观缩放；"FS2"等指 chatui 的字号档。

### 3.1 读搜行（读文件、搜索，相邻的折成一行）

| 状态 | 长相 | 出处 |
|---|---|---|
| 运行中 | 一行：转圈（字号的 1 倍，Text3）+ "正在读 2 个文件、搜 1 次"（FS2，Text2）；只有一种时只写那一种 | Lorca agents.go:552-557；Bun 工具用转圈 |
| 完成 | "读了 3 个文件、搜了 2 次" + 右侧折叠箭头（收起 0°、展开 90°）；不画勾，不写"完成" | Lorca agents.go:540-555；Codex 界面.md:528 |
| 展开 | 每一步一行，缩进一个 s3：读 → "读了 `路径`"，搜 → "搜了 `关键词`"；路径、关键词用等宽字（FS1）；子行不能再展开 | Lorca agents.go:728-736 |
| 某一步失败 | 合并行末尾和那一子行末尾各一个危险色角标（和气泡失败角标同一个图形、同一个大小）；整行不染红 | 主人"失败只用角标"；不照 Lorca agents.go:601-603 |
| 某一步被拒绝 | 子行写"不允许：`路径`"，合并行末尾一个角标 | Lorca agents.go:566-567 |

- 合并规则：只合并**相邻**的读和搜，中间夹了别的步骤（命令、改文件、思考）就断开另起一行（Lorca agents.go:511-525）。
- 行本身：最小高 = 控件高小档（28 × 字号比例），左右内距 s2，圆角 r-ctl；悬停、按下用叠色（Hover、Press）；可以点、Enter、Space 展开（只有有子步骤时才是按钮）。
- 读搜行没有卡片外壳，直接放在消息列里（照 Lorca 和 Codex 的"一行"）。

### 3.2 思考行

| 状态 | 长相 | 出处 |
|---|---|---|
| 进行中 | 一行："正在想" + 三个上下浮动的点（和"正在输入"同一套点和节奏）；展不展开看设置"进行中展开过程"（默认关，ADR-286，已被 ADR-288 扩大到整段过程）：关着只显示这一行，开着正文边想边出现在下面 | Bun Thread.tsx:~218、chat.css:231-235；Lorca 本地聊天也只显示短语 |
| 完成 | "想了 N 秒"（N 用等宽数字，最少 1）+ 折叠箭头；没有秒数时写"想了一下" | Lorca agents.go:752-761；Bun"想了一下" |
| 展开 | 思考正文：FS2，行高 1.45，Text2，左缩进 s3；最高约 20 行，超出在里面滚动 | Lorca agents.go:752-761；Bun chat.css:182-184（20lh） |

- 行的尺寸、悬停、键盘同读搜行。
- 思考和工具不混用指示：思考用三个点，工具用转圈（Bun display.tsx:184-190）。过程气泡的摘要行收起时照这条；展开着进行中摘要行不动、只放图标，在动的是下面那一行（见第二节）。

### 3.4 改文件卡（写入、改文件）

> ADR-287 起：同 3.3，是过程气泡里的一块凹块。

外壳同命令卡（ADR-281 定"写入是卡片"；Lorca 只有一行，不照）。

| 部分 / 状态 | 长相 | 出处 |
|---|---|---|
| 头部 | 笔的图标 + "正在改" / "改了" / "新建了" / "删了" + 路径（等宽 FS1，中间截断）+ 行末"+A"（成功色）"−B"（危险色），等宽数字、字重 500 | Lorca agents.go:615-622；Codex 界面.md:544、550 |
| 正文（展开时） | 统一 diff：每行等宽 FS1、行高 1.6；加的行文字成功色、减的行危险色，行底各叠一层同色 15%（深色 23%）；最多显示 16 行，超出在块里滚动 | Codex 界面.md:565；Bun chat.tsx:843-850 |
| 展开规则 | 等批准时默认展开（预览就是 diff）；完成后收起 | Codex 审批里的 diff；Bun 审批框预览 |

### 3.5 审批块（挂在命令卡、改文件卡里面）

> ADR-287 起：剩余时间挪到过程气泡的摘要行右边；审批块里只留谁引起的、原因、按钮，内容都从块的内距起（主人 2026-11-06 截图：原因前空一块、时钟离左边近离底边远）。
>
> **2026-11-15 起（主人定“我觉得都可以整”，ADR-393 修正 ADR-287 的单步画法，2026-11-18 随设计硬化合 main）**：只有一步在等批准时，过程气泡压成**一张卡**——摘要行（图标、"想运行命令"或"想改 路径"、右边倒计时）、命令的终端块或改文件的 diff 凹块、理由、靠右的按钮；不再画步骤头，图标和命令各只出现一次。审批容器本身**没有底色和内距**（不是凹块），按钮直接在气泡上，是单行控件的胶囊。下表“位置”“已决定”两行已按此改；多步时照旧。

| 自动放行 | 只剩一行：闪电图标（角色色）+ "自动放行：理由"，没有凹块 | Bun chat.tsx:818 |

- 键盘照 规格-交互原型（私有存档） 3.5：快捷键只在卡片或卡内按钮拿到键盘焦点、可操作、顶层没有别的弹层时有效；Enter 允许一次、Esc 拒绝；新审批**不**自动拿焦点；再加 Bun 的两道门：出现后 500ms 内不认 Enter，输入法选字后 100ms 内不认 Enter（Bun keys.ts）；按住重复、带修饰键的不认；多单时只作用于拿着焦点的那一单。
- 不画键帽（Codex 在按钮里画 Enter / Escape 键帽）：通用快捷键不写提示（主人 11-06）。

### 3.6 停止和中断

- 回复被停下、或一轮被打断：她的气泡朝聊天中间那一侧（右边）贴底一个停止图标（和自己消息的失败角标镜像、同一个大小，Text3；左边是头像，放不进），不写"被打断了"（Bun 写字，不照）。已出的正文保留。
- 工具被停：见命令卡"停了"。

### 3.7 流式出字（第二步）

- 回复正文改用 mygo 的 `markdown.Stream`：`Reveal{Unit: ByWord}`（中文按字出现，reveal.go:31-33）、`Fade` 130ms（Bun fade 档）、`CatchUp` 用默认 250ms；没有光标（Codex、Bun、Lorca 都没有）。
- 减少动态效果：mygo 只关淡入、不改节奏（reveal.go:228），这里另把这一条的 `Reveal.Unit` 设成 `AtOnce`。
- 停止：把这一条的 Reveal 改成 `AtOnce`，已到的字立刻出完。`Options` 每条消息各一份，不共享（reveal.go:85 的坑）。
- 时间：出字的时候不显示，字全部出完才显示（ADR-286）。出完后最后一块是普通段落时，按同一字体、宽度量出最后一行宽，照 Telegram 挂在最后一行末尾；最后一块是代码块、列表、表格等时另起一行靠右。
  - 实际做法（2026-11-07 起）：mygo 0.8.0 加了 `markdown.Revealed`（我们开的 egoist/mygo#1380），构建正文以后问它这一帧的字出完、淡入完没有，是才画时间；出字和淡入时它自己每帧要下一帧，变成 true 那一帧时间就出来，不用估、也不用自己排帧。实测一次送完 20 / 200 / 2000 个汉字，全文出来后 0.13～0.14 秒（淡入）出现时间；慢慢送的完成后 0.1 秒。被停下的、减少动态效果时直接显示；历史消息整段直接出，当帧就有时间。（11-06 到 11-07 之间是按积下的字数估等多久的临时做法 `holdFor`，已删。）
- 思考正文、工具输出不交给 markdown；模型输出里的 `<think>` 一类标签在喂给 Stream 前剥掉。
- 代码块用 `CodeBlock` 钩子：圆角按同心规则算（不照 mygo 的 Radius+2），等宽字 Maple Mono（Bun）。
  - 实际做法（2026-11-06）：外框自己画（底色同卡片里的凹块、四边内距一样、不画边），上面一行左边语言、右边只有图标的复制按钮（点了两秒内换成对勾）；代码和高亮用 mygo 的 `Body`，把它的内距 `CodeBlockPadding` 设成和上边写死的 0.25em 一样，四边才等距。长行折行（`WrapCode`），不横向滚动：几何检查已批的滚动例外只管竖向（ADR-285 第 11 条），要横向滚动得先请主人把例外扩到横向。
- 正文和几何（2026-11-06）：她的回复一律走 markdown（Host.MD 由宿主持有，每条消息一份 `Options`，按消息 ID 隔开）；自己发的、撤回的照旧是纯文字。几何仍由 chatui 量：段落用 `ui.ShapeRichText` 按真实字形（粗体、斜体、行内代码）量每行宽，和原来的纯文字量法同一套，纯文字消息的数字逐项相等；有列表、代码块等别的块时宽度铺满、高度按源码行数估（只影响圆角里 min(r-1, 高/4)）。主题全从令牌推：行高 1.6（mygo 默认 1.5）、段距一个正文字号（默认 0.75em）。喂给 markdown 前剥 `<think>` 段（写到一半的开标签先藏）、段内单个换行补成硬换行（mygo 把它当空格），两步都对追加前缀稳定。不用 `Options.Block` 接管段落（会丢逐字淡入），不用上一帧的 Bounds 算排版。
- 放大十倍（2026-11-06）：一万条历史、三分之一带列表和行内代码，打开一帧 26ms，滚到顶再滚回最慢一帧 35ms；只给看得见的消息建 markdown 状态（48 条）。

### 3.8 自动召回行（主人 2026-11-09，`feat/recall-step`）

主人要看每轮记忆召回得准不准，又觉得"自动召回"不是工具调用。定下：**自动召回单独一种过程行，不是工具**；模型主动调 `memory_search` 这类仍是工具卡（读搜族，展开看返回）。

- **出处**：只显示这一轮真正注入给模型的那份。记忆插件（`memplugin.context`）从同一次召回里把结构化结果放进 `Contribution.Recall`，内核在接纳（`acceptContext`）以后只收真注入了字的贡献，不解析拼好的文字，也不另算一遍。过滤掉的（门控、已给过、超预算）本来就没进 `Hits`，界面一律不显示（理由：看相关度看的是"给了什么"，被筛掉的另有召回日志）。
- **长相**：摘要里写"召回 N 条记忆"（书签图标，工具是扳手），不算进"调用了 X"的数；展开一行"召回了 N 条记忆"，点开每条一块凹块：正文（超过 120 字先折，点"展开全文"）、一行小字"类型 · 待确认 · 记录时间 · 来源 · 重排 · 向量 · 词法 · 综合"。分数只写真有的：没配重排就没有"重排"，向量没中就没有"向量"，固定要点不是按这句话召回的，没有分数（占位的 1 不显示）。按注入的顺序（固定要点在前）。整块最高 16 行，再多在里面滚。没有召回、或召回为空，这一行不出现。命中带着被它取代的旧版本时（注入的那一行后面拼着“取代了旧记录：[时间] 旧文字”），正文下面多一行小字“取代了：时间 旧文字；……”，旧的和注入的是同一份（`Hit.Previous`，新的在前，最多 3 条），模型读到的旧值能在这里核对；固定要点不带。
- **存哪**：不新增表、不迁移。trace 的 `steps` 表里一行 `kind='recall'`、`name='memory'`，`args_json` 放明细 JSON（字段同 `turn.RecallItem`），和思考、工具步骤一样在回复落盘时 `AttachSteps` 挂到回复上；刷新、重启后 `desktopread.processOf` 读回，不多一次读盘（和思考、工具同一次 `ReadSteps`，界面线程不读盘）。旧消息没有这一行就不显示；存坏了（不是 JSON、空数组）这一行不显示、别的步骤照常。右栏关着时不读 trace：这条数据只走过程气泡，不经右栏。
- **插话**：插话送到时内核会再拼一次参考信息，这一次的召回另记一行，排在下一步之前。
- **场合**：本地私聊、本地群聊都有（`Input.local()`，同一条路径）；QQ 私聊、QQ 群没有过程组件（ADR-281），回合没有 `onProcess` 也不 `local()`，召回明细不存不发，不适用。记忆内容只在本机界面和本机 trace 库里，不进日志（写库失败的日志不带内容）、不进模型上下文以外的外发路径。

## 四、禁止的偷懒写法

- 用字表示完成、失败（"完成""失败""成功"）；整行染红；在按钮上画快捷键键帽。
- 审批的 Enter / Esc 挂成全局快捷键（焦点不在卡上也生效）；新审批自动抢焦点。
- 自己写一套逐字淡入（用 `markdown.Stream`）；多条消息共用一份 markdown `Options`。
- 组件里写死颜色、间距、圆角、字号（全部从令牌推、随外观缩放）；成功色、危险色不核对比度。
- 读搜行把不相邻的读搜合并；把等批准的卡展开成"已执行结果"。
- 照抄 Lorca 的代码（GPL-3.0，只借机制和数值）。

## 五、已知的坑

- mygo 的 `ui.List` 不触发行的 Transition 进场，过程项要用 `Host.Appear` 那套（2026-11-06 实测）。
- 浮层里新出现的元素 mygo 也不播进场（父元素上一帧要在），审批浮卡以后做时注意。
- `markdown.Stream` 没有提前测高度；停止后已到的字会继续淡入出完；`Options` 是共享值。
- 系统要求减少动态效果时，mygo 的 Transition、Spring 自己不位移；但 markdown 的出字节奏不变，要自己切 `AtOnce`。
- 输出块贴底跟随：新输出到达时只滚块内，不能带着外面的聊天列表跳（交互原型 3.4"不抢外部历史锚点"）。
- Lorca 的本地私聊其实隐藏读搜和普通命令，"折成一行"是它协作代理页的做法；ADR-281 定的是本地看得见，照 ADR。

## 六、验收

0. ADR-287：过程气泡收起时只有摘要一行、宽度按内容；进行中 / 做完的摘要文案；有等批准的步骤时自动展开且点了不收；和前后气泡相贴、群聊名字在顶上；三档外观几何检查覆盖收起和展开。

1. chatui 每个组件每个状态一条 Tester 测试：几何（四边等距、同心、和气泡左对齐）、文案（进行时 / 过去时）、只用角标不写字、等宽数字；三档外观（默认、最小、最大）各跑一遍。
2. 对比度：成功色、危险色作文字对卡片底 ≥ 4.5、作图标 ≥ 3；输出块、diff 行底上的字 ≥ 4.5；按像素量。
3. 审批键盘：焦点在卡上 Enter 批准、Esc 拒绝；焦点在输入框、菜单、对话框里不认；出现后 500ms 内的 Enter 不认；新审批不抢焦点；每条都有"把门去掉会红"的改坏检查。（原来还有一条"输入法选字后 100ms 内的 Enter 不认"，那是 Bun 把 Enter 挂成全局键时的门；这里 Enter 只在焦点在审批块里时生效，选字时焦点在输入框，按键到不了审批块，由"焦点在输入框里不认"那一例测住，2026-11-06。）
4. 合并规则：读、读、搜 → 一行；读、命令、读 → 三项；每种顺序一条测试。
5. 工作台：假后端补齐 A01～A05、A08、P01、P04 的脚本（思考、工具成功 / 失败 / 很慢 / 取消、停止、审批、过期），几何检查和外观三档覆盖到所有新组件；浅深截图给主人看。
6. 第二步（流式）另测：中文按字出现、Fade 130ms、减少动态效果直接出完、停止立刻出完、`<think>` 不显示；出字中没有时间、出完才有，最后一块是段落时挂在行末、是代码块时另起一行。
7. "进行中展开过程"开、关两种都测（ADR-286、288）：开着时进行中整段展开、思考正文边想边出现，做完自动收起；进行中手动收起的做完以后仍收着、再点能展开；关着时进行中也只有摘要一行。
8. 自动召回行（3.8）：有召回、无召回、召回为空、重启后（trace 读回）、旧消息、存坏了各一条；模型收到的参考行和界面的明细是同一份（`turn.TestRecallStepLocalShowsInjected`）；分数只写真有的；摘要不把召回算进工具数；浅、深色截图各一张。
