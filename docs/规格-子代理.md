## 一、做什么、不做什么

做：

1. 前台用 `task` 派一个独立上下文的孩子。创建立即返回任务号；孩子完成后，结果回到原前台的原权限档。
2. 同一个 `Hub` 承载父子实例。复用模型循环、工具门、审批、取消、用量记录和压缩算法；内部任务另接上下文序列与快照存取，不依赖聊天事件。
3. 内置代理类型、用户代理定义、任务取消、受控结果读取。
4. 按原派活人的身份和渠道，推导后台能力。QQ 前台可以没有搜索工具，而有权派只会搜索的后台。
5. 持久化任务、结局、结果邮箱。进程重启后有明确结局，不重跑副作用。
6. 本地任务详情和审批显示派活来源。QQ 只收到经过渠道发送检查的前台回答。

不做：

- 代理团队自由聊天、共享可写黑板、任意代理互相发消息。
- 复制父对话全文、自动 fork 父上下文。
- 独立 CLI 子进程、远程代理和第三方代理运行时。
- 模型任意指定模型、工作目录、工具清单、权限或结果目的地。
- 自动重试整个失败任务、自动恢复被杀的任务。
- QQ 本地执行特例。ADR-081 允许以后专门打开；本版保持关闭。
- 子代理直接发 QQ 消息、写公开聊天、作为主人发言。
- Bun 后台或网页的新功能。新增实现只进 Go 和 mygo，照 ADR-203；ADR-180 的冻结状态已被其取代。

继续孩子本次不设入口。需要补充任务时，前台带必要材料新派一个孩子；旧任务号和旧结果仍可查。避免同时引入会话续接、权限更新和在途消息三套状态。

## 二、技术路线

### 2.1 包和边界

| 位置 | 管什么 |
|---|---|
| `native/internal/subagent`，新增 | 代理定义、任务管理、容量、预算、任务工具、结果邮箱 |
| `native/internal/turn`，扩展 | 独立内部运行入口、中立执行身份、工具调用 ID、执行退出追踪、内部上下文存取、指定权限档的结果注入；复用已有循环 |
| `native/internal/policy`，扩展 | 委派权限判定；登记任务工具；每次执行复核能力 |
| `native/internal/approval`，扩展 | 审批来源字段、可信访问域检查、任务取消与卡片联动 |
| `native/internal/store`，扩展 | 共用运行记录中的任务、内部上下文与快照、结果、邮箱、预算和用量完整性记录 |
| 渠道中间件 | 计算原派活人、听众和 Scope；收到结果后调度前台；裁决、守卫、发送 |
| mygo 的现有任务与审批区域 | 任务详情、来源、用量、取消和审批显示；携带宿主签发的访问域 |

子代理作为编译进程序的 `turn.Plugin`，通过 `Registry.OnTool` 注册工具。不开运行时插件加载口。已有接口见 `native/internal/turn/plugin.go:32、:87`，规格-Go后台 8.1。

复用搜索规格 2.3 的中立执行身份契约，不另建一份子代理专用的身份解释。可信记录至少包含：

- 原始 `ActorKind / ActorID`。
- 原渠道、平台账号、原始会话及群归属。
- 角色、Scope、权限代次。
- 当前任务、父任务、根任务和根会话归属。
- 直接调用或可信委托、委派能力上限。
- 服务端签发的授权句柄、授权配置代数及有效期。

身份由渠道层和内核建立，授权句柄由服务端签发。不能从模型参数、显示名、会话字符串或任意 `context.Value` 字符串补推；缺少必要身份或句柄时拒绝。

该契约必须贯穿 `Respond/Input`、内部运行描述、工具清单构建、执行前 policy 和审批检查、`OnTool` 回调及搜索等服务调用；同时覆盖 `Steer/SteerIn`、插话队列和未送达插话退回普通输入的路径。不同发起人、权限档或委托归属的插话转独立回合，不能沿用原任务授权。相同归属的插话不能重置预算、延长授权或恢复撤销的能力。

`ToolCall` 另增加内核提供的 `ToolCallID`。`loop.go` 从模型响应解析得到的调用记录 `Call.ID` 贯穿 `runTools`、审批和插件回调；插件不能从参数里接收替代 ID。当前 `ToolCall` 只有角色、会话、回合、听众和参数，`runTools` 构造回调时也未传调用 ID，必须一起修改。出处：`native/internal/turn/plugin.go:97`、`native/internal/turn/loop.go:574`。

工具来源按共同描述接入：

```go
type ToolOrigin struct {
    Kind string // builtin、mcp；后续来源沿用同一契约
    ID   string // 稳定来源号，不是显示名
}
```

工具来源还须提供稳定工具 ID、风险声明、适用渠道、授权版本和撤销状态。代理定义引用这些描述，不直接引用 MCP manager、搜索 provider 或它们的实现包。搜索工具来自哪个包，不影响委派算法。

skill 是上下文来源，不冒充工具来源。skill 中要求执行什么，仍由实际调用的工具逐次检查。

MCP、搜索两份规格同时起草时，需对齐上述字段、执行身份和撤销语义；字段名可统一调整，不能用空实现或全放行补齐接口。

### 2.2 复用一个 Hub

**进程内只建一个 `Hub`。**

`NewHub` 会调用 `SweepInterrupted`；给每个孩子另建 Hub，会把本进程在跑的记录当成遗留任务。现有约束见 `native/internal/turn/hub.go:159`，子代理调研 9.1。

孩子使用独立内部会话号。不能沿用父 Conversation、只换 Scope：现有回合队列按角色和会话串行，父等孩子时会互相卡住。出处：`hub.go:211、:257`，调研 9.1。

新增内部入口，名称暂定：

```go
StartChild(ctx context.Context, spec ChildSpec) (ChildHandle, error)
CancelTaskTree(taskID string) error
```

`ChildSpec` 由可信管理器构造，模型不能直接提交：

- TaskID、ParentTaskID、RootTaskID。
- 原角色、父回合、内核提供的父工具调用 ID、来源事件和根会话归属。
- 代理定义和模型的快照。
- 原派活人、渠道、账号、会话、委派能力上限、授权句柄及授权版本。
- ReturnAudience、ReturnScope、权限代次。
- 任务文本、已核验材料、允许的上下文来源集合、深度、截止时间和预算。

这些字段从 2.1 的可信调用记录取得，不能仅在 `ChildSpec` 中列出字段、再让 `task` 插件自行猜值。

内部会话登记为内部用途，任务内容进入共用运行记录，不进入本地或 QQ 聊天事件库。不能按会话字符串猜存储归属，也不能把内部会话登记成普通 QQ 会话。

内部任务的上下文序列、切点和快照存取按 6.1 接入 `subagent_context` 及独立快照。复用压缩算法和模型调用流程，不直接调用依赖聊天 Events 的存取路径。

新增明确的运行种类，区分前台和孩子。现有 `Input.local()` 只看 `Channel=="console"`，不能靠伪造 console 让孩子取得权限或避开渠道流程。出处：`hub.go:153`。

孩子的中间正文、思考、工具结果不发普通 `OnSeen`，不作为角色公开说过的话供记忆整理。内部运行通知必须带运行种类，订阅者显式选择接收。

### 2.3 三个模型工具

参数严格校验，未知字段、缺字段、`null`、错误类型均报参数错误，不悄悄忽略。

```text
task({
  agent: string,
  description: string,
  prompt: string
})

task_cancel({
  task_id: string
})

task_result({
  task_id: string,
  cursor?: string
})
```

`task` 一次创建一个。内核同一步的多次调用可并行，不新增 batch、chain 两套格式。

成功受理返回：

```text
{ task_id, status: "running" }
```

主人在主窗口发起的“悄悄话”处理（[规格-群聊引用和路由](规格-群聊引用和路由.md) 7.3）不走这里的 `Manager.Start`，也不在满额时拒绝：它在 `internal/whisper` 里自己按“每个派活人 2”的额度排队（先进先出），不和这里的计数共用。

未受理返回明确错误码：`invalid_agent`、`denied`、`busy`、`quota_exceeded`、`cancelled`、`storage_error`。未完成持久化不能回 `running`。

同一父工具调用重复进入时，按可信 `TurnID + ToolCallID` 返回同一任务，不再创建。唯一约束与任务受理同事务提交；缺少任一 ID 时拒绝受理，不从模型参数或会话字符串补推。

`task_cancel` 取消目标树。只能取消属于当前可信调用域的任务；本地主人另有任务管理入口。无关任务号和不存在的任务号返回相同的不可访问结果。

`task_result` 读取状态和最终结果，不提供思考和原始工具过程。分页游标由运行时签发，不能传文件路径、URL、SQL 或任意偏移表达式。

三个工具在 policy 中正式登记。`task` 的委派检查先于受理；孩子每次工具调用仍过正常工具门。深度和委派检查必须位于受保护的管理入口，旧工具声明或直接内部调用不能绕过。不能登记成 `Effects={"self"}` 后借现有“只碰自己的记忆”分支直接放行。现有分支见 `native/internal/policy/policy.go:374`。

### 2.4 代理类型

内置三个类型，均无再次派活能力：

| 类型 | 用途 | 能力需求上限 |
|---|---|---|
| `research` | 搜公开资料、读公开网页、整理来源 | 公开检索和抓网页 |
| `reader` | 本地查文件、读代码并给结论 | 本地只读工具 |
| `worker` | 本地修改文件、执行任务 | 本地读写和命令工具，照现有审批 |

名称不是权限。QQ 调 `worker` 不能取得本地执行；交集为空时明确拒绝，不偷偷换成 `research`。

用户可以增加代理定义。暂定格式为 Markdown + YAML frontmatter：

```markdown
---
id: code-reader
description: 查代码并给出处
capabilities:
  - local.read
model: auto/deepseek-v4.1-flash
---
先核对实际文件。结论带出处。
```

约束：

- 定义放当前 Go 数据根下的 `config/agents/<id>.md`。不自动发现项目仓库中的代理文件。
- 必需 `id`、`description`、`capabilities`；`model` 可省略，省略时固定为创建那一刻的父模型。
- 本版不另设 reasoning 字段。沿用选中模型的有效配置，任务详情记录实际值。
- 正文是孩子任务说明，不包含角色私下人设。
- `id` 必须非空，只允许小写 ASCII 字母、数字和连字符，最长 64 字节。文件名和 `id` 必须一致。
- 拒绝 Windows 设备保留名：`con`、`prn`、`aux`、`nul`、`com1`～`com9`、`lpt1`～`lpt9`；添加 `.md` 扩展名不豁免。现有平台文件名已有同类防护，见 `native/internal/store/platform.go:40`。64 字节是本规格暂定的代理标识配置上限，不是 Windows 路径极限；配合固定目录限制无界文件名。
- 内置 ID 不允许覆盖；用户 ID 重复报错。
- 不接受 `cwd`、`approvalMode`、`audience`、`return_to`、环境变量、密钥和任意执行命令字段。
- `capabilities` 只能申请能力，不能授予能力。未知能力报错；空集合表示无工具。
- 用户定义默认不向 QQ 暴露。QQ 可用代理和来源白名单另由主人配置；代理文件不能自行标记 QQ 可用。

格式借 omp、OpenCode、pi；不照搬项目文件覆盖用户配置的顺序。出处：调研第 1、4、5 节。

加载时完整解析后原子替换目录快照。坏文件不执行；保留上一份好版本并在本地显示错误；首次加载失败则该定义不可用。新任务用新快照，已有任务不换提示词和模型。权限撤销不受快照保护，立即收紧。

### 2.5 上下文给多少

默认不给父历史。孩子起步只收到：

1. 固定后台运行说明。
2. 当前代理定义正文。
3. 当前任务文本。
4. 调用方有权转交、且符合本任务外发限制的显式材料。
5. 按孩子听众、能力和外发限制筛过的上下文来源、skill 目录。

不给父角色私下段落、父思考、审批预览、完整工具历史或其他权限档的参考信息。

**结果听众可见与允许向外部服务披露分开判定。** 主人能在本地私聊或 QQ 私聊看见私有材料，不等于允许把材料写进查询词发给 Tavily。搜索规格第九节的首次外发授权和限定联网授权同样适用于孩子；本规格不代替该授权。

公开检索入口按允许向外部服务披露的材料集合检查。未经明确覆盖这些材料和外发范围的授权，父当前权限档已经接触私有材料时，拒绝模型生成的自由文本委派；需要公开检索的，由渠道层用核验过、允许外发的原公开请求建立公开任务。不能把“只给必要材料”、摘要或模型自称已脱敏当作外发检查。

公开检索孩子的全部上下文来源仅允许公开材料，不自动按原听众召回私有记忆。任务文本、代理定义、显式材料、记忆、skill 和后续参考信息均受此限制；原听众仍单独约束结果回流。当前记忆插件按 `in.Audience` 召回，不能直接复用这一默认路径，必须传入并执行任务的公开来源限制；不支持该限制的来源不接入此类孩子。出处：`native/internal/memplugin/plugin.go:341`。

暂定输入上限：

| 内容 | 上限 | 依据 |
|---|---:|---|
| `description` | 120 个 Unicode 字符 | 本规格的任务卡显示预算，不是别家的默认 |
| 任务文本和显式材料合计 | 16 KiB UTF-8，且估算 token ≤ 4,000 | 调研 9.6 的有界上下文建议；起步与结果内联预算一致 |
| 单份代理定义 | 32 KiB UTF-8 | 本规格的配置读取上限，防止文件被误用成资料全文 |

超限拒绝，告诉调用方缩短或拆分；任务指令不能静默截断。固定说明、schema、来源目录也计入模型窗口检查，但不计入模型可提交的 16 KiB。

上限同时检查字节和现有模型适配层的 token 估算，估算不是实际账单。模型窗口放不下时明确报错，不改模型、不自动 fork。

参考信息只在回合开头拼一次并在末尾追加；可信插话送达时，沿规格-Go后台 8.1 再给插件一次只追加的机会。孩子完成通知先入原档邮箱，只在该档下一回合开头统一追加，不借插话机会提前注入。运行中不改系统前缀、工具 schema，不插入历史中间再撤掉。权限收紧时取消旧孩子，后续新建；不靠“以后别提”洗掉旧上下文。依据：LESSONS“只能末尾追加”、规格-Go后台 8.1。

## 三、谁能用、后台能看到什么

### 3.1 可信身份

身份按来源事件的 `ActorKind / ActorID` 认。显示名、群名片、代理名、提示词中的“主人同意了”均无授权作用。

原派活人由渠道层给出，通过 2.1 的中立执行身份贯穿内核、工具回调、审批和服务调用。不能从模型的 `prompt` 猜是谁，也不能仅凭 `PrivateOK`、`OwnerAsked` 判成主人。

混批只在可信来源能确定派活人时采用该身份。主人与群友共同触发、来源不明时，按参与者授权交集处理；取不到必要身份就拒绝本地能力。`OwnerAsked` 沿用渠道中间件第四节的收紧规则，不在子代理里重算成真。

授权句柄绑定原账号、会话、Scope、任务归属和授权代次。创建、工具执行、结果读取与投递均核对当前授权；模型不能提供或修改这些绑定。

### 3.2 四种场合

| 场合 | 主人派活 | 其他人或身份不明 | 听众和结果 |
|---|---|---|---|
| 本地私聊 | 可用三个内置类型；实际能力照现有授权和审批，联网另受搜索规格授权约束 | 不因名字或本地入口冒充主人；本地执行拒绝 | 原本地会话、原权限档 |
| 本地群聊 | 主人派活的细化启用默认值待确认；确认前不自动获得委派权，启用后实际能力仍按现有授权和材料可见集合检查 | 不继承“主人在场”的执行权；本地能力拒绝 | 原本地群聊、原权限档；不自动转私聊 |
| QQ 私聊 | 公开检索的细化启用默认值待确认；本地读写、命令全部拒绝 | 已有渠道接入许可不自动获得子代理委派权或模型、搜索额度使用权 | 原 QQ 私聊、原权限档；不继承主人的其他私聊 |
| QQ 群 | 主人和群友都可请求公开检索的方向按 ADR-081 执行；实际启用须满足外发授权、联网授权及额度配置，主人身份不使本地执行自动开放 | 只给公开搜索和读网页 | 原群、原权限档；不注入到当前正在跑的另一档 |

本地群聊现在没有入口；本规格不补入口，先用可信输入和假事件验契约。（已被 ADR-369 改为：本地群聊的执行类活只走工单，角色自己不带执行类工具；工单里每次审批，审批照 ADR-269，其余上限不变。）依据：规格-渠道中间件第四节。

本地群聊、QQ 私聊的细化默认值沿搜索规格第九节保留为待主人确认项；不把渠道接入许可解释成能力和费用授权。QQ 群公开检索的既定方向不重复询问。

本地群聊的记忆可见性照现有规则，不因为本规格一律变成公开档。工具执行权、记忆可见性和向搜索服务披露材料的许可分别判定。

### 3.3 ADR-081 第 3 条逐条落地

| ADR 的五种情况 | 本版规则 |
|---|---|
| 群友让她搜东西 | 后台只拿允许外发的公开请求、公开检索、读公开网页；结果回原群对应档 |
| 群友让她看主人电脑、跑命令 | 不声明本地工具；手工猜工具名也在执行门拒绝 |
| 主人在 QQ 私聊让她改文件、跑命令 | 本版关闭。不给工具，不靠更改 Channel 绕过；以后专门开通时另落 ADR，电脑逐次审批 |
| MCP、skill 只有标了“QQ 能用”的才给 | 默认 QQ 白名单为空；MCP 按稳定来源和工具 ID，skill 按稳定来源 ID 筛选；本地白名单不等于 QQ 白名单 |
| 要有用量上限 | 并发、步骤、时限、按人和渠道的日额度都检查；满额拒绝，不排无限队列、不切付费兜底 |

公开搜索和抓网页虽可在 QQ 后台用，仍受搜索规格的地址限制、服务用量和外发数据规则约束。白名单 skill 不能让孩子读取本地文件；白名单 MCP 也不能越过原派活人的能力上限。

有效能力为：

```text
原派活人的后台授权
∩ 当前渠道允许能力
∩ 代理定义所需能力
∩ 本任务收窄限制
∩ 工具来源当前授权
```

交集在创建时固定上限，在每次执行时重查撤销。权限增加只影响新任务，权限减少影响在途任务。

孩子能力不要求是父模型可见工具名的子集：QQ 前台可能只有 `task`。必须是原派活人的后台授权子集。依据：ADR-081、调研 9.2。

## 四、审批、结果回流和显示

### 4.1 审批显示谁派的

`approval.Request` 新增可信来源结构：

```text
root_task_id、task_id、parent_turn_id、tool_call_id
requester_actor_kind、requester_actor_id
origin_channel、origin_account、origin_conversation
root_conversation
agent_id、task_description
return_scope、return_audience、authority_version
```

现有 Request 只有角色、工具、目的、预览等字段，见 `native/internal/approval/approval.go:28`。不能把来源仅拼进可由模型提供的 Purpose。

审批卡显示：

> 主人 · 本地私聊 → worker  
> 任务：更新项目配置  
> 操作：修改配置文件  
> 结果回：原本地私聊

显示名仅作辅助，卡片同时保留可核对的身份类型、来源和任务链。审批只送到有权处理该根任务的本地窗口，不广播给 QQ 或无关根会话。

来源字段只解决显示和路由，不能代替批准入口鉴权。审批列表查询、订阅和批准入口均接收宿主签发的可信访问域，在服务端核对访问者、角色、根任务／根会话归属及处理权限；无关访问域不能查询卡片，也不能凭审批 ID 批准或写入授权。内部管理入口单独授权，不能把不带访问域的入口留给普通窗口调用。

当前 `Approvals.Decide` 只接收 ID、选择和理由，`Pending()` 返回全部待审批项，必须修改接口并迁移所有查询、订阅和批准调用点。出处：`native/internal/approval/decide.go:199、:234`。禁止只在 mygo 隐藏卡片而保留服务端全量查询或无域批准。

一次性授权不复制给孩子。孩子的新操作重新过门。“这个对话允许”按原授权域、派活人、渠道、权限档和操作类别检查；不能按随机孩子会话规避限制，也不能把 QQ 群当共享授权域。现有会话授权结构见 `approval/decide.go:118`，依据调研 9.5。

### 4.2 结果封套

```text
task_id、result_id、parent_task_id
status
text、sources[]、truncated、next_cursor
usage、steps、duration
return_scope、return_audience、authority_version
```

身份、状态、用量由运行时填。孩子正文不能覆盖这些字段。`usage` 同时表达已知消耗、字段完整性和未知消费占用，不能只给一个看似完整的总数。

状态分别记：

- `completed`：模型正常结束，并有最终正文。
- `partial`：已有正文，但因步骤或预算耗尽未完成。
- `failed`：执行失败或正常结束却没有最终正文。
- `cancelled`：被明确取消。
- `timed_out`：任务总时限到。
- `interrupted`：进程退出前未留下终局。

部分正文与停止原因分开保存。取消、超时即使有字，也不能算完成。usage-only 空消息不覆盖此前的有效正文；最终正文取最后一条带非空文本的 assistant 消息，合并该消息的文本块，不回传思考或全部工具过程。依据：调研第 1、4、6 节及生态层差距第四节。

模型可见的停止结局与底层执行是否退出分开记录。取消或超时后仍有工具、模型调用或回调在途时，任务处于收尾阶段，不能显示成“已全部停止”或释放容量。迟到输出不能改写已定结局；迟到用量仍按 6.2 幂等结算。

### 4.3 长结果

暂定：

- 内联正文加来源预览合计最多 16 KiB UTF-8、4,000 个估算 token，先到者截。
- 按 UTF-8 边界保留头部，返回 `truncated=true` 和受控结果号。
- 完整结果正文与来源合计最多 512 KiB；超过时在收集阶段停止扩张，标明完整记录也已截断。
- `task_result` 每页沿用内联上限。状态和用量不随正文截断消失。

16 KiB 借调研 9.6 建议；512 KiB 是本规格暂定的存储上限，接近 omp 执行层 500,000 字节，但不照搬其尾部截断。OpenCode 的 2,000 行、50 KiB 见调研第 1 节。这里不单设行数门槛，单行 JSON 和中文仍受同样字节上限约束。

“完整结果”仅指孩子最终输出，不含全部过程。达到存储上限后不能仍声称全文已保存。

结果号不是授权。读取须核对角色、父归属、原会话、权限档、授权代次和当前访问权；其他群、其他账号、其他角色、同会话不同档都拒绝。不给 QQ 孩子通用 `read` 来补读结果文件。

### 4.4 回原权限档

结果进入持久化邮箱，键绑定原角色、父会话、ReturnScope 和权限代次，不能只按 Conversation 投递。

现有 `SteerIn` 找当前运行的实例，不接 Scope；不能用它回传孩子结果。出处：`native/internal/turn/hub.go:351`，调研 9.8。

投递规则：

1. 结果和待投递邮箱在一个事务里落库。
2. 同档前台正在跑时，结果留在邮箱；仅在该档下一回合开头统一追加。当前工具循环中的后续模型请求不因结果到达而注入新结果。
3. 正在跑的是另一档时，同样排在原档邮箱中，不打断后塞给另一档。
4. 父回合已正常结束时，由原调用方调度一个前台续回合，在续回合开头使用原档和仍有效的权限领取邮箱；不假造一条人类发言。同档当前回合尚未结束时，续回合等待其结束。
5. 实例已回收时，仅按同一有效档重建。授权已撤销、会话已重启或找不到安全目的地时，留本地待处理。
6. 邮箱消费、注入标识和接收回合关联持久化。重复通知不重复追加；接收回合崩溃后不自动再启动一个前台回复。

回合开头确定本次领取的邮箱集合；此后新到的结果留给下一回合。可信插话的参考信息追加机会不消费孩子结果邮箱。

`result_id` 在同一档的上下文账本中只出现一次。重建从账本恢复已交付的结果引用；不能靠内存 Set 保证去重。未处理结果不得被普通压缩摘要带入所有档共用的历史。

前台生成对外话语后，仍走渠道中间件的裁决、改写、字数保险丝、`CheckOutbound`、写计划、`Hub.Commit` 和发送检查。16 KiB 后台结果不等于允许发 16 KiB QQ 消息。依据：规格-渠道中间件 10.1、第十二节。

子代理包不持有适配器、不直接调用发送接口。错误、来源标题、本地路径和任务描述也不能旁路发群。

## 五、并发、时限、用量和取消

### 5.1 起步参数

以下均暂定。来自调研的建议不冒充已经量出的最佳值。

| 配置 | 起步值 | 依据与选择 |
|---|---:|---|
| `maxDepth` | 1，根为 0 | OpenCode、DeepSeek 默认 1；本版只需前后台一层 |
| `maxActivePerRoot` | 4 个孩子 | pi 示例单批并发 4；低于 omp 会话级 32 |
| `maxActiveGlobal` | 8 个孩子 | 调研 9.6 建议；作为进程总上限，不能误当 DeepSeek 的每树 8 |
| `maxActivePerRequester` | 2 | 调研 9.6 建议；避免单人占满全局 |
| 公开检索总时限 | 120 秒 | 调研 9.6 建议；约束 QQ 等待 |
| 本地任务总时限 | 15 分钟 | 调研 9.6 建议；给多步本地工作留余量 |
| 公开检索模型步骤 | 32 | 调研 9.6 建议；低于 omp 默认软请求预算 200 |
| 本地模型步骤 | 64 | 同上；任务更长，但仍有限 |
| 创建工具总时限 | 5 秒 | 只做校验、预留和持久化，不等模型 |
| 结果读取工具总时限 | 5 秒 | 本地有界读取，不调模型 |

创建、运行、等审批、停止收尾都占并发槽。预留必须原子检查全局、根、派活人三层；启动失败且没有在途执行时释放；已经启动的任务等底层执行真正结束后释放。

当前工具 `within` 到时会先返回，底层 goroutine 可能继续执行；模型循环退出不能证明工具已退出。出处：`native/internal/turn/loop.go:701`。扩展统一工具执行契约，分别记录模型可见的超时／取消结局和底层执行已退出状态。内置工具、插件及 MCP 工具均接入运行时追踪，不能只追踪孩子的模型循环。

所有在途执行在启动前登记，底层调用及其受管回调全部返回后才注销。超时或取消后进入收尾阶段；收尾期间禁止发起新工作，不释放容量。丢弃迟到结果不能代替等待执行退出。

满额立即 `busy`，不设隐藏排队。不能让父等孩子、孩子又等父占着的槽。依据：调研第 6 节。

总时限从受理开始，含审批等待、工具重试和压缩。工具自身时限继续生效，实际可用时限取两者较短。步骤数是模型逻辑步骤；每次网络重试另计实际请求和用量，不能用步骤数藏住重试支出。

### 5.2 额度

并发、单任务上限不能代替按人日额度。

暂定按以下键累计受理次数、实际模型请求和来源服务调用：

- 派活人：渠道、ActorKind、ActorID；跨群共用，不能换群重置。
- 会话：渠道、会话。
- 平台。
- 全局。

每项任务必须同时通过这些额度和搜索、MCP 来源自己的额度。超限返回 `quota_exceeded`，不换人、不换平台、不自动换付费来源。

日额度的具体数值和花费上限需要主人定，见第九节。相关额度未配置时，QQ 子代理不启用；测试用临时配置给固定额度，不把“0”解释成无限。

金额预算在发请求前预留。并发请求不能都先检查同一余额再一起超支；未知价格的付费模型不能通过金额检查，不能按零费用计算。失败、取消也记实际消耗；服务商不报用量则标 `unknown`，不填零。

模型请求与搜索规格 5.2 对齐，持久化本地唯一请求 ID、预算归属和派发状态：

- `reserved`：已预留，按调用顺序可证明尚未提交派发意图。
- `dispatched`：已持久化派发意图，即将或已经交给模型 transport，保守视为可能收费。
- `settled`：所需用量或消费结局已知，完成幂等结算。
- `unknown`：已提交派发意图，但用量或消费结局未知；可同时保存已知字段。

先事务预留最大可能消费，再提交 `dispatched`，提交成功后才允许调用模型 transport。无法确定有限消费上界时拒绝金额受限的请求，不靠事后查账冒充硬预算。每次重试和压缩请求分别登记、预留、派发与结算。

只有确定未派发的 `reserved` 可以释放。`dispatched/unknown` 不因任务失败、取消、超时或重启而退款；已派发却未收到用量的请求保留保守占用。迟到用量按请求 ID 幂等结算，不因结果已经丢弃而漏账。数据库不可写时拒绝新派发。

### 5.3 取消语义

| 事件 | 孩子怎么办 |
|---|---|
| 父回合正常完成 | 已受理的孩子继续 |
| 受理完成前父工具被取消 | 回滚预留；不留活孩子 |
| 受理后父回合被 Stop、Interrupt 或新批次打断 | 取消该父回合创建的未完成任务树 |
| 前台收到结果的续回合被取消 | 不复活孩子，不自动重发结果 |
| 用户调用 `task_cancel` | 取消目标任务树 |
| 会话重启、角色关闭 | 取消所属任务树，旧结果禁止自动投递 |
| 子代理插件停用、Hub 关闭 | 取消并等待全部孩子及其底层执行、回调收尾，再关依赖的库 |
| 工具来源撤销 | 立即停止后续调用；必要时取消使用该来源的孩子 |

正常完成与取消分开，避免前台说完“我去查”就把后台停掉。已有 `StopIn` 只停当前会话，需补任务树联动，见 `hub.go:369`、调研 9.7。

管理器受理后持有自己的生命周期 ctx，不长期借用创建工具的 5 秒 ctx。取消时先持久化取消意图，再取消模型、工具和审批。迟到批准、迟到正文、迟到完成通知不能把任务改回成功。

取消请求返回不等于执行已退出。底层工具不响应取消时，保持收尾状态和容量占用，等待其返回或由工具自身完成受管终止；不能靠一个等待超时宣布已经收尾。关闭流程先撤销新入口，再取消、等待全部在途执行与回调退出，最后关闭其依赖的库。

不声称取消会回滚已发生的文件修改。已派发的消费占用按 5.2 处理，不随并发槽释放而退款。

## 六、数据、记账和进程被杀以后

### 6.1 存哪里

当前 Go 数据根下：

- `config/subagent.yml`：开关、限额、超时、QQ 白名单。
- `config/agents/*.md`：用户代理定义。
- 共用运行记录库：任务、任务上下文与快照、结果、邮箱、预算和用量归属。

不新增一套 SQLite 文件。任务关联 `model_runs`、`steps`、审批记录；不把每个孩子再作为一笔模型消耗重复相加。

暂定新增表：

| 表 | 关键约束 |
|---|---|
| `subagent_tasks` | TaskID 主键；可信父回合与工具调用 ID 唯一；保存身份、定义、权限、截止时间和结局、收尾状态 |
| `subagent_results` | ResultID 主键；任务终局结果唯一；有界正文和来源 |
| `subagent_inbox` | 结果与接收域唯一；记录待处理、已关联接收回合、已交付、待人工处理 |
| `subagent_context` | 按内部会话、权限代次、单调追加序号记录上下文；不混公开事件 |
| `subagent_context_epochs` | 内部会话及权限代次下的独立压缩快照；保存切点、已覆盖序号和提交状态 |
| `subagent_budget` | 预算域和请求预留唯一；保存派发状态、保守占用和结算，结算幂等 |

任务记录和受理结果必须先持久化，再启动孩子。存储失败不执行。运行时固定权限快照仅作上限，不覆盖当前撤销状态。

上下文序列、切点和快照存取从聊天 Events 的具体存储中分离，前台接现有聊天后端，内部任务接 `subagent_context` 和独立快照后端。复用 token 计算、切点选择、摘要模型调用和硬门槛流程，不复制一套压缩算法。

当前 `compactSource` 从聊天消息 `Seq` 取范围，`cutEvents` 读取 `st.Events`，`compactNow` 在没有有效序号时直接返回；`buildWith` 也从 `st.Events` 读取快照和历史。必须修改这些调用点，不能给孩子造聊天事件来满足旧接口。出处：`native/internal/turn/compact.go:50、:123`、`native/internal/turn/turn.go:335`。

内部任务存取契约：

- 上下文条目以内部追加序号定位，不能与渠道聊天 seq 混用；只对实例已见范围选择切点。
- 固定任务指令、代理定义和权限快照从任务记录重建，不依赖摘要保留。
- 已完成步骤的必要执行状态和结果引用有明确条目类型；重建保留继续推理所需状态，不能重放已执行工具。
- 压缩快照与覆盖切点原子提交；新快照提交前保留旧快照和原上下文。失败、取消或进程被杀时不采用未提交摘要。
- 硬门槛重建读取同一内部会话、同一权限代次的已提交快照及其后条目，不回退到聊天 Events。
- 内部压缩通知带运行种类和序列域，聊天记忆整理不能把内部序号当渠道 seq 使用。
- A9 恢复沿内部上下文账本核对快照和执行状态；保留可查上下文不表示自动续跑任务。

本版不自动删除任务记录和结果。数据量有界于每项结果上限，长期保留策略后续沿共用运行记录维护规则定；不擅自设置到期删除真实数据。

### 6.2 用量与显示

每个孩子记录：

- 模型实际路由和思考档。
- 输入、缓存读、缓存写、输出、思考 token，各字段是否收到以及用量完整性。
- 实际请求次数、重试次数、逻辑步骤、工具调用和审批等待。
- 已知费用、未知消费占用、耗时、停止原因、原派活人和来源会话。
- 本地请求 ID、关联 model run 和 5.2 的派发状态。

未报告的字段不得以数值零表示；明确报告的零才是零。模型适配层已有 `UsageSeen`，但当前 `runRow` 在未见 usage 时只把 reasoning 置空，输入、输出和缓存字段仍写零。必须同时更新适配层的字段完整性表达、`store.Run`、`model_runs` 存储及读取汇总调用点；旧记录无法证明字段完整时保留未知，不能补成完整零用量。出处：`native/internal/llm/llm.go:242`、`native/internal/turn/loop.go:495`。

根任务汇总按唯一 model run／本地请求归集，分别报告已知消耗和未知占用。未知请求不能因缺少终局 model run 而漏出预算账本。不能用“读取父总额、加孩子、写回”处理并发完成；不能把父汇总和子明细同时算进总账。

缓存比例沿现有适配层口径归一化，不能直接把 pi 的 `usage.input` 当含缓存输入。参与计算的字段未知时，比例也标未知。依据：LESSONS“pi 的 usage.input 不含缓存命中”、调研第 4、9.9 节。

本地主窗口显示派活人、来源、代理、状态、收尾状态、当前工具、步骤、用量、未知占用、耗时、审批等待和取消入口。详情读取同样鉴权。QQ 不显示任务内部工具流、审批预览、思考、本地路径和原始服务错误。

### 6.3 A9 结局表

启动恢复沿规格-Go后台 8.3 A9：先记再跑，未收尾不自动重跑。子任务恢复与现有回合、步骤清扫对齐；不能再建 Hub 触发第二次扫描。

| 被杀时停在哪 | 重启后的结局 |
|---|---|
| 创建尚未受理 | 无孩子；仅收回可证明尚未派发的预留 |
| 已受理，尚未开始模型请求 | 任务 `interrupted`，不自动启动；确定未派发的模型预留可释放 |
| 模型派发意图已提交，尚未确认 transport 接收 | 任务 `interrupted`；请求转 `unknown`，保留保守占用，不自动重放 |
| 模型正在出字，尚未收到完整用量 | 任务 `interrupted`；已有文本仅作部分记录；未报告用量保留未知及保守占用 |
| 已收到完整用量，结算尚未完成 | 依据已持久化用量按请求 ID 幂等结算；证据不足的部分仍为未知 |
| 工具已经结束 | 保留该步骤的原结局，不重执行 |
| 工具执行中 | 步骤“不知道结果”，可能已发生副作用；任务 `interrupted` |
| 等审批 | 审批 cancelled，说明“没有执行”；旧卡片批准无效；此前已发生用量仍保留 |
| 压缩中 | 未提交摘要不采用；恢复内部账本中旧的已提交快照、切点和后续条目，不续跑压缩 |
| 终局及结果已提交，尚未投递 | 保留终局；邮箱重新核权后可在允许的回合开头恢复调度 |
| 已关联接收回合，接收回合被杀 | 不自动再调用模型；留本地待处理 |
| 取消意图已提交，取消尚未收尾 | 保持取消，不复活、不重跑；底层副作用未知时保留未知记录 |
| 已交付 | 不重复注入、不重复发消息 |

所有请求恢复时，仅释放可证明未派发的 `reserved`；未结算的 `dispatched` 转 `unknown` 并保留消费占用。任务结局清扫与预算恢复分别幂等，不能按“任务未完成”统一退款。

结果与邮箱必须同事务提交，避免“完成了但没有可交付结果”。清扫重复执行不改变已终结记录。

现有 Windows 缺口仍成立：后台被杀时 PowerShell 子进程可能继续跑，见规格-Go后台 8.3 A9。子代理不增加外部代理进程，也不声称已解决这个缺口。重启后仍标不知道结果；下一次继续前先核实，不自动重做。进程内退出追踪不能作为后台被强杀后外部进程已退出的证据。

## 七、禁止的偷懒写法和已知的坑

### 7.1 禁止的偷懒写法

- 不给每个孩子 `NewHub`，不复制一套模型循环。
- 不用父 Conversation 加新 Scope 冒充独立孩子。
- 不临时改 `Hub.Cfg`、全局模型或全局工作目录供一个孩子使用。
- 不按名字判断主人，不把 `OwnerAsked=true` 等同本地主人执行权。
- 不从模型参数、会话字符串或任意 context 字符串补推可信身份、授权句柄和工具调用 ID。
- 不把 `task` 批准当成整棵树的 yolo 授权。
- 不复制父一次性批准，不让代理定义放宽工具来源授权。
- 不把 QQ 孩子的 Channel 改成 console。
- 不靠清单隐藏工具代替执行前检查；不以 `Tool not found` 证明委派或深度执行门有效。
- 不把父模型写出的自由文本当作已经脱敏的公开检索请求。
- 不把结果听众能看等同允许发给搜索服务，不让公开检索孩子自动召回私有记忆。
- 不把后台结果写成群消息，不直接从任务包调用适配器。
- 不用当前活动实例承接原来另一档的结果。
- 不在同一回合的逐次模型请求中消费异步完成邮箱。
- 不用摘要、截断、来源标题清理或模型声明的 `public=true` 给结果降级。
- 不用可猜任务号或结果号代替鉴权。
- 不用界面隐藏卡片代替审批查询和批准入口的服务端访问域检查。
- 不用内存通知和 Set 代替持久化交付去重。
- 不把未知用量、未知工具结果填成零或成功，不退还已派发但用量未知的消费占用。
- 不把工具超时返回、模型循环退出当作底层工具已经退出。
- 不在插件收掉后继续无追踪地回调写库；关库前必须等全部在途执行和回调收尾完成。
- 不为内部压缩伪造聊天事件，不把内部序号混成渠道 seq。
- 不自动执行项目仓库里的代理定义。

### 7.2 已知的坑

| 坑 | 本版处理与出处 |
|---|---|
| 别家代理定义可能比父工具表更宽 | 自己做委派能力交集；不能据 omp、OpenCode 的普通路径宣称天然继承。调研第 1、4 节 |
| 工具回调缺少可信调用信息 | 中立执行身份贯穿全部入口，内核另传 `ToolCallID`；`plugin.go:97`、`loop.go:574` |
| 等待超时被误当任务超时 | 创建、任务、单工具分别计时；Codex wait 只限制本次等待，调研第 3 节 |
| 工具超时返回但 goroutine 仍在运行 | 分开记录可见结局与执行退出；真实收尾前占槽、不关库；`loop.go:701` |
| 会话级并发被误写成整树并发 | 全局、根、人三层原子预留；omp 的 32 是会话 semaphore，调研第 4 节 |
| 父回合正常结束与取消混为一谈 | 正常结束可继续；取消整树，调研第 1、6、9.7 节 |
| 主人档结果回来时群友档正在跑 | 原档邮箱，不调普通 `SteerIn`，调研 9.8 |
| 空 usage 消息抹掉前面答案 | 倒序找有效正文，生态层差距第四节、调研第 6 节 |
| 超长中文、emoji、单行 JSON | 按 UTF-8 边界截断，字节和 token 双限；清单②⑦ |
| 定义更新、权限撤销与在途任务交错 | 提示词固定快照；权限只收紧；清单⑭⑲ |
| 公开 prompt 已夹入父私有信息 | 按外部披露许可检查，公开孩子全部来源限公开，不只过滤结果听众；搜索规格第九节、`memplugin/plugin.go:341` |
| 内部任务没有聊天 seq，旧压缩路径直接跳过 | 独立追加序列和快照后端，接通硬门槛、重建及 A9；`compact.go:50、:123`、`turn.go:335` |
| 并发完成丢账、通知重放重复算钱 | 按 run／请求 ID 汇总，结算幂等；调研第 2、9.9 节 |
| 已派发模型请求未报用量就被杀 | 保留 `unknown` 和保守占用，已知消耗与未知占用分列；搜索规格 5.2 |
| Windows 杀父进程没杀到子孙 | 沿 A9 记未知，不用两次 signal 冒充整树终止；调研第 5 节 |
| 定义路径联接、设备名、特殊字符、CRLF | 限定配置目录，核对实际路径；拒绝设备名，ID 非空且最长 64 字节；覆盖空格、`# % ? &`、CRLF/LF；清单⑫、`store/platform.go:40` |
| 完成通知在同回合逐请求追加或插回历史中间 | 仅下一回合开头消费邮箱，保持历史前缀；不更新旧占位消息；LESSONS、规格-Go后台 8.1 |
| 审批卡隐藏了，但无关窗口仍能凭 ID 批准 | 查询、订阅和批准均做服务端可信访问域检查；`approval/decide.go:199、:234` |
| 默认每人 2 个，基准却声称单人并发 4／8 | 明确身份和根分布，屏障确认活实例，拒绝不计成功时延；调研第 8 节 |
| 把渠道接入许可扩大成委派和消费授权 | QQ 私聊、本地群聊默认值保留待确认；搜索规格第九节、ADR-081 |
| 错误和审批也能泄密 | 同样绑定听众；QQ 使用安全错误码，本地保存受控诊断；清单㉑ |

## 八、验收和分步实施

### 8.1 确定性验收

全部用临时数据目录、假模型、假来源和可控屏障。每条必须先证明进入目标状态，再检查结果。零跳过；改坏的是保护本身，不是另加一句泄漏来碰巧测红。

| 编号 | 一个测试要证明什么 | 怎么改坏会红 |
|---|---|---|
| S1 | 三种内置代理实际走同一个 Hub 的独立内部会话；孩子能在父未结束时运行 | 复用父会话，孩子首请求被队列挡住 |
| S2 | 四场合 × 主人、他人、身份不明的完整请求与工具表符合第三节；QQ 私聊和本地群聊未确认时拒绝委派，渠道接入许可不能放行 | 去掉 ActorKind 检查或把接入许可当委派授权，出现本地工具或未经授权的受理 |
| S3 | ADR-081 五条逐项成立；QQ MCP、skill 空白名单不给能力 | 把本地白名单当 QQ 白名单，出现对应工具或 skill |
| S4 | 分开验证 QQ 清单不声明本地工具，以及旧声明快照或受保护入口已到达委派判定后仍拒绝 `powershell`、MCP／skill 间接本地操作；执行计数为零 | 保持声明可达并拆掉执行前委派检查，副作用日志出现；`Tool not found` 不算执行门证据 |
| S5 | 本地主人私聊、QQ 主人私聊和群档中，父接触私有材料后未经外发授权的自由 prompt 均拒绝；核验过的公开请求可用；公开孩子不召回私有记忆，假搜索端只收到允许外发的查询 | 分别拆掉入口来源检查或公开来源限制，假搜索端收到独特私有事实 |
| S6 | 孩子请求不含父历史、私下人设、思考和审批预览 | 复制父消息，完整请求中出现唯一标记 |
| S7 | 创建、执行中撤销来源授权后，后续工具不执行 | 只检查创建快照，第二次调用仍执行 |
| S8 | 无关父、角色、群、账号和同会话不同档都读不到结果 | 删除 Scope 或账号检查，返回私有标记 |
| S9 | 原主人档孩子完成时群友档正在跑，只有原档下一回合收到结果 | 改用 `SteerIn`，群友请求出现结果 |
| S10 | 孩子实际越过硬门槛，完成内部序列压缩、实例回收和重建后，任务指令及必要执行状态仍存在，已完成工具不重跑；前台重建仍隔档，共享摘要不含结果标记 | 接回聊天 seq 路径导致不压缩、丢任务指令／执行状态，或把结果纳入共享摘要，断言失败 |
| S11 | 容量边界前、正好、超一项正确；创建、审批、底层工具超时后的收尾都占槽；无在途执行的失败才释放 | 提前释放或非原子检查，活执行峰值超限 |
| S12 | 分开验证孩子清单无 `task`，以及旧声明快照或直接受保护管理入口已到达深度判定后仍拒绝再次派活 | 保持调用可达并删除深度判定，产生孙任务；`Tool not found` 不算深度门证据 |
| S13 | 父正常完成后孩子继续；受理前取消无孤儿；受理后父取消停树 | 长期借创建 ctx 或不联动取消，状态不符 |
| S14 | 创建、等审批、工具执行、完成回流处取消；晚批准不执行，终局唯一，底层退出前保持收尾 | 去掉取消代次检查或提前结束收尾，副作用、成功回写或容量状态不符 |
| S15 | 任务时限包含审批，步骤耗尽不再发请求；重试和压缩请求各自预留、派发并扣实际额度 | 每步重置截止时间或漏扣请求，额外请求发生 |
| S16 | 空终局、多文本块、usage-only、半途失败分别得到正确正文与状态 | 只取最后消息或“有字即成功”，期望不符 |
| S17 | 16 KiB、4,000 估算 token、512 KiB 边界和中文截断正确，分页还原有界记录 | 按字节硬切 UTF-8 或漏计来源，输出非法或越界 |
| S18 | 并发完成、失败、取消、重复通知，根已知消耗等于唯一请求的已知明细之和；缺失 usage 不写零，未知请求保留保守占用，迟到用量仅结算一次 | 改成读加写、重复累计、缺失填零或取消退款，账和占用不符 |
| S19 | 坏定义、重复 ID、未知字段、权限字段和路径越界均拒绝；空 ID、设备保留名、65 字节拒绝，合法 1／64 字节边界可加载；新旧快照互不串 | 删除相应解析或文件名保护，非法定义被加载；允许代理文件覆盖授权时孩子得到额外能力 |
| S20 | 同一可信 `TurnID + ToolCallID` 重复受理只建一个孩子；不同调用不合并；缺可信 ID 拒绝；结果通知重放只追加一次 | 去掉唯一键、从模型参数取 ID 或只靠内存去重，产生错误合并、重复任务或重复注入 |
| S21 | 第六节 A9 表逐行恢复；覆盖预留后、派发状态提交后、实际派发后及用量结算前被杀；已结束步骤保留，未知副作用不重跑，未知消费不退款，未提交快照不采用 | 自动续跑、覆盖终局、采用半成品摘要或退还未知占用，计数、上下文、预算或结局不符 |
| S22 | 用屏障让工具在模型可见超时后仍阻塞；停插件时同时保留迟到模型、工具和通知，库保持打开、容量保持占用；全部底层调用和回调退出后才能释放和关库，关库后零访问 | 把循环退出当执行退出、提前释放或关库，屏障未放行时状态断言失败，或出现关库后访问 |
| S23 | 假渠道完整链路：孩子→原档前台→守卫→计划→Commit→发送；禁发时 Send 为零 | 直接发孩子结果或跳过守卫，适配器收到禁发内容 |
| S24 | 同档一个回合的多次模型请求之间连续到达结果，当前回合始终不注入；插话送达也不消费邮箱；下一回合开头统一追加且仅一次，边界后新到结果再等下一回合；旧请求前缀逐字保持 | 逐请求消费邮箱、借插话注入、回写占位或插入中间，时机断言或前缀比较失败 |
| S25 | 真实审批服务生成对应派活人和根任务的卡片；直接使用无关可信访问域查询、订阅、批准均拒绝，原审批仍待处理且未写授权；有权域可以处理，管理入口另验授权 | 只信 Purpose、只在界面隐藏或不核根归属，无关访问域取得卡片或批准成功 |
| S26 | 普通输入、内部运行、插话和退回路径的可信身份、Scope、任务归属和授权句柄贯穿清单、审批与执行；不同归属不继承原任务权限，缺失身份拒绝 | 某一路沿用旧身份、从参数补身份或漏传句柄，假服务观察到错误归属的派发 |

S11、S14、S18、S20 用屏障覆盖关键交错，每种交错 100 次；`go test -race` 零报告。次数沿规格-Go后台 8.2 A11，不靠延长超时消除红灯。

本地冒烟必须运行实际 Go 后台和任务工具：临时数据、假网关、假搜索来源，创建任务、查看卡片、取消、重启、读取结果各走一遍；实际触发一次孩子硬门槛压缩和重建，并让一次工具超时后延迟退出，观察收尾占槽及关闭顺序。mygo 检查实际任务详情和审批来源；不能只测 DTO。真实 QQ 不在验收中发送。

### 8.2 性能怎么量、怎么过线

当前调研没有可比较的子代理性能实测值，不能预写“omp 最快”或“Go 已过线”。出处：子代理调研第 8、10 节。

实现验收时，对 **omp、OpenCode v2、pi 随包示例** 同机测量，再逐项取最好的可用数；基线记录版本、入口、条件和原始输出。pi 的结论只限该示例。

不花钱的基准：

- 同一假网关、同一任务文本、同样工具结果、同样输出大小。
- 空答案、16 KiB 答案、一次阻塞只读工具三类任务。
- 并发 1、4；Go 另测全局 8 和第 9 个拒绝。默认配置不变：并发 4 至少使用两个派活人；并发 8 至少使用四个派活人和两个根，每人不超过 2、每根不超过 4。
- 用屏障确认本格要求的全部孩子已经进入运行状态，再采样该并发水平的完成、取消和内存数据；启动指标从各请求实际创建时计时，同时报告峰值活实例、活执行数和受理／拒绝计数。不能把未进入运行状态的请求算成已达到并发。
- 全局第 9 个超限探针使用尚未达到个人与根上限的独立派活人和独立根；保持前 8 个仍占槽，证明拒绝命中全局上限。拒绝请求单列，不计入成功任务时延分布。别家无法全局限额的部分记“不支持该契约”，不能当零耗时。
- 冷启动和已启动分开。预热后每格 100 项成功任务，三个程序轮换顺序，整组跑三遍；容量拒绝另报。
- 所有数据和配置放隔离目录，不碰真实代理目录和订阅凭据。

| 指标 | 对标的数 | 暂定过线 |
|---|---|---|
| 创建到孩子首请求 | 三家冷、热各自的本机开销 p95 最小值 | Go 对应 p95 不高于该值 |
| 孩子终局提交到父下一回合首请求 | 三家可比较完成投递路径的本机 p95 最小值；父空闲和父忙碌分列 | Go 可比路径不高于该值；投递丢失、重复均为零 |
| 取消到阻塞工具退出 | 三家同类进程内或直接工具取消路径的 p95 最小值，分别列承载方式 | Go 不高于可比最小值；收尾后活任务、活执行为零 |
| 每个活孩子的增量私有内存 | 扣除各自空闲基线后的峰值，取三家最小值 | Go 不高于该值 |
| 有界结果 | 本规格 16 KiB 内联、512 KiB 存储上限 | 不越界；超长输入不能使内存随全文无界增长 |
| 请求前缀复用 | 规格-Go后台 A8 的 90% | 非压缩请求 ≥90%，且旧前缀无改写 |

“终局到父请求”的持久化成本分列报告。父忙碌时额外报告等待当前回合结束的时间，不把这一契约等待冒充本机投递开销；只支持逐请求注入的路径不能直接当下一回合投递基线。不能删去 Go 的权限检查、持久化、回合边界或去重来对齐别家的简化路径。无法建立同口径时，明确列出不可比项，不宣称已达到最佳。

真实模型另测公开检索、本地读码、多孩子汇总各 5 题，每题交替跑三次。量完整正确率、请求数、输入和缓存 token、费用、p50/p95；框架开销与模型等待分开。正确率不低于三家最佳结果；副作用重复和越权为零。费用估算报主人批准后才跑，本次起草不执行。

### 8.3 分几步做

每步独立提交、带本步行为测试和文档更新。未完成整体验收前，不在真实渠道启用。撤掉底层步骤前，先停依赖它的任务入口；不删除已有运行记录。

| 步骤 | 可交付结果 | 单独撤掉时 |
|---|---|---|
| 1 | 定义解析、来源描述、中立执行身份、可信 ToolCallID 和委派判定；迁移输入、插话、清单、审批及执行调用点，对齐 MCP、搜索接口 | 撤销新增类型与解析，不影响已有前台 |
| 2 | 同 Hub 内部运行入口、独立会话、任务记录、内部上下文序列与快照；接通压缩和硬门槛重建，内部调用可跑完孩子 | 关闭子任务入口，已有普通回合照旧 |
| 3 | 三层容量、模型派发预算与未知用量、时限、底层执行追踪、整树取消、审批来源及服务端访问域检查 | 停止新任务并等全部执行收尾；不影响普通工具审批 |
| 4 | 结果存储、分页、原档邮箱、下一回合开头投递、持久化去重和 A9 恢复 | 关闭自动投递，结果留本地可核查 |
| 5 | 注册三个任务工具，接前台续回合和渠道发送路径；验证旧声明及直接入口不能绕过委派、深度检查 | 撤销工具注册，已有聊天流程照旧 |
| 6 | mygo 任务详情、来源和未知用量显示、取消及审批入口；完成冒烟和性能对照 | 撤掉新增视图，运行记录仍保留 |

每步同步更新规格-Go后台插件表、相关子系统参考页、配置示例和待办；涉及共同契约时同步更新搜索、MCP 规格。最终完成后更新本规格状态与实测结果，不用“基础已好、以后补权限”算完成。

## 九、要主人定的

只剩会影响授权默认值、花钱或真实外发的事项。其他实现取舍按本文暂定值做，不再逐项请示。

1. **后台日额度与费用上限。** ADR-081、082 已定必须有上限，但未定数值。需要拍板按人、会话、平台、全局每天允许多少任务、模型请求，以及金额预算。未配置前 QQ 子代理保持关闭；不能默认无限。
2. **QQ 的 MCP、skill 和用户代理白名单。** 默认全空不变。主人以后点名开放哪些来源、工具和代理时，再写配置与 ADR；不能把安装等同授权。
3. **QQ 本地执行特例。** 本版不开放。以后若开，需明确账号、主人身份、能力、结果目的地，并保证电脑逐次审批；不能沿用普通本地 yolo。
4. **真实模型对照和真实 QQ 发送。** 模型评测先报请求与费用估算；真实渠道启用和发送另获明确授权。假网关、临时数据和假适配器验收不依赖这些批准。
5. **QQ 私聊、本地群聊的细化启用默认值。** 沿搜索规格第九节待确认项，不因已有渠道接入许可自动授予子代理委派和额度使用权；确认前对应入口保持关闭。QQ 群公开检索方向已由 ADR-081 确定，不重复询问。
6. **首次搜索外发和联网授权粒度。** 沿搜索规格第九节确认查询词、URL 发往哪个服务，以及逐次审批还是限定范围的持续授权；子代理沿用同一授权，不另行扩大。结果返回主人不等于获准把私有材料发给 Tavily；未获材料披露授权时，公开检索仅使用核验过的公开材料。

## 这一轮改了什么（2026-10-28 复核以后）

- 采纳复核第 1 条（高）：分开判定结果听众与向外部服务披露许可；父接触私有材料后未经授权拒绝自由文本公开委派，公开检索孩子全部上下文来源限公开，不自动召回私有记忆，补本地私聊、QQ 私聊及后续召回验收。
- 采纳复核第 2 条（高）：复用搜索规格的中立执行身份，贯穿普通输入、内部运行、插话及退回、工具清单、审批和执行；内核传递 `ToolCallID`，以可信 `TurnID + ToolCallID` 幂等受理，补完整身份链路验收 S26。
- 采纳复核第 3 条（高）：区分模型可见超时结局与底层执行退出，统一追踪内置、插件和 MCP 在途工具及回调；真实收尾前不释放容量、不关闭依赖库，强化 S11、S14、S22。
- 采纳复核第 4 条（中）：审批查询、订阅和批准入口增加宿主签发的可信访问域，服务端核对角色、根归属与处理权限；迁移 `Pending/Decide` 调用点，S25 直接验证无关域不能查询或批准。
- 采纳复核第 5 条（中）：把上下文序列、切点和快照存取从聊天 Events 分离，内部任务接 `subagent_context` 与独立快照表；明确硬门槛重建、必要执行状态及 A9 恢复，S10 必须实际触发压缩。
- 采纳复核第 6 条（中）：完成结果仅在原档下一回合开头统一追加；当前回合后续请求和插话机会不消费邮箱，S24 同时验证追加时机、去重及历史前缀。
- 采纳复核第 7 条（中）：模型预算对齐 `reserved/dispatched/settled/unknown`，派发意图先持久化；未报告用量不写零，重启只释放确定未派发预留，根汇总分列已知消耗和未知占用，补崩溃及迟到结算验收。
- 采纳复核第 8 条（中）：S4、S12 分开验证声明隐藏与执行门；用旧声明快照或受保护管理入口证明调用已到达判定，禁止用 `Tool not found` 作为执行门通过证据。
- 采纳复核第 9 条（中）：并发 4 至少两个派活人，并发 8 至少四个派活人和两个根；屏障确认运行状态，全局第 9 个探针使用未触个人及根上限的独立身份和根，拒绝不计成功时延。
- 采纳复核第 10 条（中）：撤回 QQ 私聊及本地群聊未经确认的委派默认值，沿搜索规格保留待确认项；渠道接入许可不等于委派或费用授权，QQ 群既定公开检索方向不重问。
- 采纳复核第 11 条（低）：代理 ID 非空、最长暂定 64 字节并拒绝 Windows 设备名，添加 `.md` 不豁免；依据现有 `store/platform.go` 同类防护，S19 覆盖空、保留名、超长和合法边界。
- 本轮未修改原有并发、深度、时限、步骤、输入输出大小、额度或性能阈值；新增 64 字节代理 ID 上限为配置边界暂定值，其他新增数字为既有限额下的基准身份分布推导，不是实测成绩。
- 按仓库现行 ADR-203 对齐 Bun 退役表述；本轮仅做只读依据核实和规格修订，未修改仓库，未运行程序或测试，文中验收均为实现要求。
