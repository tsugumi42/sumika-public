## 一、目标和不做的事

**目标**：用户日常要动的东西都能在界面里改，不用打开 `sumika.yml`；改了马上知道生效没有、什么时候生效、值是从哪来的；出了问题能从报错直接跳到对应的设置。

**不做**：在界面里编辑密钥原文（令牌、API key 只显示"已存 / 没存"，存取走密钥库）；把内核的调度、预算这类开发参数做成控件（放进"高级"只读列表，写明在配置文件哪一行）；多用户、托管策略。

## 三、交互

1. **布局**：左栏分类、右栏内容，复用聊天页的分栏和宽度（ADR-301）；右栏按小节分组，每组一张卡片；窄窗口左栏收成顶部的下拉。
2. **搜索**：左栏顶上一个搜索框；每个设置项在注册表里登记名字、说明和中文别名（"自启动"能搜到"开机自启"），没登记的搜不到，测试钉住"每个设置项都登记了"。
3. **保存**：改了就存，不设"保存"按钮；存成功一个小提示，存失败在那一项下面写原因、值退回原来的。
4. **生效方式写在项上**：立即 / 下一轮对话 / 重启接收 / 重启程序 / 尚未生效 五种（“尚未生效”是后台还没人读的项，只读、不出可编辑控件，2026-11-14 加）；重启接收、重启程序两种在页面顶上出一条"有 N 项要重启接收才生效"和一个按钮。
5. **值的来源**：被 yml 或别处覆盖的项，旁边小字写"来自配置文件"；"恢复默认"只出现在改过的项上。
6. **测试按钮**：网关地址、协议端地址、代理旁边有"测试"，结果分类报告（连上了 / 连不上：拒绝连接、超时、认证失败、地址不对），不只写"失败"。
7. **危险操作**：删除、清空、改数据位置要确认，写清后果和能不能找回；成人向、敏感媒体打开时在开关旁写一行"后果由你负责"（ADR-307），不弹窗。
8. **入口**（从别处直接跳到某一项）：聊天顶栏的模型名 → 模型；会话的右键或资料页 → 会话规则里这个会话那一行；提醒和报错里的"去设置" → 对应的项并高亮；托盘菜单"设置"；`Ctrl+,` 打开设置；命令面板能搜设置项。
9. **只能改文件的项**：不藏起来，在"关于与诊断"里列出来，写明配置文件里哪个键、默认值、现在的值。

## 四、后台：设置注册表

角色查询和设置工具共用本节注册表；入口、字段白名单和生效回执见[客户端自知与设置工具](规格-客户端自知与设置工具.md)（ADR-317，草案未实施）。桌面可写不自动等于 QQ 可写。

- 新包（暂名 `internal/settingsreg`）：每个设置项登记 键、类型（开关 / 枚举 / 数字带范围 / 文本 / 路径 / 列表 / 会话表）、默认值、存在哪（yml 键、桌面设置键、角色卡）、生效方式、说明、别名、属于哪个分类。
- 读接口一次返回全部项的当前值和来源；写接口按键写，写 yml 照现在 `config/link_file.go` 那种保留注释的写法，写完重新读一遍核对。
- 插件的配置表单由插件登记的 schema 生成（OpenHands 的做法），核心页面（通用、外观、模型、会话规则）手写。
- 现有的 `ModelSettingsWriter`、`LinkSettingsWriter`、桌面设置 `Store` 收进注册表，旧界面照旧能用。

### S1、S2 实现约定（2026-11-08）

采用本页开头盘点和调研中的统一登记、中文别名、来源分层；复用现有模型／链接的校验及运行快照，不另建权限入口。`internal/settingsreg` 显式登记元数据，默认值取 `config.Defaults()`；反射覆盖测试独立检查全部 YAML 字段（含 inline、账号列表与角色映射），不靠反射自动登记来掩盖遗漏。

`api.SettingsRegistry` 仅交给 `app.DesktopReader`：`ReadSettingsRegistry(context.Context) (api.SettingsView, error)`；`WriteSetting(context.Context, api.SettingChange, api.SettingsVersion) (api.SettingsView, error)`。旧 `Reader.ReadSettings` 保持原契约。修改携带键和单个 JSON 值，版本分别绑定 yml、桌面文件；缺值、null、类型错误、只读键拒绝。模型和链接委托已有 writer；新增平台／会话键走 `config.SaveSetting`；桌面开关和完整外观走 `desksettings.Store.SetSetting`。

配置先备份原文、保留注释补丁，再原子替换、重读核对；核对失败还原原文，回滚失败单独报告。账号表整体提交，元素只接收 `id/character/url`，原令牌按账号 ID 保留；令牌只显示已存／没存，不经此接口编辑。平台与会话新增配置重启接收后生效，不提前改运行配置；模型／链接沿用原有发布时机。未落地的通知、快捷键、界面切换等明确只读不可用，不把登记当作功能完成。`trace.debug` 是已退役的 Bun 配置，Go 不读、不生效。

验收使用临时数据目录：全部配置键覆盖、各项中文别名、默认／显式零值来源、各写入重读一致、注释与未知项保留、外部版本冲突、写坏回滚、取消与关闭、秘密不进入返回值。新设置页控件和桌面外观应用由 S3、S4 接入。


## 五、分步

1. **S1 注册表和读接口（分支已实现）**：显式登记 221 项、13 类，含全部配置结构体字段、桌面习惯、角色卡、不可用的规划项与退役项；独立反射覆盖测试检查 YAML 字段完整性。
2. **S2 写接口（分支已实现）**：复用模型、链接、桌面 Store，开放通用、平台与账号、会话规则的已有配置键；备份、注释保留、重读核对、失败回滚，全部用临时数据目录。
3. **S3 设置页外壳**（新界面）：左栏、搜索、各类控件的渲染、保存提示、生效方式条、来源小字。
4. **S4 页面**：按 通用 → 外观 → 模型 → 会话规则 → 平台与账号 → 记忆 → 工具与权限 → 插件 → 数据与备份 → 通知 → 快捷键 → 关于与诊断 的顺序。
5. **S5 入口**：聊天顶栏、会话右键、提醒里的"去设置"、托盘、`Ctrl+,`、命令面板。

## 六、验收

- 盘点里"后台有、界面没有"的项全部能在界面看到；能改的改完重读一致。
- 搜索：每个设置项至少能用名字和一个别名搜到。
- 改一项要重启接收的设置：页面顶上出现提示条，点按钮重启接收以后提示消失、值生效。
- 用 `ui.NewTester` 量布局和状态，截图只给主人看。
