## 一、做什么（说人话）

右侧栏第二个标签"她在想什么"，给主人看**后台到底发生了什么**，分两块：

1. **对话**：每一轮一张卡片，按时间往下排。一张卡片从上到下是：她看到了哪几条消息 → 群里：闸门为什么放她进来 → 这一轮注入了什么（对面是谁、记忆）→ 她想了什么（可折叠）→ 调了哪些工具、结果怎样 → 发出去之前守卫怎么判的 → 最后发了什么（或试运行想发什么、或"看了，没说"和理由）。群里闸门没放行的，没有这一轮，只有一行"没接"和理由。
2. **后台**：不属于某一轮的模型调用排成一条时间线：整理记忆（summarize）、压缩、以后的学说话方式、识图、链接展开……每条写：哪个代理（阶段）、哪个角色哪个会话、用了哪个模型、多久、成了没有、失败的话是调用出错、超时还是回复读不懂。由某一轮触发的后台调用（例如发送前守卫的"确认"）**挂在那一轮的卡片里**，同时在后台时间线里也能搜到。

这是主人一个人在自己电脑上看的界面，可以显示全部；但群里别人的消息原文照原样带发言人，记忆的范围标签照原样标，不改写、不省略（第三节）。

**不做**：不在这里改任何设置、不批准审批、不发消息、不让主人改她的思考；不把提示词全文和原始 JSON 铺进卡片（要看另有"调用记录"，不在本规格）。

### 2.4 "思考原文"在 llm 层拿得到吗

拿得到，而且现在就在拿：`Client.Stream` 的结果里 `Result.Reasoning` 是拼好的思考文字，`ReasoningField` 记它来自哪个字段（DeepSeek 官方 `reasoning_content`、OpenRouter 式网关 `reasoning`、`reasoning_text` 三种，`llm/llm.go:254-262、338-344、406`），另有 `ReasoningDetails` 装结构化 / 加密块（`llm.go:235-236`）。`usage.reasoning_tokens` 单独记在 `model_runs.reasoning_tokens`。

不在 `Result.Reasoning` 里的情况：服务商只给摘要或只给加密块时没有可读文字，卡片要写"想了约 N token，服务商没有给文字"，不能显示空白冒充"没想"。

**思考现在会回传给模型**（不是丢掉）：`openaichat` 的 `messagesJSON` 对每条助手消息，没有结构化思考时按原字段把 `Thinking` 带回去，有结构化的就原样带 `reasoning_details`（`internal/llm/openaichat/encode.go`）；实例用 `Msg.Thinking` 把思考留在内存历史里，重建时也复制回来（`hub.go:906`）；从库重建的实例没有思考（events 里不存）。这是照 pi / OpenCode 的写法（`llm/testdata/cassettes/deepseek-venice-tool-loop.json` 的来源就是"思考在工具循环和后续对话里保持"的录像）。**本规格不改这一行为**，也不许把库里存的思考读回来塞进 `Msg`（第六节）。"DeepSeek 文档建议不回传上一轮的思考"这句我没有核对过原文，**待核实**；要改回传属于另一个会改模型请求、影响缓存前缀的行为变更，见第十节问题 3。

## 三、四种场合各显示什么

窗口是主人的本机主窗口，主人能看自己机器上存的全部；但"能看"不等于把这些东西给别的角色、别的场合的回合用（沿用[规格-界面接Go后台](规格-界面接Go后台.md)第六节）。卡片按**角色**分：右侧栏顶部有角色切换（[信息架构](信息架构.md)第 195 行），默认选最近回合的那个角色，另有"全部"；一张卡片只属于一个角色，角色 A 的注入和思考不会出现在角色 B 的卡片里。

| 场合 | 有哪些行 | 卡片有哪几段 | 显示规矩 |
|---|---|---|---|
| 本地私聊（`console:<角色>[:topic:…]`） | turns、steps、model_runs；回复就是 events 里她的那一行 | 看到的消息（主人那句）→ 注入 → 思考 → 工具 → 回复。**没有**闸门段，**没有**守卫段（守卫对本地私聊直接跳过） | 对话区本来就内联显示思考和工具，这个标签是同一份数据的另一种看法；是否在本地私聊也显示见第十节问题 4 |
| 本地群聊 | 真实模式现在没有本地群聊（[规格-界面接Go后台](规格-界面接Go后台.md)第六节），写"本地群聊还没有接入"，不拿演示数据凑 | 将来：同本地私聊，多角色按角色分卡；不过闸门（`gate.go:22-23`） | 演示模式（`-demo`）可用有类型的假群验证展示隔离 |
| QQ 私聊（`qq:private:<自己号>:<对方号>`） | turns、steps、model_runs、`outbound_plans / parts`、`guard_checks` | 看到的消息（对方的话，带名字）→ 注入 → 思考 → 工具（QQ 渠道没有执行类工具，通常没有）→ 守卫 → 发送。**没有**闸门段（私聊不过闸门） | 对方的话照原样显示发言人；"这一轮用了哪个听众档"（主人 / 朋友）显示为一个小标记 |
| QQ 群 | 以上全部 + `gate_decisions` | 看到的消息（该批全部，别人的话带发言人，原文照显）→ 闸门（结论、概率对门槛、频率、一句理由）→ 注入 → 思考 → 工具 → 守卫 → 发送。闸门没放行的是"没接"行 | **记忆范围标签照原样标**（私下 / 仅本群 / 可公开……用库里的值，不改写）；拦下的那句原文按规矩没存，不显示；思考原文里可能提到被拦下的内容，本机照显，卡片上标"这一轮有一句被守卫拦下"。多角色同群时按角色筛选，同一条消息两个角色都判断过就各有各的卡，不合并 |

范围标签现在的真实情况：第 1～2 步的"注入"只有那一整段参考信息的文字（`prompt_sections`），没有逐条的范围标签；此时**只显示文字并写明"逐条的范围标签第 3 步才有"，不许根据文字内容猜标签**。

## 四、技术路线

### 4.1 统一的模型调用记录（让后台代理也进来）

目标：任何调模型的地方，都在同一处留下一行 `model_runs`，包括失败和被停下的。

1. **调用说明**：`llm` 包加 `Purpose{Stage, Character, Conversation, TurnID, Ref}`，放在 `ctx` 里（`llm.WithPurpose`）。`Stage` 必须是登记表里的名字（登记表在 `llm` 包里，每行写：名字、谁来写记录——`kernel`（回复、重试、压缩，内核自己用 `AddRun` 写更全的一行）、`recorder`，或 `none`（离线评测 `eval`、测试 `test`：不写库）、是否挂在某一轮、一句话说明）。`cmd/` 下的离线工具和测试里直接 `llm.New(...).Stream` 的，统一带 `eval` / `test` 阶段。`Ref` 是批次引用，例如整理的 `seq:120-180`。
2. **`Client.Stream` 没有 Purpose 就拒绝**：返回 `ErrNoPurpose`，不发请求。登记之外的 Stage 同样拒绝。这样新入口忘了登记，第一次调就红，不会悄悄不记。
3. **记录器**：`Client` 带一个可选的 `Recorder`（app 装配时接上，实现写 `model_runs`）。每次 `Stream` 结束（成功、出错、被停下）调一次，`kernel` 阶段跳过。记录内容：阶段、角色、会话、回合号、`Ref`、模型、起止、首字、用量（五项 token）、route、`error_kind`、错误文字、思考原文、输出文字（只给非回复、非压缩阶段，截 8 KB；压缩的摘要已经在 `context_epochs.summary`，不存第二份）、`prompt` 字数（**不存提示词全文**：整理的提示词里有聊天记录，守卫的有被保护的记忆原文）。
4. **错误种类 `error_kind`**（`model_runs` 新列）：`call_error`（网络、服务商报错、HTTP 状态不对）、`timeout`（调用自己的时限到了）、`bad_output`（回复读不懂：JSON 坏、字段不对、守卫的答案不是 yes 或 no）、`cancelled`（被停下、关机）、`empty`（回复是空的）。`bad_output` 只有调用方读完回复才知道，所以记录器返回一个句柄，调用方用 `Annotate(kind, detail)` 补写同一行。
5. **`Generator` 改成带说明的结构**：`Call(ctx, GenRequest{Stage, Model, Prompt, CacheKey, Character, Conversation, Ref})`；守卫确认挂在哪一轮，由渠道在调 `CheckOutbound` 之前把回合号放进 `ctx`（`memory.WithTurn`），记忆包不 import 渠道。整理的 `Ref` 取 `Job.From..To`。
6. **`guard_checks` 新表（trace）**：每次 `CheckOutbound`（包括放行的）一行：时间、turn_id、角色、会话、route（normal / embed-down / model-down）、reason（`clear`、`literal`、`below_threshold`、`similarity`、`model_yes`、`model_no`、`model_call_error`、`model_timeout`、`model_bad_json`、`model_bad_answer`……沿用 `memory/outbound.go` 当前原因码）、拦下的记忆编号、对应的 `model_runs.id`（有确认调用时）、用时。现在的 `GuardRoute()` 是整个记忆包共用的一个原子量，并发的两次判断会互相覆盖，所以要新加一个把结论随返回值带出来的方法（`CheckOutboundDetailed`），渠道守卫接口同步加；旧方法保留给复读用（`CheckRepeat`）。
7. **新列和新表一览**（迁移编号以实现时 main 上最大的为准，只加不改旧表）：`model_runs` 加 `error_kind`、`detail_json`（每个阶段自己的小结，例如整理的计数、守卫的嫌疑编号）、`reasoning_text`、`output_text`；`gate_decisions` 加 `turn_id`；`turns` 加 `input_seqs`；`outbound_plans` 加 `turn_id`（chat 库迁移，所有平台库都跑）；新表 `guard_checks`。旧行这些列是 NULL，界面照实写"这一轮是关联键加上之前的记录，没有这一段"，**不拿时间窗去猜**。

### 4.2 思考原文：存哪、存多久、多大、隐私

**方向（主人 2026-11-02 原话"思考原文不是就和对话一样的吗？"）**：思考原文当成一轮回复的一部分，**默认就存**，不当调试用的东西，不设"存不存"的开关。AstrBot、MaiBot 都是这样（见开头参考表）。现状已经基本做到（第二节）：补的是下面几项。

- **存哪**：新写入统一放 `model_runs.reasoning_text`（每次模型请求一份，所有阶段一个口径）。回复阶段现在的 `steps` kind=thinking 行，**新行停写**，旧行留着，界面读两处（读旧行的代码标"临时：旧行过了保留期以后删"，挂待办）；这样思考属于哪一次请求不再靠猜。
- **截断**：沿用 32 KB（`turn/turn.go:44`）、头 60% 尾 40%、写明省略多少字节（`store.Clip`）。所有阶段共用同一个函数。
- **体积估算**（粗估，**没有量过**）：一次请求的思考几百到几千 token，按平均 4 字节一个 token，约 1～12 KB，32 KB 封顶；一个回合 1～3 次请求，典型 5 KB 上下。私聊一天 100 轮约 0.5 MB；热闹的群一天 1000 次放行约 5 MB；守卫确认和整理走后台思考档（`app/guarddeps.go:118` 取 `Defaults.BackgroundThinking`，具体档位我没查，**待核实**），整理一天几十次、守卫确认只在相似度过了门槛时才调，估计合起来 1 MB 上下。对照[规格-数据与日志](规格-数据与日志.md)第八节"除媒体外每天 < 20 MB"，留得下。上线一周后用 `SELECT sum(length(reasoning_text))` 按天量一次，把真实数写回这里。
- **存多久**：Go 里现在没有任何清理（第二节）。要和数据与日志规格的清理一起做（第 2 步）。选项在第十节问题 1，**推荐：随模型调用明细 30 天，到期只清思考文字那一列，轮的骨架（时间、用量、工具名、结局）留到按天汇总**；主人没定之前按已批准的"明细 14 天"收紧。清理走后台维护，每次写一行日志"清了什么、多少、为什么"（不悄悄删）。
- **隐私**：只在本机的 `trace.db`；**不进程序日志**（沿用 `app.newLogf` 的打码，并加一条源码扫描：日志调用里不许出现 `Reasoning` / `Thinking` / `reasoning_text` 变量，4.7）；不进界面以外的任何接口；备份是否带 `trace.db` 待核实（[规格-数据目录与备份](规格-数据目录与备份.md)）。思考原文里会复述群友的话、被保护的记忆，所以：①"忘掉某人 / 某段对话"的清单要加上 `model_runs.reasoning_text`、`output_text` 和旧的 `steps` 思考行（对照[规格-记忆-v2](规格-记忆-v2.md)第 337 行那一串）；②拦下的那句话本身按规矩不存（`store/outbound.go:99`），思考里复述了它是模型的事，本机照显，不替主人过滤。
- **不回灌**：存下来的思考只给界面读。`Msg.Thinking` 只来自当次模型回复，**不许**从库里读回来塞进请求（第六节，测试：从库重建的实例，请求里没有任何 reasoning 字段）。现行的"同一实例内回传"不动，见 2.4。

### 4.3 读接口和订阅（`desktopread`）

沿用[规格-界面接Go后台](规格-界面接Go后台.md)第四节的风格：`internal/api` 加 DTO 和读方法，`desktopread` 实现；界面不 import 任何库，不碰 `database/sql`；发布后的值不可变。

- `ReadTurns(ctx, TurnRequest{Key, Character, Limit}, Cursor) -> Result[List[TurnCard]]`：一页卡片（默认 30，上限 100，越界报参数错误，不静默放大）。游标 = `(started_at, turn rowid)`，绑定会话和角色，换了会话的游标报错。
- `WatchTurns(ctx, TurnRequest) -> Subscription[TurnSnapshot]`：先登记订阅再读初始页，之后只发"变了的卡片"（按卡片 id 合并，旧页不能把新状态改回去）。
- `ReadTurnDetail(ctx, TurnRef) -> Result[TurnDetail]`：点开才读的大块——完整思考、工具参数和输出、注入的全文、闸门 features。**列表里的卡片只带摘要**（思考只带字数和第一行、工具只带名字和状态、注入只带条数和字数），防止 30 张卡一次读几百 KB。
- `WatchBackground(ctx, BackgroundRequest{Character, Limit}) -> Subscription[BackgroundSnapshot]`：后台时间线（阶段不属于任何回合、或属于回合但要在后台里搜得到的）。
- **trace 库的变更通知**：现在 `store.changed` 只在聊天库写入后触发（`store/changes.go:43-73`，调用点只在 `write.go`、`inbound.go`、`outbound.go`、`qq_alerts.go`），**`steps`、`model_runs`、`gate_decisions`、`turns`、`guard_checks` 的写入不通知**。要在共用的 trace 库上加一套同样的失效通知（键 = 角色 + 会话，后台调用用空会话），提交成功之后才标脏，容量为 1 的唤醒只负责叫醒，正文不走通道。
- 每个读方法都是可取消的后台任务，默认 5 秒时限；失败保留上一份成功快照并标"过时"，不清成空白。

### 4.4 一张卡片怎么拼（后台里做，前端只画）

- 卡片的键是 `turn_id`。一个回合的内容 = `turns` 一行 + 该 turn_id 的 `model_runs`、`steps`、`guard_checks`、`outbound_plans`（chat 库，按 turn_id 查）、`gate_decisions`（按 turn_id 查，可能多条：插话进来的几批各一条，`respond.go:258-263`）+ `input_seqs` 对应的 `events`（按会话和 seq 取，带 `observations` 过滤，只取该角色看到过的）。
- 卡片内部按时间排：看到的消息 → 闸门 → 第 1 次请求（注入只在第一次出现一次，之后只标"同上"）→ 它的思考 → 它之后的那批工具（用 `steps.batch` 分批）→ 第 2 次请求……→ 守卫 → 发送。同时刻的先后用 `(started_at, rowid)` 决定。
- "没接"行：`gate_decisions` 里 verdict 不是 forced / enter 的，每条一行，没有回合。连续的 skip / backoff 折成一行"N 条没接"（点开看每条理由），免得热闹的群把真正的回合淹掉。
- **三张表、两个库，不是一个原子快照**：`steps / model_runs / gate_decisions` 在 trace 库，`outbound_plans / events` 在聊天库（读的时候不同连接）。卡片的状态由 `turns.outcome` 和各部分的状态决定，**不由"某一段有没有出现"决定**：回合没结束时，没有"发送"段是正常的，显示"还在进行"；回合 done 而计划查不到，显示"发送记录读取失败"，不是"没发"。
- 回合没有结局（进程被杀）：下一个进程启动会收拾成 interrupted（`store/turns.go:55-102`），卡片显示"被打断"和不知道结果的工具。
- 卡片文字全是大白话一句理由（常驻），模型名、各项门槛、原文依据放折叠（设计语言第一节第 9 条）。

### 4.5 后台时间线

数据 = `model_runs` 里 stage 不是 reply / reply-retry 的行，加 `context_epochs` 里的压缩（已经在 model_runs 里有一行，用 epoch_id 对上，不重复显示）。每行：时间、阶段（用人话：整理记忆、压缩对话、守卫确认……）、角色和会话（会话用界面里的标题）、模型、用时、用量、结果（成 / 失败 + 错误种类中文名）、点开看思考和输出（`reasoning_text`、`output_text`）。可按阶段、角色、"只看失败"筛。由回合触发的（守卫确认）同时挂在那张卡片里，点开同一份详情，不存两份。

### 4.6 界面（mygo + CrychicUI）

- 位置：`native/ui.go` 的 `sideView` 第二个标签（`ui.go:239-251`）。标签内顶部一个分段控件"对话 / 后台"（我定的，问题 5 可改成独立标签）。
- 动手前照 LESSONS 先读 CrychicUI / mygo-m3e 的组件清单（组件库清单（私有存档））、它们自己的示例和规则文件，把"折叠面板、时间线、卡片、状态点、分段控件"对着现成组件找一遍，照最接近的排，找不到再写并在注释里写为什么；不先自己拼一版。
- 默认只展开最新一张卡；其余卡片只显示一行摘要（时间、结局、一句理由、用量），点开才读 `ReadTurnDetail`。思考默认折叠成一行"想了 N 秒 / 约 N token"（[信息架构](信息架构.md)第 272 行）。
- 顺序同聊天：旧的在上，新的在下，停在底部时自动跟随，离开底部不抢滚动位置；往上滚到头再读上一页（前插保持锚点，沿用第二版规格的锚点做法）。
- 长文本（思考、工具输出）放在有最大高度的滚动区里，文字可选中复制（`Selectable`）。
- 空状态逐个写清：没选会话；还没有任何回合；Go 后台只在看历史没有接收（"只在看历史，这里不会有新的回合"）；本地群聊还没有接入；旧记录没有关联键。读失败显示错误，不转成空。
- 说明文字按设计语言第十一节：常驻最多一行。

### 4.7 防止以后新入口悄悄不记的检查

放在 `internal/archcheck`（合并前总会带上，ADR-225）。`turn` 要用 `chat.Request / llm.Model / llm.Result` 这些类型，所以"禁止 import `internal/llm`"这条路走不通；选**扫源码**，理由：不用拆类型、改动最小，缺点是只认字面写法（所以再加运行时那道）。

1. **扫调用点**：用 `go/parser` 扫模块下所有非测试 `.go` 文件，找名为 `Stream` 的方法调用，文件必须在白名单里（`turn/hub.go`、`turn/compact.go`、`app/guarddeps.go`，加 `cmd/` 下列出的几个离线工具，每个写一句原因）。新增调用点的文件不在白名单里就红，提示"请先在 llm 登记表里加 Stage，再把文件加进白名单"。
2. **扫 Stage 名**：所有 `llm.Purpose{Stage: …}` 的字面量，Stage 必须是登记表里的常量；登记表里每一项必须在本规格 2.3 的表里出现（对着文字查名字）。
3. **运行时那道**：`Client.Stream` 无 Purpose 或 Stage 未登记就拒绝（4.1 第 2 条）；加一个表驱动测试，对登记表的每一个 `recorder` 阶段用假网关调一次，断言恰好多一行 `model_runs` 且 `error_kind` 对（成功为空、网关返回 500 为 `call_error`、总时限到为 `timeout`、读不懂为 `bad_output`）；`kernel` 阶段断言记录器**没有**再写一行（不重复）。
4. **扫日志**：非测试代码里，日志函数（`logf`、`slog.*`、`log.*`）的参数不许出现名为 `Reasoning`、`Thinking`、`reasoning_text` 的标识符（4.2 隐私）。
5. 每条规则写完先故意改坏一次看它真红（LESSONS：新加检查要真跑过红）。

| 非回复阶段的输出文字 | 8 KB | 整理的输出是一份 JSON，守卫的是 yes / no |
| 读时限 | 5 秒，可取消 | 第四节 4.3 |
| 变更合并 | 订阅端 200 毫秒内合并成一次重读 | 工具循环里 steps 变得快 |

## 六、禁止的偷懒写法

- 不许在界面线程查 trace 库、聊天库或读 `prompt_sections`；全部在 worker，界面只收不可变快照。
- 不许前端拿几份接口自己拼时间线（旧规格 §8 第一条）：关联在 `desktopread` 里做，前端只画。
- 不许把提示词全文、`prompt_sections` 全文、原始 JSON 塞进卡片或列表快照；要看走 `ReadTurnDetail`，且默认只给"注入的参考信息"这一段。
- 不许在关联键缺失时用时间窗去猜"这个闸门判断属于哪个回合"（猜错了就是把别人的理由安给了这一轮）。
- 不许把库里存的思考读回来放进 `Msg.Thinking` 或任何模型请求。
- 不许根据注入文字的内容给记忆编造范围标签；没有就写没有。
- 不许绕开"拦下的、已打断的、出错的计划不存原文"：卡片只显示理由，不向别处找回原文。
- 不许给 `error_kind` 以外再发明一套字符串；中文名由一张表映射，测试覆盖每个取值。
- 不许新入口直接 `Stream` 而不带 Purpose（4.7 的检查会拦，也不许用空 Purpose 糊弄）。
- 不许为"后台"和"对话"各做一套卡片外壳、折叠、状态点组件。
- 不许只在宽窗口验收；右侧栏在窄窗口是盖在上面的抽屉（[信息架构](信息架构.md)第 25 行）。
- 不许在日志里打思考原文、记忆原文、守卫的待判文字。

## 七、已知的坑（对照常见边界情况清单）

- **④生命周期**：窗口隐藏时订阅不取消（沿用第四节 7 条），但隐藏时只记脏标记，不重读；切会话 A→B→A，A 的迟到结果按请求代次丢掉；退出时订阅先于库关闭。
- **⑤归属维度**：同一个角色在不同会话、同一个会话里不同角色、四种场合。卡片键 = 平台 + 会话 + 角色 + 回合；"全部"视图不是把几个角色的东西并成一张卡。QQ 群里两个号都看到同一条消息，各有各的回合。
- **⑥权限与执行对象**：右侧栏是只读窗口，查看历史不触发任何模型、工具或记忆整理；不提供"重跑这一轮"。
- **⑧到达与可用**：`gate_decisions.turn_id` 要等回合号拿到才回填（`respond.go:477`）；回合进行中卡片先出现、后补闸门段，界面要容忍"先有回合、后有关联"。
- **⑩部分失败**：有 `steps` 没有 `model_runs`（请求中途被停）、有思考没有正文、有计划没有发送结果、进程被杀留下 running 的工具（收拾后变"不知道结果"），每种各画一个样本。
- **⑪口径**：缓存命中率 = `cacheRead ÷ (input + cacheRead)`；`reasoning_tokens` 已含在 `output` 里（`llm/llm.go:172`），不要再加一遍；时间一律毫秒。
- **⑬并发**：同一个会话的回合排队（`respond.go` 的屏障）、守卫的路线原子量被并发覆盖（4.1 第 6 条）；变更通知要在提交之后；读和写不同连接，只读连接不能影响写。
- **⑭非原子**：三张表两个库，见 4.4；卡片状态由回合结局定。
- **⑯空值**：思考为空但 `reasoning_tokens` > 0；`ttft_ms` 为空（没出过正文）；`usage` 没收到（`rt = nil`，`loop.go:502-505`）；`input_seqs` 为空；会话名为空。
- **⑲缓存**：界面不缓存跨回合的内容；`prompt_sections` 按哈希取，哈希相同全文必同。
- **⑳时间**：展示用本地时区，存的是毫秒；回合开始的时间取 `turns.started_at`，不取第一条事件。
- **㉑隐私旁路**：思考文字会被复制到第二处（旧 `steps` 行 + 新 `reasoning_text` 的过渡期）、会进备份、会在"忘掉某人"时漏删——4.2 逐条列了；导出 / 复制按钮如果以后加，复制的是主人选中的文字，不是整份记录。
- 其他：`ReasoningDetails` 只有加密块时界面写"服务商没有给文字"；同一回合重试的 `reply-retry` 行要在卡片里标成"第 N 次请求出错，已重试"，不当成一次独立请求；压缩那一行也是一次请求，别把它的思考挂到回复上。

## 八、验收

测试只用临时数据目录和编出来的数据，绝不读写真实 `data/`。

1. **数据**：临时库里按第二节每一栏造样本（`cmd/desk-fixture` 已有十倍造数据，沿用并加 trace 侧的行），每种结局各一个，不靠"碰巧排第一"：说了、试运行、看了没说、没接（八种 verdict 各一）、保险丝、守卫拦下（字面 / 相似度 / 确认 yes）、守卫没判成、被打断、出错、进程被杀后收拾的、带工具带审批的、思考只有加密块的、旧行（无关联键）。
2. **读接口**（`desktopread` 测试）：按回合拼出的卡片内容和独立 SQL 算的集合一致；四种场合各一组（本地私聊、本地群聊为演示假群、QQ 私聊、QQ 群两个角色），断言：角色 A 的卡片里没有角色 B 的注入和思考；私聊和本地没有闸门段；分页顺序、游标跨会话报错；订阅先登记再读、订阅关闭后不再查库；trace 库写入后能收到通知（`steps`、`model_runs`、`gate_decisions`、`guard_checks` 各一）。
3. **统一记录**（4.7 第 3 条）：表驱动，每个登记阶段 × 四种结局；故意拆掉记录器 / 拆掉某个阶段的 `Annotate` / 拆掉 Purpose 检查，各自要红。
4. **隐私**：①日志里没有思考文字（扫源码 + 跑一轮后读日志文件断言）；②从库重建的实例，发给假网关的请求里没有 `reasoning_content`、`reasoning`、`reasoning_details`；③拦下的计划，卡片上没有原文；④"忘掉某人"清单测试里加上新列。
5. **界面**（`ui.NewTester` 读布局和状态，`MYGO_FRAME_STATS` 量帧耗时，见 `native/README.md`）：宽窗口、窄窗口抽屉各一组；默认只有最新一张展开；折叠的卡片没有思考正文元素；角色切换后只剩那个角色的卡；"没接"折叠和展开；4.6 列的每种空状态各一个；切会话 A→B→A 迟到结果不覆盖。
6. **放大十倍**（沿用[规格-界面接Go后台](规格-界面接Go后台.md)第九节）：10 个角色、一个群 1 万个回合、很长的思考（接近 32 KB）、一个回合 30 次工具调用，各试一遍，汇报量出来的数：点开标签耗时、元素数、帧 p95、超过 100 毫秒的帧数、驻留内存；第五节的预算对着这些数改写，不写"看着不卡"。
7. **手点清单**：对着真实的 QQ 小号私聊，点开最近一张卡和一次守卫拦下，原话、理由、思考对得上；整理一次记忆，后台时间线出一行并能点开。写在手试清单（私有存档）旁边另起一份。
8. 新页面交付前按[设计自查](设计自查.md)过一遍，不过的条目写进提交说明；改了字号、间距的同提交更新基线（LESSONS）。
9. 合进 main 之前按 `AGENTS.md`「验收」跑 `bun scripts/go-verify.ts`；提交说明里抄最后一行。
