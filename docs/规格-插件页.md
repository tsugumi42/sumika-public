## 一、放在哪

- 设置页左栏"通用"组里，"外观"下面加一项"插件"（图标 puzzle）。点了右边主区换成插件页；窄窗口照外观页的返回链。
- 主区骨架照外观页：顶部标题行（"插件"）、下面滚动区、内容居中限宽 `settingsWidth`。

## 二、页面结构（从上到下）

1. **搜索**：用左栏现成的"搜索设置"（页面里不再放第二个搜索框，原型-主人标注里搜索本来就在第二栏）；搜插件名、一句话说明、配置项名字；不区分大小写。有搜索词时，配置项名字命中的插件自动展开、只显示命中的那几项；没有结果写"没有找到「词」"和"清除"按钮。
2. **要重启的提示条**（只在有改动要重启时出现）：和插件卡同一种浮起的底加细边、四边等距（主人 2026-11-07：原来浅强调色底配强调色按钮太花、四周不等距），左边强调色的刷新图标 + "有 N 个插件的改动要重启接收才生效"，右边主按钮"重启接收"。点了以后假装重启（1 秒转圈），然后提示条消失。不在每一项旁边重复写"需要重启"。
3. **插件列表**：每个插件一张卡（圆角面板，卡与卡之间 `spaceSmall`）。排序：核心插件在最上面，然后是出错的，其余照原来的顺序（主人 2026-11-07："把那些不能关的核心插件优先排在上面"）；不加"核心"之类的组标题（主人："其实我觉得不太应该分能不能关的核心插件"）。

## 三、一张插件卡

- 卡的圆角 = 控件圆角 + 卡内距 + 展开区内距，和展开区里的控件同心；顶上那行按钮的悬停底圆角 = 卡圆角 − 卡内距。开关放在四边等距的格子里，右缘和展开区控件的右缘对齐；数字框的单位写在框里靠右（主人 2026-11-07 截图：开关贴边、单位挂在框外没对齐）。
- **折叠时一行**：左边图标格子（插件自己的图标，角色无关、用强调色）；中间第一行插件名（正文、500），第二行一句话说明（Text2、FS2、一行截断）；箭头靠最右边、单独是一个按钮（点它和点名字一样展开），开关在箭头左边（主人 2026-11-07："框的这个应该靠在最右边，那些开关什么的就往左一点交换位置"）；箭头右缘和展开区里控件的右缘对齐。
  - 点开关只切开关，不展开；点行的其余部分（包括箭头）展开、收起。开关不放进展开按钮里面（避免整张卡可点又套按钮）。
  - 没有开关的在开关的位置写为什么（主人 2026-11-07："有一些插件为什么没有开关"）：不能关的（Core，如记忆、渠道回复）写"总是开着"（ADR-291：这是还没做到能关的现状，以后都要能关）；按会话开的（复读、戳回去，后台本来就没有总开关）写"N 个会话"。开关格子宽固定、内容靠右，各卡的箭头对成一列。
  - 出错的：名字后面挂危险色角标，第二行换成错误原因（危险色、一行截断），展开后全文。
  - 开着但这次改动还没生效（要重启的）：名字后面挂一个小圆点（强调色），悬停提示"重启接收后生效"。
- **展开后**：卡里隔一条细线，下面从重到轻分两段（主人 2026-11-07："应该先配置这个插件在哪一个平台开启，接着配置在这个平台内的哪一些群或者私聊里面开启，最后才到各个功能的配置"）：
  1. **在哪里用**（小标题，正文色加粗）：先是"平台"（本地、QQ，多选小标签）；选了的平台下面按四种场合各一行（本地私聊、本地群聊、QQ 私聊、QQ 群，照词汇表），右边下拉选"全部 / 只在这些 / 除了这些 / 不开"；选"只在这些""除了这些"时下面一行列这个场合里已知的会话来挑（"在这些里开""这些里不开"），只能挑这个场合的。插件不支持的平台和会话种类不出现（复读只有群聊，戳回去只有 QQ）。她自己用的工具（技能、联网、子任务、MCP、项目说明）范围不能改，只写一行"只在你和她的本地对话里用……安全边界"——执行类工具只给主人在本地主窗口（AGENTS 安全边界），不做成能选的样子；渠道回复写"所有会话"。
  2. **设置**（同样的小标题）：插件自己的功能配置，一项一行，照外观页的行：左边名字（下面可选一行灰色说明，最多一行），右边控件。生效方式写在"设置"这一行的右边：能热改的写"改了马上生效"，要重启的写"重启接收后生效"（Text3、FS1）；没有配置项的写"没有可调的设置"。
  - 搜索命中具体配置项时只显示那几项，"在哪里用"不显示。
  - 依赖（有的话，照 ADR-289 必须在插件清单里声明）写在生效方式下面一行："需要：记忆（已开）"，没满足的危险色。
  - 插件关着时，展开区的配置项照样能改（改的是下次开时的值），整体降一档透明度提示"现在没在用"。
- **配置项的控件**（按类型自动选，不为每个插件手写）：
  | 类型 | 控件 |
  |---|---|
  | 开关 | switchControl |
  | 二到三个选项 | segment |
  | 四个以上选项 | choice（下拉） |
  | 有范围的整数 | 数字框，单位写在框里靠右；越界时框变危险色、下面一行写范围，不保存。不用每次手打（主人 2026-11-07）：按住单位左右拖，每 4 DIP 一格；鼠标在框上停满 0.35 秒以后滚轮一档一格（触控板 24 DIP 一格），往上变大；按住 Shift 一格是 10；都夹在范围里。停不满就照常滚页面——滚整页时框从鼠标底下滑过去不会误改（浏览器的数字框只在有焦点时响应滚轮，是同一个顾虑）。不在数字上拖：点数字是要放光标、选字的 |
  | 文字 | textField |
  | 从已知里挑的名单（会话、角色） | 一排小标签，每个带 ×；最后一个"添加"按钮弹出菜单，只能从已知的里挑（规格-链接自动展开第七节：不手输号码） |
  | 多选的固定项 | 一排可点的小标签，选中铺强调色浅底 |
- 后台还没接上的配置项**不显示**（不做点了没反应的空开关）；在配置文件里但不归插件管的（模型、审阅）不放这页。

## 四、原型里的插件（假数据，形状照 Go 后台 main 的真实配置）

| 插件 | 能关 | 生效 | 配置项 |
|---|---|---|---|
| 记忆 memory | 不能 | 重启 | 在哪里用：写入的场合（默认只开本地私聊，即主人私聊）。设置：写入的角色（名单）、自动确认（开关）、确认次数（整数 ≥2）、确认的种类（多选：事实、承诺、偏好、边界） |

| 复读 repeater | 按会话 | 重启 | 在哪里用：只有群聊，默认 QQ 群"只在这些"、一个也没挑（群里默认关）。没有设置项 |

| 子任务 subagent | 能 | 重启 | 用的模型（下拉）、最多同时几个（1～8） |
| 项目说明 projectcontext | 能 | 重启 | 信任的目录（名单）、读用户级说明（开关） |

复读、戳回去是"按会话开"的：卡上没有总开关，开关的位置写"N 个会话"（照"在哪里用"在已知会话里数）。

接真实后台时要对的：链接解析现在的"展开"有自己的白名单（`linkReader.expand.mode / conversations`），"读链接给她看"没有范围；原型把两者并成一个"在哪里用"，接后台前要定是给展开用、还是两样都按它管。

## 五、禁止的偷懒写法

- 不为每个插件手写一套界面：配置项用一张描述表（类型、范围、单位、生效方式）渲染，加插件只加数据。
- 不在开关旁边再摆"已开 / 已停"的字（状态就是开关本身）。
- 不在每一项旁边写"需要重启"；统一走提示条和插件名后的小圆点。
- 名单不做手输框。
- 不读真实 `data/`；测试只用假数据。

## 六、已知的坑

- 展开、收起要有动效（照过程气泡的箭头旋转 + 高度过渡），减少动态时直接切。
- 开关在展开按钮外面：键盘 Tab 先到展开按钮、再到开关，Enter / Space 各管各的。
- 搜索自动展开的卡，清掉搜索词后回到搜索前的展开状态（不把用户手动展开的收回去）。
- 100 个插件时不卡：原型实测 Tester 里最长一帧 7.5 毫秒（2026-11-07，TestPluginsScale），先不上虚拟列表；接真实后台、插件多到量出卡顿再换 `ui.List`。
- 长插件名、长错误原因一行截断，不把开关挤走（X02）。

## 七、验收

1. Tester：十个插件都画出来；点开关只切开关不展开，点行展开、再点收起；不能关的没有开关；出错的排第一、带角标。
2. 搜索"超时"：链接解析和联网自动展开、只显示命中的项；"没有这种词"显示空状态和清除，清除后回到原来的展开状态。
3. 改一项"重启接收后生效"的设置 → 提示条出现、计数对、插件名后有小圆点；点"重启接收"→ 提示条消失、小圆点消失。改"马上生效"的不出提示条。
4. 数字越界不保存、框变危险色；名单添加只能从已知会话里挑，× 能删。
5. 0 / 1 / 100 个插件（X05）：空状态一行；100 个滚动不卡，量出主线程最长一帧。
6. 几何：卡片、行、控件全部登记 `a.surface`，过 `TestSurfaceGeometry`、`TestGeometryHasNoBypass`、`TestNoTextGlyphIcons`、`TestEmptyStatesOneLine`；2048×1030、1.25 下截图。
7. 按 [设计自查](设计自查.md) 过一遍，不过的写进提交说明。

## 八、要主人定的（原型做完一起问）

- ADR-238 写"每个能开能关"，规格-链接自动展开第七节写"没接上的不造开关"。原型的做法（暂定，我定的）：能关的插件给开关，没接上的配置项不显示——两条都满足。
- 记忆、渠道回复算 Core 不给关（照 issue #16；已被 ADR-291 改为：核心插件以后也要能关，"总是开着"只是还没做到）；记忆的"写入"其实能关（`memory.write.characters` 为空就是只读），要不要把"写入"做成卡上的开关，等主人定。
- 接真实后台时配置写回哪里：现在 Go 只有一个 `sumika.yml`（链接解析已经能从设置页写回并热更新，`app/linksettings.go`），ADR-065 第 3 条的"按插件家族分文件"没做。
