主人 2026-11-09 看真窗口：消息发出后过一会儿才瞬间跳出来；思考期间看不到思考和工具；流式一大片一大片；回复先错位、展开超出画面、跳到上面、底下留白，百来毫秒后才到位。“看起来特别卡卡的，像没有优化好的样子。”

## 一、原因

1. 正在生成的回复画在输入框上方、最高 200 的滚动框里（`workbenchDraft`），不在消息列。它把输入框撑高，消息列底边跟着动；收尾时真消息进列表、草稿消失，输入框缩回去，又动一次。主人看到的错位和留白就是这两次。
2. 这个草稿气泡是纯文字，没有接 `markdown.Stream`，所以字是一片片出来的。
3. 自己的话要等写进库、订阅推回来才进列表。
4. `api.LocalRunSnapshot` 只有正文，没有思考和工具，过程气泡没有数据。

## 二、做法

消息列是唯一的显示位置，输入框高度只由输入内容决定。

- **发出的话**：点发送当场在列表末尾加一行（`Sending` 状态），带进场动画，滚到底。真消息到了原地接替，不重播动画；被后台拒收就撤掉这一行，内容回到输入框。
- **她的回复**：提交成功后列表末尾是“正在输入”；有字了变成流式气泡（她的气泡样式，走 `markdown.Stream`）。这一步存库后等真消息接替，接替时列表键不变，高度不跳。
  “正在输入”只在她真的在等的时候画：有工具正在跑（当前这一轮的过程气泡里有转圈的工具步）、或有字在出时先藏起来；工具刚结束、模型还没出字时回来，回来的还是同一行（列表键不变，不重放入场）。本地私聊、本地群聊同一套（`localRun.toolRunning`，`live_typing_tool_test.go`）。
- **接替规则**：只认这一轮开始之后的、同方向的第一条真消息。发出的话按“我说的、时间不早于发送前 2 秒”认；回复要等后台说这一步已存（`SealedStep`）才认，不比较文字，清理过的正文也接得上。接替后 3 秒还没等到就撤掉，不留假消息。
- **多步**：每一步一个气泡，步之间的思考和工具进过程气泡（第二步）。
- **本地群聊**：和私聊同一套（2026-11-09）。一轮里好几位成员轮流说，`api.LocalGroupSend` 的 `Draft`、`Process` 把每位成员的流式正文和思考、工具交给界面；换人时步号重来（`live_group.go`），真消息按“谁说的”接替。旧的草稿框已删。

### 程序退出时被中断的回合（2026-11-09，fix/tool-interrupted）

步骤只在回复存库时才挂到回复上（`AttachSteps`）。回合在工具跑着时被中断（正常退出或进程被杀）就没有回复，步骤挂不上，重启后读不出来，这次工具调用整个不见了。做法：

- 工具一开始就有记录（`steps` 行，状态 running，参数在 `args_json`），这一点早就是这样；缺的是退出后的落脚处。
- 退出时把没挂上回复的步骤挂到一行系统行上（`store.SurfaceInterrupted`，来源 `system:turn`，写在本地会话的聊天记录里，和 /goal、定期任务的系统行同一套，不进她的历史和记忆）。文字是“程序退出时，这一轮被中断了：N 个工具没有跑完，结果不知道”。聊天区把过程气泡画在这行前面，用当时说话的角色的名字和颜色（`msgFromView` 给系统行带步骤时造过程行）。
- 两条路都留：正常退出时回合收尾处（封口后被停下的回合）、被杀时下一个进程建 Hub 收拾之后（只处理这一次收拾记成被打断的回合）。只给本地会话（`console:` 开头）留行，QQ 的聊天记录不写。同一个回合只出一行（`segments.turn` 认），重复调用不多出。
- 状态：被切断的工具在 `steps.details_json` 里记 `interrupted`：`stop` 是点停止或回合被取消切断的，`exit` 是程序退出时还在跑的（正常退出收尾把 `stop` 改成 `exit`，被杀由收拾直接写 `exit`）。界面上两种都是“停了”（不转圈，也不是成功）；`exit` 的展开处第一句写“程序退出时中断：这一步没有跑完，结果不知道，可能已经执行了一部分。”，命令和已有的输出还在。已有的输出多半拿不到：工具被切断时返回的是合成结果，真实输出没存下来。
- 旧库：旧版本收拾的行没有标记，认它写下的预览（`状态 error 且预览是收拾写的那句`）；旧的被打断回合不替它们补系统行（那些库里的行是真实数据，补写要主人点头），以后需要再单独做一次迁移。
- 异常行：`unknown_tools` 不是合法 JSON 的回合在找“该提醒的工具”时跳过，不挡别的；没有步骤、步骤已挂在回复上的回合不写系统行；回合行不存在时标记函数什么都不改。

## 三、参数

- 接替等待 3 秒；发出的话时间窗 2 秒（同一台机器的时钟）。
- 流式节奏用 `markdown.Stream` 默认（规格-过程组件 3.7）。

## 四、禁止的偷懒写法

- 把草稿框挪个位置或调高度了事；用定时器猜消息到了没有。
- 给真消息改 id 来接替（回复、引用、媒体都认后台的 id）。列表键单独存。
- 文字对不上就当两条都显示。

## 五、已知的坑

- `a.msgs` 被很多地方按下标用，临时行要排在末尾、每次合并后重排（`reconcileLive`），不能散落。
- `arrivals.enter` 的水位线按 seq 算，临时行没有 seq，进场要单独标记，也不能推高水位。
- 真消息的 `markdown` 状态按消息 id 存，接替时还没淡入完的字会一次出完。

## 六、验收

- 发送后同一帧列表里就有这句话，输入框清空；真消息到了行数不变、列表键不变。
- 回复全程输入框高度不变；出字过程中消息列底边不动。
- 拒收时临时行消失，内容回到输入框。
- 回归测试覆盖：发出、接替、拒收、一步回复、两步回复、接替超时、切会话。
