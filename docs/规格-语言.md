## 零、先说人话（给主人）

笔记里研究的"像真人一样在群里说话"，拆开其实是四件事，顺序不能反：

1. **接谁**：这句话是对谁说的、在聊哪件事。群里几个话题交错，接错对象比说错话更尴尬（"出了！""我又歪了""我说的是新衣服""笑死"，回 B 一句"恭喜"就是接错了）。
2. **做什么**：这一轮是回一句、贴个表情、追问一句、接梗、还是不说话。"不说话"是正经选项，不是失败。
3. **怎么说**：用她自己的口吻，长短、断句、语气词、要不要拆成两条。
4. **学什么**：从真人聊天里学表达和黑话，但学到的只是"可以用的材料"，**不能把她改成群友的样子**。

这份规格的原则：

- 前两步尽量用规则和小模型做，大模型只负责第三步写出来，**不新增第二次大模型调用**（速度目标 ADR-011/016）。
- 系统提示里只写原则；例句、黑话、表达习惯放在库里，**按需取最多 3 条**，取不到就一条都不给。
- 学习只学真人的话：她自己说的、插件替她发的、主人用她的号发的，都不当素材（消息来源 `origin`）。
- 黑话分三档：看得懂 < 别人用了能接 < 自己主动用。主动用**默认关**。

## 二、现状

- 发言：小模型闸门决定叫不叫醒，角色主模型一次完成"想不想说 + 说什么"；@ 她、回复她、主人的消息不等合并窗口（约 2.5 秒）；发送前检查有没有更新的消息。
- 人设：核心人设（主人写）+ 成长层 + 漂移检查；提示词"只写原则，不堆场景例子"。
- 分条：提示词里说"按空行拆成几条发"；没有节奏控制。
- 表情：小黄脸三级来源、三套编号、表情回应能收能显示；她还不会主动贴表情回应。
- 表达学习 L2 已做（50d9b07，现状见 subsystems/expression.md（私有存档））；黑话、对话链没做（待办 二）。

## 三、技术路线

### 3.1 接谁：对话链

每条群消息在进回合之前，先给出"它在接谁"（规则为主）：

1. **强线索**：引用回复、合并转发里的上下文 → 直接确定父消息；只有 @ 没有引用的，按 ADR-067：连到被 @ 的人 5 分钟内最近的一条，算强线索不算定论，内容明显对不上时不硬连（细节见[规格-群聊闸门](规格-群聊闸门.md) 2.1）。
2. **弱线索**：同一个人连发（间隔 ≤ 30 秒）算一簇；时间间隔、说话人轮替、提到的人 / 事物（别名表，见规格-记忆 3.6）→ 给最近 100 条或 30 分钟内的候选打分。
3. **拿不准的**：交给小模型从候选里选，允许答"新话题"或"不知道"，不强迫归类。

每条消息记：`thread`（话题编号）、`parent_seq`（接的哪条）、`link`（`quote` / `mention` / `burst` / `guess` / `model`）、`confidence`。一条消息可以提到几条线，只选一个主归属；线可以中断后再接上。

ChatGPT 建议的阈值：≥ 0.80 直接连，0.55～0.80 交给小模型，以下不连。**都是起步值**，用回放样本校准。

第一版只在平台群聊和回溯学习里用；本地私聊、平台私聊不需要。

### 3.2 做什么：动作

分两层，名字固定，**只在代码和追踪里用，不写进提示词当模板**：

**理解侧：对方那句话在做什么**（笔记扩02，15 个）：真提问 / 反问表态 / 震惊 / 真赞同 / 敷衍附和 / 结束争论 / 善意吐槽 / 带攻击的讽刺 / 认真纠错 / 搭话 / 复读 / 接梗 / 转移话题 / 安慰 / 沉默。附带作用对象、可能的其他读法、置信度。推测是临时的，**不写进长期记忆、不当成对方的性格**。

**行动侧：我这一轮做什么**：外层 `skip` / `reply` / `wait`；`reply` 里一个主动作（笔记扩29，13 个）：

`silent` 不说 · `ack` 简短回应 · `react` 贴表情回应 · `brief_comment` 一句评论 · `answer` 回答问题 · `continue_joke` 接梗 · `light_tease` 轻调侃 · `shift_topic` 转话题 · `clarify` 追问一句 · `admit_error` 认错 · `correct_once` 纠正一次 · `set_boundary` 设边界 · `send_sticker` 发表情包

（笔记里冲突、攻击、不确定几篇的细分动作，当成这些动作的子类型，不另起一套。）

谁来选动作，已定（第九节第 2 条）：**闸门多输出一个动作草案和目标消息**，角色主模型拿到它再写，可以推翻；不新增调用。

快路径（不等合并窗口、不叫醒大模型）：被 @ 或被回复时**必须及时决定**（不等于必须回一段话）；已知的表情回应（同意、惊讶、轻调侃）直接走表情回应，不进回合。

### 3.3 怎么说：提示词的组织

角色卡拆四块（MaiBot 的 personality / behavior_style / reply_style，笔记扩26 的 C1+C2 / C3；第四块"私下"是 2026-10-20 加的，ADR-123，原来是三块）：

| 块 | 内容 | 位置 |
|---|---|---|
| 身份 | 价值、底线、驱动力、3～6 个标签（每个带触发前提和反例） | 固定前缀 |
| 行为 | 怎么参与聊天：什么时候插话、对新人 / 熟人、被攻击、自己犯错时怎么做 | 固定前缀 |
| 表达 | 长短句、标点、语气词、笑声写法、认错和拒绝的说法、梗密度 | 固定前缀 |
| 私下 | 外貌、对主人的亲近这类只在私聊和主窗口用得上的内容；可以没有 | 固定前缀，**群聊不拼**（私聊、主窗口拼） |

"私下"只看这一轮是不是群聊（`isGroupTurn`），同一个会话里不变，所以同一个实例的固定前缀不变，缓存不受影响。群聊那份少了这一块以后固定部分少约 12%，开口、多嘴、路人、熟人四项没看到变差（confirm4，ADR-123）。

再加两层：**场合**（四种场合各一段，见 3.8）、**平台**（QQ 的格式限制）。都在固定前缀里，整个纪元不变。

每轮变的东西——对面是谁（关系）、检索到的记忆、取到的表达和黑话、动作草案——一律放**只追加的尾巴**（规格-插件第七节、ADR-022）。`设计.md`「提示词的组织」里"核心人设 → 场景 → 平台 → 关系"是逻辑顺序，不是缓存位置，改的时候顺手写清。

**例句的位置**（第九节第 3 条）：系统提示只放原则和 3～4 条说话约束；"情境 → 例句"放在表达库里，按需取 ≤ 3 条，带来源、可撤销。笔记扩26 的场景规则（新人 / 熟人 / 被攻击……）用作**写卡的检查清单和评测题**，不整段塞进提示词。

**每个角色的说话指纹**（笔记母页 §9）：平均字数和长尾、分条偏好、标点习惯、常用开头词和句末语气词、笑声写法、表情偏好。这些从她自己的历史统计出来，**给漂移检查用**，不是给她模仿的目标。

**学到的表达不改人设**：角色卡（主人写）> 学到的风格（可衰减、可撤销）> 本轮取到的表达。防止几个角色在同一个群里越聊越像同一个人（笔记扩05 的互相模仿）。

### 3.4 表达学习（学说法）

> 2026-10-19 起叫法统一叫"说法"（ADR-096）：这一节和 3.5 学的东西存进同一个说法库，一条说法记"什么意思、什么情境下用、她能不能自己用"；这一节是"大家在什么情境下怎么说"那种学法。

> 2026-10-16 细化，主人定了（ADR-054），已实现（L2，50d9b07）；现状以 subsystems/expression.md（私有存档） 为准。MaiBot 1.3.5 的源码细节见 notes/MaiBot-表达学习-源码.md（私有存档）；下面每处标了"和 MaiBot 不同"的，是按我们的架构改的。

学什么：`{情境, 说法, 来源消息}`，各 ≤ 20 字，去掉人名和具体名词（MaiBot `learn_style`）。学到的是**公共材料**，不是哪个角色的性格；用不用、怎么用由每个角色自己挑（3.3 最后一段）。

#### 3.4.1 存在哪

**放公共库，不放每个角色的记忆库**（和 MaiBot 不同：它一个 Bot 一份）。群里的说法对所有角色都一样，学一次大家共用：两个角色就省一半学习调用，以后角色越多省得越多。位置 `data/shared/learning.db`，和 ADR-012 的公共知识层、ADR-034 第 5 条的"全局 / 某个群"范围放在一起，L3 的黑话也用这个库。（原来写的"存进各自 `facts`、`kind = expression`"作废。）

**情境和说法分两层**（主人 2026-10-16：意思相近应该是使用情境相近）：一个情境下面挂好几种说法，合并的是情境，说法各留各的；回复时先按情境找，再从这个情境的几种说法里挑一种（见 3.4.3）。

四张表：

| 表 | 字段 | 说明 |
|---|---|---|
| `situations` 情境 | `id`、`text`（≤ 20 字）、`first_seen_at`、`last_seen_at` | 一行一个情境，不分范围（不同群里相近的情境合成一个，范围记在说法上）；向量存这一层（`情境` 文字，用现有的嵌入子进程，本地，不花钱） |
| `expressions` 说法 | `id`、`situation_id`、`style`（≤ 20 字）、`style_norm`（去空格标点、统一大小写，用来查重）、`scope`（`conv:<群>` / `global`）、`status`（`candidate` 候选 / `pending` 等审核 / `active` 可用 / `rejected` 拒绝 / `retired` 退休）、`reviewed_by`（空 / `ai` / `owner`）、`review_note`、`speakers`（几个不同的人说过）、`hits`（一共学到几次）、`convs`（几个群见过）、`first_seen_at`、`last_seen_at`、`origin`（`learned` 学来的 / `seed` 导入的种子） | 一个情境下的一种说法 |
| `expression_evidence` 证据 | `expression_id`、`event_seq`、`conversation`、`speaker`（人物表的 id）、`quote`（原话，≤ 60 字）、`at` | 每次学到记一条；替代 MaiBot 只增不减的 `content_list`，能回查"谁在哪说的"。某个号后来被认出是 AI，按 `speaker` 把它贡献的证据撤掉、重算 `speakers`，不够的说法退回候选 |
| `expression_fit` 合不合她 | `expression_id`、`character_id`、`fit`（`good` / `ok` / `bad`）、`reason`、`used_count`、`last_used_at`、`owner_block`（主人说"她别用这句"） | 每个角色一行；取用时只读这张表，不调模型 |

#### 3.4.2 流程

1. **什么时候学**：和后台总结一样的时机（安静 10 分钟或攒够 40 条），但**按会话跑、不按角色跑**：一个群不管几个角色在，只学一遍。每个会话一个游标 `learn_state.last_seq`，只看新消息。（2026-10-16 实现：后台总结只在她回了话以后才触发，群里她不回话，所以表达学习自己每分钟看一遍；游标从插件第一次启动时开始，之前的几千条不回头学。和 MaiBot 不同：它挂在上下文裁剪上，滞后约 40 条，冷清的群几乎学不到。）
2. **取素材**：按上面的开关挑会话；只要 `origin` 是 `peer` / `owner` 的文字消息；去掉命令、只有图片表情的、她们自己的话；标成 AI 的号照常学、审核时注明（ADR-055，3.4.5）。剩下不到 8 条就不学，等下次。
   - 自检的、她看不到的（陌生人私聊）不算素材；补录的算（已被 ADR-101 改，ADR-092 原来是补录的也不算）。过滤写在 `daemon/util/material.ts` 的 `learnSql`（记忆总结用同一个文件里的 `notTagged`，补录的不进总结）；过滤在取消息时就做，一批 200 条按过滤以后的算。
   - 一批 200 条里能学的不到 8 条（一整段都是图、表情）时游标照样往前走，不卡住（ADR-092 第 4 条）。
3. **抽取**（后台模型调一次）：提示词照 MaiBot `learn_style` 的思路改写，输出 `[{situation, style, source_seq}]`；`source_seq` 用真实的事件编号，不用批内序号。最多 10 条，**多了截断，不整批丢**（MaiBot 超过 20 条就全丢）。
4. **代码校验**（不调模型）：zod 校验 JSON；情境、说法各 ≤ 20 字；`source_seq` 必须在这一批里、来源是允许的 `origin`；**说法要能在原话里找到**（去掉"xxx"占位后的字面部分是原话的子串，或者编辑距离够近），找不到就当模型编的丢掉（MaiBot 没查）；不能带人名、昵称、QQ 号、网址（2026-10-16 实现：说话人换成甲乙丙再发给模型、提示词要求不写人名，代码查号码、@、链接；对照人物表查人名以后做）；不能和提示词里的示例说法一样（MaiBot 踩过示例泄漏进库）。
5. **查重合并**：
   - **情境**：用向量找同范围里最像的情境，相似度 ≥ 0.92 当同一个情境，新说法挂到它下面；0.85～0.92 先当新情境，等主人在界面上看到再决定合不合；更低就是新情境。
   - **说法**：同一个情境下 `style_norm` 完全相同的才是同一种说法，合并进去（加证据、更新 `speakers` / `hits` / `last_seen_at`）；不同的说法并列留着，不只留一个。
   - 被拒绝过的说法（墓碑）再学到时只记证据，不复活。（MaiBot 情境和说法要完全相同才合并，近义的会越攒越多，同一情境的不同说法也没归到一起。）
6. **送审**（已被 ADR-097 改为定时审，原来是"`speakers ≥ 2`（两个不同的人用过）时晋级、晋级时才审"：720 条候选全只有一个人说过，一条都没审到）：后台每隔 `expression.reviewHours` 小时（默认 3，记忆 · 学到的说法 · 候选一栏顶上能改，0 = 不自动审；上次审的时间存在库里，重启不从头算）把候选成批交给模型，一次最多 `expression.reviewBatches` 批（默认 10）、一批 10 条，说过的人多、学到次数多、最近见过的先审；学完不顺手审。也能点"现在审一批"。每批调一次模型，同时做两件事：
   - 这条说法本身行不行：情境和说法对得上、不太特指、不带人名、不是骂人或歧视（MaiBot 的四条标准，加一条安全）；
   - 每个角色合不合：把各角色的"表达"一节给它，逐个判像 / 不像（ADR-060 第 5 条改成两档，原来是 good / ok / bad），写进 `expression_fit`。

   审核通过的：自动启用关着（默认）就进 `pending` 等主人通过，开着就直接 `active`。审核没通过的进 `rejected`，`reviewed_by = ai`，主人可以在界面上捞回来。主人在候选一栏直接通过的不等 AI 审，直接可用，半分钟内通过的几条攒成一批补判每个角色合不合。（MaiBot 每条候选单独审一次；我们成批审，一批一次调用。）
7. **遗忘**：先只做最必要的——候选 90 天没再见到、也没审到就删（证据一起删；定时审开着时候选很少留这么久）。可用的不设上限、不自动退休，先记数据（库里各状态多少条、检索耗时、每条被取到和真用上的次数），过一段时间按数据再定要不要退休、上限多少（主人 2026-10-16：上限先放宽，用数据说话）。墓碑和主人审过的不删。
8. **主人的审核**（记忆 · 学到的说法）：分候选、等审核、可用、拒绝的四栏；看证据原话、各角色合不合；候选能直接通过或拒绝，等审核的一张张滑卡片，可用的能给某个角色单独屏蔽。还没做：改字、合并情境。**主人的决定以后重学到也不会被覆盖**（MaiBot 重学会把审核通过冲掉）。

#### 3.4.3 回复时怎么取（不加模型调用）

和 MaiBot 最大的不同：它回复前要先让规划器写一段意图、再调一次快模型挑 0～5 条；我们**一次都不调**，保住响应速度（ADR-011/016）。

1. **召回情境**：在"本群 + 全局"、下面至少有一条可用说法的情境里找最近的 12 个。相似度低于门槛（起步 0.62）的不要。（已被 2026-10-19 的挑漏报告改为按单句查：这一轮的话按行拆成单句，去掉占位、@ 和不到 2 个字的，留最后 8 句，一次嵌入请求算完，每个情境取和各句相似度里最大的；原来写的"复用记忆那边的整段向量"会把几个话题混成一个查询，群里 121 轮只挑中 2 次。按单句 39 轮挑中、77 条，误中约一半，门槛要不要调见参考页 language.md"已知的不足"。门槛已被 ADR-105 改为 0.65，又被 ADR-111 放回 0.62。）
2. **每个情境挑一种说法**：把这个情境下她能用的说法（`active`，`fit` 不是 `bad`，主人没屏蔽，不在冷却里——同一条 30 分钟内不再给她）按权重随机抽一种。权重：`fit = good` 高于 `ok`、用的人多（`speakers`）、最近还有人在用（`last_seen_at`）。随机是为了同一个情境不总给同一句；权重让更地道、更合她的说法更常出现。
3. **挑最多 3 个情境**：按情境相似度排，彼此太像的只留一个（现在只做到"同一句说法一轮只给一次"：按 `norm` 比，标点不同也算同一句，2026-10-19；情境之间的相似度还没比）；**挑不出来就 0 条，不回退成全给**（MaiBot 子代理出错时会把 50 条全塞进去）。
4. **注入**：放在只追加的尾巴里、"参考信息"那一块，不进固定前缀，缓存不受影响：

   ```
   群里大家平时这样说（合适就自然地用，不合适就不用）：
   - 当"别人分享抽卡出金"时，可以说"欧皇退散"
   ```

5. 记下这一轮给了哪几条（`model_runs` 的注入记录）；回复里真的用上了（说法出现在回复里）才加 `used_count`、更新 `last_used_at`。

#### 3.4.4 和角色卡例句的关系

ADR-049 临时写在卡里的十来条例句，等库里的可用说法够多（起步：本地私聊能取到的 ≥ 30 条）就挪进库，`origin = seed`、`scope = global`，卡里只留原则。

MaiBot 时期主人审过的说法：2026-10-16 已从 MaiBot.db 的临时副本只读导出 301 条（`checked = 1`，来自 4 个会话；另有 104 条 AI 写的、没审过的不要），放在 `data/dev/seeds/maibot-表达-审过的.md`。导入时 `origin = seed`、`scope = global`、`reviewed_by = owner`（主人当时审过），也走第 4、5 步的长度、人名校验和查重；导入后照样算每个角色合不合。

#### 3.4.5 前置：认出哪些号是 AI

学习时要认出 AI 的号（ADR-055 改成照常学、注明来源）；以后群里怎么和别的 AI 互动也要用到（ADR-054 第 4 条）。分三步，先做第一步就能开始 L2：

1. **主人手动标**（2026-10-16 做了）：QQ 聊天记录里右键群友的消息、或者悬停头像的名片上点"标成 AI 号"，存在 `learning.db` 的 `ai_speakers`（按说话人 `qq:<号>`），和配置 `expression.aiAccounts` 合起来算。ADR-055 改了做法：标成 AI 的号**照常学、不撤证据**，审核卡片和表格上注明"其中几个是 AI 号"、原话旁边写"AI 号"，由主人决定。
2. **平台给的标记**：QQ 官方机器人账号有标记（群成员信息里的机器人标识，接 SnowLuma 时核对字段名），自动当 AI。
3. **线索打分**（以后）：规格-QQ渠道"认出谁是 AI 群友"那几条线索——全天候秒回、回复整齐带 Markdown、被 @ 必回、名片带 bot 等——算一个分，**只当建议**，进"待确认"列表给主人点，不自动定。

### 3.5 黑话和梗（说法库里"她不主动用"的那类）

> 已被 ADR-096 改为：不另建黑话库，存进 3.4 的说法库（"她能不能自己用"默认否，就是下面"三档使用"的前两档）；下面讲的是"这个词是什么意思"那种学法，证据门槛照旧。

**发现**：没见过的词、复读片段、谐音写法、有人解释"这是 X 梗"。真实出现、2～8 个字、离开这个圈子看不懂（MaiBot `learn_jargon` 的条件）。主人希望**比 MaiBot 查得勤**：每次后台总结都顺带抽候选，不等次数节点。

**验证**：

- 一个词可以有好几个意思并存（本群义、网络义），本群义优先，不被网上的意思盖掉。
- 每个意思带证据：哪几条消息、谁用的、谁接了、反例。**按不同使用者数算**，不按总次数。
- 定义之前先攒证据：至少 2 个不同的人在不同语境里用过，才让模型推一次意思；推断节点 [4, 8, 25] 次时再推一次、比对（MaiBot 是 4/8/25/100）。
- 缺知识才联网：先看已有的梗卡和本群上下文；陌生词、最近几天集中出现、几种解释冲突时才搜。搜索摘要不算独立证据。
- 有人刻意教错（"X 的意思其实是夸你"），记成"有人这么说"，不直接改含义（信任序，规格-记忆 3.4）。

**三档使用**：

| 档 | 条件 | 默认 |
|---|---|---|
| 看得懂 | 当前上下文里别人用了，且有已确认的意思 → 作为理解参考注入（≤ 10 条） | 开 |
| 别人用了能接 | 意思已确认、在当前 scope 里、上下文里别人刚用过 | 开 |
| 自己主动用 | 以上都满足，且使用者 ≥ 3 人、没有反例、不在冷却期 | **关**（主人可以按全局 / 按群打开，界面上一个开关切换，ADR-035 第 5 条） |

含义不确定时宁可不用。不在系统提示里长期堆黑话解释。

**存储**：（已被 ADR-096 改为存进说法库，一条说法带"意思"和"她能不能自己用"）原来写的是 `kind = jargon`（词、意思、说明）；梗的变体（谐音、改编、替换词）先用别名表连到原型，不做完整的梗图谱（笔记扩30 的八层本体太重，第一版只取"多义 + 作用域 + 证据 + 禁用条件"）。

**种子条目**（主人给的）：㊗️ —— QQ 客户端里点不出来、服务器能调用的表情回应；一般是"猪"的谐音。scope `public`（QQ 平台通用），放进她能用的表情回应列表（待办已记）。

### 3.6 分条和节奏

- **模型按格式写，代码负责拆**（ADR-035 第 4 条）：模型用空行分开每一条；代码拆开、限制条数（普通闲聊**最多 2 条**，多出来的并进最后一条）、加停顿。一条能说完就一条，不机械固定拆三条。本地私聊不拆（空行是正常的段落）。
- 两条之间的停顿 0.4～2 秒，按字数算、有上限；**不故意打错字、不故意撤回**（MaiBot 的 1% 错字不要）。
- 前一条没发出去，后一条不发；发第二条前检查话题有没有换、对方有没有接别人的话（发送前检查已有，扩到每一条）。
- 贴了表情回应，就不再发同义的"哈哈哈"。
- 不逐字流式发出去，整句通过检查再发。

这些停顿数字是起步值；笔记明确说没找到可靠的真人分条间隔数据。以后用 MaiBot.db 里真人的引用回复时间差估一个本地基准（ADR-016 已定的思路）。

**现状（2026-10-17 照代码核对）**：上面"本地私聊不拆"和"最多 2 条"已经不是现在的做法。本地的显示拆分见 ADR-048、053（本地私聊的闲聊回复按空行、换行、句末拆成气泡，只是显示、可关，条数先不设上限）。QQ 真实发送由 `daemon/plugins/qq.ts` 的 `splitMessage` 按空行拆、单段超过 1500 字再按换行或句号切；拆开的每一条末尾、一条里每行行尾单独的"。"去掉（`dropTrailingPeriods`，ADR-110 第 1 条、ADR-114 第 1、2 条，2026-10-19；agent 存回复时就改好，试运行"她会说"的、她实例历史里的也一样）；"最多 2 条、多的并进最后一条"的上限**没有实现**。停顿现在是每字 40 毫秒、上限 2.5 秒（`pace`），不是 0.4～2 秒。

### 3.7 表情和表情回应

- 四样东西分开：小黄脸（face）、商城表情（mface）、图片 / 自定义表情、表情回应（reaction）。表情回应是对一条已有消息的动作，**不算一轮发言**。
- 选哪种：表情回应 = 看到了 / 同意 / 惊讶 / 轻调侃；文字 = 纠错、认真回答、设边界；小黄脸 = 补语气；表情包 = 承载复杂的梗。别人认真求助时只贴表情像敷衍。
- 表情的含义来源：主人确认 > 本群学到的（带证据数）> 网上调研（设计已定）。官方名和实际用法常常不一样（"微笑"≈ 假笑），按本群学到的。
- 多人给同一条贴同一个表情，不一律算"支持"；她和别的角色贴的不算反馈。
- 表情包的图片描述、情绪标签只给她看，**不混进可以发出去的正文**（MaiBot #2069：标签被当成回复内容模仿）。

### 3.7.1 拍一拍（戳一戳）

调研：docs/archive/notes/拍一拍-调研.md（私有存档）（2026-10-15，Haiku）。MaiBot、AstrBot 主仓库都没有专门的处理逻辑和提示词，下面是我们自己的理解，做的时候按真实记录校准。

**它是什么**：不说话、但引起对方注意的动作，像拍拍肩膀。**大多没那么严肃**（2026-10-15 主人）：觉得好玩、突然想拍一下、看到别人拍也跟着拍、拍回去，多数没有明确含义，不要过度解读。偶尔才有"在吗""理我一下"的意思（比如私聊里隔了很久戳一下）。

- 群里一个人开头、几个人跟着拍，是一种小小的起哄 / 接龙，和复读差不多。
- 拍回去是最自然的回应，本身就是一来一回的玩。
- 被拍不等于有话要说：不要每次都当成在叫她、要她回一段话。

**自定义后缀拿来整活**：QQ 的拍一拍可以设自定义后缀（"拍了拍你的屁股"里的"屁股"就是自定义的内容），常被拿来整活。现在 SnowLuma 推来的数据里没有这个后缀（调研和我们库里都没看到），**不强制实现**，只记在这里；以后哪个协议端 / 适配器能拿到再接。拿到了也只当显示文字和梗的素材，不当成谁说的话、不当指令。

**给她看时**：作为通知写在"只追加的尾巴"里，不写成谁说了一句话，比如"（主人戳了戳你）"；短时间里连着的合并成一条（"主人连着戳了你 3 下"）。别人之间互戳不给她看，或者只在群聊增量摘要里一笔带过。

**她怎么回**（动作，见 3.2）：默认可以不理；回应时优先最轻、最好玩的方式——戳回去、跟着拍、一个表情，偶尔一句很短的话；不展开长回复，不把它当成提问。同一个人短时间连戳只回一次（冷却）；群里限频。被戳算"点到她了"，在"要不要接"那一站等同一次很轻的 @（第三阶段群聊）。

**她戳别人**：以后作为一个动作给她（`send_poke` / `group_poke` / `friend_poke`，各家协议端叫法不同，适配器里试；收发自检里已经有这一项），来源是 `character`；只在明显合适的时候用（主人在场、熟人、对方先戳了她）。

### 3.8 四种场合的语言策略

| | 本地私聊 | 本地群聊 | 平台私聊 | 平台群聊 |
|---|---|---|---|---|
| 像什么 | 编程助手，干活为主 | 主人在场的家里聊天 | 一来一回的聊天 | 旁观为主的群友 |
| 职业、工具说明 | 只在这里出现 | 只给被点名干活的那个 | 没有 | 没有 |
| 对话链 | 不需要 | 简单（人少，主人点名） | 不需要 | 需要（3.1） |
| 角色之间接话 | — | 可以互接，有防循环上限（第九节第 1 条） | — | 按多 Bot 规则：不自动接另一个角色的话 |
| 表达学习的素材 | 不进群聊表达库 | 不学（都是主人和角色） | 学对方的 | 学群友的 |
| 黑话 | 少用 | 主人的黑话可以用 | 对方的 | 本群的 |
| 分条 | 不拆，长回复用格式 | 短，最多 2 条 | 最多 2 条 | 最多 2 条 |

上表"分条"一行是起草时的设想。本地的显示拆分见 ADR-048、053；QQ 真实发送按空行和 1500 字切，"最多 2 条"的上限没实现（`daemon/plugins/qq.ts` 的 `splitMessage`）。

### 3.9 顾问和其他职业

- "拿不准时升级到更强的模型"（重要的道歉、敏感玩笑、价值冲突）是**闸门 / 路由**的事，不是顾问。顾问是独立会话，只提意见、追加 `<advisory>` 旁注，默认沉默；**不接进平台群聊的回复链路**（会拖慢快路径）。
- 顾问说话用它自己的职业说明和表达风格，**学到的群聊表达不覆盖职业口吻**；表达学习也不学顾问的话（它是 `character` 来源）。
- 顾问在群里算一个成员：它的发言计入"没有真人参与时的发言上限"（规格-插件已写），也受 3.6 的拆条规则约束。

### 3.10 擦边、低俗和地狱笑话（研究方向，ADR-045）

主人的看法（2026-10-15）：一定程度的性暗示、低俗笑话、地狱笑话，配合气氛适当地表达，有助于融入人类的聊天气氛、不冷场。难点是心理上的"满足感"和氛围解读、回复怎么构造；中文互联网里有大量和谐词和绕开和谐词的写法，要按所在场景、周围人的用词习惯来用合适的词。真人都不一定做得到，比学说梗还难。AI 在这方面通常很保守、容易拒绝，但在恰当的时候发挥能明显提升活人感。

已有的调研：Notion 笔记**扩16「边界幽默与敏感话题语用」**（整理稿 [语言-笔记整理.md](notes/语言-笔记整理.md) 的扩16 一节）。要点：
- 分四类：擦边 / 成人暧昧双关、轻度政治段子、地狱笑话 / 黑色幽默、讽刺和友好互损；只靠关键词分类会明显失真。
- 要同时看笑点机制、对象、说话人意图、关系和在场的人、场合、来源；黑色幽默看不幸发生多久、受害者在不在场、谁开的头、谁承受笑点。
- 分"理解 / 接话 / 主动"三档；红线：不把未成年人纳入性化互动、不对真实成员投放没被邀请的性暗示、不为了入乡随俗复读仇恨或霸凌。
- 主动表达优先没有具体受害者的荒诞、自嘲、对公共事实的温和讽刺；有中文数据集入口（Chumor 2.0、PunMemeCN、DiaCOLQ 等）。

下面的问题是在它基础上还要补的。

现在的规则：不主动开这类玩笑；别人开了，按普通聊天接或者不接。研究有结论前不改。

研究要回答（草稿）：

- **什么时候可以**：这个群的玩笑尺度（从历史里看谁常玩、玩到什么程度、别人怎么接）、在场的人熟不熟、刚才的气氛；从"别人开了头、她跟一句"起步，而不是她先开。
- **什么时候绝对不行**：有人在认真说事、难过、求助；针对某个具体的真人（身体、隐私）；涉及未成年人；对方或旁人表示不舒服（记成边界，之后不再犯）；主人没打开的群。
- **二次元语境和现实语境分开**（2026-10-15 主人）：二次元语境下有些限制相对宽松，比如"萝莉控"一类的圈内自嘲梗（"挨电"之类），分清说的是虚构角色和圈内梗、不是现实的人，正常人都能把握。暂定的线：现实中的未成年人、群里的真人始终是红线；虚构角色只到"圈内梗、自嘲"的程度，不做露骨的性描写；看不出是哪种语境时按现实处理。研究里要回答怎么判断当前是哪种语境。
- **"别这样"不一定是负面证据**（2026-10-15 主人）：有些梗本身就用"别这样说""不要啊"这类词；一群人一个个都在复读"别这样说"，多半是在玩梗，不是真的反感。真人为了配合冒犯性的笑话也会假装很生气，旁边的人拱火、看乐子，整体仍是在附和气氛。要分清玩笑式的拒绝、玩梗、真的被冒犯，得综合看每个人的背景和性格、用的是什么梗、当时的气氛（有没有复读、有没有人接着拱火、说"别这样"的人之后还在不在一起玩）。做法：从真实聊天记录（MaiBot 库副本、以后的回溯学习）里挑出这几类情况的例子，主人核验后当成标注样本和评测题；反馈信号不能简单按"出现了拒绝词"算负面。
- **用词**：跟着本群已经在用的说法、和谐词和绕开的写法走（和黑话学习共用证据：使用者数、有没有人接、有没有反感），不自己发明新的擦边词。
- **怎么接得好**：幽默理论里"冒犯但无害"（良性冒犯）一类的解释、群体规范、时机；接不好时怎么自嘲收场。
- **模型**：哪些模型会过度拒绝、哪些会过头；需不需要单独的判断步骤（这一轮适不适合）。
- **开关**：大概率和"主动用黑话"一样，按全局 / 按群一个开关，默认关（待主人定）。

### 3.11 时间感（草稿，2026-10-16，待主人看过再做）

**要什么**（主人）：她知道现在几点、星期几、隔了多久没说话，但不要高估时间流逝（十几分钟就"好久不见"、几小时前的事说成"前几天"），也不要动不动评论时间。

**现状**：`agent.ts` 的 `buildContext` 在本轮参考信息里每满 15 分钟加一句"现在是 2026年10月16日 星期四 05:40"（`CLOCK_EVERY_MS`，ADR-022 只追加）；记忆条目前标"今天 / 昨天 / N 天前"（`memory.ts` 的 `ago`，按 24 小时整除，不按日历日）。间隔要模型自己拿时间点去减。

**调研**（notes/时间感-调研.md（私有存档））：模型算时间差常错一天左右（Test of Time、TimeBench）；别人的做法是程序算好、给人能读的标签（SillyTavern `{{idleDuration}}`）、稀疏地给锚点（pi-time-awareness 至少隔 1 小时）、精确时刻给工具；**没找到**公开的"抑制过度评论时间"的方案，只能靠实测。

**做法（草案）**：
1. **程序算好再给**：报时那句改成"现在是 星期四 下午 3:40。距离上一条消息：40 分钟 / 今天早些时候（约 5 小时前）/ 昨天晚上 / 3 天前"。"距离"按这个会话里上一条别人或她的消息算；跨日按日历日算（"昨天晚上"而不是"1 天前"）。记忆的 `ago` 一起改成按日历日。
2. **只在有意义时说**：间隔不到门槛（起步值 1 小时）的回合，不重复报"距离"，只按原来的节奏报时；跨过门槛、跨日、深夜（起步 0:00～5:00）才在报时里带上。仍然只追加在尾巴，不改历史。
3. **尺度说明放固定前缀**（核心规则一句）："时间信息是给你判断用的，不用每次都提。人一天里离开几个小时、隔一晚再聊都是平常事；隔了好几天、或者对方熬夜，才值得说一句。"
4. **人设不再写"时间感和人不一样"**（2026-10-16 已从铃音当前草稿删掉，它会鼓励她把时间说错）。
5. **精确时刻**：被问"几点了""今天几号"时，答报时里给的；以后有工具系统时可以加一个 `time` 工具。

**参数（起步值，待实测）**：报时间隔 15 分钟（不变）；"距离"门槛 1 小时；分档 1～6 小时"今天早些时候"、跨日"昨天 + 时段"、2～6 天"N 天前"、7 天以上"一周多 / N 周前"；深夜 0:00～5:00。

**验收**：做一组固定情景（隔 10 分钟、2 小时、跨夜、3 天、深夜两点），各跑若干次，统计她有没有说出不对的时间判断、有没有在不该提的时候评论时间；用临时数据目录和假时钟，不碰真实 `data/`。改坏检查：把"距离"换回让模型自己减、把门槛改成 0，看统计变差。

**待主人定**：门槛和分档；深夜要不要单独提示；私聊和群聊要不要不一样（群里话多，"距离"可能更该按"她上次说话"算）。

## 六、禁止的偷懒写法

- 把语用标签、动作列表、例句库整段写进系统提示当模板。
- 选不出表达 / 黑话时把全部候选塞进去。
- 学习素材不按 `origin` 过滤（会学自己、学插件、学主人代发的话）。
- 每条消息都调一次大模型做语用分析或对话链。
- 用故意错字、故意拖延来"装真人"。
- 按"回复率""群里有人笑了"当成功指标。
- 学到的表达直接改写角色卡。
- 黑话按总出现次数算可信度（一个人刷屏就"学会"了）。
- 测试读写真实的 `data/`、MaiBot 的库。

## 七、已知的坑

- **自我污染**：几个 Bot 互相接话，把对方编的评价当训练信号（笔记扩14、基础04）。她们之间的话一律不进学习。
- **互相模仿**：长对话里角色口吻趋同、趋向默认助手口吻（SPASM、Persistent Personas）。漂移检查用每个角色的说话指纹。
- **表情标签进正文**：MaiBot #2069。
- **MaiBot 社区踩过的**：生成成功不等于送达（要看发送回执）；断网后重试发送、不重试生成；后台学习任务要有各自的超时和 token 上限；OneBot 事件处理里不做重活；结构化输出要校验。
- **同名多义**：一个词在两个群意思相反，scope 必须分开。
- **语用推理拖慢速度**：理解侧"想 2～3 种读法"只在拿不准（反讽、争执、玩笑边界）时展开；推理过程不进上下文，只留结论。

## 八、验收

测试只用临时目录；回放样本从 MaiBot.db **复制到临时目录**用。

1. **素材过滤**：`character`、`automation:*`、`human` 的消息不出现在表达 / 黑话学习的输入里（把过滤删掉测试就红）。
2. **送审**（ADR-097 改，原来是"两个人各说一次才进"）：学完不顺手审；没到点、关了自动审都不审，到点审一次，一次最多 `reviewBatches` 批，说过的人多、学到次数多的先审；调用失败也算审过这一次，不每 10 分钟重来；主人在候选一栏直接通过的补判合不合。
3. **取用失败为空**：选择返回不合法 JSON 时，注入 0 条，不是全部。
4. **scope**：群 A 学到的黑话在群 B 的回合里取不到。
5. **三档**：主动使用关着时，回复里不会出现只在"主动用"档才允许的词（看注入内容，不靠看回复）。
6. **分条**：前一条发送失败，后一条不发；贴了表情回应的回合不再发同义文字。
7. **对话链**（L5）：20～30 段回放样本里，引用 / @ 的父消息 100% 对；猜的部分报告准确率，不设硬门槛，先看数。
8. **缓存**：加了表达、黑话注入后，注入面板的前缀复用仍 ≥ 90%。
9. **表达：编的不收**：抽取结果里说法在原话中找不到的，不入库（去掉这道检查测试就红）。
10. **表达：主人的决定不被冲掉**：主人通过 / 拒绝过的说法再被学到，状态不变，只多一条证据。
11. **表达：取用不调模型**：一轮回复的模型调用次数和不开表达学习时一样（看 `model_runs`）。
12. **表达：只学一遍**：同一个群两个角色都在，一批消息只产生一次抽取调用。

**第 3 条"例句"是什么**：就是"在什么情境下，可以怎么说"的具体句子。比如：

- 情境"被群友调侃说你又在装"→ 说法"我装什么了我"；
- 情境"别人分享抽卡出金"→ 说法"欧皇退散"。

如果把这类句子写死在系统提示里，模型会反复套用同一句，几个角色还会说得一模一样（Cumora 踩过的坑，设计.md 里已经定了不堆例子）。所以系统提示只写原则，比如"被调侃时短句回嘴，不解释"；具体说法从群友的真实聊天里学，存进表达库，每轮按当前情境挑最合适的 0～3 条给她参考，用过的还有冷却。
