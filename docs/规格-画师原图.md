# 规格：画师的推文发原图（画师表、导入、按需待确认）

> 状态：2026-11-13 起草，规格定稿，已合 main（合并提交，分支 `feat/x-artist-originals`；之后补的准备阶段和配置测试在随后的小提交）。决策 ADR-371，需求登记 R-371～R-373。
>
> 用户原话（2026-11-13，要点）：希望画师发的图是原图而不嵌入卡片，或者在卡片基础上也发原图；用画师标记识别（简介里的特定网址、关键词等），标记存在本地一个表，用改名不变的账号标识（X 的数字 ID）而不是 @用户名。补充：关注有 4893 人，逐行勾不现实，确认页要默认勾“画师”类；有的画师简介、名字、地点都不带线索（被封过换新号的也有），不要批量爬几千个账号的媒体页，做成按需判断——展开链接遇到不在表里的带图原创推文作者，用已取到的资料判断，像画师的记进“待确认”表，不自动生效；sumika-ctl 能列出待确认、确认、移除。

## 〇、现状（2026-11-13 读码，`main`）

1. **X 默认模板不嵌图**：`linktemplate/sites.go:147` 的 `xDirectText` 是“链接、名字[@ID]、「正文」、时间、`$图片`、`$视频`、`$被引推文`”——图本来就是原图（`linkreader/twitter.go:385` 把 fx 的图地址设成 `name=orig`，超限再退 `name=large`，见 `linkexpand/image_limit.go:16`）。图被“嵌进卡片”只发生在样式选了“卡片”或 `@推特卡片`（`linktemplate/styles.go:138`，模板 `$卡片$链接`）时。所以本功能是：**命中画师时，不管 x 站点的样式是什么，都保证原图发出去**。
2. **卡片算一张图**：`linkexpand/shape.go:21` 的 `visualItem` 把 `card` 算进直发的图数；卡片加 3 张原图是 4 张，超过 `directImageMax`（默认 3）按 B3 进合并转发。
3. **作者数字 ID 只有两条线路给**：`linkreader/twitter.go:276` fx_v2 填 `Author.ID`（fx 的 `author.id`）；`linkreader/twitter_syndication.go:244` 嵌入接口填（`user.id_str`）；**vx 不给**（`twitter.go:459` 的 `vxPost` 只有 `user_name`、`user_screen_name`、头像），`mapVX` 只填名字、账号、头像。`linkreader/twitter_routes.go` 的 `fetchX` 是 fx_v2 和 vx 同时取、先到的成功结果为准，所以同一条链接有时拿不到 ID。
4. **作者资料**：fx 的 `author` 对象（`linkreader/testdata/x-four.json`）带 `description`（t.co 已换成真实地址）、`raw_description.facets`、`location`、`website.url`、`followers`、`media_count`、`statuses`；`xAuthor`（`twitter.go:13`）现在只读了名字、账号、ID、头像、认证。有的响应里作者对象只有 id、名字、账号、头像（`x-public-*.json`），这时没有资料。
5. **展开入口**：只有 QQ 渠道（`app/linkexpand.go:66` 的 `admitLink` 要求 `Conv.Channel == "qq"`）。`linkexpand.Build` 的调用点：插件发送 `linkplugin/expand.go:424`、`ctl link preview` 的 `app/linkpreview.go:118`、两个开发工具 `cmd/link-samples/samples.go:249`、`cmd/link-probe/samples.go:191`。降级重排（`linkplugin/degrade.go`）拿的是已经建好的 `Part`，不再调 `Build`。
6. **Pixiv**：pixiv 作品链接本身就是画师的作品，模板是“首行 + 链接 + `$图片`”，图是原图，不嵌卡片（`linktemplate/sites.go` 的 `pixiv-artwork`），**不需要也不查画师表**。表里留 `pixiv` 的扩展位是给以后“从 X 画师跳到他的 pixiv”或“订阅”用的。
7. **sumika-ctl 只依赖协议包**（`cmd/sumika-ctl/main.go` 头注释，`internal/archcheck` 守着），不能自己写表；会改状态的命令经管道交给正在运行的程序。

## 一、行为（用户可见）

| 情形 | 行为 |
|---|---|
| 表里没有、或状态不是 `confirmed` 的作者 | 一切照旧，一个字节都不变 |
| `confirmed` 画师，推文有至少一张自己的图，模式 `cardAndOriginals`（默认，待用户确认） | 卡片、干净链接、再把每张原图发出来（视频照旧单独一条）：模板 `$卡片$链接$图片$视频` |
| 同上，模式 `originalsOnly` | 只发干净链接和原图（视频照旧）：模板 `$链接$图片$视频`，不发卡片、不发正文 |
| 同上，模式 `off` | 不特殊处理，当作不是画师（表和待确认照常记） |
| `confirmed` 画师，但这条推文没有自己的图（纯文字、只有视频、只有被引推文的图、X 文章） | 照旧 |
| 原图多于 `directImageMax` | 照旧的 B3：站点不是 never 就整条改合并转发（第一个节点是文字和链接，后面一图一节点；卡片也是一个节点），never 就只发前几张并标“发出/总数” |
| 图被协议端拒收 | 照旧的降级阶梯（转 180°、合并转发里转、文字版），不新增 |
| 展开时作者不在表里、是带图原创推文、资料像画师 | 记进待确认表，这一次发送不受影响 |

命中画师时的几条取舍（实现必须照做）：
1. `templates.x`、`templates.x-forward` 的自定义写法和 `sites.x.forward` 的 auto / always **不生效**（用户指定“画师发原图”比样式优先）；`sites.x.forward: never` 仍然生效，只管“图太多时截断还是转发”。要完全保留自己的写法就把 `artist.mode` 设成 `off`。
2. **拆图拼回关掉**：画师发的横幅拆成三张时，用户要的是三张原图，不拼成一张（`panorama.go` 的 `markPanorama` 和拼图 `$拼图` 都不用）。
3. 译文：`cardAndOriginals` 里卡片按现有规则只画译文；`originalsOnly` 不发任何文字，也就不发译文。
4. “发过 N 次”“还有 N 条没处理”这类提示照旧接在第一条上。
5. 卡片画不出来时退回通用卡片（现有行为），原图照发。

## 二、画师表

### 二点一 位置和格式

- 路径：`data/go/artists/<平台>.json`（`paths.ArtistsFile(platform)`），**一个平台一个文件**（和 `go/chat/<平台>.db` 的分法一致）。现在只有 `x.json`；别的平台的校验函数不登记，传 `pixiv` / `bluesky` / `misskey` 一律报“这个平台还没做”，不写文件。
- 整个文件是一个 JSON：`{"version":1,"platform":"x","entries":{"<ID>":{...}}}`。小表（上万行以内，一行约 200 字节），整个读进内存，每次改动整份写回：先写同目录临时文件，再改名覆盖，不留半个文件。上限 20000 行，超了拒绝新增并写日志。
- 键是 **账号数字 ID**（X：`^[1-9][0-9]{0,19}$`，1～20 位、不以 0 开头，也就排除了全 0 和前导零）。`@用户名` 只存在于 `handle` 字段里给人看，**匹配只按 ID**，不按 handle、不按名字。
- 一行：

| 字段 | 含义 |
|---|---|
| `status` | `confirmed` 生效；`pending` 待确认（按需发现，不生效）；`declined` 不是画师（用户拒绝，或判断后“不像”，不再提） |
| `source` | `import`（导入的确认结果）/ `auto`（按需判断）/ `manual`（用 ctl 手动改的） |
| `handle`、`name` | 最近一次看到的账号和名字，只给 `list` 显示；外来文字，存前去控制字符、各截 64 字 |
| `at` | 状态最后一次变化的时间（RFC 3339） |
| `batch` | 最近一次把这一行改成现在状态的导入批次；之后被别的操作改动就清空（撤回只动还带着这个批次的行） |
| `prev` | 导入改动前的整行（状态、来源、显示名、时间、分数、线索）；原来没有这一行就没有 `prev`（撤回时删行） |
| `score`、`clues` | 按需判断的分数和命中线索名（第七节），给确认时参考；`clues` 只写线索表里的名字，不写简介原文 |

- 文件读不开（JSON 坏了、版本不认识）：**不覆盖**，改名成 `x.json.bad-<毫秒时间戳>`，本次按空表启动，写一行日志；不因此让展开失败。
- 并发：一个互斥锁；`Observe` 在链接插件的两个取数协程里调，导入和 ctl 命令在控制管道的协程里调。读表（`Mode`）取读锁的快照，不在锁里做网络、发送。

### 二点二 状态怎么变

```
没有 ──按需判断像──▶ pending ──confirm──▶ confirmed ──remove──▶ declined
  │                    │  └──remove（拒绝）──▶ declined
  └──按需判断不像──▶ declined(auto)     declined ──confirm──▶ confirmed
没有 ──导入──▶ confirmed；pending / declined(auto) ──导入──▶ confirmed（记 prev）
```
- `declined` 的行永远不再被按需判断改动，只有用户手动 `confirm` 或导入（导入不覆盖 `source: manual` 的 `declined`，计入“跳过”）能改。**“同一账号只判断一次”靠“判断过的账号一定有行”实现，判断不像也落一行 `declined(auto)`**，上限 20000 行里它们占大头，所以 `list` 默认不列它们。
- “没有资料”（取数线路没给作者资料，见第七节）不落行，等下次有资料时再判。

## 三、导入和命令行

### 三点一 为什么用 sumika-ctl 子命令，不用“启动时读文件”

| | sumika-ctl 子命令 | 启动时读文件 |
|---|---|---|
| 生效 | 立刻，程序不用重启 | 要重启；Go 的 exe 要 quit 再起 |
| 重复跑 | 导入是幂等的（第三点二），随时可再跑 | 每次启动都读，用户改了表又被文件盖回去 |
| 撤回 | 按批次撤，只动这一批 | 没有批次的概念 |
| 和“列出待确认、确认、移除”的关系 | 同一个命令组，同一条通道 | 要另做一套 |
| 风险 | 命令行经管道交给运行中的程序读文件，路径要校验 | 路径固定，无参数 |
选前者。路径校验：必须是绝对路径、规范化后是普通文件（不是目录、不是符号链接到别处）、不超过 8 MiB；读的是 JSON，结构不对一律报错，不写表。管道只对当前 Windows 用户开放（ctl 现有的保证）。

### 三点二 命令

```
sumika-ctl artist list [--status pending|confirmed|declined|all] [--platform x] [-n 100]
sumika-ctl artist import <文件> [--platform x]
sumika-ctl artist import --undo <批次> [--platform x]
sumika-ctl artist confirm <ID>... [--platform x]
sumika-ctl artist remove <ID>... [--platform x]
```
- 默认 `--platform x`；`--status` 默认 `pending`；`list` 按 `at` 新到旧，显示 ID、handle、名字、分数、线索名、来源、状态；handle、名字出去前过 `ctlproto.Clean`。
- `import <文件>`：文件格式是确认页导出的 `artists-confirmed.json`：`{"exportedAt":"…","confirmedArtists":[{"id":"…","screen_name":"…","name":"…"}]}`。ID 不合格式的行跳过并计数（回复里写“N 行格式不对”，不写那一行的内容）。每个合格的 ID：没有行 → 新增 `confirmed`（source `import`）；是 `pending`、`declined(auto)` → 改成 `confirmed`、记 `prev`；已经是 `confirmed` → 不动；`declined(manual)` → 跳过。有至少一行变化才生成批次号 `imp-<UTC 时间 yyyymmddhhmmss>`，回复里写批次号和“新增 / 改为生效 / 已是 / 跳过 / 格式不对”各几行。**没有变化不生成批次**（所以对同一个文件反复跑是幂等的，不产生一串空批次）。
- `import --undo <批次>`：把还带着这个批次号的行恢复（有 `prev` 就恢复 `prev`，没有就删行）；之后被 `confirm` / `remove` 动过的行批次已清空，不受影响。回复里写恢复几行、删几行。批次号不存在报错。
- `confirm <ID>...`：每个 ID 要在表里（`pending` 或 `declined`）才能确认，不在表里报“表里没有这个账号，先导入或等它被发现”（不凭空新增，避免手误）；记 source `manual`。
- `remove <ID>...`：`confirmed`、`pending` 改成 `declined`（source `manual`，不再提）；本来没有的报错。
- 一次最多 200 个 ID。**只读的只有 `list`**：`ctlserver.readOnly` 里 `CmdArtist` 且 `Args[0]=="list"` 才算只读；`describe` 白名单加 `artist`、`import`、`confirm`、`remove`；演示数据模式（`demo`）一律拒绝；日志里记“做了什么、成败”，不记账号和文件路径。
- 退出码沿用 ctl 现有的（0 成功、1 失败、3 被拒）。

## 四、怎么拿作者数字 ID

| 线路 | 有没有 ID | 出处 |
|---|---|---|
| fx_v2 | 有：`author.id` | `linkreader/twitter.go:276` |
| 官方嵌入接口（syndication） | 有：`user.id_str` | `linkreader/twitter_syndication.go:244` |
| vx | **没有** | `linkreader/twitter.go:459`（`vxPost` 无用户 ID 字段） |

规则：
1. `Author.ID` 必须是 `State == "available"` 且符合 `^[0-9]{1,20}$`、不全为 0 才算有 ID。~~没有 ID 一律当“不是画师”，既不查表也不按 @账号 兜底~~（已被 ADR-372 改为：线路**没给** ID 时（vx），按 @账号 找 `confirmed` 的行兜底，不分大小写、去掉开头的 @；两行确认过的画师存着同一个账号名算对不上；线路给了但格式不对的 ID 不兜底；有 ID 时只按 ID 认。`Store.ConfirmedHandle`。）
2. 作者取 `Result.Author`（发帖的人），不取被引推文的作者：被引帖在 `Result.Quote.Value` 里，是另一个 `Result`，不参与。
3. ~~残余问题：vx 先到时这一次认不出~~（ADR-372 起按 @账号 兜底，不等 fx、不动取数）。为了让兜底不过时，带 ID 的结果展开时顺手把表里这个 ID 存的账号名更新成现在的，并清掉别的行里还存着同一个名字的（X 的账号名同一时间只属于一个人）；只改账号名，不动状态、批次和撤回用的 Prev（`Store.RefreshHandle`，在 `observeArtist` 里调，预览路径不写）。剩下的漏认：画师改了名、fx 还没带着新名字来过一次之前，vx 先到的那几次认不出。

## 五、发送怎么接

### 五点一 数据流

1. 链接插件取到 `Result` 后（`linkplugin/expand.go`，`Build` 之前）：`mode := p.artistMode(&r, cfg)`——配置 `artist.mode` 不是 `off`、`Result` 是 X 帖子且作者有合格 ID、表里这个 ID 的状态是 `confirmed` 才非空。
2. `linkexpand.Options` 新增字段 `Artist string`（`""` 是旧行为，`"cardAndOriginals"`、`"originalsOnly"`），由调用方填，和 `Translation` 一样每条链接不同；`BuildOptions` 不填它。
3. `linkexpand.Build`：`key == "x"` 且 `o.Artist` 是两个已知发法之一且 `xOwnImages(r)` 非空且是推文（`Kind == "post"`、不是 X 文章）时，`builder.artist` 取模式、跳过 `autoForward`（`forwd` 恒为假）、`template()` 返回内置的画师模板（第一节）、`xMediaItems` 不调 `markPanorama`。其余照旧：`shapeDirect` 管图数、`appendNote` 管提示。
4. 空表、模式 off、不是画师、没有 ID、不够条件：`Artist` 是空，`Build` 的输出和今天逐字节相同（对拍基线不变，见验收 5）。

### 五点二 入口表（命中画师的判断在哪几处）

| 入口 | 带不带画师判断 | 说明 |
|---|---|---|
| 链接插件发送（QQ 私聊、QQ 群） | 带 | `linkplugin/expand.go` 在 `Build` 前填 `bo.Artist` |
| 翻译启动（`startTranslate`） | 不改 | 译文在 `cardAndOriginals` 里照用；`originalsOnly` 白翻一次，不为它另写判断（成本是一次后台模型调用，和今天一样会缓存） |
| ctl `link preview` | 带 | `app/linkpreview.go` 填同一个字段，预览看到的和真发的一样；预览**不**调 `Observe`（预览不记待确认） |
| `cmd/link-samples`、`cmd/link-probe` | 不带 | 开发工具，`Artist` 恒空 |
| 降级重排（`degrade.go`） | 不需要 | 它处理已建好的 `Part` |
| 本地私聊、本地群聊 | **不可能** | `admitLink` 只认 QQ；本地会话不展开链接 |

### 五点三 形状 × 入口（命中画师时）

| 帖子形状 | 结果 |
|---|---|
| 0 张图 / 只有视频 / 只有 link card 图 / 文章 | 不命中，照旧 |
| 1～3 张图，模式 cardAndOriginals | 卡片 + 链接 + 图：≤ 3 个图项直发一条（卡片 1 + 原图 ≤ 2）；原图 3 张时卡片也算，共 4 个图项 → 合并转发（待用户确认第 3 条） |
| 4 张图 | 合并转发：节点 1 链接，后面卡片、四张原图各一个节点（never 时只发前 3 个图项） |
| 1～3 张图，模式 originalsOnly | 链接 + 图直发一条；4 张起合并转发 |
| 图 + 视频 | 图照上面；视频单独一条（B3 第 2 条） |
| 带被引推文 | 被引推文不单独发（卡片里画，originalsOnly 不发）；只算作者自己的图 |
| 拆图候选组（3 张接起来的横幅） | 不拼，三张原图 |

## 七、按需判断（待确认表）

**原则：判断本身不发任何网络请求**，只用这一条推文这一次取回来的 fx / 嵌入接口数据。没有“去拉最近 N 条推文算带图比例”这一步——11-10 的方案笔记实测账号时间线接口匿名下不稳，几千个账号也不能批量爬；用资料里的 `media_count / statuses`（终生带媒体推文占比）代替“最近带图比例”。

### 七点一 什么时候判断

全部成立才判断：展开发送路径上（`j.run != nil`，不是“给她看”的上下文读取、不是预览）；配置 `artist.autoDetect` 开；`Result` 是 X 帖子；作者有合格 ID；**表里这个 ID 没有行**；这条推文有至少一张自己的图（`xOwnImages`）；不是回复（`Result.ReplyTo` 无值）；作者资料可用（见下）。

资料可用 = `Result.Author.Profile` 非 nil（`linkreader.AuthorProfile`：简介、地点、主页和简介里展开后的链接、粉丝数、`media_count`、`statuses`，只有 fx_v2 线路在作者对象带了 `description` 时才填；数字没给记 -1，比例线索不算）。fx_v2、嵌入接口之外（vx 赢了）、响应里作者对象很瘦（只有 ID、名字、账号、头像）时没有资料，**不判、不落行**，下次再说。

### 七点三 判断结果

## 八、验收标准

1. **表**：增、改、删、重载后内容相同；写入用临时文件加改名（测试里让改名失败，原文件不坏）；坏 JSON 改名成 `.bad-*` 并按空表启动；20000 行上限；ID 格式表（空、`0`、字母、过长、带空格、前导零合法性）逐格。
2. **导入**：新增、`pending` 改生效、已生效不动、`declined(manual)` 跳过、格式不对计数；同一文件跑两次第二次“没有变化”且不生成批次；`--undo` 只动带批次的行，被 `confirm` / `remove` 动过的不动；`--undo` 之后表和导入前逐字节相同；路径校验（相对路径、目录、超大、非 JSON、符号链接到别处）各一格。
3. **命令**：`list` 只读（`readOnly` 表里登记、测试里漏登记会红）；写命令在演示模式拒绝；`describe` 白名单；一次超过 200 个 ID 拒绝；handle、名字里的控制字符和换行被清掉；`confirm` 不在表里的 ID 报错且不写表。
4. **ID**：fx_v2、嵌入接口、vx 三条线路各一个夹具：前两条取到 ID，vx 取不到，`Build` 都不报错；~~没有 ID 的结果即使 handle 相同也不命中~~（ADR-372 起：没有 ID 时账号名对上 `confirmed` 行就命中，`pending` 不算、两行同名不算、给了坏 ID 不兜底，`TestHandleFallback`、`TestConfirmedHandle*`、`TestRefreshHandle*`）。
5. **空表不变**：`Artist` 为空时 `Build` 的输出与改动前逐字节相同（跑现有 `corpus`、`golden` 对拍，不重录）；插件整条路径在空表、`mode: off`、`pending`、`declined` 时的 `Part` 与改动前相同。
6. **命中行为**：`cardAndOriginals` 出 `卡片 + 链接 + 原图`、`originalsOnly` 出 `链接 + 原图`，第五点三表逐行有测试；原图地址仍是 `name=orig`；拆图候选组不拼；自定义模板、`forward: always` 被盖过、`never` 生效；`directImageMax` 改 1、3、9 各跑一次；卡片画不出来退通用卡片、原图仍在。
7. **改坏检查**：把“要求 `status == confirmed`”改成“表里有行就算”→ `pending`、`declined` 的测试变红；把 @账号 兜底关掉 → `TestHandleFallback` 变红（ADR-372，2026-11-13 实测）；把 `markPanorama` 的跳过去掉 → 第 6 条拆图测试变红。
8. **按需判断**：像画师的带图原创推文记 `pending`；判断不像记 `declined(auto)`；同一作者第二次不再判（`Observe` 对已有行是只读）；没有资料不落行；回复、没有图的推文、预览路径、`autoDetect` 关闭都不判；`pending` 满 500 行后落 `declined`；判断过程不发请求（测试里 `Fetcher` 的假 HTTP 计数为 0）；`pending` 行不改变这一次的发送（同一条链接前后两次的 `Part` 相同）。
9. **线索表**：Go 判断函数对线索表里每条线索有一个命中例和一个不命中例；“描く”只加 0.5；确认页生成脚本用同一份 `clues.json`，同一个简介两边得分相同（用编的样例）。

## 九、禁止的偷懒写法

- 用 `@用户名` 或名字作为表的键；有 ID 时按 handle 认（ADR-372 只允许“线路没给 ID 时按账号名找 confirmed 行”这一种兜底，名字永远不参与匹配）。
- 判断时为了“更准”去拉账号时间线、媒体页、关注列表；批量遍历。
- 按需判断的结果直接生效（`pending` 在任何地方被当成 `confirmed`），或者在 Build / 发送路径上看 `status != declined`（要看 `== confirmed`）。
- 导入覆盖用户手动做的决定；导入没有批次、撤回靠“整表还原”（会把导入后的手动改动一起撤掉）。
- 把线索表正则写在 Go 里、确认页脚本里各一份。
- 在 `Logf`、trace、错误文字里写简介、名字、账号、ID。
- 命中画师时改动 `shapeDirect`、降级阶梯、回声认领、撤回的逻辑；本功能只换模板和关掉拼图。
- 测试读写真实 `data/`；测试、示例里出现真实账号名、ID。

## 十、已知的坑

- ~~vx 先到时认不出~~（ADR-372 按 @账号 兜底；改名后、fx 还没来过时仍认不出）。fx 的接口还可能整体变更，`Profile` 字段缺了只是不判断。
- **卡片算一张图**：`cardAndOriginals` 下 3 张原图会进合并转发。这是 B3 规则的直接结果，不单改它。
- **改名**：ID 不变，按 ID 识别不受影响；表里存的 handle 现在也拿来兜底（ADR-372），所以带 ID 的结果会顺手更新它。
- **被封换新号**：新号是新 ID，要重新确认；按需判断会把它记进待确认，用户 `confirm` 即可。旧号的行留着，无害。
- **`media_count / statuses` 是终生比例**，不是“最近”；转推多、早年发过很多图的账号会偏。所以它只占 1～1.5 分，单靠它到不了 3 分。
- **判断过的账号不再判**：账号后来改了简介变成画师，按需判断不会再提；用户可以 `confirm`（`declined` 可以直接 `confirm`）。
- 导入文件的 `screen_name`、`name` 是用户自己导出的，仍按外来文字处理（清控制字符、截断）。
