## 进程与入口

桌面主程序在 [`native/main.go`](../native/main.go)，使用 mygo 原生窗口和 MewTypeUI；Go 后台与窗口在同一进程。窗口经 `internal/api` 的查询、订阅和动作接口访问后台，桌面连接不经过旧网页端口。QQ 协议连接仍用 WebSocket，模型调用仍由独立的网络客户端承担。

| 入口 | 实现 | 职责与当前边界 |
|---|---|---|
| 桌面和托盘 | [`native/host.go`](../native/host.go) | 持有一个 `app.App`，串行切换 archive / receive；先关桌面查询，再关后台资源。默认 archive 只看已有 Go 历史，启动接收后才装配会话处理 |
| 无界面后台 | [`cmd/sumika-go`](../native/cmd/sumika-go/main.go) | 调同一个 `internal/app`，不另造后台 |
| 本机控制 | [`cmd/sumika-ctl`](../native/cmd/sumika-ctl/main.go) | 经本机管道控制已打开的桌面程序；不是网页客户端 |
| 本地模型进程 | [`cmd/sumika-models`](../native/cmd/sumika-models/main.go) | 嵌入、重排的独立进程；宿主按 `embed.backend` 选择并管理，见Go 本地模型（私有存档） |

资源根、数据目录的选择和重启语义见[运行时参考](subsystems/runtime.md#go-桌面根目录与数据位置adr-248)；启动参数见 [native/README](../native/README.md)。当前 archive 不接受本地发送，本地与 QQ 独立启停的方向见[多平台装配规格](规格-多平台装配.md)，不能把架构目标当作已经接通的入口。

## 装配与扩展

[`internal/app/app.go`](../native/internal/app/app.go) 负责构造配置、存储、模型、回合与记忆等资源并关闭它们。内核插件实现 `turn.Plugin`，由宿主 `Hub.Use` 安装；`Setup(*turn.Registry)` 注册上下文贡献、工具、已观察事件、回合结束和压缩前钩子。接口及撤销约定见 [`turn/plugin.go`](../native/internal/turn/plugin.go)。渠道还有拦截器、入库观察者和平台适配器，不能把所有 Go 包都视为同一种插件。

插件所需服务由宿主通过公开接口或回调注入，插件不引用彼此实现。例如宿主打开角色记忆后将查询回调交给 `memplugin`，再注册到 Hub；链接服务在 [`app/channel.go`](../native/internal/app/channel.go) 构造后交给 `linkplugin`，同时接内核和渠道挂点。

| 要改的部分 | 入口与规格 |
|---|---|
| 会话实例、排队、回合、工具循环、压缩 | `internal/turn`；[Go 后台](规格-Go后台.md)、内核补强（私有存档） |
| 本地私聊与本地群聊 | `app.DesktopReader`、`internal/localgroup`；[界面接 Go 后台](规格-界面接Go后台.md)、[本地群聊](规格-本地群聊.md) |
| QQ 接收、调度、裁决与投递 | `internal/channel`、`channel/snowluma`；[渠道中间件](规格-渠道中间件.md)、[QQ 发送上线](规格-QQ发送上线.md) |
| 记忆读取、写入准入与回合接线 | `internal/memory`、`memwrite`、`memplugin`；[记忆与嵌入参考](subsystems/memory.md)、[记忆写入上线](规格-记忆写入上线.md) |
| 工具、授权与审批 | `internal/tools`、`policy`、`approval`；[Go 工具参考](subsystems/go-tools.md)、[外平台执行和远程审批](规格-外平台执行和远程审批.md) |
| 配置写回与插件入口 | `internal/config`、`app`、`api`；[模型设置页](规格-模型设置页.md)、插件配置与扩展点（私有存档）、[插件页](规格-插件页.md) |

更细的包依赖图在[子系统参考](subsystems/README.md#现行-go-后台分层2026-11-04)。统一插件身份、依赖、开关和声明式界面扩展仍有待做部分；现有 Registry 不等于已具备通用插件设置页或任意插件热重载。

## 消息的实际路径

1. **本地私聊**：桌面调用 [`DesktopReader.SendLocal`](../native/internal/app/desktop_chat.go)，核对会话归属后交给 `Hub.SendLocal`，草稿回调显示流式正文，停止和审批走同一桌面契约。本地群由 `localgroup.Service` 处理成员、观察和调度，再调用 Hub。
2. **QQ 私聊与 QQ 群**：SnowLuma 适配器翻译输入，宿主装配的渠道中间件执行准入、存储、观察通知、拦截和闸门；`Responder` 调内核，结果经裁决、出口检查和持久化后交给协议适配器投递。收到、生成完成和确认送达是不同状态。
3. **记忆**：`memplugin` 的上下文钩子召回并追加参考信息；`OnSeen` 唤醒后台整理排程。`memwrite` 单独决定角色能否写入、能否整理；注册了插件不等于两档都开启。第一档 remember 已有真实写入记录，完整后台整理验收仍见[上线规格](规格-记忆写入上线.md)。
4. **显示**：`desktopread` 从 Go 平台库查询历史并订阅提交后的变化；界面经 `api.Reader` 获取结果。媒体查询与读取见[界面接 Go 后台](规格-界面接Go后台.md)，不复用旧网页的 `/api` 接口。

四种场合的权限、召回与披露边界统一引用[架构总纲第四节](架构.md#四不能破的规矩)。已定的本地群执行审批、外平台远程审批、前台开工单交给后台执行者分别按 ADR-269、277、295 的规格推进；不能以设计目标为现有入口放宽能力。

## 数据与配置位置

以下路径相对选定的数据目录；代码真源为 [`internal/paths`](../native/internal/paths/paths.go)、[`store.Set`](../native/internal/store/set.go) 及记忆装配。

| 数据 | 位置与状态 |
|---|---|
| 配置 | `config/sumika.yml`；当前配置查找和受支持字段写回见[运行时参考](subsystems/runtime.md)。按插件家族拆文件是已定待实施方向 |
| 角色卡 | `characters/<角色>/card/`；不进 git，仓库的 `characters/` 只留示例 |
| 平台聊天记录 | `go/chat/local.db`、`go/chat/qq.db`；每个平台一份原始事件及角色观察关系 |
| 运行追踪 | `go/trace.db`；各平台共用 |
| 角色记忆 | ADR-308 已定固定为 `go/characters/<角色>/memory.db`；装配用 `paths.Paths.MemoryDB`，不再读导入标记 |
| 主人共用记忆 | `shared/owner-memory.db`；共用资格、来源和角色专属内容边界见[记忆参考](subsystems/memory.md) |

聊天与追踪库当前仍由 `Paths.ChatDB` / `GoTraceDB` 打开 `go/` 下的文件。待办中的搬到 `shared/` 计划尚在，不能因 Bun 已退役就宣称搬迁已发生或已取消；本页不改变该规划。角色记忆的位置则已由 ADR-308 单独确定。

新角色缺记忆库时，当前 `openMemories` 会跳过该角色。2026-11-08 用户已定“插件开着就自动建好”，正式建库入口待做；建库与授权写入、后台整理是不同步骤。

## 原生界面与后续设计

界面结构和交互以[信息架构](信息架构.md)、交互原型（私有存档）、[设计语言](设计语言.md)及[设计规格](设计规格-照Grokbot.md)为准：主线 Go + mygo，分栏照 Telegram、设计和配色照 Bun 版、消息内渲染照 Grok（ADR-279、283）。原型与正式接线的进度分别记在各自规格，不把原型假数据当后台能力。

原有初稿中的职业、人设成长、表达学习、桌宠、手机客户端和按需技能等产品方向继续由[路线图](路线图-1.0.md)与[待办](待办.md)管理；Bun 的 React/PWA、CSS、旧模型岗位与阶段时间表不再作为落法。手机客户端的配对与审批按架构总纲的 ADR-277 方向，后台工单与固定分工按 ADR-295 / 299，详细接口以各自规格为准。

主仓库的 Bun 只承担 `scripts/` 和 Git 钩子运行时。文档用 `bun run check:docs`；Go 检查按改动挑包；原生界面验收用布局和状态、帧耗时及对应手试清单，入口见 [native/README](../native/README.md)。旧 `check:ui`、`build:web` 和网页端口验收已退役。
