# 规格：回合耗时时间线

> 状态（2026-11-16 整理）：记录、`sumika-ctl stats spans` 和运行页“质量”标签已做；只剩攒数据看哪段最慢，再定先优化什么（待办“每一步的耗时时间线”）。
> 依据：主人 2026-11-09：“有没有什么地方可以存下使用客户端进行工具调用或者其他地方的时候，大概各个部分花了多长时间？比如组装上下文、发送上去等待回复，或者工具调用、代码执行、搜索文件之类的，我觉得这些细节也有很多可以提升性能的地方……这个和Deepseek harness那个带有时间和步骤的日志相关”。

## 参考了什么

| 参考 | 采用 | 不采用 |
|---|---|---|
| DeepSeek harness 轨迹视图（拆解（私有存档） 第 18 节） | 按轮、按步排的时间记录；进行中不虚构耗时；首字从步骤开始计 | 这一步不做它的检查器界面，先有数据和命令行 |
| adk-go 的 span 边界（对照笔记（私有存档）） | 模型、工具各一段，队列和执行分开 | OpenTelemetry 依赖：只写自己的表 |

## 现在缺什么

`model_runs` 有首字和总耗时，`steps` 有工具开始和结束。缺：组装上下文没计时；首字节和首段内容没分开；工具的开始在派发前，排队和等审批都算进工具耗时；重试等待、写库没计时。

## 记什么

trace 库新表 `turn_spans`：`turn_id, seq, kind, name, started_at, ms, outcome`。只追加，不存正文、参数、路径；`name` 只放插件名、工具名、模型名。

| kind | name | 从哪到哪 |
|---|---|---|
| `turn.total` | 空 | 这一轮开始到结束 |
| `context.images` | 空 | 这一轮备图 |
| `context.plugin` | 插件名 | 单个插件拼参考信息（记忆召回在这里） |
| `context.request` | 空 | 每步裁剪历史、拼请求 |
| `model.queue` | 模型 | 排模型名额 |
| `model.wait` | 模型 | 发出到第一个字节 |
| `model.first` | 模型 | 第一个字节到第一段内容 |
| `model.stream` | 模型 | 第一段内容到结束 |
| `model.retry` | 模型 | 出错后等重试 |
| `tool.prepare` | 工具名 | 派发前准备，含等审批 |
| `tool.queue` | 工具名 | 等工具槽 |
| `tool.exec` | 工具名 | 真正执行 |
| `tool.save` | 工具名 | 存结果 |
| `turn.save` | 空 | 每步结束写库 |

`outcome`：`ok` 或 `failed`。回合结束时整批写入；写失败只记日志，不影响回合。

## 不记什么

压缩在进回合之前做，它自己有模型记录；排队等上一轮的时间也不算。渠道发送有 `task_runs`。这几段先不进表，真要查再加。

## 怎么看

- `sumika-ctl stats spans [--days N | --all]`：每种环节的次数、合计、p50、p95、最长，按合计排，能直接看出时间花在哪。
- `sumika-ctl stats spans --turn last` 或 `--turn <回合号>`：这一轮的时间线，按开始时间列。
- 运行页“质量”标签的“每一步的耗时”（2026-11-09）：和 `stats spans` 同一份。
- 右栏“上下文”里一轮的轨迹（ADR-293）还没做。

## 保留

30 天。启动时清一次，不靠定时任务。

## 禁止的偷懒写法

- 不从 `model_runs`、`steps` 反推：反推不出排队和等审批。
- 不在计时点上做 IO：回合里只往内存追加，结束才写库。
- 没有首字节时不编：失败的请求只记一段 `model.wait`，`outcome=failed`。

## 验收

1. 真跑一轮带工具的回合：表里有 `turn.total`、`context.request`、`model.wait`、`model.first`、`model.stream`、`tool.prepare`、`tool.queue`、`tool.exec`、`tool.save`、`turn.save`，时间都不为负。
2. 等审批的时间算在 `tool.prepare`，不算在 `tool.exec`。
3. 模型出错重试：有 `model.retry`，失败那次 `outcome=failed`。
4. 写表失败不影响回合结果。
5. 超过 30 天的行启动时被清掉，新行不动。
6. `stats spans` 的 p50、p95 和合计对得上夹具。
