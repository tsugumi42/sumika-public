## 一、概念

- **预设**：一整套“怎么排”的设置：每个站点的模板（直发、转发）、每站点三项设置（`forward`、`forwardOver`、`descLimit`）、合并转发的节点名和卡片文字（ADR-338 第十四节那五项）。有名字，比如“默认”“简洁”“图多群”。
- **内置预设“默认”**：就是现在 [规格-链接解析模板](规格-链接解析模板.md) 第四节的默认排版。不能删、不能改；想改就新建一个基于它的预设。
- **继承**：每个用户预设有一个上游（`base`），缺省是“默认”。预设里只写和上游不同的项，没写的一律跟上游走；上游以后改了，下游自动跟上。链最多 4 层，不能成环。
- **分配**：会话 → 预设。没分配的会话用全局选定的预设（`linkReader.expand.preset`，缺省“默认”）。多个会话选同一个预设，就是复用。

## 二、配置

```yaml
linkReader:
  expand:
    preset: 默认              # 没单独分配的会话用哪个
    presets:
      简洁:
        base: 默认
        sites:
          x:
            template: "$作者\n$正文文字[\n$图片]"
            forwardOver: 200
          bilibili-video:
            template: "@封面文字"
        forward:               # ADR-338 那五项，可只写一部分
          nodeName: ""
      图多群:
        base: 简洁
        sites:
          x:
            platforms:
              telegram:
                template: "**$作者**\n$正文文字[\n$图片]"
    assign:
      "qq:group:<群号>": 简洁
      "qq:private:<她的号>:<对方>": 图多群
```

- 现在的 `linkReader.expand.templates`、`sites.<站点>`、`forward` 迁移成一个叫“我的设置”的预设（`base: 默认`），`preset` 设成它；迁移只在第一次读到旧键时做，先备份配置文件（`sumika.yml.bak-<时间>`），写回后用加载函数再读一遍确认。迁移后旧键不再读，不留双写（主人 11-03“不被旧设计拖累”）。
- `assign` 的键是会话 id；只能分配给名单里允许展开的会话，设置页只列这些。名单里删掉的会话，`assign` 里那行保留但不生效，设置页标灰“已不在名单里”，可一键清理。
- 预设名：1～20 个字，不能含换行、控制字符、`/`；“默认”保留。改名时 `base` 和 `assign` 里的引用一起改（一次原子写入）。
- 删除预设：有会话或下游预设在用时，确认框列出谁在用，确认后这些会话退回全局预设、下游的 `base` 改成被删预设的上游。

## 三、一个会话最终用什么（解析顺序）

对一条要展开的链接，按 会话 → 站点 → 平台 取值，每一项单独找，找到就停：

1. 分配给这个会话的预设（没有就用全局预设）里，`sites.<站点>.platforms.<平台>.<项>`
2. 同一预设里，`sites.<站点>.<项>`
3. 沿 `base` 往上一层，重复 1、2
4. 内置“默认”

“项”是 `template`、`forwardTemplate`、`forward`、`forwardOver`、`descLimit` 之一，各自独立继承（只改了 `forwardOver` 的预设，模板照样跟上游）。平台键：`qq`、`telegram`、`local`（本地窗口），以后加平台就加键。

运行时把解析结果缓存在每个会话上，配置一变整体丢掉重算（热生效，照模板规格第八节）。

## 四、排版标签跨平台：语义 + 平台翻译

模板里的排版标签表示“想要的效果”，每个平台的适配器自己翻译。适配器只做翻译，不改文字内容、不决定发不发。

| 标签 | 意思 | QQ | Telegram | 本地窗口 |
|---|---|---|---|---|
| `$分段` | 另起一条消息 | 新消息 | 新消息 | 新气泡 |
| `$合并转发` | 之后的内容折起来 | 合并转发 | 可展开折叠引用（`expandable_blockquote`）；超过单条 4096 字再按 `$分段` 拆 | 折叠块 |
| `$节点` | 折叠里再分一节 | 新转发节点 | 折叠里空一行 | 分隔线 |
| `$卡片` | 一张信息卡 | 现在画的卡片图 | 退回 `$封面` + 粗体标题 + 统计行 | 原生卡片组件 |
| `$封面` `$图片` | 图 | 图片段 | 和同一条里的图合成相册（≤10 张，多的分条） | 内嵌图 |
| `$视频` | 视频 | 单独一条（QQ 不能和文字混发） | 和图一起进相册 | 内嵌播放 |
| `**…**`（新） | 强调 | 去掉星号，纯文字 | 粗体 | 粗体 |
| `\|\|…\|\|`（新） | 剧透遮住 | 去掉竖线，纯文字 | spoiler | 点开显示 |

- 新加的两种行内标记在模板语言第 2 条的转义规则里补上：要输出字面的 `**`、`||`，写 `\*\*`、`\|\|`。外部内容（推文正文、标题等字段的值）里的星号和竖线**一律当字面**，不会被解释成标记（防止别人在推文里写 `**` 改我们的排版）；Telegram 适配器负责按它的格式转义。
- 平台不支持某个效果时按上表降级，不报错、不丢内容。降级规则写在适配器代码里，有表驱动测试，每格一条。
- 表里的翻译是代码给的默认，预设不用写任何东西就能在所有平台用；只有想要不一样的排版才在 `platforms.<平台>` 下覆盖。

## 五、设置页

在“链接解析”一节里：

1. **预设**分组：列表（名字、基于谁、几个会话在用），新建（选基于谁）、复制、改名、删除。点开一个预设就是现在的“消息格式”编辑页（按站点分页、插入占位符、套用内置模板），每一项旁边显示“跟随 默认”或“已改”，已改的有“恢复跟随”。
2. 站点页里加一行平台切换（通用 / QQ / Telegram / 本地）：选“通用”编辑 `sites.<站点>`；选某个平台编辑覆盖，没覆盖时文本框显示通用模板的灰字，开始输入才创建覆盖。
3. **会话**分组：名单里每个会话一行，右边下拉选预设（第一项“跟随全局：<名字>”）。可多选会话批量改。
4. 预览：现有预览加平台切换，同一条链接看三个平台各自发成什么样（消息数、每条的文字和图位置、哪里降级了）。

说明照设计语言第十一节：常驻一行，细的折叠。

`sumika-ctl link preview` 加 `--preset <名字>`、`--conversation <会话 id>`（按分配解析）、`--platform qq|telegram|local`。

## 六、禁止的偷懒写法

- 不许把预设展开成每个会话一份完整模板存进配置（继承就失去意义，改默认要改 N 处）。
- 不许在平台适配器里按站点写特例（`if site == "x"`）；站点差异只能在模板和预设里。
- 不许让外部字段值里的 `**`、`||`、`$`、`[` 被当成标记或占位符。
- 不许缺省分配时静默用“默认”而不是全局预设。
- 迁移不许保留旧键双写或兼容读取。

## 七、已知的坑

- Telegram 折叠引用和相册不能在同一条消息里：相册的说明文字不支持折叠引用。适配器遇到“图 + 折叠内容”时，相册一条、折叠文字另一条，顺序和模板一致。
- Telegram 单条文字 4096 字、相册说明 1024 字；超了按 `$分段` 的位置拆，没有 `$分段` 就在段落边界拆。
- QQ 合并转发里节点名和卡片文字是 ADR-338 的五项，它们属于预设（第二节 `forward`），不同群可以不同；节点头像和号仍固定是她自己（ADR-338 原规则，预设不能改）。
- 继承链里某层被删或成环（手改配置时可能）：加载时报错并指出哪个预设，整个配置不生效，同现有配置写错的处理。
- 会话 id 里有群号和 QQ 号：配置本来就不进 git，示例和测试里的号一律编（LESSONS）。

## 八、验收

1. 解析顺序：表驱动测试覆盖第三节每一步（会话分配 / 全局、平台覆盖 / 通用、各层继承、各项独立继承），改坏任一步都红。
2. 跨平台翻译：第四节表里每格一条测试；外部字段含 `**`、`||`、`$标题`、`[` 时三个平台都原样输出字面。
3. 迁移：旧配置（含 `templates`、`sites`、`forward`）迁移后，同一批真实样本链接（用模板规格第十一节的样本，临时数据目录）在 QQ 平台渲染结果逐字不变；备份文件存在；第二次启动不再迁移。
4. 删除、改名、成环、链过长、预设名非法、分配给不在名单的会话：每种都有测试，报错指出位置。
5. 热生效：改预设或分配后，下一条链接就用新排版，不用重启。
6. 设置页按[设计自查](设计自查.md)验收；预览三平台切换实测截图。
