# 规格：合并走 PR

> 状态：2026-11-19 起公开仓库为开发主仓库，手动走 GitHub PR（ADR-398）。合并自动化见 S3。

## 开工卡

- 每一步在公开仓库开一个可单独撤回的 PR，由 GitHub CI 跑合并检查。
- 合并采用合并提交。需要本机资源的测试由[每日整套](规格-每日整套.md)覆盖。
- 验收时在 PR 上能看到各项结果。必过检查通过、分支跟上 main 后合并。

## 一、现状

`tsugumi42/sumika-public` 是开发主仓库，本机远端为 `origin`。原私有仓库以 `private` 留作只读存档。[CI](../.github/workflows/ci.yml) 在推送和 PR 时跑 Windows、Linux 两格。需要真字体、ffmpeg、中文 pwsh 的用例和慢对拍交每日整套。

## 二、PR 的流程

1. 在功能分支做完一步。推送前按[提交前检查](规格-提交前检查.md)扫描本次新增的隐私内容。
2. 开 PR，正文写这一步的验收。高风险改动补改坏检查和复核结论。
3. 主会话可绑定 PR 接收检查事件。分支要跟上 main，合并以 PR 的必过检查为准。
4. 由负责合并的会话执行 `gh pr merge --merge --delete-branch`，在合并说明里记录 CI 结果。本机用 `git pull --ff-only` 更新 main。

本机[合并队列](规格-合并队列.md)只在 GitHub 不可用时兜底。

## 三、主仓库切换记录

2026-11-19 本机开发仓库切到公开仓库历史。下列步骤保留供追溯。

1. 等私有仓库手上在跑的分支都合进 main，导出最后一次、推到公开仓库。
2. 本机仓库加 remote `public` 指向公开仓库，取下 `public/main`。它和私有仓库的历史没有共同祖先。
3. 本机 `main` 改为跟踪 `public/main`：`git checkout -B main public/main`。工作区里公开版没有的已跟踪文件（`server/`、`desktop/`、`docs/archive/` 等）会从工作区消失，它们留在私有仓库的历史里；`data/` 等不进 git 的目录不受影响。
4. 切换前还没合的分支：用导出脚本的“排除表 + 改写”处理成补丁，在新 main 上重开分支，不直接合（历史不相交）。
5. 私有仓库设为只读存档，`origin` 改名为 `private`，`public` 改名为 `origin`。
6. 导出脚本 `scripts/export-public.ts` 和同步脚本从此不再需要，按 ADR-389 的删除规则处理（2026-11-19 已删；以后还要从私有仓库搬旧分支，用 `git show private/main:scripts/export-public.ts` 取回）。

撤回：私有仓库没有动过，`git checkout -B main private/main` 就能回去。

## 四、分支保护（公开仓库）

- 按 S4 的启用记录，main 经 PR 合并，要求分支跟上 main，`test (windows-latest)` 必过。实际保护设置以 GitHub PR 为准。
- Linux 仍在 CI 中运行，当前工作流设置为允许失败，结果供排查参考。
- 管理员绕过只用于修复检查本身的 PR，正文写原因。合并后删除功能分支。

## 五、禁止的偷懒

- 为了等 CI 写轮询循环（用 PR 绑会话收事件）。
- GitHub 检查没出结果就手动合。
- 为了让合并快一点，又在本机加回一道验证（ADR-398）。
- 为了让 PR 变绿，在 CI 里跳过测试而不写原因；只有“这台机器缺某样东西”的测试可以跳过，跳过信息里写缺什么（2026-11-18 第一次 CI 的做法）。

## 六、已知的坑

- GitHub 的检查挂在提交上，不挂在 PR 上：PR 每推一次新提交，两条检查都要重跑。
- CI 测的是 PR 头和 main 合起来的树（`pull_request` 事件的合并引用）；分支保护要求“分支是最新的”，保证合并时 main 没有在这之后又前进。
- 分支保护要求“分支是最新的”时，main 前进以后其他 PR 要先合上 main 再推，CI 要重跑一遍。一天十来次合并能接受。
- Windows 机器的临时目录是 8.3 短名，产品代码遇到短名会误判成链接（待办已挂）；CI 里已换成长路径临时目录。

## 七、验收

- 普通 PR 核对必过检查结果。合并后确认 main 上有合并提交，功能分支已删除。
- S3 实现时，验证必过检查失败或仍在等待时保持待合并，并覆盖 PR 已关闭或头提交变更的情况。
