## 开工卡

- **我理解成**：Sumika 自己能回答“我现在缺什么、坏在哪、你下一步该做什么”。一张环境清单，每项说清现在的状态、影响什么、下一步怎么办；命令行 `sumika-ctl doctor` 和界面看的是同一份。正例：PowerShell 7 不在，清单里有一条“命令分析器没起来：每条命令都会来问你。装 PowerShell 7 后重启 Sumika”；密钥锁着、程序开不起来接收时，界面和命令行照样能看到“密钥库锁着：用 `sumika-ctl secrets unlock` 解开”。反例：现在这样，`sumika-ctl status` 只有一行“2 项异常（id…）”，下一步写在没人看的 JSON 里；命令分析器缺 PowerShell 时什么都不说。
- **领域正统做法**：`brew doctor`、`flutter doctor`、Hermes `doctor`：一次列出全部检查项，每项一个状态和一句可执行的建议，有问题时退出码非 0；只读，修复是单独的动作。
- **最省事的字面做法够不够**：在现有自检里再加 11 条 S 项不够：自检只在接收模式、程序开起来以后才跑（坑 1、2），缺密钥这类最需要它的时候恰好看不到；而且现有“下一步”在自由文本里，没人看得到（坑 4）。
- **不做什么**：不做自动修复（`--fix` 以后再说）；不做 QQ 连接是否连上的检查（适配器还没有可读的连接状态，坑 5，另挂）；不做每日整套新鲜度的产品项（P1-5 没做，且那是开发机的事，坑 12，这一项显示“不适用：只在开发机上有”）；不做设置页的“运行与诊断”页（P3-6 才分页，坑 14）；不把外部程序的查找收成一处（那是 P2-5，这里只建它要接管的清单）。
- **用户能看能试的验收**：见“验收”第 1、2、3 条。

## 设计

### 1. 一份快照，两个读者

- 新包 `internal/envcheck`：定义清单项和快照，所有检查是**纯函数**，输入由调用方注入（和 `selfcheck` 一样不 import `store/app/turn/...`，坑 3），评估时不起外部程序、不扫目录（坑 3）。
- 清单项：`Item{ID, Group, Name, State, Detail, Next, Affects}`。
  - `State`：`ok`（正常）、`warn`（能用但打了折扣）、`bad`（有功能用不了）、`na`（不适用，写原因）、`unknown`（不知道，写原因；**不能当正常显示**）。
  - `Detail`：现在是什么样，一句话，可以带路径、号码打码。
  - `Next`：下一步，一句话，能给命令就给命令。`ok`、`na` 可以空；`warn`、`bad`、`unknown` 必须有（测试守）。
  - `Affects`：影响什么，一句话（例：“审批：每条命令都会问你”）。
- 快照 `Snapshot{At, Mode, Items}`，`Mode` 是后台当前所处的模式（接收、只看历史、没开）。
- **生产者只有一个**：宿主（`native/host.go` 那一层）。它在后台没开或打开失败时也能生成“基础部分”（不依赖 App 的那些项）；App 开起来以后再补“运行部分”。命令行和界面都读宿主给的这一份，界面不在绘制时读文件或查找程序（坑 14）。快照在状态变化时重算（开关接收、配置保存、解锁密钥），另外每 60 秒重算一次运行部分。

### 2. 第一版的清单（ID 固定，界面和命令行按这个顺序）

| ID | 组 | 来源 | bad / warn 的条件 | 下一步（举例） |
|---|---|---|---|---|
| `env.secrets` | 账号和密钥 | `SecretsStatus`（基础部分；宿主直接读，不经 App，坑 1） | 没有文件：`na`（没有用到密钥时）或 `bad`（配置里的 QQ 号要令牌时）；锁着：`bad`；没有本机副本：`warn` | `sumika-ctl secrets unlock`；`secrets set qq.<号>.token` |
| `env.platform` | 账号和密钥 | 配置（QQ 号、地址）+ 令牌名字在不在（不读值） | 开了 QQ 但没号 / 没地址 / 没令牌：`bad` | 在设置 · 平台账号填号；`secrets set …` |
| `env.models.gateway` | 模型 | `CatalogState`/`CatalogError`（运行部分） | 连不上：`bad` | 打开 Magpie，或在设置 · 模型里换地址 |
| `env.models.catalog` | 模型 | `modelmeta.Store.State()` | 取不到、用的是旧缓存：`warn` | 联网后重启，或关掉 `modelMeta.modelsDev.enabled` |
| `env.embed` | 模型 | S13 的同一份状态 | 同 S13 | 同 S13（带完整路径） |
| `env.kernel` | 后台 | S10 的同一份状态 | 同 S10 | `sumika-ctl kernel retry` 或重启 |
| `env.plugins` | 后台 | `Hub.PluginStatuses()` | 有 `failed`：`bad`，例子写插件 id 和错误摘要 | 看日志；在设置 · 插件关掉它 |
| `env.mcp` | 后台 | S11 的状态 + 从没连上的服务（坑 11） | 被隔离 / 重连用完 / 从没连上：`bad` | 同 S11；从没连上的：查服务的命令和参数 |
| `env.analyzer` | 审批 | `policy.Analyzer` 新加的 `Status()`（坑 8） | 起不来：`warn`，`Affects` 写“每条命令都会问你，检查点不拍” | 装 PowerShell 7（`pwsh` 进 PATH）后重启 |
| `env.backup` | 数据 | S9、S12 的同一份状态 | 备份过期或失败、抽验过期或失败：`bad` | `sumika-ctl backup now`、`backup verify` |
| `env.nightly` | 数据 | — | 永远 `na`：“只在开发机上有（P1-5）” | — |
| `env.tools` | 外部程序 | `internal/toolchain` 的查找结果（第 3 条） | 必需的找不到：`bad`；可选的找不到：`warn`；每个程序一个子项，写找到的路径和来源（自带 / PATH / 配置） | 按程序给：装 ffmpeg 或在 `qq.media.ffmpeg` 填路径 |
| `env.paths` | 数据 | `RootLocation`、配置里写了绝对路径的键 | 配置里有指向数据目录外的绝对路径：`warn`（换电脑要改） | 改成相对数据目录的路径，或换电脑后在设置里改 |

- `env.analyzer` 和 `env.tools` 里的 PowerShell 是两件事（坑 7）：命令分析器只认 PATH 里的 `pwsh`；执行工具能退回 Windows PowerShell 5.1。清单里分开写，`Affects` 写清楚各自影响什么。
- 三类“模型”分开（坑 6）：网关、模型资料库、本地嵌入模型，下一步各不相同。

### 3. 外部程序清单 `internal/toolchain`

- 一张登记表：每个外部程序一行 `{Name, Required, Purpose, 找法}`。第一版登记：`pwsh`（可选，命令分析器）、`powershell`（执行工具的退路）、`rg`、`fd`（必需，搜索工具；`<资源根>/vendor/bin` 优先再 PATH）、`ffmpeg`、`ffprobe`（可选，收视频和链接展开；配置 `qq.media.*` 优先再 PATH）、`git`（可选，Git Bash 钩子）。
- 宿主启动时在后台查一遍（`LookPath` 和文件存在检查，不跑程序、不取版本），结果缓存；配置保存后重查。版本号这一版不取（要起进程），P2-5 再加。
- P2-3 只用这张表**出报告**，不改现有各处的查找代码；P2-5 把各处查找改成走这张表（坑 9），所以表的找法必须和现有代码一致，测试里逐个对照现有查找函数。

### 4. 命令行

- `sumika-ctl doctor`：只读（进只读名单），列出全部项：一行一项“状态 名字：详情”，不是 `ok` 的下一行缩进写“下一步：…”；最后一行汇总“N 项有问题、M 项要注意”。有 `bad` 时退出码 1，只有 `warn` 时 0。`--json` 输出整个快照。
- 程序没在跑时：ctl 报“先启动 Sumika”（和其他命令一致），**不自己去读文件拼一份**（只有一个生产者）。
- `sumika-ctl status` 的“自检”那行照旧，后面加一句“环境：N 项有问题（sumika-ctl doctor 看详情）”。

### 5. 界面

- 运行页“状态”标签里，现有内容下面加一组“环境”：只显示不是 `ok` 的项，每项一行名字加详情，下一步折叠在下面（设计语言第十一节：常驻一行，细的折叠）；全是 `ok` 时显示一行“环境检查都正常（13 项）”。
- **不放进设置页**：ADR-381 的“运行与诊断”页要到 P3-6 才做，现在把状态塞进八页之一会和分页冲突（坑 14）。P3-6 做那一页时，读同一份快照加一组。路线 P2-3 验收里的“设置页”按此改成“运行页·状态”，理由写在这里。

### 6. 现有自检的配合

- `selfcheck.Result` 加 `Next` 字段（JSON 里多一个键，旧读者不受影响），S9、S10、S11、S12、S13 把 Note 里的下一步挪进 `Next`（Note 留原因）；S9 的 bad 补上下一步（坑 4 的反例）。
- 环境清单里 `env.embed`、`env.kernel`、`env.mcp`、`env.backup` 读的是和 S9～S13 同一份注入状态，不另算。

### 7. 绑机器的路径（开发侧）

- `internal/archcheck` 加一条：`native/internal/` 下非测试的 Go 文件里，字符串字面量不许出现盘符路径（`^[A-Za-z]:[\\/]`）；现存的登记成例外清单，只许缩短。`native/cmd/` 和 `scripts/` 是开发工具，不在这条里（坑 13）。

## 分步（每步可单独撤回、单独入队）

1. **清单包和外部程序表**：`internal/envcheck`（类型、每项的纯函数、`Next` 必填的测试）、`internal/toolchain`（登记表、查找、和现有各处找法逐个对照的测试）；`policy.Analyzer` 加 `Status()`；`selfcheck.Result` 加 `Next`，S9～S13 挪下一步。
2. **接线和命令行**：宿主生成快照（基础部分 + 运行部分），后台没开或打开失败时也有基础部分；`ctlproto`/`ctlserver`/`cmd/sumika-ctl` 加 `doctor`，进只读名单；`status` 加一句；MCP 从没连上的口径；插件 failed。测试覆盖验收第 1、2 条。
3. **界面**：运行页“状态”加“环境”一组，`ui.NewTester` 测有问题、全正常、折叠展开。
4. **archcheck 盘符规则**和例外清单。

## 禁止的偷懒写法

- 环境项挂在自检 runner 上（程序开不起来时就没了，坑 1）。
- 界面和命令行各自算一份。
- 检查时起外部程序或扫目录。
- `unknown` 显示成正常；`warn`/`bad` 没有下一步。
- 把命令分析器的 PowerShell 和执行工具的 PowerShell 写成一条“PowerShell 不可用”。
- 在 `envcheck` 里 import `store`、`app`、`turn`。

## 验收

1. 测试里注入“PATH 里没有 `pwsh`”：`sumika-ctl doctor`（测试调后端函数，不真跑程序）有 `env.analyzer` 一条 `warn`，下一步写装 PowerShell 7；`env.tools` 里 `pwsh` 一行是 `warn`、`powershell` 仍是 `ok`。

3. 界面：运行页“状态”里“环境”组列出上面那几条，下一步能展开；全正常时一行。
4. 所有 `warn`/`bad`/`unknown` 都有 `Next`、`Affects`（表驱动测试遍历全部项）。
5. `toolchain` 的找法和现有各处一致：对每个登记的程序，现有查找函数和登记表在同样的 PATH、目录、配置下找到同一个路径（`rg`/`fd` 对 `tools/search.go`，`ffmpeg` 对 `mediafetch/video.go`，PowerShell 对 `tools/shell.go`）。
