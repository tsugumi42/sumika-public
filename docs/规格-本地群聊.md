## 二、先说人话与范围

在本地会话栏点“新建群聊”，起名字、勾选至少两个角色，建完立刻出现在“群聊”组，即使还没有消息也能点开。主人发一句，点名的人先回；没有点名，按成员顺序轮换首位回复者。一条主人消息最多两个不同角色接话，后一位看到前一位已经说完的话。停止会取消整个群这一轮，下一位不能再开始。

本地私聊、本地群聊、QQ 私聊、QQ 群保持四种身份；本地群不是 QQ 群，没有外人。实现不修改 QQ 发送规则、不改真实配置、角色卡或数据。群文字输入框在本次接线范围内；成员增删、群改名/删除、自动无人接话和本地附件不在本次范围。

## 三、存储与技术路线

1. 本地平台库增加 `local_groups`（ID、名字、创建时间、下一位轮转位置）和 `local_group_members`（群 ID、角色 ID、固定序号、自动接话计数、上次自动接话时间）。新迁移只在可写打开时运行。
2. 唯一会话身份 `console:group:<ULID>`，平台 local、渠道 console、形式 group。名字不能作身份。群名 1–40 字；2–10 个不重复、存在且可读的角色（我定的）。组和成员同一事务写入，提交才通知桌面。
3. 展示必须查询成员表核对：观察者过滤只能选群成员；没成员资格、伪造会话形式均拒绝。旧的只读库尚未有群表时，不展示群能力，不能迁移或偷偷写库。
4. 复用同一个 `turn.Hub` 的 `RespondContext`，它与 `turn.Run` 共用完整的内核执行路径；不逐角色调用冷启动的 `turn.Run`，因为那会反复扫中断回合并绕过已挂记忆插件。首轮消息先存为 owner，回复由内核存为对应 character，全部进同一会话。所有成员都记观察记录。
5. 群历史保留原文，每条带可信的说话人 ID；群成员 ID 与名字的对应表由宿主给到关系信息。自己的回复是 assistant，别的角色是带标签的 user，不能丢掉或冒充自己的话。已有实例追上别的角色已完成的回复，不重建整份历史。
   压缩快照仍按 `character_id + conversation` 读取；同群角色不能复用别人的摘要，没有自己的快照就从原文构建。`history.For`、首次构建、缓存实例重建、提前压缩的版本检查统一通过这个入口。
6. 接口是 `api.LocalGroupWriter`，作为 Reader 的可选能力，不扩张 `api.Reader`。`CreateLocalGroup`、`SendLocalGroup`、`StopLocalGroup`；desktopread 只在装配了可写服务时转交，archive 返回明确不支持。发送调用等整轮结束，消息和最终回复由原有订阅推送。
7. 每群同时一个主人轮次；重复发送报忙，不隐式丢弃或排无限队列。不同群互不阻塞。取消信号贯穿等待、冷却和内核；关闭先拒收、取消、等待所有轮次，再关库。
8. `localchat.go` 共用一个 Composer 与按会话保存的输入/运行状态；本地私聊走 `LocalChat`，本地群走 `LocalGroupWriter`，Mentions 留空由后台解析正文。群整轮等待期间显示“正在回复”，发送区禁用而停止按钮可用；发送和停止均收尾后才恢复输入，失败照实显示。切会话不取消发送，换数据源取消并丢弃迟到结果。审批卡只在本地私聊绘制。archive 提示启动后台；Reader 不实现群写接口时不绘制群输入框。

## 四、调度与参数

以下数值均为“我定的”，保守起步，不伪称主人已经拍板。

- 每条主人消息最多 2 个不同角色运行；角色之间最多 1 层接话，同一角色不接自己，不在本轮重复运行。
- @ 的明确 ID 列表按给定顺序，重复 ID 去重；不在群内直接报错。未提供结构化 @ 时，解析独立的 `@角色ID` / `@角色名`；同名有歧义时报错，不能按显示名认权限。
- 有 @：前两位先后回复；只 @ 一位时，第一位若明确 @ 另一个成员，才允许对方自动接话。没有 @：按持久化轮转位置挑首位，完成后下一位可自动补一句。
- 自动接话每位最多 1 次；主人无 @ 时重置全体计数，有 @ 时只重置被 @ 的角色（ADR-035）。自动接话距该角色上次自动发言至少 5 秒，冷却内直接跳过，不挂定时器补发。主人明确 @ 的回复不受此冷却限制。
- 第一个角色出错、被停或没说话，整轮到此为止；已存消息保留。第二位失败不会抹掉第一位的回复。
- 消息非空且最多 32 KiB（UTF-8 字节，我定的）；不切断原文。名字、身份都由边界检查和成员表绑定，输入没有任意 actor 字段。

## 五、记忆与听众

群输入固定 `Audience{Channel:console, Scene:group, PrivateOK:true}`；主人直接触发的角色 `OwnerAsked:true`，角色自动续接的为 false；`PersonIDs` 只记录触发者。场合段使用 `scene-home-group`，不走本地二人私聊提示。

ADR-242 要求每个角色的记忆跨场合可想起、角色之间仍隔离。本分支复用当前记忆插件和 `memory.write` 的角色/场合开关，场合明确为 `local-group`；不在群调度器新设记忆白名单，也不把别人的记忆库挂给当前角色。ADR-242 的全局记忆迁移是已有独立待办，本分支不越过尚未落地的记忆规则：本地群当前听众按现有群规则运行，其他三种场合保持原样，合并记忆分支后自然沿用其新规则。

## 六、禁止的偷懒写法与已知的坑

- 不用群名拼会话 ID，不靠消息作者猜群成员；名字相同不合并角色身份。
- 不把各角色回复写进自己的私聊；不只把主人一句发给两个互相看不见的实例。
- 不另造模型调用循环、不绕过内核清理/工具/记忆，不用无人触发的计时器继续互聊。
- 不把本地群当平台群，也不以本地主人私聊听众冒充群听众。
- 停止可能发生在模型请求前、第一条输出中、两位之间；仅调用 `StopIn` 会漏掉排队但尚未 active 的回合，所以取消必须覆盖排队上下文。
- 同一个群的角色实例分别缓存，必须能追上其他角色的回复；同毫秒事件依 seq 排序。
- 新建空群没有最后发言时间；列表不能伪造“刚刚”，需单独使用可显示空行的既有控件。
