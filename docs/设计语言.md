## 一、总原则

1. **内容是实的，控制是浮的。** 消息、卡片、列表这些内容用实色；顶栏、输入框、菜单这些浮在内容上的控制层才用玻璃。不做玻璃叠玻璃。（参考 Apple Liquid Glass 规范）（“内容是实的”已被 ADR-396 修正：气泡可选玻璃，只有模糊和填充不透明度两个量、不做折射）
2. **只用档位，不写数字。** 颜色、间距、尺寸、圆角、阴影、时长都有固定的几档，组件从档位里取。组件的样式里不出现写死的颜色值、`color-mix`、圆角像素。
3. **圆角同心。** 里面一层的圆角 = 外面一层的圆角 − 两层之间的距离；四边距离相等。
4. **形状跟着内容的形状走。** 只有图标的是正圆；圆角已经到高度一半的是胶囊；其他用超椭圆。
5. **深色不是把浅色反过来。** 浅色靠投影分层次，深色靠"越往上越亮"加细亮边分层次。
6. **一种意思一种样子。** 同一种状态（悬停、选中、危险……）在所有组件里长得一样。
7. **安静，不装饰。** 只有在表达信息时才用颜色、动效、描边。不用 emoji 和 ✓✕ 字符当图标。
8. **看的地方和拍板的地方分开设计**（ADR-057）。
   - **阅览**（看）：分类清楚，能筛、排、搜，信息稳定不跳，一屏多条，可以批量勾选。
   - **决定**（拍板）：一堆同类的事要人隔一阵批量过一遍时，做成一次一条的审核队列。
     - 卡片上只放做决定要的信息，AI 的建议和理由放最显眼处。
     - 一个动作定一条（滑动或一个键），错了撤销、不弹确认框；有进度、结束有小结。
     - 手感可以像游戏（滑卡片、微交互），目的是降低每次决定的成本、不分散注意力。
   - 同一份数据通常两种都有：待处理的走决定，处理过的走阅览，两边能互相跳。
   - 撤不回、影响大的决定（执行工具的审批）不用轻快的滑动手感，要看清再点。
9. **替人做的判断要看得出来**（ADR-058；微软 HAX 指南第 11 条"说清楚为什么这样做"、Google People + AI Guidebook"可解释性与信任"）。
   - AI 或程序替主人做的判断（审核、分类、挑选、过滤），都要看得出三样：
     - **谁定的**：AI / 规则 / 你，用一个小标记，常驻。
     - **一句话理由**：常驻。
     - **细节**：模型、各项标准、原文依据，折叠，点开才看。
   - 常驻的只放做判断必需的；其余都折叠。

## 二、层次

从下到上一共六层。每个组件都要能说出自己在哪一层，样式（底色、投影、怎么收起）就跟着那一层走，不在单个组件里另调投影。

| 层 | 是什么 | 底色 | 材质 | 分层次靠 |
|---|---|---|---|---|
| 0 背景 | 窗口底、聊天背景（图案 / 图片） | `bg` | 实色 / 图案 | — |
| 1 内容 | 消息气泡、思考和工具卡片、列表、设置页的卡片 | `surface`；你的气泡用角色色浅阶 | **实色** | 浅色：`shadow-1`；深色：比背景亮一档 |
| 2 控制 | 顶栏、输入框、侧栏、"跳到最新" | 跟着"面板材质"设置 | 液态玻璃 / 磨砂 / 实色 | 玻璃的边缘高光 + `shadow-2` |
| 3 侧边面板 | 盖在页面上、贴着窗口一边的大面板：放不下三栏时的右侧栏（浮动，离窗口 8、不压暗，见规格-新界面主线第十一节）；以后的通知中心、抽屉 | `surface` | 实色 | `sh-sheet`（比浮层重，四周都有）+ 一圈细边；**点面板外面、按 Esc 收起**，从面板里弹出的菜单、确认框不算外面 |
| 4 浮层 | 菜单、弹出卡片、斜杠命令、确认框、刻度的悬停卡片 | `float`（深色比内容再亮一档） | 实色（玻璃材质时半透明磨砂） | `shadow-3` + 一圈细边 |
| 5 提示 | 悬停提示、小通知 | `tip`（浅色深底，深色浅底） | 实色 | `shadow-2` |

- 第 1 层里还可以有"凹下去"的一块（代码块、审批框、输入框底色），用 `sunken`。Go 外壳里能打字的凹槽（输入框、搜索框、步进器、下拉入口）不用实色，用一层半透明暗色（`winshell.Palette.Well`：浅色是正文色、深色是黑，不透明度取“盖在页面底上明度降 4”的一档），放在页面底上、白卡片上都比所在的面深差不多同样多；实色在页面底上几乎看不出、在白卡片上又显得特别深（2026-11-17 主人在画廊对比小样里挑定 A5“相对凹”）。“平的”那档（分段轨道、没选中的筛选片）仍用实色 `sunken`。
- 导航栏（最左的图标竖栏）用 `rail`，比会话列表（`bg`）深一档，深色模式也是更深；两栏靠底色分开，不靠分隔线或托盘（照线框图和 Telegram 桌面版的文件夹栏，2026-10-15）。窗口窄时会话列表只剩头像，**和展开时是同一栏、同一个底色**，只是变窄，不另做样子。选中块怎么做见"未定"。

## 三、颜色

### 3.1 阶梯

每个颜色生成一组 **12 阶**（做法参考 Radix Colors），组件只按用途取阶，不自己混色。【已有】`tokens.css` 里生成阶梯，组件样式里只剩带 `/* 材质 */` 的 `color-mix`（玻璃、聊天背景、壁纸遮罩，共 13 处，`lint-ui` 放过），其余都取 `tokens.css` 按用途起的名字。

| 阶 | 用途 |
|---|---|
| 1 | 最亮的底（浅色的内容层） |
| 2 | 窗口背景、侧栏 |
| 3 | 组件底色（平时） |
| 4 | 组件底色（悬停） |
| 5 | 组件底色（按下、选中） |
| 6 | 很淡的细边、分隔线 |
| 7 | 细边（组件、输入框） |
| 8 | 细边（悬停、强调） |
| 9 | 实色（主按钮、角标、开关打开） |
| 10 | 实色悬停 |
| 11 | 低对比文字、图标 |
| 12 | 正文 |

需要的阶梯：

- **中性色**：一组，色相和饱和度跟"底色冷暖"设置走（冷 250°、中、暖 70°）。
- **每个角色的主题色**：各一组。色相取角色色，明度按阶固定，饱和度上限压住，保证不同色相的角色看起来一样亮。
- **语义色**：好（绿）、提醒（琥珀）、危险（红）、焦点（蓝）各一组。

深色有自己一套 12 阶，不是浅色倒过来。

### 3.2 按用途起名

组件里只用下面这些名字，不直接写"第几阶"，以后改阶梯不用改组件。【要改】

| 名字 | 取哪 | 说明 |
|---|---|---|
| `surface` | 中性 1 | 内容层（浅色里最亮的一阶） |
| `bg` | 中性 2 | 窗口背景、会话列表 |
| `rail` | 介于中性 3、4 之间（深色比中性 2 更深） | 导航栏 |
| `float` | 浅：同 surface；深：比 surface 亮一档 | 浮层 |
| `sunken` | 中性 3 | 凹下去的块 |
| `hover` / `press` | 中性 4 / 5（叠加在下面的颜色上） | 所有可点的东西的悬停、按下 |
| `line` / `line-strong` | 中性 6 / 7 | 分隔线、细边 |
| `text` / `text-2` / `text-3` | 中性 12 / 11 / 介于 10~11 | 正文、次要文字、提示文字。OKLCH 明度亮色 0.25 / 0.38 / 0.52，深色 0.94 / 0.81 / 0.68，三档等距；原来二级字 0.47（深色 0.77）和三级字几乎一样灰（2026-11-17 体检 C） |
| `accent` / `accent-hover` | 角色 9 / 10 | 主按钮、开关、角标、选中图标 |
| `accent-soft` | 角色 3 | 你的气泡、选中项底色 |
| `accent-line` | 角色 7 | 你的气泡细边 |
| `accent-text` | 角色 11 | 角色色的文字和图标 |
| `on-accent` | 中性 12（深） | 角色色实底上的字 |
| `ok` / `warn` / `danger` 各自的 `-soft`、`-text` | 语义色 3 / 9 / 11 | 状态 |
| `focus` | 焦点蓝 9 | 键盘焦点环 |
| `tip` / `on-tip` | 中性 12 / 1 | 提示、小通知。深色模式下阶梯本身是反的，所以自动变成浅底深字 |

规则：

- **对比度**：正文对背景至少 4.5:1，次要文字和图标至少 3:1。新阶梯生成后用脚本检查一遍。
- **混色**只在生成阶梯时用，用 `oklab`（`oklch` 会转色相）。【已有】
- 实色上的文字永远用 `on-accent`（中性深色），不用白字（浅色的角色色上白字看不清）。【已有】

## 四、文字

- **字体**：文渊圆体（中文和西文都用它）；代码用 Maple Mono，行内代码 500 字重、0.94em。【已有】
- **字号**只有七档（`fs-0` 即 11px，只给角标数字、气泡里的时间、职业标签这种很小的字）。下表是"文字大小 15"时的基准值；设置 · 外观的"字号"（Go 版 13～18，默认 13，亮色和夜间一起改，控件间距和气泡内边距跟着乘，圆角不跟、有自己的两个输入框；网页版是 14～18、默认 16，ADR-128）把字号、间距单位 `--g`、按钮圆角 `--r` 一起乘"文字大小 ÷ 15"（tokens.css 的 `--ts`），默认 16 时正文是 16px。三栏宽度、断点、图标像素不跟着变：

| 档 | 大小 | 用在 |
|---|---|---|
| `fs-0` | 11 | 角标数字、气泡里的时间、职业标签 |
| `fs-1` | 12 | 时间、角标、辅助说明 |
| `fs-2` | 13 | 次要文字、列表第二行、卡片正文 |
| `fs-3` | 14 | 按钮、菜单、表单 |
| `fs-4` | 15 | 聊天正文 |
| `fs-5` | 18 | 区块标题 |
| `fs-6` | 22 | 页面标题 |

- **字重**只用 `--fw-medium` / `--fw-semi` / `--fw-bold`（500 / 600 / 700，深色模式 460 / 560 / 660，见九点五）：正文不单独写字重；medium 用在按钮、表头、行内代码这类比正文稍重的地方，semi 强调、名字，bold 标题、选中项名字。
- **行高**：正文 1.6，单行控件里 1.25。
- 数字用等宽数字（`tabular-nums`）：时间、用量、计数。【已有】
- 不用全大写、不用斜体强调、不在标题里单独给一个词换颜色。
- **标题只有两档类**（2026-10-16 统一，原来设置、右侧栏、性能、记忆卡片各写各的）：页面标题 `.su-h-page`（fs-6、700）用在分类页左上和右边内容顶上；区块标题 `.su-h-group`（fs-2、700、`--text-2`）用在设置分组、右侧栏里的小节、表格上方、弹出卡片里的小节。外边距由放它的地方定，不写在类里。会话列表顶上的"本地 / QQ"（fs-5）是列表的名字，不算这两档。
- **说明小字** `.su-note`（fs-1、`--text-3`）；**凹下去的块** `.su-well`（`--sunken` 底、圆角跟着外层的 `--in-r`）；**统计格** `.su-stats`（每格一个凹块，列数用 `--cols`）。分类页、设置分组、一行一项用组件 `CategoryPage`、`SettingGroup`、`SettingRow`（`ui/page.tsx`，样式在 `ui/page.css`）。一行的说明小字放在名字下面（`SettingRow` 的 `meta`，比如模型的上下文长度），控件靠右贴边、不挤在控件旁边（2026-10-19 主人定）。行里的下拉框、输入框宽 300（`.su-set-ctl:has(> .su-field)`），常见的模型名整个装得下；宽度写在控件上、框填满它，不写死在框上（写死的宽会让窄窗口横着滚）。

## 五、间距和尺寸

间距单位 `g` 跟"疏密"设置走（紧 6 / 标准 8 / 松 10）。

| 档 | 值（标准） | 用在 |
|---|---|---|
| `s1` | 4 | 很紧的组、一行字左右的小留白 |
| `s1-5` | 6 | 半档，只在控件里面和紧挨着的小块之间用：图标和文字之间、标签和输入框之间、一排标签之间、气泡和下面那行时间之间 |
| `s2` | 8 | 同一组里的东西之间 |
| `s2-5` | 10 | 半档，只在控件里面用：单行控件（菜单项、胶囊、小通知按钮）左右的留白 |
| `s3` | 12 | 卡片内边距、消息之间 |
| `s4` | 16 | 区块之间、对话区左右留白 |
| `s5` | 24 | 页面大块之间 |
| `inset` | 6 | 一个容器紧紧包住一个控件时的内边距（输入框、工具卡片、菜单、列表项） |
| `inset-tight` | 3 | 分段、标签条这种一排按钮的外框 |

| `lg` | 44 | 列表项、会话头像（`--h-ctl-lg`，已有）【已有】 |

**小东西**（2026-10-16 定，原来 20 / 22 / 24 / 26 / 28 各写各的）：

| token | 高 | 用在 |
|---|---|---|

**布局和层级**（2026-10-16，原来 CSS 和 `App.tsx` 各写一遍）：三栏宽 `--w-rail` 64 / `--w-list` 280（右侧栏收起时 240、只剩头像 72）/ `--w-side` 320（这几栏的分隔线能拖，会话列表 `--w-list-min` 220 ～ `--w-list-max` 400、右侧栏 `--w-side-min` 260 ～ `--w-side-max` 520，聊天窗口最窄 `--w-chat-min` 420；上面写的是默认宽度，双击分隔线回到它；窗口 ≤ `--bp-compact` 时列表固定只剩头像宽、不能拖；分隔线平时看不见，悬停、拖动、键盘聚焦时在边上显出一条竖条，拖动时是主题色；宽度按像素记在浏览器里，`web/src/Shell.tsx`，ADR-120）；断点 `--bp-narrow` 1180（右侧栏变侧边面板）、`--bp-compact` 820（列表只剩头像）、`--bp-page` 760（分类页目录收到顶上）。`@media` 里用不了变量，数字照抄并在行尾注明是哪个 token，样式检查核对；JS 用 `breakpoint('narrow')` 从计算样式里读。层级只用七档：组件里 `--z-raised` 1 / `--z-bar` 2 / `--z-pop` 3，挂在 body 上的 `--z-sheet` 20 / `--z-approvals` 60 / `--z-overlay` 100 / `--z-toasts` 200。
**滚动区**：设置区（`.su-app-settings`）一直留着滚动条的位置（`scrollbar-gutter: stable`），内容短的分类不留的话，切换时内容会左右跳（2026-10-19 量过：模型页的隐藏标签跳出裁剪、撑出文档滚动条时，整页左移半条滚动条的宽）；文档本身不滚，只有区域里面滚。设置行里的字段（`.su-set-ctl > .su-field`）自己是定位块，里面的隐藏标签不跳出设置区的滚动裁剪。

## 六、形状

### 6.1 用哪种角

| 情况 | 角 | 例子 |
|---|---|---|
| 只有图标的按钮、头像（正圆设置时）、状态点、回应小圆 | **正圆** | 发送、附件、顶栏按钮 |
| 圆角已经 ≥ 高度一半 | **胶囊**：两头用 `superellipse(1.5)`，和直边平滑接上（正圆弧接直边曲率会突变）；高度不到 32px 的（开关、标签、进度条、数字角标）用正圆弧，超椭圆在这么小的地方显得方 | 单行气泡、标签、小通知；进度条、角标 |
| 其他 | **超椭圆**（跟"圆角形状"设置） | 带字的按钮、多行气泡、卡片、面板、输入框 |

### 6.2 圆角的档位

从最里层往外推，每包一层加上那一层的内边距：

| 档 | 计算 | 用在 |
|---|---|---|
| `r-xs` | `r-ctl` × 0.3 | 勾选框、快捷键、行内代码、职业标签 |
| `r-pill` | 999px | 所有胶囊和细条（开关、角标、进度条、滚动条、光标） |
| `r-ctl` | 用户设置（8 / 12 / 16 / 20） | 按钮、输入框、菜单项 |
| `r-1` | `r-ctl` + `inset` | 气泡、列表项、输入框外框、审批框 |
| `r-2` | `r-1` + `g` | 工具卡片、普通卡片、弹出卡片 |
| `r-win` | `r-2` + `g` | 窗口、对话区、设置页大块 |

- 里面的东西圆不到那么大（比如 28 高的按钮最多圆到 14）时，**反过来加大外层的内边距**：内边距 = 外层圆角 − 里层实际圆角，至少 `inset`。【已有：输入框】

## 七、层级和材质

- **投影**四档，按层用，不在组件里另写：`shadow-1`（内容）、`shadow-2`（控制层、悬停提示）、`sh-sheet`（侧边面板）、`shadow-3`（浮层）。设置为"只靠底色深浅"时全部关掉。侧边面板比浮层重：它大、贴着窗口边，`shadow-3` 往下收得紧，用在大面板上左边缘看不出浮起来（2026-10-15 主人指出窄窗口的右侧栏"没有明显的投影区分层级"）。

### 7.1 特效的规矩

融球、液态玻璃、圆角选区、平滑光标、滚动边缘、镂空这些"不规则"的效果，也按同一套规矩来。每种都要说清楚四件事：**用在哪、长什么样（固定参数）、关掉以后变成什么、性能上限**。

| 特效 | 只用在 | 固定参数 | 关掉 / 不支持时 | 性能 |
|---|---|---|---|---|
| 液态玻璃 | 控制层（顶栏、输入框、侧栏、跳到最新） | 磨砂 3px + 边缘 12px 内折射，最多挪 3~4px，**只往里取样**（玻璃拿不到自己外面的背景，往外取会让边缘一圈发灰）；浓度跟设置（−18% / 0 / +20%） | "磨砂"：只模糊 24px；"实色"或系统降低透明度：实色 | 折射图按元素大小生成，只在尺寸变化时重算 |
| 滚动边缘 | 控制层下面那一条 | 三层 10 / 5 / 2px 渐进模糊，高度 = 控制层 + 12px | 实色材质时不画 | 静态，不重算 |
| 融球 | 从一个形状里"长出来"的小东西：跳到最新、表情回应 | 平滑并集宽度 14；小圆直径 28；长出 / 缩回走不过冲的弹簧 | 关动效：直接出现 / 消失 | 玻璃上每帧重算距离场，但只重算圆附近那一块（只有矩形的底图按尺寸缓存），在 Worker（`goo.worker.ts`）里出图，主线程只换图片地址；单帧约 5ms，和整块重算逐像素一致。实色上用滤镜，不重算 |
| 镂空 | 头像上被压住的地方 | 缝 2px，形状跟被压的东西同一条曲线 | — | 静态 |
| 圆角选区 | 正文和聊天输入框的选中文字 | 色块圆角 6，同一段相邻行连成一片，段落之间分开；颜色 = 所在位置的角色色 | 设置"默认选区"、高对比度模式、选超过 4000 字：浏览器默认 | 一帧最多算一次 |
| 平滑光标 | 聊天输入框 | 2px 宽，滑动 90ms，停 500ms 后柔和地闪 | 设置"系统光标"、减少动效：系统光标 / 不闪 | — |
| Live Orb | 角色头像（设置为 Orb 时） | 眼睛按球面投影转，最多转 ±41°；随机眨眼 | 减少动效：不呼吸 | 所有 Orb 共用一个动画循环，页面藏起来时停 |
| 轮次刻度（只在本地会话） | 聊天右边的刻度尺，悬停一格 | 离指针 3 格以内的格子按余弦放大，最多 1.5 倍（`BUMP_MAX` 0.5、`BUMP_TICKS` 3）；"当前这一轮" 1.3 倍（`CUR_SCALE`）；缩放和卡片位置指数平滑，时间常数 60ms（`TAU`）；速度上限按 16 毫秒折算：卡片最多挪两格，格子缩放最多变 0.05（`SCALE_STEP`）；卡片顶边对着指针下面那一格的顶边。没用弹簧：要把 342px 的大跳一帧压到两格以内，弹簧得拖到秒级 | 减少动效：直接到位，不限速 | 只动 `transform` 和 `--y`，不动宽度；指针移动只记坐标，每帧（rAF）算一次、不读布局；格高 9px 只在 `chat.css` 的 `.su-tick` 写一次，脚本运行时量 |

### 8.1 交互叠层 `.su-press`（2026-10-15）

"悬停叠一层、按下再深一层"只有一种写法：能点的**块**（卡片标题、列表行、引用块、文件树项、单选卡片、回应小圆、右侧栏的段落行……）加上 `class="su-press"`。

- 底色不动，在上面用 `background-image` 叠一层 `--press-ov`：悬停 `--hover`，按下 `--press`。圆角自动跟着元素走，元素自己有底色（引用块、单选卡片、选中的文件树项）也一样。
- 焦点环也由它画，默认在里面；独立浮着的块（引用块、单选卡片、回应小圆、跳到最新）设 `--press-ring: var(--ring-out)` 画在外面。
- `--press-ov` 用 `@property` 注册成能渐变、能往下继承（文件树贴在右边的改动数跟着这一行变色）；每个 `.su-press` 先清成透明，嵌套的不会沾上外层的。渐变放在 `:where()` 里，组件自己写了 `transition` 的，在列表里加上 `--press-ov`。
- **控件不用它**：按钮、分段、标签页、勾选框、输入框、菜单项有自己设计的状态色（主按钮悬停是更深的角色色），照旧。
- 普通按钮的底是半透明的 `--btn-soft`（悬停 `-hover`、按下 `-press`），放在什么颜色的底上都跟着那个颜色走（2026-10-15：原来是实心的 `--sunken`，放在黄色提示条上是一块脏灰色，警告卡片还得单独补）。输入框是"凹下去的块"，仍然用实心的 `--sunken`。
- `bun run lint:ui`（网页时代，已退役，在 sumika-bun）会拦住：能点的块在 `[data-hovered]` / `[data-pressed]` / `:hover` 里自己写 `background`。
- 来由：主人指出"叠层太补丁了"——之前 49 条悬停规则，没底色的直接换底色，有底色的各想各的办法叠（`::after`、渐变、自定义变量）。

## 九、动效

- 默认是**平滑弹簧**（0.17 s、不回弹）；"回弹"（0.17 s、回弹量 0.25，过冲约 3%）只用在位移和缩放上，**高度变化永远不过冲**（ADR-152；时长 ADR-155 从 0.26 s 改成快档 0.17 s，试用中）。
- 时长两档：`dur-fast` 140ms（颜色、透明度）、`dur` 230ms（位置、大小、展开收起，弹簧采样出来的）。分档的打算见[规格-组件库需求清单](规格-组件库需求清单.md)第五节。设置里的"动效速度"把所有时长乘 0.8 / 1 / 1.25。
- 出现：淡入 + 很小的位移或缩放（具体数值见下表）；消失比出现快。
- （已被 ADR-124 改为：减少动态效果时留下淡入淡出、时长照常，只把位移、缩放、模糊、高度展开的幅度乘 `--motion` 变 0；循环动画那半句不变。改动和 animate-ui 那批动效一起做，做完把这条重写）系统"减少动态效果"或设置为"关"：只把 `--motion` 改成 0。过渡、进出场的时长都写成 `calc(基数 * var(--motion))`，自动变 0；呼吸、眨眼、转圈这类循环动画不乘（乘成 0 会停在最后一帧），各自停成什么样写在 `@container style(--motion: 0) { … }` 里（转圈放慢到三倍、思考点停住、闪一下换成焦点环）。所有时长都在 tokens.css 起名，样式检查拦写死的秒数。（2026-10-16，原来两份清单各写一遍，系统减少动态效果时弹簧时长和转圈都没停）
- 不做没人触发的装饰动画。例外：Live Orb 的呼吸和眨眼，三个点的浮动。
- **进出场的时长和曲线**（数值来自 Notion《界面动效与层级｜开源做法、场景参数与 motion token（2026-10-13）》，token 在 `tokens.css`）：退出比进入快，进来用 `--ease-out`（先快后慢），出去用 `--ease-in`。

  | 场景 | 进 / 出 | 位移 |
  |---|---|---|
  | 悬停提示 | 150 / 100ms | 2px |
  | 菜单、弹出卡片 | 180 / 130ms，缩放 .98 | 6px，从触发它的那一边出来 |
  | 确认框 | 220 / 160ms，缩放 .985 | 10px |
  | 看大图（遮罩 + 图） | 220 / 160ms；退场时图缩到 .97 | 已被 ADR-304 改为：从缩略图位置飞出放大、关闭飞回，缩略图不在屏幕里时淡入淡出；下有胶片条。原规则：不位移（scripts/check-viewer-exit.ts 逐帧量；网页时代，已退役，在 sumika-bun） |
  | 小通知 | 220 / 150ms，缩放 .96 | 10px；用浏览器的视图过渡，剩下的几条会顺着挪 |
  | 新消息、新卡片 | 200ms | 往上浮 8px，不缩放文字 |
  | 换角色、换标签、进设置 | 200ms 淡入 | 不整块横移 |
  | 右侧栏打开 | 230ms（ADR-155，原来 280ms） | 从右边滑进 12px |
| 右侧栏收起（窄窗口的侧边面板） | 200ms，`--ease-in` | 往右退 16px 淡出，放完才摘掉，期间内容照旧、不接点击（2026-10-20，对照 animate-ui 侧边面板"出 0.2s"） |

- **她说话时新出来的字**：从模糊到清晰（默认）、淡入、直接出现三选一（设置里改）。用 Streamdown 自带的动画，按词，140ms，词和词之间只错开 8ms；只有正在出字的那一条动，写完换成静态渲染、动画节点清掉；代码块和工具输出不动；关了动效时直接出现。参数来自 Notion《聊天区性能与动效》。
- **不动的**：键盘导航、输入回显、频繁跳动的数字直接更新；读历史记录一次进来好几条不播进场；草稿换成正式消息、三个点换成气泡是原地换掉，也不播。按下缩放：已被 ADR-349 改为按住缩到 .97（只有图标的圆钮 .96），试用中。
- **进出场一律用关键帧动画，不用 transition**：React Aria 的 `data-entering` 只存在一帧，Chrome 来不及画起点，过渡会直接跳过（2026-10-14 实测菜单打开第一帧就是不透明的）；关键帧动画 React Aria 会等它放完才摘掉 `data-entering` / `data-exiting`，退场放完才移除元素。【已有】

  - **滑块指示器**（sliding indicator）：一组里"选中"的那块是一个独立的块，换选中项时从旧位置滑到新位置，而不是旧的变暗、新的变亮。用在分段切换、图标标签条（React Aria 的 `SelectionIndicator`），会话列表的选中块和悬停块（自己写的，同一个思路）。以后侧栏、单选卡片要加也用这一个。【已有】
  - 展开收起：高度用不过冲的曲线（工具卡片、并行卡片）。【已有】
  - 浮层出现、消失；按下缩放见 ADR-349。【已有】
  - 截图对比只截静止的样子，过渡本身靠在画廊里点一点看。

## 九点五、文字的细节

- **字重**用 `--fw-medium / --fw-semi / --fw-bold`（500 / 600 / 700），深色模式各减 40（460 / 560 / 660）：浅色字在深底上看着会变粗。两款字体都是可变字体，中间字重是真的。样式检查不许写死字重。
- **避免最后一行只剩一个字**：写完的消息正文用 `text-wrap: pretty`，标题用 `balance`；正在出字的不用（每来一个字整段都要重排）。对中文有改善，不保证完全没有。
- **深色浮层的边**：0.5px 内侧亮线代替 1px 描边；125% / 150% 缩放下要是看着忽明忽暗，就退回 1px、更低的透明度。

## 九点六、消息里的媒体（media.tsx）

- **图片**本身就是气泡：没有底色，圆角和气泡一样（`--r-1`）。单张按原比例缩进 320 × 360 以内，**小图不放大**；加载前按比例占位，量到的真实尺寸记下来，下次挂上不再跳。表情包缩进 160 × 160、没有底、不裁圆角。带引用卡、表情回应、注释的图片消息用同一套排法：图始终贴着气泡左右边、圆角由气泡裁；引用卡、表情回应条、配文自己离气泡边一个竖内边距（卡在图上面、条在图下面，和图之间也是一个竖内边距）；注释和时间同在叠在图上的牌子里。图在文字后面（图文混排）时图缩在内边距里。
- **多张**拼网格：2、4 张两列，其余三列，格子之间 2px，最多 9 格，多的写"+N"。
- **给她看的描述**：悬停或键盘聚焦时图片变模糊、描述浮在上面。普通图：模糊挂在描述遮罩上（backdrop-filter），和遮罩一起淡入淡出，图片本身不动 filter（动 filter 悬停时掉帧，scripts/check-hover-blur.ts 拦）。表情包例外：遮罩不带 backdrop-filter（透明的角也在方框里，糊成一块色块就丢了轮廓），模糊挂在表情包图本身上（filter 的函数列表固定，悬停只改 `--img-blur`，过渡用 `--dur-fast`）。叠在图片上的字（时间、+N、描述、GIF）压在暗色遮罩上，深浅色都用白字。
- **动图**照常播放；系统"减少动态效果"时有第一帧就显示第一帧。
- **图种**：图片下面一条提醒色的"图片里藏了一个文件：名字（大小）"，按钮"另存出来"，不自动打开。
- **看大图**：全局只有一个，消息刷新、重新挂载时不会被关掉。滚轮缩放（100%～400%）、放大后拖动、双击切换、← → 换张、+ - 0 键盘缩放、Esc 关；暗幕用更深的 `--scrim-strong`。关掉时遮罩淡出、图缩到 .97 一起淡掉（160ms，退场期间内容不先清空；减少动效时直接消失）。
- **语音条**：播放按钮 + 波形（有真实音量用真实的，没有就按时长生成固定的高低）+ 秒数，越长越宽（132～260px）；播放时波形从左往右变成角色色；可以带一行转写。
- **视频**：按比例放进 480 × 400（比图片大，图是 320 × 360；横拍 480 × 270，竖拍 225 × 400；小的视频也放大到框，不像图片那样"小图不放大"）；框用后台存好的宽高先占位，挂上就是最终大小，列表不跳。控制条：播放、进度、时间（框窄于 300 时挤掉）、喇叭（点一下静音，悬停或键盘聚焦时浮出短滑块；所有视频共用一个音量）、放大看（打开看大图的查看器，在那里接着播，底下有播放、进度、时间、音量、全屏、关掉；行内停下的位置跟着走）。查看器里点画面切换播放，点画面两边的黑边关掉（和看大图点空白处一样）。没下载的显示封面和"视频没有下载（几秒）"。（scripts/check-video.ts 量）
- **文件卡**：文件类型图标、名字、大小；文件已经在这台电脑上时按钮是"在文件夹里显示"，不重复下载。

- **链接卡片**（`LinkCard`，QQ 小程序、分享卡片）：来源一行（小图标 + 名字）、标题最多两行、简介一行、16:9 封面（离卡片三边 `--linkcard-pad`，圆角同心）。整张卡片是链接：新窗口打开、不带来源，悬停按下走 `.su-press`。卡片总是放在气泡里，宽 280、不超过气泡（别写 `min(100%, …)`：气泡量自己多宽时百分比不算，会按标题排成一行的长度撑宽）。封面和图标经后台代取（`/api/qq/remote-image`，只取腾讯图片服务器），页面不直接连。【已有】

## 九点七、加载状态（2026-11-08）

加载占位（骨架屏、"取数据中…"、刷新标记）只在"确实慢"的时候出现，不能一开始取数就闪出来再消失。公共状态机是 `native/internal/loadstate`，骨架条和占住位置的提示行在 `native/internal/loadui`；各页面共用，不自己写计时。

| 规则 | 做法 |
|---|---|
| 延迟出现 | 开始加载后过 `ShowDelay`（300 毫秒）数据还没到，才画骨架或刷新标记；阈值内到了，全程不画。阈值内没有旧数据时只留空位，位置占住、什么都不画 |
| 出现后至少留一会儿 | 占位一旦画出，至少留 `MinShow`（300 毫秒）再撤，数据早到也等够再换 |
| 保留旧数据 | 刷新、切筛选、切角色时继续显示上一次的内容，新数据到了原地整份替换，不先清空再填；有旧数据时只在角落放一个不打扰的小标记（同样遵守上面两条）。只有第一次进入、确实没有数据时才走骨架 |
| 换成另一件东西 | 点了另一条记录这类"旧内容不能当新内容显示"的，先 `Reset`；阈值内留空位，之后才出骨架 |
| 尺寸一致 | 骨架条用同字号、看不见的文字行撑高，行数、间距、内边距照真实内容；整块高度出现前后不变。提示行用 `loadui.Line`，没出现时也占着同样的高度 |
| 出错 | 有旧数据就留着并标"已过期"，不清空；没有旧数据才画出错状态 |

两个常量的出处（2026-11-08 核对）：`MinShow` 照 React 调度里的 `FALLBACK_THROTTLE_MS = 300`（兜底刚出现过，300 毫秒内不揭示真内容，免得连着闪出很多加载状态；`ReactFiberWorkLoop.js`）；`ShowDelay` 参照交互时延通行分档（0.1 秒即时、1 秒思路不中断，Nielsen，Response Times）和 spin-delay 的默认值（delay 500 毫秒、minDuration 200 毫秒），取 300 毫秒。React 自己没有"延迟多久才出兜底"的常量，不拿它当出处。没有核对 Telegram、iOS / macOS 的数值。

时间由页面每帧传 `c.Now()`，状态机自己不读时钟；到点那一帧用 `loadui.Wake` 安排。测试用 `ui.Tester.Advance` 推进时间，不用墙钟等待。

## 十一、措辞

- 按钮写它会做什么（"批准""删除"），不写"确定""提交"；同一个动作从按钮到提示用同一个词（点"删除"，提示"删掉了"）。
- 取消叫"算了"，免得和"撤销"看混。
- 不用超链接样式的文字当按钮；不放不必要的说明文字。
- **功能和设置起名**（主人 2026-10-16）：用大多数 App 里常见的叫法，而且功能上要能类比，看名字就能联想到它做什么、不产生歧义（比如"睡眠模式"而不是"暂停"：手机上的睡眠模式大家都知道是"安静、但东西照收"）。起完名字问一句：用户会不会以为它多做或少做了什么。
- **加一个设置之前**：先想清楚它有没有实际要用的场合、存在的理由是什么；和相近的设置会不会冲突、会不会让人分不清。说不出理由的不加；和别的分不清的，合并或者重新定义（例：暂停、频率 0、不学习，2026-10-16 重新分清）。
- **说明文字**（设置项下的小字、提示、空状态里的话，行业叫 helper text / microcopy；ADR-059）：
  - 先让标签自己说清楚；要靠一段话才懂的选项，该改的是选项本身。
  - 常驻的说明最多一行，说"这个会怎样"，不讲原理。
  - 更细的放悬停提示或折叠的"详细"里。
  - 状态不同、说明跟着变时，只写当前状态下有用的那句。
- **用平常说话的完整说法，不要省字省成文言**（主人 2026-10-17："没设""设好"太精炼）：写"还没有设置主密码"不写"没设"，写"保存主密码"不写"设好"，写"原因"不写"为什么"当表头。状态和按钮不放在一起比长短：一行里有按钮时，状态写进按钮本身（"设置主密码" / "修改主密码"）或下面那行说明，不在按钮旁边再摆两三个字的状态（样式检查拦：设置行里挨着按钮的状态文字少于 4 个字）。
- 以后整体换成更软、更可爱的说法，但要提醒注意的地方仍然要清楚，内容要准确（另写一份措辞表）。【待定】

## 十二、切换不抖，控件分族（2026-11-08，ADR-322）

- **切换时不相关的元素一帧也不能动。** 点分段、拨开关、选下拉、换分类、拖滑块的时候，没被这次切换影响的元素，x、y、宽、高每一帧都和切换前一样。测试用 `assertNoLayoutShift` / `assertNoHorizontalShift`（`native/layoutshift_test.go`）逐帧量。字号变了行高跟着变不算，控件自己的横向位置和大小不能动。栏宽（导航 72）不随字号、疏密缩放：缩放会让整页横向挪动。
- **控件按语义分族，每族只留一种实现**：几选一且固定几格、语义不同用**分段**（`winshell.Segment`：选中块四边等距、圆角 = 轨道圆角 − 内边距、滚动不飞、只在换选项时滑动、方向键切换）；选项多、会换行的筛选用**筛选片**（`winshell.Chips`：药丸、四边内距相等）；连续数值用**滑块**（`winshell.Slider`：带刻度、键盘左右键可调、拖动时界面实时变、松手才写盘）；要精确数字用**输入框**；从一长串里选一个用**下拉**。
- **悬停、按下用中性色（hover、press），强调色只给选中项。** 悬停块内层缩进、四边等距、圆角同心，不许比所在的栏宽。
- **分组之间用细线（line）加留白，不用整行宽的色带。**
- **滚动条半透明、浮在内容上、不占布局宽度**，颜色用令牌（正文色 32%），亮色夜间同一个。
