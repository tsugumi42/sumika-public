# 规格：日志分级（级别、模块标签、旧行兼容、读取过滤）

> 状态：第 1–6 步已实现并经一轮复核修正，已合 main（合并提交，2026-11-13，实现记录和偏离见第十四节）；第 7、8 步未做。开工顺序见第九节，每一步可单独撤回。依据 [ADR-367](决策记录.md#adr-367)。
>
> 现状依据：`native/internal/filelog/filelog.go`（一行一条、本地时间、换行转义，唯一写入口 `Logger.Printf`）；全仓约 677 处 `func(format string, args ...any)` 形式的日志调用，**没有级别**，靠文字前缀区分（`snowluma: `、`链接插件：`、`回合 %s …` 三种写法并存）。

## 一、要解决什么

1. 读日志的人（主人、巡检、Agent 通过 `sumika-ctl logs`）分不出“要处理”和“只是记一笔”：`connect.go:219` 的“连不上协议端，按退避重连”和 `connect.go:561` 的“接收端未收下消息”在文件里长得一样。
2. 没法只看错误：巡检现在只能 grep `error` 和几个中文短语（见 [规格-运行时自检](规格-运行时自检.md) 第一节）。
3. 模块名靠每处手写的字符串前缀，写错、漏写都不报。
4. 桌面程序是 `-H windowsgui` 编的，没有 stderr。`app.newLogf` 的兜底是 `log.Printf`，`checkpoint.go:116`、`checkpoint/service.go:163/191/194` 直接用 `slog.Warn`，这些行**进不了 desk 日志文件**（盘点结论，第一步就修）。另有一个相关落点：`filelog.fileFor` 在数据目录的身份文件（`paths.MetaFile`）出现之前不开文件，那之前的行只去 `out`，桌面里 `out` 是 nil，**启动早期的行直接丢失**。

## 二、参考（采用什么、不采用什么）

- **Go 标准库 `log/slog`**（本仓库 `go 1.27.3`）：采用四档级别 `DEBUG / INFO / WARN / ERROR` 及其名字；采用 `slog.SetDefault` 把 `log` 包和三方的输出也接进同一个 Handler（官方文档：设了默认 logger 以后 `log` 包的输出走它的 Handler）；采用“先判 Enabled 再格式化”。**不采用** slog 的 `key=value` 文本格式和 JSON：gate-report、巡检和人读的都是中文整句，行格式要保持我们自己的一行一条。
- **RFC 5424 的严重度名字**：只借“错误 > 警告 > 通知 > 调试”的划分含义，不用它的数字和设施（facility）。
- **不采用中文级别名**（调试 / 信息 / 警告 / 错误）作为文件里的词：文件里的词要能被 grep、能被过滤，定宽英文词在 Agent 和脚本里最稳。界面（`sumika-ctl logs` 的表头、运行页）再映射成中文标签。
- 本仓库已有的 `filelog` 行格式（时间、换行转义）**保留**，它是 gate-report 和 `oneLine` 的依据。

## 三、行格式（定死）

```
2026-11-13 10:02:31 WARN snowluma 连不上协议端，按退避重连: 连接被拒绝
│                   │    │       └ 消息（一行，换行写成字面 \n，同现在）
│                   │    └ 模块标签（ASCII 小写字母、数字、下划线；来自封闭名单）
│                   └ 级别：DEBUG | INFO | WARN | ERROR（大写、不补空格）
└ 时间：StampLayout，19 个字符，和现在一样
```

- 前 19 个字符仍是时间，后面紧跟一个空格，所以 `gate-report` 的 `line[19] == ' '` 检查**不用改**。
- 旧行（没有级别和模块的行，比如 `2026-11-12 19:37:00 snowluma: 连不上…`）继续有效：读取时算“无级别”（`Level == ""`），消息原样。
- 新旧行的区分靠第 3 个字段：是 `DEBUG | INFO | WARN | ERROR` 之一就是新行；否则是旧行。新行的模块标签不合法（不在名单里、带大写）时写成 `Module == "?"`，并计入读取侧的“坏行”计数，不丢。
- 消息里原来写的 `snowluma: ` 之类前缀**迁到模块标签里**，消息文字去掉前缀。gate-report 依赖的整句（`QQ 连上了`、`QQ 断了，…`、`桌面程序启动，…`、`关完了（关机诊断：…`）只要不带前缀，就照常匹配。

### 3.1 读取：唯一的解析函数

`internal/filelog` 新增：

```go
type Entry struct {
    At     time.Time // 时间（本地）
    Level  string    // DEBUG|INFO|WARN|ERROR；旧行为 ""
    Module string    // 模块标签；旧行为 ""；坏行为 "?"
    Msg    string    // 消息正文（不含级别和模块）
    Raw    string    // 原行，sumika-ctl logs 原样输出它
}
func ParseLine(line string) (Entry, bool) // 时间不合法返回 false
```

`gate-report`（`cmd/gate-report/connections.go:70-82`）、`sumika-ctl logs` 的过滤、看门狗事件记录（`watchdog/incident.go:143`，只取原行，可不改）都走 `ParseLine`。**禁止**各处自己 `line[20:]` 切（现在 `connections.go:70` 就是这么切的）。

## 四、写入：一个 Handler，一个出口

### 4.1 包和类型

新包 `native/internal/applog`（只依赖 `filelog`、`config.MaskID` 那一层的打码函数由装配处注入，不反过来 import `app`）：

- `Root`：一个进程一份。持有 `*filelog.Logger`（或 nil）、当前级别（`slog.LevelVar`，原子）、模块级别覆盖表、早期行环形缓冲、打码函数 `Redact func(string) string`（装配处传入，内部就是 `app.RedactLog(s, tokens)`）。
- `Root.Slog(m Module) *slog.Logger`：带模块的 slog logger，给新的调用点用（可以写 `Warn`、`Error`）。
- `Root.Logf(m Module) func(string, ...any)`：**保留现在的签名**，内部是 `Slog(m).Info(fmt.Sprintf(...))`。677 处现有调用点靠它平移，不改签名。
- `Root.Handler()`：`slog.Handler` 实现。`Handle` 组装整行：`时间 级别 模块 消息[ 属性]`，属性写成 ` key=value`（值里的换行转义），**整行**过 `Redact` 和 `oneLine`，再交给 `filelog` 的新方法 `Line(s string)`（写一整行，不再加时间前缀）。

`Module` 是封闭名单：`applog` 包里一组常量（`app`、`desk`、`go`、`turn`、`channel`、`snowluma`、`linkplugin`、`memory`、`memplugin`、`memwrite`、`watchdog`、`ctl`、`mcp`、`proactive`、`backfill`、`store`、`llm`、`approval`、`taskrun`、`mediafetch`、`checkpoint`、`selfcheck`、`backup`，以后加的写进这里）。名单外的字符串不能造出 `Module`（类型保护，构造函数只接常量）。

### 4.2 装配（谁给谁日志）

- 模块**不自己填模块名**。装配处（`internal/app`，`app.go` 里 `a.logf` 的各个注入点，现在约 40 处）改成 `a.root.Logf(applog.Turn)` 这种写法，把常量交给模块。模块内部的默认值（`turn/plugin.go:241` 的 `log.Printf`，`memplugin/plugin.go:98` 等）改成接收注入的 logger；**没有注入时**的默认值是 `applog.Fallback()`（模块写 `misc`，见 4.4），不许再是 `log.Printf` 或空函数。
- `slog.SetDefault(root.Slog(applog.Misc))` **只在入口调一次**：`cmd/sumika-go/main.go` 在建 `lg` 之后，`desklog.go:37` 在 `filelog.New` 之后。**不放进 `app.New`**（测试里会多次建 App，全局默认值会互相覆盖）；测试里用 `t.Cleanup` 还原。
- **现行做法（复核二改）**：打码函数由入口注入 Root（`app.RouteLogs`、`openDeskLog`、`openWatchLog`），Printf 形状的出口和 slog 都经它，写文件前只打一次；自己带令牌表打过码的出口走 `Root.Masked`。**禁止**新增入口时不注入打码函数。以下是原来的写法：`host.logf`（`native/host.go:152`）和 `app.newLogf`（`app/log.go:86`）、`shell.go:244` 的 `backend.RedactLog(line, nil)` 三处都是打码入口，所有行都经 Handler，Handler 再用注入的打码函数过整行一次。`host.logf` 的 `h.redactor` 和 `newLogf` 的 `a.tokens` 在装配时指向同一份令牌。

### 4.3 级别和早期行

- `Handle` 之前先看 `Enabled(level)`：级别不够直接返回，不做 `fmt.Sprintf` 之外的任何工作（`Logf` 的 `Sprintf` 在 Handler 调用前已做，所以热路径上的大段调试消息要用 `Slog(...).Debug` 配 `slog.LogAttrs` 或判断 `Enabled`，不许循环里 `Sprintf`）。
- 文件还没开（数据目录的身份文件未出现）时，行进入**早期环形缓冲**：最多 200 行或 64 KB（先到先算），文件一开就按顺序写进去，之后不再写。缓冲满了丢最旧的，并在第一次丢时写一行 `WARN applog 早期日志缓冲满，丢了 N 行`（这一行本身进缓冲）。
- 数据目录一直没出现（比如第一次启动就失败）：早期缓冲写到 `%LOCALAPPDATA%\Sumika\early.log`（`os.UserCacheDir()` 下），只在 `Close` 时写，最多 200 行。

### 4.4 没归属的行

`slog.Default` 接到的第三方和 `log` 包的行没有模块标签时，写成模块 `misc`，并且**同一进程里只为“第一次出现的每个调用位置”**记一条 WARN（`misc 出现未归属的日志：<文件:行>`）。测试扫描生产代码（非 `_test.go`、非 `cmd/`）里对裸 `log.Print*` 的直接调用，发现一处就红。

## 五、级别怎么定

### 5.1 规则（写给改调用点的人）

| 级别 | 定义 | 判定词（参考，不是硬规则） | 例子（盘点的 20 条） |
|---|---|---|---|
| ERROR | 有数据会丢、或要人处理、或一次操作最终失败且没有后续重试 | 没收下、丢、最终放弃、写入失败、打不开 | `snowluma/connect.go:561/566/571` 接收端未收下消息／通知／状态；`turn/hub.go:258` 收拾上一个进程没收尾的回合出错；`turn/hub.go:2083` 最后一次重试仍失败的那条 |
| WARN | 出错或降级，但系统会自己接上（重试、重连、兜底、降级） | 出错、重试、重连、降级、兜底、没成、没来得及 | `connect.go:219` 连不上协议端，按退避重连；`connect.go:259` 连接断了；`connect.go:398` 没收到任何帧判掉线；`connect.go:544` 无法解析帧（单帧跳过）；`hub.go:905/908` 压缩没成、只带最近的话重建；`hub.go:992` 后台提前压缩没用上；`hub.go:1204` 没交回写库的结果，照库重写；`hub.go:1558` 库里读出的条数与批次不一致，照旧拼成一条；`hub.go:2083` 每次重试（非最后）；`linkplugin/expand.go:408` 取数失败；`expand.go:189` 开始状态未入队；`app.go` 启动时本地私聊 backend 与配置不一致（需要重启才生效，WARN） |
| INFO | 正常的生命周期、正常结果、用户可见的状态变化 | 启动、退出、清掉、记成、已恢复 | `turn/hub.go:248` 清掉超过 N 天的回合时间线；`hub.go:260` 上一个进程没收尾的回合记成被打断（正常启动恢复）；`watchdog/supervisor.go:123` 守护进程结束（正常结束；**异常结束的原因升为 ERROR**）；`turn/late.go:39` 补图没来得及送到 |
| DEBUG | 每轮、每步的细节；为排查准备；用户设置预期的结果 | 每步、补图送到、在设置里关了 | `hub.go:1884` 补图送到 conversation=…；`hub.go:2016` 回合第 N 步；`linkplugin/expand.go:401` 在设置里关了，不展开 |

判定顺序：先看有没有“丢”和“最终失败”（ERROR）；再看“会重试 / 会降级”（WARN）；其余是 INFO；只给排查用的是 DEBUG。拿不准的写 WARN，并在提交说明里写“拿不准，等主人看”。

## 八、读取侧（第 5 步）

`sumika-ctl logs` 加过滤，**过滤在截行数之前做**：

```
sumika-ctl logs [-n 行数] [--level debug|info|warn|error] [--module <名>] [--errors]
```

- `--level warn`：WARN 和 ERROR。`--errors`：只要 ERROR，等价 `--level error`。
- 服务端（`ctl.go:190` `Logs` 那一支）：`Tail` 读取上限 `scanLimit`（20000 行，按行数不按字节），过滤后取最后 `n` 行；返回里带 `scanned`（扫了多少行）和 `matched`（匹配多少行）。
- 旧行（无级别）：**不带过滤时照常显示**；带 `--level` 或 `--module` 时不显示，并在结果末尾注一行“另有 K 行是旧格式（没有级别），没有参与过滤”。
- `ctlproto.Logs` 增字段是加法（JSON 可选字段），老客户端不受影响；`ctlproto/proto.go:33` 的行数上限不变。
- 表头和颜色不做（ctl 是纯文本）；界面标签的中文映射（调试 / 信息 / 警告 / 错误）只在界面里做。

## 十一、已知的坑

- **gate-report 的整句匹配**依赖消息正文不带前缀。第 3 步迁移模块前缀时，要把每条整句匹配的消息核一遍（`connections.go:77-82`）。
- **巡检 SKILL 在仓库外**（`%USERPROFILE%\.claude\scheduled-tasks\sumika-daily-patrol\SKILL.md`）。它 grep 的 `error` 和中文短语在新格式下仍能匹配（`ERROR` 在 grep 里大小写不敏感要写 `-i`），但它的“开始接收失败”等短语来自 `native/host.go:362`，格式变了要改它时由主会话做，本规格不改它。
- **`filelog.Tail` 只认两天**（`tail.go:39`）。过滤时扫描上限只按行数算，不要因为文件跨两天就漏行。
- **`slog.SetDefault` 是全局的**：测试里不还原，会让后面的测试的 `log.Printf` 进错的 Handler。
- **打码函数的令牌是后来才拿到的**（配置读完才有）。早期缓冲的行到文件开以后再打码，要保证“先缓冲、后打码”不会把令牌原文留在缓冲里：缓冲只存**已经过 `Redact` 的整行**，令牌还没拿到时整行先不进缓冲，只进计数（写 `WARN applog 令牌未就绪，早期行 N 条未写入`）。
- **属性值可能很长**：属性写进整行前截到 500 字符，超过的写 `…`。
- 旧的 `Logf` 在格式串里有 `%`（比如 `%.1f 秒`）的调用，改 Handler 之后不能再对结果做第二次 `Sprintf`（现在 `newLogf` 是 `out("%s", …)`，要保持）。

## 十二、验收标准（每条都有测试或实测）

- **A1 解析**：`ParseLine` 对旧行、新行、缺模块的行、级别小写的行、时间错误的行各有一条用例；坏行返回 `Module == "?"` 且计数。
- **A2 一行一条**：消息里有 `\r\n` 的，写出后仍是一行（现有 `oneLine` 测试扩到 Handler 路径）。
- **A3 级别过滤**：`logs.level: info` 时 `Debug` 调用不写、不调用 `String()`（用计数的 `slog.LogValuer` 断言）。
- **A4 打码**：令牌原文出现在消息正文和属性里，写出后都是 `***`；两条入口（`host.logf` 和 `newLogf`）各一条用例；`shell.go:244` 的路径也过同一个 Handler。
- **A5 早期行**：数据目录身份文件出现前写的 5 行，出现后写进 `desk-<日期>.log`，且排在前面；`Close` 之前没有出现身份文件时写到 `early.log`。
- **A6 模块**：装配测试枚举 `app.Options` 的每个注入点（测试里列清单，新增注入点不列就红：用反射数 `Options` 的 `Logf` 字段数），每个 logger 的模块属于名单；跑一个完整的启动和关闭，文件里不出现 `misc` 行（或出现时测试指出是哪一行）。
- **A7 gate-report 不变**：`testdata/` 放一份脱敏的桌面样本（旧格式和新格式各一份，手写，不从真实日志复制），统计结果与改动前一致（`connections.go` 的输出逐项相等）。
- **A8 ctl 过滤**：`--level warn` 只返回 WARN 和 ERROR；`--module snowluma` 只返回该模块；带过滤时旧行被排除且有注记；`scanned`、`matched` 数对得上。
- **A9 保留**：假时钟下，超过 `keepDays` 的文件删，今天和昨天的不删；删除那一行存在且只写一次。
- **A10 性能**：`BenchmarkHandle`（写到 `io.Discard`，不含磁盘）对比改动前的 `filelog.Printf`，单行开销不超过 1.5 倍；`Enabled` 为假时不分配（`testing.AllocsPerRun` 断言 0）。
- **A11 旧行可读**：`Tail` 对只有旧行的文件照常返回原文，与改动前逐行相等。
- 每一步的测试在 `native/` 里用 `bun ../scripts/slot.ts go test ./internal/applog/ ./internal/filelog/ …` 跑；只用 `t.TempDir()`；`slog.SetDefault` 用 `t.Cleanup` 还原。
