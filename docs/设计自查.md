# 设计自查

新页面、新组件交付前，以及改动一块界面的结构时，按这张表逐条过一遍。不过的条目写进提交说明，或者当场改掉。2026-10-16 起（ADR-056）。

起因：第一次做出来的结构常常"有就行了"，没想过往后数据变多、窗口变化、看的人第一次来会怎样（主人 2026-10-16）。这类检查在设计行业叫**启发式评估**（heuristic evaluation，最常用的是 Nielsen 的十条可用性原则）或**设计评审**（design critique）；下面每一条后面写了它的通用叫法，方便查资料。

给 AI 派界面任务、验收 AI 做的界面时，另照 [人指导 AI 做界面的准则](notes/准则-人指导AI做界面-2026-11-04.md)：信息架构和设置归属（A）、视觉层级（B）、间距圆角对齐（C）、动效（D）、AI slop 症状（E）、任务模板和验收清单（f 节和末尾）。2026-11-04 起。

## 一、读得懂吗

1. **一眼先看到什么**（视觉层级，visual hierarchy）：这一页最重要的一件事是不是最先被看到？标题、正文、辅助说明有没有拉开档次（字号、字重、颜色至少差一档），还是全是一个灰度？
2. **扫得下去吗**（可扫读性，scannability）：列表和表格里，用户要找的那个字段是不是在每行同一个位置、左对齐、够醒目？长段说明能不能缩成一句 + 展开？
3. **东西是不是按关系摆的**（格式塔的接近原则，proximity）：属于一组的挨得近，不同组之间的间距明显大于组内间距。间距只用 `--s1…--s5`，同一层级用同一档。
4. **有没有重复和多余**（信息冗余，redundancy）：同一个信息有没有在标题、副标题、说明里说两遍？分类页里标题下面有没有又一个意思一样的标题？每个元素删掉后用户会不会少知道什么？不会就删。
5. **一次给多少**（信息密度 information density、渐进披露 progressive disclosure）：常用的直接看到，少用的收进展开、悬停、右键；不要把所有字段平铺成一张宽表。
6. **加的这个设置 / 功能有理由吗**：说得出要用的场合吗？和相近的设置会不会冲突、让人分不清？名字是不是常见 App 的叫法、看名字能不能猜对它做什么（设计语言第十一节）。
7. **词是用户的词吗**（系统与现实匹配，match between system and the real world）：写用户懂的说法，不写内部字段名、接口名；同一件事在按钮、提示、标题里叫同一个名字。

## 二、放大十倍还行吗（内容压力测试，content stress test）

7. **数量**：10 个角色、上千条记录、几百个群时，这个结构还成立吗？一个角色占一列、一类一个标签这种结构，数量一多就塌（2026-10-16 学到的表格）。
8. **长度**：特别长的名字、标题、一整段没空格的英文、空字符串，会不会把布局撑开、挤掉按钮？该截断的地方有省略号和悬停全文。
9. **空、错、加载中**（各种状态，empty / error / loading states）：没数据、出错、正在加载时各显示什么？有没有下一步可以做的事？
10. **量出来**：元素数、切换时主线程卡多久、滚动跳几次，写数字（AGENTS.md 验收）。

## 三、窗口变了还行吗（响应式布局 responsive layout、尺寸约束 size constraints）

11. **每个大块的最小宽、最大宽、最大高**定了吗？正文一行不超过 45 个字左右（行长 measure）；很宽的屏幕上内容是限宽居中还是无限拉长？
12. **弹性容器**：flex / grid 里的子元素有没有 `min-width: 0`，长内容会不会把它撑出容器？能缩的、不能缩的分清楚。
13. **能拖的**：会话列表、右侧栏这类边栏要不要能拖宽、拖到多少为止、记不记住？
14. **断点两边**都看一遍（`--bp-*` 两侧各差 1px），再看很窄（480）、很矮（560 高）、很大（1920），以及主人自己的屏幕（2048×1030，像素比 1.25：1px 的线会落在半个物理像素上，细线、细字要在这个比例下看）。`scripts/check-fit.ts` 会量（网页时代，已退役，ADR-203，脚本在 sumika-bun 仓库；mygo 界面的量法见最后的"工具"一节）。

## 四、点得中、用得顺吗

15. **点击目标**至少 24×24（WCAG 2.2 的 target size），常用的按钮 32 以上；挨着的两个按钮之间有空隙。
16. **每种状态都有样子**：悬停、按下、键盘焦点、禁用、选中，状态矩阵里都摆出来了。
17. **键盘能走通**：Tab 顺序合理，Esc 能关，焦点框只在键盘操作时出现。

## 五、和其他地方一样吗（一致性，consistency and standards）

18. 同一类东西用同一个组件、同一档尺寸。新出现一种高度、圆角、字号时，`scripts/check-census.ts` 会拦下来（网页时代，已退役，ADR-203，脚本在 sumika-bun 仓库）：先想能不能用已有的档。
19. 做之前先翻[线框](界面清单.md)和[设计语言](设计语言.md)，有现成的样子就照着做。

## 六、风格统一吗（2026-11-15 起，主人看组件画廊后定的）

第一次按这节盘点的结果：[盘点-风格统一-2026-11-16](notes/盘点-风格统一-2026-11-16.md)。

起因：主人看画廊说“有些地方很扁平，有些地方又很立体，属于同一个组件的元素变化时整体性不强”“审批卡叠了很多层”。下面每条都是主人说过或规格里写着的，括号里是出处；画廊的“族谱总览”一页把每一族的静止样子并排放，用来一眼对这张表。

20. **立体感只有三档**：凹下去（等人填的：输入框、搜索框、步进器外框、下拉入口）、平的（贴在面上的：按钮、图标钮、分段轨道、没选中的筛选片）、浮起来（选中块、卡片、圆钮；菜单、下拉面板、对话框是浮层档）。底色、细线、阴影只经 `winshell` 的 `Sunken` / `Flat` / `Raised` / `FloatShadow` 上，不在组件里自己写阴影或黑色加透明度（`internal/winshell/depth.go`；主人 2026-11-15“我觉得都可以整”）。
21. **单行控件一律胶囊，多行的才用圆角矩形**（`Geometry.Pill`；主人 2026-11-15“单行的其实用胶囊也没什么”，这条是归纳，主人没逐字确认）。**放在圆角面板里的项跟面板同心，不另做胶囊**：菜单项、下拉和选择器的选项、斜杠命令行、选区条上的按钮、可展开的行（主人 2026-11-16 照推荐定；macOS、iOS 的菜单项也这样）。
22. **嵌套同心等距、层数尽量少**：内圆角 = 外圆角 − 内距；里层圆角被挤得很小时先数嵌套了几层、能不能少一层，别先改圆角（LESSONS“界面”；主人 2026-11-15“同一个层上面叠了 3 层，加上文字有 4 层”）。几何检查 `uitest.CheckTree` 自动量。
23. **同一个信息只出现一次**：图标、命令、名字不在标题、步骤头、正文里各写一遍（主人 2026-11-15 审批卡“出现了两个图标、两份指令”）。
24. **状态用图形，少写字**：结果用小图标加两三个字，失败用角标，通用快捷键不写提示（主人 2026-11-06、11-15）。
25. **选中只有一层**：选中就是带主题浅色的那一块（`Palette.Self`），选中项自己不另画底；用 mygo 底座的控件每个状态都显式写 `Background`（规格-过渡动画第十一节）。
26. **一个组件变化时像一个整体**：下拉是入口自己长开，菜单、对话框从触发它的东西长出来、缩回去，审批卡收成一行时是同一张卡在变（主人 2026-11-15“整体性不强”“下拉……基于收起来时的状态，同一个组件扩展拉伸”）。
27. **动效只从弹簧预设里挑**：位移、尺寸、缩放用 `design.Springs` 六个预设，颜色、透明度用时长淡变；减少动态效果时不动只淡（规格-过渡动画第十一节）。
28. **会变的数字留死宽**：按最宽的数字量宽度（`chatui.DigitSlotWidth`），每秒最多变一次、逐位滚（同上）。
29. **两边的气泡是一种做法**：自己的气泡不比对方的多一圈边（主人 2026-11-15“一边突出来，另一边……还有个边框”）。
30. **液态折射只给压在文字上的浮层**（标题条、输入区、菜单、下拉）；气泡的玻璃只有模糊和填充不透明度（主人 2026-11-15）。
31. **单行控件两档高，同一行只用同一档**：36（`RowHeight`）给输入框、搜索框、步进器、下拉入口和放在它们旁边的按钮（`Kit.FieldButton`）；28（`HitSmall`）给工具栏、卡片里、单独一行的按钮、筛选片、分段（`Kit.Button`）。混在一行会高低不齐（主人 2026-11-16 照推荐定）。
