## 一、工具

`ask_owner`，`policy.Specs` 登记 `Effects: ["self"]`、`Audience: "owner-console"`，不并行。参数：

```json
{ "question": "问题", "options": [ { "label": "短名字", "detail": "可选的一句话说明" } ] }
```

| 参数 | 限制 | 超出时 |
|---|---|---|
| `question` | 去掉首尾空白后 1～500 字，换行可以，其他控制字符不行 | 出错结果，告诉她怎么改，不弹卡 |
| `options` | 2～4 个；每个可以是对象，也可以直接是字符串（弱模型常这么传） | 同上 |
| `label` | 去掉首尾空白后 1～40 字，一行，不重复 | 同上 |
| `detail` | 可选，最多 120 字，一行 | 同上 |

自由回答一律有（输入框），不是参数，模型不写“其他”。

## 二、结局

| 结局 | 怎么到的 | 给她的结果 | 聊天记录 |
|---|---|---|---|
| 选了 | 点选项 | `主人选了：「X」`，加“这是回答不是批准” | 问题是她的一条；选项是主人的一条 |
| 直接说了 | 等待中有插话（第四节） | 中性措辞：`主人没有点选项，直接回了一句（就在这条后面）`，加“不是批准” | 问题；主人的话走插话那条路存 |
| 先不答 | 点“先不答”，或焦点在卡片里按 Esc | 别再问同一件事；能定就选最稳妥的，定不了就说明 | 问题 |
| 没回答 | 到期 | 不算同意；不靠答案的先做完，靠答案的别猜，说明后结束这一轮 | 问题（主人之后回了开新一轮） |
| 被停了 | 停止按钮、回合被取消 | 工具错误，这一轮本来就在收 | 问题 |
| 程序退出、崩溃 | 见第六节 | 她收不到 | 问题；系统行 |
| 没等 | 无人值守（第五节）、时限不够、同时等的太多、这轮上一个已经没等到 | 说明为什么没等，怎么接着做 | 问题，无人值守时带上选项 |

等待时限 = `tools.approvalMinutes`（默认 10 分钟）和“这一轮的总时限（`agent.budget.maxDurationMs`，默认 15 分钟）减 45 秒”里小的那个。不够 45 秒就不等。等待算进这一轮的总时限，和审批一样；不改预算。

## 三、不等于批准

- `internal/askowner` 不 import `internal/approval`、`internal/policy`，不碰 `Grants`、`ConvGrants`。
- 答案只变成一段文字进工具结果和聊天记录。答完以后的 `write`、`powershell` 照常过 `Gate.Check`。
- 选项叫“允许”也一样；卡片不用审批卡的“允许一次 / 拒绝”布局。
- 问题不进 `approvals.Snapshot`：目标模式的 `pendingApproval`、自检的 `waiting_approval` 都看不到它。

## 四、和插话、停止怎么共存

会话里有问题在等时：

1. **输入框打字发出去 = 回答**。界面在输入框有字时把停止键换回发送键，这句话交给 `SubmitLocal`。
2. `SubmitLocal` 看到这个会话有问题在等：`start` 改成对当前运行的 `steer`（和自动轮的处理同一处）。受理成功后结束等待（`Center.Interrupt`）。
3. 这句话照插话那条路：提交时存成主人的消息，带引用、带图都行；工具结果先回，下一步开头她看到它。
4. **任何插话都结束等待**，不只界面来的。否则工具等回答、插话等工具做完，互相等到超时。
5. 斜杠命令照旧在提交时处理，不算回答，问题还在等。
6. 插话撞上这一轮刚好结束（`ErrInputConflict`）：改成普通发送。
7. 排队（`queue`）不算回答：它的语义是这一轮结束后再发。
8. 停止按钮、Esc（焦点不在卡片和输入框里）不答问题，停下这一轮；为避免误停，卡片开着时窗口级 Esc 不停止，和审批卡一样。输入框有字时要停，先清空。
9. 回车守门：卡片出现后 500 毫秒内焦点按钮上的回车不算，防正在打字时误点。新卡片不抢焦点。

## 五、无人值守

| 入口 | 能看见工具吗 | 行为 | 依据 |
|---|---|---|---|
| `/goal` 进行中（第一轮和续轮都算） | 能 | 不等：问题留在聊天里（带选项）、提醒主人、结果里说“能定就选最稳妥的接着做并说明，定不了就说明卡在哪后结束这一轮” | 引导加简单兜底 |
| `/goal`，她问完这一轮什么工具也没再调就结束了 | | 轮末 `NeedsUser` 为真，目标走现有暂停路径 | 她定不了就别再自动续；问完接着干的不暂停 |
| `/loop` 的一轮 | 能 | 同目标的不等 | |
| 主动联系的线 | 不能（`PrivateOK` 为假） | 线里 `thread_send` 本来就是对主人说话，不需要卡住线 | 规格-主动联系第八节 |
| 自检话题 | 能 | 不等、不提醒：`sumika-ctl chat` 没人能点，也不该把卡片留给主人 | |
| 子任务 | 不能（`authorizeInternal` 不放行，执行时再核 `Kind`） | | Codex 只给根线程 |

判无人值守只看宿主自己的状态（`auto.has`、`goalActive`、`IsSelftest`），模型改不了。

## 六、重启

路线是“如实结束并在界面标出”。不做待答表，也不恢复等待。

- 问题在问出口时已经是一条消息：重启后还在聊天里，主人照常回一句就开新一轮，她重建的历史里有这个问题。
- 卡片是内存里的，不恢复。一轮被切断本来就不可恢复（规格-内核补强：未完成运行记 interrupted）。
- 崩溃：`SweepInterrupted` 把这一步记成不知道结果，`SurfaceInterrupted` 留系统行“程序退出时，这一轮被中断了”并挂上这一步（对象是问题正文）；下一轮参考信息里有“上一轮还没做完”。
- 正常退出：回合被取消，同样留系统行。

## 八、界面

输入区上方、审批卡旁边一张卡（`chatui.QuestionCard`）：

- 问题正文（最多 4 行，超出省略；全文在聊天气泡里），下面每个选项一行整宽按钮：名字，有说明时跟一行小字。
- 最下面一行：左边“也可以直接在下面打字回她”，右边“先不答”。
- 提交中按钮禁用；失败写原因，可以再点；已结束写“这个问题已经结束了”由卡片消失表达，不留死按钮。
- 通知：卡片出现时走 `attend`（种类 `question`），窗口不在前台才弹，同一会话 20 秒一次。
- 新界面（workbench）在输入区上方、审批卡下面；旧界面（legacy）用同一张卡，但旧输入框等待时只读，所以打字回答只在新界面（旧界面不再长新功能）。标题栏状态写“在等你回答”，排在“正在回复”前面。
- 输入框有字时发送键换回来（`submitComposer` 在有问题等时放行，收到回执若还是同一轮就不重开运行监听）；没字时还是停止键。
- 过程气泡里这一步显示为工具 `ask_owner`，对象是问题，输出是结果。

## 十、禁止的偷懒写法

- 不许把问题塞进 `Approvals`，或在 `Decision` 上加字段。
- 不许超时默认选一项，或超时当同意。
- 不许从 `Args` 读“是否无人值守”“问谁”，也不许从文字猜身份。
- 不许让 `Spec.TimeoutMs` 或预算到点去切等待：结果文字会变成“可以缩小范围再试”这种错话，必须自己先到点返回。
- 不许等待时不看 `ctx`：停止要立刻收回卡片。
- 不许只在界面做“打字算回答”：`sumika-ctl`、别的入口也走 `SubmitLocal`。

## 十一、已知的坑

1. 工具默认按 `StopGrace` 宽限，点停止后卡片会多挂几秒；所以 `stopsAtOnce` 加上 `ask_owner`。
2. 等待占一个全局工具槽（共 8 个），所以同时最多等 4 个问题，超过的不等。`task_result` 也是这样占的。
3. 这一轮的时限是固定的 `context.WithDeadline`，延长要动内核预算，不做；调大靠 `agent.budget.maxDurationMs`。
4. 问题事件的来源是 `ask_owner`，不是 `character`：过程步骤不会挂到它上面，“她最后说了什么”的判断也不算它。完成后步骤挂在最后那条回复上，所以问答气泡会排在这一轮的过程气泡前面。
5. 这轮内 `catchUp` 不会把问答事件再追给她：不在 `done` 里；重建历史时才读到。
6. 第二次调用同一个问题由现有的重复调用提醒处理；到期之后同一轮再问直接不等。

## 十三、验收标准

1. 完整路径（假模型，`internal/app`）：模型收到工具 → 调用 → 卡片出现 → 点选项 → 结果进下一次请求 → 这一轮说完；聊天记录顺序是问题、回答、回复。
2. 打字回答：等待中 `SubmitLocal` 的 `start` 变 `steer`，等待结束；下一次请求里工具结果在前、主人的话在后；没有等到超时。
3. 到期：结果写“没回答”“不算同意”；卡片消失；同一轮再问直接不等。
4. 时限：`ctx` 只剩不够 45 秒时不等；够的时候等待时限被压到总时限之内。
5. 停止：等待中 `StopLocalRun` 立刻收回卡片。
6. 无人值守：目标进行中、定期任务、自检不建卡片；目标和定期任务提醒主人，自检不提醒；问完就结束的目标暂停。
7. 可见性：第十二节那张表。
8. 不是批准：答“允许”后 `write` 还是弹审批卡；`approvals.Snapshot` 里看不到问题；import 边界测试。
9. 错误入口：`AnswerLocal` 对别的会话、不存在、已结束、越界都返回 `ErrQuestionGone`，问题状态不变。
10. 界面（`ui.NewTester`）：卡片画出问题和选项；点选项调 `AnswerLocal`；失败写原因可重试；输入框有字时发送键出现，回车走提交，且不重复开运行监听；窗口级 Esc 不停止；窄窗口不溢出；组件区截图存 `data/dev/`。
11. 真实模型：`cmd/harness-check -answer 1` 走 Magpie 的 DeepSeek 跑一次分叉任务，确认她真的调工具、拿到结果后接着做；记录存 `data/dev/`。

每条验收的出处写进第十四节。
