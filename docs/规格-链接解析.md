## 一、范围、已定行为与交付边界

实现放 `native/internal/linkreader`：纯解析核心及与它分文件的联网取数服务；渠道插件接线放 `native/internal/channel/qq`，内核只读详情工具通过现有 Registry 注册。核心不 import 渠道或内核，不直接发 QQ 消息，不调用模型。

第一版覆盖 X 的 status 帖（纯文字、长 Note、图片、GIF、视频、图视频混排、引用帖）及 Article 的实测可读部分；B 站视频 BV/AV、多 P、b23 短链、动态/opus、CV 专栏、直播间公开摘要和 QQ 分享卡片。直播只取房间摘要，不录流；番剧 ep/ss 不冒充普通视频，列入 B 站后续类型步骤。某类型匿名拿不到时返回明确的字段状态，不声称它没有正文或媒体。Article 完整展开另受第四节的实测门槛约束，拿到标题不算完成长文章需求。

第三轮增加 GitHub 仓库/issue/PR/release/gist、YouTube watch/Shorts、抖音视频/图文、网易云歌曲/歌单/专辑、pixiv 作品元数据；返回范围与匿名失败边界见 4.3～4.7。

第一版不接 Cookie、不读浏览器登录态、不做翻译、不下载付费或权限受限资源、不分析视频画面；字幕来自平台可公开取得的字幕，不生成字幕。上述行为依据 ADR-025、192；其余平台顺序见第十二节。

| 场合 | 给她看 | 展开 |
|---|---|---|
| 本地私聊 | 她实际接管回话后，已可见消息附短摘要、可查详情 | 第一版无 QQ 自动展开；不把结果送到 QQ 私聊 |
| 本地群聊 | 同上，按当前角色的观察范围 | 第一版无本地自动展开；不映射到任何 QQ 群 |
| QQ 私聊 | 仅她原本准入且实际观察的会话；陌生人只存不分析 | 按账号和私聊打开，默认关；不借此打开 `qq.reply` 或扩大 `privateAllow` |
| QQ 群 | 仅她已加入、准入且非只记录的会话 | 按账号和群打开，默认关；仍受会话档位、发送权、暂停检查约束 |

“给她看都开”指已有可见范围内默认启用（ADR-192 第 2 条），不是给插件扩大准入权。“展开默认关”沿用旧规格第一节。试运行可以生成发送计划，但不得出任何发送类 action；archive 连解析预取也不启动（ADR-209）。

## 二、技术路线与当前缺口

数据流：`统一消息段 → 纯提链/卡片还原 → 清洗/识别 → 短链安全展开 → 再清洗/识别 → 缓存/在途合并 → 平台取数 → 详情与消息关联 → 短附注 / 展开计划`。下载只在展开需要媒体时启动，给她看不预下载大视频。

截至本分支的读码事实：

| 位置 | 现状 | 接入必须补什么 |
|---|---|---|
| `native/internal/channel/types/seg.go` 的 `Seg.Raw`，`snowluma/snowluma.go` 的 `segments` | json/xml 均映射 card，`data.data` 被截到 `RawMax=200` 字 | json 增加独立完整载荷字段，例如 `CardJSON json.RawMessage`，与原始段类型一起传递、落库；不能把截短 Raw 当完整 JSON |
| `native/internal/channel/pipeline.go` 的 `OnStored` | 观察后跑 Chain，再交 Gate；不得卡住会话队列 | 增加只负责提链/入后台队列的接点，网络放受生命周期控制的工作队列 |
| `native/internal/channel/line.go` 的 `FormatLine` | 引用只留正文前 20 字；没有链接附注字段 | 原文引用预览和链接短摘要分字段组装；摘要不受 20 字预览截断 |
| `native/internal/app/line.go` 的 `quote` | 按当前会话查本平台库，返回原作者和 Text | 同会话查消息关联的短摘要；不能改成跨库搜索 |
| `native/internal/turn/plugin.go` 的 `Registry`、`Tool`、`ToolCall` | 已有插件注册工具、听众过滤和当前会话身份 | 注册只读详情工具，校验消息可见性；不是等待内核从零提供注册工具 |
| `native/internal/channel/types/adapter.go` | Caps 只有 Image/Poke/Echo/MaxText；Part 一段对应一次 action | 加 Quote/Forward/React 及实际媒体消费者；带引用的正文必须作为一次组合消息，不能分开发 quote 和 text |
| `native/internal/channel/snowluma/call.go` 的 `Send`，`snowluma.go` 的 `Caps` | Send 只接 PartText，Caps 仅 Poke 为真 | 文字发送已经有实现，图片/视频/GIF/引用/回应/转发仍是前置缺口 |

以上文件路径是现状定位，不承诺未实现的字段或函数已存在。接线实现时同步更新中间件能力表、段契约、装配和参考页，不另开第二套出口。

### 2.1 哪个出口先上

先交付不联网的核心，再交付匿名取数、缓存和只读诊断回放；这些都不依赖 QQ 真发或角色真回话。然后优先接“给她看”：依赖 Go 已接管对应会话回话、FormatLine/历史重建/引用都能查关联、详情工具已注册。已有内核接口降低了接线成本，但不代表生产接管已完成。

展开依赖 Go 发送上线全部门槛，且额外需要引用回复、群回应、合并转发、图片/视频/GIF 能力和真实 QQ 验收。文字加戳一戳上线不能宣称展开上线。两出口复用同一份结果，发送未就绪仍可完成“给她看”，反之角色未接管时可单独验展开，不能说她已经看懂。

第一版可先验收到第十三节第 3 步：隔离目录内实际运行回放，输出干净链接、字段状态、详情和短摘要；证明解析服务可接，尚不宣称真实 QQ 产品上线。第 4～6 步继续完成两个出口；外部前置未齐时按表报告阻塞，不删验收项。

## 三、不联网的纯函数契约（与 lr-core 的接合面）

下面是目标接口，供 `lr-core` 和联网层统一；本分支尚未读到 lr-core 实现，合入时按语义逐项对齐实际导出名，不增加同义包装层。纯函数只用输入，禁止 HTTP、DNS、文件、数据库、时钟、随机数、模型或全局可变配置。

```go
// 类型名为接合草图；ID 全是字符串，不经 float64。
type Candidate struct {
    URL string
    Segment, Offset int // 段序与该文字段内的 UTF-8 字节位置
    Source string       // text / card
}
type CardInfo struct {
    Links []Candidate
    Title, Description string
    Issues []string     // 固定错误类别，不含原卡片正文
}
type Target struct {
    Platform, Kind, ID string
    CleanURL string
    Part string         // B 站 p；缺省语义第六节规定
    NeedsResolve bool
}
func ExtractText(text string) []Candidate
func ExtractCard(raw []byte) CardInfo
func CleanURL(raw string) (string, error)
func Identify(clean string) (Target, error)
func CacheKey(target Target) (string, error)
```

调用顺序固定：Extract → CleanURL → Identify → CacheKey；短链先返回 NeedsResolve，不猜终点。缓存键包含规范化版本、平台和完整干净 URL；资源 ID 用于校验响应，不可只按 ID 丢掉未知 query、分 P 或时间参数。缓存键可以是该元组的稳定哈希，禁止使用原始带追踪参数 URL。短链终点取得后重新走后三个函数。

函数语义：

- 仅认 http/https 和明确的受支持主机/路径；主机按解析后的 hostname 精确匹配，大小写归一，拒绝 userinfo、非标准端口、伪后缀和混淆主机。纯函数不判断 DNS 安全；那是第五节的联网层职责。
- 文字按出现顺序提所有候选，标点不吞进链接；成对括号和合法 URL 内的转义不靠无条件 TrimRight 剥除。裸 BV/AV 是否启用见最后一节，不由提链函数擅自联网。
- 卡片按白名单路径提取，不递归抓任意字符串或图标 URL；一条消息扫描全部 text/card，`@` 不影响，坏卡不遮住后续文字和卡片。用消息段序及卡片字段序稳定排序，再按干净 URL 去重。
- 清洗满足 `CleanURL(CleanURL(u)) == CleanURL(u)`；未知 query 的值、重复次数、空值与相对顺序保留；只对参数名解码一次来匹配删除表，不反复 URLDecode 整条 URL。无 query 时不留孤立 `?`；不擅自删 fragment，平台图片定位等片段先保留。
- Identify 不把任意同域路径都当已支持内容。未知平台/路径返回 unsupported，不能假造 ID。X status ID、B 站 aid/BV/动态 ID 全按字符串保存。
- 返回结果不就地修改调用方的字节或切片；无法解析的 URL 返回固定类别错误，宿主保留原消息。

### 3.1 QQ 卡片字段与全部入口形状

字段检查顺序（同一对象同一 URL 合并；不同 URL 均保留）：

| 节点 | URL 字段顺序 | 可展示文字 |
|---|---|---|
| `meta.detail_1` | qqdocurl、jumpUrl、url、sourceUrl、shareUrl、targetUrl | title、desc |
| `meta.news` | jumpUrl、url、sourceUrl、shareUrl | title、desc |
| `meta.music` | musicUrl、jumpUrl、url | title、desc |
| `meta.miniapp` | legacyUrl、pcJumpUrl、jumpUrl、sourceUrl、url | title、desc |

目标域名按 `Recognize` 的精确平台和路径表判断；已支持平台的卡片走同一条取数路线。其他平台卡片仍可返回标题、描述，不请求其他平台。

| 外部形状 | 适配器入口 | 纯函数入口 | 结果与证明 |
|---|---|---|---|
| `json.data.data` 为 JSON 对象或对象的 JSON 字符串 | 保留完整 json 载荷和类型 | 一次解码，最多再解一层字符串 | 合法 card 样本得到相同候选 |
| 外包对象的 `data` 为 JSON 字符串 | 同上 | 仅允许再解一层 data | 总解包最多 3 层；循环/更深标 malformed，不无界递归 |
| JSON 的 `\/`、字符串内 `%xx` | 不先替换原文 | JSON 解码处理斜杠；仅当整个 URL 字段为编码 URL 时解一次 | 双重编码不反复解码，不能凭标题拼 URL |
| meta/节点/URL 缺失、null、空串、数字、数组、非法 JSON | 不丢同条其他段 | 非字符串 URL 忽略，坏节点继续后面的白名单节点 | detail_1 无 URL 时仍能取 news |
| `@ + 卡片`、多卡片、文字加卡片 | 全部段按原顺序传入 | 每段分别提取 | 坏第一张不影响后面的文字和卡片 |
| `xml` 卡片、未知 app、只有封面 | xml 保留类型和受限预览，不当 JSON；json 卡片不按 app 筛，合法对象照样存完整载荷（2026-10-30 和链接线商定），认不认得出由 `FromCard` 判断 | 不猜 URL；返回已有标题/描述或“卡片未识别” | 不联网，不把封面当原帖 |
| 超载荷上限 | 明确标 card_too_large，保留原消息的既有处理 | 不解析残缺 JSON | 不把截断后的字串当合法空卡片 |

完整 json 载荷工程初值上限 256 KiB；超过时只跳过此卡片，不影响消息其他段。这个边界不是把 RawMax 改大：Raw 仍是预览。历史里已经截断的卡片不能恢复，不能伪称迁移后都能解析。

## 四、联网取内容及字段契约

联网服务接收 Target 和 ctx，返回纯数据 `Result`：平台/类型/请求 ID、干净链接、作者显示名及稳定 ID、发布时间、有序 Blocks、字段状态、取数时间、来源接口名、局部失败原因。每个 Block 为 text/image/video/gif/quote/article_title 之一，引用用带原作者的子块；媒体候选地址只在内部取用，绝不当干净原帖链接。

字段状态必须区分 `available`、`not_returned`、`login_required`、`rate_limited`、`unsupported`、`failed`，正文截取另带 truncated；0 统计不是缺字段。缺稳定作者 ID 就标 not_returned，不拿显示名充当稳定 ID。正文、标题、评论均是不可信外部资料，展示和工具输出沿用转义，不能变成系统指令。

FX 的整个 media 未给/null 或显式 all:null 时，Media 标 not_returned；media:{} 是本轮公开响应表示无附件的形状，和 all:[] 一样记 available 空列表。B 站分 P 的标题、时长也使用 Field；未给时长不填 0 秒，显式的 0 与缺失分开保存。

### 4.1 推特 / X：候选取法，以实测笔记为准

本次按推特公开接口实测（私有存档）采用 FX v2 `api.fxtwitter.com/2/status/<ID>` 主取、VX `api.vxtwitter.com/<账号>/status/<ID>` 有限备用；不实现旧版 FX、syndication 或 oEmbed 的运行时轮询。`/photo/N`、`/video/N` 由现有 Recognize 提取 status ID，API 不接收后缀。只在 HTTP 5xx、网络失败或超时时退到 VX；404、登录限制、429 和坏 JSON 不退。各字段的实际映射如下：

| Result 字段 | FX v2 的 status 内路径 | VX 路径与缺项 |
|---|---|---|
| Author、Published | author.name/screen_name/id/avatar_url；created_timestamp（UTC） | user_name/user_screen_name/user_profile_image_url；date_epoch；作者数字 ID 标 not_returned |
| Text、ReplyTo、Article | text 长 Note 全文；replying_to.status；article.content 正文按下述结构映射 | text；replyingToID；文章正文标 not_returned/vx_article_body_omitted |
| Media、Blocks | media.all 原顺序；MP4 formats 选最高码率，同时保留全部候选；图用 orig；width/height/duration | media_extended 原顺序；size 是尺寸；duration_millis 除 1000；变体标 not_returned/vx_omits_variants |
| Quote、MoreQuotes | quote 子结果，保留被引作者；只留一层，再引用时 MoreQuotes=true、Quote 为 not_returned/deeper_quote_omitted；按 ID 防环 | qrt；同样限制；自回复仅父帖指针，不声称完整线程 |
| Stats | likes/reposts/replies/quotes/bookmarks/views | likes/retweets/replies；未给的数据标 not_returned |
| Flags | possibly_sensitive、is_note_tweet、community_note；未给 AI 标记不推断为 false | possibly_sensitive；其余缺项分别标记 |

| Expansion | ADR-253 第 2 条：short / long；正文按 Unicode 码点计数，GIF 算视频 | 相同分类，字段不全且不能确定长帖时标 not_returned/incomplete_content |

`Media.Variants` 保留每个格式的 URL、container、bitrate、width/height、declared_bytes。FX 未给变体宽高时，只解析 CDN 路径中明确的 `宽x高`；原视频尺寸不冒充每档尺寸。大小只消费平台声明，不按码率乘时长估算、不为大小新增 HEAD 请求。没有声明时逐项 not_returned/interface_omitted。

Article 复用 B 站图文的 `Result.Blocks`：主帖引导文字之后依次是 article_title、article_cover、正文块。`Title` 保存文章标题，`Text` 保留主帖引导文字，`Article` 保存正文文字；标题和封面不混进正文。`Media` 同时保留封面和正文配图，引用媒体留在子结果。正文按 content.blocks 顺序消费；乱序 entityMap 以 key 关联，MEDIA 通过 mediaItems[].mediaId 查 media_entities，不能用数组位置。文字保留空段、换行、SourceType（标题层级/引述/列表等），LINK 存在各块的 Links；MARKDOWN 保留代码/表格原文，DIVIDER 单独占块。图片宽高来自 original_img_*。

文章 TWEET 实体按 tweetId 补取 FX v2，结果放原位置的 quote 卡片；重复内联 ID 复用本次结果，不跟随正文外站链接。内联推文本身是 Article 时也保留其正文；其内再引用的推文不补取，原位置留下 deeper_quote_omitted，MoreQuotes=true。正文不在响应、实体关联缺失、未知块/媒体、内联取数失败各保留具体原因，Article.truncated 表示正文结构未完整保留；只有 preview_text 不算正文。主帖与内联补取共享原有 30 秒、请求预算与冷却，不为内联失败抹掉已取得正文。

### 4.2.2 B 站风控与冷却（2026-11-13）

调研见[调研-B站412风控](notes/调研-B站412风控-2026-11-13.md)，代码在 `linkreader/rate.go`（services 表的 `riskBase`、`riskMax`、`freqCool`）、`fetch.go` 的 `send`、`bili_extra.go`。

- **冷却**：HTTP 412、JSON 的 -352、-412 都算风控，整个 bilibili 平台（b23.tv、bili2233.cn、全部 bilibili.com 子域）一起冷却：15 分钟起，连撞一次翻倍，到 2 小时封顶；对端给的 Retry-After 更长就取它（也封顶 2 小时）；冷却期内的请求直接报 `rate_limited`，不发请求；冷却结束后的第一次成功让计数归零。同一批在途请求陆续报回来只算一轮。-509、-799 是频率码，冷却 5 分钟、不翻倍。记账在 `send` 一层，被调用方吞掉的子请求也算。其他平台的 412 不受影响。
- **减少触发**：B 站所有请求用完整的桌面 Chrome UA（`FetchOptions.UserAgent` 明确指定则用它的）、`Accept-Language: zh-CN`、`Referer: https://www.bilibili.com/`，api.* 带 `Origin`；第一次请求 api.* 主机时取一次 `x/frontend/finger/spi` 的匿名访客标识（buvid3、buvid4），缓存 6 小时，带在发往 api.* 的请求上，取不到不挡主请求、5 分钟内不重试；这一次请求只受冷却约束、不占每分钟预算。网络层断连后的那次重发也走冷却和预算。
- **不做**：伪造设备或风控指纹、`bili_ticket`、借登录账号或别人的 cookie、代理池换 IP、绕验证码。WBI 签名：当前用到的接口都是 `/wbi/` 以外的老路径、没有要签的（播放信息 `x/player/playurl` 未实测是否已要求签名，播放默认关），原先 view 风控后的回退已删；以后哪个接口被要求签名，再单独加（旧实现在提交 的 `bilibili.go`，nav 取 key、`signWBI`）。
- **没做的减少触发项**：请求间隔（调研标为推测，每条视频链接要多等 4 到 6 秒）、下调每分钟预算（没有数据定数值）；冷却、请求头、访客标识上线后 412 还回来再做。

R-18 与年龄墙（未实测，只按公开字段与重定向判断）：JSON 中 `is_adult: true` 返回 `FetchError{Kind: "age_restricted"}`，不返回任何商品内容，也不进入成功缓存；HTTP 302/303 且 `Location` 指向含 `adult` 或 `age` 的确认页，同样返回 `age_restricted`。站点要求本人在浏览器确认年龄，我们不替它确认。

错误映射：404/410 `not_found`；401/403 `login_required`；429 `rate_limited`（同时进入 booth 平台的冷却）；JSON 解码失败、缺 `name`、`id` 不符：`invalid_response` 或 `identity_mismatch`；HTML 第 2 步失败不影响主体，只降级为 resized。`published_at` 解析失败也整条按 `invalid_response` 失败，来源写 `booth_json`（不降级，等规格定了再改）。

已知的坑：`shop` 对象没有数字 `id`，只有 `uuid`，不能拿显示名充当稳定 ID；`price` 是字符串且可能带 `~`；`published_at` 的毫秒是 `.000`，解析要接受小数秒；`data-origin` 可能和 JSON 图数不一致（例如页面上有其他商品的缩略图），所以必须按 UUID 主干对应，不能按位置对应；`booth.pximg.net` 的 resized 文件名去掉后缀直接请求会 404，不能用来"还原原图"。

禁止的偷懒写法：不设 `adult=t` 或任何年龄确认 Cookie；不对 R-18 猜测内容或改取站内的其它镜像；不按位置把 `data-origin` 配给图片；不为找原图而逐扩展名探测；不把 404 写成"商品已删除"。

验收：默认测试只用 `testdata/` 里从真实公开响应裁出的 JSON 与 HTML 片段（店铺 uuid、图标和创作者数字 ID 已换成虚构值，`TestBoothFixturesUseInventedIdentities` 守住），注入 Transport，不联网，不读 `data/`。覆盖：识别的正常、语言段、子域、末尾斜杠、查询噪声、追踪参数、大小写、非法 ID、伪域、凭据和端口；取数的正常、原图对应与降级、404、410、429、登录墙、R-18 JSON 与重定向、坏 JSON、缺字段、超长正文、零图。每个关键行为拆掉被测代码确认变红。实际 `link-probe` 匿名运行调研样本（不超过 12 次请求），输出存 scratchpad，结果写进最终提交说明。

失败分支（HTTP 与业务层）：
- 400 且 body 的 `error` 为 `NotFound`：not_found（不是 404；已删除的帖子同样返回这一条）。
- `thread.$type` 为 `app.bsky.feed.defs#notFoundPost`：not_found；为 `app.bsky.feed.defs#blockedPost`：not_found，reason=blocked_post。两者都不进成功缓存。
- 401、403：login_required（沿用通用映射，不尝试登录）；429：rate_limited，沿用通用冷却；`RateLimit-Reset` 是 Unix 时间戳，换成 HTTP 日期放进 RetryAfter 只作展示；冷却仍只看 `Retry-After`。
- 响应不是合法 JSON、`thread` 缺失、帖子 `$type` 不符：invalid_response。
- 主页 `actor` 与返回的 DID 或 handle 都对不上：identity_mismatch。

不做的：
- PDS `com.atproto.sync.getBlob`、`plc.directory` 查询（视频 mp4 要再跳到任意 PDS，不属于匿名公开 AppView 的范围）。
- 线程回复（depth>0）、父帖链（只留 ReplyTo 的 URL）、feed、列表、入门包、作者动态。
- handle 到 DID 的解析请求（靠返回体里的 handle 与 DID 做身份校验，不额外请求）。
- 图片 alt 文字（需要 Media 结构加字段，属于共享结构改动，留待单独任务）。
- 成人标签的内容屏蔽或展示策略：只输出 `possibly_sensitive` 标记，渲染层是否跳过由下游决定。
- 插件渲染与"可接收"判断：本次只做 linkreader 包。**已被后续接入改为：** 2026-11-09 起 `linkexpand.Supports` 收 bluesky 的 post、profile，默认模板见[链接解析模板](规格-链接解析模板.md)第四节；成人标记不拦截，只在 `possibly_sensitive` 为真时写一行“敏感内容：是”。

禁止的偷懒写法：
- 不把 400 NotFound、notFoundPost、blockedPost 映射成空正文成功，也不写入缓存。
- 不用 handle 当稳定 ID，不用 `indexedAt` 当 Published。
- 不把 HLS 清单当 mp4 交给下载层，不为了拿 mp4 去请求任意 PDS。
- 不发 Cookie、Authorization，不调 session、login 接口，不做签名。
- 不因 429 换出口、不并发刷新，冷却期内不发请求。

已知的坑：
- 帖子不存在的响应是 HTTP 400 加 `{"error":"NotFound"}`，不是 404；线程的 `$type` 有三种，必须按 `$type` 分支。
- 自标签在 `record.labels`（selfLabels 的 `values`），AppView 标签在 `post.labels`，两处都要看。
- facet 偏移是 UTF-8 字节，不是 rune；中文和 emoji 正文里偏移和字符数对不上。
- 返回的 handle 可能和请求大小写不同，身份校验用大小写不敏感比较；DID 才是稳定身份。
- `getPostThread` 在 depth=0 时 `replies` 不返回，映射时不把"没有 replies 字段"当成"没有回复"的统计；回复数只用帖子的 replyCount。
- 视频 HLS 地址在 `video.bsky.app`，不是 `cdn.bsky.app`；两个域名在媒体白名单里分开放行。

验收标准（每条对应测试名，合并前逐条打勾）：
- 识别表：正例（规范、大小写、尾斜杠、追踪参数、主页、did 形式）；反例（look-alike host、后缀拼接、凭据、非默认端口、尾段、错误 rkey、m.bsky.app）。
- 离线回放：图文、画廊、视频、外链卡、引用、recordWithMedia、纯文字、主页；夹具来自保存的公开响应，删 DID、handle、正文和头像外的一切个人信息。
- 失败分支：400 NotFound、notFoundPost、blockedPost、401/403、429 带 Reset 头、坏 JSON、缺 thread、身份不符、空正文、超长正文、零媒体。
- 请求头：每个请求断言没有 Cookie 与 Authorization。
- 活体：link-probe 对研究样本取数，请求总数不超过 12 次，计数含经代理的 DoH 域名解析（每次解析 A、AAAA 各计 1 次），摘要和计数写进提交说明，原始输出不入库。2026-11-07：已完成 1/4（图文帖子，计数 5），其余 3 个样本待主会话复跑，此项暂未满足。
- 改坏检查：至少三处（identity 比较、NotFound 分支、facet 字节切片）改坏后对应测试必须变红。

### 4.10 Misskey 与 Mastodon：公开帖、用户与账号（fediverse）

**接入自动展开（2026-11-09，fix/link-finish）：** 接进自动展开（站点键 `misskey`，Mastodon 共用；Misskey 的 note、user，Mastodon 的 status、account）；图床 `media.misskeyusercontent.jp`、`proxy.misskeyusercontent.jp`、`files.mastodon.social` 进了媒体下载白名单；有内容提醒（CW）时写“内容提醒：…”，敏感标记写“敏感内容：是”，都不拦截。

状态：2026-11-07 实现，经 `feat/link-sites` 合进 main（各站分支逐个合并、合并后整体复跑测试）。

只认两个写死在代码里的实例：`misskey.io` 与 `mastodon.social`。其他域名，包括同样运行 Misskey、Mastodon 的实例，一律不识别、不当作 fediverse 服务器。平台名分开：Misskey 为 `misskey`，Mastodon 为 `mastodon`。不做远程用户的 `@user@domain` 形式（拒绝），不做全站、标签、本地时间线，不做 Misskey 的频道、剪贴板和页面，不取 Mastodon 的 `quote` 字段。

| 形状（主机需精确相等） | 平台 / 类型 | 标识 ID | 干净链接 |
|---|---|---|---|
| `misskey.io/notes/<id>`，id 为 6～32 位小写字母数字 | misskey / note | `misskey.io/<id>` | `https://misskey.io/notes/<id>` |
| `misskey.io/@<name>`，1～20 位字母、数字、下划线 | misskey / user | `misskey.io/<小写名>` | `https://misskey.io/@<name>` |
| `mastodon.social/@<name>/<id>`、`/web/@<name>/<id>`、`/users/<name>/statuses/<id>`，id 为正整数 | mastodon / status | `mastodon.social/<id>` | `https://mastodon.social/@<name>/<id>`（users 形式归一为 @ 形式） |
| `mastodon.social/@<name>`，1～30 位字母、数字、下划线 | mastodon / account | `mastodon.social/<小写名>` | `https://mastodon.social/@<name>` |

主机名不分大小写归一；Misskey 的 notes ID 不转大小写，不符合形状就拒绝；Mastodon 用户名保留原样进干净链接。尾斜杠和查询参数按通用追踪表处理，表外参数原样保留。没有本平台专属的删除项（未经实测的分享键不删）。

端点（全部匿名：无 Cookie、无 Authorization、无签名、无 token 字段）：

- Misskey 帖子：`POST https://misskey.io/api/notes/show`，JSON `{"noteId": "<id>"}`；返回的 `id` 必须与请求一致。
- Misskey 用户：`POST https://misskey.io/api/users/show`，JSON `{"username": "<name>", "host": null}`；返回的 `username` 忽略大小写一致，且 `host` 为 null。
- Mastodon 帖子：`GET https://mastodon.social/api/v1/statuses/<id>`；`id` 一致，且 `account.username` 与 URL 中的用户名忽略大小写一致，否则 `identity_mismatch`。
- Mastodon 账号：`GET https://mastodon.social/api/v1/accounts/lookup?acct=<name>`；`username` 忽略大小写一致，`acct` 等于 `username`（本地账号）。

错误映射：Misskey 非 2xx 时解析 `error.code`，`NO_SUCH_NOTE`、`NO_SUCH_USER` → not_found，`ACCESS_DENIED` → login_required，`RATE_LIMIT_EXCEEDED` → rate_limited；其余按 HTTP 状态（404/410 not_found，401/403 login_required，429 rate_limited）。Mastodon 按 HTTP 状态映射；JSON 结构不对 → invalid_response。429 进平台冷却（沿用 `request` 的既有逻辑）。

字段映射（Misskey 帖子）：

- Title：`missing("platform_has_no_title")`。Misskey 没有标题字段，不拿正文首行冒充标题；缓存判定靠 Text。
- Author：`name` 非空用 name，否则用 username（显示名兜底，不计失败）；Account 为 username，远程用户（host 非 null）为 `username@host`；ID 为用户 id 字符串；Avatar 为 `avatarUrl`。
- Published：`createdAt`。
- Text：`text` 原文保留，经 `previewField` 截断到 800 rune；null 或空 → not_returned / empty_text。投票另拼成一行「投票：选项 N 票…」，多选标注；`expiresAt` 写进 `Flags["poll_expires_at"]`，不自己判断是否已截止。
- Flags `content_warning`：`cw` 字符串，null 视为空串（即无警告）。
- Flags `sensitive`：任一文件 `isSensitive` 为 true 时为 true，全部为 false 时为 false，无文件时不填（Misskey 没有帖子级敏感标记）。
- Media：`files` 缺失 → not_returned / interface_omitted；空数组 → available 空列表。MIME `image/gif` → gif，其余 `image/*` → image，`video/*` → video，`audio/*` → audio；其他 MIME 不展示，计数写进 `Flags["unsupported_files"]`。`url`、`thumbnailUrl`、`size` 直接映射；宽高取 `properties.width/height`，缺失为 not_returned；不返回时长；`Media.Sensitive` 取文件的 `isSensitive`。
- Quote：`renote` 存在 → 一层嵌套 Result，映射方式相同，但不再展开它自己的 renote，`MoreQuotes=true`。`renoteId` 有值而 `renote` 缺失 → Quote 为 not_returned / renote_omitted。有 text 的是引用，text 为空的是纯转发，二者都放进 Quote。嵌套的 id 与 `renoteId` 不一致 → Quote 为 identity_mismatch，不抛出整次失败。
- Stats：`renoteCount` → renotes，`repliesCount` → replies；reactions 用 `reactionCount`，缺失时对 `reactions` 字典求和 → reactions。0 仍为 available。

字段映射（Misskey 用户）：Title 为显示名（兜底 username）；Text 为 `description`（null → not_returned）；Stats 为 notes、followers、following；Published 为 createdAt。

字段映射（Mastodon 帖子）：

- `content` 是 HTML：`<br>` 与 `</p>` 换成换行，去掉其余标签，再解码实体；不保留 HTML 原样。`spoiler_text` → `Flags["content_warning"]`；`sensitive` → `Flags["sensitive"]` 与每个媒体的 Sensitive；`visibility` → `Flags["visibility"]`，只记录，不过滤。
- `media_attachments`：image、video、`gifv`（→ gif）、audio 分别映射；`unknown` 计入 unsupported_files。`meta.original` 的宽高映射到媒体，`duration`（秒）映射到 Duration。
- Poll：同 Misskey，`expires_at` → `Flags["poll_expires_at"]`。
- `card` → LinkCard：url、title、description、provider_name（Site）、image（空串为 not_returned）。
- `reblog` 存在 → Quote 一层嵌套（纯转发，Text 为空），嵌套的 reblog 不再展开，`MoreQuotes=true`。Stats：`favourites_count` → favourites，`reblogs_count` → reblogs，`replies_count` → replies。

字段映射（Mastodon 账号）：Title 为 display_name（兜底 username）；Text 为 `note`（HTML 去标签）；Stats 为 statuses、followers、following；Published 为 `created_at`。

不做的事：不取回复串（Thread 为 unsupported）；不下载任何媒体；不用 Cookie 或登录态读私密帖，拿到 ACCESS_DENIED / 401 就报 login_required，不绕过；不展开两层以上的引用；不翻译；MFM 不渲染，清成纯文字（`misskeyPlain`：函数只留内容、去掉 `<center>` 这类排版标签，粗体、Markdown 链接写成“文字 地址”，punycode 域名换回原字；2026-11-12 复核 #55、#56）。

禁止的偷懒写法：

- 不得把任意域名当作 Misskey 或 Mastodon 实例，包括同款软件的其他站。
- 不得拿 Misskey 的 `text` 首行当标题，不得把 Mastodon 的 `content` HTML 原样进正文。
- 不得为了通过而加 Authorization、Cookie 或 `i` 字段；不得调用 timeline 接口代替单帖。
- 不得把 `isSensitive` 缺失当成 false，不得把 404 / NO_SUCH_NOTE 当成空成功写进缓存。
- 不得因为 CW 或 sensitive 而自动展开，展开策略按第十四节另议。

已知的坑：

- Misskey 的 `text` 可能为 null（只有图，或只有 CW）。
- 不存在的帖子实测返回 HTTP 400 加 `error.code = NO_SUCH_NOTE`，因此按错误码映射，不能只看 404。
- Misskey 远程帖的文件可能指向远程实例的域名，`inspectMedia` 会标 unsafe_target，不是错误。
- 投票数是取数时的快照；`expires_at`、`expiresAt` 过了也只记录，不下结论。
- Misskey 的 `reactionCount` 只在部分版本有，缺失时按 reactions 字典求和；字典可能为空对象，那是 0，不是缺失。
- 限流额度未知（Misskey）；Mastodon 按 `X-RateLimit-*` 响应头（约 300 次 / 5 分钟），超额为 429。
- 两个实例的媒体与头像主机固定：`media.misskeyusercontent.jp`、`proxy.misskeyusercontent.jp`（头像代理）、`files.mastodon.social`，其他媒体主机一律 unsafe。

验收：

1. `Recognize` 表驱动覆盖上表四种形状、`/web`、`/users`、尾斜杠、追踪参数、大小写主机、非法 ID；形似域名（`misskey.io.evil.example`、`evilmisskey.io`、`www.misskey.io`、`mastodon.social.evil.example`、`misskey.design`）、带凭据、非默认端口全部拒绝。
2. 夹具只保留消费字段，来自真实公开响应：文字帖、图片、GIF 与 CW、视频与敏感标记、投票、一层引用、用户；Mastodon 图片、视频、gifv、卡片、账号。
3. 失败形状：404/410、429、ACCESS_DENIED 与 401 登录墙、畸形 JSON、缺失可选字段、超长正文（截断标记）、零媒体（files 为空数组）。
4. 身份不一致（id 不同、username 不同、远程 host）拒绝。
5. 匿名实测，请求总数不超过 12 次，提交说明只写计数和日期（2026-11-07：12 次请求，11 次 200、1 次 400 NO_SUCH_NOTE，映射全部与字段一致），明细不进仓库。

**识别（纯函数，`recognizeSteam`）**

- `store.steampowered.com/app/<appid>[/<slug>][/]`；`/agecheck/app/<appid>` 归一为 `/app/<appid>`；`/sub/<id>[/<slug>]` 为打包。appid 与 id 必须是正整数十进制。规范化后去掉 slug（它只是名字，不影响身份）。

- 路径关键字只认小写（app、sub、agecheck、sharedfiles、workshop、filedetails、id、profiles）。这是有意的：Steam 生成的分享链接全是小写，大写路径按"不认识"处理，不替它猜。
- `steamcommunity.com`（含 `www.`）的 `/sharedfiles/filedetails/?id=` 与 `/workshop/filedetails/?id=` 都归一为 `/sharedfiles/filedetails/?id=<id>`，只保留 id。
- `/id/<自定义名>[/]`：名字 3～32 位字母、数字、下划线、连字符，ID 统一小写，写成 `id/<名>`。`/profiles/<id64>[/]`：17 位、以 765611 开头，写成 `profiles/<id64>`。抓取时直接拼成 `https://steamcommunity.com/<ID>/?xml=1`。
- 主机只认精确的 `store.steampowered.com`、`steamcommunity.com`、`www.steamcommunity.com`。`steampowered.com` 裸域、`store.steampowered.com.evil.example`、`steamcommunlty.com` 拒绝。端口、凭据、非 http(s) 沿用包里的统一规则。
- 不做短链：`s.team` 没有测过，不写。
- 清洗：`l=`（语言）保留，它决定返回中文还是英文文本，是用户能看见的选择，不当追踪参数删。追踪表只删 `snr`、`curator_clanid`（Steam 的推荐来源参数）。
- 给别的平台复用：`SteamAppLink(appid)` 纯函数，把 appid 转成规范的 app Link（小黑盒的游戏页用的就是 Steam AppID）；拿它调用 `Fetcher.Fetch` 就是同一条取数路径，不另写一套。

**取法（匿名，无 Cookie、无 key、无 Authorization）**

| 类型 | 请求 | 映射 |
|---|---|---|
| 应用 app | GET `store.steampowered.com/api/appdetails?appids=<id>&cc=cn&l=schinese` | 外层 `{"<id>":{success,data}}` 按请求的 key 取；`success:false` → not_returned/app_unavailable_or_missing（不是 not_found，也不是删除，可能是地区限制）；`data.steam_appid` 必须等于请求，否则 identity_mismatch。name→Title；developers 用 " / " 拼接→Author.Name，Author.ID 记 not_applicable（没有稳定 ID）；short_description→Text（800 rune 截断）；release_date.date（本地化文字，如"2026 年 8 月 21 日"）→PublishedText，Published 记 not_returned/localized_text_only；header_image 与 screenshots[].path_full 为 image，movies 为 video（URL 记 unsupported/playback_not_requested，缩略图取 movies[].thumbnail）；genres→Tags；price_overview→Steam.Price 与 Stats；is_free、coming_soon、required_age、content_descriptors.ids、platforms、type、publishers 进 Steam 块或 Flags |

**不做（有意的）**

- 玩家评测。调研时 `store.steampowered.com/appreviews/<id>?json=1` 带与不带 UA、不同 cursor 编码、跟随重定向，全部 302 回首页（研究员存的 `rev570.json` 就是首页 HTML）。代码不识别、不请求。若以后要做，先在另一时间或另一网络复测，并另写规格；现在不写"不可用"以外的结论。
- 社区指南（工坊里的 guide 类型）。API 对指南返回 result 9，本次不做 HTML 切块；非 1 的 result 只记 not_returned 与 Code。
- 工坊作者昵称（另一次请求）、bundle 页、curator、短链、视频播放地址（dash/hls）、下载 Steam 图片。
- Cookie（含年龄确认的 birthtime）、登录、key。年龄墙的 302 不绕过，记 not_returned/redirect_not_followed。
- 推断内容敏感度：content_descriptors.ids 原样保存，是否发送由发送层按会话政策决定。
- 聊天文本里的 Steam 链接，完整写法和裸域名都经既有的提取、缓存、取数通路（`extract.go` 的 `wideHosts` 已收录三个主机，`Extract` 与 `FromCard` 有断言），和网易云同样待遇；这不是新增的权限。
- 展开与发送层：本节写成时 `linkexpand.Supports` 不收录 Steam。**已被后续接入改为：** 2026-11-09 起收 app、package、sharedfile、profile，默认模板和字段见[链接解析模板](规格-链接解析模板.md)；`required_age` 大于 0 时写“年龄限制：N+”，不拦截（ADR-323）。

**禁止的偷懒写法**

- 不把 `success:false` 当 not_found，也不当成功的空应用。
- 不用 name 或 developers 显示名当稳定 ID。
- 不因 required_age 是字符串而丢字段，也不当成 0。
- 不把缺失的 price_overview 当 0 元（免费游戏就是没有这个字段，用 is_free 表示）。
- 不爬社区 HTML 绕开 POST 或 405。
- 不把 302 当成功；不跟随到年龄确认页。
- 不为绕过年龄墙、地区限制加 Cookie。

**已知的坑**

- appdetails 的 required_age：有时是数字 0，有时是字符串 "17"，两种都要接。
- release_date.date 是本地化文字，不能按 RFC3339 解析。
- GetPublishedFileDetails 只接受 POST，GET 返回 405（"must be called with a HTTP POST request"）；file_size 是字符串。
- 新格式的 movies 没有 mp4 字段，只剩 dash_h264、hls_h264 等；不得把它们当 mp4 下载。
- 工坊描述含 BBCode（`[h1]`、`[img]`）：清成纯文字再发，Flags 里的 text_format 记原来是 bbcode。
- 图片域名：`shared.akamai.steamstatic.com`（商店图、截图、影片缩略图、打包图）、`images.steamusercontent.com`（工坊预览）、`avatars.fastly.steamstatic.com`（头像）。候选地址只按这三个精确主机放行，不按后缀。
- 请求头：这些接口不需要 Referer，不发 bilibili 的 Referer。

**接入自动展开（2026-11-09，fix/link-finish）：** 接进自动展开（`afdian`，creator、post、album、album_post；商品页匿名取不到，不进展开范围）；付费动态写“需要赞助才能看全文，最低 ¥…”。

识别 `afdian.com`（含 `www.`）以及旧域 `afdian.net`、`ifdian.net`，统一规范为 `afdian.com`。路由：`/a/<slug>`（创作者）、`/p/<ID>`（动态）、`/album/<相册ID>`（相册）、`/album/<相册ID>/<动态ID>`（相册里的动态，ID 为两段拼接）、`/item/<ID>`（商品，只识别）。slug 保留大小写（研究样本有 `Qianjin4FYS`、`Arabian_nights`），只允许 `A-Za-z0-9_-` 且 1～64 字符；动态、相册、商品的 ID 必须是 32 位十六进制，统一小写。干净链接丢弃全部查询参数和片段（爱发电页面的参数不参与内容选择，分享来源参数也没有保留价值）。

- 付费内容不解锁：不带赞助人身份、不换接口、不改 `has_right`、不读附件（`attachment` 的下载地址是私有 COS 和重定向，全部不取）。
- 音频（`audio`）不映射：样本为空，未验证。GIF 未映射：研究期间没有找到 `.gif` 样本，未验证。
- 相册只取第一页：翻页参数（`lastRank`）未测，用 `Links.Truncated` 如实标出。
- 动态正文 HTML 里的内嵌图、creator 的完整简介、评论、官方开放接口（签名，只查自己的订单和赞助人）都不取。

禁止的偷懒写法：
- 不把 `ec` 为 404/400 的 HTTP 200 当成功空动态或空用户；不把 `has_right=0` 的空正文当成"作者没写内容"。
- 不用显示名当 Author.ID；`user` 缺失时 Author 标 not_returned，不编造。
- 不把签名视频地址当干净链接或分享地址；`Clean` 保持 `/p/<ID>` 页面。
- 不因 `afdian.net` 不通就换成别的主机或代理；只识别、不回退。
- 不为了过 `has_right` 而加 Cookie、Referer 伪装或重试。

已知的坑：
- 同一接口的数字字段有时是 int、有时是字符串（列表 int，详情字符串）；解析两种都接受，其他类型（布尔、对象）整条返回 invalid_response。
- `pics` 在列表和详情里都可能是 null，要当成零媒体，不当成错误。
- `type=1` 长文正文约 1.3 万字节 HTML，截取后 Text.truncated=true；截取前不要整段保留进缓存。
- 视频 URL 的签名参数会过期，缓存只保存元数据，下载由已有的 100 MB 规则决定。
- 接口没有文档，是网页前端在用的接口；平台改版时返回 interface_error 或 not_returned，不猜替代接口。

4. 预算：afdian 的请求计入独立的平台，不占 x 的额度。
5. 匿名实测：每类至少一条真实链接的 link-probe 输出（时间、退出码、字段），写进提交说明；未测的类型单列。

### 4.13 Spotify：嵌入页 JSON 与 oEmbed 兜底

**接入自动展开（2026-11-09，fix/link-finish）：** 接进自动展开（`spotify`，track、album、playlist、artist、episode；show 不取数不展开）；发行日期只写日期，不写钟点。

状态：2026-11-07 实现，经 `feat/link-sites` 合进 main（各站分支逐个合并、合并后整体复跑测试）。

识别 `open.spotify.com/` 下的 track、album、playlist、artist、episode、show 六类，允许 `intl-xx/` 语言前缀和 `embed/` 前缀，ID 必须是 22 位字母数字；`spotify.link/<码>` 作为短链。`si` 分享参数加入平台追踪表删除，`utm_*` 沿用通用表，其余表外参数原样保留。拒绝 `open.spotify.com.*` 等伪主机、凭据、非默认端口和 `spotify:` URI。

取数只 GET `https://open.spotify.com/embed/<类型>/<ID>`，Accept 为 HTML 或 JSON（oEmbed 共用同一出口），不带 Cookie、Authorization 和页面里的匿名 web-player token；从 `<script id="__NEXT_DATA__">` 的 JSON 取 `props.pageProps.state.data.entity`。entity.id 必须等于请求 ID、entity.type 必须等于请求类型，否则 identity_mismatch。不调用 api.spotify.com，不取 audioPreview 的 mp3 内容。

embed 失败且为 invalid_response（页面结构变了）时，才请求 `https://open.spotify.com/oembed?url=<干净链接>` 兜底，只映射 title 和 thumbnail_url，来源标 `spotify_oembed`。oEmbed 也失败就返回 embed 的原错误，不合成空成功。

show 不取数：embed 对 show 返回的是最新一集而不是节目，识别后 Fetch 返回 unsupported（同 B 站 season 的处理）。

| 类型 | 字段映射与边界 |

embed 和 oEmbed 都不给播放、粉丝、点赞数，Stats 一项都不写，不填 0。

失败分类：地区限制（2026-11-07 实测单集为 HTTP 200，`pageProps.forbiddenReason` 为 `NOT_AVAILABLE_IN_MARKET`；也可能是 HTTP 403 带同样正文）时为 `not_returned`，原因 `not_available_in_market`，不当 login_required，不进成功缓存；其他 403 为 login_required；404/410 为 not_found；429 为 rate_limited，沿用 Fetcher 的平台冷却；没有 `__NEXT_DATA__`、JSON 解码失败或缺 entity 为 invalid_response。标量字段（duration、maxWidth、isExplicit）类型不符只让该字段缺失，不整页失败、不走 oEmbed（TestSpotifyScalarTypeMismatchKeepsPage）。

不做：完整音频和 30 秒试听的下载、播放；歌单逐首取歌；粉丝、播放量等统计；登录、Premium、Web API 的 client credentials；show 的节目信息。

禁止的偷懒写法：把 embed token 拿去调 api.spotify.com；为绕过地区限制换出口或代理池；把 audioPreview 的 mp3 地址当干净链接或成功媒体；show 用 embed 返回的最新一集冒充节目；oEmbed 失败时合成成功结果；用歌手或节目显示名当稳定 ID。

已知的坑：地区限制因出口而异，403 不等于不存在；show 的 embed 给的是最新一集，必须靠 entity.id 校验拦下；歌单只给前 50 首，看起来像全部；封面 CDN 有 image-cdn-fa、image-cdn-ak、i.scdn.co 三个精确主机，都要进媒体白名单；参考实现（microlinkhq/spotify-url-info，许可证未核对）同时兼容 resource、initial-state、`__NEXT_DATA__` 三种脚本，本实现只认 `__NEXT_DATA__`，结构变了就 invalid_response 并走 oEmbed，不自己去猜新结构。只借鉴端点和字段路径，代码自写。

验收：Recognize 表驱动覆盖六类、intl 与 embed 前缀、尾斜杠、`si` 和 utm 清理、大小写主机、22 位与非法 ID、伪主机、凭据和端口、show 不 fetchable；Fetch 用 testdata 里的真实公开样本（删去账号和令牌字段）覆盖 track、album、playlist、artist、episode 各一；失败分类覆盖 404、429、区域 403、其他 403、HTML 无脚本、坏 JSON、id 或 type 不符、oEmbed 兜底成功和失败；短链跳转覆盖合法、外站、show、循环；封面 host 白名单和 fake-ip 名单（5.1）经 inspectMedia 测试；实测记录写进提交说明。

### 4.14 TikTok：视频、图文、用户页与短链（匿名元数据）

**接入自动展开（2026-11-09，fix/link-finish）：** 接进自动展开（`tiktok`，video、user）；视频文件要会话 Cookie，只发封面和文字；`tiktokcdn` 图床进了媒体下载白名单；作品没写文案也能展开。

状态：2026-11-07 实现，经 `feat/link-sites` 合进 main（各站分支逐个合并、合并后整体复跑测试）。

许可：yt-dlp 为公有领域（Unlicense），gallery-dl 为 GPL-2.0，两者只借端点、形状和字段名，未复制代码。任务说明里提到的 AstrBot 媒体解析插件记为 AGPL，本轮未参考它的代码（本机 _external 的 AstrBot 中没有 TikTok 相关代码）。

识别（`native/internal/linkreader/tiktok_urls.go`）：`tiktok.com`、`www.tiktok.com`、`m.tiktok.com` 的 `/@<用户>/video/<数字 ID>` 和 `/@<用户>/photo/<数字 ID>`。`/photo/` 归一为 `/video/`，网页只在 video 路径给作品数据（gallery-dl `tiktok.py:157-158` 同样改写）。图文还是视频不由路径决定，由响应里是否有 `imagePost` 决定；Kind 只有 `video`。用户页 `/@<用户>` 为 Kind `user`，ID 为小写用户名。短链 `vm.tiktok.com/<码>/`、`vt.tiktok.com/<码>/`、`www.tiktok.com/t/<码>` 为 Kind `short`，ID 为空，沿第五节逐跳检查（yt-dlp `tiktok.py:1512` 同样认这三种形状）。用户名按 `[\w.-]{1,64}`（yt-dlp `tiktok.py:1020`），Clean 中小写。`/locale/` 语言前缀未见实测样本，按拒绝处理；直播、音乐、标签、合拍、收藏等路径一律拒绝。

不做，也禁止的偷懒写法：

### 4.15 小黑盒：游戏页匿名简介；帖子、用户页明确不支持

**接入自动展开（2026-11-09，fix/link-finish）：** 接进自动展开：只收游戏页（`xiaoheihe`，写游戏编号、开发商、发行日期、简介；接口没有游戏名，不编标题）；帖子、用户页要签名和设备验证，不进展开范围（进了每条链接都会回一条失败文字）。

状态：2026-11-07 实现，经 `feat/link-sites` 合进 main（各站分支逐个合并、合并后整体复跑测试）。

识别（纯函数，`cncommunity.go`）：
- `www.xiaoheihe.cn`、`xiaoheihe.cn` 的 `/app/topic/game/pc/<appid>` → kind=game，ID 为纯数字 appid，规范为 `https://www.xiaoheihe.cn/app/topic/game/pc/<appid>`。只认 pc：Steam AppID 等同只在两个 pc 样本上核过。

取数（联网层）：
- game 只请求 `GET https://api.xiaoheihe.cn/game/game_introduction/?steam_appid=<appid>&return_json=1`，匿名、不签名、不带 Cookie。`status` 为 `ok` 时读 `result`。
- 字段映射：Title 是游戏名：接口不给名字，小黑盒的游戏编号就是 Steam appid，照同一编号问 Steam 商店 `appdetails`（`filters=basic`，多 1 次串行请求）取 name；Steam 回 success:false 等明确没有时记 `steam_name_not_returned` 并照常缓存，网络、超时、5xx、限流这类临时失败整条结果不进缓存、下次再问；取不到时模板写“游戏 编号”，不从简介编一个（2026-11-12 复核 #84）；Text 取 `about_the_game`，`</p>`、`<br>` 等段落和换行标签先换成换行，再去标签、反转义 HTML 实体，经 `previewField` 截 800 字；Author.Name 取 `developers[0].value`（发行商不顶替），Author.ID 为 `not_returned`（接口没有稳定 ID）；Category 取 `game_type`；PublishedText 取 `release_date` 原文，空白串与缺失同样标 `not_returned`；Published 只在能解析 `2006年01月02日`（东八区）时填，其他（如"即将推出"）标 `not_returned`；身份校验通过后 `Flags["steam_appid"]` 记录请求的 appid，与返回值不一致时 `identity_mismatch`。

- 个别字段类型不对（开发商给成字符串、发行日期给成数字等）：只那一项缺失，其余照出，缺的如实记原因（2026-11-09，宽松解码 `lv[T]`，`TestCNHeyboxBadFieldTypeKeepsPage`）；只有 JSON 语法错误或 `result` 整体不是对象才是 `invalid_response`。

不做：帖子正文、评论、用户页、视频；hkey 签名；设备 token（`x_xhh_tokenid`）；任何用于绕过 `show_captcha` 的重试或轮换。

禁止的偷懒写法：照抄参考实现的 hkey 或数美设备 token 算法（参考源码是 AGPL，且属于逆向，参数一改即失效）；遇到 `show_captcha` 立刻重试；拿显示名当稳定作者 ID；把简介当游戏标题；把 `release_date` 不能解析当成 0 或"已发售"。

### 4.17 Telegram：公开频道帖子（embed 页）

- **认什么**：`t.me`、`telegram.me` 的 `/<频道>/<号>` 和网页预览写法 `/s/<频道>/<号>`。频道名 4～32 位字母数字下划线、字母开头，转小写；帖子号正整数；路径带 `%` 转义拒绝。`/c/<数字>/<号>` 是私有频道帖子，识别出来但**不发请求**，取数直接按“需要登录”失败。频道主页、`/share`、`/joinchat`、`/addstickers` 等不认。干净链接 `https://t.me/<频道>/<号>`，查询串整条丢弃（`?single`、`?embed`、`?comment`、`?t` 都不影响帖子）。平台 `telegram`，类型 `post`，身份 `<频道>/<号>`（私有 `c/<数字>/<号>`）。

### 5.1 fake-ip 与代理（2026-11-13，用户同意：“可以”）

参考与采用：
- 决策记录 ADR-273 第 1、2 条（检测到假 IP 就改走配置的代理；代理那一层要写清要求）：采用，检测条件就用“解析结果落在假地址段”，不做网卡检测；代理这一层的要求写在本节第 6 点。
- 决策记录 ADR-252 第 5 条（“只对代码里写死的平台接口域名放行 198.18.0.0/15”）：修正。不再直连假地址，也不再为单个主机写死例外；名单内的主机经代理按主机名连，名单外照旧拒绝。
- 本节上文的 safeDial 绑定已验 IP、逐跳检查、混合答案整组拒绝：保留，只在“有 fake-ip 地址”这一种情形下换连接方式。
- 2026-11-13 的 `fix/link-fetch-1113`（c7f1ca1e6、881c023f4）为 TikTok 图床写死放行 p16-common-sign、p19-common-sign 两个主机：撤掉，由本节通用规则覆盖。
- [规格-QQ收图下载和断线补录](规格-QQ收图下载和断线补录.md) 4.4（`mediafetch` 自己的 fake-ip 放行）、`internal/web/access.go`（网页抓取自己的 fake-ip 判断）：不走本节的拨号，不改，见下面“不在范围”。

背景：Clash / mihomo 一类代理的 fake-ip 模式让本机 DNS 给出 `198.18.0.0/15`（RFC 2544 保留段，fake-ip 默认 198.18.0.1/16）里的假地址，真实地址只有代理知道。取数程序的安全拨号按地址判断，会把它当保留地址拦下。

1. **配置键** `linkReader.fakeIPRanges`：CIDR 列表，默认 `["198.18.0.0/15"]`。含义是“解析到这些段 = 真实地址未知”。校验：每条是合法 CIDR（带主机位如 `198.18.0.1/16` 按网段取整）、不接受 IPv4 映射的 IPv6 写法、IPv4 前缀不短于 /8、IPv6 不短于 /16、最多 16 段、不许和本机 / 内网 / 保留地址段重叠（`0.0.0.0/8`、`10/8`、`100.64/10`、`127/8`、`169.254/16`、`172.16/12`、`192.168/16`、`224/4`、`240/4`、`::/128`、`::1/128`、`::ffff:0:0/96`、`fd00::/8`、`fe80::/10`、`ff00::/8`，盖住它们或落在它们里面都算；写错了会把真私有地址当假地址，名单内主机就不再整次拒绝，复核发现）；`fd00::/8` 是真实局域网用的那一半，里面的段要写到 /48 或更长（Clash 的 `fdfe:dcba:9876::/48` 能过），`fc00::/8` 没有真实分配，sing-box 默认的 `fc00::/18` 能过；写 `[]` = 没有假地址段（保留段地址一律拒绝）；键不写用默认；写 null 或留空和其他列表键一样按类型错误拒绝加载。它是安全项：设置页只读，只在 `sumika.yml` 里改，改了要重启接收（`settingsreg` 登记为只读）。`FetchOptions.FakeIPRanges` 为 nil 用默认。link-samples、link-probe 没有命令行参数，用默认段：它们本来就不读 `sumika.yml`（链接设置也是 `DefaultLinks()`），只是主人手动跑的开发工具；配置里写 `[]` 关掉假地址段时它们仍按默认段放行，比主进程宽，这是有意的（复核评为低，不加参数）。
2. **裁决**（`network.go` 的 `netPolicy.judge`，拨号 `safeDial` 和媒体候选检查 `inspectMedia` 共用，不各算各的）：
   - 每个解析出来的地址先归类，IPv4 映射的 IPv6 先还原：在假地址段里（`netsafe.InFakeRanges`；盖住第 1 点那些内网地址段的段不认，绕开解析直接拼出来的规则也一样）= 真实地址未知；否则必须是真公网（`netsafe.PublicIP`）；两者都不是（私网、回环、链路本地、CGNAT、文档段、保留段、组播、NAT64……）= 整次拒绝，名单内主机、混合答案一律如此，原因与代理有没有无关。
   - 没有假地址：绑定第一个地址去连，照旧。
   - 有假地址，主机在名单内（第 3 点）、端口是 80 或 443、主机名写法合格（小写字母数字和 `.-_`、不超过 253 字）、有代理可走：不连假地址，经配置的 HTTP 代理 `CONNECT 主机名:端口`（不带 IP，让代理解析，TLS 仍按原主机名校验）。
   - 有假地址，主机不在名单内、是 IP 字面量、写法不合格、或端口不是 80 / 443：拒绝（无法确认它不指向局域网），`FetchError{Kind: unsafe_target, Reason: fake_ip_not_listed}`，端口不对时 Reason 为空。
   - 有假地址，主机在名单内但没有代理可走：拒绝，`Reason: fake_ip_no_proxy`，日志详情写“fake-ip 下没有代理可走”。“有代理”指 `linkReader.proxy`，没写时沿用环境变量 `HTTPS_PROXY` / `HTTP_PROXY`（与第五节分路一致）。
   - Kind 一律保持 `unsafe_target`（下游 linkexpand 按 Kind 分支），原因只放 Reason 和日志详情。
3. **名单**（`trustedHost`）= 取数白名单（上面各表的精确主机，`fetchHosts`）∪ 各站下载许可名单（`mediaHost` 各平台、`moreMediaHost`，含后缀项：hdslb.com、biliimg.com、bilivideo.com、douyinpic.com、douyincdn.com、byteimg.com、afdiancdn.com、music.126.net、tiktokcdn-us.com、tiktokcdn.com、googlevideo.com、cdn-telegram.org、telesco.pe 等平台自家 CDN 域）。这改了第四节、本节以前“未知 hdslb、douyinpic、douyincdn、byteimg 子域 fake-ip 不放行、不按平台后缀放宽”的写法：同域的新子域现在算名单内。理由：fake-ip 下是代理解析名字，风险只在“名字归谁”，平台自家域名可信；伪后缀（`hdslb.com.evil.example`）、IP、任意外站、`mediaHost` 以外的同类域名（如 `image-cdn-zz.spotifycdn.com`）仍不算。`mediaPlatforms` 要和 `mediaHost` 认识的平台同步，`TestMediaPlatformsListed` 对着源码查。
4. **跳转**：客户端禁自动跟随，每一跳是新请求、新拨号，重新走第 2 点；`Stream` 还在每一跳先查 `mediaURL`（名单 + 默认端口）。重定向到名单外的 fake-ip 主机拒绝。
5. **出口分流不变，只在碰到假地址时换连接方式**：国内直连的线路平时仍直连、不经代理；真公网地址仍绑定已验 IP。只有解析到假地址时，两条线路（含国内主机）才经 `linkReader.proxy` 按主机名连，由代理自己的规则决定出口。这修正了上文“显式给代理也不会把国内平台送到海外出口”的说法：假地址下国内主机的出口取决于用户代理的规则，要把国内域名放 DIRECT。
6. **代理那一层的要求**（ADR-273 第 2 条）：假地址下解析发生在代理里，Sumika 看不到真实地址，所以只对名单内的平台域名这样做；代理必须是用户本机自己的代理，不把名单内的域名转到内网（Clash 规则里不给这些域名配指向内网的规则）。上文“部署若使用代理，必须证明代理也执行同样的目标地址校验，不能靠本地 DNS 检查后让代理重新解析”对假地址这一种情形改为这条要求；非假地址的真公网仍绑定已验 IP，不让代理重新解析。首版仍不读取代理配置。
7. **行为退化（要用户知道）**：以前名单内主机解析到假地址时，程序直连假地址、靠 TUN 接管能通；现在没配代理（`linkReader.proxy` 和环境变量都空）又遇到假地址，一律拒绝并写原因。本机是 Clash TUN + fake-ip 且没给程序配代理的，要在 `linkReader.proxy` 写上 `http://127.0.0.1:<端口>` 才能恢复；link-samples、link-probe 不带 `--proxy` 同理。
8. **不在范围**：`mediafetch`（QQ 图片下载，规格 4.4 的白名单主机放行 fake-ip 并直连）和 `internal/web`（网页抓取）各自有拨号和 fake-ip 判断，不跟 `linkReader.fakeIPRanges`，本轮不改；它们和本节同样的“名单内放行 / 直连假地址”做法是否也换成经代理按主机名连，另议。

### 6.1 全平台清链接（2026-11-09）

主人原话：“脏链接清洗是要所有平台都得执行好的，去追踪参数，但是不要洗掉时间点标记”。规则分三层，优先级从高到低：

1. **保留表**（`tracking.go` 的 `locatorKeys`）：`t`、`start`、`end`、`time_continue`、`start_progress`、`p`、`index`、`list`、`lid`，以及片段（`#t=` 等）。任何追踪表都不能删它们；唯一例外是 X 的 `t`（随机串，不是时间点），只在 X status 和 t.co 上生效，X 的搜索页等其余路径仍保留。`TestLocatorNeverTracking` 守住“追踪表里没有保留键”。
2. **追踪表**：通用表加各平台表，表里每项的出处写在 `tracking.go`、`tracking_more.go` 的注释里。出处是 ClearURLs 公开规则库（rules2.clearurls.xyz，2026-11-09 取回核对）、ADR-214、主人提供的样本；没有出处的项是 App 分享里常见的参数名，按名字判断，可信度中。
3. **表外参数**一律保留，包括重复值、空值、次序、编码；不做白名单（小红书 `xsec_token`、Steam `l=`、网易云 `id` 没了就打不开或换语言）。

**出口一律用清过的链接**：`Recognize` 的 `Clean`（取数、缓存键、`$链接`、合并转发、失败文字、详情“来源”都读 `Result.CleanURL`）、`FindURLs` 的 `Clean`（桌面、插件去重、取不到时的关联键）都过同一张表。`Recognize` 把链接改写成规范形态时必须带上定位参数：B 站活动页和嵌入播放器的 `page` 改写成 `p`、`t` 照带，b23.tv 的 `ep`、`ss` 短码带 `t`；这样取数用规范链接，展示和发出去的链接仍能跳到那一分钟。缓存键是干净链接，因此不同 `t`、`p` 分开缓存，不会把不同 P 合并。短链（b23.tv、t.co、xhslink）解析出的终点在 `Resolve` 里再走一遍 `Recognize`，终点自带的分享参数在那里清掉。

验收：`tracking_table_test.go` 的 `TestCleanTable` 每个平台至少一条 App 分享形态的脏链接（编号编的），同时验 `Recognize`、`CleanAny`、`FindURLs`，并检查两遍等于一遍、大小写和转义的键、片段、表外参数、重复值和空值；`TestShortLinkTargetCleanedAgain` 覆盖短链终点。

不同追踪值归到同键；不同未知参数、p、t 不合并。即使第三方接口只按 status ID 取数，缓存对外也不丢用户的定位语义。媒体直链的签名和过期参数不套原帖删除表；对外只给干净原帖链接，内部按资源使用，不泄漏到诊断日志。

## 七、缓存、参数与生命周期

ADR-192 已定结果复用 24 小时、视频下载和缓存 100 MB 可配。MB 按十进制：100 × 1000 × 1000 字节，不写成 100 MiB。总磁盘预算、重启复用、群内再次展开规则尚无决策，见最后一节；实现这些部分前先补决定。

配置草图放 `<数据目录>/config/sumika.yml` 的 `linkReader` 段；键名是工程暂定，实施时同步 Go 配置、示例、参考页。数字工程初值可调但没有用户决定效力。

结果缓存只写已校验的主体；有正文但视频超限/下载失败是主体成功，媒体另记状态。评论等可选子请求失败写字段状态，不能用空集合冒充没有评论。整体解析失败不写 24h 成功缓存，只受平台冷却控制。过期刷新失败不覆盖旧好结果，返回旧值须标“已过期，更新失败”，不能重记 fetchedAt。

并发同键只跑一个取数任务，两个出口共享；等待者取消不取消仍有人等待的任务，最后一个等待者离开或插件停用才取消。短链解析期间也按干净短链合并，确认终点后合并同终点任务。消息关联和发送去重不放进全局结果缓存，避免跨群/角色串结果；过期、重启和重复展开政策等最后一节决定后落地。

第 3 步独立实现（2026-10-30）：`linkreader.NewService(store.Stores, ContentFetcher, CacheOptions)` 返回共享服务；`Get(ctx, raw)` 清洗后查库或合并取数，`Close()` 拒绝新取数、取消并等待任务，宿主必须先关闭服务再关库。缓存过期刷新失败直接返回原错误，旧成功行保留供历史详情使用，本步不返回未标注的旧值。`CacheOptions.TTLHours` 的零值取 24，`Now` 可注入回放时钟；尚未接 Go `config.go` 或 YAML。

同键最后一个等待者取消后，任务保留到实际退出才移除；此时新来的等待者可取消地等待旧任务收尾，再重新查缓存或取数，避免旧网络请求尚未退出就启动同键新请求。`TestCacheCanceledTaskExitsBeforeReplacement` 用返回屏障固定交错，核对新等待可取消、两次取数不重叠。

`go/trace.db` 的 `link_results(clean_url, fetched_at, result_json)` 保存经身份和主体校验的完整 `Result`，`link_aliases(clean_url, target_url, resolved_at)` 保存干净短链别名，别名按同一 TTL 重新确认。共享缓存只代表外部取数结果，不代表任何角色拥有读取权限。每个会话所属平台库新增 `message_links(conversation, message_seq, clean_url, previous_count, snapshot)`，主键为前三列，另建 `(conversation, clean_url)` 计数索引；详情按 JSON 的 sha256 存进同库的 `link_snapshots(hash, result_json)`，同一份结果只存一次（2026-10-30 起，chat/0005；同一条长推文关联 1 万次从 256 MB 降到 3 MB），`message_links.result_json` 只留给 0004 时写入的旧行。快照不随共享缓存刷新而改写，重放不留没人引用的快照，不引用其他平台的 seq。

`Associate(ctx, conversation, seq, raw, *Result) (int, error)` 在同一事务里记录并返回首次处理时的历史次数；重放返回原次数，空结果可随后补齐，同消息同链接仍只有一行。失败也可传 nil 记录出现次数；短链取数完成后以返回的 `Result.CleanURL` 关联，避免把短链与终点算成两份。`Detail(ctx, conversation, seq, raw)` 只查指定会话的关联快照；本步没有角色权限消费者，后续详情工具仍须验证当前角色可见性，不能把此存储接口直接开放成工具。

`FetchOptions.Rate` 的 `RateOptions` 配置每个平台各自的滚动一分钟 HTTP 预算（`RequestsPerMinute` 零值 10）和 429 冷却下限（`CooldownSeconds` 零值 60）；`Now` 可注入。预算和冷却属于共享的同一个 Fetcher，短链跳、子请求和回退均在 `request` 扣预算，HTTP 429 在读响应体前进入冷却，Retry-After 支持秒数及 HTTP 日期；拒绝请求返回 `rate_limited`，不建排队重试（已被 ADR-370 改为：只有冷却时立刻拒绝；额度用满时排队等空位，最多 `RateOptions.MaxBudgetWait`，生产由配置 `linkReader.rate.maxWaitSeconds` 给，默认 45 秒，回合时限先到就不等；额度由 `linkReader.rate.perMinute`（默认 60）和按平台的 `linkReader.rate.platforms`（默认 `bilibili: 10`）给，`PerPlatform` 覆盖 `RequestsPerMinute`；测试 `TestBudgetFullWaitsForSlot`、`TestBudgetWaitGivesUpBeyondMax`、`TestBudgetWaitRespectsContextDeadline`、`TestCooldownDoesNotWait`、`TestPerPlatformLimit`）。运行中的预算和冷却不持久化。本步不接配置加载、不下载媒体，`Result` 中媒体字段按原结构存库。

**限速的键（2026-11-13，`fix/rate-limit-keys`，来自 `data/dev/audit-shared-parts-20261113.md` 第一节）**：预算和冷却的键由 `rate.go` 里的 `services` 表给出，不在限速代码里写平台特判。表的每一行是“平台、主机后缀或精确主机、`splitCooldown`”：预算永远按平台一份；冷却默认也按平台，`splitCooldown` 为真的平台（现在是 X 和 Steam）改按主机冷却——X 的 fx、vx、官方嵌入接口各自限流，Steam 的社区和商店各自限流，一家回 429 不挡另一家；平台级冷却（`cooldown(平台)`，如 GitHub 额度耗尽、小黑盒验证码）仍挡住该平台所有主机。以前 `hostCoolKey` 里写死的 `platform != "x" && platform != "steam"` 已删，新平台出同类事故只改表。**认不出平台的普通网页不再落在 X 名下**：键是 `web@` 加小写主机名（不含端口），只去掉开头的 `www.`，子域各算各的（`a.example.com` 和 `b.example.com` 是两份预算和冷却，`example.com` 与 `www.example.com` 是同一份），所以一波普通网页链接耗不掉 X 的每分钟预算，它的 429 也只冷却那台主机。X 现在由表里的 x.com、twitter.com、t.co、fxtwitter.com、vxtwitter.com、fixupx.com、fixvx.com、twimg.com（含子域）认出。普通网页主机很多，限速表项超过 256 个时清掉窗口里没有请求且冷却已过的项，冷却中的不清。测试：`TestPlainWebDoesNotSpendXBudget`、`TestRequestPlatformPlainWebKeys`、`TestPlainWebCooldownIsPerHost`、`TestPlainWebEntriesAreSwept`。

**Retry-After 的上限（2026-11-13，同分支）**：对端回的 Retry-After 最多让一个键冷却 `MaxRetryAfter`（常量，10 分钟），以前没有上限，对端回一个很大的值整个平台会冷却到重启。秒数和 HTTP 日期两种写法都封顶；写不进 int64 的超长数字按上限算；负数、小数、空、乱值、过去的日期按默认冷却（`rate.cooldownSeconds`）；`rate.cooldownSeconds` 本身配得比 10 分钟大时仍以它为底。到点放行后对端仍限流就再冷却一轮。GitHub 匿名额度耗尽后按 `X-RateLimit-Reset` 冷却是例外：额度窗口是一小时，上限用 `githubResetCap`（1 小时），不被 10 分钟截短。测试：`TestRetryAfterIsCapped`、`TestRequest429HugeRetryAfterEndsAtCap`、`TestGithubResetNotCutByRetryAfterCap`。

下载流写隔离临时目录；累计实际字节，缺/假 Content-Length 不能绕过上限；DASH 音视频/HLS 分片共用一次预算，合并输出和 GIF 产物再次检查。完整成功后才提交文件；取消/错误删除半文件，不用“文件存在”判断下载成功。超限按 ADR-192 只发封面和链接。GIF 尽量转回 GIF，工程初值长边 720、最多 300 帧、15 fps，产物同样受视频体积上限；转换失败/超限保留 MP4 和原因，不把静态图冒充 GIF。无旧的 5 分钟时长限制。

插件停用、消息撤回或会话关闭后取消对应等待和未开始的发送；共享结果仍可供其他合法等待者使用。发送开始后依出口三态回执收尾，未知不自动重发。关机先停解析入口、取消并等待工作队列/子进程，最后关关联存储；迟到任务不能写库、发消息或提醒。清理不得删除在途发送持有的文件。

## 八、两个出口与渠道接线

### 8.1 给她看、详情工具和引用

短附注用确定性字段拼成“B站视频《标题》｜作者”或“X：正文开头”，总计最多 40 个 Unicode rune（省略号计入），未知卡片用标题/描述，失败用“链接没解析出来”。一条消息多个链接按顺序组合，整个附注共用 40 字预算，未显示的写“另有 N 条”，详情保留全部已处理项。外部文字转义后再核对长度，不能截断 UTF-8。

详细卡保存 Blocks、字段状态、原消息关联、干净链接、fetchedAt；只读工具暂名 `read_link_detail`，输入当前会话 message seq、候选序号、正文 offset，单页正文最多 1500 rune、每页最多 20 块，返回 nextOffset 和缺失状态。工具不能发送、不能接受任意 URL 变成通用联网工具；请求必须能从当前角色当前会话可见的消息查到关联。伪造 seq、其他私聊/群、其他角色不可见消息一律拒绝；共享缓存命中不构成可见性授权。历史详情过期可返回带时刻的已有卡，不自动越权重抓。

格式化当前批次、插话、历史重建及被引用消息都查同一消息关联；以 (渠道、会话、seq) 关联，平台消息号通过本会话映射到 seq。纯机器人已有展开按 ADR-104 归触发者原消息附件；不能靠“相邻 5 秒”或昵称把另一群的机器人内容挂过来。第一版不新增抓取其他机器人的识别启发式。

网络未完成时不阻塞入库/观察或拦截链。尚未进入回合的消息可在排文本时取最新关联；已提交到实例的原有行不能原地重写，完成后在下一次该会话输入尾部追加带源 seq 的资料，标记一次，保留原来前缀（ADR-022）。不因资料晚到额外唤醒她回一句。引用的原文预览 20 字与链接摘要独立展示；反复引用不重复联网，无授权可见性时只显示未取到，不放宽到其他会话查。

### 8.2 展开、拦截语义和协议动作

> 已被 ADR-251 改为：自动展开不经模型、不挂在角色的会话档位上，按插件自己的白名单 / 黑名单（设置 · 插件页）决定发不发；只记录的会话在名单里照样展开。下面讲出口动作和来源的部分照旧。

默认作为观察后的后台内容插件，纯提链入队后返回 Passed，让“给她看”和普通对话继续；不得为了避双回复让整批链接加提问都消失。是否让纯链接的自动展开接管该条回话未在 ADR 定，见最后一节。工作任务独立于拦截链 3 秒时限；拦截超时取消后不能留下一个迟到自动发送任务，入队必须由宿主明确接管生命周期。

确认启用、发送许可、能力和去重决策后，开始网络处理前：QQ 群只点一次表情回应；QQ 私聊先排状态句，再取数并排结果。只给她看的会话不点回应、不发状态（ADR-193、194）。缓存命中省网络，若仍需发结果也遵循同一状态次序，不发完成/失败的额外表情（ADR 未要求）。选哪个开始表情尚待主人定。

| 能力 | QQ 群动作候选 | QQ 私聊动作候选 | 首版要求与证据边界 |
|---|---|---|---|
| Quote | `send_group_msg` 中 reply+正文/图片的同一段数组 | `send_private_msg` 同样组合 | 原消息号非空且本会话可引用；不能把当前 PartQuote 单独发作一次 action |
| React | 候选 `set_msg_emoji_like`，参数 message_id、emoji_id、set | 不支持，不调用 | ADR-193 确认群回应需求、私聊不支持；动作名/参数须协议端文档及假端/真机核验 |
| Forward | `send_forward_msg` 或协议端明确的群转发动作 | `send_forward_msg` 或明确的私聊转发动作 | 中间件第十三节记载动作差异；不能轮着调用猜成功，适配器固定其验证过的一条 |
| GIF/图片、视频 | send_group_msg 的 image/video 段 | send_private_msg 的 image/video 段 | 当前 Go 未接；GIF 实际是否按动图展示、视频能否进 Node 都需真机验收 |
| 收卡片 | 入站 json 的 data.data | 同左 | 当前映射已有，完整载荷缺口见第二、三节；xml 不宣称支持 |

此表是待实现的动作映射，不是已核实 SnowLuma 支持；本任务禁止读 SnowLuma 文件，也未真机发包。Caps 需能表达 Quote/Forward 的群/私聊差异、React 仅群以及 Video/动图实际支持。媒体能力自 ADR-310 起默认声明能发（图片、GIF、视频、转发内媒体），未经真机验证的以发送回执为准：明确失败按场合和种类退成文字，见[链接自动展开规格](规格-链接自动展开.md)第十一、十二节。React 等非正文动作也经唯一出口排计划和检查，不给插件适配器句柄。

普通结果/失败引用原消息；长文章、混排用一层合并转发（ADR-192）。正文块按原顺序输出，禁止先视频后图片分组。引用与 Nodes 能否同一次发出必须实测（2026-10-30 在 QQ 群实测：不能，协议端回 1400，见《规格-QQ发送上线》3.4）；不能时，我的建议是先发一条引用原消息的导语，再发转发，两者绑定同一计划，须最后一节确认，不能静默去掉引用（这一句已被[规格-链接发送改版](规格-链接发送改版.md) B4、A5 改为（ADR-360）：转发前不另发导语，转发段上的引用直接去掉、靠源消息上的进度表情和入库连接对上）。节点显示原作者须标“外部内容”，QQ 发送身份仍为自动化；作者自串和其他人的评论分区，不冒充她在说。

所有状态/摘要/转发/失败来源为 `automation:link-reader`，不进入她的学说法、画像或作为她主动发言计数；接收回声不再次提链。试运行由出口使用既有 dry-run 来源，不擅自直发。第一段成功而后段失败要保留成功回执，不能把整计划重放；结果未知沿用发送上线规格不重试。详细异常不附在群失败句里。

### 8.3 群里谁发的链接能触发展开（2026-11-13，`feat/link-senders`，R-375）

用户 2026-11-13 要“给群聊添加用户白名单 / 黑名单 / 全通过机制”。在会话名单（`expand.mode`、`expand.conversations`）之外再加一层发送者名单：

- **配置** `linkReader.expand.senders`：`mode` 为 `all`（默认，谁都能触发，和改动前一样）/ `whitelist`（只有 `users` 里的号）/ `blacklist`（`users` 里的号除外）；`users` 写 QQ 号（规范的正整数串）；`groups` 按群号单独设 `{mode, users}`，写了某个群就整份用它的，不和全局合并。校验：模式只认这三个、号和群号必须是数字、名单最多 2000 个号、最多给 500 个群单独设，`senders` 子树里拼错键（`mod`、`group`、`user` 之类）也拒绝加载（复核：宽松解码会把拼错的白名单悄悄当成 all），写错整份配置加载失败。**只在配置文件里改**（设置页登记为只读，还没有写入入口）：改完重启接收生效，或者在链接设置页保存任意一项时整份重读、一并生效；读进来以后，在途的展开按新名单撤销（`Refresh`）、发送前复查（`permit`）也按新名单拦。
- **只管群聊**：私聊照旧由会话名单和私聊白名单决定。**主人永远能触发**，名单拦不住主人。只管“展开发出去”，不管给她看的链接摘要（`linkReader.context`）。
- **认人按身份不按名字**：主人是 `ActorOwner`；别人是 `ActorHuman`、ID 为 `qq:<号>`；取不出号的当认不出（白名单不放、黑名单不拦）；群名片、昵称写成主人或名单里的人都不算。
- **四处入口共用一个判断** `linkplugin.SenderAllowed`（底层 `config.LinkExpand.AllowsSender`）：插件收消息时（`OnStored`）、补录和重复送到时记没展开原因（`traceIgnored`、`traceNotExpanded`，原因“发消息的人不在这个群的展开名单里”）、设置热改后撤掉已不允许的在途展开（`Refresh`）、发送前复查（`permit`）；宿主发送前最后一道门 `app.checkLinkParts` 按库里源消息的身份再查一次，插件漏了也发不出去，而且它在取数前就会被问到，所以连数都不取。
- **形状 × 入口**（场合：本地私聊、本地群聊不进展开，`admitLink` 只收 QQ，记“不可能”；QQ 私聊不受名单影响，记“处理了”并有测试；下表是 QQ 群）：

| 形状 | 插件收消息 | 没展开原因 | 热改撤销 / 发前复查 | 最后一道门 |
|---|---|---|---|---|
| 缺（没有身份） | 测了：白名单不放、黑名单不拦 | 测了 | 处理了（同一函数） | 处理了（同一函数） |
| 空（`qq:` 后为空） | 测了 | 处理了 | 处理了 | 处理了 |

| 7 排障出口 | 复用装配的 `<数据目录>/logs/go-<日期>.log`；详情/诊断关联 ID 同存解析记录，主窗口详情显示（ADR-191） | mygo 尚无 link-reader 详情入口，接入前用隔离目录的诊断回放验证，不能说主窗口已完成 |

诊断记录字段：随机关联 ID、平台/资源 ID、阶段、接口代号、尝试/回退序、脱敏请求方法/路径、HTTP 状态/Content-Type/业务码、期望字段路径/实际类型、耗时、声明/实际字节、局部失败类别。响应预览最多 300 rune，先脱敏后裁剪，固定类别日志不打印完整原卡或整响应。query 值默认遮蔽，Cookie、Authorization、登录参数、签名媒体 URL 不进日志/提示词；原帖公开正文只在授权详情里。主窗口按原消息进入详情，失败条目的关联 ID 对上日志，不改变群里默认失败句。连续失败提醒复用 `internal/alert`，阈值工程初值同平台 3 次主体失败只 Raise 一次，主体恢复 Clear；429 和用户删除内容不算接口连续故障。

## 十、禁止的偷懒写法

- 不读 Raw 的 200 字预览当完整卡片，不只看第一张卡，不用递归扫任意字符串替代 URL 字段契约。
- 不按域名字符串包含识平台，不让短链/媒体重定向访问内网，不以关 TLS 校验解决风控。
- 不删除表外参数，不把 X 的 t 表用于 B 站，不把清洗后的链接覆盖原消息，不把签名媒体地址当分享地址。
- 不把图片/视频分组重排，不用长 Note/推文串替代 Article，不把首 MP4 后面的媒体丢掉。
- 不让 Parse 自动开下载/发送，不给两个出口各写一套缓存、请求、限速；不只查 Content-Length。
- 不把元数据可读当完整可播，不把字段缺失当数值 0，不把字幕、AI 总结和视频内容理解混为一项。
- 不在拦截队列等 30 秒网络，不把补录、自发回声、自检、陌生人或只记录消息当自动展开触发；详情不按任意缓存键越权查。
- 不绕发送权、核号、守卫、暂停和三态回执，不先发无引用结果然后补称支持引用，不用假端通过宣称真机支持。
- 不编造实测接口字段、可靠性、主窗口现成功能或主人决定；未定项保留选项，不在实现里偷偷落默认。

## 十一、已知的坑与验收标准

本节是实现验收要求，本次纯文档任务没有运行这些代码场景。每行在实现提交说明附对应测试名或回放日志；平台响应先脱敏录样，永久测试离线，真实网络验证另记时间和失败项。

| 编号/边界类别 | 场景与必须观察的结果 | 证明方式 |
|---|---|---|
| A1 ②⑯ | CRLF、中文标点、emoji、括号、重复 query、空值、一次/二次编码、未知参数；清两遍等于一遍 | 纯函数断言正确 URL、顺序、保留项和幂等；故意删 B 站 t/p 或全 query 时应红 |
| A2 ⑥⑱ | x.com.evil、userinfo、混淆主机、IPv4/IPv6 内网、短链循环、5 跳/第 6 跳、DNS rebinding、媒体重定向 | 隔离 HTTP/DNS 假端和拨号记录：不安全目标没有连接；正常公开样本能到取数阶段 |
| A3 ⑯ | 3.1 每种形状 × 实时/存库回读/引用/工具读详情入口 | 超 200 字的合法卡仍还原；坏第一卡不遮后项；xml 不冒充 json；>256 KiB 只跳当前卡 |
| A4 ⑦⑪ | 40 字边界、1500 字详情分页、长作者名、多链接组合、20 字引用预览 | 实际上下文/工具输出无越界、摘要未被引用预览截掉，nextOffset 可连起来还原可见正文 |
| A5 ⑱ | X 表 4.1 所有类型，媒体交错、GIF、引用循环、缺 Article 正文、目标 ID 不符 | 脱敏响应离线回放，Blocks 顺序和状态对；5～10 个匿名真实样本独立运行，分别报告可用/缺字段，未测 Article 不算完成 |
| A6 ⑧⑩⑯ | B 站各类型、分 P 边界、412/-412、普通网络错、HTML、评论失败、字幕需登录、直播离线 | 离线断言只有风控走 WBI、子项失败保留主体；5～10 个真实匿名样本覆盖实际声称支持的类型，不足的类型单列未验证 |
| A7 ⑬⑲ | 同追踪不同键值、不同未知参数、p/t、两群同时同链接、部分成功、TTL 前/正好/后、失败后重试 | 假平台精确请求计数；同键只一个在途、不同内容不误合，失败不刷新 TTL；重启按最终决策验 |
| A8 ⑦⑩ | 无/假 Content-Length、上限少一字节/正好/多一字节、DASH 合计、GIF 输出超限、中断 | 下载实际写入计数及文件状态；超限仅封面链接，无半文件复用；B 站关下载时视频请求数为 0 |
| A9 ⑤⑥㉑ | 本地私聊/本地群聊/QQ 私聊/QQ 群，展开开/关、试运行/只记录、其他角色/群 seq、自动化回声 | 四场合小表报告变/不变；可见性负例拒绝、没有未经许可 action，缓存共享不能越权 |
| A10 ④⑧⑭ | 网络迟到、已提交实例、插话/重建/再次引用、撤回、关插件/关机后放行阻塞 | 不改旧前缀、不重复摘要、不额外唤醒；停止后无迟到写库/发送，临时目录可重新打开 |
| A11 ⑩⑱ | QQ 群回应、私聊先状态、引用摘要/失败、长文和混排转发、GIF/视频；部分发出/未知 | 先假端逐帧核对，再按主人指定会话真机观察；引用指向原消息、节点顺序正确、私聊无 reaction、未知不重发 |
| A12 ⑪㉑ | 编造 Cookie/token/签名 URL、恶意正文伪行头、结构错、连续失败及恢复 | 日志/主窗口/工具实际输出无秘密、无伪身份；固定失败句与诊断关联对上，提醒去重和恢复正确 |
| A13 ⑫⑲ | 临时目录路径含空格/#/%、冷启动/archive、持久化版本变更 | 隔离入口 smoke；archive 无联网、无新建解析存储；存储按最后一节确认的政策运行 |

纯函数正负样本均需覆盖支持/拒绝形状；不得把仅“没报错”当链接正确。高倍验收在隔离数据目录放 10 个角色、至少一万条带重复和多链接的消息回放，记录候选数、平台请求数、峰值在途数、缓存/文件占用和关机耗时，不能只写“看着不卡”。只在改到 UI 详情页的步骤按设计自查验证窄窗口和长正文；本任务不做 UI。

实现合进 main 前按项目约定低优先级跑 `native/` 的 `go vet ./...`、`go test ./...`，保留退出码；文档跑 `bun run check:docs`。本分支只改文档，不代跑代码验收、不启动真实接收、不向真实 QQ 发送，不访问真实 data 或其他机器人文件。

第 4 步进度（2026-10-30 合进 main）：
- 入库后的 QQ 接点是流水线的 `Observers`（`channel.Observer`，插件统一规范草案 v0.1 的 Message.Observe）：进链的那批消息才给（补录、陌生人、她自己的、只记录的会话不给），只排任务；段直接给，不另读库。本地私聊通过 `turn.Config.OnLocalStored`、本地群通过 `localgroup.Service.OnStored` 在提交后、回合前通知同一插件的 `ObserveLocal`；已送达本地插话也接同一通知。使用真实本地会话键，不套 QQ 的私聊格式。队列在 `linkplugin` 里（2 个协程、256 长，满了丢并记日志），不持久：重启时没取完的丢掉，同一个链接再发照样取。
- 摘要不写进存库的那一行（入库时还没取到），统一走拼参考信息：回合开头和插话时，本会话她看到过（`observations`）、24 小时内、最近 20 条带链接的消息里还没给过的，追加成「[链接资料] … 编号 N（名字 时刻 发的）：摘要」，进了实例才记“给过”；这一批里还有在取的最多等 2 秒。实例重建后会重新给一遍最近的。
- 本地事件没有 QQ 的 segs/from 信封；`LinkNote` 从同一事件读原文和 actor_kind，原文用于未处理候选数，可信 owner 身份用于补发言人，不向原消息写摘要或伪造段信封。
- `read_link_detail` 参数是消息编号、第几个链接、offset；头每页都给，正文一页 1500 字、20 块。编的编号、别的会话、别的角色看不到的，回同一句“没有这个编号的链接资料”。
- 验收：`internal/linkplugin` 单元测试（含越权、关机迟到不写库、队列满、40 字预算和转义），`internal/app` 的 `TestLinkSummaryReachesModel` 覆盖 QQ 入库到内核；`TestLocalLinkSummaryReachesModel` 覆盖本地日常、话题、群聊的正式写入口、摘要、详情结果进下一次模型请求以及开关两态。`TestLinkVisibilityAcrossScenes` 同时覆盖四场合、其他角色、其他群及非法编号；`TestLocalLinkSourceAndBudget` 覆盖本地原文没有段信封时的来源和四条只取三条。
- 引用：被引用的那条有链接资料时，引用那一行写成「↪引用 名字：前 20 字｜链接：摘要（编号 N）」，摘要和 20 字预览分开（`LineEnv.QuoteLinks`）。引用本身把那条摆在了会话里所有人面前，所以这里不按角色筛（`store.QuotedLinkNotes`）；详情工具照样按角色筛。行是入库时排好存下的：被引用的那条当时还没取完，就不带。`TestQuotedLinkSummary` 量的是存下的那一行。

## 十四、要主人定的（2026-10-30 已由 ADR-217 定下）

1. 每条消息默认最多处理 3 条链接，配置能改，多出的标"还有 N 条没处理"；只认完整网址，裸 BV / av 号识别要做、默认关。
2. 同一链接再发，每次都展开回复；本会话之前发过的加一句"发过 x 次"；取数 24 小时内复用；展开以后她照常接话（暂定）。
3. 结果和消息关联存库、跨重启；图片视频发完即删、用时再下载，不另定总磁盘上限；单视频 100 MB。
4. B 站视频下载默认关；开始处理的表情等协议端确认后给主人候选；合并转发先引用原消息回一句、再发转发，同一次展开。
5. 成人 / 敏感 / 判断不了：默认只发文字和干净链接；每个 QQ 群、QQ 私聊单独开关放开媒体；登录内容不绕过。pixiv 的 R18/R18-G 默认已被 ADR-254 改为整条替换成可自定义提示，默认「该作品包含18+内容」，按会话开关放开，发送轮实现。自动展开只在 QQ 私聊、QQ 群，本地私聊、本地群聊只给她看。
6. 翻译第一版不做，以后默认关、手动打开。
