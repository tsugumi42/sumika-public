# 规格：读大文件、PDF 和 Office 文档，写前查外部改动

> 状态：2026-11-09 在 `feat/read-docs` 实施，已合 main（ADR-335； 补了忙机器上第一次读 PDF 失败）。进度看第九节勾选；没勾的没做，第一节到第五节写的是目标。来源：工具审查 B10、B28、优先清单第 10 件前半（`data/dev/harness-audit/00-总表.md`）。
>
> 参考：opencode v2 `packages/core/src/tool/read-filesystem.ts`（窗口数字、NUL 判二进制、分块流式）；omp `packages/coding-agent/src/tools/read.ts`、`utils/src/binary.ts`、`markit/`（小文件整读、大文件流式；文档转文字后再走行窗口；`:page2.png` 看 PDF 页图）；Hermes `tools/read_extract.py`（docx、xlsx 只用标准库；扫描件覆盖提示放开头）、`tools/file_tools_read_tracking.py`、`file_tools_write_guards.py`（读时记 mtime，写前漂移就拒）；OpenClaw `extensions/document-extract`（PDFium，文字太少的页转图）；Claude Code 更新日志和工具说明（`pages` 参数、FIFO 不阻塞、改名 `PARTIAL view`）；Codex `codex-rs`（没有 read 工具，作为数字对照）。
>
> 采用：opencode 的窗口数字、omp 的“小文件整读 + 大文件流式”“文档转成文字后共用行窗口”、Hermes 的 docx/xlsx 做法和“提示放开头”、OpenClaw 的 PDFium 与低文字页判定、Claude Code 的单页看图参数。没采用：Hermes 的“没读全就不许写”（比主人要的严）；omp 把 PDF 页塞进路径的写法（模型要学一种路径语法）；OpenClaw 自动附页图（用不用图应由模型决定，省 token）。

## 决定和依据（已写成 ADR-335，下面是写 ADR 时的底稿）

1. **PDF 用 PDFium 的 WebAssembly 版（`github.com/klippa-app/go-pdfium` v1.21.4 + `github.com/tetratelabs/wazero` v1.12.0），不用纯 Go 解析器。**
   - 依据：2026-11-09 已实测，选型成立（同四份编的样本：LaTeX 论文式英文、中文 CID 字体、表格、坏内联图，结果见第八节）。实测确认的差距：`ledongthuc/pdf` 在 LaTeX 式排版上词间空格全丢（`Understandingtheeffectsofweightdecay`），表格每个格子单独成行、行结构丢了，中文换行处给出 U+FFFD；PDFium 在这三项上都对。没复现的：原先写的“坏内联图直接报错”，三种坏法（数据不是 Flate、没有 EI、参数乱写）两边都读出了前后文字。没测的（来自读源码和 issue，未亲测）：内部大量 `panic`、加密只到 AESV2、开放 issue 里的无界内存增长（#80）和 XObject 文字取不到（#67）。
   - “纯 Go 优先”的取舍：go-pdfium 的 WASM 模式不用 cgo，交叉编译和纯 Go 库一样；PDFium 跑在 WASM 沙箱里，坏文件崩不了进程。代价是可执行文件变大（实测：带 pdftext 的测试二进制 25.9MB，只带 tools 的 19.3MB，多约 6.6MB），首次读 PDF 要编译 WASM（2026-11-09 本机实测：无缓存 4.7 秒，有磁盘缓存 0.25 秒）。
   - 候选（2026-11-09 用 `gh` 查）：`ledongthuc/pdf` BSD-3、631 星、2026-10-20 还在提交；`rsc/pdf` 已归档；`dslipak/pdf` BSD-3、2024-04 后没动；`pdfcpu/pdfcpu` Apache-2.0、8.9k 星、活跃，但只给原始内容流，没有文字提取；`unidoc/unipdf` 商业授权；`gen2brain/go-fitz` AGPL-3.0；`seehuhn/go-pdf` GPL-3.0；`benoitkugler/pdf` MIT，低层模型；`LightningRAG/pdf-go` MIT、10 星，太新。
   - 许可证：go-pdfium MIT，内嵌 PDFium Apache-2.0，wazero Apache-2.0；传递依赖 `github.com/jolestar/go-commons-pool/v2`（Apache-2.0）、`github.com/google/uuid`（已有）。
   - 装配：PDF 引擎放独立包 `internal/pdftext`，由 `internal/app` 注入 `tools`，几十个导入 `tools` 的测试二进制不带 5.8MB 的 WASM。
2. **read 新增可选参数 `page`：PDF 第 N 页转成图片，连同这一页的文字一起返回。** 依据：扫描件没有文字可读，模型得有办法看；Claude Code 的 `pages`、omp 的 `:pageN.png` 都是这条路。文字层的分段继续用 `offset`、`limit`，不再加第二套。
3. **write 只在“这个会话读过，之后文件变了”时拒绝；没读过的不拦。** 依据：Claude Code、Hermes 都拒，Hermes 还要求读全；主人的倾向是引导加简单兜底，检查点已经能撤回，所以只拦确实会丢别人改动的那一种。edit 不查（旧文本对不上本来就报错）。

4. **Office 用自写的 `archive/zip` + `encoding/xml` 转换（`internal/doctext`），不加依赖。** 依据：docx、xlsx 只需要读文字，XML 结构固定；Hermes 也只用标准库；自己写能控制解压上限和文字上限，第三方库（如 `unioffice` 商业、`excelize` 偏写入且依赖多）都不划算。pptx、旧 `.doc`、`.xls` 不做，理由见第四节。

## 一、read 的分流

打开前先 `Stat`，打开后读前 8KB 判断，判断结果只决定走哪条路，图片的处理逻辑不变。

| 文件 | 处理 | 结果 |
|---|---|---|
| 目录 | 不打开 | 报错，提示用 `ls` |
| 设备、管道、套接字（`CON`、`NUL`、FIFO） | 不打开 | 报错。读它们会永远卡住（Claude Code 2.1.41 修过同一个坑） |
| 图片文件头 | 现有逻辑，文件句柄交给 `mediastore.PrepareImage`，超过 20MB 由它报错 | 不再先读全文 |
| `%PDF`（前 1KB 内，PDF 规范外的常见写法） | PDF 路线 | 第三节 |
| ZIP 且内有 `word/document.xml` | docx 路线（含 docm） | 第四节 |
| ZIP 且内有 `xl/workbook.xml` | xlsx 路线（含 xlsm） | 第四节 |
| ZIP 且内有 `ppt/presentation.xml` | 报错，说明不支持 pptx | 第四节 |
| 其他 ZIP（普通压缩包、损坏的文件头是 PK 的文件） | 按二进制说明，不当文本读 | 实现时补的：损坏的 docx 当文本读会得到半截乱码 |
| UTF-16 BOM | 解码成 UTF-8 后走文本 | 结尾写明编码 |
| 含 NUL | 二进制 | 报错，写明类型和大小 |
| 合法 UTF-8 | 文本 | 第二节 |
| 不合法 UTF-8 | 试 Shift-JIS（假名多）、GB18030（汉字多），能解才算文本；都不像时，控制字节不超过 2% 就按 Windows-1252 显示（旧代码也能读西欧老文本），否则按二进制报 | 结尾写明编码，并说明 `edit` 匹配不到、`write` 会存成 UTF-8 |

二进制判定不照 omp“不是 UTF-8 就算二进制”：主人的机器上 GBK、Shift-JIS 的文本很常见，全拒掉是倒退。

## 二、文本的窗口和体积上限

| 数字 | 取值 | 来源 |
|---|---|---|
| 每次最多行数 | 2000 | opencode `MAX_READ_LINES`、Hermes `DEFAULT_READ_LIMIT`、Claude Code 工具说明都是 2000；omp `DEFAULT_MAX_LINES` 3000；pi 2000（原值） |
| 每次最多字节 | 50KB | opencode `MAX_READ_BYTES`、omp `DEFAULT_MAX_BYTES`、pi 都是 50KB；Hermes 100000 字符；Claude Code 按 token，超了给 `PARTIAL view`（2.1.145） |
| 整读上限 | 4MiB | omp `SNAPSHOT_MAX_BYTES`；以下读进内存，语义和 Bun 录像完全一样 |
| 流式块大小 | 256KiB | opencode `FIRST_CHUNK` |
| 数总行数的上限 | 64MiB | 自定：普通磁盘 1 秒内能扫完。更大的文件不数，提示里写文件大小 |
| 判断用的头部 | 8KB | omp `BINARY_SNIFF_BYTES` |
| 单行 | 不单独截；一行超过 50KB 时给开头 50KB 并说明 | opencode 2000 字符、omp 512 列。没照搬：中文一段常超过 2000 字符，`edit` 又要精确匹配，短截断会让后面的字永远读不到 |
| Codex | 没有 read 工具，只有 shell + `apply_patch`：`DEFAULT_OUTPUT_BYTES_CAP` 1MiB（`utils/pty/src/lib.rs:25`），默认模型 `truncation_policy` 10000 字节（`models-manager/src/model_info.rs:127`） | 只作对照，不是可比的数字 |

- 不超过 4MiB：沿用原来的切片逻辑（JS 的小数、负数语义），`read-*` 五个录像逐字不变。
- 超过 4MiB：流式扫行，内存只留窗口。`offset`、`limit` 取整，`limit<1` 当没写。
- 文件变大以后 `offset` 仍要从头扫到那一行，耗时和偏移成正比；这里不做行索引，提示里引导用 `grep`。
- 窗口里出现 NUL（头部是文本、后面是二进制）也按二进制报，不交半截乱码。

提示沿用原文案，新增两种：

```
[Showing lines 1-2000 of a 5.0GB file. Use offset=2001 to continue. grep finds things faster in a file this big.]
[Line 1 is 5.0GB, exceeds 50.0KB limit; showing its first 50.0KB. offset can't go inside a line: use grep for what you need, or powershell to cut a range.]
```

## 三、PDF

- **文件上限 512MiB**：Claude Code、opencode 的 20MB 是整份发给模型的限制，Hermes 的 50MB 是整份读进内存转换的限制；这里用 `FileReader` 按需读，内存不随文件变大。超过直接报体积。
- **页数上限 2000 页、文字上限 16MiB、时间上限 20 秒**（read 的总时限是 30 秒，要留给首次编译和收尾）。到上限就停，开头写明提取到第几页，后面的用 `page` 逐页看。OpenClaw 的 200k 字符上限是因为文字整份进上下文，这里有行窗口，不需要那么小。
- **输出**：开头一行页数和提示，之后 `--- 第 N 页 ---` 分页，走第二节的行窗口。同一文件连续分段不重新提取：按路径、大小、修改时间缓存最近 4 份结果。
- **没有文字的页**：非空白字符少于 20 个（Hermes `PDF_EMPTY_PAGE_CHARS`），且页上有图片、路径等非文字对象（空白页不算）；或者文字里三成以上是替换符、私用区字符（字体没有映射）。提示放开头（Hermes 的理由：分段时结尾可能永远读不到）。
- **全都没字**：`[PDF 共 12 页，没有可用的文字层（多半是扫描件）。用 read 加 page=1 把第 1 页转成图片看，一次一页。]`。这不是报错。
- **`page=N`**：长边 1568 像素（Anthropic 视觉文档的建议上限，A4 约 135 DPI，小字还能认），白底 JPEG 质量 85，连同这一页的文字返回。扫描页 PNG 动辄几 MB，JPEG 约 300KB。结果里写明“如果看不到图，就是当前模型不能看图”，模型不会把没看到的当看到了。
- **密码**：打不开就说有密码，让主人给无密码的版本。只设了所有者密码（空用户密码）的能正常读。工具不接受密码参数。
- **隔离**：不挂任何目录（go-pdfium 默认把整个盘挂进沙箱，这里传空的 `FSConfig`）；内存上限 2GiB；关掉 stdout、stderr；每次新实例、用完即关，大文件的内存能还；取消时 `Kill`，配合 `WithCloseOnContextDone` 真的停下。
- **编译缓存**：`<数据目录>/cache/pdfium`，属于可再生，不进备份（规格-数据目录与备份）。

## 四、Office

只用 `archive/zip` + `encoding/xml`，新包 `internal/doctext`，能做干净，一起做了。

- **docx**：段落、表格（`|` 分隔）、标题（按 `styles.xml` 的 `heading N`、`Title` 写成 `#`）、列表（`- `）、图片（`[图片]`）、文本框、脚注和尾注。跳过注音（`w:rt`）、删除修订（`w:delText` 本来就不是 `w:t`）、域代码（`w:instrText`）、`mc:Fallback`（否则文本框字重复）。有批注时结尾说明没提取。页眉页脚不取。编号列表的序号要跑 Word 的编号引擎才算得出，这里只给 `- `。
- **xlsx**：按 `workbook.xml` 的顺序、`rels` 找表，跳过隐藏表并在结尾写名字。每行一行、制表符分隔，单元格里的换行和制表符换成空格。日期单元格按 `styles.xml` 转成 `2026-11-09`，处理 `date1904`（Hermes 不处理，日期会变成序列数）。公式显示缓存值，没缓存时显示 `=公式`。列数上限 256（Hermes `_MAX_XLSX_COLS`）。不设 Hermes 的 5000 行上限，靠 16MiB 文字上限兜底，超了写明只到哪一行。
- **压缩炸弹**：每个 XML 部件解压上限 256MiB，总量上限 512MiB，走 `io.LimitReader`，不信 ZIP 头里的大小。`encoding/xml` 不展开自定义实体，没有“十亿笑”。
- **不做**：pptx（模型读幻灯片的需求还没出现，真要做是同样的 ZIP + XML，约五十行）；`.doc`、`.xls` 老格式（OLE2 复合文档，没有干净的纯 Go 库），报错并建议另存为新格式。

## 五、write 的外部改动检查

- 按“角色 × 会话 × 真实路径”记 `read`、`write`、`edit` 成功后的文件版本（大小、修改时间），Scope 从 `kernel.InvocationFromContext` 取，不改 turn。不同会话互相算外部：另一个角色或子代理写了，这个会话下次写前要重读。
- `write` 在 `withFileMutation` 的队列锁内、写入之前比较。审批等待期间的改动也能发现（检查在审批之后）。
- 变了就报错，不写，结果里给两边的大小和时间，让她先 `read`。文件被删了照常创建；从没读过的照常写。
- 记录上限 4096 条，满了丢最早的，丢了只是回到“没读过”，不误拒。进程重启清空，同样回到“没读过”。
- 只比大小和修改时间，不算哈希：NTFS 精度 100 纳秒，大文件读的时候也不该全文算一遍。假阳性（只 `touch`）的代价是多读一次。
- `powershell` 改文件不更新记录：她自己用命令改了也算“变了”，要先重读；多一次读，不会丢东西。

## 六、场合

`read`、`write`、`edit` 的可见和可用范围没有变化，`policy.Specs` 不动；文件内容的上限只会让输出更少，`page` 不产生新的路径入口（路径判定仍是 `pathArg`）。写前检查只会多拒，不会多放。

| 形状 × 入口 | 本地私聊 | 本地群聊 | QQ 私聊 | QQ 群 |
|---|---|---|---|---|
| 读 PDF、Office、大文件 | 主窗口审批门，处理了 | 工具不提供（`ownerConsoleAudience`），不可能 | 工具不提供，不可能 | 工具不提供，不可能 |
| `page` 看图 | 同上，处理了 | 不可能 | 不可能 | 不可能 |
| 路径缺、空、目录、设备 | 测了 | 不可能 | 不可能 | 不可能 |
| 路径是受保护目录 | 审批门在执行前判，分流在后，没变 | 不可能 | 不可能 | 不可能 |
| 恶意 PDF、ZIP 炸弹 | WASM 沙箱和解压上限，测了 | 不可能 | 不可能 | 不可能 |
| 别的会话改了文件再 write | 拒绝，测了 | 不可能 | 不可能 | 不可能 |
| 没有 Invocation（评测、命令行程序） | 空 Scope 也记，行为一致，测了 | 同左 | 同左 | 同左 |

## 七、禁止的偷懒写法

- 不许先 `os.ReadFile` 再判断大小。
- 不许把解析失败的 PDF、Office 退回当文本读。
- 不许二进制也回成功，也不许把 U+FFFD 成串塞给模型。
- 不许扫描件回空字符串（模型会以为文件是空的）。
- 不许说“已提示可以看图”却没有实际的看图路径。
- 不许用真实文件做测试样本，也不许入库别家仓库的样本。全部在测试里生成，名字是编的。

## 八、已知的坑

- **PDF 文字提取实测：go-pdfium（WASM）对 ledongthuc/pdf（2026-11-09）**。四份编的样本（生成器同 `internal/pdftext/testpdf_test.go`，比较程序在临时目录、不入库），两边都用默认参数、只比文字：

  | 样本 | go-pdfium | ledongthuc/pdf |
  |---|---|---|
  | LaTeX 式英文（词间距用 `TJ` 的 -333 微调，没有空格字符） | 5/5 命中，句子完整：`Understanding the Effects of Weight Decay` | 0/5，所有空格丢光：`UnderstandingtheEffectsofWeightDecay` |
  | 中文 CID 字体（带 ToUnicode，不嵌字体） | 3/3，两行各自成行 | 3/3，但两行之间是 U+FFFD 不是换行 |
  | 表格（4 行 3 列，每格单独定位） | 5/5，一行一排，格子之间用空格：`Item Qty Price` | 5/5，但每个格子单独成行，行结构丢了 |
  | 坏内联图（数据不是 Flate；没有 EI；参数乱写，各一份） | 都读出了图前后的文字 | 也都读出了，没有报错——原先写的“直接报错”没复现 |

  结论：选型成立，决定性的是第一项（模型读英文论文拿到的是粘成一串的词）。耗时：go-pdfium 第一次含 WASM 编译约 4.2 秒（这次没给编译缓存目录；装配里有 `cache/pdfium`，第二次起不用再编），之后每份 7 到 12 毫秒；ledongthuc 约 1 毫秒。没有推翻选型，代码不用改。没测：`panic` 频率、加密格式覆盖、内存增长（#80）、XObject 里的文字（#67），仍是读源码和 issue 的判断。
- PDFium 的 `GetPageText` 用 `\r\n` 换行，还可能带 U+FFFE（软连字符）、NUL：统一规范化，清两遍等于清一遍。
- 渲染出的图片缓冲只在 `Cleanup()` 之前有效，要先编码再清理。
- 页面可能带透明背景，直接编 JPEG 会变黑：先铺白底。
- `Kill` 不拿实例锁，和 `Close` 并发会空指针：由看门狗协程串行化，先停看门狗再决定关还是已杀。
- BMP 文件头只认 `BM` 两个字节，开头是 `BM` 的文本文件（比如 `BMW 报告`）会被当成坏图片报错。这是图片已有逻辑，这轮按任务不动，已列入交回的未完成项。
- 对拍录像只能由已退役的 Bun 脚本生成，所以新行为全写 Go 单元测试，不往 `testdata/cases.json` 加。

## 九、验收

- [x] 大文件分段：6MiB、70MiB 文本，内存不随文件增长，分段续读行号衔接，超 64MiB 不数总行数；单行超长给开头。
- [x] 五个 `read-*` 录像、十一个 `write-*` 录像不变（`TestSameAsBun`）。
- [x] 二进制：ZIP、EXE、随机字节，不把乱码塞进结果；头部文本后面二进制也报。
- [x] GBK、Shift-JIS、UTF-16 文本正确解码。
