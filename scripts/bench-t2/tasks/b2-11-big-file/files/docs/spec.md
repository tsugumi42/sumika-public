# semver 包说明

包名 `semver`，全部写在一个文件 `semver.go` 里，只用标准库。测试在 `semver_test.go`，以测试为准。

## 版本

```go
type Version struct {
    Major, Minor, Patch uint64
    Pre   []string // 预发布标识，"1.0.0-rc.1" 得到 ["rc", "1"]；没有就是 nil 或空
    Build string   // 构建元数据，"1.0.0+exp.sha" 得到 "exp.sha"；没有就是空串
}
```

### Parse(s string) (Version, error)

- 开头可以有一个小写 `v`（`v1.2.3`），其余都不许带空白。
- 核心部分必须正好是 `主.次.修` 三段，每段只能是数字，不许前导零（`0` 本身可以，`01` 不行），要放得进 uint64。
- 核心后面可以跟 `-预发布`，再后面可以跟 `+构建`。预发布和构建都是用 `.` 分隔的标识，每个标识非空，只含 `0-9A-Za-z-`。预发布里纯数字的标识不许有前导零；构建里的标识不限制前导零。
- 任何不合规的输入返回错误（错误信息里带上原输入）。

### (Version).String() string

不带 `v`。预发布用 `-` 接在核心后面、标识之间用 `.`；构建用 `+` 接在最后。`Parse` 再 `String` 要还原（去掉开头的 `v` 之外）。

### (Version).Compare(o Version) int

按语义化版本的优先级比较，返回 -1、0、1，**构建元数据不参与比较**：

1. 先比主、次、修，数字大的大。
2. 核心相同时，没有预发布的比有预发布的大。
3. 都有预发布时，从左到右逐个标识比：两个都是纯数字的按数值比；两个都不是纯数字的按 ASCII 字符串比；一个纯数字一个不是的，纯数字的小。前面都相等时，标识少的小。

### (Version).Bump(part string) (Version, error)

返回新版本，不改原值。`part` 取值：

- `"major"`：主版本加一，次、修归零，清掉预发布和构建。
- `"minor"`：次版本加一，修归零，清掉预发布和构建。
- `"patch"`：如果原版本带预发布，只是去掉预发布和构建（`1.2.3-rc.1` 变 `1.2.3`）；不带预发布，修版本加一，清掉构建。
- `"prerelease"`：原版本没有预发布时，修版本加一，预发布设为 `["rc", "1"]`；有预发布时，如果最后一个标识是纯数字就把它加一，否则在末尾追加标识 `"1"`；两种情况都清掉构建。
- 其他取值返回错误。

## 范围

### ParseConstraint(s string) (Constraint, error)

```go
type Constraint struct { /* 自己定 */ }
```

写法（和 npm 的习惯一致）：

- `||` 分隔多个组，满足任意一组就算满足；组内用空白分隔多个比较，必须全部满足。整个字符串为空（去掉空白后）等同于 `*`；但 `||` 两边的组不许为空，否则返回错误。
- 比较符：`=`（可省略）、`!=`、`>`、`>=`、`<`、`<=`、`^`、`~`。比较符和版本之间允许有空白（`>= 1.2.3` 和 `>=1.2.3` 一样）。
- 版本可以不完整：`1`、`1.2`，或者用 `x`、`X`、`*` 当通配（`1.x`、`1.2.*`、`*`）。通配之后的段必须也是通配或者省略。不完整的版本开头也可以有 `v`。不完整的版本不能带预发布或构建。完整版本可以带预发布，比如 `>=1.2.3-beta.2`；构建部分解析后忽略。
- 不完整版本补零得到下界 lo（`1.2` 补成 `1.2.0`），"下一个"指把最后一个出现的段加一、后面归零（`1.2` 的下一个是 `1.3.0`，`1` 的下一个是 `2.0.0`）。各比较符对不完整版本的含义：
  - 无符号或 `=`：`>= lo` 且 `< 下一个`；`*` 或 `x` 单独出现就是任意版本。
  - `>`：`>= 下一个`；`>=`：`>= lo`；`<`：`< lo`；`<=`：`< 下一个`。
  - `!=` 只能配完整版本，不完整的返回错误。
  - `~`：`>= lo` 且 `< 下一个次版本`（只给了主版本时是 `< 下一个主版本`）。例：`~1.2.3` 是 `>=1.2.3 <1.3.0`，`~1` 是 `>=1.0.0 <2.0.0`。
  - `^`：`>= lo` 且 `<` 最左边第一个非零段加一（后面归零）的版本；给出的段全是零时，把最后一个给出的段加一。例：`^1.2.3` 是 `<2.0.0`，`^0.2.3` 是 `<0.3.0`，`^0.0.3` 是 `<0.0.4`，`^0.0` 是 `<0.1.0`，`^0` 是 `<1.0.0`，`^1.x` 是 `<2.0.0`。
- 连字符范围 `A - B`（连字符两边都要有空白）：`>= A 补零`，上界 B 完整时 `<= B`，不完整时 `< B 的下一个`。它自己占一个组，不能和别的比较混写在同一组里。
- 其他任何写法返回错误。

### (Constraint).Check(v Version) bool

按上面的规则判断。另有一条预发布规则：带预发布的版本 `v`，只有当某个组里存在一个带预发布、且主次修都和 `v` 相同的比较时，这个组才可能满足它（`1.2.3-beta.2` 能匹配 `>=1.2.3-beta.1`，不能匹配 `^1.2.0` 或 `*`）；不带预发布的版本不受这条影响。组里不存在这样的比较，这个组就一定不满足带预发布的 `v`。

## 其他

- `Sort(vs []Version)`：原地按 `Compare` 升序排序，要稳定。
- `MaxSatisfying(vs []Version, c Constraint) (Version, bool)`：返回满足 `c` 的版本里 `Compare` 最大的；没有就返回零值和 false。同样大的取先出现的那个。
